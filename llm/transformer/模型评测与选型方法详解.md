# 模型评测与选型方法详解（横切主题 · 训练验收与部署选型的尺子）

> 定位：**横切主题**，不占环节编号——它不属于 Transformer 内部机制，而是"模型产出之后"怎么验、怎么选的方法论。
> 所属总揽：[Transformer全链路总揽与环节拆解.md](./Transformer全链路总揽与环节拆解.md)（落在 §0.2 两个生命周期**之间**的验收尺子）。
> 相邻环节：训练侧 [环节 09 · 训练管线](./环节09-训练管线详解.md)；部署侧 [环节 11 · 服务化与推理引擎](./环节11-服务化与推理引擎详解.md)（机制先看 [环节 10](./环节10-推理解码与KV缓存详解.md)）。
> 适合人群：训练/微调完要做验收的人、要选型开源模型的人、以及想看懂"旗舰发布会跑分"的人。

## 0. 一句话定位

评测（evaluation）= 用**一组"能打分的任务 + 裁判"**回答"这模型到底行不行"。它出现在两处：

- **训练收尾**（环节 09 之后）：验"训好了没、退步了没"；
- **部署选型**（环节 11 之前）：比"该用哪个、能不能上"。

**第一个认知必须先纠**：跑分 ≠ 真实使用。所有评测集都是"代理指标"，分数只说明"它在这些题上表现如何"。用分要过三问——**测对维度了吗、裁判公平吗、题还干净吗**（对应全文 §1 → §2 → §3/§4）。

评测要回答的三个问题：

| 问题 | 场景 | 手段 |
|---|---|---|
| 它能力怎么样（**绝对值**） | 训练后验收 | 覆盖面广的基准跑分 + 人工抽检 |
| 它比另一个强吗（**相对值**） | 选型 | 同配置对比 + 配对比较（Arena） |
| 它退步了没（**回归**） | 微调后 / 量化后 | 同一套回归集前后对照 |

> 记忆点：**验收看"绝对能力有没有达标"，选型看"相对谁更强"，回归看"别处掉没掉"**——三问三套配置，别混成一套。

## 1. 评测三维：测什么 × 谁打分 × 题干不干净

| 维度 | 问题 | 展开节 |
|---|---|---|
| **能力域** | 测的是知识/推理/代码/……？与你的用途一致吗 | §3 Benchmark 地图 |
| **裁判** | 谁给"对错/好坏"？程序、规则、模型判官还是人 | §2 |
| **数据卫生** | 题被模型"偷看"过吗？还有区分度吗 | §4 三大坑 |

能力域速览（维度清单，非完整列表）：知识 / 推理 / 数学 / 代码 / 长上下文 / 指令遵循 / 偏好 / Agent·工具 / 安全对齐 / 多语言。

> 第一原则：**没有单一"智能分"**——分数永远挂在能力域上。被问"这模型强不强"，先反问"在哪个能力域、用什么测的"；能拆开维度说，比报一个总分专业得多。

## 2. 裁判方法（谁给分）——从硬到软再到真，能程序判就别让模型判

### 2.1 程序校验（最可信，优先用）

- 数学答案精确匹配 / 代码跑测试用例 / 检索命中率 / 输出 schema 校验。
- 好处：零主观、可复现；坏处：只能覆盖"答案确定"的任务。

### 2.2 规则匹配与选择题

- 代表：MMLU / C-Eval 等单选题集。实现简单、可比性强。
- 坑：选项顺序敏感、Few-shot 模板不稳定、模型会"跟着选项走"。对策：多模板取中位，别只报最好的一次。

### 2.3 LLM-as-Judge（判官模型打分）——覆盖开放题的主力

让一个强 LLM 按评分标准（rubric）给生成结果打分；成本低、能覆盖写文章/总结/对话这类无标准答案的任务。

**三大偏差（背诵点）**：

1. **位置偏差**：倾向于给排在前面的答案高分；
2. **长度偏差**：更长 ≠ 更好，但判官常偏爱长输出；
3. **自偏好**：判官（或其同源模型）偏爱自己风格的输出。

对策：打分时**隐藏身份与位置（双盲交换）**、提供参考范文/rubric、多次采样平均、必要时换不同判官交叉验证。

### 2.4 人工评测 + Arena Elo（最接近真实，最贵）

- 真人偏好判断最像"真人想要的"，但收集贵、慢、难大规模复现 → 只做抽样与最终裁决。
- Elo / Arena：把"打分"变成"两两对决谁赢"，产出**相对排位而非绝对分**——它回答"谁更强"，不回答"强多少"。

### 2.5 应用内评测（离真相最近）——跑分之外必须补的一层

- 离线基准永远只是代理；把评测搬进真实链路才算数：Agent 任务完成率、RAG 命中与引用正确、代码能过 CI、线上 A/B（真实用户行为）。
- **升级路线**：规则基准 → Judge → 人工 → 线上 A/B，成本递增、可信度也递增；投产决策尽量落在最右侧。

> 面试点：被问"LLM 评测怎么做"，按 §2.1 → §2.5 给"从硬到软再到真"的升级路线，点出 Judge 三偏与"最终看应用内/线上"，就是完整答案。

## 3. Benchmark 地图（选"测什么"的货架）

| 能力域 | 代表评测 | 测什么 | 提醒 |
|---|---|---|---|
| 综合知识 | MMLU / MMLU-Pro | 多领域选择题知识 | 老题饱和、易污染；Pro 提难 |
| 推理 | GSM8K → MATH → GPQA | 小学 → 竞赛 → 研究生级 | 难度递进；低层分数涨不动就上新 |
| 数学前沿 | AIME / FrontierMath 类 | 竞赛 / 研究级数学 | 发布越新，污染风险越小、区分度越大 |
| 代码 | HumanEval / MBPP | 单函数补全 | 饱和快；真实工程上 SWE-bench 类整库任务 |
| 长上下文 | LongBench / RULER | 超长文档理解 | 光长没用，要测"长且没丢" |
| 指令遵循 | IFEval 类 | 是否照做格式/约束 | 与真实 prompt 遵循度相关度高 |
| 偏好真实感 | Chatbot Arena 类 | 人类两两对决 | 唯一"人说了算"的公开榜 |
| 中文 / 多语 | C-Eval / CMMLU 等 | 本土知识 | 国际集 + 中文集一起跑 |
| Agent / 工具 | SWE-bench / 各 tool 集 | 会调工具、完成多步任务 | 最贴近 coding agent 的真实用法 |
| 安全 | 越狱 / 幻觉 / 偏见集 | 拒绝与事实性 | 与能力正交，别用一个分掩盖 |

> 选型时的货架逻辑：**先定用途 → 圈 2~3 个能力域 → 每域 1~2 个有区分度的题 + 1 个真实任务**。全都要 = 全都不精。

> 工具链速览：`lm-eval-harness`（跑分标配）、OpenCompass、HELM；框架内置评测（如推理引擎自带的精度回归）只覆盖"引擎没改坏模型"这一层（见 [环节 11](./环节11-服务化与推理引擎详解.md) §6 坑 5）。

## 4. 三大坑：跑分怎么骗你

### 4.1 数据污染（最阴险）

预训练语料可能已含测试题 → 分数虚高、真实使用却跟不上的经典现象。

- 自查信号：模型答公开测试集"过好"，但同难度新题拉胯；
- 对策：用**发布之后的题**、**私下保留集**、查官方去重声明、看**独立复测**。

### 4.2 饱和（区分度归零）

老题人人 90+ 分 → 谁强谁弱看不出来 → 榜单沦为"谁分高"的橡皮图章。

- 症状：多家旗舰挤在个位数差距里；
- 对策：盯**新出的难题**（前沿数学 / 研究级推理）——顶层题目上的差距才真实。

### 4.3 选择题 ≠ 真实使用（代理失真）

单选题只测"认出对的"，不测"产出对的"；且推理模型对 prompt 措辞、格式、temperature 高度敏感，换个问法分数可波动 10%+。

- 对策：多模板取区间、跑开放生成 + 程序/Judge 判、最终落到真实任务。

> 面试速记：**污染抬高虚分、饱和抹平差距、选择题≠真实使用**——三坑一问一答，解都指向"独立新题 + 真实任务"。

## 5. 决策表：什么场景用什么评测

| 场景 | 评测配置 | 关键动作 |
|---|---|---|
| 预训练 / 继续预训练验收（环节 09 侧） | 通用能力域抽样 + **崩溃检测** | 看有没有某能力域"塌方"，别只看平均 |
| 微调验收（对应环节 09 §4.5 的 Eval 回归） | **任务专属集 + 通用回归集** | 任务分涨而通用分跌 = 灾难性遗忘，判失败 |
| 开源 / 自研选型（环节 11 前） | 目标任务真实集 + 竞品**同配置**对比 | 同 temperature / 同 prompt；能力、成本、延迟三角一起看 |
| 上线前（环节 11 侧） | 量化 / 格式回归 + 真实流量 A/B | INT4 等量化必回归（环节 11 §6 坑 5）；新格式先小流量 |
| 读厂商新闻 / 论文 | 官方口径 vs 独立复测 | 过一遍 §6 核对清单五问 |

> 一句话配法：**验收者配"任务集 + 回归集"，选型者配"真实任务 + 竞品同配"，读新闻配"独立复测"。**

## 6. 读"旗舰发布会跑分"的核对清单（评测卡五问）

新闻里"最强 / 超越人类"怎么验？拿五问逐条过——可复用于任何旗舰发布（含 4o 系、GPT-6 Astra 这类评测卡发布）：

1. **谁测的？** 官方自测（可挑题、挑 prompt、挑基线）vs 第三方独立复测——后者才可信；
2. **比的是谁、什么配置？** 基线版本、temperature / 采样、是否同题同 prompt 同环境——差一样就失真；
3. **"超过人类"在什么限定任务里成立？** 常在受限/专项任务成立，≠ 通用能力强；看能力域矩阵的**覆盖度**，不只盯峰值；
4. **题新不新、干不干净？** 撞训练数据 = 污染嫌疑；发布前新题 + 可复现代码的题，才经得起复测；
5. **换个问法、换个格式还成立吗？** 多模板验证；"特定提示词下超强、换措辞即崩"是代理失真信号（§4.3）。

> 记忆点：**官方评测卡负责好看，独立复测负责真相**——标题信五分，五问过完信七分，剩下的交给真实任务。
>
> 注：本清单刻意不写任何具体跑分数字——方法论可套用，数字请查发布当时的一手报告与独立复测，别转载二手榜单。

## 面试高频追问（横切主题速刷）

1. 怎么判断模型"真变强"还是"刷分"？→ 独立新题 / 私下集 + 排除污染 + 真实任务三件套。
2. LLM-as-Judge 有哪些偏？怎么治？→ 位置 / 长度 / 自偏好；双盲交换 + rubric + 多次采样。
3. 微调后该跑什么评测？→ 任务专属集 + 通用回归集，通用分掉 = 灾难性遗忘（回 [环节 09](./环节09-训练管线详解.md)）。
4. MMLU 98% 能说明什么？→ 只说明"选择题知识识别"强；不说明开放生成、复杂推理与真实使用。
5. 老题人人 90+ 为什么没法用？→ 饱和无区分度；要换新难题看顶层差距。
6. 官方"超越人类"要不要信？→ 先过 §6 五问，等独立复测，再看真实任务。
