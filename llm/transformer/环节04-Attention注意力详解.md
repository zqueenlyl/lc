## 1. 干什么

让每个 token 的向量，变成"它该看的其他 token 的信息加权和"。例如"猫坐**在**垫子上"，"在"要参考"猫/垫子"才能确定关系。这是 Transformer **唯一跨位置**的通道，是 `O(n²)` 与 KV Cache 的源头，也是 [环节 03 位置编码](./环节03-位置编码详解.md) 注入旋转后 Q/K 真正登场的舞台。

---

## 2. 怎么干（单头流程）

1. **三个投影（projection）**：对输入 `X` 分别乘 `W_Q / W_K / W_V`，得到 `Q(查询)、K(键)、V(值)`；
2. **打分**：`S = Q·Kᵀ / √d_k`——第 i 个 token 拿自己的 Q 去问每个历史 token 的 K："你跟我相关吗？"
3. **掩码（mask）**（Decoder-only）：把"未来位置"（上三角）置 −∞（因果掩码，causal mask）；
4. **归一**：`P = softmax(S)` 按行归一（每行和 = 1，即"注意力权重"）；
5. **汇总**：`O = P·V`——按权重把 V 加权求和。

公式（单头写法；多头 = 并行 H 组后拼接再投影）：

```
Q = X·W_Q,   K = X·W_K,   V = X·W_V                    # 输入 X：(n, d) → 各 (n, d)
S     = Q·Kᵀ / √d_k                                    # (n, n)  ← O(n²) 的来源
M[i][j]= -∞  if j>i  else 0                            # 因果 Mask（上三角）
P     = softmax(S + M)   （按行）                       # (n, n)，每行和为 1
O     = P·V                                            # (n, d)
```

### 2.1 Q / K / V 的语义（背下来）

- **Q（Query）**：我在找什么 → 我去照别人；
- **K（Key）**：我能被怎么找到 → 别人来照我（呼应 RoPE 转 Q/K 不转 V）；
- **V（Value）**：我实际提供的**内容** → 按相关度加权求和的对象。

输出 = 按相关性加权的内容求和：**每个位置的输出向量 = 它看得见的 token 的内容按相关度加权求和**。

### 2.2 为什么要除以 √d_k

内积（inner product）随维度增大而线性变大（d 维随机向量点积量级 ~ d）；不缩放，softmax 会进入饱和区（saturation）（输入过大 → 概率贴 0/1），梯度消失（vanishing gradient）。除以 √d_k 把分数拉回稳定量级。

### 2.3 因果 Mask 到底在干什么

Decoder-only 训练是"整条序列并行前向"，位置 i 只能看 j≤i。做法：把分数矩阵 S 的上三角（j>i）置 −∞，softmax 后这些位置概率被挤到 0，梯度也不穿过它们——**"并行算所有位置" ≡ "逐词预测"的等价性就靠这一行**。

### 2.4 Multi-Head（多头）

单头 = 整套流程只在一套 Q/K/V 投影、一个 d 维空间里进行。多头 = 把这套流程**并行复制 H 份**，每份参数独立、只在自己分到的 `d/H` 维窄子空间里算，最后**拼回全维再投影一次**：

```
输入 X：(n, d)，其中 d = H × d_head（如 512 = 8 头 × 64）

第 i 个头（i = 1…H；W_Q⁽ⁱ⁾ / W_K⁽ⁱ⁾ / W_V⁽ⁱ⁾ 各自独立、随机初始化）：
    Qᵢ = X·W_Q⁽ⁱ⁾,   Kᵢ = X·W_K⁽ⁱ⁾,   Vᵢ = X·W_V⁽ⁱ⁾   # (n, d_head)
    Sᵢ = Qᵢ·Kᵢᵀ / √d_head                            # (n, n)，本子空间内打分
    Oᵢ = softmax(Sᵢ + M)·Vᵢ                           # (n, d_head)，Mask/归一照旧

最后：O = concat(O₁, …, O_H)·W_O   # H 段拼回 (n, d) → 输出投影 W_O 融合 → (n, d)
```

必须知道的四件事：

1. **切维是"不增算力、白拿视角"的关键**：若每头都在全 d 维上独立算，总计算量 ×H，没人用得起；切成 `d/H` 维后，H 份之和仍等于"单头全维算一次"——**同一笔算力买到 H 个互不干扰的子空间视角**；
2. **"多头分工"不是规定出来的**：H 套投影初始全是随机数，谁管什么并不确定；训练中靠反向传播**自发分化**，不同头各自抢着学一类关系模式（可解释性观测近似：有的头盯前一个 token 做"位置头"、有的做指代回看、有的做 induction head 式"复制上一个模式"……）——"一组抓语法、一组抓指代（coreference）、一组抓主题"是**事后的结果描述，不是预设机制**；
3. **每个头只在窄子空间里打分** = 各自只需在一类关系里分主次，专注度更高；头与头算完前互不通信，**唯一的汇合点是 concat 后的 W_O**——它把 H 份低维"孤岛"结论线性混合成一份全维向量，交给下一层/LM Head；
4. **H 个头 = 每层有 H 张"谁在看谁"的热力图**（都是 (n,n)），只是每张图按不同子空间的标准画的。

> 记忆钩子：单头是"一个人粗看全场"，多头是"H 个专科医生会诊、各看一科，最后综合意见"。H 张注意力图并存，就是"多视角"的物理形态。

微例（衔接 §5 手算）：d=8、H=2 → d_head=4——头 1 用输入向量前 4 维的投影打分、头 2 用后 4 维（严格说是各行向量左乘各自的 `W_Q⁽¹⁾/W_Q⁽²⁾`，效果等价于各拿一份切片）；两头的输出各 (n,4)，拼回 (n,8) 再过 `W_O`。后来的 **GQA/MQA 只是改"几个 Q 头共享同一套 K/V"**（每个头算注意力这件事不变），KV Cache 省的就是"K/V 存几份"（见 §3 家族表、§4 公式）。

## 3. Attention 家族（方法与优缺点——重要横向表）

| 方案 | 改了什么 | 解决了什么 | 代价/缺点 | 代表 |
|---|---|---|---|---|
| **MHA**（基准） | H 组 Q/K/V 各自独立 | 表达能力基准 | KV Cache = 2×H×d；算力/显存都最贵 | 原论文、BERT |
| **MQA**（多查询） | H 组 Q，**只共享 1 组 K/V** | KV Cache 降到 1/H | 共享过狠 → 质量略掉；训练不稳 | PaLM（早期探索） |
| **GQA**（分组查询，**主流**） | K/V 分成 G 组（G<H），组内共享 | 在质量和 KV 省显存间取平衡 | 组数需调；仍是显存大头之一 | LLaMA-2/3、Qwen、Mistral |
| **MLA**（Multi-head Latent Attention，多头潜在注意力） | 把 K/V 先压缩进低维潜在空间（latent space），做注意力时再展开 | KV Cache 小一个量级、推理省显存省带宽 | 结构复杂、难直接复用社区优化 | DeepSeek V2/V3、Kimi |
| **FlashAttention** | 不打大矩阵，分块计算（blockwise）+ 在线 softmax（online softmax） | Prefill 快且省显存（I/O 优化） | 属于"怎么算"而非"改结构"，叠加在任意家族上 | 所有现代引擎 |

> 记忆钩子：**H > G > 1**。MHA（每头一套 KV）→ GQA（几头共享一套 KV）→ MQA（所有头一套 KV）→ MLA（KV 先压缩再展开）。越往后 KV Cache 越小、结构越复杂。

---

## 4. 复杂度与 KV Cache 的由来

- 每层注意力矩阵是 `序列长度²`：**总上下文越长，单步越贵** → `O(n²)` 是一切长上下文优化的出发点。
- 自回归生成时，第 t 步要再看一遍前 t−1 个 token 的 K/V——**存下来不重算**就是 KV Cache：用显存换算力。KV Cache 大小 ≈ `2 × 层数 × KV头数 × 头维度 × 总长度 × 字节数`。GQA/MLA 砍的就是公式里的 KV 头数项。（生成侧细节见 [环节 10](./环节10-推理解码与KV缓存详解.md)。）
- **长序列方案谱系**：KV Cache 压缩（GQA/MLA）→ 显存分页（memory paging；PagedAttention）→ 稀疏注意力（sparse attention；滑窗/局部+全局）→ 状态空间模型（state space model，SSM）/线性注意力（linear attention）（Mamba，`O(n)`，另一条路线）。

| 稀疏/线性方案 | 核心 | 优点 | 缺点 |
|---|---|---|---|
| 滑窗注意力（sliding window attention，SWA） | 只看最近 W 个 token | 复杂度 O(n·W)，Mistral 用过 | 丢掉远距离直连，信息靠层层传递 |
| 全局+局部（Longformer/BigBird） | 少量"全局位" + 滑窗 | 兼顾长程与复杂度 | 工程复杂，训练需专门设计 |
| 线性注意力（linear attention）/RoPE-free（RWKV/Mamba） | 用递归式状态（recurrent state）替代注意力图 | O(n) 可真正无限长 | 表达力/生态弱于 Transformer，是前沿而非主流 |

## 5. 数值手算走查：从输入 token 到注意力输出

**玩具设定（全部为了手算可读，不是真实初始化）**：单层、单头、d=4、词表 {a,b,c,d}。训练样本 = 语料 `a b c d` 中取长度为 3 的窗口：

```
输入 X_tokens = [a, b, c]       标签 Y = [b, c, d]        # 位置0→b、位置1→c、位置2→d
```

演示权重（教学取值）：Embedding 用单位词向量 a=[1,0,0,0] b=[0,1,0,0] c=[0,0,1,0] d=[0,0,0,1]；W_Q = W_K = W_V = I；位置/LayerNorm/FFN 本例恒等。

**Step 1 输入**：

```
X = | a |   | 1 0 0 0 |
    | b | = | 0 1 0 0 |
    | c |   | 0 0 1 0 |
```

**Step 2 QKV 与注意力分数（Q=K=V=X）**：不同词嵌入两两正交、自相似为 1，除以 √d_k = √4 = 2：

```
S_raw[i][j] = x_i·x_j / 2   →   自注意力分 = 0.5，跨词 = 0

S_raw  = | 0.5   0    0   |
         |  0   0.5   0   |
         |  0    0   0.5  |
```

**Step 3 因果 Mask（上三角置 −∞）**：

```
S = | 0.5   -∞    -∞   |     行0：a 只能看 a
    |  0   0.5   -∞   |     行1：b 看 a,b
    |  0    0    0.5  |     行2：c 看 a,b,c
```

**Step 4 Softmax → 注意力权重 P（每行和为 1）**：

```
e^0 = 1, e^0.5 = 1.64872

行0：[1,0,0]（归一化后仅看自己）
行1：softmax(0, 0.5) = [ 1, 1.64872 ] / 2.64872 = [0.37754, 0.62246]
行2：softmax(0, 0, 0.5) = [1, 1, 1.64872] / 3.64872 = [0.27408, 0.27408, 0.45185]
```

注意每行元素由少到多、权重自动归一——Mask 之外的未来位置概率被挤到 0。

**Step 5 加权求和 O = P·V**：

```
O0 = 1.0·a                       = [1.00000, 0, 0, 0]
O1 = 0.37754·a + 0.62246·b       = [0.37754, 0.62246, 0, 0]
O2 = 0.27408·a + 0.27408·b + 0.45185·c = [0.27408, 0.27408, 0.45185, 0]
```

这就是"注意力"的实质：每个位置的输出 = 它看得见的 token 的内容向量按相关度加权求和——看行 2，c 不仅能引用自己，还能按权重翻阅 a、b。

**Step 6 残差（residual connection，模型内每子层后都要把输入加回主干）**：

```
Z0 = a + O0 = [2.00000, 0, 0, 0]
Z1 = b + O1 = [0.37754, 1.62246, 0, 0]
Z2 = c + O2 = [0.27408, 0.27408, 1.45185, 0]
```

残差的意义：Z 同时携带"原始 token 信息 + 上下文加权信息"，深度堆叠也不丢主路（残差机制详解见 [环节 06](./环节06-残差连接与归一化详解.md)）。

> 走查的"下一半"——Z 过 LM Head 得到预测分布、算交叉熵（cross-entropy）损失、看梯度往哪走——在 [环节 08 · 输出头与训练目标](./环节08-输出头与训练目标详解.md) §4 继续（手算数字完全相同，可对照）。

### 5.1 可运行验证代码（复现上述全部数字）

```python
import numpy as np

V = 4  # {a,b,c,d}
X  = np.eye(V)[[0,1,2]]           # a,b,c 的 one-hot 型嵌入（= 手算用词向量）
Y  = np.array([1,2,3])            # 标签 b,c,d
Wq = Wk = Wv = np.eye(V)

Q, K, V_ = X@Wq, X@Wk, X@Wv
S = Q@K.T / np.sqrt(V)
n = S.shape[0]
mask = np.triu(np.full((n,n), -np.inf), 1)   # j>i → -inf
P = np.exp(S + mask); P /= P.sum(1, keepdims=True)
O = P@V_
Z = X + O
logits = Z                                    # W_head=I
p = np.exp(logits); p /= p.sum(1, keepdims=True)
print("P =\n", np.round(P, 5))
print("Z =\n", np.round(Z, 5))
print("p =\n", np.round(p, 5))
loss = -np.log(p[np.arange(n), Y]).mean()
print("loss =", round(loss, 4))               # 期望 ≈ 2.1838（对应环节08 的损失讲解）
```

## 6. 面试高频追问

1. **Self-Attention 为什么能并行而 RNN 不能？** 各位置间无串行数据依赖，Q/K/V 全是整序列矩阵乘法，天然可并行；RNN 每步 h_t 依赖 h_{t-1}。（架构演进背景见 [环节 07](./环节07-Block堆叠与整体架构详解.md)。）
2. **attention 为什么要除以 √d_k？** 防内积随维度变大而过大，softmax 进入饱和区导致梯度消失。
3. **训练时整条序列并行，凭什么位置 i 不会偷看位置 i+1？** Mask 把 S 的上三角置 −∞，softmax 后这些位置权重为 0，梯度也不穿过它们。
4. **MHA / GQA / MQA / MLA 的演化逻辑？** KV Cache 由 `2×层×KV头×头维×长度` 决定，压缩"KV 头数"或先压缩再展开，换来显存与带宽，代价是结构与质量微调。
5. **FlashAttention 为什么快？** IO 感知：不打大中间矩阵，分块 + 在线 softmax，省显存省读写。
6. **长上下文为什么贵？** 每层注意力矩阵 O(n²)；KV Cache 又线性吃显存——一切长文本优化都从这两条公式出发。
7. **MHA 凭什么比单头强、还不额外花算力？** 切维：每头只在 d/H 维子空间独立打分，H 份总算力 ≈ 单头全维一次，却拿到 H 个互不干扰视角；头分工由训练自发分化、非预设（§2.4）。
