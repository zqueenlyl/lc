# 音频与语音详解（ASR / TTS / 语音 tokenizer / 端到端语音对话）

> **定位**：音频是"最像文本又最不像文本"的模态——语音里有离散的语言信息，但物理载体是连续波形。本篇覆盖：**听懂（ASR）、说出（TTS）、把语音当 token 接入 LLM（语音对话）**，以及后端最关心的延迟/成本工程。生成范式两种都有：ASR/TTS 走自回归（transformer/ 那套）为主，非自回归 TTS 用扩散/流匹配（[图像扩散模型详解.md](./图像扩散模型详解.md) 的音频版）。

---

## 1. 信号基础极简（够工程用即可）

| 概念 | 数值常识 | 说明 |
|---|---|---|
| 采样率 | 语音常见 16kHz（电话 8k，HiFi 44.1k） | 每秒采样点数 |
| 帧 / 窗 | 25ms 帧窗、10ms 步进 → 16kHz 下每帧 400 样本 | 语音短时平稳，按帧处理 |
| 特征 | **Log-Mel 谱**（如 80 频带） | 把波形 → 时间×频带矩阵 |
| Whisper 输入 | 30 秒窗 → 80×3000 的 log-mel | 每 10ms 一帧 → 30s = 3000 帧 |

记住一句话：**语音 API 拿到的"音频"通常是 PCM 波形（或压缩码流），模型吃的是"帧特征/离散 token"，中间永远有一步信号转换**——这就是语音系统和文本系统工程差异的来源。

## 2. 三块任务地图

| 任务 | 干什么 | 代表 |
|---|---|---|
| ASR | 语音 → 文本 | Whisper、K2/Conformer（流式） |
| TTS | 文本 → 语音 | CosyVoice、Seed-TTS、ElevenLabs |
| 语音对话（端到端） | 语音进语音出，单模型 | GPT-4o audio、Qwen-Omni |
| （语音理解入 LLM） | 语音 → token 进 LLM | Whisper 特征 / 神经编解码 token |

## 3. ASR：把声波变成文本

- **Whisper 系**（离线主流）：80 通道 log-mel → Encoder-Decoder（= 文本 transformer 同构）→ 逐 token 出文本，附语言/时间戳。优点：多语言、抗噪强、自带时间戳对齐；缺点：30s 窗口、流式要靠工程切窗
- **CTC 系**（流式主流）：帧级对齐免去逐字切分，可流式；精度一般略逊，延迟低
- 工程要点：热词/人名注入、数字格式后处理、**时间戳与字幕**、噪声鲁棒（前端降噪）、多语种路由
- 评测：**WER/CER**（词/字错误率）；中文常看 CER

## 4. TTS：文本变语音，三代演化（看懂为什么越来越快）

| 代际 | 方案 | 特点 |
|---|---|---|
| 1 | 拼接（选库拼波形）/ 参数（统计建模） | 机械、成本高 |
| 2 | **两阶段神经 TTS**：自回归声学模型（文本→梅尔） + vocoder（梅尔→波形，如 WaveNet/HiFi-GAN） | 自然，但慢（分两步 + 自回归逐帧） |
| 3 | **单阶段非自回归**：文本 → 隐表示 → 波形一次合成 | 快、可控强 |

第三代的关键词：
- **流匹配 / 扩散**：用 [图像扩散详解 §2-3](./图像扩散模型详解.md) 的"加噪-去噪"对波形建模，整段并行合成 → 一个 ODE 步数控制速度质量
- **神经编解码 token（codec）**：把波形压成离散 token（如每秒 50 个 token，每 token 码率可控）——**语音因此能被当"语言 token"训练/生成**，这是语音大模型的基础设施
- **声音克隆/音色控制**：说话人 embedding、多参考音频条件（cosyvoice 的三方解耦：音色/韵律/内容分离，可跨语种克隆）
- 评测：**MOS**（主观自然度）、**RTF**（real-time factor：合成 1 秒音频耗时，<1 才可实时）、字音正确率（文本朗读对齐）

**关键认知**：自回归 TTS 按"帧/token"滚（慢、可长文本但错误累积）；非自回归流匹配一次算整段（快、需模型保证时长对齐）。**实时对话场景必须 RTF < 1 且首包延迟短 → 通常选非自回归 + 分段合成。**

## 5. 语音 tokenizer：音频接入 LLM 的桥

```
波形 → 神经编解码器（encoder-decoder + 矢量量化）→ 离散 code token（50Hz）→ LLM 按文本方式训练
```

- 代表：EnCodec/SoundStream 等；可多码本（残差量化 RVQ，码率 = 帧率 × 码本 × bit）
- 意义：**语音与文本在同一个 token 域** → 可做语音 LLM（输入输出语音、跨语种翻译保留音色）、字幕对齐
- 代价：量化丢音质细节（重合成依赖 codec 解码质量），高音质靠加码率或连续特征

## 6. 端到端语音对话（延迟是生死线）

- 管线式（今天主流）：ASR → LLM → TTS 三模块编排。好处：各模块独立迭代、可换模型；坏处：累积延迟
- 端到端（GPT-4o/Qwen-Omni 路线）：语音 token 直接进出单模型，低延迟 + 保留情感语气；代价：难调试、训练贵、语音能力与文本对齐难
- **延迟预算（工程要点）**：

| 环节 | 预算 | 手段 |
|---|---|---|
| 听（ASR） | 边说边出（半句起翻） | VAD 断句 + 流式 ASR + 半句级 partial |
| 想（LLM） | 首 token 尽量快 | 推理优化（见 [环节10](../transformer/环节10-推理解码与KV缓存详解.md)/[环节11](../transformer/环节11-服务化与推理引擎详解.md)） |
| 说（TTS） | **首包 < 300~500ms** | 分段合成（先合前半句就播）、首包优先、流式播放 |
| 总预算 | 人耳舒适 ≤ ~1s 轮询 | 三模块全做增量/流式，别"整句等完再回" |

- 打断/双工（barge-in）：麦克风实时回采 + VAD 判断用户插话 → 立即停 TTS

## 7. 工程要点（后端直用）

1. 音频存储与传输：WAV/PCM（无损大）、Opus/MP3（小）；流式用 WebSocket/RTMP；16kHz mono 常为语音默认，音乐 44.1k
2. 成本 = 音频时长 × 模型 RTF 对应算力；TTS 可缓存（同文本同音色 hash）；ASR 后处理结果可缓存
3. 评测基线：WER/CER、MOS、RTF、断句/时间戳准确率；升级模型跑回归集（方言/噪声/专名）
4. 合规：声纹/音色克隆与深度伪造（声音需授权）、通话录音合规、儿童/骚扰过滤

## 8. 面试高频追问

1. **音频为什么不像文本那样直接用 token？** 波形是连续信号、帧间强相关；文本天然离散。所以先"特征化"（mel/帧）或"token 化"（codec），才能进神经网络/语言模型。
2. **TTS 为什么从两阶段进化到单阶段？** 两阶段慢（梅尔→波形两步 + 自回归逐帧）；流匹配/扩散一次合成整段、RTF<1，实时对话可行。
3. **Whisper 为什么很难直接做低延迟流式？** 它的输入是 30s 整窗、输出自回归；流式要外部切窗 + 半句拼接，属于工程集成而非模型天然支持。
4. **神经编解码 token 为什么是语音大模型的基石？** 把连续音频离散成固定速率 token，语音才能进入与文本一致的"自回归预测"范式（跨语种、音色、对话）。
5. **语音对话延迟怎么压？** VAD 半句起翻、分段合成先播、流式三链路、端到端模型省编排——总预算 ~1s 内。
6. **RTF<1 意味着什么？** 合成 1s 音频耗时要少于 1s，是"能实时"的门槛；进一步要首包延迟（而非总时长）达标才适合对话。
