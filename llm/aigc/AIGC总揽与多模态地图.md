## 1. 模态矩阵与统一视角

| 模态 | 代表 | 底层范式 | 输入/输出粒度 | 成熟度 | 成本量级 |
|---|---|---|---|---|---|
| 文本 / 代码 | GPT、DeepSeek、Claude、Qwen | 自回归 Transformer | token（BPE） | 成熟 | 低（按 token） |
| 图像 | Stable Diffusion、FLUX、Midjourney | **扩散（DDPM/DiT）** | 像素 ↔ 潜空间 | 成熟 | 中（步数驱动） |
| 视频 | Sora、可灵、Veo、Vidu | DiT + 时空建模 | 时空 patch ↔ 视频 VAE | 迭代期 | 高（≈帧数 × 图像成本） |
| 语音 | Whisper（ASR）、CosyVoice/Seed-TTS | 自回归 / 非自回归（流匹配） | 波形 → 帧/离散 token | 成熟 | 低-中 |
| 音乐 / 3D | Suno、Udio / TripoSR 等 | 自回归 + 扩散混合 | 音频 token / 多视图+重建 | 早期 | 中-高 |
| 多模态 LLM | GPT-4o、Gemini、Qwen-VL/Omni | 统一 Transformer | 视觉/音频 patch + token | 主流方向 | 视模态而定 |

**统一视角（最重要的一句话）**：所有模态在做同一件事——**把连续、高维、冗余的物理信号（像素/波形/帧）压成"机器好用的离散或低维连续表示"，再让一个模型学会"从表示预测表示"**。差异只在表示怎么来、模型用什么范式预测：

- 文本：天然离散 → BPE token，自回归逐 token
- 图像/波形：**高度连续 + 强局部性** → 逐 token 自回归不划算（每像素决策、错误累积），扩散"整张并行去噪"更自然
- 所以选范式本质是：**信号该"串行展开"还是"并行变换"？该按"语言"建模还是按"分布"建模？**

## 2. 两大生成范式（吃透这条线，四篇全通）

### 2.1 自回归：逐单元预测（= transformer/ 全部 11 环节服务的那套）

- 单元可以是词、图像 VQ token、语音神经编解码 token、视频帧 token
- 优：**通用**（理解与生成同构、可带任意条件、生态最熟）；劣：逐单元慢、成本随序列线性涨、长序列错误累积
- 图像/视频/音频侧也用它：VQGAN（图像 token）、VALL-E/SpeechGPT（音频 token）、VAR 等

### 2.2 扩散：加噪-去噪（DDPM 思路，见 [图像扩散模型详解.md](./图像扩散模型详解.md)）

- 训练：真实样本逐步加噪，学反向去噪；生成：从纯噪声**迭代去噪 N 步**（SDXL 经典 20~50 步，蒸馏后 1~8 步）
- 优：像素级全并行、无逐位错误累积、对连续信号天然友好；劣：每步要跑一遍骨干网络（成本 ≈ LLM 推理的 N 倍）、步数与质量/成本三角
- 视频：扩散到帧序列（在时间上也"逐步长出"）；音频：TTS 用扩散/流匹配做非自回归合成

**对比速记**：自回归 = "一行行打字"，扩散 = "从马赛克噪点里一次次抛光"。前者擅长生成"结构序列"（语言、代码、逻辑），后者擅长生成"连续分布"（图像、波形）。多模态 LLM 想"一个模型出所有"，路线就是**把理解统一成自回归 token、把像素级生成外包给扩散/其他 decoder**（详见 [多模态理解与统一模型详解.md](./多模态理解与统一模型详解.md)）。

## 3. 生成与理解的公共底座（各专题会复用，先在此建参照系）

| 组件 | 干什么 | 出现在哪 |
|---|---|---|
| 视觉编码器（ViT/ConvNeXt 等） | 把图/视频帧切成 patch 抽特征 | 理解侧（VLM）、生成侧条件（CLIP 图像塔） |
| **CLIP 类对比对齐** | 图-文双塔拉近语义，是"视觉的语言接口" | 文生图条件、图检索、零样本分类 |
| VAE / 自编码器 | 像素 ↔ 潜空间（压缩 ~8×~48×），或图像 ↔ token | 扩散隐空间、视频 3D VAE、图像 VQ |
| 神经编解码器 | 波形 ↔ 离散/连续 token（如 50Hz 帧率） | TTS 单元、语音 LLM 输入 |
| 文本编码器 | 条件入口（CLIP text / T5 / 大 LLM） | 文生图/视频 prompt 注入 |
| 模态 projector | 把视觉/音频特征映射进 LLM embedding 空间 | VLM 接入层 |

> 同一个"编码器/VAE/tokenizer"思想贯穿四篇：**图像切 patch、音频变 token、视频压时空 patch、文本本来就 token**——"一切皆 token/patch"是 2026 年多模态工程的通用语言。

## 4. 工程横切（后端直接可用，四篇都遵守）

| 原则 | 落地 |
|---|---|
| 生成慢 → **异步** | 图像秒级、视频分钟级：提交任务 → 队列 → 轮询/SSE 进度 → 结果存储；**绝不同步阻塞 HTTP** |
| 成本由"步数/帧数/时长"驱动 | 图像：步数（50 → 蒸馏 1-4 步差一个数量级）；视频：每秒 ≈ 24-30 帧 × 图像成本；语音：RTF（实时率）与并发 |
| **幂等可缓存** | 图像/视频同 prompt + seed 结果确定 → hash 缓存命中即可返回；TTS 同文本可复用 |
| 分级模型 | 低质快 / 高质慢路由，配额看板，降级链 |
| 内容审核是刚需 | 生成内容不可信（与幻觉同源）：服务端规则 + 模型双过滤；**审核放客户端 = 可绕过** |
| 版本漂移 | 生成模型升级必须跑回归（风格/质量漂移），锁版本 + 灰度 |

## 5. 合规、评测与安全

- 版权/肖像权（训练数据、真人肖像、深度伪造、声音克隆）——商用前法务评审
- 评测横切：文生图看图文一致性（CLIP 分）+ 美学主观；视频看时序一致性；语音看 WER/MOS/RTF；多模态 LLM 看 MMMU/MMBench/OCRBench
- 对抗：Prompt 注入、越狱、提示词投毒（污染品牌图库）、身份冒充

## 6. 读法与 Agent 视角

- **读法 A（机制线）**：本总揽 §2 → 图像扩散详解（把扩散数学吃透）→ 视频（=扩散+时间）→ 音频（=扩散/自回归在波形）→ 多模态理解（CLIP/VLM，与生成互为镜像）
- **读法 B（工程线）**：四篇的"工程要点"节 + 总揽 §4/§5 → 直接当后端接入清单用
