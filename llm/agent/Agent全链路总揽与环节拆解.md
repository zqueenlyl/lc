## 0. 宏观总揽

### 0.1 一句话认知

**Agent = 一台会"边想边动手、做完看结果再想"的机器**：底座仍是 [Transformer](../transformer/Transformer全链路总揽与环节拆解.md) 那台"只认数字的接龙机器"，但我们在它外面套了一个**决策循环（agentic loop）**——想一步、做一步、观察一步、再想…… 把"闭卷写作文"升级成"开卷 + 动手实验 + 用完记笔记"。

- **训练做的是压缩**（把世界知识压进权重）；**Agent 做的是组合**：用"循环 + 工具 + 记忆 + 检索"补上单次生成的三个致命短板——① 不会中途求证（幻觉）；② 记不住上下文之外的事（无长期记忆）；③ 只会说不会做（无行动能力）。
- 后端的心法贯穿始终：**Agent 应用 = 传统后端 + 一个生成式组件**。LLM 是**外部不可靠服务**，重试/超时/限流/降级/缓存/可观测/权限全部照搬（详见 [环节 10](./环节10-生产级工程化详解.md)）。

### 0.2 全链路 = 一条主循环 + 三个支撑面 + 两道横切

```
用户任务
   │
   ▼
┌────────────── 主循环（每次迭代调用一次 LLM，一次只往前迈一步）──────────────┐
│                                                                          │
│  [环节1] 决策/规划：读全部上下文，决定下一步                               │
│     ├─ 只想清楚再答  → CoT 内省                                         │
│     ├─ 需要动手/求证 → ReAct：Thought → Action（调工具）                 │
│     ├─ 需要外部知识  → 走 [环节6] RAG 检索 / [环节3] 长期记忆召回          │
│     └─ 已能作答      → 输出最终答案（Final Answer），循环终止              │
│            │                                                            │
│            ▼                                                            │
│  [环节4] 工具调用：模型输出结构化调用请求（函数名+参数）                    │
│       ↓                                                                 │
│  [环节5] MCP / 宿主执行：应用侧真正执行工具（含权限校验）                  │
│            │                                                            │
│            ▼                                                            │
│  Observation：工具结果/报错回填进上下文 → 回到 [环节1]                    │
│   （由 [环节7] 编排层管控：状态机、终止条件、步数上限、断点、人机协同）       │
└──────────────────────────────────────────────────────────────────────────┘
   │
   ▼
最终答案（含过程产物/落库状态，由 [环节7] Checkpointer 持久化）

支撑面（不在循环步骤里，但决定模型"能不能理解任务 / 记得住 / 接得上工具"）：
   [环节2] 提示与上下文工程 —— System Prompt / Few-shot / 结构化输出引导
   [环节3] 记忆与状态     —— 工作记忆(State) / 会话记忆 / 长期记忆，可见性管理
   [环节8] 多 Agent 协作   —— 主管-下属 / 流水线 / 辩论等群体编排

横切（贯穿所有环节的"工程门槛"，transformer 里叫横切主题，这里同构）：
   [环节9] 评测与可观测   —— 离线 Eval / 轨迹评估 / 在线回归 / trace+成本
   [环节10] 生产级工程化  —— 可靠性 / 成本 / 安全 / 降级 / 交互体验
```

- **循环的关键**：每一步的"下一轮输入 = 上一轮输出 + 工具观察结果"。上下文会随步数**线性膨胀**，这是主循环最重要的敌人（记忆/压缩见 [环节 3](./环节03-记忆与状态详解.md)、[环节 2](./环节02-提示与上下文工程详解.md)）。
- **与 Transformer 的生命周期对照**：Transformer 的 11 环节是"训练/推理一条流水线"；Agent 的 10 环节是"一次任务的一次运行 + 让它可上线的一切支撑"。推理侧的采样/流式/KV 缓存是 Agent 每步调 LLM 的底层账单（回 [Transformer 环节 10/11](../transformer/环节10-推理解码与KV缓存详解.md)）。

### 0.3 先把"为什么长这样"记住（演进因果链）

| 历史痛点 | 对应解法（Agent 里的零件） | 归属 |
|---|---|---|
| 单次问答答不了多步任务 | 决策循环：拆成"想→做→看"多轮 | [环节 1](./环节01-决策与推理范式详解.md) |
| 纯 CoT 只"想"不"做"，纯工具只"做"不"想" | ReAct：Thought ↔ Action ↔ Observation 闭环 | [环节 1](./环节01-决策与推理范式详解.md) |
| 模型不按规矩出牌、输出乱格式 | 提示工程 + 结构化输出三层闭环（引导/校验/修复） | [环节 2](./环节02-提示与上下文工程详解.md) |
| 会话历史+观察累积撑爆上下文窗口 | 上下文裁剪/压缩/摘要；记忆分层 | [环节 2](./环节02-提示与上下文工程详解.md) / [环节 3](./环节03-记忆与状态详解.md) |
| 任务状态散落各处、不可续跑 | 显式 State + Checkpointer（状态机化） | [环节 3](./环节03-记忆与状态详解.md) / [环节 7](./环节07-编排与循环控制详解.md) |
| 模型不会自己调用工具 | Function Calling：声明 Schema + 强制/自动选择 | [环节 4](./环节04-工具调用详解.md) |
| N 个工具 N 套接入方式 | MCP：Host/Server 标准化，JDBC/USB-C 类比 | [环节 5](./环节05-工具接入协议MCP详解.md) |
| 私有数据/实时世界不在训练集里 | RAG 检索增强（知识外置） | [环节 6](./环节06-检索增强RAG详解.md) |
| 循环失控：死循环/乱序/没终态 | 状态机编排 + 步数上限 + 条件边 + interrupt | [环节 7](./环节07-编排与循环控制详解.md) |
| 一个模型干不了太宽/要隔离专业域 | 多 Agent 分工协作 | [环节 8](./环节08-多Agent协作详解.md) |
| 上线不知道它"会不会干傻事" | Agent 轨迹级评测（不是单轮 BLEU） | [环节 9](./环节09-评测与可观测详解.md) |
| LLM 不可靠 + 每步花钱 + 会被注入 | 重试/幂等/降级、成本路由、工具权限最小化 | [环节 10](./环节10-生产级工程化详解.md) |

## 2. 结构全景图（一次 Agent 请求的系统级视角）

```
                        ┌────────────────────────────────────────────┐
   用户                    │            应用层（Host / 编排运行时）       │
  输入 ───▶ 会话入口 ─────▶ │  [环节7] 状态机：State / Node / Edge        │
   (聊天/HTTP/IDE/任务)    │      ┌────────────────────────────┐        │
                        │      │ 主循环（一次=一个 Node）       │        │
                        │      │  调 LLM（[环节1]决策）          │        │
                        │      │  组装上下文（[环节2/3]）        │        │
                        │      └──────────┬─────────────────┘        │
                        │                 │ 工具调用请求               │
                        │                 ▼                           │
                        │  工具路由层：[环节4] FC 解析/校验            │
                        │      ├─▶ [环节5] MCP Client ──▶ MCP Server  │
                        │      │          （工具/数据源/子 Agent）      │
                        │      └─▶ 内置能力：RAG[环节6] / 代码执行器    │
                        └──────────────────────────────┬─────────────┘
                                                       │
                     ┌──────────────────────────────────┴─────────────┐
                     │              模型服务层（不可靠但聪明）            │
                     │  LLM API / vLLM —— 采样、流式、token 计费        │
                     │  账单与延迟来源（Transformer 环节10/11 的主题）    │
                     └────────────────────────────────────────────────┘
       横切贯穿：记忆存储（DB/向量库/Redis）· 可观测（trace）· 评测（回归）· 安全（权限）
```

看图要点（每层对应一个环节详解文档）：

- **一层（应用层）是你的代码**：所有循环/重试/权限/状态都在这里，模型只是被反复调用的"决策子程序"——这也是"Agent 应用 = 后端 + 生成式组件"的物理形态（[环节 7](./环节07-编排与循环控制详解.md)）；
- **主循环的输入永远是"上下文"**：System Prompt + 记忆 + 工具结果，怎么组装直接决定输出质量（[环节 2](./环节02-提示与上下文工程详解.md)、[环节 3](./环节03-记忆与状态详解.md)）；
- **工具的两种接入**：Function Calling 是"模型侧的协议格式"，MCP 是"应用侧的接入总线"，两者叠加而非竞争（[环节 4](./环节04-工具调用详解.md)、[环节 5](./环节05-工具接入协议MCP详解.md)）；
- **知识三态**：参数记忆（模型权重里，训练时灌入）→ 上下文记忆（当前窗口）→ 外部知识库（RAG/长期记忆，按需召回）——成本与新鲜度依次更优（[环节 6](./环节06-检索增强RAG详解.md)）。

## 3. 推荐的三种读法

1. **速览（半天）**：本文件 0 → 1 导航表 → 本文件 2 结构图 → [环节 01](./环节01-决策与推理范式详解.md) 方法对比表 + [环节 10](./环节10-生产级工程化详解.md) 可靠性命门表。
2. **原理（吃透一个能上生产的 ReAct Agent）**：按 01→05 顺序精读，把 [环节 01](./环节01-决策与推理范式详解.md) 的 ReAct 示例与 [环节 04](./环节04-工具调用详解.md) 的协议走查对照着过一遍，再补 [环节 07](./环节07-编排与循环控制详解.md) 的状态机视角——一个最小可用的 Agent 就齐了。
3. **面试冲刺**：每篇详解末尾都有"面试高频追问"与"方法对比表"，逐篇刷完即背诵版；再对着 [环节 09](./环节09-评测与可观测详解.md) / [环节 10](./环节10-生产级工程化详解.md) 想一遍"假如我上线会踩什么坑"。
