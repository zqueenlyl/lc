> 所属总揽：[Agent全链路总揽与环节拆解.md](./Agent全链路总揽与环节拆解.md) 环节 10（横切）。

> 适合人群：后端/资深读者。**这一篇是对你 9 年后端经验的总复用**——Agent 工程的每一条命门，都是你把老手艺平移过来。

---

## 1. 干什么

把"聪明但不可靠 + 每次调用都要花钱 + 会被注入 + 响应慢"的 Agent 服务，工程化成可靠、可控、安全、可运维的线上服务。

**心法（一句话贯穿全篇）**：

> **Agent 应用 = 传统后端 + 一个生成式组件。LLM 是外部不可靠服务**——你在后端对付 Redis 抖动、第三方 API、上游慢接口的所有手段，在这里全部照搬：重试、超时、限流、降级、缓存、幂等、可观测、灰度、权限最小化。**不要因为"它是 AI"就放弃后端纪律。**

---

## 2. 可靠性（把"不稳定"焊成"稳定"）

### 2.1 后端照搬对照表（面试可以直接背）

| 后端老手艺 | Agent 里的落地 | 解决 |
|---|---|---|
| 超时 | 每轮 LLM 调用 + 每工具调用都有超时；整体任务有超时 | 上游卡死不拖死整单 |
| 重试 + 退避 | 瞬时错误（429/超时/网关错）自动重试，指数退避 + jitter | 临时故障自愈 |
| 幂等 | 工具副作用操作带幂等键；重试不产生重复扣费/重复发送 | 重试 ≠ 重复执行副作用 |
| 降级 | 模型挂了走规则引擎/降级提示；高级模型失败降到低级模型 | 无 LLM 也能给底线服务 |
| 缓存 | **语义缓存**（相同/相似请求命中缓存答案）+ 前缀 KV 缓存 | 省成本降延迟（见 §3） |
| 限流 | 按用户/按 Key 限 LLM 调用与工具调用 | 防单个用户打爆预算 |
| 熔断 | 某模型/某工具持续失败 → 快速失败切备份 | 防级联雪崩 |
| 断点续跑 | Checkpointer（[环节 7](./环节07-编排与循环控制详解.md)） | 长任务崩溃不重头来 |

### 2.2 Agent 特有的可靠性点

- **重试要小心"模型重复输出"**：LLM 失败后重试时，要把"上次怎么失败的"也喂回去（Reflexion 式，[环节 1](./环节01-决策与推理范式详解.md)），否则同输入大概率同输出，重试=白烧钱；
- **外部依赖记账**：工具是真实副作用，成功了就是成功了——**成功后不要因为后续步骤失败而"回滚"或重跑整条工具链**，除非工具本身支持事务；
- **输出做防御性校验**：结构化输出永远过 Schema 校验（[环节 2](./环节02-提示与上下文工程详解.md)），不能直接信任模型。

## 3. 成本工程（账单长在上下文里）

### 3.1 先看懂钱花在哪（成本结构）

| 成本项 | 来源 | 杠杆 |
|---|---|---|
| **上下文常驻费** | 每轮都把 System + 历史 + 工具结果重新发送（`prompt_tokens` 随轮数累积） | 上下文压缩、记忆外置（[环节 2](./环节02-提示与上下文工程详解.md)/[环节 3](./环节03-记忆与状态详解.md)）——**Agent 成本最大头** |
| 采样轮数 | 循环每转一圈收一次费 | 步数上限、更好的决策范式（[环节 1](./环节01-决策与推理范式详解.md)） |
| 重试/反思 | 重试 = 重复全轮上下文 | 限定重试次数，注入失败经验 |
| 检索/精排 | embedding + rerank 调用 | 粗排 top-K 控量（[环节 6](./环节06-检索增强RAG详解.md)） |
| 输出 token | 模型输出（尤其 Thought 很长） | 控制 verbose 输出、只给需要的层 |

### 3.2 四大成本手段

1. **模型分级路由**：按任务难度路由——简单任务走便宜小模型（如摘要、格式化、实体抽取），复杂规划走旗舰；判断器本身可以是便宜模型（路由成本 < 全程旗舰）。**ROI 最高的一招**；
2. **语义缓存**：相同/相似请求（embedding 距离低于阈值）直接返回缓存答案——FAQ、重复查询场景省 50%+；
3. **上下文瘦身**：历史摘要 + 记忆外置 + 工具结果截断（承接 [环节 2](./环节02-提示与上下文工程详解.md)/[环节 3](./环节03-记忆与状态详解.md)）——降常驻费；
4. **批处理**：可并行的子任务合并请求（如一次让模型处理多个条目，别逐条调）。

### 3.3 "什么时候微调"（成本视角的选型）

| 手段 | 适用 | 成本/维护 |
|---|---|---|
| Prompt/Few-shot/记忆 | 大部分场景（改提示即生效） | 0，首选 |
| RAG | 知识型（新鲜/私有/溯源） | 索引维护成本，无训练成本 |
| **微调** | ① 格式/语气/领域"风格"长期固定 ② 要压提示长度省每轮 token ③ 模型学不会你的输出协议 | 训练 + 数据 + 回归（贵） |

**结论**：知识型问题别微调（用 RAG）；风格/格式/长上下文压缩型才值得微调；微调前先算账——省下的每轮 token 要多久回本。

## 4. 安全（Agent 攻击面比传统接口大一个维度）

| 风险 | 形态 | 防线 |
|---|---|---|
| **Prompt 注入** | 用户/网页/工具内容夹带"忽略指令…" | 不可信内容隔离（[环节 2](./环节02-提示与上下文工程详解.md)）+ 输出检测 |
| **工具滥用/越权** | 模型被诱导调用敏感工具 | 宿主鉴权（模型只是建议者，[环节 4](./环节04-工具调用详解.md)）+ 权限最小化 + 高危人工确认（[环节 7](./环节07-编排与循环控制详解.md) interrupt） |
| **数据泄露** | 检索/记忆喂给无权用户 | 检索链权限过滤（[环节 6](./环节06-检索增强RAG详解.md)）+ 脱敏 |
| **MCP 后门** | 恶意 Server | 只接可信 Server、能力审计（[环节 5](./环节05-工具接入协议MCP详解.md)） |
| **越狱/隐私** | 诱导输出系统提示词/他人数据 | 输出过滤 + 系统提示词不进对话上下文 + 审计 |

**安全基线五件套**：① 工具权限最小化（按 Agent 角色给）；② 敏感操作人工确认；③ 全量审计日志（谁/何时/调了啥/读了啥，与 [环节 9](./环节09-评测与可观测详解.md) trace 共用）；④ 数据脱敏（日志/上下文中密钥个人数据打码）；⑤ 权限模型：模型/检索/工具三处都按"用户能干什么"约束，**不信任模型自觉**。

## 5. 交互体验（长任务的用户体验）

- **流式**：SSE / WebSocket，打字机式吐字，TTFT 控制在感知阈值内（首字即响）；
- **长任务异步化**：>30s 的任务不能占着 HTTP——用任务队列 + 任务 ID，前端轮询/订阅进度（MQ 手艺平移，见知识地图 §3.5）；
- **进度可视化**：把"规划/调工具/查资料"映射成用户可读的步骤卡（别暴露原始 Thought 洪水，[环节 1](./环节01-决策与推理范式详解.md)）；
- **可打断/可纠偏**：用户中途可插话改需求（Human-in-the-loop 通道，[环节 7](./环节07-编排与循环控制详解.md)）；
- **优雅失败**：失败了告诉用户"做到哪、卡在哪、已保存什么、怎么重试"，别只抛一句"出错了"。

## 6. 上线流程（把 Agent 当正式服务发布）

灰度（小流量 → 观察在线质量分/成本/延迟 → 放量）→ A/B（功能收益归因）→ 回滚（版本化图 + Checkpointer，秒级回退）→ 看板（成功率/成本/延迟/终止原因，持续盯漂移）——全部依赖 [环节 9](./环节09-评测与可观测详解.md) 的评测与观测资产。

## 7. 方法对比总表（后端视角的 Agent 工程）

| 工程问题 | 传统后端答案 | Agent 侧特别提醒 |
|---|---|---|
| 上游不稳 | 重试/熔断/降级 | 重试要喂"上次失败经验"，否则同输入同输出 |
| 状态恢复 | 状态机 + 持久化 | Checkpointer + 幂等工具 |
| 成本 | 资源配额/监控 | 上下文常驻费是大头，模型分级路由 ROI 最高 |
| 安全 | 鉴权/审计/最小权限 | +Prompt 注入防护，模型永不直接执行 |
| 测试 | 单测/E2E | 分层 Eval（[环节 9](./环节09-评测与可观测详解.md)），轨迹也是断言对象 |
| 发布 | 灰度/回滚 | 图 + Prompt 全版本化，无评测不放量 |

## 8. 工程红线（必守）

1. **模型永不直接执行任何事**：执行前必经宿主校验 + 鉴权（参数校验、权限、幂等）。
2. **LLM 调用与工具调用全部有超时与预算**（步数/token/金额），单用户打爆预算要能熔断。
3. **敏感信息不进日志/上下文**（密钥、个人数据一律脱敏或外置引用）。
4. **无评测不发布**：Prompt/图/工具/检索的改动全走回归（[环节 9](./环节09-评测与可观测详解.md)）。
5. **降级路径必须真实存在**：模型全挂时，你的服务还能给用户一个体面结果（规则引擎/缓存/明确报错），不许静默坏。

## 9. 面试高频追问

1. Agent 为什么比普通后端更难上生产？→ 生成式输出不可控 + 每步花钱 + 攻击面多（注入/工具/数据）+ 评测难；解决的钥匙正是后端老手艺 + 评测分层。
2. 上下文常驻费怎么降？→ 模型分级路由、语义缓存、上下文瘦身（摘要/记忆外置/结果截断）、批处理。
3. 模型和工具哪一层防注入最有效？→ 工具宿主鉴权是底线（模型只是建议者）；输入隔离是前端，两者都要。
4. 什么时候该微调而不是 RAG/Prompt？→ 风格/格式长期固定、要压每轮 prompt 长度、模型学不会输出协议时；知识型问题走 RAG。
5. Agent 服务怎么灰度？→ 影子模式陪跑比轨迹 → 小流量金丝雀看在线质量分 → 放量；配版本化图与秒级回滚。
