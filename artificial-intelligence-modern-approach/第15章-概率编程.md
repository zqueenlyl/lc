## 0. 本章要解决的问题

贝叶斯网络的可能世界是"给变量赋值"。一阶概率模型的可能世界是一阶逻辑的模型（对象、关系、解释），这个集合是**无限**的：式 (15.1) 的求和可能算不完，无限世界上的分布也很难写全。

本章分四步把表示抬高，同时仍要得到**唯一、一致**的分布：

| 节 | 提升点 |
|---|---|
| 15.1 关系概率模型 | 用**数据库语义**（唯一名称 + 域封闭）得到有限世界；用带类型的依赖语句代替手工画网。**不做**封闭世界假设 |
| 15.2 开宇宙概率模型 | 对象**是否存在、是不是同一个**都可以不确定 |
| 15.3 追踪复杂世界 | 多个对象产生观测时的**数据关联**（身份不确定性的时序版） |
| 15.4 作为概率模型的程序 | 可能世界 = 程序的**执行轨迹** |

## 15.1 关系概率模型

数据库语义：常元满足**唯一名称**，并且**域封闭**（没有未命名的对象）。这样可能世界有限，符号到对象的映射没有不确定性。这样定义的模型叫**关系概率模型（RPM）**。和数据库语义的关键差别：RPM **不做封闭世界假设**（不能把未知事实一律当成假）。

### 15.1.1 语法与语义

正文例子是**网上书店的荐书**，不是学生-课程。一个顾客 `C1` 荐一本书 `B1` 时，网是 `Honest(C1)`、`Kindness(C1)`、`Quality(B1)` → `Recommendation(C1, B1)`。顾客和书一多，手工画网不现实，但结构重复。

类型是 `Customer` 与 `Book`。类型签名：

| 函数 | 签名 |
|---|---|
| `Honest` | `Customer → {true, false}` |
| `Kindness` | `Customer → {1,2,3,4,5}` |
| `Quality` | `Book → {1,2,3,4,5}` |
| `Recommendation` | `Customer × Book → {1,2,3,4,5}` |

每个函数一条**依赖语句**（参数是逻辑变量）：

```
Honest(c) ∼ ⟨0.99, 0.01⟩
Kindness(c) ∼ ⟨0.1, 0.1, 0.2, 0.3, 0.3⟩
Quality(b) ∼ ⟨0.05, 0.2, 0.4, 0.2, 0.15⟩
Recommendation(c, b) ∼ RecCPT(Honest(c), Kindness(c), Quality(b))
```

`RecCPT` 有 `2×5×5 = 50` 行、每行 5 个数。诚实推荐：质量 `q`、善意 `k` 时，分数在 `[⌊(q+k)/2⌋, ⌈(q+k)/2⌉]` 上均匀。

**基本随机变量** = 每个函数用该类型全部已知对象实例化一遍。`C` 个顾客、`B` 本书：`2^C · 5^{C+B+BC}` 个可能世界。一千万本书、十亿顾客大约是 `10^{7×10^{15}}` 个世界，参数仍**不到 300 个**（大多在 `RecCPT` 里）。

**上下文特定独立**：不诚实的顾客忽略质量和善意：

```
Recommendation(c, b) ∼ if Honest(c) then HonestRecCPT(Kindness(c), Quality(b))
                        else ⟨0.4, 0.1, 0.0, 0.1, 0.4⟩
```

推断引擎**不一定知道** `Honest(c)` 的值。再加一层：诚实且是作者的粉丝就一定打 5 分（`Exactly(5)`）。`Author(b)` 未知时要考虑所有可能作者——`Author(B2)` 像多路选择器，决定 `Fan(C1, A1)` 还是 `Fan(C1, A2)` 影响推荐。这种"依赖结构本身不确定"叫**关系不确定性**。

依赖必须无环，并且通常要良基（不能有无限祖先链）。

### 15.1.2 例子：评估玩家的技能等级（TrueSkill）

Elo：初学者大约 **800**，世界冠军通常在 **2800** 以上。贝叶斯评级写成 RPM：

```
Skill(i) ∼ N(μ, σ²)
Performance(i, g) ∼ N(Skill(i), β²)
Win(i, j, g) = if Game(g, i, j) then (Performance(i, g) > Performance(j, g))
```

`β²` 是单场发挥相对技能的方差。胜负比的是**这场发挥**，不是技能差本身。

团队赛（TrueSkill 用的就是这个模型）：`TeamPerformance(t, g) = Σ_{i∈t} Performance(i, g)`。个人发挥看不见，但只要各场阵容在变，仍能估计技能。TrueSkill 配一个高效近似推断，每天服务**数亿**用户。

给定选手、比赛和部分赛果，推断每个选手技能的后验，以及再赛一场的可能结果。【延伸·非原著：笔记里"用来匹配水平相近的对手"是用途推断，正文写的是后验技能和下一场结果。】

### 15.1.3 关系概率模型中的推断

- **落地 / 展开（grounding / unrolling）**：按已知常元把依赖语句展开成普通贝叶斯网络，相当于一阶逻辑的命题化。网可能极大；未知关系（如 `B2` 的作者）会让一些节点父节点很多
- 不是查询或证据的**祖先**的变量，以及在证据下与查询条件独立的变量，都不用实例化
- 展开后很多因子相同。缓存相同因子，大网络上曾有**三个数量级**的加速
- **MCMC**：每个状态里关系结构是确定的（例如已经选定 `Author(B2)`），关系不确定性不增加网的复杂度；转移会改关系结构，从而改依赖结构
- **提升推断（lifted inference）**：一个提升因子代表一整族只是常元不同的基因子，一步顶许多步基推理。细节超出本书范围

【延伸·非原著：板模型（plate）不是本章正文的说法。】

## 15.2 开宇宙概率模型

RPM 假定相关对象的集合已知，而且观测已经正确对到了给它们命名的常元上。很多场景这两条都不成立。书店的例子：一个"逻辑上的书"可以有多个 ISBN；不诚实顾客可以有成千上万个登录号（**女巫攻击，sybil attack**）。于是同时有

- **存在不确定性**：数据背后真正的书、真正的顾客有哪些
- **身份不确定性**：哪些逻辑项其实指同一个对象

开宇宙概率模型（OUPM）用一阶逻辑的标准语义（图 15.1 上半），在无限可能世界上给出唯一、一致的分布。【延伸·非原著：BLOG 是历史上第一种开宇宙形式语言，写在章末文献注记里，不是 15.2 正文的语法。】

### 15.2.1 语法与语义

生成步骤可以**往世界里加对象**，个数和类型可以依赖已经生成的对象。做法是**数量陈述（number statement）**，给出各类对象个数的条件分布，不是给预先点名的对象一个"以概率 p 存在"。

荐书域里把顾客和登录号分开（做推荐的是登录号）：

```
#Customer ∼ UniformInt(1, 3)
#Book ∼ UniformInt(2, 4)
#LoginID(Owner = c) ∼ if Honest(c) then Exactly(1) else UniformInt(2, 5)
```

`Owner` 是**起源函数（origin function）**：说明这个数量陈述生成的对象从哪来。没有起源函数的类型，对象起源为空，例如 `⟨Customer, , 2⟩` 是该陈述生成的第 2 个顾客。有起源时，对象记下起源，例如某顾客的第 3 个登录号。

个数不必有先验上界。非负整数上最常用的是 **Poisson(λ)**：`P(X=k) = λᵏ e^{−λ} / k!`，方差也是 `λ`。均值一百万只蚂蚁时，标准差只有一千（0.1%）。大数量更常用**离散对数正态**；**数量级分布** `OM(3, 1)` 的均值是 `10³`，标准差一个数量级，大头落在 `10²` 到 `10⁴` 之间。

**数量变量**记录每种起源下有多少对象；基本随机变量仍给谓词和函数赋值。可能世界 = 全部数量变量 + 基本随机变量的取值。按拓扑序采样；图 15.4 那个世界的概率是各采样值概率之积，`1.2672×10^{−11}`。每个对象带起源，保证每个世界**恰好一条**生成序列，否则概率会变成对所有生成序列的组合求和。

可以有无限多个随机变量（Poisson、递归依赖、整数/字符串等无限类型）。良构性禁止环和无限倒退的祖先链；一般不可判定，但有容易检查的充分条件。

### 15.2.2 开宇宙概率模型中的推断

把隐含的贝叶斯网络全部展开再做精确推断不现实。用 **MCMC**。一步转移不仅可以改关系和函数，还可以**增加或删去对象**，以及**改变常元的解释**。相邻世界的概率比只依赖被改变量周围**常数大小**的子图，Gibbs 或 Metropolis–Hastings 大多是常数时间。逻辑查询也可以增量求值。

世界可以无限大（图 15.9 里飞机状态 `X(a,t)` 对无界架数、每个时刻都是无穷序列）。因此采样的是**部分世界**：证据和查询变量的祖先的一个最小自支撑实例化。最后一次观测（或查询时刻）之后的 `X(a,t)` 无关，只保留无穷序列的有限前缀。

### 15.2.3 例子

标准用法有三块：模型、证据、查询。查询可以带自由逻辑变量；答案是自由变量每种替换的后验联合。

**引文匹配**（图 15.5）。证据是从 PDF 里刮下来的引用字符串，没有对象标识符，还有拼写和语法错误。要问的是**身份**：下面两条是不是同一篇论文（答案是同一篇）。2002 年 CiteSeer 曾报告 Russell 和 Norvig 写了 **120 本以上**不同的书。简化模型假定每篇论文一个作者：

```
#Researcher ∼ OM(3, 1)
Professor(r) ∼ Boolean(0.2)
#Paper(Author = r) ∼ if Professor(r) then OM(1.5, 0.5) else OM(1, 0.5)
Text(c) ∼ HMMGrammar(Name(Author(CitedPaper(c))), Title(CitedPaper(c)))
```

只给引用字符串，挑最可能解释的错误率比 CiteSeer **低 2 到 3 倍**。引用越多，对每条的分析越准，因为分析必须在论文事实上一致。

**核禁试监测（NET-VISA）**。全面禁核试条约要找出地球上超过某震级的全部地震事件。IMS 基于百年地震学的自动处理，漏检大约 **30%**。模型（图 15.6）直接写地球物理：`#SeismicEvents ∼ Poisson(T·λ_e)`，`EarthQuake(e) ∼ Boolean(0.999)`，地震深度 `UniformReal(0, 700)`、非地震 `Exactly(0)`。证据是从波形里抽出的检测，其中 **90% 是虚警**；查询通常是最可能的事件公报。2009 年，震级 3–4 的 27294 个事件里，联合国 SEL3 漏了 **27.4%**，NET-VISA 漏了 **11.1%**；与密集区域台网比，比专家终报多找出至多 **50%** 的真实事件。2018 年 1 月 1 日起进入 CTBTO 监测流水线。2013 年 2 月 12 日朝鲜核试验：地下试验入口距 NET-VISA 估计 **0.75 km**。

两个例子结构相同：未知对象（论文、地震）按某个物理过程产生知觉；知觉的来源有歧义；把多条知觉归到同一个未知对象上，对象的性质就估得更准。观测不到的对象仍可能被推断出来（天王星的观测导致发现海王星）。

## 15.3 追踪复杂世界

第 14 章只处理了原子表示（HMM）和因子分解表示（DBN、卡尔曼滤波），适合**单个**对象。两个或更多对象产生观测时，多出来的是：哪次观测是哪个对象产生的。这就是 §15.2 的**身份不确定性**，放到时间上；控制论文献里叫**数据关联**。

### 15.3.1 例子：多目标追踪

最初的背景是雷达跟踪多个目标：每个时刻屏幕上有多个光点，但不知道时刻 `t` 的光点对应 `t−1` 的哪一个。

先假定**恰好两架**飞机 `A1`、`A2`，它们是**保证对象**（一定存在、彼此不同，且没有别的飞机）——这一段对飞机而言就是 RPM 的数据库语义。位置 `X(a,t)`，`t=0` 时先验 `InitX()`，转移是线性高斯；每架飞机每个时刻**恰好一个**光点：

```
guaranteed Aircraft A1, A2
X(a, t) ∼ if t = 0 then InitX() else N(F X(a, t−1), Σ_x)
#Blip(Source=a, Time=t) = 1
Z(b) ∼ N(H X(Source(b), Time(b)), Σ_z)
```

和普通卡尔曼滤波的差别：两个对象都在产生读数，所以 `Source(b)` 不确定。`n` 个对象、`T` 个时刻，把光点分给飞机有 **`(n!)^T`** 种。

真实情况更糟：虚警（杂波）、检测失败、新目标出现、旧目标消失（图 15.8(d)、图 15.9）。新飞机进入率 `λ_a`（Poisson），每步离场概率 `α_e`，虚警率 `λ_f`，检测概率依赖当前位置。

精确滤波会变成指数多个分布的混合（和切换卡尔曼滤波同一个原因），没有已知的高效精确算法。近似：

| 方法 | 做法 |
|---|---|
| **最近邻滤波** | 反复把"预测位置最近的观测"配成一对。目标分得开、预测和观测误差都小时才好 |
| **匈牙利算法** | 在 `n!` 种分配里选出当前观测联合概率最大的那一个，多项式时间 |
| 每步只承诺一个最佳分配 | 错一次，下一步预测就偏，然后连续错 |
| **粒子滤波** | 维持一大批当前分配 |
| **MCMC** | 在分配历史上游走，可以改口（图 15.8(b–c) 就是状态空间里的两个状态） |

**Rao-Blackwellization**（第 14 章）：关联假设一旦给定，每架飞机的滤波就是对分给它的观测序列跑一个卡尔曼滤波，不必再采样状态序列。改关联时只重算观测变了的对象。当时的 MCMC 数据关联可以实时处理**几百个**对象。

### 15.3.2 例子：交通监控

图 15.10：加州萨克拉门托 99 号公路上相距大约 **两英里** 的上游、下游监控摄像头，同一辆车被框出来。两个目标：（1）当前路况下从一处到另一处要多久；（2）**需求**——特定时刻、一周里的哪一天，任意两点之间有多少车。要在很多摄像头、每小时**数万辆**车的范围内做数据关联。

虚警来自移动的影子、铰接车辆、水坑反光；漏检来自遮挡、雾、黑夜、反差不够。车从可能没监控的匝道进出。同一辆车在不同相机下外观会因光照和姿态大变；堵车时转移模型也在变。相机离得远、车又密时，预测误差远大于车与车的典型间距。尽管如此，现代数据关联已经能在真实路网上估计这些交通参数。

没有数据关联就无法把同一对象的多次观测合在一起。对象之间还有复杂交互时，要把数据关联和 §15.2 的关系 / 开宇宙模型合起来用——这仍是研究中的问题。

## 15.4 作为概率模型的程序

概率模型可以用**带随机源的可执行代码**来定义。可能世界是**执行轨迹**；轨迹的概率是走出这条轨迹所需随机选择的概率。这样的 PPL 继承底层语言的数据结构、递归，有的还有高阶函数。许多 PPL 是计算通用的：停机的概率图灵机能采样的分布，它们都能表示。

【延伸·非原著：把接口写成 `sample` / `observe` 是后来一些 PPL 的习惯。本章正文的随机选择写成 `∼`，证据是在推断时拿轨迹去对，而不是在图 15.11 的生成程序里写一条 `observe`。】

### 15.4.1 例子：阅读文本

读被水渍糊住、模糊，或纸张老化出斑点的文字；也可用来破解某些 CAPTCHA。图 15.11 的生成程序：

```
GENERATE-IMAGE: letters ← GENERATE-LETTERS(10); return RENDER-NOISY-IMAGE(letters, 32, 128)
GENERATE-LETTERS(λ): n ∼ Poisson(λ)；每个 letters[i] ∼ UniformChoice({a,b,c,…})
RENDER: noise variance ∼ UniformReal(0.1, 1)；每个像素 ∼ N(干净像素, noise variance)
```

两段：生成字母序列；用现成图形库渲染成带噪声的模糊图像。

### 15.4.2 语法与语义

**生成程序**里每一次随机选择定义模型中的一个随机变量 `Xᵢ`。轨迹 `ω = {xᵢ}`，`P(ω) = Πᵢ P(xᵢ | x₁,…,xᵢ₋₁)`，和 OUPM 里世界上的分布同一想法。OUPM 可以改写成生成程序：为每条数量陈述和每个因此存在的基本随机变量做随机选择，并自己建出对象、函数、关系的数据结构。

图 15.12 右上角那张含 `ocflwe` 的图，展开成贝叶斯网络有 **4104** 个节点：`n` 1 个、`letters[i]` 6 个、噪声方差 1 个、像素 4096 个。随机选择的个数事先没有上界，取决于 `n`，所以这是开宇宙模型。

### 15.4.3 推断结果

图 15.13：加性噪声图像上，三次独立 MCMC，每次 **25** 步。三次都得到字母序列 `uncertainty`，后验很集中。

再模糊到人也不好读（图 15.14）：字母**个数**是对的，但第一个字母被认成 `q`，后面十个里有五个不确定。可能是链已经混合、这就是真后验；也可能没混合——300 条链、每条 2.5 万或 2500 万步，也许会显示首字母更可能是 `u`。蒙特卡罗没有万无一失的收敛检验。改进可以是更好的提议分布、用图像自下而上的线索做初始假设，或者改进模型（下一小节的字母对）。

### 15.4.4 改进生成程序以纳入马尔可夫模型

PPL 是模块化的，改模型不必改推断器。图 15.15 用**字母二元文法**：`n ∼ Poisson(λ)` 之后，每个字母按上一个字母的转移分布抽取，转移概率由一份英语词表估计。图 15.12 下半是这个程序采出的图，比独立字母更像能读的串。图 15.14 右侧是把它用到高噪声图像上的结果，更接近生成轨迹，但仍有不确定。

【延伸·非原著：掷骰子直到某结果、对算术表达式做贝叶斯推断、随机递归数据结构，不是 15.4.4 的例子。】

### 15.4.5 生成程序中的推断

精确推断通常贵到不能做，或根本不可能。

| 方法 | 书中的说法 |
|---|---|
| **拒绝采样** | 跑程序，只留与证据一致的轨迹，数查询答案 |
| **似然加权** | 沿轨迹把观测到的值的概率乘进权重。数据在模型下相当可能时才好用 |
| **MCMC** | 采样并修改执行轨迹。改掉一条 `if` 的结果可能让轨迹的后半截作废，要专门处理 |
| **提升推断** | 同 15.1，有时能从原则上改变哪一类问题可解 |
| **编译** | 把 13.4.3 的编译想法用到 OUPM 和 PPL 上，通常快 **2 到 3 个数量级**。另有专用硬件：低精度概率、细粒度并行，速度和能效 **100–10,000 倍** |
| **学习提议** | 自适应提议分布；也可以用第 21 章的深度学习，在模型自己生成的合成数据上，训练重要性采样的提议分布 |

通用 MCMC 常常太慢，需要专用提议；近期工作让用户自己定义提议，使 PPL 推断能赶上手写的专用算法。

若底层程序对所有输入和随机选择都停机，推断是否仍不可判定？**是，但只在无限精度的连续随机变量上**：可以写出一个可计算的概率模型，其推断编码停机问题。有限精度、再加上实际中常用的光滑分布，推断仍可判定。

## 小结

1. **关系概率模型**用数据库语义（唯一名称、域封闭，但不做封闭世界假设）和依赖语句定义有限的可能世界。基本随机变量是谓词/函数在已知对象上的全部实例。
2. **开宇宙概率模型**允许存在不确定性与身份不确定性。个数由**数量陈述**给出；对象是带起源的生成历史，使每个世界恰好对应一条生成序列。
3. 多个对象产生观测时，困难是**数据关联**。`n` 个对象、`T` 步有 `(n!)^T` 种分配；实用算法是最近邻、匈牙利算法、粒子滤波和 MCMC，常配合 Rao-Blackwellization。
4. **生成程序**把概率模型写成可执行代码。可能世界是执行轨迹，`P(ω)` 是轨迹上随机选择的概率之积。
5. 生成程序上的通用推断以拒绝采样、似然加权和轨迹上的 MCMC 为主；编译可带来两到三个数量级的加速。无限精度连续变量上，推断可以不可判定。
