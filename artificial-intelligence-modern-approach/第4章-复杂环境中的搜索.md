## 0. 本章要解决的问题

第 3 章处理的是**完全可观测、确定性、静态、已知**的环境，解是一条动作序列。本章逐条放宽这些假设：4.1–4.2 只关心终态而不关心到达它的路径（离散 / 连续）；4.3 放宽确定性，解变成条件规划；4.4 放宽可观测性，改到信念状态空间上搜索；4.5 环境完全未知，只能边探索边搜索。

## 4.1 局部搜索与最优化问题（Local Search and Optimization Problems）

有时我们只在乎**终态**而不在乎怎么走到那里：8 皇后只要求出一个合法摆法（知道摆法，构造出产生它的步骤是平凡的）；集成电路设计、厂房布局、作业车间调度、自动程序设计、电信网络优化、种植规划、投资组合管理同样如此。**局部搜索**（local search）从起始状态走向邻域状态，**不记录路径，也不记录已到达状态的集合**，因此不是系统性的——它可能永远不去探索真正有解的那片空间。两个关键优势：(1) **内存占用极少**；(2) 在很大甚至**无限**的状态空间中常能找到说得过去的解，而系统性算法在那里根本不适用。它也能解**最优化问题**（optimization problem）——按某个**目标函数**（objective function）找最佳状态。

把状态铺在**状态空间地形**（state-space landscape）上理解（Figure 4.1）：每个点的"海拔"由目标函数值给出。海拔对应**目标函数** → 找最高的峰，即**全局极大值**（global maximum），这个过程叫**爬山**（hill climbing）；海拔对应**代价** → 找最低的谷，即**全局极小值**（global minimum），叫**梯度下降**（gradient descent）。图上还标出：局部极大值（local maximum）、"平坦的"局部极大值、**山肩**（shoulder）。

### 4.1.1 爬山搜索

Figure 4.2 的爬山搜索只维护一个当前状态，每轮走向**值最高的邻接状态**，即沿**最陡上升**（steepest ascent）方向前进；到达没有邻居更高的"峰"时终止。

```
function HILL-CLIMBING(problem) returns a state that is a local maximum
    current ← problem.INITIAL
    while true do
        neighbor ← a highest-valued successor state of current
        if VALUE(neighbor) ≤ VALUE(current) then return current
        current ← neighbor
```

- 爬山**不向前看**当前状态的直接邻居之外——就像在浓雾中、且患了失忆症的情况下去攀登珠穆朗玛峰顶。
- 可以把启发式**代价**函数 `h` 的相反数当作目标函数，这样就会局部爬到"到目标的启发距离最小"的状态。
- 爬山又称**贪婪局部搜索**（greedy local search）：抓到一个好邻居就走，不思考下一步去哪——贪婪虽是七宗罪之一，贪婪算法却往往表现不错。

> ⚠️ 待核：印刷版 Figure 4.2 用的是 `VALUE(neighbor) ≤ VALUE(current)`，即**值相等时也停下**，不会自动做侧向移动；这与 4.1.1 后文"允许侧向移动"的变体是两件事，不要混淆。

**8 皇后示例（Figure 4.3）**——采用**完整状态形式化**（complete-state formulation）：每个状态都包含解的**全部组成部分**，只是未必都在正确的位置上。

| 要素 | 设定 |
|---|---|
| 状态 | 棋盘上 8 个皇后，**每列一个** |
| 初始状态 | 随机选取 |
| 后继 | 把某一个皇后移到**同一列**的另一格 → 每个状态有 `8 × 7 = 56` 个后继 |
| 启发式代价 `h` | 正在互相攻击的**皇后对数**，只有解才为 `0` |
| 攻击判定 | 两个棋子在同一条线上就算攻击，**即使中间隔着别的棋子** |

Figure 4.3(b) 的状态 `h = 17`；它的全部后继中有 **8 个并列最优**，都是 `h = 12`，爬山算法会从中任选一个。从该状态出发只要 **5 步**就能到达 Figure 4.3(a) 那个 `h = 1`、非常接近解的状态。

**爬山会被卡住的三种地形**

| 地形 | 说明 |
|---|---|
| **局部极大值** | 比每个相邻状态都高，但低于全局极大值；算法被吸到峰顶后就无路可走。**Figure 4.3(a) 就是一个局部极大值**（即代价 `h` 的局部极小值）：单独移动任何一个皇后都会让情况变糟 |
| **山脊**（ridge） | Figure 4.4：造成一串**互不直接相连**的局部极大值，从每个局部极大值出发所有可用动作都指向下坡。这类拓扑在低维空间（如二维平面）常见；但在几百乃至几千维的空间中这个直觉图像**不成立**——通常总能找到若干维度让人逃出去 |
| **高原**（plateau） | 平坦区域，可能是**平坦的局部极大值**（无上坡出口），也可能是**山肩**（仍可继续前进）。爬山搜索会在高原上迷失打转 |

**关键数据（p.113）**：从随机生成的 8 皇后状态出发，最陡上升爬山 **86% 的时间被卡住，只解决 14%** 的实例；不过它很快——成功时平均 **4 步**、卡住时 **3 步**——对一个 `8⁸ ≈ 1700 万` 个状态的空间不算差。到达高原时继续走、即允许**侧向移动**（sideways move），但**限制连续侧向移动的次数**（如 100 次后停下），把解决比例从 **14% 提高到 94%**；成功是有代价的：成功实例平均约 **21 步**，失败实例约 **64 步**。

**常见变体**：**随机爬山**（stochastic hill climbing）从所有上坡移动中随机选一个，选择概率可随陡度变化，通常收敛更慢但某些地形上能找到更好的解；**首选爬山**（first-choice hill climbing）随机生成后继直到出现更好的就走，当状态有成千上万个后继时是好策略；**随机重启爬山**（random-restart hill climbing）"一次不成功，就再试、再试"。

随机重启爬山**以概率 1 完备**——它迟早会把一个目标状态生成为初始状态。若每次成功概率为 `p`，期望重启次数为 `1/p`：8 皇后**不允许**侧向移动时 `p ≈ 0.14`，约需 **7 次**迭代，期望步数 ≈ **22 步**；**允许**侧向移动时平均 `1/0.94 ≈ 1.06` 次迭代，步数 `(1 × 21) + (0.06/0.94) × 64 ≈ 25`。即使是**三百万皇后**也能在数秒内求解（脚注 1：Luby et al. (1993) 建议固定步数后重启，并证明这可能比让每次搜索无限进行下去高效得多）。

> **注意**：成败极度依赖地形形状。局部极大值和高原少时，随机重启爬山很快能找到好解；真实问题的地形则常像"平坦地板上散落着一群秃顶豪猪，每根豪猪刺的尖端还住着微型豪猪"。**NP-hard 问题通常有指数多个局部极大值**可以卡住你。尽管如此，少量重启后常能找到一个相当不错的局部极大值。

### 4.1.2 模拟退火

从不做"下坡"移动的爬山算法永远容易卡在局部极大值；而完全不看值、随机走向后继的**纯随机游走**最终会撞上全局极大值，却极其低效。把两者结合以兼顾效率与完备性，就得到**模拟退火**（simulated annealing）——冶金学中，退火是把金属和玻璃加热到高温再逐渐冷却，使其达到低能晶态。

**直觉图像**：把视角切换到梯度下降（最小化代价），想象要把一个乒乓球送进一个非常崎岖的表面上最深的那条裂缝。只让球滚，它会停在某个局部极小值；摇动表面可以把球弹出来，也许弹进更深的局部极小值并在那里待更久。诀窍是**摇得刚好够**把球从局部极小值里弹出来，又不至于把它从全局极小值里摇出来——模拟退火的做法就是**开始使劲摇（高温），然后逐渐减小强度（降温）**。算法结构（Figure 4.5）与爬山类似，但**不挑最好的移动，而是随机挑一个**：让情况变好就**总是接受**；否则以小于 1 的概率接受。该概率随移动的"坏度"——评价值恶化的量 `∆E`——**指数下降**，也随"温度" `T` 下降而下降：坏移动在 `T` 高的初期更容易被允许，随 `T` 降低越来越不可能。若调度把 `T` 足够慢地降到 0，则由玻尔兹曼分布 `e^{∆E/T}` 的性质，全部概率集中到全局极大值上，算法以趋近 1 的概率找到它。

```
function SIMULATED-ANNEALING(problem, schedule) returns a solution state
    current ← problem.INITIAL
    for t = 1 to ∞ do
        T ← schedule(t)
        if T = 0 then return current
        next ← a randomly selected successor of current
        ∆E ← VALUE(current) – VALUE(next)
        if ∆E > 0 then current ← next
        else current ← next only with probability e^{−∆E/T}
```

> ⚠️ 待核：上面是本项目 PDF（p.115）的**原样**。官方勘误页 <https://aima.cs.berkeley.edu/errata/aima-115.pdf> 把指数中的负号**去掉**，作 `e^{∆E/T}`。按"把 `VALUE` 视作待最小化的**能量／代价 `E`**"来读，勘误版是自洽的：`∆E = VALUE(current) − VALUE(next) > 0` 表示**变好**，必接受；否则 `∆E < 0`，以 `e^{∆E/T} < 1` 的概率接受。印刷版多出的负号会让接受概率大于 1。建议按勘误版理解，但以自己手上的印次为准。

模拟退火从 1980 年代起被用于求解 **VLSI 布局**问题，并广泛应用于工厂调度和其他大规模优化任务。

### 4.1.3 局部束搜索

只在内存里保留一个节点，似乎是对内存限制过于极端的反应。**局部束搜索**（local beam search）保留 `k` 个状态：从 `k` 个随机生成的状态开始，每步生成这 `k` 个状态的**全部**后继；若其中任何一个是目标就停止；否则从完整后继清单中挑出**最好的 `k` 个**并重复。

乍看它不过是把 `k` 次随机重启**并行**跑而不是串行跑，其实两者很不一样：随机重启中每次搜索**彼此独立**；局部束搜索中并行线程之间**传递有用信息**——效果上，产生最好后继的状态在对其他状态喊**"过来这边，这边的草更绿！"** 算法迅速放弃没有产出的搜索，把资源挪到进展最大的地方。

它的毛病是 `k` 个状态**缺乏多样性**——可能挤在状态空间的一小片区域，使搜索退化成慢 `k` 倍的爬山。变体**随机束搜索**（stochastic beam search，类比随机爬山）可缓解：不选前 `k` 个后继，而是**按后继值的比例**分配被选中的概率，从而增加多样性。

### 4.1.4 进化算法

**进化算法**（evolutionary algorithms）可以看作随机束搜索的变体，只是显式地以生物学的自然选择作隐喻：存在一个由个体（状态）组成的**种群**（population），最适应（值最高）的个体产生**后代**（后继状态）去填充下一代，这个过程叫**重组**（recombination）。形态繁多，差异体现在：

| 维度 | 可选做法 |
|---|---|
| **个体表示** | **遗传算法**（genetic algorithm）：有限字母表上的串（常为布尔串），正如 DNA 是 ACGT 上的串；**进化策略**（evolution strategies）：实数序列；**遗传编程**（genetic programming）：一个计算机程序 |
| **混合数 ρ** | 共同产生后代的父代个数。最常见 `ρ = 2`；`ρ = 1` 就是随机束搜索（可看作无性生殖）；`ρ > 2` 在自然界罕见但计算机上容易模拟 |
| **选择过程** | 按适应度**成比例**地从所有个体中选取；或先随机选 `n` 个（`n > ρ`），再挑最适应的 `ρ` 个做父代 |
| **重组过程** | 常见做法（`ρ = 2`）：随机选一个**交叉点**（crossover point）把两个父代串各切成两段，重组出两个孩子——一个取父 1 前段 + 父 2 后段，另一个取父 2 前段 + 父 1 后段 |
| **变异率** | 后代生成后，其组成中的**每一位**都以等于变异率的概率被翻转 |
| **下一代构成** | 可以只有新后代；也可保留上一代少数得分最高的父代，这叫**精英保留**（elitism），它保证整体适应度**永不下降**。**淘汰**（culling，丢弃低于阈值的全部个体）也能带来加速（Baum et al., 1995） |

**Figure 4.6（8 位数字串表示 8 皇后，第 `c` 位 = 第 `c` 列皇后所在行）**

1. **(b) 适应度**：8 皇后用**互不攻击的皇后对数**，解的值为 `8 × 7 / 2 = 28`。四个状态的值为 **24、23、20、11**，归一化成概率后为 **29%、31%、26%、14%**。
2. **(c) 选择**：按 (b) 的概率选出两对父代。**注意有的个体被选中两次，有的完全没被选中**。
3. **(d) 交叉**：为每对随机选交叉点。例如第一对的第一个孩子取父 1 的前三位 `327` + 父 2 的剩余位 `48552` → `32748552`（Figure 4.7：绿色列在交叉中丢失，红色列被保留）。
4. **(e) 变异**：每个位置以**小的独立概率**变异；本例第 1、3、4 个后代各有一位发生变异。在 8 皇后中这对应"随机选一个皇后，移到所在列的随机一格"。

> **注意**：早期种群多样性高，交叉常常在状态空间中跨出**大步**（类似模拟退火）；经过多代向高适应度选择之后，多样性下降，典型步幅变小。

```
function GENETIC-ALGORITHM(population, fitness) returns an individual
    repeat
        weights ← WEIGHTED-BY(population, fitness)
        population2 ← empty list
        for i = 1 to SIZE(population) do
            parent1, parent2 ← WEIGHTED-RANDOM-CHOICES(population, weights, 2)
            child ← REPRODUCE(parent1, parent2)
            if (small random probability) then child ← MUTATE(child)
            add child to population2
        population ← population2
    until some individual is fit enough, or enough time has elapsed
    return the best individual in population, according to fitness
────────────────────────────────────────
function REPRODUCE(parent1, parent2) returns an individual
    n ← LENGTH(parent1)
    c ← random number from 1 to n
    return APPEND(SUBSTRING(parent1, 1, c), SUBSTRING(parent2, c + 1, n))
```

**交叉到底有没有用？** 遗传算法与随机束搜索的差别就在于多了交叉。当存在"能发挥有用功能的**块**"时这是有利的——例如把前三个皇后放在位置 2、4、6（互不攻击）构成一个有用的块，可与其他个体中的有用块组合成解；反过来可以数学地证明：**若这些块没有意义**（例如把遗传编码的位置随机置换），**交叉就不带来任何优势**。遗传算法理论用**模式**（schema）来解释这一点：模式是**某些位置可以留空不指定**的子串，如 `246*****` 描述所有"前三个皇后分别在位置 2、4、6"的 8 皇后状态；与模式匹配的串（如 `24613578`）称为该模式的**实例**（instance）。可以证明：**若某模式实例的平均适应度高于均值，则该模式的实例数会随时间增长**。若相邻比特彼此毫无关系，就不会有连续块能提供一致的好处，这个效应也就不显著。遗传算法在**模式对应于解的有意义部件**时效果最好——例如串表示天线时，模式可以代表反射器、偏转器之类的部件，而好部件在多种设计中都可能是好的。**这说明成功使用遗传算法需要仔细设计表示**。实践中它适合电路布局、作业车间调度这类**结构复杂**的问题（Marler and Arora, 2004），近年还用于演化深度神经网络架构（Miikkulainen et al., 2019）。

> **进化与搜索（原书专栏）**：Darwin（1859）与 Alfred Russel Wallace（1858）独立提出进化论——繁殖中出现变异，变异按其对繁殖适应度的影响大致成比例地保存下来。Darwin 提出时对性状如何遗传**一无所知**；概率定律首先由 Mendel（1866，用甜豌豆做实验的修士）确认；Watson 与 Crick（1953）确定了 DNA 结构与字母表 AGTC。与局部搜索类比后可见，随机束搜索与进化的**主要差别**是**有性生殖**。但真实进化比多数遗传算法丰富得多：大段 DNA 的反转/复制/移动、病毒借用 DNA、只自我复制的转座基因、毒死不携带该基因配偶的基因；**最重要的是基因本身编码了基因组如何被复制和翻译的机制**，而遗传算法中这些机制是被操作串之外的另一段程序。另外，**Lamarck**（1809）"获得性状可遗传"是**错的**，而 **Baldwin**（1896）表面相似的理论是**对的**：学习能有效**放松适应度地形**从而加速进化；模拟（Hinton and Nowlan, 1987）确认**鲍德温效应**真实存在，其后果是**难学的东西最终进入基因组，易学的东西不必待在那里**（Morgan and Griffiths, 2015）。

## 4.2 连续空间中的局部搜索（Local Search in Continuous Spaces）

多数真实环境是连续的；连续动作空间有**无限的分支因子**，因此前面讲过的大多数算法都处理不了——**例外是首选爬山和模拟退火**。本节简要介绍连续空间上的局部搜索技术（许多基本技术起源于 17 世纪 Newton 与 Leibniz 发明微积分之后），本书在学习、视觉、机器人等章节会用到。

**示例**：在罗马尼亚境内任意位置放 3 个新机场，使**每个城市到其最近机场的平方直线距离之和最小**。状态由 `(x₁, y₁), (x₂, y₂), (x₃, y₃)` 决定——这是一个**六维**空间（一般地，状态由 `n` 维变量向量 `x` 定义）。令 `Cᵢ` 为（在状态 `x` 下）最近机场是机场 `i` 的城市集合：

```
f(x) = f(x₁, y₁, x₂, y₂, x₃, y₃) = Σ_{i=1}^{3} Σ_{c∈Cᵢ} (xᵢ − x_c)² + (yᵢ − y_c)²       (4.1)
```

> **注意**：式 (4.1) **只在状态 `x` 及其局部邻域上正确，全局并不正确**——若偏离 `x` 太远，"哪些城市离该机场最近"就变了，必须重算 `Cᵢ`。

**① 离散化**（discretization）：把 `(xᵢ, yᵢ)` 限制在间距为 `δ` 的矩形网格上，每个状态就只有 **12 个后继**（6 个变量各 `±δ`），任何局部搜索算法都能用。也可以**随机采样后继**（沿随机方向移动小量 `δ`）把分支因子变成有限。**经验梯度**（empirical gradient）方法用**两个邻近点之间目标函数值的变化**衡量进展——经验梯度搜索**等价于在离散化版本的状态空间上做最陡上升爬山**；减小 `δ` 可以提高精度，但**不保证**在极限下收敛到全局最优。

**② 用微积分解析求解**：目标函数的**梯度** `∇f` 是给出最陡斜率**大小与方向**的向量，`∇f = ( ∂f/∂x₁ , ∂f/∂y₁ , ∂f/∂x₂ , ∂f/∂y₂ , ∂f/∂x₃ , ∂f/∂y₃ )`。有时可以解 `∇f = 0` 求极大值（只放**一个**机场时，解就是所有城市坐标的**算术平均**）；但多数情况下这个方程**不能闭式求解**——三个机场时梯度的表达式取决于当前哪些城市离哪个机场最近。我们因此只能**局部地**计算梯度：

```
∂f/∂x₁ = 2 Σ_{c∈C₁} (x₁ − x_c)                                                        (4.2)
```

有了局部正确的梯度表达式，就可以做最陡上升爬山：`x ← x + α ∇f(x)`，其中 `α` 是小常数，通常叫**步长**（step size）。`α` 太小需要太多步，太大会**越过**极大值。**线搜索**（line search）试图化解这个两难：沿当前梯度方向延伸——通常反复**加倍** `α`——直到 `f` 又开始下降，该点成为新的当前状态。

**③ 牛顿–拉弗森法**（Newton–Raphson）：对许多问题最有效的算法。它本是求 `g(x) = 0` 的根的通用技术，迭代式 `x ← x − g(x) / g′(x)`。求 `f` 的极大或极小就是找使梯度为零向量的 `x`，于是 `g(x)` 换成 `∇f(x)`，更新式写成矩阵–向量形式 `x ← x − H_f(x)^{-1} ∇f(x)`。其中 `H_f(x)` 是二阶导数的**海塞矩阵**（Hessian），元素 `Hᵢⱼ = ∂²f / ∂xᵢ∂xⱼ`。对我们的机场例子，`H_f(x)` 特别简单：**非对角元素全为 0**，机场 `i` 对应的对角元素就是 **`Cᵢ` 中城市数的两倍**；稍加计算可见**一步更新就把机场 `i` 移到 `Cᵢ` 的质心**，那正是式 (4.1) 局部表达式的最小值。一般地（脚注 3），这个更新可看作在 `x` 处给 `f` **拟合一个二次曲面**并直接跳到该曲面的极小点——若 `f` 本身是二次的，那就是 `f` 的极小点。但对**高维**问题，计算 `n²` 个海塞元素并求逆很昂贵，因此有许多近似版本。

> **注意**：局部搜索在连续空间中**同样**受困于局部极大值、山脊和高原，随机重启和模拟退火常常有用。不过高维连续空间是个很大的地方，非常容易在里面走丢。

**约束优化**：若解必须满足对变量值的**硬约束**（如机场须在罗马尼亚境内且在干地上），就是**约束优化**（constrained optimization）问题。最著名的类别是**线性规划**（linear programming）：约束必须是构成**凸集**（convex set）的线性不等式，目标函数也线性，其时间复杂度是**变量数的多项式**。它是**凸优化**（convex optimization）的特例——后者允许约束区域为任意凸区域、目标为凸函数，在一定条件下也多项式可解，实践中上千变量可行；机器学习与控制论中若干重要问题可表述为凸优化（第 20 章）。凸集（脚注 4）：点集 `S` 中任意两点的连线仍在 `S` 内则 `S` 凸；**凸函数**是其"上方"空间构成凸集的函数，**按定义凸函数没有（非全局的）局部极小值**。

## 4.3 非确定性动作的搜索（Search with Nondeterministic Actions）

第 3 章假设环境完全可观测、确定性、已知，智能体可以算出动作序列后"闭着眼睛"执行。但**部分可观测**时智能体不确定自己在哪个状态，**非确定性**时不知道动作后会转移到哪个状态，于是它的思考方式从"我在 `s₁`，做 `a` 会到 `s₂`"变成"我要么在 `s₁`、要么在 `s₃`；做 `a` 会到 `s₂`、`s₄` 或 `s₅`"。我们把**智能体认为可能的物理状态的集合**称为**信念状态**（belief state）。在部分可观测和非确定性环境中，解不再是序列，而是**条件规划**（conditional plan，也称**应变规划** contingency plan 或**策略** strategy）——它规定执行期间收到什么感知就做什么。本节处理非确定性，下一节处理部分可观测性。

### 4.3.1 不稳定的真空吸尘器世界（the erratic vacuum world）

第 2 章的真空世界有 8 个状态（Figure 4.9），三个动作 `Right`、`Left`、`Suck`，目标是清理所有灰尘（状态 7 和 8）。完全可观测、确定性且完全已知时用第 3 章任何算法都容易求解，解是动作序列——例如从状态 1 出发 `[Suck, Right, Suck]` 到达状态 8。

现在引入一台**强力但不稳定**（erratic）的吸尘器制造非确定性：`Suck` 作用于**脏**方格时清洁该方格、**有时**也把相邻方格的灰尘一并清掉；作用于**干净**方格时**有时**会在地毯上留下灰尘。

要精确表述，需要推广转移模型：不再用返回**单一**结果状态的 `RESULT`，而用返回**结果状态集合**的 `RESULTS`。例如 `RESULTS(1, Suck) = {5, 7}`。从状态 1 出发**没有任何单一动作序列**能解这个问题，但下面这条条件规划可以：

```
[Suck, if State = 5 then [Right, Suck] else [ ]]                                       (4.3)
```

条件规划可以包含 **if–then–else** 步骤，这意味着**解是树而不是序列**。注意 `if` 的条件测试的是**当前状态**——这是智能体**运行时**能观察到、但**规划时**不知道的东西；也可以写成测试**感知**而非状态的形式化。现实物理世界中的许多问题都是应变问题，因为精确预测未来不可能——正因如此，许多人走路时是睁着眼睛的。

### 4.3.2 与或搜索树

如何为非确定性问题找出这些应变解？仍像第 3 章那样构造搜索树，但树的性质不同：

| 节点 | 分支来源 | 例子 |
|---|---|---|
| **或节点**（OR node） | 智能体自己的选择 | 在或节点上选 `Left`、`Right` 或 `Suck` |
| **与节点**（AND node） | **环境**对动作结果的选择 | 状态 1 的 `Suck` 得到 `{5, 7}`，需要**同时**为状态 5 和状态 7 各找一份规划 |

两类节点交替，形成 **AND–OR 树**（与或树，Figure 4.10）：状态节点是或节点（须选一个动作），与节点画成圆圈，其**每条出边都必须被处理**（用一条弧把出边连起来表示），粗线标出找到的解。**解**是完整搜索树的一棵子树，满足：(1) **每个叶节点**都是目标节点；(2) **每个或节点**指定**一个**动作；(3) **每个与节点**包含**每一条结果分支**。

**Figure 4.11 给出 AND–OR 图搜索的递归深度优先算法**。一个关键之处是它**如何处理环**（环在非确定性问题中很常见，比如某个动作有时没有效果）：**若当前状态与从根到当前节点的路径上的某个状态相同，就返回失败**。

> **注意**：这**并不意味着**从当前状态出发没有解，它只是说**若存在非循环解，它必定能从更早出现的那个当前状态到达**，所以新出现的这一次可以丢弃。加上这个检查，算法在**任意有限状态空间**中都终止，因为每条路径必到达目标、死端或重复状态。另外，算法**不检查**当前状态是否与其他路径上的状态重复——这对效率很重要。

AND–OR 图既可广度优先也可最佳优先地探索；启发式须改为估计**条件解**（而非序列）的代价，但**可采纳性**（admissibility）概念可以沿袭，且存在与 `A*` 类比、求最优解的算法。

```
function AND-OR-SEARCH(problem) returns a conditional plan, or failure
    return OR-SEARCH(problem, problem.INITIAL, [ ])
────────────────────────────────────────
function OR-SEARCH(problem, state, path) returns a conditional plan, or failure
    if problem.IS-GOAL(state) then return the empty plan
    if IS-CYCLE(path) then return failure
    for each action in problem.ACTIONS(state) do
        plan ← AND-SEARCH(problem, RESULTS(state, action), [state] + path])
        if plan ≠ failure then return [action] + plan]
    return failure
────────────────────────────────────────
function AND-SEARCH(problem, states, path) returns a conditional plan, or failure
    for each sᵢ in states do
        planᵢ ← OR-SEARCH(problem, sᵢ, path)
        if planᵢ = failure then return failure
    return [if s₁ then plan₁ else if s₂ then plan₂ else . . . if s_{n−1} then plan_{n−1} else plan_n]
```

> ⚠️ 待核：以上是本项目 PDF（p.125）的**原样**。印刷版 `[state] + path]` 与 `return [action] + plan]` 各多一个右方括号。官方勘误页 <https://aima.cs.berkeley.edu/errata/aima-125.pdf> 把 `IS-CYCLE(path)` 改为 `IS-CYCLE(state, path)`（补上 `state`，与正文"当前状态与根路径上某状态相同"一致），并去掉这两处多余的右方括号。建议按勘误版理解。

### 4.3.3 试了再试

考虑一个**打滑**（slippery）的真空世界：与普通真空世界相同，只是**移动动作有时会失败**、让智能体留在原地。例如在状态 1 执行 `Right` 得到信念状态 `{1, 2}`。Figure 4.12 显示搜索图的一部分：显然从状态 1 出发**不再存在任何无环解**，`AND-OR-SEARCH` 会返回失败。

但存在一个**循环解**（cyclic solution）——**一直试 `Right` 直到它生效**。可以用新的 `while` 构造表达，也可以给规划的某段加**标签**再引用：

```
[Suck, while State = 5 do Right, Suck]
[Suck, L1: Right, if State = 5 then L1 else Suck]
```

**循环解何时才算解？** 最低条件是：(1) **每个叶节点都是目标状态**；(2) 从规划中的**每一点都能到达某个叶节点**。此外还要看**非确定性的成因**：若驱动机构确实有时工作、有时又**独立随机地**打滑，则重复足够多次**终究**会生效，规划会成功；若非确定性源于某个**未被观测到的事实**（如传动带断了，机器人**永远**动不了），重复就毫无帮助。

理解这个抉择的一种方式：智能体放弃了原先的形式化（**完全可观测、非确定性**），改用另一种（**部分可观测、确定性**），把循环规划的失败归因于"传动带"这个**未观测属性**。第 12 章讨论如何在若干不确定的可能性之间判断哪个更可能。

## 4.4 部分可观测环境中的搜索（Search in Partially Observable Environments）

现在转向部分可观测性：智能体的感知不足以钉死确切的状态。这意味着智能体的**某些动作会以"减少当前状态的不确定性"为目标**。

### 4.4.1 无观测时的搜索

当感知**完全不提供任何信息**时，我们面对的是**无传感问题**（sensorless problem，也称 **conformant problem**）。你也许会觉得无传感智能体连自己从哪出发都不知道、没希望解决问题，但**无传感解出人意料地常见且有用**，主要是因为它**不依赖传感器正常工作**——例如制造系统中用一串**完全不用感知**的动作把零件从未知初始姿态定向好。有时候**即使存在带感知的条件规划，无传感规划反而更好**：医生常开**广谱抗生素**，而不是"先验血 → 等结果 → 再开针对性抗生素"，这样省时省钱，也避免化验结果出来前感染恶化。

**无传感（确定性）真空世界**：智能体知道世界的地理，但**不知道自己的位置，也不知道灰尘分布**，初始信念状态为 `{1, 2, 3, 4, 5, 6, 7, 8}`。

| 动作序列之后 | 信念状态 | 说明 |
|---|---|---|
| （初始） | `{1, 2, 3, 4, 5, 6, 7, 8}` | 完全无知 |
| `Right` | `{2, 4, 6, 8}` | **智能体没有感知到任何东西，却获得了信息！** |
| `Right, Suck` | `{4, 8}` | |
| `Right, Suck, Left, Suck` | `{7}` | 无论起点是哪一个都保证到达目标状态 7——智能体把世界**强制**（coercion）到状态 7 |

> **注意**：无传感问题的解是**动作序列**而不是条件规划（因为没有感知）。但我们是在**信念状态空间**中搜索，而不是在物理状态空间中。在信念状态空间里这问题是**完全可观测**的——智能体**总是知道自己的信念状态**。而且解**永远是动作序列**，因为每步之后的感知**完全可预测**——它们永远是空的！所以没有意外要规划。**即使环境非确定性，这一点也成立。**

于是可以不另起炉灶，而是把底层物理问题 `P` 自动变换成信念状态问题，再用第 3 章的现成算法搜索：

| 成分 | 定义 |
|---|---|
| **状态** | 物理状态的**每一个可能子集**。若 `P` 有 `N` 个状态，则信念状态问题有 **`2ᴺ` 个**信念状态（很多从初始状态不可达） |
| **初始状态** | 通常是 `P` 中全部状态构成的集合；某些情况下智能体知道得更多 |
| **动作** | 稍棘手：若 `b = {s₁, s₂}` 而 `ACTIONS_P(s₁) ≠ ACTIONS_P(s₂)`，智能体**不确定哪些动作合法**。若假定**非法动作对环境没有影响**，取并集 `ACTIONS(b) = ⋃_{s∈b} ACTIONS_P(s)` 是安全的；若**非法动作可能造成灾难**，只取**交集**更安全。真空世界每状态合法动作相同，两者结果一样 |
| **转移模型** | 确定性：`b′ = RESULT(b, a) = {s′ : s′ = RESULT_P(s, a) 且 s ∈ b}` **(4.4)**；非确定性：`b′ = ⋃_{s∈b} RESULTS_P(s, a)`。`b′` 的大小对确定性动作**不变或变小**，对非确定性动作**可能变大**（Figure 4.13） |
| **目标测试** | **可能**达成：存在某个 `s` 满足 `IS-GOAL_P(s)`；**必然**达成：**每个** `s` 都满足。**我们追求必然达成** |
| **动作代价** | 若同一动作在不同状态代价不同，代价可能是**若干个值之一**（引出新问题类，见习题 4.MVAL）。此处假定代价处处相同，可直接照搬 |

（脚注 6：在**完全可观测**环境中每个信念状态只含**一个**物理状态，因此可把第 3 章的算法看作在"**单元素**信念状态空间"中搜索。）Figure 4.14 给出确定性无传感真空世界的**可达**信念状态空间：`2⁸ = 256` 个可能信念状态中**只有 12 个可达**。普通图搜索的重复状态检查对信念状态同样适用（如 `[Suck, Left, Suck]` 与 `[Right, Left, Suck]` 都到达 `{5, 7}`）。更进一步，可以**丢弃（剪枝）任何超集信念状态**：`[Left]` 到达的 `{1, 3, 5, 7}` 是 `{5, 7}` 的超集，为什么能丢？

- `{1, 3, 5, 7}` 的解必须同时是 1、3、5、7 **各自**的解，因而也是它们的任意组合（如 `{5, 7}`）的解，所以只需去解**严格更容易**的 `{5, 7}`；反之若 `{1, 3, 5, 7}` 已被发现有解，则任何子集（如 `{5, 7}`）**必定**有解——**如果我在非常糊涂时都有效的解，那我不那么糊涂时当然也有效**。

即便如此，这种做法在实践中仍**常常不可行**：信念状态空间是 **`2ᴺ`** 量级（上一章已见到规模为 `N` 的空间往往就太大），而其中**每个元素**又是最多 `N` 个元素的集合——`N` 很大时连**一个**信念状态都表示不出来。两条出路：

1. 用**更紧凑的描述**表示信念状态（如"Nothing"、"不在最右列"），第 7 章讲如何在形式化方案中做到；
2. **增量式信念状态搜索**（incremental belief-state search）——不把信念状态当黑盒，而是**一次处理一个物理状态**、逐步把解搭起来。例如先找一个对状态 1 有效的解，再检查它对状态 2 是否也有效，不行就回头换一个对状态 1 的解。**与 AND–OR 搜索的差别**：AND–OR 可为**每个分支**找**不同的**解，增量式必须找**同一个**对所有状态都成立的解。**主要优点**：通常能**很快检测失败**——信念状态无解时，往往只检查前几个状态构成的小子集就已经无解了，某些情况下加速可达信念状态规模（它本身可能和物理状态空间一样大）的量级。

### 4.4.2 在部分可观测环境中搜索

许多问题**没有感知就无解**（**无传感 8 数码是不可能的**）；但**一点点感知就能走很远**——只要能看到**左上角那一格**就能解 8 数码：依次把每块滑块移进那个可观测的格子，并从那以后记住它的位置。对部分可观测问题，规范会给出 `PERCEPT(s)`：状态 `s` 下收到的感知；感知非确定性则用返回**可能感知集合**的 `PERCEPTS`。完全可观测时 `PERCEPT(s) = s`；无传感时 `PERCEPT(s) = null`。

**局部感知真空世界**：位置传感器在左格给 `L`、右格给 `R`；灰尘传感器在当前格脏时给 `Dirty`、干净时给 `Clean`。状态 1 的 `PERCEPT` 是 `[L, Dirty]`。由于部分可观测，**通常有若干状态产生同一感知**——状态 3 也产生 `[L, Dirty]`；因此给定这个初始感知，**初始信念状态是 `{1, 3}`**。

**信念状态转移的三阶段（Figure 4.15）**

| 阶段 | 公式 | 说明 |
|---|---|---|
| **① 预测** | `b̂ = RESULT(b, a)` | 与无传感情形完全一样地算动作导致的信念状态。`b` 上的"帽"表示"**估计的**"；`PREDICT(b, a)` 是 `RESULT(b, a)` 的同义词 |
| **② 可能感知** | `POSSIBLE-PERCEPTS(b̂) = {o : o = PERCEPT(s) 且 s ∈ b̂}` | 在预测信念状态中可能被观测到的感知集合（字母 `o` 表示 observation） |
| **③ 更新** | `b_o = UPDATE(b̂, o) = {s : o = PERCEPT(s) 且 s ∈ b̂}` | 对每个可能感知 `o`，算出由它导致的信念状态——即 `b̂` 中**可能产生该感知**的那些状态 |

智能体必须在**规划时**就处理"可能感知"，因为**执行时**才知道实际感知。三段合起来（注意两条性质：物理环境的**非确定性**会在**预测阶段放大**信念状态，但每个更新后的 `b_o` **不会大于** `b̂`——**观测只能减少不确定性**；对**确定性感知**，不同可能感知对应的信念状态**互不相交**，构成对 `b̂` 的一个**划分**）：

```
RESULTS(b, a) = {b_o : b_o = UPDATE(PREDICT(b, a), o) 且 o ∈ POSSIBLE-PERCEPTS(PREDICT(b, a))}      (4.5)
```

### 4.4.3 求解部分可观测问题

有了上面导出的 `RESULTS`，就可以把 Figure 4.11 的 AND–OR 搜索**直接拿来**求解。Figure 4.16 显示局部感知真空世界搜索树的第一层（假设初始感知为 `[A, Dirty]`），解是：

```
[Suck, Right, if Bstate = {6} then Suck else [ ]]
```

> **注意**：因为我们把一个**信念状态问题**交给了 AND–OR 搜索，它返回的条件规划测试的是**信念状态**而不是**实际状态**。这本该如此——部分可观测环境中智能体**不知道**实际状态。
>
> ⚠️ 待核：Figure 4.16 与本节正文用 `[A, Dirty]`、`[B, Clean]`、`[B, Dirty]`、`[A, Clean]` 记感知，而 4.4.2 正文把位置传感器定义为给出 `L`／`R`。疑似原书在"两个方格"的记法上不统一（A/B 很可能就是左/右两格）。本笔记按原文照录。

同无传感情形一样，AND–OR 搜索也把信念状态当黑盒；改进办法仍是检查已生成信念状态中的**子集或超集**，也可以派生**增量式**搜索算法，相对黑盒做法有可观加速。

### 4.4.4 面向部分可观测环境的智能体

这类智能体：形式化问题 → 调用搜索算法（如 `AND-OR-SEARCH`）求解 → 执行解。与"完全可观测确定性环境"的智能体有两点主要差别：(1) 解是**条件规划**，执行 if–then–else 时必须**测试条件**并走相应分支；(2) 必须在执行动作、接收感知的过程中**维护信念状态**。维护过程类似式 (4.5) 的预测–观测–更新，但**更简单**，因为感知是**环境给出**的而不是智能体自己算的。给定信念状态 `b`、动作 `a` 和感知 `o`：

```
b′ = UPDATE(PREDICT(b, a), o)                                                         (4.6)
```

**幼儿园真空世界**（kindergarten vacuum world）：智能体只能感知**当前格**的状态，而且除非它此时正在清理某格，任何格子**随时**可能变脏（Figure 4.17）。在部分可观测环境中——现实世界的**绝大多数**环境都属于这一类——**维护自己的信念状态是任何智能系统的核心功能**，这个功能有各种名字：**监视**（monitoring）、**滤波**（filtering）、**状态估计**（state estimation）。

式 (4.6) 称为**递归状态估计器**（recursive state estimator），因为它从**前一个**信念状态算新的，而不是重新检查整条感知序列。为了不"落后"，计算必须跟得上感知进来的速度；环境变复杂后智能体只能算**近似的**信念状态，也许只关注感知对环境中**当前感兴趣部分**的影响。这方面多数工作针对**随机、连续状态**环境、用概率论工具完成（第 14 章）；本节给一个**离散环境 + 确定性传感器 + 非确定性动作**的例子。

**定位**（localization）示例（Figure 4.18）：给定世界地图与一串感知和动作，算出自己在哪。机器人有四个声纳，分别报告北、东、南、西是否有障碍，感知是按北、东、南、西顺序的**位向量**（`1011` = 北、南、西有障碍、东没有）；传感器**完全正确**，机器人也持有**正确的地图**；但导航系统坏了——执行 `Right` 会**随机移动到相邻方格之一**。

1. 刚开机时不知道自己在哪 → 初始信念状态 `b` 是**所有位置**的集合；
2. 收到第一个感知 `1011`，做 `b_o = UPDATE(1011)`，得到 Figure 4.18(a) 的 **4 个位置**（检查迷宫可知只有这 4 个位置能产生 `1011`）；
3. 执行 `Right`（非确定性）→ `b_a = PREDICT(b_o, Right)` 包含所有与 `b_o` 中位置相距一步的位置；
4. 第二个感知 `1010` → `UPDATE(b_a, 1010)`，信念状态**坍缩到 Figure 4.18(b) 的单一位置**——那是唯一可能是 `UPDATE(PREDICT(UPDATE(b, 1011), Right), 1010)` 结果的位置。

> **要点**：**非确定性动作**让 `PREDICT` **放大**信念状态，`UPDATE` 把它**缩回去**——**只要感知提供了有用的识别信息**。

有时感知对定位帮助不大：若存在一条或多条**东西向长走廊**，机器人可能收到一长串 `1010` 却永远不知道自己在走廊的哪一段；但**地理变化比较丰富**的环境里，定位常常很快收敛到单点，即使动作非确定性。**如果传感器有故障怎么办？** 若只能用布尔逻辑推理，就只能把每个传感器比特当成"**要么对要么错**"，这等同于**完全没有感知信息**；但**概率推理**（第 12 章）能让我们从有故障的传感器中**提取有用信息**——只要它出错的时间**少于一半**。

## 4.5 在线搜索智能体与未知环境（Online Search Agents and Unknown Environments）

**离线搜索**（offline search）智能体在迈出第一步**之前**就算出完整解；**在线搜索**（online search）智能体**交替进行计算与行动**：先做动作，再观察环境，再计算下一个动作。在线搜索在**动态或半动态**环境中是好主意（那里"坐着算太久"要付出代价），在**非确定性**域中也有帮助：它让智能体把算力集中到**实际发生的**意外上，而不是那些**可能发生但大概不会发生**的意外。当然有取舍：规划得越远，越不会发现自己"到了河里却没有桨"。

在**未知环境**中——智能体不知道有哪些状态存在、也不知道自己的动作做什么——它必须**把动作当作实验**来学习环境。典型例子是**建图问题**（mapping problem）：机器人被放进一栋未知建筑，探索并建图，之后用于从 A 走到 B；逃离迷宫的方法（古代有志成为英雄者的必备知识）也是在线搜索算法。但空间探索不是唯一形式——想想一个**新生儿**：它有许多可能的动作，却不知道任何一个动作的结果，也只经历过它能到达的状态中的少数几个。

> **注意**（脚注 8，重要）：这里的"**在线**"指**必须随输入到达就处理输入**、而不是等整个输入数据集就绪后才处理的算法。**这种"online"的用法与"有互联网连接"毫无关系。**

### 4.5.1 在线搜索问题

在线搜索问题通过**交替进行计算、感知和行动**求解。先假设**确定性且完全可观测**（第 17 章放宽），并规定智能体只知道：

| 已知 | 说明 |
|---|---|
| `ACTIONS(s)` | 状态 `s` 下的合法动作 |
| `c(s, a, s′)` | 在 `s` 执行 `a` 到达 `s′` 的代价。**注意：在智能体知道 `s′` 是结果之前，这个代价没法用** |
| `IS-GOAL(s)` | 目标测试 |

特别要注意：智能体**无法确定 `RESULT(s, a)`**，除非**真的处在 `s` 并真的做了 `a`**。例如在 Figure 4.19 的迷宫中，它不知道从 `(1,1)` 向上走会到 `(1,2)`；就算走过了，也不知道向下走会回到 `(1,1)`。某些应用中这种无知可降低——机器人探索者可能知道移动动作如何工作，只是不知道障碍在哪。智能体还可能有**可采纳启发式** `h(s)`，如**曼哈顿距离启发式**（第 97 页）。

通常目标是**到达目标状态且代价最小**（另一个可能目标只是**探索整个环境**），代价是行进中累积的**总路径代价**。常见做法是把它与"**若事先知道搜索空间**"时的路径代价（即已知环境中的最优路径）比较——在在线算法的语言中叫**竞争比**（competitive ratio），越小越好。

**死端与对手论证**：在线探索者容易遭遇**死端**（dead end）——从该状态**无法到达任何目标状态**。若智能体不知道每个动作做什么，它可能执行"**跳进无底洞**"动作，永远到不了目标。**一般地说，没有算法能在所有状态空间中避免死端。** 看 Figure 4.20(a)：一个已访问过 `S` 和 `A` 的在线搜索算法**无法分辨**自己在上、下哪个状态空间——**基于它见到的东西两者完全相同**，因此不存在一种能让它在这两个空间都选对动作的方法。这就是**对手论证**（adversary argument）：想象一个**对手**在智能体探索的同时构造状态空间，随意放置目标和死端（Figure 4.20(b)：无论智能体选哪条路，对手都用**另一道又长又薄的墙**堵住，使走过的路径**远长于**最优路径）。

死端对机器人探索是**真实的困难**：楼梯、坡道、悬崖、单行道、甚至自然地形都会产生某些动作**不可逆**（irreversible action）的状态——**没有办法回到前一个状态**。本节算法只保证在**安全可探索**（safely explorable）的状态空间有效——从**每个可达状态**都能到达某个目标状态；只有可逆动作的空间（如迷宫和 8 数码）显然安全可探索（只要有解）。安全探索在 22.3.2 节更深入讨论。

> **注意**：**即使在安全可探索环境中，只要存在无界代价的路径，也无法保证有界的竞争比。** 这在有不可逆动作的环境中容易证明，但**即使动作可逆也依然成立**（Figure 4.20(b)）。因此人们常用**整个状态空间的规模**而非"最浅目标的深度"来刻画在线搜索算法的性能。

### 4.5.2 在线搜索智能体

每做一个动作之后，可观测环境中的在线智能体收到感知、得知到达了哪个状态，据此**扩充环境地图**，再用更新后的地图**规划下一步**。这种交替使在线算法与离线算法**相当不同**：**离线算法探索状态空间的模型，在线算法探索真实世界**。例如 `A*` 可以在空间某处扩展一个节点后立刻到很远的另一处扩展，因为**节点扩展涉及模拟动作而非真实动作**；在线算法则只能为**它物理占据着**的状态发现后继。为避免跑到远处去扩展下一个节点，最好**按局部顺序**扩展——**深度优先搜索**恰好有这个性质：除回溯时外，下一个扩展的节点就是上一个扩展节点的孩子。

```
function ONLINE-DFS-AGENT(problem, s′) returns an action
  persistent: s, a, the previous state and action, initially null
              result, a table mapping (s, a) to s′, initially empty
              untried, a table mapping s to a list of untried actions
              unbacktracked, a table mapping s to a list of states never backtracked to
  if problem.IS-GOAL(s′) then return stop
  if s′ is a new state (not in untried) then untried[s′] ← problem.ACTIONS(s′)
  if s is not null then
      result[s, a] ← s′
      add s to the front of unbacktracked[s′]
  if untried[s′] is empty then
      if unbacktracked[s′] is empty then return stop
      else a ← an action b such that result[s′, b] = POP(unbacktracked[s′])
  else a ← POP(untried[s′])
  s ← s′
  return a
```

- 地图存在表 `result[s, a]` 中（对非确定性动作可在 `results[s, a]` 下存一个状态**集合**）；只要当前状态还有未探索的动作就试一个；
- 困难在于**所有动作都试过之后**：离线深度优先直接把状态从队列丢掉，**在线搜索必须在物理世界中回溯**——回到最近一次进入当前状态的那个状态，因此另存一张表列出每个状态下**还没回溯到的前驱状态**；若再没有可回溯的状态，搜索完成。

> 建议读者自己跟踪一遍 `ONLINE-DFS-AGENT` 在 Figure 4.19 迷宫中的执行过程。不难看出最坏情况下它会把**每条连接恰好走两次**——**对探索这是最优的**；但对**找目标**而言，若它一头扎进长途远足而目标就在初始状态旁边，**竞争比可以任意差**。**在线迭代加深**变体解决这个问题，对均匀树环境这类智能体的竞争比是一个**小常数**。另外，由于它回溯的方式，该算法**只在动作可逆的状态空间中工作**；有稍复杂的算法能用于一般状态空间，但**没有这样的算法具有有界竞争比**。

> ⚠️ 待核：以上是本项目 PDF（p.137）的**原样**。官方勘误页 <https://aima.cs.berkeley.edu/errata/aima-137.pdf> 作三处修改：`unbacktracked` 的类型由 `a list of` 改为 **`a queue of`**；`add s to the front of` 改为 **`add s to the end of`**；回溯那行改为 **`s′, a ← null, an action b such that result[s′, b] = POP(unbacktracked[s′])`**。

### 4.5.3 在线局部搜索

和深度优先一样，**爬山搜索**的节点扩展也具有**局部性**；而且它只保留**一个**当前状态，**本来就已经是在线搜索算法了**。可惜基本算法**不适合探索**——它把智能体丢在局部极大值上无处可去，而且**不能用随机重启**，因为智能体**无法把自己传送到新的起始状态**。

**随机游走**（random walk）：从当前状态的可用动作中随机选一个（可优先选没试过的）。容易证明：只要空间**有限且安全可探索**，它**最终**会找到目标或完成探索（脚注 9：随机游走在**一维、二维无限网格**上完备；但在**三维**网格上，游走**曾经**回到起点的概率只有约 **0.3405**（Hughes, 1995））。但它可能**非常慢**：Figure 4.22 的环境中随机游走要花**指数多**步才能找到目标，因为除 `S` 外顶行每个状态**向后走的概率是向前走的两倍**；这是人为构造的例子，但现实中许多状态空间的拓扑会给随机游走设下这类"陷阱"。

**给爬山加记忆而非随机性更有效**：为**每个访问过的状态**保存"当前最佳估计" `H(s)`——从该状态到目标的代价，`H(s)` 初始就是启发式估计 `h(s)`，随经验更新。Figure 4.23 是一个一维例子（每状态标注当前 `H(s)`，每条连接代价为 1，红色是智能体位置，被更新的估计画双圈）：

1. **(a)**：智能体看似卡在红色状态的**平坦局部极小值**里。它不该原地不动，而应顺着"按当前估计看来最好"的路走。经过邻居 `s′` 到目标的估计代价是 `c(s, a, s′) + H(s′)`；本例两个动作分别是向左 `1 + 9`、向右 `1 + 2`，所以**最好往右走**。
2. **(b)**：可见 (a) 中红色状态的估计 **2** 过于乐观——最优动作代价为 1，它到达的状态距目标**至少**还有 2 步，故该状态距目标**至少** 3 步，`H` 应相应更新。
3. 继续这个过程，智能体还会**来回两次**，每次更新 `H`，把局部极小值"**填平**"，最终**向右逃出**。

实现这一方案的智能体叫**学习实时 A\***（learning real-time A\*, **LRTA\***），见 Figure 4.24。它和 `ONLINE-DFS-AGENT` 一样在 `result` 表中建图，**更新刚离开的那个状态的代价估计**，再按当前估计选"**看起来最好**"的移动。

```
function LRTA*-AGENT(problem, s′, h) returns an action
  persistent: s, a, the previous state and action, initially null
              result, a table mapping (s, a) to s′, initially empty
              H, a table mapping s to a cost estimate, initially empty
  if IS-GOAL(s′) then return stop
  if s′ is a new state (not in H) then H[s′] ← h(s′)
  if s is not null then
      result[s, a] ← s′
      H[s] ← min_{b ∈ ACTIONS(s)} LRTA*-COST(s, b, result[s, b], H)
  a ← argmin_{b ∈ ACTIONS(s)} LRTA*-COST(problem, s′, b, result[s′, b], H)
  s ← s′
  return a
────────────────────────────────────────
function LRTA*-COST(problem, s, a, s′, H) returns a cost estimate
  if s′ is undefined then return h(s)
  else return problem.ACTION-COST(s, a, s′) + H[s′]
```

> **一个重要细节**：在状态 `s` 中**尚未尝试过**的动作，总是被假定**立刻以最小可能代价 `h(s)` 到达目标**。这种**不确定性下的乐观**（optimism under uncertainty）鼓励智能体探索**新的、可能有希望**的路径。

`LRTA*` 保证能在**任何有限、安全可探索**的环境中找到目标；但与 `A*` 不同，它对**无限状态空间不完备**——存在它被引入无限歧途的情形；最坏情况下用 **`O(n²)` 步**探索 `n` 个状态的环境，但通常好得多。它只是一大类在线智能体中的一个成员——通过指定不同的**动作选择规则**与**更新规则**就能定义其他成员；这个家族最初为**随机环境**发展，第 22 章讨论。

### 4.5.4 在线搜索中的学习

在线搜索智能体**最初的无知**提供了若干学习机会：(1) 通过**记录每一次经验**学会环境的"**地图**"——更确切地说，学会**每个状态下每个动作的结果**；(2) 局部搜索智能体通过**局部更新规则**获得更准确的每状态代价估计，如 `LRTA*`。第 22 章会说明：**只要智能体以恰当方式探索状态空间，这些更新最终会收敛到每个状态的精确值**；一旦精确值已知，只需**移动到代价最低的后继**就能做出最优决策——**纯爬山法此时就是最优策略**。

如果你照建议跟踪过 `ONLINE-DFS-AGENT` 在 Figure 4.19 中的行为，会发现它**不太聪明**：看到 `Up` 把 `(1,1)` 带到 `(1,2)` 之后，它仍**不知道** `Down` 会回到 `(1,1)`，也不知道 `Up` 同样会把 `(2,1)` 带到 `(2,2)`、`(2,2)` 带到 `(2,3)`……一般地说，我们希望它学到"**`Up` 增加 y 坐标，除非有墙挡着**""**`Down` 减少它**"这类**一般规则**。这需要两件事：(1) 为这类规则提供**形式化的、可显式操作的**表示——目前信息**藏在 `RESULT` 函数这个黑盒里**（第 8–11 章）；(2) 能从**具体观察**构造出合适一般规则的**算法**（第 19 章）。

最后，若预期将来要解**多个相似问题**，就值得投入时间（和内存）让未来搜索更容易。做法都归入**增量搜索**（incremental search）：保留**搜索树**并复用新问题中**未变**的部分；保留**启发式 `h` 值**并随新信息更新（世界变了或算出了更好的估计）；保留最优路径的 **`g` 值**用来拼出新解，并在世界变化时更新。

## 小结

1. **局部搜索**方法（如爬山法）只在内存中保留少量状态。它们被用于**最优化问题**——目标是找一个**高分状态**，而**不关心到达它的路径**。已发展出若干随机局部搜索算法，包括**模拟退火**——给它合适的冷却调度，它返回最优解。
2. 许多局部搜索方法也适用于**连续空间**。**线性规划**与**凸优化**对状态空间形状和目标函数性质施加限制，从而拥有**多项式时间**算法，且实践中往往极其高效。对某些数学上性质良好的问题可用微积分**求梯度为零之处**找极大值；其他问题只能用**经验梯度**——它衡量两个邻近点之间的适应度之差。
3. **进化算法**是一种**随机爬山搜索**，维护一个**状态种群**；新状态由**变异**和**交叉**（组合两个状态）产生。
4. 在**非确定性**环境中，智能体可用 **AND–OR 搜索**生成**应变规划**，使无论执行中出现哪些结果都能到达目标。
5. 环境**部分可观测**时，**信念状态**表示智能体可能处在的**状态集合**。
6. 标准搜索算法可直接用于**信念状态空间**求解**无传感**问题；**信念状态 AND–OR 搜索**可求解一般的**部分可观测**问题；**增量式**算法在信念状态内部逐状态构造解，往往更高效。
7. **探索问题**出现在智能体对环境的状态和动作**一无所知**时。对**安全可探索**的环境，在线搜索智能体可以**建图**并在目标存在时找到它；**从经验中更新启发式估计**提供了一条逃离局部极小值的有效途径。

## 延伸阅读

**原书注释要点**

- **局部搜索**：牛顿–拉弗森法（Newton, 1671；Raphson, 1690）可看作利用梯度的极高效连续局部搜索；Brent (1973) 是不需要梯度的经典参考。束搜索源自 `HARPY` 语音识别中有界宽度的动态规划变体（Lowerre, 1976）。1990 年代初 n 皇后（Minton et al., 1992）与布尔可满足性（Selman et al., 1992）的好结果让局部搜索复兴，Papadimitriou 称之为"New Age"算法。**禁忌搜索**（Glover and Laguna, 1997）维护不可重访的禁忌表；`STAGE`（Boyan and Moore, 1998）用局部极大值拟合二次曲面再解析求其全局极大值作为重启点；Gomes et al. (1998) 指出回溯算法运行时间常呈**重尾分布**，此时随机重启平均更快。**模拟退火**由 Kirkpatrick et al. (1983) 首次描述，直接借用物理学的 Metropolis 算法（Metropolis et al., 1953）。
- **连续空间与凸优化**：优化理论、最优控制理论、变分法是求连续空间最优解的几家学问，Bishop (1995) 讲基本技术，Press et al. (2007) 覆盖面广并提供软件。线性规划由 Kantorovich (1939) 系统研究，单纯形法（Dantzig, 1949）至今仍用，内点法（Karmarkar, 1984）更高效；Nesterov 与 Nemirovski (1994) 证明凸优化类的多项式复杂度；Boyd 与 Vandenberghe (2004) 是好的入门。
- **进化计算**：Sewall Wright (1931) 的适应度景观是先驱；Rechenberg (1965) 用进化策略解翼型优化使其流行；Holland (1975) 倡导遗传算法；遗传编程由 Koza (1992, 1994) 推动。多数比较研究发现遗传算法比随机爬山等**收敛更慢**（Mitchell et al., 1996；Baluja, 1997 等）。
- **AND–OR 搜索与信念状态**：Slagle 的 `SAINT` 最早显式使用与或树；Amarel (1967) 用于命题定理证明；Nilsson (1971) 提出求最优解的 `AO*`；`A*LD`（Felzenszwalb and McAllester, 2007）是 `A*` 的自底向上推广。信念状态变换思路源自 Astrom (1965)（概率不确定性情形，见第 17 章）；Erdmann and Mason (1988) 研究无传感器机器人操作；Genesereth and Nourbakhsh (1993) 在无传感/部分可观测搜索中重新发明；Bonet and Geffner (2000) 给出第一批有效启发式；Russell and Wolfe (2005) 提出新的增量式算法。
- **探索与在线搜索**：可逆迷宫的深度优先搜索可用"左手扶墙"实现；欧拉图探索由 Hierholzer (1873) 解决；Deng and Papadimitriou (1990) 证明对一般图**不存在有界竞争比**；Papadimitriou and Yannakakis (1991) 证明方形障碍物下竞争比可以很小、一般矩形则不行。`LRTA*` 由 Korf (1990) 提出，是随机环境强化学习算法的特例（Barto et al., 1995）；Dasgupta et al. (1994) 证明在线迭代加深在无启发式的均匀树上最优高效；动态环境的增量搜索有 Lifelong Planning `A*`（Koenig et al., 2004）与 `D* Lite`（Koenig and Likhachev, 2002）。
