## 0. 本章要解决的问题

第 3–4 章的搜索算法把状态当成**原子黑箱**：算法只会问"这个状态是不是目标？不是？那这个呢？"，每个状态内部没有结构可用，启发式也只能是领域专属的。本章要**撬开这个黑箱**——用一组**变量—值**对来表示状态（**因子化表示**，factored representation），于是可以：

- 一眼看出**哪些变量违反了约束**，把注意力集中在关键变量上；
- 用**领域无关**的通用启发式与推断方法，一次性砍掉搜索空间的一大片；
- 连动作与转移模型都不用写——它们能从问题描述中直接推导出来。

> 原本章首题词：*In which we see how treating states as more than just little black boxes leads to new search methods and a deeper understanding of problem structure.*

## 6.1 定义约束满足问题（Defining Constraint Satisfaction Problems）

**约束满足问题**（constraint satisfaction problem, CSP）由三个成分 `X`、`D`、`C` 组成：

| 成分 | 含义 |
|---|---|
| `X` | 变量集合 `{X₁, …, Xₙ}` |
| `D` | 域集合 `{D₁, …, Dₙ}`，每个变量一个域 |
| `C` | 约束集合，规定变量可取值的**相容组合** |

- **域** `Dᵢ` 是变量 `Xᵢ` 的允许值集合 `{v₁, …, vₖ}`；布尔变量的域是 `{true, false}`，不同变量的域大小可以不同。
- 每条约束 `Cⱼ` 是一个对子 `⟨scope, rel⟩`：**作用域**（scope）是参与该约束的变量元组，**关系**（rel）规定这些变量能取哪些值。关系既可以显式枚举为满足约束的**全部元组**，也可以写成能判定某个元组是否属于该关系的**函数**。

例：若 `X₁`、`X₂` 的域都是 `{1,2,3}`，"X₁ 必须大于 X₂" 可写成

```
⟨(X₁,X₂), {(3,1),(3,2),(2,1)}⟩     或     ⟨(X₁,X₂), X₁ > X₂⟩
```

### 赋值的几个层次

| 术语 | 定义 |
|---|---|
| **赋值**（assignment） | 给部分或全部变量指定值，形如 `{Xᵢ = vᵢ, Xⱼ = vⱼ, …}` |
| **相容赋值 / 合法赋值**（consistent / legal assignment） | 不违反任何约束的赋值 |
| **完整赋值**（complete assignment） | 每个变量都被赋了值 |
| **解**（solution） | **相容且完整**的赋值 |
| **部分赋值**（partial assignment） | 还有变量未赋值 |
| **部分解**（partial solution） | 相容的部分赋值 |

> ⚠️ **一般地，求解 CSP 是 NP-complete 问题**；但存在一些重要子类可以非常高效地求解（见 6.5 节）。注意"可满足"与"一致"不是一回事：后文的弧一致性**不能**保证有解。

### 6.1.1 示例问题：地图着色

厌倦了罗马尼亚，这次给**澳大利亚**地图上色（Figure 6.1(a)）：七个州/领地，每块染红、绿、蓝之一，相邻区域颜色不同。

```
X = {WA, NT, Q, NSW, V, SA, T}
Dᵢ = {red, green, blue}   （每个变量都一样）
C = {SA≠WA, SA≠NT, SA≠Q, SA≠NSW, SA≠V, WA≠NT, NT≠Q, Q≠NSW, NSW≠V}
```

- 一共有 **9 处接壤**，所以是 9 条约束。
- `SA≠WA` 是 `⟨(SA,WA), SA≠WA⟩` 的简写，而后者可完全枚举为
  `{(red,green),(red,blue),(green,red),(green,blue),(blue,red),(blue,green)}`。
- 解有很多，例如 `{WA=red, NT=green, Q=red, NSW=green, V=red, SA=blue, T=red}`。

**约束图**（constraint graph，Figure 6.1(b)）：节点对应变量，参与同一约束的两个变量之间连一条边。

**为什么要把问题形式化成 CSP？** 三个理由：

1. CSP 是覆盖面极广的**自然表示**，很多问题容易写成 CSP；
2. CSP 求解器经过多年打磨，**快**且成熟；
3. CSP 求解器能**成片剪掉搜索空间**——原子状态空间搜索做不到这一点。

> 例：一旦在澳大利亚问题中选定 `{SA = blue}`，立刻可知它的 5 个邻居都不能取 blue。不用约束要考虑 `3⁵ = 243` 种赋值；用了约束只剩 `2⁵ = 32` 种，**减少 87%**。
> 更重要的是：一旦发现某个部分赋值违反约束，就可以**立刻丢弃它的全部后继细化**，并且能看出"是哪个变量违反了约束"。

### 6.1.2 示例问题：作业车间调度

工厂要排定一天的工作，实际中大量此类问题用 CSP 技术求解。以**汽车装配**为例：每项任务是一个变量，变量的取值是该任务的**开始时间**（整数分钟）。

考虑装配的一小部分，共 **15 个任务**，建模为 15 个变量：

```
X = {AxleF, AxleB, WheelRF, WheelLF, WheelRB, WheelLB,
     NutsRF, NutsLF, NutsRB, NutsLB, CapRF, CapLF, CapRB, CapLB, Inspect}
```

**优先约束**（precedence constraint）：若任务 `T₁` 必须在 `T₂` 之前完成，且 `T₁` 耗时 `d₁`，就加一条算术约束 `T₁ + d₁ ≤ T₂`。装一根轴要 10 分钟，故：

```
AxleF + 10 ≤ WheelRF ;  AxleF + 10 ≤ WheelLF
AxleB + 10 ≤ WheelRB ;  AxleB + 10 ≤ WheelLB
```

每个轮子：装轮 1 分钟 → 拧螺母 2 分钟 → 装轮毂盖 1 分钟：

```
WheelRF + 1 ≤ NutsRF ;  NutsRF + 2 ≤ CapRF      （LF / RB / LB 同理）
```

**析取约束**（disjunctive constraint）：四个工人装轮子，但只有一把装轴的辅助工具，所以 `AxleF` 与 `AxleB` 不能时间重叠——要么一个先，要么另一个先：

```
(AxleF + 10 ≤ AxleB)  or  (AxleB + 10 ≤ AxleF)
```

它看起来混合了算术与逻辑，但仍可归约为 `AxleF`、`AxleB` 可取值对的集合。

**收尾**：检验 `Inspect` 必须最后做、耗时 3 分钟，对每个非 `Inspect` 的变量加 `X + dₓ ≤ Inspect`；要求总装配 30 分钟内完成，就把所有变量的域限为 `Dᵢ = {0,1,2,…,30}`。

> 这个具体例子平凡可解，但 CSP 已成功用于含**数千变量**的作业车间调度问题。

### 6.1.3 CSP 形式体系的变体

#### 按变量的域分

| 类型 | 说明 | 例子 |
|---|---|---|
| **离散有限域**（discrete, finite domain） | 最简单的一类 | 地图着色；带时限的调度；8 皇后（`Q₁…Q₈`，`Dᵢ = {1,…,8}`，约束为不同行、不同对角线） |
| **离散无限域**（infinite domain） | 如整数集、字符串集 | 不给调度问题加截止期限，每个变量的开始时间就有无限多种；此时必须用 `T₁ + d₁ ≤ T₂` 这类**隐式约束**，不能枚举元组 |
| **连续域**（continuous domain） | 现实世界常见，运筹学研究广泛 | 哈勃太空望远镜的观测调度——观测与机动的起止时刻是连续值变量，要服从天文、优先、电力等约束 |

- **线性约束**（linear constraints）：每个变量只以线性形式出现。整数变量上的线性约束有专门的求解算法（本书不讨论）。
- **非线性约束**（nonlinear constraints）：**可以证明不存在求解整数变量上一般非线性约束的算法——该问题是不可判定的**。
- **线性规划**（linear programming）是最著名的连续域 CSP 类别，约束必须是线性等式或不等式，**可在关于变量数多项式的时间内求解**；此外还有二次规划、二阶锥规划等。

#### 按约束的类型分

| 类型 | 定义 | 例子 |
|---|---|---|
| **一元约束**（unary） | 只限制单个变量的取值 | `⟨(SA), SA ≠ green⟩`（南澳人不接受绿色）。变量初始域的规定本身也可看作一元约束 |
| **二元约束**（binary） | 关联两个变量 | `SA ≠ NSW` |
| **二元 CSP** | 只含一元与二元约束的 CSP | 可画成 Figure 6.1(b) 那样的约束图 |
| **高阶约束**（higher-order） | 涉及三个及以上变量，如三元约束 `Between(X,Y,Z)` = `⟨(X,Y,Z), X<Y<Z 或 X>Y>Z⟩` | |
| **全局约束**（global） | 涉及**任意多个**变量的约束 | 名字是历史遗留且容易误解——全局约束**不必**涉及问题中的所有变量 |

最常见的全局约束是 **Alldiff**：约束涉及的所有变量必须取**互不相同**的值。数独中每一行、每一列、每个 `3×3` 宫都满足一条 Alldiff。

**密码算术**（cryptarithmetic，Figure 6.2(a)）：每个字母代表一个不同数字，于是有全局约束 `Alldiff(F,T,U,W,R,O)`；四个列上的加法写成 n 元约束：

```
O + O      = R + 10·C₁
C₁ + W + W = U + 10·C₂
C₂ + T + T = O + 10·C₃
C₃         = F
```

其中 `C₁`、`C₂`、`C₃` 是表示进位数字的**辅助变量**。这类约束可用**约束超图**（constraint hypergraph）表示：普通节点（图中圆圈）加**超节点**（图中方块，代表 n 元约束）。

**化为二元约束的两种方法**：

1. **引入辅助变量**：任何有限域约束都可归约为一组二元约束（习题 6.NARY 要求证明）。这意味着任何 CSP 都能转成只含二元约束的 CSP。
2. **对偶图变换**（dual graph transformation）：新图中，原图的**每条约束**变成一个变量，原图中**共享变量的两条约束**之间连一条二元约束。例：原 CSP 有 `X={X,Y,Z}`，域均 `{1,2,3,4,5}`，约束 `C₁: ⟨(X,Y,Z), X+Y=Z⟩` 与 `C₂: ⟨(X,Y), X+1=Y⟩`；对偶图有变量 `{C₁,C₂}`，`C₁` 的域是 `C₁` 的全体 `(xᵢ,yⱼ,zₖ)` 元组，`C₂` 的域是全体 `(xᵢ,yⱼ)` 元组，两者之间是 `⟨(C₁,C₂), R₁⟩`，其中
   `R₁ = {((1,2,3),(1,2)), ((2,3,5),(2,3))}`。

**为什么宁愿用 Alldiff 而不是一堆二元约束？** 两条理由：

1. 问题描述写起来更简洁、更不易出错；
2. 可以为全局约束设计**专用的推断算法**，比用基本约束更高效（见 6.2.5 节）。

**偏好约束**（preference constraints）：前面都是**绝对约束**（absolute constraints），违反即排除该候选解；现实 CSP 常含偏好约束，指出哪些解更受偏好。例：大学排课中"教授不能同时上两门课"是绝对约束，而"R 教授偏好上午、N 教授偏好下午"是偏好约束——把 R 排在下午 2 点仍是**可行解**，只是不是最优解。

偏好常编码为**赋值的代价**：R 教授排下午扣 2 分，排上午扣 1 分。这样带偏好的 CSP 可用路径搜索或局部搜索等**优化**方法求解，称为**约束优化问题**（constrained optimization problem, COP）。线性规划就是一类 COP。

## 6.2 约束传播：CSP 中的推断（Constraint Propagation: Inference in CSPs）

原子状态空间搜索只有一条推进途径：扩展节点、访问后继。**CSP 算法有选择**：它可以选一个新变量赋值来生成后继，也可以做一类特殊的推断——**约束传播**（constraint propagation）：

> 用约束**减少某个变量的合法取值数**，这又可能减少另一个变量的合法取值，如此连锁下去。

传播可以与搜索**交错**进行，也可以在搜索开始前作为**预处理**步骤；有时仅靠预处理就把整个问题解完了，完全不需要搜索。其核心概念是**局部一致性**（local consistency）：把变量看作图中的节点、二元约束看作边，在图的各部分强制局部一致性，就能让不一致的值在整个图中被消掉。局部一致性分若干等级。

### 6.2.1 节点一致性

单个变量（对应 CSP 图中的一个节点）是**节点一致**（node-consistent）的，当且仅当其域中的**所有值都满足该变量的一元约束**。

例：在"南澳人不接受绿色"的变体中，`SA` 初始域 `{red, green, blue}`，删掉 green 后变成 `{red, blue}`，即达成节点一致。**图是节点一致的**，当且仅当图中每个变量都节点一致。

在求解开始时通过缩减含一元约束的变量的域，就能消去全部一元约束；同理也可把 n 元约束转成二元约束。因此**有些 CSP 求解器只处理二元约束**，要求用户事先消掉其他约束。**本章余下部分（除特别说明外）都作此假设。**

### 6.2.2 弧一致性

一个变量是**弧一致**（arc-consistent）的，当且仅当其域中每个值都满足该变量的二元约束。形式化地说：`Xᵢ` **相对于** `Xⱼ` 弧一致，当且仅当对当前域 `Dᵢ` 中的**每个值**，域 `Dⱼ` 中都**存在某个值**使得弧 `(Xᵢ,Xⱼ)` 上的二元约束被满足。**图是弧一致的**，当且仅当每个变量相对于其他每个变量都弧一致。

> 原书脚注：我们一直用"边"（edge）而不是"弧"（arc），所以叫"边一致"其实更合理，但"弧一致"是历史名称。

**示例**：约束 `Y = X²`，`X`、`Y` 的域都是十进制数字。显式写为 `⟨(X,Y), {(0,0),(1,1),(2,4),(3,9)}⟩`。

- 让 `X` 相对于 `Y` 弧一致 → `X` 的域缩为 `{0,1,2,3}`；
- 再让 `Y` 相对于 `X` 弧一致 → `Y` 的域变为 `{0,1,4,9}`，整个 CSP 弧一致。

> **注意方向**：`REVISE(Xᵢ, Xⱼ)` 只**删减 `Dᵢ`**，从不改动 `Dⱼ`。弧 `(Xᵢ,Xⱼ)` 与弧 `(Xⱼ,Xᵢ)` 是**两条不同的弧**，必须分别处理。

**弧一致性对澳大利亚地图着色毫无作用**：约束 `(SA,WA)` 的相容值对是那 6 个组合，无论给 `SA`（或 `WA`）选什么值，另一个变量总有合法值可取，所以两个域都不会缩小。

> ⚠️ **T3 要点**：弧一致**不等于**可满足。弧一致的 CSP 仍可能无解（6.2.3 的两色澳大利亚就是典型反例）。

**AC-3**（Figure 6.3）是最流行的弧一致性算法：

```
function AC-3(csp) returns false if an inconsistency is found and true otherwise
    queue ← a queue of arcs, initially all the arcs in csp
    while queue is not empty do
        (Xi, Xj) ← POP(queue)
        if REVISE(csp, Xi, Xj) then
            if size of Di = 0 then return false
            for each Xk in Xi.NEIGHBORS - {Xj} do
                add (Xk, Xi) to queue
    return true

function REVISE(csp, Xi, Xj) returns true iff we revise the domain of Xi
    revised ← false
    for each x in Di do
        if no value y in Dj allows (x,y) to satisfy the constraint between Xi and Xj
        then delete x from Di
    revised ← true
    return revised
```

**逐步说明**（含易错的入队/终止条件）：

1. **初始队列**含 CSP 中**所有弧**；每条二元约束变成**两条弧**（正反各一）。
2. 弹出**任意**一条弧 `(Xᵢ, Xⱼ)`，调用 `REVISE` 使 `Xᵢ` 相对于 `Xⱼ` 弧一致。
3. **若 `Dᵢ` 未变**：直接处理下一条弧（不入队）。
4. **若 `Dᵢ` 被缩减**：把**所有弧 `(Xₖ, Xᵢ)`** 入队，其中 `Xₖ` 取遍 `Xᵢ` 的邻居**且不含 `Xⱼ`**。必须这样做，是因为 `Dᵢ` 的变化可能进一步缩减 `Dₖ`，即便 `Xₖ` 先前已经处理过。
5. **若 `Dᵢ` 被缩减到空**：整个 CSP 必然无解，AC-3 立即返回 `false`。
6. **终止条件**：队列为空。此时得到的 CSP 与原 CSP **等价**（解集相同），但域更小、搜索更快。
7. 两种极端结果：所有域缩到大小 1（问题被彻底解出），或某个域缩到 0（证明无解）。

**AC-3 的复杂度**（逐字照录）：设 CSP 有 `n` 个变量，域大小至多 `d`，有 `c` 条二元约束（弧）。每条弧 `(Xₖ,Xᵢ)` **最多只能入队 `d` 次**（因为 `Xᵢ` 至多只有 `d` 个值可删）；检查一条弧的一致性耗时 `O(d²)`，因此**总最坏情况时间为 `O(cd³)`**。

> 名字 "AC-3" 来自发明者 Mackworth (1977)：它是那篇论文里开发的第三个版本。
> ⚠️ 待核：图 6.3 中 `revised ← true` 写在 `for` 循环**之外**（与第 3 版一致），按字面 `REVISE` 恒返回 true；实际实现通常把它放进 `delete` 分支内。

### 6.2.3 路径一致性

设想只用**红、蓝**两色给澳大利亚地图上色。弧一致性什么都做不了——每条约束单独看都能满足（一端红、一端蓝）。但**显然无解**：WA、NT、SA 两两接壤，光这三块就需要至少三种颜色。

弧一致性是用弧（二元约束）去收紧域（一元约束）。要在地图着色这类问题上取得进展，需要更强的概念——**路径一致性**（path consistency）用考察**三元组变量**推出的隐式约束去收紧**二元约束**：

> 二变量集合 `{Xᵢ, Xⱼ}` **相对于第三个变量 `Xₘ` 路径一致**，当且仅当：对每个满足 `{Xᵢ,Xⱼ}` 上约束（若有）的赋值 `{Xᵢ = a, Xⱼ = b}`，都存在 `Xₘ` 的某个赋值，同时满足 `{Xᵢ,Xₘ}` 与 `{Xₘ,Xⱼ}` 上的约束。

名字指的是：**以 `Xₘ` 为中间节点的、从 `Xᵢ` 到 `Xⱼ` 的整条路径**的整体一致性。

**两色澳大利亚的推演**：让 `{WA,SA}` 相对于 `NT` 路径一致。先枚举 `{WA,SA}` 的相容赋值，只有两个：`{WA=red, SA=blue}` 与 `{WA=blue, SA=red}`。对这两个赋值，`NT` 既不能红也不能蓝（无论取哪个都会与 WA 或 SA 冲突）。既然 `NT` 无合法取值，就把这两个赋值**都删掉**——于是 `{WA,SA}` 不再有任何合法赋值，**该问题无解**。

### 6.2.4 k-一致性

用 **k-一致性**（k-consistency）可以定义更强的传播形式：

> 一个 CSP 是 **k-一致的**，当且仅当：对任意 `k−1` 个变量的集合及其任意相容赋值，总能为**任意第 `k` 个变量**找到一个相容的值。

层级关系（这是 T5 易混点，务必分清）：

| 级别 | 等价概念 |
|---|---|
| 1-一致性 | 就是前面说的**节点一致性** |
| 2-一致性 | 就是**弧一致性** |
| 3-一致性 | 对**二元约束图**而言就是**路径一致性** |

**强 k-一致**（strongly k-consistent）：既是 k-一致的，也是 (k−1)-一致的、(k−2)-一致的……一直到 1-一致的。

设 CSP 有 `n` 个节点，若把它做成**强 n-一致**的，就可以这样求解：先为 `X₁` 选一个相容值；由于图 2-一致，`X₂` 必有值可选；由于 3-一致，`X₃` 必有值可选……对每个 `Xᵢ`，只需在域中的 `d` 个值里搜索一个与 `X₁,…,Xᵢ₋₁` 相容的值即可。**总运行时间仅 `O(n²d)`**。

> ⚠️ **天下没有免费午餐**：CSP 一般是 NP-complete 的，**任何建立 n-一致性的算法在最坏情况下都必须花关于 n 指数的时间**；更糟的是，n-一致性还要求**关于 n 指数的空间**。
> 实践中，"检查到哪一级一致性"主要是一门**经验科学**：算 2-一致性很常见，算 3-一致性就不那么常见了。

### 6.2.5 全局约束

**Alldiff** 的一种简单不一致检测：若约束涉及 `m` 个变量，它们合起来只有 `n` 个不同的可能取值，且 `m > n`，则该约束不可能被满足。（注意此处 `m`、`n` 是本节局部记号，与全章的"变量数 n"无关。）

由此得到如下简单算法：

1. 反复做：找出约束中**域已退化为单值**的变量，把它的值从其余变量的域中删掉；只要还有这种单值变量就继续。
2. 若某时刻**出现空域**，或**剩余变量数多于剩余取值数**，就检测到不一致。

这个方法能查出 Figure 6.1 中赋值 `{WA=red, NSW=red}` 的不一致：`SA`、`NT`、`Q` 两两必须不同色，实际上被一条 Alldiff 连着；在给定该部分赋值后跑 AC-3，三者的域都缩为 `{green, blue}`——**三个变量、只有两种颜色**，Alldiff 被违反。

> 结论：**对高阶约束做简单一致性检查，有时比对等价的一组二元约束做弧一致性更有效**。

**资源约束**（resource constraint），又称 **Atmost 约束**：设 `P₁,…,P₄` 是分给四项任务的人数，总人数不超过 10 写成 `Atmost(10, P₁,P₂,P₃,P₄)`。

- **检测不一致**：只要检查各当前域的**最小值之和**。若每个变量的域都是 `{3,4,5,6}`，最小和 12 > 10，Atmost 无法满足。
- **强制一致性**：删掉任何与其余变量最小值不相容的**最大值**。若每个变量的域是 `{2,3,4,5,6}`，则可从每个域中删掉 5 和 6。

**界传播**（bounds propagation）：对涉及成千上万人的大型资源受限整数问题，不可能把每个变量的域表示成庞大的整数集合再逐步缩减；改为用**上下界**表示域。例：两架航班 `F₁`、`F₂` 的载客容量分别为 165 与 385，初始域 `D₁ = [0,165]`、`D₂ = [0,385]`；加上约束 `F₁ + F₂ = 420` 后传播界，得到 `D₁ = [35,165]`、`D₂ = [255,385]`。

> **界一致**（bounds-consistent）：对每个变量 `X`，以及 `X` 的下界值与上界值，对每个变量 `Y` 都存在某个 `Y` 的取值使 `X` 与 `Y` 之间的约束被满足。界传播在实际约束问题中应用广泛。

### 6.2.6 数独

数独让数百万人接触了 CSP（尽管他们未必意识到）。棋盘 81 格，部分预填 1–9，要求填满其余格子，使每行、每列、每个 `3×3` 宫中没有重复数字。**行、列、宫统称单元**（unit）。报纸与谜题书上的数独**恰有一个解**；人工解某些题要几十分钟，而 CSP 求解器每秒可解数千道题。

建模：**81 个变量**，顶行从左到右 `A1…A9`，底行 `I1…I9`；空格的域是 `{1,…,9}`，预填格的域是单值；另有 **27 条 Alldiff 约束**（9 行 + 9 列 + 9 宫）：

```
Alldiff(A1,A2,A3,A4,A5,A6,A7,A8,A9)      …（行）
Alldiff(A1,B1,C1,D1,E1,F1,G1,H1,I1)      …（列）
Alldiff(A1,A2,A3,B1,B2,B3,C1,C2,C3)      …（宫）
```

**弧一致性走多远？**（假设 Alldiff 已展开为 `A1≠A2` 之类的二元约束，以便直接跑 AC-3）

- 变量 `E6`（中间宫里位于 2 与 8 之间的空格）：由宫的约束删掉 1、2、7、8；由列的约束删掉 5、6、2、8、9、3。剩下 `D = {4}`——**已经知道答案了**。
- 变量 `I6`（底部中间宫里被 1、3、3 包围的格子）：由列删掉 5、6、2、4（因为已知 `E6` 必为 4）、8、9、3；再通过与 `I5` 的弧一致性删掉 1，只剩 `{7}`。
- 此时第 6 列已有 8 个已知值，弧一致性可推出 `A6 = 1`。

如此推进，**AC-3 最终能解出整道谜题**（所有变量的域都缩为单值，见 Figure 6.4(b)）。

> 当然，若每道题都能靠机械地跑 AC-3 解出，数独就没意思了——**AC-3 只对最简单的数独有效**。稍难的要靠 PC-2，代价更高：一道数独要考虑 **255,960** 条不同的路径约束。最难的题需要更聪明的办法。

人类解题者用的复杂策略有各种花名，例如 **naked triples（显性三元组）**：

> 在任一单元中，找三个格子，它们的域都包含同三个数字（或其子集），例如 `{1,8}`、`{3,8}`、`{1,3,8}`。虽然不知道哪个格子是 1、3、8，但知道这三个数必然分布在这三个格子里，于是可以把 1、3、8 从该单元**其他所有格子**的域中删掉。

> **注意**：除"81 个变量、域为 1–9、27 条 Alldiff"之外，其余策略（弧一致性、路径一致性乃至 naked triples）**全部通用于所有 CSP**，并非数独专属——naked triples 本质上就是一种强制 Alldiff 约束一致性的策略。**这正是 CSP 形式体系的力量所在**：面对新问题域，只需把问题写成约束，剩下的交给通用求解机制。

## 6.3 CSP 的回溯搜索（Backtracking Search for CSPs）

有时把约束传播做完，仍有变量带着多个可能值，那就必须**搜索**。本节讨论作用于**部分赋值**的回溯搜索；下一节讨论作用于**完整赋值**的局部搜索。

**先看清"可交换性"带来的巨大收益。** 若用第 3 章的标准深度受限搜索：状态是部分赋值，动作是扩展赋值。对 `n` 个变量、域大小 `d` 的 CSP，搜索树顶层分支因子是 `nd`（`n` 个变量任选、`d` 个值任选），下一层 `(n−1)d`，如此 `n` 层——**搜索树有 `n!·dⁿ` 个叶子，尽管完整赋值总共只有 `dⁿ` 个！**

去掉那多余的 `n!` 因子，靠的是 CSP 的关键性质——**可交换性**（commutativity）：

> 若**任意给定动作集的施加顺序不影响结果**，则称该问题可交换。CSP 中，先赋 `NSW=red` 再赋 `SA=blue`，与反过来做，毫无区别。

因此**搜索树的每个节点只需考虑一个变量**：根节点上可以在 `SA=red`、`SA=green`、`SA=blue` 之间选择，但绝不会在 `NSW=red` 与 `SA=blue` 之间选择。**叶子数降回 `dⁿ`**。每层仍需决定"先处理哪个变量"，但**永远不必在这个选择上回溯**。

`BACKTRACKING-SEARCH`（Figure 6.5）：

```
function BACKTRACKING-SEARCH(csp) returns a solution or failure
    return BACKTRACK(csp, { })

function BACKTRACK(csp, assignment) returns a solution or failure
    if assignment is complete then return assignment
    var ← SELECT-UNASSIGNED-VARIABLE(csp, assignment)
    for each value in ORDER-DOMAIN-VALUES(csp, var, assignment) do
        if value is consistent with assignment then
            add {var = value} to assignment
            inferences ← INFERENCE(csp, var, assignment)
            if inferences ≠ failure then
                add inferences to csp
                result ← BACKTRACK(csp, assignment)
                if result ≠ failure then return result
                remove inferences from csp
        remove {var = value} from assignment
    return failure
```

- `SELECT-UNASSIGNED-VARIABLE` 与 `ORDER-DOMAIN-VALUES` 实现 6.3.1 的通用启发式；`INFERENCE` 可按需施加弧、路径或 k-一致性。
- 若某个取值导致失败（由 `INFERENCE` 或 `BACKTRACK` 发现），就把赋值（含 `INFERENCE` 所做的赋值）撤销，换下一个值；所有值都不行则返回 failure。
- 注意它**只维护状态的一份表示**（赋值）并**就地修改**这份表示，而不是创建新表示（见第 80 页）。

**关键**：第 3 章的无信息搜索只能靠**领域专属**启发式改进；而回溯搜索可以用**领域无关**的启发式改进，因为它利用了 CSP 的因子化表示。后文四小节分别回答：

1. （6.3.1）下一步该给哪个变量赋值（`SELECT-UNASSIGNED-VARIABLE`），它的值按什么顺序试（`ORDER-DOMAIN-VALUES`）？
2. （6.3.2）搜索的每一步该做哪些推断（`INFERENCE`）？
3. （6.3.3）能不能在适当时候**一次回退多步**？
4. （6.3.4）能不能**保存并复用**搜索中的部分结果？

### 6.3.1 变量与值排序

`SELECT-UNASSIGNED-VARIABLE` 最简单的策略是**静态排序**（按 `X₁,X₂,…` 依次选），其次是**随机选**，两者都不优。

例：Figure 6.6 中赋了 `WA=red`、`NT=green` 之后，`SA` 只剩一个可能值，此时显然应该先赋 `SA=blue` 而不是去赋 `Q`；事实上 `SA` 一旦赋值，`Q`、`NSW`、`V` 的选择全都被迫确定。

**最小剩余值**（minimum-remaining-values, MRV）启发式正是这个直觉——**选合法取值最少的变量**。它也叫 **"最受约束变量"**（most constrained variable）或 **"失败优先"**（fail-first）启发式：后者是因为它挑的变量**最可能马上导致失败**，从而剪掉搜索树。

- 若某个变量 `X` 已无合法值，MRV 会选中 `X`，**立即检测到失败**，避免在其他变量上做无谓搜索。
- MRV 通常比随机或静态排序好，**有时好上几个数量级**（因问题而异）。

**度启发式**（degree heuristic）：MRV 在给澳大利亚上色时**选第一步毫无帮助**（初始每个区域都有三种合法颜色）。此时度启发式派上用场：它**选与最多未赋值变量有约束关系的变量**，以降低未来选择的分支因子。

- Figure 6.1 中 `SA` 的度最高，为 **5**；其余变量度为 2 或 3，只有 `T` 的度为 **0**。
- 事实上，一旦选中 `SA`，再用度启发式就能**一步不错地解完**——每个选择点上任取一个相容颜色都能走到解，无需回溯。
- MRV 通常是更强的向导，**度启发式可作为打破平局的手段**。

**最小约束值**（least-constraining-value）启发式解决"值按什么顺序试"：**优先选那个给邻居变量排除掉最少选择的值**。

例：Figure 6.1 中已有 `WA=red`、`NT=green`，下一个要给 `Q` 赋值。选 blue 是坏选择，因为它会消掉 `Q` 的邻居 `SA` 仅剩的最后合法值；因此最小约束值启发式**偏好 red 而非 blue**。总体而言，该启发式试图为后续赋值**留下最大的灵活性**。

> **为什么选变量要"失败优先"，选值却要"失败最后"？**
> 每个变量**迟早都要被赋值**，所以先挑最可能失败的那些，平均而言需要回溯的成功赋值就更少。
> 而选值时我们**只需要一个解**，因此先试最可能的值说得通。（若想枚举全部解而非只找一个，值的排序就无关紧要了。）

### 6.3.2 搜索与推断交错进行

AC-3 可以在搜索开始前缩减各变量的域，但**推断在搜索过程中威力更大**：每当我们为某变量选定一个值，就有了**全新机会**去推断邻居变量上的域缩减。

**向前检查**（forward checking）是最简单的形式之一：每当变量 `X` 被赋值，就为它建立弧一致性——对每个通过约束与 `X` 相连的**未赋值**变量 `Y`，从 `Y` 的域中删掉所有与 `X` 所选值不相容的值。

Figure 6.7 展示了澳大利亚 CSP 上带向前检查的回溯过程，两个要点：

1. 赋完 `WA=red` 与 `Q=green` 后，`NT` 与 `SA` 的域都缩为单值——通过从 `WA`、`Q` 传播信息，**完全消掉了这两个变量上的分支**。
2. 赋完 `V=blue` 后，`SA` 的域变空，向前检查**立即发现部分赋值 `{WA=red, Q=green, V=blue}` 与问题约束不相容**，算法立刻回溯。

**MRV + 向前检查**：赋完 `{WA=red}` 后，直觉上该约束它的邻居 `NT`、`SA`，先处理它们，其余变量就会各就各位——MRV 正是如此：`NT` 与 `SA` 各剩两个值，先选其中一个、再另一个，然后是 `Q`、`NSW`、`V`，最后 `T` 仍剩三个值且任取其一都行。可以说，**向前检查是增量计算 MRV 所需信息的高效方式**。

**向前检查的盲区**：它看得不够远。仍看 Figure 6.7 的 `Q=green` 那一行：我们让 `WA` 与 `Q` 弧一致了，却把 `NT` 与 `SA` 都留成"只有 blue"——而它们**互为邻居**，这就是不一致。

**MAC**（Maintaining Arc Consistency）能发现这类不一致：变量 `Xᵢ` 赋值后，`INFERENCE` 调用 AC-3，但**队列初始只含弧 `(Xⱼ, Xᵢ)`**，其中 `Xⱼ` 取遍 `Xᵢ` 的**未赋值邻居变量**（注意方向：从邻居指向 `Xᵢ`，这样 `REVISE` 缩减的是邻居的域）。此后 AC-3 照常做约束传播；若任何变量的域被缩减为空集，AC-3 调用失败，立即回溯。

> **MAC 严格强于向前检查**：在 MAC 队列的初始弧上，向前检查做的与 MAC 相同；但**与 MAC 不同，向前检查在域发生变化时不做递归传播**。

### 6.3.3 智能回溯：向后看

Figure 6.5 的策略很朴素：某分支失败就退回**前一个**变量、换一个值再试。这叫**时序回溯**（chronological backtracking）——总是重访最近的决策点。本节考虑更好的做法。

**回跳**（backjumping）的动机：在 Figure 6.1 上按固定顺序 `Q, NSW, V, T, SA, WA, NT` 做简单回溯，若已生成部分赋值 `{Q=red, NSW=green, V=blue, T=red}`，下一个变量 `SA` 的每个值都违反约束，于是**退回 `T` 去换塔斯马尼亚的颜色**——显然荒谬，给塔斯马尼亚换色不可能解决南澳的问题。

更聪明的做法是**回退到那个可能修好问题的变量**，即那个"使 `SA` 的某个可能值变得不可能"的变量。为此，跟踪一组**与 `SA` 的某个值冲突**的赋值——这个集合（本例中是 `{Q=red, NSW=green, V=blue}`）称为 `SA` 的**冲突集**（conflict set）。**回跳**方法回退到冲突集中**最近**的那个赋值：本例中**跳过塔斯马尼亚、直接给 `V` 换新值**。

- 实现：修改 `BACKTRACK`，让它在检查合法值的过程中**累积冲突集**；若找不到合法值，算法返回**冲突集中最近的元素**外加失败标志。
- **向前检查可以零额外开销地提供冲突集**：每当基于赋值 `X = x` 的向前检查从 `Y` 的域中删掉一个值，就把 `X = x` 加入 `Y` 的冲突集；若 `Y` 的域中最后一个值被删掉，就把 `Y` 冲突集中的赋值并入 `X` 的冲突集——即"已知 `X = x` 导致矛盾（在 `Y` 上），因此该给 `X` 换个赋值"。

> ⚠️ **简单回跳其实是冗余的**：回跳发生在"域中每个值都与当前赋值冲突"时，而向前检查**恰恰会检测到这一事件**，使搜索根本到不了那样的节点。事实上可以证明——**凡是被回跳剪掉的分支，也都会被向前检查剪掉**。因此，在一个用向前检查的搜索中（或更强的如 MAC 的搜索中），简单回跳是多余的，二者取其一即可。

**冲突导向回跳**（conflict-directed backjumping）保留了"按失败原因回溯"的好想法。回跳只在"变量的域变空"时才发现失败，但**很多分支早在那时之前就已经注定失败**：

再看部分赋值 `{WA=red, NSW=red}`（已知不相容）。假设接下来试 `T=red`，然后依次赋 `NT`、`Q`、`V`、`SA`。我们知道最后四个变量不可能有解，于是最终在 `NT` 上耗尽取值。此时该往哪回溯？

- 回跳**不管用**：`NT` 确实有与前面已赋值变量相容的值——`NT` 并没有一个由前述变量构成的**完整冲突集**导致它失败。
- 但我们知道：`NT`、`Q`、`V`、`SA` 这四个变量**合在一起**失败，是由一组前述变量造成的，那必然是直接与这四个冲突的变量（本例中是 `WA` 与 `NSW`）。

这就引出对 `NT` 这类变量的**更深一层冲突集**定义：**导致 `NT` 连同其后继变量一起无解的那组先前变量**。本例中该集合是 `{WA, NSW}`，算法应回退到 `NSW`、跳过塔斯马尼亚。

**冲突集如何计算**（原书逐步示例）：

1. 分支的"终极"失败总是发生在某个变量的域变空时；该变量有**标准冲突集**。本例中 `SA` 失败，其冲突集是（比如说）`{WA, NT, Q}`。
2. 回跳到 `Q`；`Q` 把 `SA` 的冲突集（当然要去掉 `Q` 自身）**吸收**进自己的直接冲突集 `{NT, NSW}`，得到新冲突集 `{WA, NT, NSW}`。含义是：给定 `{WA,NT,NSW}` 的先前赋值，从 `Q` 往后无解。
3. 于是回退到其中最近的 `NT`。`NT` 把 `{WA,NT,NSW} − {NT}` 吸收进自己的直接冲突集 `{WA}`，得到 `{WA, NSW}`（与前一段所述一致）。
4. 现在算法**回跳到 `NSW`**——正是我们希望的。

**汇总公式**：设 `Xⱼ` 为当前变量，`conf(Xⱼ)` 为其冲突集。若 `Xⱼ` 的每个可能值都失败，则回跳到 `conf(Xⱼ)` 中**最近的**变量 `Xᵢ`，并按

```
conf(Xᵢ) ← conf(Xᵢ) ∪ conf(Xⱼ) − {Xᵢ}
```

重算 `Xᵢ` 的冲突集。

### 6.3.4 约束学习

遇到矛盾时，回跳能告诉我们**该退多远**，省去修改那些修不好问题的变量的工夫。但我们还想**避免再次撞上同一个问题**。搜索到达矛盾时，我们知道冲突集的某个子集应对此负责。**约束学习**（constraint learning）就是**从冲突集中找出导致问题的最小变量集合**；这组变量连同其对应的值称为一个 **no-good**。我们把 no-good 记录下来——要么给 CSP **增加一条新约束**以禁止该赋值组合，要么**另存一份 no-good 缓存**。

例：Figure 6.6 最底行的状态 `{WA=red, NT=green, Q=blue}` 是 no-good，因为 `SA` 无合法赋值（向前检查即可告知）。

- 在这个具体情形下，记录它**没用**：一旦把这根分支从搜索树中剪掉，就再也不会遇到这个组合。
- 但若 Figure 6.6 的树其实是一棵**更大的搜索树**的一部分，而那棵大树的开头是先给 `V` 与 `T` 赋值，那么把 `{WA=red, NT=green, Q=blue}` 记为 no-good 就**很值得**——因为对 `V` 与 `T` 的每种可能赋值组合，我们都会重新撞上同一个问题。

no-good 可被向前检查或回跳有效利用。**约束学习是现代 CSP 求解器在复杂问题上取得高效率的最重要技术之一。**

## 6.4 CSP 的局部搜索（Local Search for CSPs）

局部搜索算法（4.1 节）对求解许多 CSP 极为有效。它们使用**完整状态形式化**：每个状态给**每个**变量都赋了值，搜索每次改变**一个**变量的值。

以 8 皇后（第 183 页定义为 CSP）为例，Figure 6.8：

1. 从左边的完整赋值出发（通常会违反若干约束）；
2. **随机选一个冲突变量**，结果是 `Q₈`（最右一列）；
3. 我们想把它改成能让冲突更少的值——最自然的做法是**选使与其他变量的冲突数最小的**值，即 **最小冲突**（min-conflicts）启发式。图中可见有两行只违反一条约束，于是取 `Q₈ = 3`（把皇后移到第 8 列第 3 行）；
4. 下一轮（图中中间的棋盘）选中 `Q₆` 作为要改的变量，把皇后移到第 8 行**不产生任何冲突**；
5. 此时再无冲突变量，得到解。

```
function MIN-CONFLICTS(csp, max_steps) returns a solution or failure
    inputs: csp, a constraint satisfaction problem
            max_steps, the number of steps allowed before giving up
    current ← an initial complete assignment for csp
    for i = 1 to max_steps do
        if current is a solution for csp then return current
        var ← a randomly chosen conflicted variable from csp.VARIABLES
        value ← the value v for var that minimizes CONFLICTS(csp, var, v, current)
        set var = value in current
    return failure
```

- 初始状态可随机选，也可用贪心过程依次为每个变量选一个最小冲突值。
- `CONFLICTS` 函数统计在给定其余当前赋值的情况下，某个值所违反的约束数。

**最小冲突出奇地有效**。令人惊讶的是，在 n 皇后问题上，**若不计皇后的初始放置，最小冲突的运行时间大致与问题规模无关**——**它解百万皇后问题平均只需 50 步**（初始赋值之后）。这一惊人观察是 1990 年代关于局部搜索以及"易问题 vs 难问题"之分的大量研究的**导火索**，我们在 7.6.3 节继续讨论。粗略地说，n 皇后对局部搜索容易，是因为**解在状态空间中分布得非常密集**。

最小冲突对难问题同样有效：它已被用于**哈勃太空望远镜的观测调度**，把排一周观测所需的时间从**三周**（！）降到**约 10 分钟**。

4.1 节的所有局部搜索技术都可用于 CSP，其中几种尤其有效：

| 技术 | 作用 |
|---|---|
| **高原搜索**（plateau search，允许**侧向移动**到同分值状态） | 最小冲突启发式下的 CSP 地形常有成片的高原——可能有数百万个"只差一个冲突"的赋值；侧向移动帮助算法走下高原 |
| **禁忌搜索**（tabu search） | 保存一张最近访问状态的小名单，禁止算法回到这些状态，为高原上的游走提供方向 |
| **模拟退火** | 也可用于逃离高原 |
| **约束加权**（constraint weighting） | 给每条约束一个数值权重（初始全为 1）。每步选择**使被违反约束的总权重最小**的变量/值对来修改，然后把当前赋值所违反的每条约束的权重**加 1**。好处有二：给高原加上地形（保证总有改进方向），以及带来**学习**——难的约束随时间获得更高权重 |

局部搜索的另一优势是可用于**在线**场景（4.5 节）——当问题发生变化时。例：某航空公司一周航班的调度涉及数千航班与数万人员指派，一个机场的恶劣天气就能让整份调度不可行，我们希望**以最少改动修复调度**。从当前调度出发跑局部搜索即可轻松做到；而用新约束集做回溯搜索通常耗时多得多，且可能得到一个与当前调度相差很大的解。

> 原书脚注：局部搜索很容易推广到约束优化问题（COP），此时爬山与模拟退火的整套技术都可用来优化目标函数。

## 6.5 问题的结构（The Structure of Problems）

本节考察**约束图的结构**如何被用来快速求解。这里的多数方法也适用于 CSP 之外的其他问题，例如概率推理。

**要应对庞大的真实世界，唯一希望是把它分解成子问题。** 再看澳大利亚的约束图（Figure 6.12(a)），一个事实很突出：**塔斯马尼亚不与大陆相连**。直觉上显然——给塔斯马尼亚着色与给大陆着色是**独立子问题**（independent subproblems）：大陆的任意解配上塔斯马尼亚的任意解，就是整张地图的解。

这种独立性只需**找出约束图的连通分量**（connected component）即可确定：每个分量对应一个子问题 `CSPᵢ`；若 `Sᵢ` 是 `CSPᵢ` 的解，则 `⋃ᵢ Sᵢ` 是 `⋃ᵢ CSPᵢ` 的解。

**为什么重要？** 设每个 `CSPᵢ` 有 `c` 个变量（`c` 为常数），总共 `n` 个变量，则有 `n/c` 个子问题，每个至多花 `dᶜ` 的功夫。于是**总工作量 `O(dᶜ · n/c)`，关于 `n` 是线性的**；不分解则是 `O(dⁿ)`，**关于 `n` 是指数的**。

> 说得具体些：把一个含 100 个布尔变量的 CSP 分成四个子问题，最坏情况求解时间从**宇宙的寿命**降到**不到一秒**。

完全独立的子问题很美妙但罕见。幸运的是，某些其他图结构同样易解。例如**约束图是树**（任意两变量间只有一条通路）时——我们将证明**任何树状 CSP 都能在关于变量数线性的时间内求解**。

关键是新的一致性概念——**有向弧一致性**（directional arc consistency, DAC）：

> 在变量序 `X₁, X₂, …, Xₙ` 下，一个 CSP 是**有向弧一致的**，当且仅当每个 `Xᵢ` 相对于每个 `Xⱼ`（`j > i`）都弧一致。

求解树状 CSP 的步骤：

1. 任选一个变量作树的**根**；
2. 选一个变量序，使每个变量都排在其父节点之后——这样的序叫**拓扑排序**（topological sort，Figure 6.10）；
3. 任何含 `n` 个节点的树有 `n−1` 条边，因此可在 `O(n)` 步内使该图有向弧一致，每步最多比较两个变量的 `d` 个域值，**总时间 `O(nd²)`**；
4. 一旦有了有向弧一致图，就沿变量列表一路往下、任取剩余值即可。由于每条父→子边都弧一致，无论给父节点取什么值，子节点都必有合法值可取——**无需回溯**，可线性地穿过所有变量。

```
function TREE-CSP-SOLVER(csp) returns a solution, or failure
    inputs: csp, a CSP with components X, D, C
    n ← number of variables in X
    assignment ← an empty assignment
    root ← any variable in X
    X ← TOPOLOGICAL-SORT(X, root)
    for j = n down to 2 do
        MAKE-ARC-CONSISTENT(PARENT(Xj), Xj)
        if it cannot be made consistent then return failure
    for i = 1 to n do
        assignment[Xi] ← any consistent value from Di
        if there is no consistent value then return failure
    return assignment
```

> 若 CSP 有解，我们会在**线性时间**内找到它；若无解，我们会检测到矛盾。
> 原书题外话：细心的制图师或爱国的塔斯马尼亚人可能会反对——塔斯马尼亚不应与它最近的大陆邻州同色，以免让人误以为它是该州的一部分。另外，世界上**树状地图极少**，苏拉威西岛勉强算一个。

有了树的高效算法，就可以问：更一般的约束图能否**化为树**？有两条路——**删节点**（6.5.1）或**合并节点**（6.5.2）。

### 6.5.1 割集条件化

第一条路：给某些变量赋值，使剩下的变量构成一棵树。仍看澳大利亚（Figure 6.12(a)）——**去掉南澳后，图就变成（两棵树的）森林**（Figure 6.12(b)）。我们可以通过**固定 `SA` 的值**、并从其他变量的域中删掉任何与 `SA` 所选值不相容的值，来"删掉"南澳（图中删掉，不是地图上删掉）。于是，删去 `SA` 及其约束后的 CSP 的**任意**解，都与 `SA` 的所选值相容。（这对二元 CSP 成立；高阶约束下情形更复杂。）因此可以用上述算法解掉剩下那棵树，从而解完整个问题。当然，一般情形（不像地图着色）下给 `SA` 选的值可能是错的，所以需要把每个可能值都试一遍。

**一般算法**：

1. 选变量子集 `S`，使得从约束图中**移除 `S` 后图变成树**。`S` 称为**环割集**（cycle cutset）。
2. 对 `S` 中变量满足 `S` 上全部约束的**每种可能赋值**：
   1. 从其余变量的域中删掉与该赋值不相容的值；
   2. 若剩下的 CSP 有解，则把它连同 `S` 的赋值一起返回。

**复杂度**：若环割集大小为 `c`，则**总运行时间 `O(dᶜ · (n−c)d²)`**——要试 `S` 中变量的 `dᶜ` 种取值组合，每种组合要解一个规模 `n−c` 的树问题。

- 若图"接近树"，`c` 就小，相对朴素回溯的节省就巨大——对我们那个 100 布尔变量的例子，若能找到 `c = 20` 的割集，就能**从宇宙的寿命降到几分钟**。
- **最坏情况下 `c` 可以大到 `(n−2)`**。
- **寻找最小环割集是 NP-hard**，但已知若干高效的近似算法。
- 这套整体方法叫**割集条件化**（cutset conditioning），第 13 章做概率推理时会再次用到。

### 6.5.2 树分解

第二条路：构造约束图的**树分解**（tree decomposition）——把原图变换成一棵树，树上每个节点是**一个变量集合**（Figure 6.13）。树分解必须满足三条要求：

1. 原问题中的**每个变量**至少出现在某个树节点中；
2. 原问题中**由约束相连的两个变量**，必须（连同该约束）**同时出现**在至少一个树节点中；
3. 若一个变量出现在树的两个节点中，则它必须出现在**连接这两节点的路径上的每个节点**中。

前两条保证所有变量与约束都被表示到。第三条看似技术性，但它让我们可以说：原问题中的任何变量**无论出现在哪里都必须取相同的值**——树中的约束规定，某节点中的变量必须与相邻节点中对应变量取相同值。例：`SA` 出现在 Figure 6.13 中四个相连的节点里，于是树分解的每条边都包含"`SA` 在一个节点中的值必须等于它在下一个节点中的值"这一约束。

一旦有了树状图，就可以用 `TREE-CSP-SOLVER` 在 `O(nd²)` 时间内求解，其中 **`n` 是树节点数**，`d` 是**最大域的大小**。但要注意：在树这一层，一个域是**值的元组**的集合，而非单个值的集合。

例：Figure 6.13 左上角的节点在原问题层面代表子问题 `{WA, NT, SA}`（域 `{red,green,blue}`，约束 `WA≠NT`、`SA≠NT`、`WA≠SA`）；在树这一层，它代表**一个变量**，不妨叫 `SANTWA`，其值必须是一个三元组，如 `(red,green,blue)`，但不能是 `(red,red,blue)`（那会违反原问题的 `SA≠NT`）。然后走到相邻节点（变量 `SANTQ`），会发现只有一个元组 `(red,green,blue)` 与 `SANTWA` 的选择相容。对后两个节点重复同样过程，而 `T` 可以独立地任取。

**规模与树宽**：

- 每个节点含 10 个变量时 `d = 2¹⁰`，100 布尔变量的问题应该**几秒钟**可解；但若有节点含 **30 个变量**，就要花**几个世纪**。
- 同一图有许多树分解，选择时应**让子问题尽量小**（把所有变量塞进一个节点在技术上也是树，但没用）。
- **树分解的树宽**（tree width）＝**最大节点的大小减一**；**图的树宽**＝其所有树分解中的**最小宽度**。
- 若图的树宽为 `w`，则在给定相应树分解的情况下，问题可在 **`O(ndʷ⁺¹)`** 时间内求解。**因此，约束图树宽有界的 CSP 可在多项式时间内求解。**
- ⚠️ **寻找最小树宽的分解是 NP-hard**，但有实践中效果良好的启发式方法。

**割集 vs 树分解，哪个更好？**

| 方法 | 时间 | 内存 |
|---|---|---|
| 割集分解 | `O(dᶜ · (n−c)d²)` | **线性内存** |
| 树分解 | `O(ndʷ⁺¹)` | **关于 `w` 指数** |

- 只要存在大小为 `c` 的环割集，就存在 `w < c + 1` 的树宽，某些情形下 `w` 还会**小得多**。所以**时间上偏向树分解**。
- 但**环割集方法的优势是可用线性内存执行**，而树分解需要关于树宽指数的内存。
- 把两者结合，可以在**内存与时间之间取得更好的折中**。

### 6.5.3 值对称

前面看的是约束图的**结构**。变量的**值**之中、或约束关系本身的结构之中，也可能存在重要结构。

考虑用 `d` 种颜色做地图着色：对每个相容解，实际上存在 **`d!` 个**由**置换颜色名**得到的解。例：澳大利亚地图上，我们知道 `WA`、`NT`、`SA` 必须三者颜色互不相同，但把三种颜色分给三个区域有 `3! = 6` 种方式。这叫**值对称**（value symmetry）。我们希望通过**打破赋值中的对称**，把搜索空间缩小 `d!` 倍。

做法是引入**对称破缺约束**（symmetry-breaking constraint）。对我们的例子，可以强加一条任意的序约束 `NT < SA < WA`，要求三个值按字母序排列。该约束保证 `d!` 个解中**只有一个**是可能的：`{NT = blue, SA = green, WA = red}`。

> 对地图着色，找到消除对称的约束很容易。**一般地，消除所有对称是 NP-hard**；但打破值对称已被证明在一大类问题上重要且有效。

## 小结

1. **约束满足问题（CSP）**用一组变量/值对表示状态，用一组约束表示解的条件。许多重要的现实问题都能描述为 CSP。
2. 若干**推断技术**用约束排除某些变量赋值，包括**节点一致性、弧一致性、路径一致性与 k-一致性**。
3. **回溯搜索**（深度优先搜索的一种形式）常用于求解 CSP；推断可以与搜索交织进行。
4. **最小剩余值（MRV）与度启发式**是决定"下一步选哪个变量"的**领域无关**方法；**最小约束值启发式**帮助决定"先试哪个值"。当某变量找不到合法赋值时发生回溯；**冲突导向回跳**直接回退到问题源头；**约束学习**把搜索中遇到的冲突记录下来，以免后续重蹈覆辙。
5. 采用**最小冲突启发式的局部搜索**用于 CSP 也极为成功。
6. 求解 CSP 的**复杂度与约束图的结构密切相关**：**树状问题可在线性时间内求解**；**割集条件化**能把一般 CSP 归约为树状问题，只要能找到小割集就相当高效（且**只需线性内存**）；**树分解**技术把 CSP 变成一棵子问题树，当约束图的**树宽**小时高效，但需要**关于树宽指数的内存**。把割集条件化与树分解结合，可以在内存与时间之间取得更好的折中。
