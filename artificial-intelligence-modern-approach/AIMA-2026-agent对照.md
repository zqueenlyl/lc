# AIMA 在 2026 Agent 时代还剩什么

> **用途**：把《人工智能：现代方法》第 4 版对照 2026 年的 agent 实践。上一半是「哪些还能用」的压缩；下一半是「哪些实现已经过时、现在换成什么」。
> **书**：Stuart Russell、Peter Norvig，《人工智能：现代方法》第 4 版（2020）。本目录章节笔记是学习笔记，不是逐字译文。
> **对照日期**：2026-10-08。前沿数字来自文末列出的论文与基准，会过期；范式判断比单个百分比耐放。
> **不覆盖**：不替代各章笔记，也不改原书表述。

---

## 0. 一句话

第 4 版写在工具调用和长程 agent 普及之前。不过时的是它给 agent 起的名字和问题结构：环境有多难、信念和目标怎么分开、计划为什么会在执行中作废、多个决策者为什么不能各写各的最优脚本。过时的是把这些结构亲手算出来的那套实现：归结、全联合分布、价值迭代、2020 年的网络结构，都不再是 agent 的内核。

2026 年的 agent 程序是：**一个大模型负责在测试时选择下一步，脚手架负责状态、工具、记忆、计划和审批。** 模型是策略，不是整个智能体。

## 1. 前两轮结论（压缩）

### 1.1 第 12–18 章在讲什么

这七章是一条线：先在说不准的世界里更新信念，再按「我想要什么」做决定，最后变成多个会互相反应的决策者。

| 章 | 问题 | 留下的一句 |
| --- | --- | --- |
| 12 不确定性的量化 | 逻辑的真假不够用 | 用信念度；理性动作是期望效用最大的那个 |
| 13 概率推理 | 全联合分布存不下 | 用图写下直接依赖；「看见」和「动手改」不是一回事 |
| 14 时间上的概率推理 | 信念要随时间滚 | 滤波估现在，平滑回头看，最可能序列是整条轨迹一起挑 |
| 15 概率编程 | 对象个数和身份也可以不确定 | 可能世界可以是一段生成过程，难在「这条观测属于谁」 |
| 16 做简单决策 | 信念还要配上效用 | 只有会改变下一步动作的信息才有价值；偏好不确定时保持可纠正 |
| 17 做复杂决策 | 现在的动作会改未来 | 看得到状态用 MDP；看不全就维持信念状态；探索和利用要分开 |
| 18 多智能体决策 | 别人也会针对你反应 | 最优由均衡定义；分任务、拍卖、投票会改变参与者怎么报 |

### 1.2 哪些还能当设计语言

**第 2 章最经用。** 智能体是感知再行动。好不好看性能度量，不看像不像人。部分可观测、随机、序贯、动态、多智能体，就是现在写代码、操作电脑、跑长任务的环境。结构分层还在：只对当前输入做反应的，是没有世界状态的单轮调用；带内部模型的，才记得已经发生了什么；再往上才是有目标、有效用、能从结果里改自己。性能度量写成「看起来在干活」，agent 就会刷无效步骤。吸尘器把灰倒出来再吸、好刷干净次数，就是评价被钻空子。

**第 1 章把标准定成做对的事。** 模型默认被训练成说得像人。agent 要交付的是任务后果。两件事混在一起，评估就会漂。

### 1.3 哪些还能当决策骨架

**第 12、16、17 章把「世界怎样」和「我要什么」拆开。** 没有人在每次工具调用里把期望效用算出来，但这仍是「这一步该不该做」的问法。信息价值对应再查一次、再问用户一句值不值得。信念状态对应 agent 看不见全貌，只能维持一份「现在大概怎样」；上下文窗口是这份判断的一种很损的载体。老虎机对应选模型、选工具、要不要再试一条没走过的路。偏好不确定时避免走了就回不来的动作，对应对删数据、付款、对外发送加人工确认。

**第 18 章因为行业走到了多智能体，反而更贴。** 目标相同要靠惯例避免互相踩踏。合同网就是招标分任务。几个 agent 报结果再合并时，合并规则本身会改变它们怎么报。

### 1.4 拿问题结构，别照搬求解器

**第 3、4、11 章解释长任务为什么会断。** 有用的是：动作有前提和效果、高层动作再往下拆、计划失效后重做、想不完也得先动。Graphplan、把规划编成可满足性问题，不是要写进 agent 里的算法。

**第 6 章：约束留给求解器。** 排班、配置、资源冲突去调用专门程序，不要让模型在文本里硬凑一个满足全部约束的解。

**第 7–10 章用来认识失败。** 限定问题和框架问题说明规则列不完例外，动作之后哪些事实没变也不能靠穷举。这正是模型忘掉前提、编造世界状态的原因。该留下来的是「哪些东西必须显式记在状态里」。归结和一阶逻辑定理证明不是主路径。

### 1.5 当作底片

**第 19–24 章：** 学习和语言是 agent 的部件。奖励、信用分配这些词还能对上偏好训练。深度网络和经典自然语言流水线的具体结构，对不上长上下文、工具协议和测试时多花的算力。

**第 25–26 章：** 纯软件 agent 用处有限。做操作界面或机器人时，感知—行动闭环仍然是对的问题；具体算法以现在的多模态模型为准。

**第 27 章：** 武器、监视、偏见、工作、安全这些问法还在。安全那一节和性能度量、能不能被纠正，是同一件事。技术细节停在 2020 年。

## 2. 2026 年 agent 实际在做什么

用第 2 章的词把现在的系统翻译一遍：

| AIMA 部件 | 2026 年的对应物 |
| --- | --- |
| 传感器 | 文件、终端输出、网页、屏幕截图、工具返回的结构化结果 |
| 执行器 | 改文件、跑命令、点界面、调用工具、发消息 |
| 智能体程序 | 模型 + 脚手架。脚手架管循环、显式状态、工具路由、记忆、审批 |
| 性能度量 | 任务是否完成、测试是否通过、副作用是否可接受。不是回答像不像人 |
| 环境 | 部分可观测、随机、序贯、动态，而且常常已经是多智能体 |

四件已经落地进行的事：

1. **工具是单独一层，而且正在变成动作层。** 模型上下文协议（MCP）是目前公开 agent 工具的主流接口。一项对 2024-11 至 2026-02 公开 MCP 工具的清点覆盖约 17.7 万个工具：软件开发约占工具数的 67%、服务器下载的 90%；按使用量看，直接改外部环境的「动作类」工具占比从约 27% 升到约 65%。多数动作仍是改文件这类中等后果的事，也已经出现付款这类更高后果的工具。
2. **电脑使用是「看屏幕」和「调工具」混在一起。** OSWorld-MCP（ICLR 2026）在真实桌面里同时考图形界面操作和工具调用。接上 MCP 工具后任务成功率上升（例如 o3 在 15 步设定从 8.3% 到 17.6%，Claude 4 Sonnet 在 50 步设定从 38.9% 到 45.0%），但强模型真正去调用工具的比例仍然只有约三分之一。工具摆在那里，模型经常继续用又慢又容易点错的界面动作。
3. **长任务不再指望一个 agent 从头串到尾。** 多智能体电脑使用（MACU）让一个管理者把任务拆成有依赖的有向无环图，准备好的子任务并行交给子 agent，新观测一到就增、删、改节点。相对强的单 agent，桌面和网页基准上成功率高约 3.4 到 25.5 个百分点；在长程网页任务上，完成时间大约快到 1.5 倍。管理者留住子 agent 以后看不到的信息，就是在部分可观测环境里传递信念。
4. **评价看轨迹，不看单次回答。** MCP-Bench（ICLR 2026）把模型接到 28 个活的服务器、约 250 个工具上，考的是多步里工具能不能接上、参数对不对、计划有没有按依赖走完。执行成功和任务成功是两件事。

这些系统没有在内部跑变量消元或价值迭代。它们把第 11、16、17、18 章的问题结构做进了循环：观察，决定要不要再花一步去获取信息，行动，更新显式状态，计划作废就改，多个工作者并行，不可逆动作停下来等人。

## 3. 过时的实现，和换成的范式

「过时」指：**不要再把它当成 agent 的实现来抄。** 同一行右侧是这本书仍然在问的那个问题。

| 章节 | 不要再当实现来抄 | 2026 年的做法 | 书里还站得住的问题 |
| --- | --- | --- | --- |
| 1–2 | 用一张感知–动作表实现智能体；用「像人」当完成标准 | 模型出下一步，脚手架保状态和边界；用任务后果打分 | 理性、性能度量、环境分类、反射 / 模型 / 目标 / 效用 / 学习这几层 |
| 3–5 | 把 A\*、α-β 剪枝写成智能体本体 | 测试时对思路或动作分支搜索、并行采样、失败重试。博弈搜索留给下棋和红队 | 启发式、想不完就先动、对手会针对你 |
| 6 | 让模型在文本里解约束 | 把约束交给求解器、数据库或代码，模型只负责把问题交出去并读结果 | 组合约束不该靠抽样碰运气 |
| 7–10 | 归结、一阶逻辑定理证明、手工搭一个封闭本体当内核 | 模型携带隐式知识；可核查的事实放在显式状态、文件和检索里 | 例外列不完；动作之后必须明确哪些事实变了、哪些没变 |
| 11 | Graphplan、可满足性规划、离线算出完整计划再执行 | 技能和工作流是高层动作。管理者拆开依赖图，边执行边改计划 | 前提与效果、分层、无传感时的应变、在线重规划 |
| 12–15 | 手写贝叶斯网、每次查询做变量消元或粒子滤波，作为主循环 | 日常不确定性留在模型里。身份、金额、权限等要核的量，用代码、检索和校验算死 | 信念要随证据改；干预不同于观察；多对象时要回答「这条观测是谁的」 |
| 16–17 | 每个动作枚举期望效用；价值迭代求最优策略 | 模型直接选动作。值不值得再调用一次工具、再问一句人，是信息价值。不可逆动作进入审批 | 期望效用是评价标准。看不全世界就要信念状态。探索和利用是不同的步 |
| 18 | 手工求纳什均衡当作控制系统 | 管理者–工人、招标式分任务、共享状态。合并多份结果时先定规则 | 单方面最优脚本站不住；机制会改变上报行为 |
| 19–22 | 按 2020 年的网络从零训练一个智能体；把强化学习教材算法原样套到长任务上 | 预训练模型，再用偏好和轨迹做后训练。脚手架先改，模型后改。信用分配落在整段轨迹上 | 奖励写错会刷指标；泛化、探索仍然是学习问题 |
| 23–24 | 分词、句法分析、流水线式自然语言系统；以书里的网络规模理解语言能力 | 一个模型同时完成理解、生成和工具参数填写。长上下文和检索是记忆，不是又一条 NLP 流水线 | 一句话可以是一个行动，要看意图和后果 |
| 25–26 | 用 2020 年的视觉特征或经典控制器充当软件 agent 的眼睛和手 | 多模态模型读屏幕；软件 agent 的身体是电脑（键鼠加上工具）。机器人仍要单独的感知与控制 | 感知有噪声，动作有误差，闭环不能省 |
| 27–28 | 把 2020 年的安全讨论当成当前技术清单；把书末预测当成 2026 年的现状 | 风险看工具层能改什么、审批在不在、任务成功率如何。评价延伸到轨迹和副作用 | 目标写错了会怎样；系统能不能被纠正、被关掉 |

## 4. 新范式：一个循环，不是一个求解器

把上面右侧收成一条现在真的在跑的循环。

1. **环境给出不完整观测。** 可能是一段报错、一张屏幕、一次工具的返回。agent 没有世界的全联合分布。
2. **模型在这一步上多花计算。** 先想要不要行动、行动前还缺什么。这是测试时计算，对应「想清楚再动」，但预算有限，所以经常想不完。
3. **在两类执行器里选。** 结构化工具（改文件、查 API、跑测试）优先于在屏幕上点击。屏幕动作用于没有工具的界面。OSWorld-MCP 说明：给了工具不代表模型会用。
4. **脚手架写下这一步之后什么变了。** 显式状态比「全靠上下文记住」可靠。这是基于模型的智能体，用来对付框架问题。
5. **计划是一份会改的依赖图，不是一份先算完的操作序列。** 子任务能并行就并行。新事实出现，管理者改图。这是第 11 章的在线规划和第 18 章的分工，算法换成了编排。
6. **后果越大，越不像一次自由的期望效用最大化。** 删、付、对外发送，停下来等人。这是第 16 章「保持可纠正」在工具层的落地。
7. **用整段轨迹打分，再决定改脚手架还是改模型。** 学习智能体的外环还在，内环已经不是从零做梯度下降。

因此，读这本 2020 年的书，是为了认出循环里的哪一步出了问题：没有状态、度量写错、该问人却自己做了、计划不能改、多个工作者互相踩踏。实现时按第 4 节的「2026 年的做法」那一列来做。

## 5. 时间不够时怎么读

按这个顺序读笔记，读每章开头的问题和小结即可；算法推导先跳过。

1. 第 2 章全文。后面所有对照都用它的词。
2. 第 11 章的问题定义、分层规划（11.4）、非确定性域里的行动（11.5）。
3. 第 16 章的期望效用、信息价值、未知偏好；第 17 章只读 MDP / POMDP / 老虎机各自在问什么。
4. 第 18 章的环境分类、合同网，以及「均衡不是我的最优脚本」。
5. 第 27 章 27.3，尤其是安全。用来检查性能度量会不会把人要的东西写错。

第 8–9 章的证明程序、第 13 章的消元细节、第 21–24 章的网络结构，留到要做对应专题时再读。它们解释历史和失败模式，不提供 2026 年的代码结构。

## 6. 来源与边界

对照依据是本目录第 1–28 章学习笔记，加上 2026-10 前后能核对到的公开结果：

- Hou 等，MCP 工具使用清点（约 17.7 万个公开工具，2024-11 至 2026-02）。软件开发占比与动作类工具使用占比见正文第 2 节。
- OSWorld-MCP，ICLR 2026。桌面环境中图形界面与 MCP 工具的联合评测。
- 多智能体电脑使用（MACU）。管理者维护任务依赖图，子 agent 并行，计划随观测改写。
- MCP-Bench，ICLR 2026。多服务器、多步工具协调；执行成功不等于任务成功。

数字是这些基准上的快照，不是全行业成功率。协议和模型名称会换，第 3 节表格右侧的做法以「模型选步、脚手架管状态和边界、计划可改、后果大就审批、用轨迹打分」为准。
