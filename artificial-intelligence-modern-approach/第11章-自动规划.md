## 0. 本章要解决的问题：从"搜索"到"规划"

第 3 章的搜索型问题求解智能体在面对真实世界问题时会出现两个致命困难：

| 困难 | 表现 | 规划智能体的解法 |
|---|---|---|
| **无关动作爆炸** | 买一本书有 100 亿个 `Buy(ISBN)` 动作，搜索要枚举所有后继状态 | 用**显式目标**+**动作模式**，通过一次合一即可推出 `Buy(ISBN0137903952)` |
| **启发式函数不可自动获得** | 问题求解智能体把目标检测当黑盒，只能靠人给启发式 | 目标表示为**子目标合取**，可用**领域无关启发式**：未满足合取子句数 |

**一句话定义**：规划 = 找出一个能达成目标的动作序列。

**经典规划环境（classical planning）的五个假设**：

1. 完全可观测（fully observable）
2. 确定性（deterministic）
3. 有限（finite）
4. 静态（static，只有智能体动作才改变世界）
5. 离散（discrete，时间、动作、对象、效果都离散）

> 不满足以上假设的属于**非经典规划**（部分可观测／随机环境），对应第 12 章（概率推理）和第 17 章（复杂决策）。

## 11.1 经典规划的定义

### 核心思想

用一套**受限但表达力足够**的一阶逻辑子集来描述状态、目标与动作，让规划器能"看穿"目标与动作的内部结构，而不是把它们当黑盒。

### 1. 状态（State）

- 状态 = **基原子（ground atoms）的合取**，如
  `At(C1, SFO) ∧ At(C2, JFK) ∧ At(P1, SFO) ∧ Cargo(C1) ∧ Plane(P1) ∧ Airport(JFK) ∧ Airport(SFO)`
- 采用**封闭世界假设**：未列出的原子为假，这样可以用原子集合（而非完整真值赋值）表示状态。

### 2. 目标（Goal）

- 目标的合取式，其中变量**默认存在量化**：
  `At(C1, SFO) ∧ At(C2, JFK)`
- 目标是**部分状态**描述，不是完整状态——这使得目标可以用一个"状态子集"来表达。

### 3. 动作模式（Action Schema）

```
Action(Fly(p, from, to),
       PRECOND:  At(p, from) ∧ Plane(p) ∧ Airport(from) ∧ Airport(to)
       EFFECT:   ¬At(p, from) ∧ At(p, to))
```

- `PRECOND`（前置条件）：动作可执行的条件
- `EFFECT`（效果）：真值增加（ADD）与删除（DEL）两类文字
- 效果可以是**条件效果**（conditional effect），PDDL 还支持量词、类型、等式、派生谓词等

### 4. 形式化定义

一个规划问题由三元组给出：

```
Problem = (Init, Actions, Goal)

RESULT(s, a) = (s − DEL(a)) ∪ ADD(a)     if a 的 PRECOND 在 s 中成立
             = s                          否则
```

计划（plan）= 动作序列 `a₁, a₂, …, aₙ`，使得 `RESULT(RESULT(…Init, a₁)…, aₙ) ⊨ Goal`。

### 5. 三个范例领域

| 领域 | 要点 | 教学价值 |
|---|---|---|
| **航空货物运输**（Air cargo） | 飞机与货物在不同机场间移动，`Load/Unload/Fly` | 多对象、多参数动作的代表 |
| **备用轮胎问题**（Spare tire） | 换轮胎需要 `Remove/ PutOn/Inflate`，存在工具与轮胎的相互依赖 | 展示**前置条件链**与子目标交互 |
| **积木世界**（Blocks world） | `Move(b, x, y)`、`MoveToTable`、`On/ Clear/ ArmEmpty` | 规划领域的"果蝇"，动作与效果最纯粹 |

> **积木世界动作示例**
> ```
> Action(Move(b, x, y),
>        PRECOND: On(b, x) ∧ Clear(b) ∧ Clear(y) ∧ ArmEmpty
>        EFFECT:  On(b, y) ∧ Clear(x) ∧ ¬On(b, x) ∧ ¬Clear(y) ∧ ¬ArmEmpty)
> ```

### 6. 语言表达力

PDDL（Planning Domain Definition Language）是经典规划的标准语言，经典子集只允许：
- 状态为基文字合取、无函数符号、无负前置（STRIPS 风格）
- 动作效果为文字合取

扩展：ADL（Action Description Language）放开负前提与量词；PDDL 2.x+ 支持条件效果、派生谓词、持续动作等。

## 11.2 经典规划的算法

| 算法 | 搜索方向 | 搜索空间 | 特点 |
|---|---|---|---|
| 前向状态空间搜索 | Init → Goal | 状态空间 | 分支因子大，但便于用启发式 |
| 反向状态空间搜索 | Goal → Init | 状态空间（部分状态） | 只考虑**相关动作**，分支小，但代价大 |
| 布尔可满足性规划（SATPLAN） | 命题编码 | 命题公式 | 可用工业级 SAT 求解器 |
| 规划图 / 偏序规划 / CSP 规划 | 混合 | 规划空间 | 并行动作、部分序 |

### 11.2.1 规划的前向状态空间搜索

- 从 `Init` 出发，用第 3 章的搜索算法（BFS/DFS/A\*）搜索。
- 节点 = 状态，边 = 动作。
- **分支因子大**（每个状态可能有大量适用动作），因此**启发式是成败关键**（见 11.3）。
- 优点：容易处理函数符号与量词，可以方便地做启发式搜索。

### 11.2.2 规划的反向状态空间搜索

- 从 `Goal` **回归**（regression）到 `Init`。
- 关键：对**部分状态**反向套用动作效果：
  ```
  g' = (g − ADD(a)) ∪ PRECOND(a)      （需 a 与该回归状态"相关"且无冲突）
  ```
- **相关动作（relevant action）**：其效果能达成目标中某个文字的动作。
- 优点：分支因子通常远小于前向搜索。
- 缺点：
  1. 不能处理量词与函数符号（不像前向搜索那样只要状态是基的就行）；
  2. 若一个文字无法被任何动作达成，搜索可能无限回归，需要额外检测。

### 11.2.3 使用布尔可满足性规划（Planning as SAT）

**核心思想**：把"存在长度为 k 的计划"编码成一个命题公式，交给 SAT 求解器判定。

编码要素（时间步 0…k）：

1. **初始状态公理**：`Init⁰`
2. **目标公理**：`Goal^k`
3. **动作排除公理**：每个时间步只能有一个动作
4. **前提前提公理**：动作 ⇒ 其前置条件
5. **后继状态公理**：流（fluent）在 t+1 的值由 t 的值与动作决定

从 k = 0 逐步增加 k（或倍增）直到公式可满足。SATPLAN 是经典规划的重要范式：**规划 = 定理证明**。

### 11.2.4 其他经典规划方法

- **规划图 / GraphPlan**：交替的"命题层—动作层"，先构建多项式规模的图，再从中反向提取计划。
- **规划空间搜索 / 偏序规划（POP）**：不搜索状态，而搜索**部分有序的动作集合**，逐步消除"开放前提"与"威胁"。
- **约束可满足规划（CSP）**：变量 = 各时间步的流，域 = 取值，约束 = 初始/目标/前提/效果。
- 现代规划器：FF（基于松弛计划启发式）、Fast Downward 等。

## 11.3 规划的启发式方法

**目标**：让规划器**自动**从领域描述中导出好的启发式，不再依赖人类手工提供。

### 核心技巧：松弛问题（relaxed problem）

对一个规划问题做"松弛"，得到更容易求解、且其最优代价可作为原问题启发式的子问题。

| 松弛方式 | 说明 | 启发式 |
|---|---|---|
| **忽略负效果（删除表）** | 效果只增不减，子目标不会互相破坏 | `hMax`（可采纳但偏弱）、`hAdd`（不可采纳但更准） |
| 忽略负前提 | 动作更容易满足 | 同样可导出启发式 |
| 分解为独立子问题 | 假设每个子目标独立 | 启发式可加（代价相加） |

**关键启发式**：

- **hMax**：松弛问题中，达到目标的最大（最难的）子目标代价 → **可采纳**（低估真实代价），可用于 A\*。
- **hAdd**：假设子目标代价可加 → 通常**高估**（不可采纳），但实践中更强、更快。
- **松弛规划图启发式**：在松弛规划图上"从不含负效果的动作层"反向提取**松弛计划**，用其长度作启发式——这正是 FF 规划器的主力。

> 直觉：`hAdd` 像"把每本书都买一遍再相加"，`hMax` 像"只算最难的那本"。

### 11.3.1 领域无关剪枝（Domain-Independent Pruning）

- **删除不相关/不可达的原子**：从目标反向可达性分析，剔除与目标无关的流。
- **删除不可能的动作**：前置条件永不可满足的动作直接移除。
- 目的：缩小搜索空间，且这类分析对任意领域都适用。

### 11.3.2 规划中的状态抽象

- 将状态映射到抽象空间（去掉细节），在抽象空间求解，得到可用的启发式或计划骨架。
- 典型：**模式数据库（pattern database）**——只保留部分变量的取值组合，预计算到目标的代价。
- **地标（landmarks）**：任何计划都必须经过的命题或动作，可作为子目标顺序约束。

## 11.4 分层规划

### 动机

工业级问题（如航天器操作）可能有**百万级**动作，平面规划不可行。人类写计划时天然有层次：先定"去哪里、做什么"，再细化到每一步。

### 11.4.1 高层动作（High-Level Action, HLA）

一个 HLA 由三部分组成：

```
HLA h = (name, preconditions, refinement)
```

- **refinement（细化）**：把 h 替换为一个步骤序列（步骤本身可以是 HLA 或基元动作）。
- 一个 HLA 可以有**多条**细化（如"去机场"可开车、可打车、可坐地铁）。
- **细化的细化**最终得到**基元动作（primitive action）**。
- **无回路细化性质（downward refinement property）**：若高层计划能达成目标，则它的任意细化也能达成目标——这是分层规划正确性的基础。

### 11.4.2 搜索基元解

- 做法：把 HLA 全部展开成基元动作，再做普通规划。
- 问题：展开后是**指数级**的——等于放弃分层带来的好处。

### 11.4.3 搜索抽象解

在**高层**搜索计划，用**乐观/悲观描述**来剪枝：

| 概念 | 含义 | 用途 |
|---|---|---|
| **乐观可达集**（optimistic reachable set） | 该 HLA 序列**可能**达到的状态集合（上界） | 若目标不在上界内 → 该分支**不可能成功**，剪掉 |
| **悲观可达集**（pessimistic reachable set） | 该 HLA 序列**一定**能达到的状态集合（下界） | 保证搜索**完备**、不漏掉可用解 |

- 这种"在最有利/最不利条件下评估 HLA"的语义称为**天使语义（angelic semantics）**。
- 若能证明高层解一定可行（不管怎样细化都成立），就可**不展开到基元**就直接保证计划正确。
- 常与 SATPLAN 结合（在抽象层做命题编码），也可与 HTN 规划器（如 SHOP2）配合。

### 分层规划的两种用法

1. **HTN 规划**：领域专家提供 HLA 库，规划器只在细化空间搜索（知识驱动）。
2. **分层搜索加速**：自动构造抽象，用于启发式与剪枝（自动化）。

## 11.5 非确定性域的规划和行动

当环境部分可观测或非确定时，智能体不能只执行预先算好的固定动作序列，需要三类方法：

| 方法 | 观测 | 环境 | 输出 |
|---|---|---|---|
| **无传感器规划**（sensorless / conformant） | 完全没有 | 非确定 | 一个能应对所有初始状态的动作序列 |
| **应变规划**（contingent planning） | 部分 | 非确定 | 一棵**与或树**（带分支的"计划树"） |
| **在线规划**（online planning） | 部分/未知 | 非确定 | 边执行边感知边重规划 |

### 信念状态（Belief State）

- 非确定性下，智能体的"知识"是所有可能状态的集合 = **信念状态**。
- 关键工程问题：信念状态可能指数级膨胀。**1-CNF 表示**（一个合取子句集合）能在很多实际问题上保持紧凑，并且对动作封闭（确定动作 + 确定性效果下仍是 1-CNF）。

### 11.5.1 无传感器规划

- 从初始信念状态出发做搜索，动作的效果是"信念状态的转移"。
- 由于没有观测，问题变成：**只靠动作就让所有可能状态收敛到目标**。
- 可用命题逻辑表示并用 SAT 求解（类似 SATPLAN，但作用于信念状态）。
- 难点：条件效果会让 1-CNF 不再封闭，需要额外的表示技巧。

### 11.5.2 应变规划

- 在**与或搜索树（AND-OR tree）**中搜索：
  - **或节点**：智能体选择动作（选择分支）
  - **与节点**：环境对感知结果的分支（智能体必须处理所有分支）
- 传感器提供信息、减少不确定性，但也**增加分支**，需要权衡。
- 计划不再是一条路径，而是一棵**条件化的策略树**（policy tree）。

### 11.5.3 在线规划

- 循环：**规划 → 执行 → 监控 → （必要时）重规划**。
- 执行监控的三个层次：

| 层次 | 监控什么 | 触发什么反应 |
|---|---|---|
| 动作监控（action monitoring） | 动作的前置/效果是否如预期 | 重试或修正当前动作 |
| 计划监控（plan monitoring） | 计划剩余部分是否仍可行 | 计划修复（plan repair）或重规划 |
| 目标监控（goal monitoring） | 目标是否仍值得追求 | 反思／放弃／改换目标 |

- **计划修复 vs 重规划**：修复保留原计划大部分结构，通常更省；重规划从当前状态重新算。

## 11.6 时间、调度和资源

经典规划把动作视为**瞬时**且**不消耗资源**，真实世界不成立：动作有持续时间、有先后关系、会占用机器/工人/金钱。

### 11.6.1 时间约束和资源约束的表示

**时间约束**
- 每个动作有**持续时间** `Duration(a)`；
- 约束形式：`Start(a_i) + Duration(a_i) ≤ Start(a_j)`（a_j 晚于 a_i 结束）；
- 可表达：overlap、during、before、after 等区间关系。

**资源约束**
- **可复用资源**（reusable，如机器、工具）：在任意时刻占用不超过容量；
- **可消耗资源**（consumable，如燃料、预算）：总量不超过上限；
- 车间作业调度（job shop）典型：每个作业是一串有序操作，各自需要特定机器。

**关键路径法（Critical Path Method, CPM）** —— 时间规划的基础：
- **最早开始/结束时间**：ES、EF，从前往后推
- **最晚开始/结束时间**：LS、LF，从后往前推
- **松弛量（slack / float）** = LS − ES；松弛量为 0 的动作构成**关键路径**，决定最小总工期

### 11.6.2 解决调度问题

- **形式化为 CSP**：
  - 变量 = 各动作的开始时间
  - 域 = 可能的时间点
  - 约束 = 时间先后约束 + 资源容量约束
- 求解方法：**最小冲突局部搜索**（第 6 章）+ 关键路径临界性启发式。
- 大问题：分层规划 + 调度结合（先规划动作，再排时间），如 NASA Remote Agent / ASPEN。

## 11.7 规划方法分析

| 维度 | 完全可观测 + 确定性 | 部分可观测 / 非确定 |
|---|---|---|
| 表示 | 单个状态 | 信念状态 / 与或树 |
| 输出 | 动作序列 | 策略树 / 应变计划 |
| 主要算法 | A\*、SATPLAN、规划图、偏序规划 | 信念空间搜索、AND-OR 搜索、在线重规划 |
| 复杂度 | 一般情形 **PSPACE-完全**（长度有界时 NP-完全） | 更高，常需近似或在线方法 |

**要点**：
- 规划问题的难度主要来自**子目标交互**（一个子目标的达成会破坏另一个）。
- **领域无关启发式**（HSPr、hAdd、hMax、松弛计划）是经典规划实用化的关键。
- 分层规划通过**抽象**把大问题拆小，是工业界的主流手段。
- 不确定性不可避免时，必须从"一次性算好序列"转向"**执行—监控—重规划**"的闭环。

## 小结（原书本章总结要点）

1. 经典规划假设环境完全可观测、确定性、静态、离散、有限，用受限逻辑语言（PDDL）描述。
2. 状态是基原子的合取，目标是部分状态，动作由前置条件与效果定义。
3. 规划可归约为**状态空间搜索**（前向/反向）、**SAT 求解**、**规划空间搜索**（偏序规划）、**规划图**等方法。
4. 高质量**领域无关启发式**可从问题描述自动导出（如松弛问题、忽略删除表）。
5. **分层规划**用高层动作与细化压缩搜索空间，天使语义可在抽象层剪枝。
6. 非确定性域需要**信念状态**、**应变规划**（与或树）与**在线重规划**。
7. 引入**时间与资源**后，规划扩展为**调度问题**，可用关键路径法与 CSP 技术求解。
