## 0. 本章要解决的问题

命题逻辑足以说明逻辑、推断与基于知识的智能体的基本概念，但**它能说的东西太有限**：它只能把世界拆成一个个命题符号，无法"一次说清"一类对象。例如 wumpus 世界必须为**每一格**单独写一条规则 `B₁,₁ ⇔ (P₁,₂ ∨ P₂,₁)`，而用英语说"与坑相邻的方格有微风"只是一句话。

本章引入**一阶逻辑（first-order logic，又称一阶谓词演算，缩写 FOL / FOPC）**：它承诺世界由**对象（object）**与对象之间的**关系（relation）**、**函数（function）**构成，并用量词 `∀` / `∃` 表达"全部"与"某些"。

## 8.1 重新审视表示（Representation Revisited）

#### 编程语言为什么不够（原书 §8.1 正文，无编号）

程序里的数据结构当然能表示事实，例如 `World[2,2] ← Pit` 就断言 [2,2] 有坑。但编程语言有两个致命缺陷：

| 缺陷 | 说明 |
|---|---|
| **没有通用的推导机制** | 每次更新数据结构都靠程序员手写的**领域相关**过程；而命题逻辑是**声明式（declarative）**的，知识与推断分离，推断完全**领域无关**（SQL 数据库取混合路线） |
| **无法直接处理部分信息** | 很难说"[2,2] 或 [3,1] 有坑""若 wumpus 在 [1,1]，它就不在 [2,2]"；程序只能给变量存单个值 |

**表示语言的三个理想性质**：① 声明式——语义建立在句子与可能世界之间的真值关系上；② 能处理部分信息——靠 `∨` 与 `¬`；③ **组合性（compositionality）**——句子的意义是其各部分意义的**函数**（`S₁,₄ ∧ S₁,₂` 的意义绝不可能与 `S₁,₄`、`S₁,₂` 的意义无关）。

> **因子化 vs 结构化**：命题逻辑是**因子化表示（factored representation）**，描述多对象环境时不简洁；英语与一阶逻辑是**结构化表示（structured representation）**。

### 8.1.1 思想的语言

自然语言表达能力极强，语言学与语言哲学中有一条悠久传统把它视为声明式知识表示语言。但现代观点认为，自然语言首先是**交流媒介，而不是纯粹的表示语言**：

- 说话人指着说"看！"，听者就知道了某件事——但我们不会说"看！"这句话**表示**了那件事。句子的意义取决于**句子本身 + 说出它的语境**，你无法把"看！"存进知识库并指望单独恢复它的意义
- 自然语言还有**歧义**。Pinker（1995）："当人们想到 spring 时，肯定不会混淆'春天'和'弹簧'——**如果一个词能对应两个思想，思想就不可能是词**。"

**萨丕尔–沃尔夫假说（Sapir–Whorf hypothesis, Whorf 1956）**声称我们对世界的理解受所说语言的强烈影响。Whorf 主要靠直觉与思辨，其观点大体已被否定，但后来确实有了真实数据：

| 实验 | 结论 |
|---|---|
| Wanner（1974）：辨认读过的句子用的是哪一版措辞 | 正确率只有**随机水平（约 50%）**，但对所读**内容**的记忆准确率**超过 90%** → 人形成**内部非语言表示**，原话措辞并不重要 |
| Guugu Yimithirr（澳大利亚原住民语言）**没有**"前后左右"等相对方向词，只用绝对方向（"我**北**边的胳膊疼"） | 语言差异带来行为差异：他们更擅长在开阔地形导航，英语使用者更擅长把叉子放在盘子右边 |
| Boroditsky（2003）："bridge"在西语中是阳性、德语中是阴性 | 西语者选 *big, dangerous, strong, towering*；德语者选 *beautiful, elegant, fragile, slender* |
| Loftus & Palmer（1974）：车祸影片 + 不同措辞提问 | "contacted（接触）"→ 平均 **32 mph**；"smashed（撞碎）"→ 平均 **41 mph** |
| Mitchell et al.（2008）：fMRI 脑成像 + 机器学习 | 二选一任务（"celery"还是"airplane"）预测正确率 **77%**；对**从未见过脑图的词**和**从未见过的人**也高于随机水平 |

**总体结论**：不同语言使用者的认知加工存在**可测量但很小**的差异，**没有**令人信服的证据表明它导致了世界观的重大差异。

> **从形式逻辑的角度看**：同一知识用两种方式表示，可推导出的**事实集合完全相同**，绝不产生差别。但实践中一种表示可能比另一种**少几步**——资源有限的推断器用一种能得出结论、用另一种不能。对**非演绎**任务（如从经验学习），结果必然依赖表示形式：第 19 章会说明，当学习程序面对两个都与数据一致的理论时，最常见的打破平局方法是**选更简洁的那个**，而这取决于表示理论所用的语言。**因此对任何会学习的智能体，语言对思想的影响不可避免。**
> （顺带一提：在采用 CNF 的逻辑系统里，我们能"看进系统内部"，看到 `¬(A ∨ B)` 与 `¬A ∧ ¬B` 存成同一个规范形式。**对人脑做类似的事正开始成为可能**——fMRI 与颅内电生理（Sahin et al., 2009）有望给出更具体的答案，尽管这类工作仍在起步阶段。）

### 8.1.2 结合形式语言与自然语言之长

做法：以命题逻辑的基础（**声明式、组合性、语境无关、无歧义**的语义）为地基，借自然语言的表示思想而避开其缺陷。看自然语言的句法：

| 成分 | 对应 |
|---|---|
| 名词 / 名词短语 | **对象（object）**：方格、坑、wumpus |
| 动词 / 动词短语 + 形容词 / 副词 | **关系（relation）**：有微风、与……相邻、射击 |
| 其中"给定输入只有一个值"的关系 | **函数（function）** |

- **对象**：人、房子、数字、理论、Ronald McDonald、颜色、棒球赛、战争、世纪……
- **关系**：一元关系即**性质（property）**（红的、圆的、假的、素数、多层的……）；更一般的 n 元关系（……的兄弟、比……大、在……内、是……的一部分、有颜色、发生在……之后、拥有、介于……之间……）
- **函数**：……的父亲、最好的朋友、第三局、比……多一、……的开头

几乎任何断言都能看成在谈论对象与性质/关系：

- "一加二等于三"：对象 = 一、二、三、一加二；关系 = 等于；函数 = 加（"一加二"是把"加"作用于"一""二"所得对象的名字，"三"是同一对象的另一个名字）
- "与 wumpus 相邻的方格是臭的"：对象 = wumpus、方格；性质 = 臭的；关系 = 相邻
- "邪恶的约翰王在 1200 年统治英格兰"：对象 = 约翰、英格兰、1200；关系 = 统治于；性质 = 邪恶的、国王

一阶逻辑还能表达关于**宇宙中某些或全部对象**的事实，从而表示**普遍规律**。

#### 本体论承诺与认识论承诺

命题逻辑与一阶逻辑的**主要区别**在于各自的**本体论承诺（ontological commitment）**——即它关于现实本质做了什么假设；数学上，这通过"定义句子真值所依据的形式模型的性质"来表达。

| 语言 | 本体论承诺（世界上有什么） | 认识论承诺（对事实的信念状态） |
|---|---|---|
| 命题逻辑 | 事实 | 真 / 假 / 未知 |
| 一阶逻辑 | 事实、**对象、关系** | 真 / 假 / 未知 |
| 时序逻辑 | 事实、对象、关系、**时间** | 真 / 假 / 未知 |
| 概率论 | 事实 | **信念度 ∈ [0, 1]** |
| 模糊逻辑 | 带有**真值度 ∈ [0, 1]** 的事实 | 已知区间值 |

（原书 Figure 8.1）

**本体论承诺是逻辑的巨大优势**：它让我们从真陈述出发推断出其他真陈述，在每个命题都有清晰边界的领域（数学、wumpus 世界——一个方格要么有坑要么没坑，不存在"有点像坑的凹陷"）尤其强大。

但真实世界中许多命题边界模糊：维也纳算大城市吗？这家餐厅好吃吗？——取决于你问谁，答案可能是"有点"。三种应对：① **细化表示**（增加规模类别，或改用 `Population` 函数符号）；② **模糊逻辑（fuzzy logic）**——承诺命题有 0 到 1 之间的**真值度（degree of truth）**，"维也纳是大城市"真值度 0.8、"巴黎是大城市"真值度 0.9，这更合直觉但**推断更难**（确定 `A ∧ B` 的真值不再只有一条规则，而要按域区分）；③ 把概念映射到多维空间中的点，再度量"大城市"与"维也纳/巴黎"的距离（见 §24.1）。

各种专用逻辑还做出进一步的本体论承诺：**时序逻辑（temporal logic）**假定事实在**特定时刻**成立、时刻（点或区间）有序——专用逻辑让某类对象及其公理获得"一等公民"地位，而不仅仅在知识库里被定义。**高阶逻辑（higher-order logic）**把关系与函数本身也当作对象，因而能断言"某关系是传递的"这类关于**所有关系**的命题；与多数专用逻辑不同，高阶逻辑**严格强于**一阶逻辑——有些高阶句子无法用任意有限条一阶句子表达。

> ⚠️ **真值度 ≠ 信念度**：概率论系统的**信念度（degree of belief）**取值也是 [0, 1]（0 = 完全不信，1 = 完全相信），但它是智能体的**主观可能性**；模糊逻辑的**真值度**是事实本身的性质。有些模糊系统还允许"关于真值度的不确定性"。
> 例：概率化的 wumpus 智能体可能相信 wumpus 在 [1,3] 的概率是 **0.75**、在 [2,3] 的概率是 **0.25**——尽管 wumpus **确定地**在某一个格子里。

## 8.2 一阶逻辑的语法与语义（Syntax and Semantics of First-Order Logic）

要点有二：语言的语法如何支持**简洁表示**，语义如何导出**可靠的（sound）推断过程**。

### 8.2.1 一阶逻辑的模型

一个逻辑语言的**模型（model）**就是构成所考虑的可能世界的形式结构，它把句子的**词汇**关联到可能世界的元素上，从而确定任何句子的真值。命题逻辑的模型把命题符号关联到预先给定的真值；**一阶逻辑的模型里面有对象**。

模型的**域（domain）**是它包含的对象（**域元素**）的集合，**域必须非空**。数学上对象是什么无关紧要，要紧的只是**有多少个**。

原书 Figure 8.2 的模型含 **5 个对象**：狮心王理查（1189–1199 年在位的英格兰国王）、他的弟弟邪恶的约翰王（1199–1215 年在位）、理查的左腿、约翰的左腿、一顶王冠。

关系**形式上就是相关对象构成的元组（tuple）的集合**（元组是按固定顺序排列的对象，用尖括号书写）：

```
兄弟关系     = {⟨狮心王理查, 约翰王⟩, ⟨约翰王, 狮心王理查⟩}          (8.1)
"在头上"关系 = {⟨王冠, 约翰王⟩}
```

模型还含**一元关系（性质）**：`person` 对理查与约翰都成立；`king` 只对约翰成立（理查此时已死）；`crown` 只对王冠成立。某些关系最好当作**函数**——一个给定对象必须**恰好**关联到另一个对象：每个人都有**一条**左腿，所以模型有一个一元"左腿"函数：

```
⟨狮心王理查⟩ → 理查的左腿        ⟨约翰王⟩ → 约翰的左腿              (8.2)
```

> **注意**：严格地说，一阶逻辑的模型要求**全函数（total function）**——每个输入元组都必须有值。于是王冠也得有条左腿，左腿本身也得有条左腿。技术上可引入一个额外的"不可见对象"作为所有没有左腿的东西（包括它自己）的左腿。只要你不就"没有左腿的东西的左腿"做任何断言，这些细节就无关紧要。

### 8.2.2 符号与解释

基本语法元素是代表对象、关系、函数的**符号**（本书约定以**大写字母**开头），共三类：

| 符号种类 | 代表 | 例子 |
|---|---|---|
| **常量符号（constant symbol）** | 对象 | `Richard`、`John` |
| **谓词符号（predicate symbol）** | 关系 | `Brother`、`OnHead`、`Person`、`King`、`Crown` |
| **函数符号（function symbol）** | 函数 | `LeftLeg` |

名字的选择完全由使用者决定；每个谓词与函数符号都带有**元数（arity）**，固定参数个数。

每个模型还必须含一个**解释（interpretation）**，指明各符号指称哪些对象、关系、函数。原书例子的**预期解释（intended interpretation）**：`Richard` 指狮心王理查、`John` 指邪恶的约翰王；`Brother` 指式 (8.1) 的兄弟关系；`OnHead` 是王冠与约翰王之间的关系；`Person`/`King`/`Crown` 是识别人、国王、王冠的一元关系；`LeftLeg` 指式 (8.2) 的函数。当然还有很多别的解释（例如某个解释把 `Richard` 映到王冠），模型有 5 个对象，所以**仅就这两个常量符号就有 `5² = 25` 种解释**。

原书 Figure 8.3 给出完整形式文法（Backus–Naur 范式）：

```
Sentence → AtomicSentence | ComplexSentence
AtomicSentence → Predicate | Predicate(Term,...) | Term = Term
ComplexSentence → (Sentence) | ¬Sentence | Sentence ∧ Sentence | Sentence ∨ Sentence
                | Sentence ⇒ Sentence | Sentence ⇔ Sentence | Quantifier Variable,... Sentence
Term → Function(Term,...) | Constant | Variable          Quantifier → ∀ | ∃
Constant → A|X1|John|···              Variable → a|x|s|···
Predicate → True|False|After|Loves|Raining|···           Function → Mother|LeftLeg|···
OPERATOR PRECEDENCE: ¬, =, ∧, ∨, ⇒, ⇔
```

量词的优先级约定：**一个量词的作用范围一直延伸到它右边的一切**。

> **注意**：并非所有对象都要有名字——预期解释就没给王冠和两条腿命名；**一个对象也可以有多个名字**——存在使 `Richard` 与 `John` 都指王冠的解释。若觉得别扭，回想命题逻辑：完全可以有 `Cloudy` 与 `Sunny` 同时为真的模型，**排除与知识不一致的模型是知识库的职责**。

**小结**：一阶逻辑的模型 = 一组对象 + 一个解释（常量符号 → 对象，函数符号 → 对象上的函数，谓词符号 → 关系）。与命题逻辑一样，**蕴涵、有效性等都用"所有可能模型"定义**。

> 一阶模型的数量**无界**（对象数从 1 到无穷，常量到对象的映射方式各异），因此**不能靠枚举所有模型检查蕴涵**——那是命题逻辑能做的事。即使限制对象个数，组合数也极大：原书 Figure 8.4 的例子（两个常量符号 `R`、`J` 加一个二元关系符号），**对象数 ≤ 6 的模型就有 137,506,194,466 个**。

### 8.2.3 项

**项（term）**是**指称对象**的逻辑表达式。为每个对象都准备一个常量符号并不方便——英语里我们说"约翰王的左腿"而不给那条腿起名，函数符号就是干这个的：`LeftLeg(John)`。一般地，**复合项** = 函数符号 + 括号内的项作为参数列表。

> ⚠️ **直觉上要当心**：复合项只是**一种复杂的名字**，它不是"返回值的子程序调用"。**不存在**以人为输入、返回一条腿的 `LeftLeg` 子程序。我们可以**就左腿进行推理**（断言"人人都有左腿"这条普遍规律，再推出约翰必有一条），却**从不提供 `LeftLeg` 的定义**——这在编程语言的子程序里做不到。

**项的形式语义**：对项 `f(t₁, …, tₙ)`，函数符号 `f` 指模型中某个函数 `F`，各参数项指域中对象 `d₁, …, dₙ`，整个项指 `F` 作用于 `d₁, …, dₙ` 的值。**解释就这样确定了每个项的指称。**

### 8.2.4 原子句子

**原子句子（atomic sentence）**，简称**原子（atom）** = 谓词符号 + 可选的括号项列表：

```
Brother(Richard, John)                    // 狮心王理查是约翰王的兄弟
Married(Father(Richard), Mother(John))    // 理查的父亲娶了约翰的母亲
```

> 本书约定参数顺序：`P(x, y)` 读作"**x 是 y 的 P**"。原子句子在给定模型中为真，当且仅当谓词所指称的关系在参数所指称的那些对象之间成立。

### 8.2.5 复合句子

用逻辑联结词构造更复杂的句子，语法与语义都与命题演算相同。以下四句在 Figure 8.2 的模型（预期解释）下为真：

```
¬Brother(LeftLeg(Richard), John)
Brother(Richard, John) ∧ Brother(John, Richard)
King(Richard) ∨ King(John)
¬King(Richard) ⇒ King(John)
```

### 8.2.6 量词

一旦逻辑里有了对象，就自然想表达**整个对象集合**的性质而非逐个枚举名字。**量词（quantifier）**就是干这个的：一阶逻辑有两个标准量词。

#### 全称量化（∀）

"所有国王都是人"写作 `∀ x King(x) ⇒ Person(x)`。`∀` 读作"**对所有……**"（倒置的 A 代表 all）；`x` 是**变量（variable）**，按约定小写，本身就是一个项，也能作函数参数（`LeftLeg(x)`）；**不含变量的项叫基项（ground term）**。

**形式语义**：`∀ x P` 在给定模型中为真，当且仅当 `P` 在**所有可能的扩展解释（extended interpretation）**下为真——每个扩展解释都给 `x` 指定一个域元素。Figure 8.2 的模型有 5 种扩展方式（`x` → 理查 / 约翰 / 理查的左腿 / 约翰的左腿 / 王冠），所以 `∀ x King(x) ⇒ Person(x)` 等价于断言 5 条蕴涵式："理查是国王 ⇒ 理查是人""约翰王是国王 ⇒ 约翰王是人""理查的左腿是国王 ⇒ 理查的左腿是人""约翰的左腿是国王 ⇒ 约翰的左腿是人""王冠是国王 ⇒ 王冠是人"。

只有约翰是国王，所以第二条断言了他是人（正是我们想要的）。另外四条**在模型中为真，却对腿、王冠、理查的"人格"未作任何断言**——因为它们**都不是国王**：查 `⇒` 的真值表，前件为假时蕴涵恒真，与后件真值无关。

> **这正是 `⇒` 的真值表定义完美适配全称量词的原因**：断言一条全称量化句子 = 断言一整列逐个对象的蕴涵式；我们只对**前件为真的对象**断定后件，对前件为假的对象**什么也没说**。
> ⚠️ **最常见错误**：把 `⇒` 换成 `∧`。`∀ x King(x) ∧ Person(x)` 等价于断言"理查是国王**且**是人""约翰王是国王**且**是人""理查的左腿是国王**且**是人"……——显然不是我们想要的。（原书特意提醒：**连把这一段读了好几遍的认真读者也常犯这个错**。）

#### 存在量化（∃）

谈论某个对象而不点名，用**存在量词**。说"约翰王头上戴着一顶王冠"：`∃ x Crown(x) ∧ OnHead(x, John)`。`∃x` 读作"**存在一个 x 使得……**"。`∃ x P` 在给定模型中为真，当且仅当 `P` 在**至少一个**把 `x` 指派到某个域元素的扩展解释下为真。

> **注意**：按此定义，在"约翰王戴了两顶王冠"的模型中该句**同样为真**——与"约翰王头上有顶王冠"的本来意思完全一致。（变体 `∃¹` 或 `∃!` 表示"恰好存在一个"，也可用等值语句表达。）
> ⚠️ **`∧` 是配合 `∃` 的自然联结词，正如 `⇒` 配合 `∀`。** 反过来用 `⇒` 配合 `∃` 会得到**极弱**的句子：`∃ x Crown(x) ⇒ OnHead(x, John)` 说的是"至少有一个对象使'它是王冠 ⇒ 它在约翰头上'为真"，而蕴涵式只要**前件为假就为真**——理查不是王冠，第一条断言就为真，存在式即被满足。**只要有任何对象不满足前件，存在量化的蕴涵句就为真**，这样的句子实际上什么也没说。

#### 嵌套量词

- 同类量词连用："兄弟是手足"→ `∀ x ∀ y Brother(x, y) ⇒ Sibling(x, y)`
- 同类量词可合并为带多个变量的量词："手足关系对称"→ `∀ x,y Sibling(x, y) ⇔ Sibling(y, x)`
- 混合量词：**顺序极其重要**

```
∀ x ∃ y Loves(x, y)    // 每个人都爱某个人
∃ y ∀ x Loves(x, y)    // 存在一个人，他被所有人爱
```

加括号更清楚：`∀ x (∃ y Loves(x,y))` 说**每个人都有某种性质**（爱某人的性质）；`∃ y (∀ x Loves(x,y))` 说**世界上某人有某种性质**（被所有人爱的性质）。

> **同名变量的坑**：`∀ x (Crown(x) ∨ (∃ x Brother(Richard, x)))` 中，`Brother(Richard,x)` 里的 `x` 受**存在量词**约束。**规则：变量从属于提到它的那个最内层量词，不再受其他量词管辖。** 换言之，`∃ x Brother(Richard,x)` 是**关于理查**的句子（他有兄弟），不是关于 `x` 的，外面套 `∀ x` 没有效果；写成 `∃ z Brother(Richard,z)` 也一样。**本书此后在嵌套量词中一律使用不同的变量名。**

#### `∀` 与 `∃` 的联系

两个量词通过**否定**紧密相连：

```
"人人都不喜欢欧防风" ≡ "不存在喜欢欧防风的人"
∀ x ¬Likes(x, Parsnips) ≡ ¬∃ x Likes(x, Parsnips)
"人人都喜欢冰淇淋"   ≡ "没有人不喜欢冰淇淋"
∀ x Likes(x, IceCream)  ≡ ¬∃ x ¬Likes(x, IceCream)
```

因为 `∀` 实际上是**对宇宙中所有对象的合取**、`∃` 是**析取**，它们服从**德摩根律**就不足为奇：

| 带量词的德摩根律 | 不带量词的德摩根律 |
|---|---|
| `¬∃ x P ≡ ∀x ¬P` | `¬(P ∨ Q) ≡ ¬P ∧ ¬Q` |
| `¬∀ x P ≡ ∃x ¬P` | `¬(P ∧ Q) ≡ ¬P ∨ ¬Q` |
| `∀ x P ≡ ¬∃x ¬P` | `P ∧ Q ≡ ¬(¬P ∨ ¬Q)` |
| `∃ x P ≡ ¬∀x ¬P` | `P ∨ Q ≡ ¬(¬P ∧ ¬Q)` |

我们其实并不**需要**同时有 `∀` 和 `∃`，正如不需要同时有 `∧` 和 `∨`。但**可读性比简约更重要**，两者都保留。

### 8.2.7 相等

除了用谓词和项造原子句子，还可以用**相等符号**表示两个项指称**同一对象**：`Father(John) = Henry`。因为解释确定了任何项的指称，判定等值句的真值只需看两项指称是否同一对象。等值符号既可陈述关于某函数的事实，也可与否定连用**强制两个项不是同一对象**——"理查至少有两个兄弟"：

```
∃ x,y Brother(x, Richard) ∧ Brother(y, Richard) ∧ ¬(x = y)
```

> ⚠️ **去掉 `¬(x = y)` 就不行**：`∃ x,y Brother(x,Richard) ∧ Brother(y,Richard)` 在 Figure 8.2 的模型中为真，而理查在那里**只有一个兄弟**——因为存在把 `x` 与 `y` **都**指派给约翰王的扩展解释。加上 `¬(x = y)` 才排除这类模型。（`x ≠ y` 常用作 `¬(x = y)` 的缩写。）

### 8.2.8 数据库语义

假设我们**相信**理查有两个兄弟约翰和杰弗里。写 `Brother(John, Richard) ∧ Brother(Geoffrey, Richard)`（式 8.3）并不能完整刻画事态：① 它在"理查只有一个兄弟"的模型中也为真 → 需补 `John ≠ Geoffrey`；② 它没排除"理查还有更多兄弟"的模型 → 需补域闭包。正确翻译是：

```
Brother(John, Richard) ∧ Brother(Geoffrey, Richard) ∧ John ≠ Geoffrey
  ∧ ∀ x Brother(x, Richard) ⇒ (x = John ∨ x = Geoffrey)
```

这条逻辑句子比对应英语句子笨重得多，**但翻译不到位，逻辑推断系统就会出错**。数据库系统中非常流行的方案是三条假设：

| 假设 | 含义 |
|---|---|
| **唯一名称假设（unique-names assumption）** | 每个常量符号指称**互不相同**的对象 |
| **封闭世界假设（closed-world assumption）** | 未知为真的原子句子**实为假** |
| **域闭包（domain closure）** | 每个模型包含的域元素**不多于**常量符号所命名的那些 |

在这套**数据库语义（database semantics）**下，式 (8.3) 确实陈述了"理查恰好有两个兄弟约翰和杰弗里"（逻辑程序设计系统也用它，见 §9.4.4）。对照 Figure 8.5（与 Figure 8.4 同情形）：两个对象有 **4 个可能的二元组**，满足该关系的元组子集有 `2⁴ = 16` 种，**总共只有 16 个可能模型**——远少于标准语义下的无穷多个。**代价**：数据库语义要求**确定地知道世界包含什么**。

> **重要观点**：逻辑并不存在唯一"正确"的语义。一种语义的用处取决于两点——能否让我们**简洁直观**地写下想写的知识，以及对应的**推理规则**是否容易、自然地建立。数据库语义在"确定知道全部对象身份、且掌握全部事实"时最有用，其他情形下相当别扭。**本章其余部分采用标准语义**，同时指出它导致表达笨拙的场合。

## 8.3 使用一阶逻辑（Using First-Order Logic）

在知识表示中，**域（domain）**就是我们想表达某些知识的世界的某个部分。本节依次看亲属关系、数/集合/列表、wumpus 世界。

### 8.3.1 一阶逻辑中的断言与查询

句子用 `TELL` 加入知识库，称为**断言（assertion）**：

```
TELL(KB, King(John)) .        TELL(KB, Person(Richard)) .
TELL(KB, ∀ x King(x) ⇒ Person(x)) .
```

用 `ASK` 提问，被问的问题称为**查询（query）**或**目标（goal）**。任何被知识库逻辑蕴涵的查询都应得到肯定回答：`ASK(KB, King(John))` → `true`；`ASK(KB, Person(John))` → `true`。

也可以问量化查询 `ASK(KB, ∃ x Person(x))`，答案是 `true`——但这就像回答"能告诉我几点了吗？"说"能"一样没用。若想知道**使句子为真的 x 的值**，需要另一个函数 `ASKVARS`：`ASKVARS(KB, Person(x))` → `{x/John}` 和 `{x/Richard}`。这样的答案称为**代入（substitution）**或**绑定列表（binding list）**。

> `ASKVARS` 通常只用于**仅由 Horn 子句构成**的知识库，因为在那里每种使查询为真的途径都会把变量绑定到具体值。一阶逻辑不是这样：在只被告知 `King(John) ∨ King(Richard)` 的知识库中，查询 `∃ x King(x)` 事实上为真，却**没有单个绑定**能使它为真。

### 8.3.2 亲属关系域

对象是人。一元谓词有 `Male`、`Female` 等；亲缘关系用二元谓词 `Parent, Sibling, Brother, Sister, Child, Daughter, Son, Spouse, Wife, Husband, Grandparent, Grandchild, Cousin, Aunt, Uncle`；`Mother` 与 `Father` 用函数（每个人生物学上恰好各有一个）。把每个符号用其他符号写下我们所知道的：

```
∀ m,c  Mother(c) = m  ⇔ Female(m) ∧ Parent(m, c)                  // 母亲是自己父母中女性那个
∀ w,h  Husband(h, w)  ⇔ Male(h) ∧ Spouse(h, w)                    // 丈夫是自己的男性配偶
∀ p,c  Parent(p, c)   ⇔ Child(c, p)                               // 父母与子女互逆
∀ g,c  Grandparent(g, c) ⇔ ∃ p Parent(g, p) ∧ Parent(p, c)        // 祖父母是自己父母的父母
∀ x,y  Sibling(x, y) ⇔ x ≠ y ∧ ∃ p Parent(p, x) ∧ Parent(p, y)    // 手足是自己父母的另一个孩子
```

**公理与定理**：以上每条都是亲属域的一条**公理（axiom）**，同时也是**定义（definition）**——形如 `∀ x,y P(x,y) ⇔ …`，用其他谓词定义了 `Mother` 函数与 `Husband`、`Male`、`Parent`、`Grandparent`、`Sibling` 谓词；定义最终"触底"在一组基本谓词（`Child`、`Female` 等）上。**基本谓词集未必唯一**（也可用 `Parent` 代替 `Child`），有些域中根本找不出明确的基本集。

> **"手足关系是对称的" `∀ x,y Sibling(x,y) ⇔ Sibling(y,x)` 是公理还是定理？**
> 它是**定理**——由定义手足关系的公理逻辑蕴涵出来，`ASK` 该句应返回 `true`。纯逻辑观点：知识库只需含公理、不必含定理，因为定理不增加可推出的结论集合。实践观点：定理对**降低计算代价**必不可少；没有定理，推断系统每次都得从第一原理重推，就像物理学家每做一道新题都要重新推导微积分法则。

并非所有公理都是定义：有些只给出关于某谓词的更一般信息；有些谓词我们**知之不足以完整刻画**，例如没有明显方式补全 `∀ x Person(x) ⇔ …`。一阶逻辑允许我们**不完全定义**就使用 `Person`，只写部分规范——`∀ x Person(x) ⇒ …`（凡是人的都有什么性质）与 `∀ x … ⇒ Person(x)`（什么性质使人成为人）。公理也可以是"纯事实"，如 `Male(Jim)`、`Spouse(Jim, Laura)`，它们构成**具体问题实例**的描述。

> **缺少公理的信号**：常常发现**预期中的答案推不出来**。例如由 `Spouse(Jim, Laura)`（在多数国家的法律下）我们期望能推出 `¬Spouse(George, Laura)`，但它**并不**由前面的公理蕴涵——即使按 §8.2.8 补上 `Jim ≠ George` 也不行。这就是缺少公理的信号（习题 8.HILL 要求补上）。

### 8.3.3 数、集合与列表

**自然数（natural numbers，即非负整数）**是"庞大理论如何从极小公理核长出"的最鲜明例子。只需要一个谓词 `NatNum`、一个常量 `0`、一个函数 `S`（**后继**）。**皮亚诺公理（Peano axioms）**定义自然数与加法：

```
NatNum(0) .
∀ n NatNum(n) ⇒ NatNum(S(n)) .              // 0 是自然数；自然数的后继也是自然数
∀ n 0 ≠ S(n) .                              // 0 不是任何数的后继
∀ m,n m ≠ n ⇒ S(m) ≠ S(n) .                 // 不同数的后继也不同
∀ m NatNum(m) ⇒ +(0, m) = m .               // 0 加任何自然数 m 得 m
∀ m,n NatNum(m) ∧ NatNum(n) ⇒ +(S(m), n) = S(+(m, n)) .
```

于是自然数就是 `0, S(0), S(S(0)), …`。把 `S(n)` 写成 `n + 1` 后，第二条加法公理成为 `∀ m,n NatNum(m) ∧ NatNum(n) ⇒ (m + 1) + n = (m + n) + 1`，把加法化归为反复应用后继。

> ⚠️ **待核**：原书在讲解第一条加法公理时提到"二元函数符号 `+` **在项 `+(m,0)` 中的使用**"，但该公理写的是 `+(0,m) = m`，疑为原书笔误；此处按公理正文录。
> **记法说明**：一阶逻辑采用的记法叫**前缀（prefix）**，日常数学写 `m + 0` 用的是**中缀（infix）**；本书允许用中缀。这正是**语法糖（syntactic sugar）**——对标准语法的扩展/缩写，**不改变语义**，任何带糖的句子都能"脱糖（desugar）"成普通一阶逻辑中的等价句子。其他例子：用方括号代替圆括号；合并量词 `∀ x ∀ y P(x,y)` → `∀ x,y P(x,y)`。

有了加法，乘法就是重复加法，幂是重复乘法，进而可定义整除与余数、素数……**整个数论（包括密码学）都能由一个常量、一个函数、一个谓词和四条公理搭建起来。**（注：皮亚诺公理还包括**归纳原理**，但那是**二阶逻辑**的句子而非一阶逻辑的；这一区别的重要性在第 9 章说明。）

**集合（set）**同样是数学与常识推理的基础（事实上可在集合论中定义数论）。词汇（均作语法糖）：常量 `{}`（空集）；一元谓词 `Set`；二元谓词 `x ∈ s`（x 是 s 的元素）、`s₁ ⊆ s₂`（子集，可相等）；二元函数 `s₁ ∩ s₂`（交）、`s₁ ∪ s₂`（并）、`Add(x, s)`（把 x 加入 s 所得集合）。一组可能的公理：

```
1. ∀ s Set(s) ⇔ (s = {}) ∨ (∃ x,s₂ Set(s₂) ∧ s = Add(x, s₂))   // 只有空集和"加出来的"是集合
2. ¬∃ x,s Add(x, s) = {}                                       // 空集无法分解成更小的集合+元素
3. ∀ x,s x ∈ s ⇔ s = Add(x, s)                                 // 加入已有元素无效果
4. ∀ x,s x ∈ s ⇔ ∃ y,s₂ (s = Add(y, s₂) ∧ (x = y ∨ x ∈ s₂))    // 成员资格递归定义
5. ∀ s₁,s₂ s₁ ⊆ s₂ ⇔ (∀ x x ∈ s₁ ⇒ x ∈ s₂)
6. ∀ s₁,s₂ (s₁ = s₂) ⇔ (s₁ ⊆ s₂ ∧ s₂ ⊆ s₁)
7. ∀ x,s₁,s₂ x ∈ (s₁ ∩ s₂) ⇔ (x ∈ s₁ ∧ x ∈ s₂)
8. ∀ x,s₁,s₂ x ∈ (s₁ ∪ s₂) ⇔ (x ∈ s₁ ∨ x ∈ s₂)
```

**列表（list）**与集合类似，差别在于列表**有序**且同一元素可出现多次。沿用 Lisp 词汇：`Nil` 是无元素的常量列表；`Cons`、`Append`、`First`、`Rest` 是函数；`Find` 是谓词（对列表的作用相当于 `Member` 对集合）；`List` 是只对列表为真的谓词。语法糖：空列表 `[]`；`Cons(x, Nil)` 写作 `[x]`；`[A,B,C]` 对应嵌套项 `Cons(A, Cons(B, Cons(C, Nil)))`。（列表公理见习题 8.LIST。）

### 8.3.4 wumpus 世界

第 7 章给的是命题逻辑公理；本节的一阶公理**简洁得多**，恰好只说我们想说的东西。

**感知与动作**：智能体接收含 5 个元素的**感知向量**，存入知识库的句子必须**同时包含感知和它发生的时刻**，否则智能体会搞不清"何时看到了什么"。时间步用整数：`Percept([Stench, Breeze, Glitter, None, None], 5)`。动作表示为逻辑项 `Turn(Right)`、`Turn(Left)`、`Forward`、`Shoot`、`Grab`、`Climb`；要决定哪个最好，执行 `ASKVARS(KB, BestAction(a, 5))` → `{a/Grab}`。

**从原始感知推出当前状态的事实**（这是称为**感知（perception）**的推理过程的最简单形式，第 25 章深入讨论）：

```
∀ t,s,g,w,c  Percept([s, Breeze,  g, w, c], t) ⇒ Breeze(t)
∀ t,s,g,w,c  Percept([s, None,    g, w, c], t) ⇒ ¬Breeze(t)
∀ t,s,b,w,c  Percept([s, b, Glitter, w, c], t) ⇒ Glitter(t)
∀ t,s,b,w,c  Percept([s, b, None,    w, c], t) ⇒ ¬Glitter(t)      （其余依此类推）
```

> **注意对时间 `t` 的量化**：在命题逻辑中，每个时间步都得复制一份同样的句子。

简单"反射"行为也可用量化蕴涵句实现：`∀ t Glitter(t) ⇒ BestAction(Grab, t)`。结合上面的感知与规则，就会得到想要的结论 `BestAction(Grab, 5)`。

**表示环境本身**：对象是方格、坑和 wumpus。

- **方格**：给每格起名（`Square₁,₂` 等）会让"相邻"变成一条条额外事实，每对格子都要一条。更好的办法是用**复合项**把行列写成整数（如列表项 `[1,2]`），于是任意两格的相邻关系可**一次定义**：

  ```
  ∀ x,y,a,b  Adjacent([x,y], [a,b]) ⇔
      (x = a ∧ (y = b − 1 ∨ y = b + 1)) ∨ (y = b ∧ (x = a − 1 ∨ x = a + 1))
  ```

- **坑**：给每个坑命名不合适，因为没有理由区分它们（就像我们不会给每只迁徙的鸟起名；研究迁徙模式的鸟类学家才会给鸟套环以追踪个体）。用**一元谓词 `Pit`**，对含坑的方格为真。
- **wumpus**：恰好只有一只，用常量 `Wumpus` 就够（也许对 wumpus 来说更体面）。

**位置与状态**：智能体位置随时间变化，写成 `At(Agent, s, t)`（在时刻 t 位于方格 s）。

```
∀ t At(Wumpus, [1,3], t)                              // 把 wumpus 永久固定在某处
∀ x,s₁,s₂,t  At(x, s₁, t) ∧ At(x, s₂, t) ⇒ s₁ = s₂    // 一个物体同一时刻只能在一处
∀ s,t        At(Agent, s, t) ∧ Breeze(t) ⇒ Breezy(s)  // 有微风的时刻所处的方格是有微风的
```

> `Breezy` **没有时间参数**——这一点很有用，因为我们知道坑不会到处移动。

**核心对比**：命题逻辑必须为每一格单独写一条公理（见第 220 页 R2、R3），而且**每种地理布局都要换一套公理**；一阶逻辑只需要**一条**：

```
∀ s Breezy(s) ⇔ ∃ r Adjacent(r, s) ∧ Pit(r)                                     (8.4)
```

同样，一阶逻辑可以对**时间**量化，因此每个谓词只需**一条后继状态公理（successor-state axiom）**，不必为每个时间步复制一份。例如箭的公理（原书式 (7.2)，第 240 页）变成：

```
∀ t HaveArrow(t + 1) ⇔ (HaveArrow(t) ∧ ¬Action(Shoot, t))
```

从这两条可见：一阶逻辑的表述**不比**第 7 章英语描述的原版更啰嗦。（智能体位置与朝向的类似公理留给读者构造，它们同时量化空间与时间。）第 11 章更深入讨论一阶后继状态公理及其在构造计划中的用途。

## 8.4 一阶逻辑中的知识工程（Knowledge Engineering in First-Order Logic）

上一节展示了在三个简单域中如何用一阶逻辑表示知识。本节描述构造知识库的通用过程——**知识工程（knowledge engineering）**。**知识工程师**考察某个特定域、弄清该域中哪些概念重要、并为域中的对象与关系建立形式表示。下面以**电子电路域**为例。

> 本节方法适用于开发**用途明确、范围被仔细限定、查询范围事先已知**的专用知识库。覆盖广泛人类知识、用于支持自然语言理解等任务的**通用知识库**在第 10 章讨论。

### 8.4.1 知识工程过程

知识工程项目差异极大，但都包含以下 **7 步**：

| 步 | 名称 | 要点 |
|---|---|---|
| 1 | **确定问题** | 划定要支持的问题范围，以及每个问题实例可获得哪些事实。例：wumpus 知识库是要选动作，还是只回答环境内容？**这一步类似于第 2 章设计智能体的 PEAS 过程** |
| 2 | **收集相关知识** | 知识工程师可能已是专家，也需与真正的专家合作抽取知识——即**知识获取（knowledge acquisition）**。此阶段知识尚未形式化。（wumpus 世界由人造规则定义，相关知识易识别——但**"相邻"的定义并未在其规则中显式给出**。真实域中"相关性"可能很难判断：模拟 VLSI 要不要考虑杂散电容和趋肤效应？） |
| 3 | **确定词汇表** | 把**领域层概念**翻译成**逻辑层名字**，风格问题影响重大。例：坑用对象表示还是用方格上的一元谓词？朝向用函数还是谓词？wumpus 的位置是否依赖时间？选完的词汇表称为该域的**本体（ontology）**——**本体决定存在哪类事物，但不决定它们的具体性质与相互关系** |
| 4 | **编码域的通用知识** | 为所有词汇项写下公理，固定其含义，使专家能检查内容。这一步常暴露词汇中的误解或空缺，需回到第 3 步迭代 |
| 5 | **编码问题实例的描述** | 本体想得好时这步很容易：就本体已有概念的实例写简单原子句子。逻辑智能体的问题实例由传感器提供；"无实体"知识库则像传统程序接收输入数据 |
| 6 | **提出查询并取得答案** | 让推断过程在公理与问题特定事实上运行，导出我们想知道的事实，从而**免去编写针对具体应用的求解算法** |
| 7 | **调试与评估知识库** | 答案很少第一次就对。更准确地说：假定推断过程可靠，答案对**所写的知识库**是正确的，只是**不是用户期待的那些** |

**第 7 步的两类错误各有特征**：

- **缺失公理 / 公理过弱**：容易通过"推理链在意料之外的地方中断"定位。例如找 wumpus 的**诊断规则**若写成 `∀ s Smelly(s) ⇒ Adjacent(Home(Wumpus), s)` 而不是双条件句，智能体就**永远无法证明某处没有 wumpus**
- **错误公理**：可识别，因为它们是**关于世界的假陈述**。例如 `∀ x NumOfLegs(x, 4) ⇒ Mammal(x)` 对爬行动物、两栖动物和桌子都是假的。**这种假可以独立于知识库其余部分判定**——相比之下，程序里的典型错误形如 `offset = position + 1`，不看清周围上下文根本无法判断该写成 `position` 还是 `position + 1`

> 当你觉得知识库里没有明显错误时，很想宣布成功。但**除非确实明显没有错误，更好的做法是用一组查询组成的测试集正式评估系统，统计答对了多少**。没有客观度量，太容易说服自己"做完了"。

### 8.4.2 电子电路域

按上述 7 步开发本体与知识库，用于推理 Figure 8.6 的数字电路（号称**一位全加器**：前两个输入是要相加的两位，第三个输入是进位位；第一个输出是和，第二个输出是给下一级加法器的进位位；含两个 XOR 门、两个 AND 门、一个 OR 门）。

**① 确定问题**：功能分析（最高层）——电路真的能正确相加吗？若所有输入都为高，门 A2 的输出是什么？结构问题——接在第一个输入端子上的是哪些门？电路含反馈回路吗？（时序延迟、面积、功耗、成本等更细的层次各需额外知识。）

**② 收集相关知识**：数字电路由**导线**和**门**组成。信号沿导线流到门的输入端子，每个门在其输出端子上产生信号，再沿另一条导线流出；要知道信号是什么，需知道各门如何变换输入信号。门有四种类型：AND、OR、XOR 有两个输入端子，NOT 有一个；所有门都有一个输出端子。电路像门一样有输入和输出端子。

> **关键的本体决策**：为推理功能与连通性，我们**不需要**谈论导线本身、走线路径或交汇点。唯一要紧的是**端子之间的连接**——可以说"一个输出端子连到另一个输入端子"而不必说是什么把它们连起来的；元件的尺寸、形状、颜色、成本都与本次分析无关。
> **目的变了，本体就要变**：若目的是调试故障电路，最好把导线纳入本体（坏导线会破坏流经它的信号）；要解决时序故障，需加入门延迟；要设计能盈利的产品，电路成本与相对竞品的速度就很重要。

**③ 确定词汇表**：

| 类别 | 表示 |
|---|---|
| 门 | 每个门是一个**对象**，由常量命名，用 `Gate(X1)` 断言它是门 |
| 门的类型 | 取值是常量 `AND, OR, XOR, NOT` 之一；因每个门**恰好一个**类型，用**函数**：`Type(X1) = XOR` |
| 电路 | 用谓词标识：`Circuit(C1)` |
| 端子 | 谓词 `Terminal(x)`；函数 `In(1, X1)` 表示第一个输入端子、`Out(n, c)` 表示输出端子、`Arity(c, i, j)` 表示 i 个输入 j 个输出 |
| 连通性 | 谓词 `Connected`：`Connected(Out(1,X1), In(1,X2))` |
| 信号 | 把两个信号值 **1** 和 **0**（"开""关"）作为**对象**引入，再用函数 `Signal(t)` 表示端子 t 的信号值 |

> 为什么不用一元谓词 `On(t)`？因为那样很难提出"电路 C1 输出端子上所有可能的信号取值是什么"这类问题。**把信号值做成对象**就是为了能对它做量化查询。

**④ 编码域的通用知识**——本体好的一个标志是只需**很少几条**通用规则，且都能清晰简洁地陈述。所需的全部公理（①相连的端子信号相同；②信号非 1 即 0；③`Connected` 可交换；④门共四种类型；⑤–⑧ AND / OR / XOR / NOT 的行为；⑨元数；⑩端子数不超过元数；⑪三类对象互异；⑫门是电路）：

```
 1. ∀ t₁,t₂ Terminal(t₁) ∧ Terminal(t₂) ∧ Connected(t₁,t₂) ⇒ Signal(t₁) = Signal(t₂)
 2. ∀ t Terminal(t) ⇒ Signal(t) = 1 ∨ Signal(t) = 0
 3. ∀ t₁,t₂ Connected(t₁,t₂) ⇔ Connected(t₂,t₁)
 4. ∀ g Gate(g) ∧ k = Type(g) ⇒ k = AND ∨ k = OR ∨ k = XOR ∨ k = NOT
 5. ∀ g Gate(g) ∧ Type(g) = AND ⇒ Signal(Out(1,g)) = 0 ⇔ ∃ n Signal(In(n,g)) = 0
 6. ∀ g Gate(g) ∧ Type(g) = OR  ⇒ Signal(Out(1,g)) = 1 ⇔ ∃ n Signal(In(n,g)) = 1
 7. ∀ g Gate(g) ∧ Type(g) = XOR ⇒ Signal(Out(1,g)) = 1 ⇔ Signal(In(1,g)) ≠ Signal(In(2,g))
 8. ∀ g Gate(g) ∧ Type(g) = NOT ⇒ Signal(Out(1,g)) ≠ Signal(In(1,g))
 9. ∀ g Gate(g) ∧ Type(g) = NOT ⇒ Arity(g,1,1)
    ∀ g Gate(g) ∧ k = Type(g) ∧ (k = AND ∨ k = OR ∨ k = XOR) ⇒ Arity(g,2,1)
10. ∀ c,i,j Circuit(c) ∧ Arity(c,i,j) ⇒
        ∀ n (n ≤ i ⇒ Terminal(In(n,c))) ∧ (n > i ⇒ In(n,c) = Nothing)
      ∧ ∀ n (n ≤ j ⇒ Terminal(Out(n,c))) ∧ (n > j ⇒ Out(n,c) = Nothing)
11. ∀ g,t,s Gate(g) ∧ Terminal(t) ∧ Signal(s) ⇒ g ≠ t ∧ g ≠ s ∧ t ≠ s
12. ∀ g Gate(g) ⇒ Circuit(g)
```

**⑤ 编码具体问题实例**——Figure 8.6 编码为电路 C1：

```
Circuit(C1) ∧ Arity(C1, 3, 2)
Gate(X1) ∧ Type(X1) = XOR      Gate(X2) ∧ Type(X2) = XOR
Gate(A1) ∧ Type(A1) = AND      Gate(A2) ∧ Type(A2) = AND
Gate(O1) ∧ Type(O1) = OR

Connected(Out(1,X1), In(1,X2))   Connected(In(1,C1), In(1,X1))
Connected(Out(1,X1), In(2,A2))   Connected(In(1,C1), In(1,A1))
Connected(Out(1,A2), In(1,O1))   Connected(In(2,C1), In(2,X1))
Connected(Out(1,A1), In(2,O1))   Connected(In(2,C1), In(2,A1))
Connected(Out(1,X2), Out(1,C1))  Connected(In(3,C1), In(2,X2))
Connected(Out(1,O1), Out(2,C1))  Connected(In(3,C1), In(1,A2))
```

**⑥ 提出查询**——什么输入组合会使 C1 的第一个输出（和位）为 0、第二个输出（进位位）为 1？

```
∃ i₁,i₂,i₃  Signal(In(1,C1)) = i₁ ∧ Signal(In(2,C1)) = i₂ ∧ Signal(In(3,C1)) = i₃
          ∧ Signal(Out(1,C1)) = 0 ∧ Signal(Out(2,C1)) = 1
```

`ASKVARS` 给出**三个**代入：`{i₁/1, i₂/1, i₃/0}`、`{i₁/1, i₂/0, i₃/1}`、`{i₁/0, i₂/1, i₃/1}`。

再问"所有端子上的可能取值集合是什么"：

```
∃ i₁,i₂,i₃,o₁,o₂  Signal(In(1,C1)) = i₁ ∧ Signal(In(2,C1)) = i₂ ∧ Signal(In(3,C1)) = i₃
                ∧ Signal(Out(1,C1)) = o₁ ∧ Signal(Out(2,C1)) = o₂
```

这个查询返回该器件的**完整输入–输出表**，可用来检查它是否真的正确相加——这是**电路验证（circuit verification）**的一个简单例子。用电路的定义还可搭建更大的数字系统并施行同样验证（习题 8.ADDR）。许多域都适合这种结构化开发：**在较简单的概念之上定义较复杂的概念**。

**⑦ 调试知识库**——可用各种方式扰动知识库，看会冒出什么错误行为。例如假设我们没读 §8.2.8，因而**忘了断言 `1 ≠ 0`**。突然之间，系统除输入情形 **000 和 110** 之外，**证明不出电路的任何输出**。

定位办法是逐个门追问其输出。问 `∃ i₁,i₂,o Signal(In(1,C1)) = i₁ ∧ Signal(In(2,C1)) = i₂ ∧ Signal(Out(1,X1)) = o`，会发现：在输入为 10 和 01 的情形下，X1 处**没有任何已知输出**。于是去看 XOR 门公理在 X1 上的实例 `Signal(Out(1,X1)) = 1 ⇔ Signal(In(1,X1)) ≠ Signal(In(2,X1))`；若已知输入分别为 1 和 0，它归约为 `Signal(Out(1,X1)) = 1 ⇔ 1 ≠ 0`。问题一目了然：系统无法推断 `Signal(Out(1,X1)) = 1`，所以必须告诉它 `1 ≠ 0`。

## 小结

1. 知识表示语言应当**声明式、组合性、表达力强、语境无关且无歧义**。编程语言缺通用推导机制、也无法直接表达部分信息；自然语言依赖语境且有歧义。
2. 各种逻辑的区别在于**本体论承诺**与**认识论承诺**。命题逻辑只承诺**事实**；一阶逻辑还承诺**对象与关系**，由此获得表达力，适合 wumpus 世界与电子电路这样的域。二者的认识论承诺都是"真 / 假 / 未知"三种状态。
3. 二者都难以表示**模糊命题**——这限制了它们在需要个人判断的领域（政治、烹饪）的适用性。应对有细化表示、模糊逻辑的**真值度**、概念空间中的距离；⚠️ **真值度（模糊）≠ 信念度（概率）**。
4. 一阶逻辑的**语法**在命题逻辑之上加了**项**（指称对象）与**全称/存在量词**。⚠️ `∀` 自然配 `⇒`，`∃` 自然配 `∧`；量词**顺序**与**变量名作用域**都要小心。
5. 一阶逻辑的**模型** = 一组对象 + 一个**解释**（常量 → 对象，谓词 → 关系，函数 → 函数）。原子句子为真当且仅当谓词所指关系在参数所指对象之间成立；量化句子的真值由**扩展解释**定义。模型数量无界，因此**不能靠枚举模型检查蕴涵**。
6. 在一阶逻辑中开发知识库需要严谨的过程：**确定问题 → 收集知识 → 确定词汇（本体）→ 编码通用知识 → 编码实例 → 提出查询 → 调试与评估**（7 步）。
