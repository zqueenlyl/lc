## 0. 本章要解决的问题

第 3–4 章的问题求解智能体"知道"的东西非常有限且死板：它知道某个状态下某个动作的结果，但不知道任何**一般性事实**（路线寻找智能体不知道"路程不能是负数"；八数码智能体不知道"两个方块不能占同一格"）。第 6 章的变量赋值表示法朝正确方向走了一步，但本章要把这步走到它的逻辑结论——**把逻辑作为一类通用的知识表示**，让智能体能对复杂世界形成表示、用推断（inference）推出关于世界的新表示，并据此决定该做什么。

## 7.1 基于知识的智能体（Knowledge-Based Agents）

**核心组件是知识库（knowledge base, KB）**：一组句子（sentence）。"句子"是技术术语，与英语句子相关但不等同；每个句子用一种**知识表示语言**（knowledge representation language）表达，对世界做出某种**断言**（assertion）。当句子不是从其他句子推导出来、而是被直接当作给定时，称它为**公理**（axiom）。

知识库必须提供两种操作：

| 操作 | 作用 |
|---|---|
| `TELL` | 向知识库加入新句子 |
| `ASK` | 查询知识库已知什么 |

两者都可能涉及**推断**（inference）——从旧句子推出新句子。推断必须遵守一条要求：向知识库提问时，答案应当**从先前 TELL 过的内容中得出**（"follow" 的确切含义留到后文再精确化）。

**通用知识智能体程序** `KB-AGENT(percept)`（Figure 7.1）：

```
persistent: KB（知识库）, t（计数器，初值 0，表示时间）
TELL(KB, MAKE-PERCEPT-SENTENCE(percept, t))   // 断言：此刻感知到 percept
action ← ASK(KB, MAKE-ACTION-QUERY(t))         // 询问：此刻该做什么动作
TELL(KB, MAKE-ACTION-SENTENCE(action, t))      // 断言：已执行该动作
t ← t + 1
return action
```

- `MAKE-PERCEPT-SENTENCE` 构造"在给定时间感知到给定感知"的句子；
- `MAKE-ACTION-QUERY` 构造"当前时刻应做什么动作"的问句；
- `MAKE-ACTION-SENTENCE` 构造"所选动作已执行"的句子。

**知识级 vs 实现级**：`TELL`/`ASK` 的定义使基于知识的智能体不再是"任意一个算动作的程序"。它可以在**知识级**（knowledge level）上被描述——只需说明智能体知道什么、目标是什么，就能确定其行为，而不必关心实现细节。例：自动出租车知道金门大桥是连接旧金山与马林县的唯一通道，于是它**会**过桥，因为知道过桥能达成目标；至于它的地理知识是链表还是像素图、推理是符号串操作还是神经网络信号传播，**与这个分析无关**。

**声明式 vs 过程式**：从空知识库出发，设计者一条条 `TELL` 句子，直到智能体知道如何在环境中行动——这叫**声明式系统构建**（declarative approach）。与之相对，**过程式方法**（procedural approach）把期望行为直接编码成程序代码。20 世纪 70–80 年代两派激烈争论；如今我们知道二者是互补的（第 9 章的 Prolog 是声明式的典范）。

## 7.2 wumpus 世界（The Wumpus World）

wumpus 世界是本章贯穿始终的示例（按本书约定，wumpus 不译、保留小写）。

### 环境规格

- **环境**：`4×4` 方格，四周有墙。智能体总是从 `[1,1]` 出发，面朝东（向右）。金子与 wumpus 的位置在非起点方格中**均匀随机**选取；此外，每个非起点方格独立地以概率 `0.2` 是坑（pit）。
- **执行器**：`Forward`（前进）、`TurnLeft`（左转 90°）、`TurnRight`（右转 90°）。进入有坑或有**活** wumpus 的方格即惨死（进入有死 wumpus 的方格安全，只是臭）。前进撞墙则原地不动。`Grab` 在同行方格捡起金子；`Shoot` 朝面朝方向射一支箭，箭一直飞到击中（并杀死）wumpus 或撞墙为止——**智能体只有一支箭**，所以只有第一次 `Shoot` 有效。`Climb` 用于爬出洞穴，但**只能从 `[1,1]`** 爬出。
- **传感器**（五种，各给 1 比特信息）：

| 感知 | 触发条件 |
|---|---|
| `Stench`（恶臭） | 与 wumpus **直接相邻**（非对角） |
| `Breeze`（微风） | 与坑**直接相邻** |
| `Glitter`（闪光） | 与金子同格 |
| `Bump`（碰撞） | 前进时撞墙 |
| `Scream`（尖叫） | wumpus 被杀时发出，**全洞可闻** |

感知以五符号列表给出，如 `[Stench, None, Breeze, None, None]`。

### 环境性质与难度

沿第 2 章的维度刻画：**确定性、离散、静态、单智能体**（wumpus 不动）；**序贯**（奖励可能在多步动作后才出现）；**部分可观测**（智能体位置、wumpus 健康状况、是否还有箭不能直接感知）。对坑与 wumpus 的位置有两种看法：可视为状态中未观测的部分（转移模型完全已知）；也可视为**转移模型本身未知**（智能体不知道哪些 `Forward` 会致命）。约 **21%** 的环境是**彻底不公平的**——金子本身在坑里或被坑包围。

### 一个推断示例（Figure 7.3–7.4）

初始感知 `[None,None,None,None,None]`，谨慎的智能体只进入它**知道** OK 的方格。

1. 前进到 `[2,1]`，感知到 `Breeze` → 相邻格必有坑；坑不在 `[1,1]`（规则禁止），故 `[2,2]` 或 `[3,1]`（或两者）有坑，记作 `P?`。此时唯一已知 OK 且未访问的方格是 `[1,2]`，于是掉头回 `[1,1]` 再前进到 `[1,2]`。
2. 在 `[1,2]` 感知到 `Stench`（无微风）→ wumpus 在附近；但 wumpus 不在 `[1,1]`（规则），也不在 `[2,2]`（否则在 `[2,1]` 时就会闻到恶臭）→ **推断 wumpus 在 `[1,3]`**（记 `W!`）。同时 `[1,2]` 无微风意味着 `[2,2]` 无坑；而前面已知 `[2,2]` 或 `[3,1]` 有坑 → **推断坑在 `[3,1]`**。

> 这一步相当难：它组合了**不同时间、不同地点**获得的知识，并依靠**感知的缺失**（lack of a percept）完成关键一步。

## 7.3 逻辑（Logic）

逻辑表示与推理的基本概念**独立于逻辑的任何具体形式**，因此本节用熟悉的算术作例子，把形式细节留到下一节。

| 概念 | 含义 |
|---|---|
| **语法**（syntax） | 规定哪些句子是良形成的。算术里 `x + y = 4` 良形成，`x4y+ =` 不是 |
| **语义**（semantics） | 规定每个句子在**每个可能世界**（possible world）中的真值 |
| **模型**（model） | 需要精确时用"模型"代替"可能世界"：对每个相关句子都有固定真值的数学抽象 |
| **满足**（satisfaction） | 若句子 α 在模型 m 中为真，就说 m 满足 α，或 m 是 α 的一个模型 |

标准逻辑里每个句子在每个可能世界中**要么真要么假，没有中间地带**。

**后承（entailment）**：若在每个 KB 为真的模型中 α 也都为真，则 KB 后承 α，记作

```
KB |= α
```

**示例（Figure 7.5）**：设 KB 断言"[1,1] 无微风"与"[2,1] 有微风"。关于 `[1,2]`、`[2,2]`、`[3,1]` 三格是否有坑，每格可真可假，共 `2³ = 8` 个模型。KB 在**恰好 3 个**模型中为真（图中实线框出）——其余模型里 KB 为假（如任何含 `[1,2]` 有坑的模型，因为那样 `[1,1]` 就该有微风）。考察两个候选结论：

```
α₁ = "[1,2] 无坑"      α₂ = "[2,2] 无坑"
```

逐模型检查：**每个 KB 为真的模型中 α₁ 都为真** → `KB |= α₁`；但存在 KB 为真而 α₂ 为假的模型 → `KB` 不后承 α₂（智能体既不能断定 `[2,2]` 有坑，也不能断定无坑）。

**推断算法**（inference algorithm）：若算法 `i` 能从 KB 推出 α，记作 `KB ⊢ᵢ α`（读作"α 由 i 从 KB 推出"）。

- **可靠性 / 保真性**（sound / truth-preserving）：只推出被后承的句子。不可靠的过程等于**凭空捏造**——宣布发现了不存在的针。模型检查（model checking）在适用时是可靠的。
- **完备性**（completeness）：能推出**所有**被后承的句子。对有限 KB，结论的干草堆有限，系统检查显然总能判定；但对许多 KB，结论的干草堆是**无限的**，完备性成为重要议题。幸运的是，存在对许多 KB 足够强的逻辑的完备推断过程。

> **干草堆与针的类比**（Figure 7.6）：把 KB 的全部后承看成干草堆，α 是针。后承像"针在堆里"，推断像"把针找出来"。句子是智能体的物理构型，推理是从旧构型构造新构型的过程——逻辑推理要保证新构型所代表的**世界方面确实从旧构型所代表的方面得出**。

一个推断过程若其结论在任何前提为真的世界中都为真，就是**保真的**；特别地，若 KB 在真实世界中为真，则其所有后承也在真实世界中为真。那么 KB 在真实世界中为真吗？（KB 只是智能体头脑中的"语法"。）这是哲学问题（见第 27 章）。简单回答：**智能体的传感器建立了这种联系**——感知句子的意义与真值由产生它的感知与句子构造过程定义。其余知识（如"wumpus 使相邻方格有恶臭"）是一般规则，由**学习**（learning）产生（第五部分主题）。学习是**可错的**（fallible）——wumpus 也许**除了**闰年的 2 月 29 日之外都会散发恶臭（那天它们洗澡）。因此 KB 在真实世界中未必为真，但好的学习过程值得乐观。

## 7.4 命题逻辑：一种非常简单的逻辑（Propositional Logic）

命题逻辑足以说明逻辑、推断与知识智能体的基本概念，但表达能力有限（第 8 章的一阶逻辑更强）。

### 7.4.1 语法

命题逻辑的原子句子（atomic sentence）由**一个命题符号**（proposition symbol）构成，每个符号代表一个可真可假的命题。用 `P`、`Q`、`R`… 以及带下标的符号（如 `P₁,₂`）表示。复合句子（complex sentence）由连接词构造：

```
Sentence → AtomicSentence | ComplexSentence
AtomicSentence → True | False | P | Q | R | ...
ComplexSentence → (Sentence) | ¬Sentence | Sentence∧Sentence
                | Sentence∨Sentence | Sentence⇒Sentence | Sentence⇔Sentence
运算符优先级（高→低）： ¬, ∧, ∨, ⇒, ⇔        （Figure 7.7）
```

优先级消除了歧义：`¬A∧B` 等价于 `(¬A)∧B` 而非 `¬(A∧B)`（与算术中 `−2 + 4 = 2` 同理）。

### 7.4.2 语义

语义规定在给定模型下如何计算任意句子的真值，**递归进行**。模型只是给每个命题符号设定真值。例：KB 用到 `P₁,₂`、`P₂,₂`、`P₃,₁` 三个符号，一个可能模型是 `m₁ = {P₁,₂ = false, P₂,₂ = false, P₃,₁ = true}`——三个符号共 `2³ = 8` 个模型，正是 Figure 7.5 所画。注意模型是纯数学对象，与 wumpus 世界没有必然联系：`P₁,₂` 可以表示"[1,2] 有坑"，也可以表示"我今天明天在巴黎"。

对任意子句 `P`、`Q` 与模型 `m`，五条规则（"iff" = 当且仅当）：

| 连接词 | 真值条件 |
|---|---|
| `¬P` | 为真 **iff** `P` 在 m 中为假 |
| `P ∧ Q` | 为真 **iff** `P` 与 `Q` 在 m 中**都**为真 |
| `P ∨ Q` | 为真 **iff** `P` 或 `Q` 在 m 中为真（或两者） |
| `P ⇒ Q` | 为真，**除非** `P` 真而 `Q` 假 |
| `P ⇔ Q` | 为真 **iff** `P` 与 `Q` 同真或同假 |

真值表见 Figure 7.8。例：`¬P₁,₂ ∧ (P₂,₂ ∨ P₃,₁)` 在 `m₁` 下 = `true ∧ (false ∨ true)` = `true ∧ true` = `true`。

> **常见混淆点**：`P ∨ Q` 在 `P`、`Q` 同真时**仍为真**（这是"或"的包容义）。另一个连接词**异或**（exclusive or, xor）在两者同真时取假；其符号无共识，可选 `˙∨`、`⁄=` 或 `⊕`。
> `⇒` 的真值表可能令人困惑：前件为假时蕴含式**恒为真**（"前件为假则任何东西都成立"）。它适合用 `⇔` 书写的场景是**双向成立**时——如"方格有微风 **当且仅当** 相邻方格有坑"：`B₁,₁ ⇔ (P₁,₂ ∨ P₂,₁)`。

### 7.4.3 一个简单的知识库

为 wumpus 世界构造 KB，先处理**不变**的方面（mutable 方面留到 7.7）。每个位置 `[x,y]` 用五个符号：

| 符号 | 含义 |
|---|---|
| `Px, y` | `[x,y]` 有坑 |
| `Wx, y` | `[x,y]` 有 wumpus（死或活） |
| `Bx, y` | `[x,y]` 有微风 |
| `Sx, y` | `[x,y]` 有恶臭 |
| `Lx, y` | 智能体在 `[x,y]` |

句子编号 `Rᵢ` 便于引用：

```
R1 : ¬P1,1                                    // [1,1] 无坑
R2 : B1,1 ⇔ (P1,2 ∨ P2,1)                     // 微风 iff 相邻有坑
R3 : B2,1 ⇔ (P1,1 ∨ P2,2 ∨ P3,1)
R4 : ¬B1,1                                    // 感知：[1,1] 无微风
R5 : B2,1                                     // 感知：[2,1] 有微风
```

这些句子足以推出 `¬P₁,₂`（[1,2] 无坑），即 7.3 节非正式推断的结论。

### 7.4.4 一个简单的推断过程

目标：判定 `KB |= α` 是否成立（如 `¬P₁,₂` 是否被后承）。第一个算法是**模型检查**——直接实现后承的定义：枚举所有模型，检查 α 在每个 KB 为真的模型中是否都为真。

`TT-ENTAILS?(KB, α)`（Figure 7.10，TT = 真值表）：

```
symbols ← KB 与 α 中所有命题符号的列表
return TT-CHECK-ALL(KB, α, symbols, {})

TT-CHECK-ALL(KB, α, symbols, model):
  if EMPTY?(symbols) then
      if PL-TRUE?(KB, model) then return PL-TRUE?(α, model)
      else return true                    // KB 为假时恒返回 true
  else
      P ← FIRST(symbols); rest ← REST(symbols)
      return TT-CHECK-ALL(KB, α, rest, model∪{P=true})
        and TT-CHECK-ALL(KB, α, rest, model∪{P=false})
```

- 递归地对符号做**有限赋值空间**的枚举；`model` 是**部分模型**（partial model）。
- **可靠**（直接实现后承定义）且**完备**（对任意 KB 与 α 都适用，且必终止——模型数有限）。
- 若 KB 与 α 共含 `n` 个符号，则模型数 `2ⁿ`，**时间复杂度 `O(2ⁿ)`**；空间复杂度仅 `O(n)`（深度优先枚举）。
- 不幸的是，命题后承是 **co-NP-complete**（即大概不比 NP-complete 容易，见附录 A），所以每个已知的命题逻辑推断算法最坏情况复杂度都是**输入规模的指数**。

## 7.5 命题定理证明（Propositional Theorem Proving）

模型检查枚举模型；**定理证明**（theorem proving）则**直接把推断规则应用于知识库中的句子**，构造出目标句子的证明，不consulting模型。当模型数很大但证明很短时，定理证明比模型检查更高效。

**逻辑等价**（logical equivalence）：α 与 β 在**同一组模型**中为真，记 `α ≡ β`（注意 `≡` 用于对句子做断言，`⇔` 用作句子内部的一部分）。标准逻辑等价见 Figure 7.11，包括：

```
(α∧β) ≡ (β∧α)                     交换律           (α∨β) ≡ (β∨α)
((α∧β)∧γ) ≡ (α∧(β∧γ))             ∧ 结合律         ((α∨β)∨γ) ≡ (α∨(β∨γ))
¬(¬α) ≡ α                         双重否定消除      (α⇒β) ≡ (¬β⇒¬α)     逆否
(α⇒β) ≡ (¬α∨β)                    蕴含消除          (α⇔β) ≡ ((α⇒β)∧(β⇒α))  双向消除
¬(α∧β) ≡ (¬α∨¬β)                  德摩根           ¬(α∨β) ≡ (¬α∧¬β)
(α∧(β∨γ)) ≡ ((α∧β)∨(α∧γ))         ∧ 对 ∨ 分配      (α∨(β∧γ)) ≡ ((α∨β)∧(α∨γ))
```

**SAT 问题**：命题逻辑的**可满足性**问题是第一个被证明为 NP-complete 的问题（Cook, 1971）。许多计算机科学问题本质都是可满足性问题（如第 6 章所有 CSP 都在问约束能否被某赋值满足）。有效性（validity）与可满足性对偶：

```
α 有效  iff  ¬α 不可满足
α 可满足 iff  ¬α 无效
```

**关键结论**：

```
α |= β  当且仅当  (α ∧ ¬β) 不可满足
```

用检查 `(α ∧ ¬β)` 不可满足来从 α 证 β，正对应数学中的**归谬法**（reductio ad absurdum，"归约到荒谬之物"），也称**反证法**（proof by refutation / proof by contradiction）：假设 β 为假，推出与已知公理 α 的矛盾。

### 7.5.1 推断与证明

**推断规则**（inference rule）是能用来推导**证明**（proof，一串通向目标的结论）的模式。最著名的是 **Modus Ponens**（肯定前件）：

```
α ⇒ β ,  α
─────────
   β
```

书写约定：前提在横线上方，结论在下方。通过考察 α、β 的可能真值，可一次性证明 Modus Ponens 与 **And-Elimination**（`α∧β ⊢ β`）是可靠的；之后这些规则可在任何适用的具体实例中使用，产生可靠推断而**无需枚举模型**。Figure 7.11 所有等价都可用作推断规则（如双向消除给出两条规则）。但并非所有规则都能双向运行——例如 Modus Ponens 不能反向：不能从 `α ⇒ β` 与 `β` 推出 `α`。

**wumpus 世界中的证明示例**（证 `¬P₁,₂`）：

```
1. 对 R2 用双向消除 → R6 : (B1,1⇒(P1,2∨P2,1)) ∧ ((P1,2∨P2,1)⇒B1,1)
2. 对 R6 用 And-Elimination → R7 : ((P1,2∨P2,1)⇒B1,1)
3. 用逆否等价 → R8 : (¬B1,1 ⇒ ¬(P1,2∨P2,1))
4. 对 R8 与感知 R4（即 ¬B1,1）用 Modus Ponens → R9 : ¬(P1,2∨P2,1)
5. 用德摩根 → R10 : ¬P1,2 ∧ ¬P2,1     // [1,2] 与 [2,1] 都无坑
```

第 3 章任何搜索算法都能用来找这样一串证明步骤——只需把**证明问题**定义为：初始状态 = 初始 KB；动作 = 所有可应用于匹配前提的句子的推断规则；结果 = 把规则下半部的句子加入；目标 = 包含待证句子的状态。**搜索证明**是枚举模型之外的另一条路。

**单调性**（monotonicity）：对任意句子 α、β，若 `KB |= α`，则 `KB ∧ β |= α`。即向 KB 加入信息只会**增加**后承集合，不会使已有结论失效。例：再加入"全世界恰好八个坑"的断言，可能帮智能体推出更多结论，但**不能推翻**"[1,2] 无坑"这类已得结论。单调性意味着推断规则只要前提在 KB 中出现就可应用——结论必然成立，与 KB 里还有什么无关。

### 7.5.2 归结证明（Proof by Resolution）

前述推断规则是可靠的，但用它们的推断算法的**完备性**尚未讨论。搜索算法（如迭代加深搜索）是完备的——能找到任何可达目标；但若可用规则不足，目标就不可达（不存在只用这些规则的证明）。例：去掉双向消除规则，上一节的证明就走不通。

本节引入**一条**推断规则——**归结**（resolution）——它与任何完备搜索算法结合都能给出完备的推断算法。

**单元归结**（unit resolution）：设 `ℓ₁ ∨ ⋯ ∨ ℓₖ` 与 `m`，其中 `ℓᵢ` 与 `m` 是**互补文字**（complementary literals，即一个是另一个的否定），则得新子句 `ℓ₁ ∨ ⋯ ∨ ℓᵢ₋₁ ∨ ℓᵢ₊₁ ∨ ⋯ ∨ ℓₖ`。**子句**（clause）是文字的析取；单个文字可看作一个文字的析取，即**单元子句**（unit clause）。

**一般归结**：

```
ℓ₁ ∨ ⋯ ∨ ℓₖ ,  m₁ ∨ ⋯ ∨ mₙ
─────────────────────────────
ℓ₁ ∨ ⋯ ∨ ℓᵢ₋₁ ∨ ℓᵢ₊₁ ∨ ⋯ ∨ ℓₖ ∨ m₁ ∨ ⋯ ∨ mⱼ₋₁ ∨ mⱼ₊₁ ∨ ⋯ ∨ mₙ
```

即取两个子句、消去那对互补文字、其余文字全部保留。例：

```
P1,1 ∨ P3,1 ,  ¬P1,1 ∨ ¬P2,2
────────────────────────────
        P3,1 ∨ ¬P2,2
```

**一次只能归结一对互补文字**。例：可由 `P ∨ ¬Q ∨ R` 与 `¬P ∨ Q` 得 `¬Q ∨ Q ∨ R`，但不能同时对 `P` 和 `Q` 归结去推 `R`。

**因子提取**（factoring）：结果子句中每个文字只保留一份。例：`(A∨B)` 与 `(A∨¬B)` 归结得 `(A∨A)`，经因子提取化为 `A`。

**可靠性**直观可证：设 `ℓᵢ` 与 `mⱼ` 互补。若 `ℓᵢ` 真则 `mⱼ` 假，故去掉 `mⱼ` 后 `m₁∨⋯∨mⱼ₋₁∨mⱼ₊₁∨⋯∨mₙ` 必真（因为整句 `m₁∨⋯∨mₙ` 已知为真）；若 `ℓᵢ` 假则去掉 `ℓᵢ` 后 `ℓ₁∨⋯∨ℓᵢ₋₁∨ℓᵢ₊₁∨⋯∨ℓₖ` 必真——`ℓᵢ` 非真即假，两种结论必有一种成立。

**合取范式**（conjunctive normal form, CNF）：`Clause₁ ∧ ⋯ ∧ Clauseₙ`，每个子句是文字的析取。任意句子转 CNF 四步（以 `B₁,₁ ⇔ (P₁,₂ ∨ P₂,₁)` 为例）：

```
1. 消除 ⇔：(B1,1⇒(P1,2∨P2,1)) ∧ ((P1,2∨P2,1)⇒B1,1)
2. 消除 ⇒（α⇒β 换成 ¬α∨β）：(¬B1,1∨P1,2∨P2,1) ∧ (¬(P1,2∨P2,1)∨B1,1)
3. ¬ 只出现在文字中（双重否定、德摩根把 ¬ 向内推）：
   (¬B1,1∨P1,2∨P2,1) ∧ ((¬P1,2∧¬P2,1)∨B1,1)
4. 分配律：(¬B1,1∨P1,2∨P2,1) ∧ (¬P1,2∨B1,1) ∧ (¬P2,1∨B1,1)
```

**归结算法** `PL-RESOLUTION(KB, α)`（Figure 7.13）基于反证：为证 `KB |= α`，证 `(KB ∧ ¬α)` 不可满足，即推出矛盾。

```
clauses ← (KB ∧ ¬α) 的 CNF 子句集；new ← {}
while true do
  for each 子句对 (Ci, Cj) in clauses do
     resolvents ← PL-RESOLVE(Ci, Cj)
     if resolvents 含空子句 then return true      // 空子句 = False
     new ← new ∪ resolvents
  if new ⊆ clauses then return false
  clauses ← clauses ∪ new
```

空子句（无析取项的析取）等价于 False，且**只能**由两个矛盾单元子句（如 `P` 与 `¬P`）归结产生。含互补文字对的子句（如 `B1,1 ∨ ¬B1,1 ∨ P1,2` ≡ True）可直接丢弃。

**归结的完备性**：引入子句集 `S` 的**归结闭包** `RC(S)`（反复归结到不再产生新子句）。定理：`S` 不可满足 **iff** `RC(S)` 含空子句。证明走逆否——若不含空子句，则构造出 `S` 的模型（对 `P₁,…,Pₖ` 依次赋值：若某子句含 `¬Pᵢ` 且其余文字在已选赋值下全假则 `Pᵢ` 取假，否则取真）。

### 7.5.3 霍恩子句与确定子句（Horn Clauses and Definite Clauses）

**霍恩子句**（Horn clause）：至多含一个正文字的子句。例：`¬A ∨ ¬B ∨ C` 是霍恩子句（正文字只有 `C`），可改写为确定子句形式 `A ∧ B ⇒ C`。

```
HornClauseForm → DefiniteClauseForm | GoalClauseForm
DefiniteClauseForm → Fact | (Symbol₁∧⋯∧Symbolₗ)⇒Symbol
GoalClauseForm   → (Symbol₁∧⋯∧Symbolₗ)⇒False
```

- **确定子句**（definite clause）：恰含一个正文字。可写成"前提为正文字合取、结论为单个正文字"的蕴含。例：`(¬L1,1 ∨ ¬Breeze ∨ B1,1)` 即 `(L1,1 ∧ Breeze) ⇒ B1,1`——"若智能体在 `[1,1]` 且感知到微风，则 `[1,1]` 有微风"。蕴含形式中前提称**体**（body），结论称**头**（head）。
- 单个正文字的句子是**事实**（fact），可写作 `True ⇒ L1,1`，但通常直接写 `L1,1`。
- **目标子句**（goal clause）：无正文字的子句。霍恩子句在归结下封闭（两个霍恩子句归结仍是霍恩子句）。
- **k-CNF**：每个子句至多 `k` 个文字的 CNF。

确定子句知识库之所以有趣，有三条理由：

1. 每条确定子句都能写成"正文字合取 ⇒ 单个正文字"的蕴含；
2. 可用**前向链**（forward-chaining）与**后向链**（backward-chaining）推断，步骤自然、易被人跟随——这正是逻辑编程（第 9 章）的基础；
3. 判定霍恩子句的后承可在**与知识库规模成线性**的时间内完成。

### 7.5.4 前向链与后向链

**前向链** `PL-FC-ENTAILS?(KB, q)`（Figure 7.15）判定单个命题符号查询 `q` 是否被确定子句 KB 后承。它从 KB 中已知事实出发：若某蕴含的所有前提都已知为真，则其结论入"议程"队列，如此反复直到不动点。

```
queue ← KB 中已知为真的符号队列
while queue 非空 do
  p ← POP(queue)
  if p = q then return true
  if inferred[p] = false then
     inferred[p] ← true
     for each 前提含 p 的子句 c in KB do
        decrement count[c]
        if count[c] = 0 then add c.CONCLUSION to queue
return false
```

- `count[c]` 记录子句 `c` 前提中尚未证明的符号数；某符号被处理后所有含它的子句计数减一，归零即前提全知、结论入队。
- `inferred` 表防止重复处理，既避免冗余也防止 `P⇒Q`、`Q⇒P` 这类死循环。高效实现**线性时间**。

**后向链**是**目标导向推理**（goal-directed reasoning）的一种形式，适用于"我现在该做什么？""我的钥匙在哪？"这类具体问题。它从查询 `q` 出发，反向查找以 `q` 为结论的蕴含，若某蕴含的所有前提都能被证明，则 `q` 为真。对 Figure 7.16 中的查询 `Q`，它沿 AND–OR 图向下回溯，直到作为证明基础的已知事实 `A`、`B`。该算法本质上与 Figure 4.11 的 `AND-OR-GRAPH-SEARCH` 相同；高效实现同样线性时间。后向链只触及相关事实，代价常常**远低于**知识库规模的线性。

## 7.6 有效的命题模型检查（Effective Propositional Model Checking）

本节描述两族高效的通用命题推断算法：**回溯搜索**与**局部爬山搜索**。它们属于命题逻辑的"技术"部分，首次阅读可略读。算法都针对可满足性（SAT）问题（由 7.5 节，测后承 `α |= β` 可化为测 `α ∧ ¬β` 的不可满足性）。它们与第 6.3 节的回溯、第 6.4 节的局部搜索极为相似——因为 SAT 求解与 CSP 求解本质相通——但其自身极其重要：太多实际问题归结为 SAT。

### 7.6.1 一种完备的回溯算法

**Davis–Putnam 算法**得名于 Davis 与 Putnam (1960) 的开创性论文，但实际版本出自 Davis、Logemann、Loveland (1962)，故按四人首字母称 **DPLL**。输入为 CNF 句子（子句集），本质是**递归、深度优先**地枚举可能模型，相对 `TT-ENTAILS?` 有三项改进：

1. **提前终止**（early termination）：部分模型下即可判定句子必真或必假。任一文字为真则子句为真（即使其他文字未赋值），故整句可能已被判真；同理，某子句每个文字都假则子句为假、整句为假。例：`(A∨B)∧(A∨C)` 只要 `A` 真就为真，与 `B`、`C` 无关。提前终止避免检查搜索空间中的整棵子树。
2. **纯符号启发式**（pure symbol heuristic）：**纯符号**在所有子句中都只以同一种"符号"出现。例：`(A∨¬B)`、`(¬B∨¬C)`、`(C∨A)` 中 `A` 纯（只出现正文字）、`B` 纯（只出现负文字）、`C` 不纯。若句子有模型，则存在一个使纯符号的字面量为真的模型——因为这样赋值**永远不会**使子句为假。判纯度时可忽略在当前模型下已知为真的子句。
3. **单元子句启发式**（unit clause heuristic）：当某子句只剩一个未赋值文字时，该文字必须取使子句为真的值——**强制赋值**，无需分支。

`DPLL-SATISFIABLE?(s)`（Figure 7.17）先试纯符号、再试单元子句，二者都不存在时才按符号顺序分支（先试 `true` 再试 `false`）。

现代求解器在此之上还有三项增强（与 CSP 中的对应技术同源）：

| 增强 | 说明 |
|---|---|
| **分量分析**（component analysis） | 赋值后子句集可能分裂为互不共享未赋值变量的不相交**分量**，分别求解大幅加速 |
| **变量与值排序** | 度启发式：选在所有剩余子句中出现最频繁的变量 |
| **智能回溯**（intelligent backtracking） | 非时序回溯（no-good learning）跳过导致失败的赋值组合——许多顺序回溯数小时解不出的问题几秒可解 |

配合这些增强，现代求解器能处理**数千万变量**的问题，已彻底改变硬件验证与安全协议验证等原本依赖繁琐手工证明的领域。

### 7.6.2 局部搜索算法

`HILL-CLIMBING`（p.111）、`SIMULATED-ANNEALING`（p.115）等局部搜索算法可直接用于可满足性问题，只要选对评价函数：目标是找满足所有子句的赋值，**统计不满足子句数**的评价函数即可胜任——这正是 CSP 中 `MIN-CONFLICTS`（p.198）所用的度量。

**WALKSAT**（Figure 7.18）：从随机赋值出发，每步要么以概率 `p`（典型值约 `0.5`）随机翻转某子句中随机一个符号（**随机游走**），要么翻转能使满足子句数最大化的符号（**贪心**）。`max_flips` 次内找到满足模型则返回，否则报失败。

- 若 `max_flips` 无穷且句子不可满足，算法**永不终止**。故 WALKSAT 最适用于**预期解存在**的情形（第 3、6 章的问题通常有解）。
- WALKSAT **不能可靠检测不可满足性**——而判定后承正需要这一点。智能体不能说"我证明了这个方格安全"，只能说"我想了一小时，想不出一个它不安全的可能世界"。这是良好的**经验指标**，但**绝不是证明**。

### 7.6.3 随机 SAT 问题的地形

有些 SAT 问题比另一些难。易问题任何老算法都能解，但既然 SAT 是 NP-complete，至少某些实例必然需要指数时间。第 6 章已有惊人发现：n-queens 问题——原以为对回溯相当棘手——对局部搜索（如 min-conflicts）却**出奇地容易**，因为解在赋值空间中分布极密，任何初始赋值附近都有解。这类问题**约束不足**（underconstrained）。

对 CNF 句子，约束不足指约束变量的子句相对较少。例：随机生成的五符号五子句 3-CNF：

```
(¬D∨¬B∨C) ∧ (B∨¬A∨¬C) ∧ (¬C∨¬B∨E) ∧ (E∨¬D∨B) ∧ (B∨E∨¬C)
```

32 个可能赋值中有 16 个是模型，平均只需**两次**随机猜测即可命中——这是易的 SAT 问题，大多数约束不足问题皆然。

**阈值效应**（thresholding effect，Figure 7.19）：对 `n = 50` 符号的随机 3-CNF，可满足概率随子句/符号比 `m/n` 变化：

- `m/n` 小（约束不足）：几乎总是可满足；
- `m/n` 大（**过约束**，overconstrained）：几乎总是不可满足；
- 阈值附近（约 `4.3`）：最困难。

难问题也常常就在阈值处：`n = 50` 时阈值比 `4.3` 的问题比 `3.3` 的问题**难约 20 倍**。约束不足最易解（猜解太容易）；过约束虽不如约束不足易，但仍远比阈值处的问题容易。这种阈值效应在 SAT 及其他 NP-hard 问题中都很常见。

## 7.7 基于命题逻辑的智能体（Agents Based on Propositional Logic）

本节把前面所学合起来，构造使用命题逻辑的 wumpus 世界智能体：先让智能体根据感知历史尽可能推断世界状态（需要写出动作效果的**完整逻辑模型**）；再展示逻辑推断如何被用于 wumpus 世界；然后展示智能体如何**高效**跟踪世界而不必每次推断都回到感知历史；最后展示智能体如何用逻辑推断构造**保证达成目标**的计划（前提是环境完全可观测或无传感）。

### 7.7.1 世界的当前状态

7.4.3 节已开始收集公理：起点无坑（`¬P1,1`）、无 wumpus（`¬W1,1`）；每格"有微风 iff 相邻有坑"、"有恶臭 iff 相邻有 wumpus"，即大批形如 `B1,1 ⇔ (P1,2 ∨ P2,1)`、`S1,1 ⇔ (W1,2 ∨ W2,1)` 的句子。**恰好一个 wumpus**分两部分表达：

```
至少一个：  W1,1 ∨ W1,2 ∨ ⋯ ∨ W4,3 ∨ W4,4
至多一个：  对每对位置 (i,j),(k,l) 加  ¬W(i,j) ∨ ¬W(k,l)
```

**感知与时间步**：能否用单个命题 `Stench` 表示"智能体感知到恶臭"？不能——若上一时刻无恶臭则已断言 `¬Stench`，新断言会直接矛盾。解决办法：**感知只断言当前时刻**。若时间步为 4，则加入 `Stench₄` 而非 `Stench`，巧妙避开与 `¬Stench₃` 的矛盾。微风、碰撞、闪光、尖叫同理。

把命题与时间步关联的做法可推广到任何随时间变化的世界方面。例：初始 KB 含 `L⁰₁,₁`（时刻 0 智能体在 `[1,1]`）、`FacingEast₀`、`HaveArrow₀`、`WumpusAlive₀`。**流**（fluent，源自拉丁语 *fluens*，流动）指世界中随时间变化的方面，是"状态变量"的同义词（此处用"流"强调时间维度）。

**动作发生**（action occurrence）也需要命题符号，同样以时间索引：`Forward₀` 表示时刻 0 执行 `Forward`。约定：**先发生该时刻的感知，再执行该时刻的动作，然后转移到下一时刻**。

**效果公理**（effect axiom）规定动作在下一时刻的结果。例：

```
L⁰₁,₁ ∧ FacingEast₀ ∧ Forward₀ ⇒ (L¹₂,₁ ∧ ¬L¹₁,₁)          (7.1)
```

即时刻 0 在 `[1,1]` 面朝东并前进，结果是时刻 1 在 `[2,1]` 且不再在 `[1,1]`。对 16 格 × 4 朝向 × 每个时间步都需要一条，其余动作（`Grab`、`Shoot`、`Climb`、`TurnLeft`、`TurnRight`）同理。

> **帧问题**（frame problem）：若只写效果公理，`ASK(KB, HaveArrow₁)` 的答案是 false——智能体既证不出仍有箭，也证不出没有箭。信息丢失了，因为效果公理**没有说明动作之后什么保持不变**。逐条加**帧公理**（frame axiom）显式断言所有保持不变的命题（如 `Forwardₜ ⇒ (HaveArrowₜ ⇔ HaveArrowₜ₊₁)`）可行，但命题太多——这正是帧问题。

**后继状态公理**（successor-state axiom）是更好的方案。一般形式：

```
Fₜ₊₁ ⇔ ActionCausesFₜ ∨ (Fₜ ∧ ¬ActionCausesNotFₜ)
```

即 `F` 在 `t+1` 为真，当且仅当**要么** `t` 时刻的动作使 `F` 在 `t+1` 为真，**要么** `F` 在 `t` 已为真且该动作不会使其在 `t+1` 为假。最简单的例子是 `HaveArrow`（无装箭动作，`ActionCausesFₜ` 项消失）：

```
HaveArrowₜ₊₁ ⇔ (HaveArrowₜ ∧ ¬Shootₜ)                    (7.2)
```

位置流的后继状态公理更复杂。`L₍₁,₁₎` 在 `t+1` 为真，当且仅当 (a) 智能体从 `[1,2]` 面朝南、或从 `[2,1]` 面朝西前进；或 (b) `L₍₁,₁₎` 在 `t` 已为真且动作未引起移动（非 `Forward`，或前进撞墙）：

```
L₍₁,₁₎ᵗ⁺¹ ⇔ (L₍₁,₁₎ᵗ ∧ (¬Forwardₜ ∨ Bumpₜ₊₁))
          ∨ (L₍₁,₂₎ᵗ ∧ (FacingSouthₜ ∧ Forwardₜ))        (7.3)
          ∨ (L₍₂,₁₎ᵗ ∧ (FacingWestₜ ∧ Forwardₜ))
```

给定一组完整的后继状态公理与本节初列出的其他公理，智能体就能 `ASK` 并回答任何关于当前世界状态的可回答问题。例：7.2 节初始感知与动作序列为

```
¬Stench₀∧¬Breeze₀∧¬Glitter₀∧¬Bump₀∧¬Scream₀ ; Forward₀
¬Stench₁∧Breeze₁∧¬Glitter₁∧¬Bump₁∧¬Scream₁ ; TurnRight₁
⋯ TurnRight₂ ; Forward₃ ; TurnRight₄ ; Forward₅
Stench₆∧¬Breeze₆∧¬Glitter₆∧¬Bump₆∧¬Scream₆
```

此时 `ASK(KB, L⁶₁,₂) = true`（智能体知道自己在哪），`ASK(KB, W₁,₃) = true` 且 `ASK(KB, P₃,₁) = true`（找到了 wumpus 与一个坑）。

**OK 谓词**：智能体最关心某方格是否可进入——即无坑且无活 wumpus。加入公理：

```
OKᵗₓ,ᵧ ⇔ ¬Pₓ,ᵧ ∧ ¬(Wₓ,ᵧ ∧ WumpusAliveₜ)
```

于是 `ASK(KB, OK⁶₂,₂) = true`——`[2,2]` 可进入。配合 DPLL 这类可靠完备的推断算法，智能体能回答任何"哪些方格 OK"的问题，且对中小规模 wumpus 世界**只需几毫秒**。

> **资格问题**（qualification problem）：解决帧问题（表示的与推断的）是巨大进步，但一个顽固问题仍在：必须确认动作所有必要前提都成立，它才会产生预期效果。我们说 `Forward` 使智能体前进（除非有墙），但还有许多其他异常可能使动作失败：绊倒、心脏病发作、被巨蝠带走……逐一列出所有例外即**资格问题**。逻辑内**没有完备解**；系统设计者必须凭良好判断决定模型要多细、略过哪些细节。第 12 章将看到，概率论允许我们**概括**所有例外而不必逐一点名。

### 7.7.2 混合智能体

把"推断世界状态各方面"的能力与条件–动作规则（2.4.2 节）及第 3–4 章的问题求解算法相当直接地结合起来，可得到 wumpus 世界的**混合智能体**（hybrid agent）。

`HYBRID-WUMPUS-AGENT(percept)`（Figure 7.20）同时维护知识库与当前计划：

```
persistent: KB（初始为不含时间的"wumpus 物理"公理）, t（初值 0）, plan（初始为空）
TELL(KB, MAKE-PERCEPT-SENTENCE(percept, t))
TELL KB 时刻 t 的时间相关"物理"句子（后继状态公理等）
safe ← { [x,y] : ASK(KB, OKᵗₓ,ᵧ) = true }

if ASK(KB, Glitterₜ) = true then
   plan ← [Grab] + PLAN-ROUTE(current, {[1,1]}, safe) + [Climb]
if plan 为空 then
   unvisited ← { [x,y] : ASK(KB, Lᵗ'ₓ,ᵧ) = false 对所有 t' ≤ t }
   plan ← PLAN-ROUTE(current, unvisited ∩ safe, safe)
if plan 为空且 ASK(KB, HaveArrowₜ) = true then
   possible_wumpus ← { [x,y] : ASK(KB, ¬Wₓ,ᵧ) = false }
   plan ← PLAN-SHOT(current, possible_wumpus, safe)
if plan 为空 then                                  // 别无选择，只能冒险
   not_unsafe ← { [x,y] : ASK(KB, ¬OKᵗₓ,ᵧ) = false }
   plan ← PLAN-ROUTE(current, unvisited ∩ not_unsafe, safe)
if plan 为空 then
   plan ← PLAN-ROUTE(current, {[1,1]}, safe) + [Climb]

action ← POP(plan); TELL(KB, MAKE-ACTION-SENTENCE(action, t)); t ← t + 1; return action
```

**目标优先级递减**：先找金子（`Grab` → 回 `[1,1]` → `Climb`）；否则规划到最近的、安全且未访问的方格；再否则若有箭，射击可能的 wumpus（可能释放被金子占用的方格）；再否则冒险走"不（确定不安全）"的方格；最后退路是回起点爬出。**计划一旦定出，后续各步不再咨询 KB**——除非计划失败（如前进撞墙），此时重新规划。

### 7.7.3 逻辑状态估计

混合智能体每步都从 KB 推断，但 KB 随时间增长，推断代价上升。能否只维护一个描述**所有与感知历史相容的可能状态**的句子？

**信念状态**（belief state）是物理状态的集合。例：Figure 7.21 中，时刻 1 的信念状态是"wumpus 存活、智能体在 `[2,1]`、该格有微风、且 `[3,1]` 或 `[2,2]`（或两者）有坑"的所有状态之集合（图中虚线阴影区域）。

**精确信念状态作为逻辑公式维护起来并不容易**。若时刻 `t` 有 `n` 个流符号，则有 `2ⁿ` 个可能状态（赋值）；信念状态集合是物理状态集的**幂集**——`2ⁿ` 个物理状态对应 `2^(2ⁿ)` 个信念状态。即使用最紧凑的编码（每个信念状态一个唯一二进制数），标注当前信念状态也需要 `log₂(2^(2ⁿ)) = 2ⁿ` 比特。即：**精确状态估计可能需要规模对符号数呈指数的逻辑公式**。

一种常见且自然的**近似**方案：把信念状态表示为**文字的合取**，即 **1-CNF** 公式。做法：给定 `t−1` 时刻的信念状态，智能体程序对每个符号 `Xₜ`（以及每个真值未知的非时间符号）分别尝试证明 `Xₜ` 与 `¬Xₜ`；**可证的文字之合取**成为新的信念状态，旧的丢弃。

> 关键：这种做法会**随时间丢失信息**。例：若式 (7.4) 是真实信念状态，则 `P₃,₁` 与 `P₂,₂` 各自都不可证，都不会出现在 1-CNF 信念状态中。
> 但另一方面，因为 1-CNF 信念状态中每个文字都由前一信念状态证出、而初始信念状态是真断言，所以**整个 1-CNF 信念状态必为真**。即它所表示的可能状态集合**包含所有实际上给定完整感知历史确实可能的状态**。

如图 7.21，1-CNF 信念状态 acting 为精确信念状态的一个简单外封套，即**保守近似**（conservative approximation）。这种"用简单可表示的保守近似包裹复杂集合"的思想，是 AI 许多领域的反复出现的主题。

### 7.7.4 用命题推断制定计划

Figure 7.20 的智能体用逻辑推断确定哪些方格安全，但用 `A*` 搜索制定计划。本节展示**用逻辑推断制定计划**。基本思想：

1. 构造一个句子，包含：(a) `Init₀`，关于初始状态的一组断言；(b) `Transition₁,…,Transitionₜ`，各时刻所有可能动作的后继状态公理（`t` 为某最大时间）；(c) 断言目标在时刻 `t` 达成：`HaveGoldₜ ∧ ClimbedOutₜ`。
2. 把整句交给 SAT 求解器。若找到满足模型，则目标可达；若不可满足，则问题无解。
3. 从模型中提取表示动作且被赋值为真的变量，它们合起来就是达成目标的计划。

**`SATPLAN(init, transition, goal, T_max)`**（Figure 7.22）实现上述思想，只加一处转折：智能体不知达成目标需几步，故在 `0…T_max` 上逐个尝试步数 `t`，**保证找到最短计划**（若存在）。由于搜索方式，它**不能用于部分可观测环境**——会直接把不可观测变量设成造出解所需的值。

关键在于 KB 构造，而**后承（`ASK` 所测）与可满足性之间有重大差别**，`SATPLAN` 会暴露三类缺失的知识：

- **位置唯一性缺失**：初始 `L⁰₁,₁`、目标 `L¹₂,₁`。`ASK` 在断言 `Forward₀` 时证得出 `L¹₂,₁`，断言 `Shoot₀` 时证不出。但 `SATPLAN` **同时**找到 `[Forward₀]` 与 `[Shoot₀]`——检查模型发现它含 `L⁰₂,₁`，即"时刻 0 就在 `[2,1]` 然后射击"。我们说过智能体时刻 0 在 `[1,1]`，但**没告诉它不能同时在两处**！对后承 `L⁰₂,₁` 未知、不能用于证明；对可满足性 `L⁰₂,₁` 未知、可被设成任意值。修复：断言"每刻智能体恰在一个位置"，或断言除 `[1,1]` 外所有位置的 `¬L⁰ₓ,ᵧ`（后继状态公理会处理后续时刻）。朝向同理。
- **不可能动作**：如无箭却射击。后继状态公理正确预测"前提不满足时执行该动作什么都不会发生"，但**没说该动作不能被执行**。修复：加**前提公理**（precondition axiom），如 `Shootₜ ⇒ HaveArrowₜ`。（加了前提公理后，后继状态公理中就不必再写前提。）
- **同时多动作**：如 `Forward₀` 与 `Shoot₀` 同真。修复：加**动作互斥公理**（action exclusion axiom）——对每对动作 `Aᵗᵢ`、`Aᵗⱼ` 加 `¬Aᵗᵢ ∨ ¬Aᵗⱼ`。但"同时前进与射击"并不难做到，只需对**真正互相干扰**的动作对加互斥公理，就能允许计划含多个同时动作；由于 `SATPLAN` 找最短合法计划，它自然会利用这一能力。

**总结**：这组公理（初始状态、目标、后继状态、前提、动作互斥）是**充分的**——不再有任何伪"解"，满足该命题句子的任何模型都是原问题的合法计划。现代 SAT 求解技术使该方法相当实用——DPLL 式求解器轻松生成 Figure 7.2 实例的解。

> 本节描述的是**声明式**智能体构建：智能体通过"在 KB 中斷言句子 + 做逻辑推断"工作。其弱点藏在"对每个时刻 `t`""对每个方格 `[x,y]`"这类短语中——对任何实用智能体，这些短语必须由**自动生成**一般句子模式实例的代码实现。对一个合理规模的 wumpus 世界（如 `100×100` 棋盘、1000 时间步），KB 可能有**数千万到数亿**句子，既不实用，也暴露一个更深的问题：我们知道 wumpus 世界的"物理"在所有方格与所有时刻**运作方式相同**，却**无法用命题逻辑的语言直接表达**这一点。解决之道需要更富表达力的语言——**一阶逻辑**（第 8 章）正是如此：任意规模与时长的 wumpus 世界大约**十句**逻辑即可描述，而非一千万或一万亿句。

## 小结

1. **智能体需要关于世界的知识**才能做出好决策；知识以知识表示语言中的句子形式存于知识库，通过 `TELL`（加入）与 `ASK`（查询）使用。基于知识的智能体可在**知识级**被描述，独立于实现级。
2. **逻辑**提供语法（良形成句子的规则）与语义（句子在每个模型中的真值）。**后承**（`KB |= α`）指 α 在所有 KB 为真的模型中皆真；推断算法只推出被后承的句子则**可靠**，能推出所有被后承的句子则**完备**。
3. **命题逻辑**是最简单的逻辑。后承可用**模型检查**（枚举 `2ⁿ` 个模型，`O(2ⁿ)` 时间）判定，但命题后承是 co-NP-complete。
4. **定理证明**直接对句子应用推断规则：Modus Ponens、等价规则、**归结**（对 CNF 完备）、**前向链/后向链**（对霍恩子句自然且线性）。**单调性**保证加信息只增后承。
5. **高效模型检查**：`DPLL`（回溯 + 提前终止 + 纯符号 + 单元子句 + 分量分析/智能回溯）可解数千万变量问题；`WALKSAT`（局部搜索）快但**不完备**，不能可靠检测不可满足性。随机 SAT 呈**阈值效应**：子句/符号比约 `4.3` 时最难。
6. **逻辑状态估计**：维护描述所有与感知历史相容状态的句子；精确信念状态规模可能**指数级**（`2ⁿ` 比特），实用中用 **1-CNF 保守近似**。
7. **帧问题**由**后继状态公理**解决；残留的**资格问题**在逻辑内无完备解，留到第 12 章用概率论概括例外。
8. **SATPLAN** 用 SAT 求解制定计划，需补三类公理：**前提公理**、**动作互斥公理**、以及保证对象唯一性的公理（如"智能体每刻恰在一处"）。
9. **命题逻辑无法扩展到无界规模的环境**——它缺乏简洁处理时间、空间与对象间普遍关系模式的能力。这需要第 8 章的**一阶逻辑**：任意规模与时长的 wumpus 世界约**十句**即可描述，而非一千万或一万亿句。
