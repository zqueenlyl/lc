## 0. 本章要解决的问题

第 8 章给了我们一阶逻辑这门**语言**，本章给出**有效过程**来回答用这门语言提出的问题。核心张力只有一条：一阶逻辑表达力强，但模型空间是**无穷**的。

原书 p.280 的路线图给出三条路线：

| 路线 | 思路 | 代价 |
|---|---|---|
| **命题化**（9.1） | 把一阶知识库转成命题逻辑，用第 7 章的算法 | 可能生成天文数字的实例 |

## 9.1 命题推断与一阶推断（Propositional vs. First-Order Inference）

最朴素的一阶推断：把一阶知识库转成命题逻辑。第一步是**消去全称量词**。设知识库含"所有贪婪的国王都是邪恶的"：

```
∀ x King(x) ∧ Greedy(x) ⇒ Evil(x)
```

从它可推断出下面任意一条（分别对应置换 `{x/John}`、`{x/Richard}`、`{x/Father(John)}`）：

```
King(John)    ∧ Greedy(John)    ⇒ Evil(John)
King(Richard) ∧ Greedy(Richard) ⇒ Evil(Richard)
King(Father(John)) ∧ Greedy(Father(John)) ⇒ Evil(Father(John))
```

### 全称实例化与存在实例化

令 `SUBST(θ, α)` 表示把置换 θ 作用到句子 α 上：

```
∀ v α                                    ∃ v α
————————————————  （g 为任意基项）        ————————————————  （k 为 KB 中未出现过的新常量）
SUBST({v/g}, α)                          SUBST({v/k}, α)
```

- **全称实例化（Universal Instantiation，UI）**：对全称量化变量替换**基项**（ground term，不含变量的项），所得句子都可推断。
- **存在实例化（Existential Instantiation）**：把存在量化变量替换为一个**全新常量** k。由 `∃ x Crown(x) ∧ OnHead(x, John)` 可推断 `Crown(C1) ∧ OnHead(C1, John)`，前提是 `C1` 未在别处出现。

> **直觉上**：存在句只是说"存在某个满足条件的对象"，存在实例化不过是**给它起个名字**，这名字显然不能已被别人占用。原书用数学举例：我们发现有个比 2.71828 略大的数满足 `d(x^y)/dy = x^y`，可命名为 `e`；命名为 `π`（已有对象）就错了。逻辑里这个新名字叫 **Skolem 常量（Skolem constant）**。

> ⚠️ **方向要点**：UI 可对同一条公理**反复**使用产生许多结论；存在实例化只需用**一次**，之后原存在句即可丢弃（有了 `Kill(Murderer, Victim)` 就不再需要 `∃ x Kill(x, Victim)`）。

### 9.1.1 归约到命题推断（Reduction to propositional inference）

正如存在句可替换为一个实例，全称句可替换为**所有可能实例的集合**。设知识库只有（式 9.1）`∀ x King(x) ∧ Greedy(x) ⇒ Evil(x)`、`King(John)`、`Greedy(John)`、`Brother(Richard, John)`，且论域只有 John 与 Richard：

1. 对首句用所有可能置换 `{x/John}`、`{x/Richard}` 做 UI，得 `King(John) ∧ Greedy(John) ⇒ Evil(John)` 与 `King(Richard) ∧ Greedy(Richard) ⇒ Evil(Richard)`；
2. 把基原子句子（如 `King(John)`）换成命题符号（如 `JohnIsKing`）；
3. 用第 7 章任意完备的命题算法推出 `JohnIsEvil`，它等价于 `Evil(John)`。

**问题**：当知识库含**函数符号**时，可能的基项置换集合是**无穷**的——提到 `Father` 就能构造出 `Father(Father(Father(John)))` 这样无穷多个嵌套项。

**出路：Herbrand 定理**（Herbrand, 1930）。若一个句子被原一阶知识库蕴含，则存在一个只用到命题化知识库**有限子集**的证明。由于任何这种子集都有最大的基项嵌套深度，可这样找它：先生成所有常量符号的实例（`Richard`、`John`），再生成深度为 1 的项（`Father(Richard)`、`Father(John)`），再深度为 2……直到能构造出命题证明。

| 性质 | 内容 |
|---|---|
| ✅ 完备 | 任何被蕴含的句子都能被证明——考虑到模型空间无穷，这是重大成就 |
| ⚠️ 不知何时停 | 在证明完成之前，我们**不知道**句子是否被蕴含 |
| ❌ 不可判定 | 若句子**未**被蕴含，我们无从判断：过程一直生成越来越深的嵌套项，我们分不清它是卡在死循环里，还是证明马上就要冒出来 |

这很像图灵机的停机问题。Turing（1936）与 Church（1936）用相当不同的方法各自证明了这种局面不可避免。**一阶逻辑的蕴含问题是半可判定的（semidecidable）**——存在算法对每个被蕴含的句子回答"是"，但不存在算法还能对每个未被蕴含的句子回答"否"。

## 9.2 合一与一阶推断（Unification and First-Order Inference）

命题化会生成大量**不必要的实例**。我们想要的是：只用"贪婪的国王是邪恶的"这一条规则，靠 `{x/John}` 就把查询 `Evil(x)` 解掉。

更一般地：若存在置换 θ 使蕴含前提的每个合取项都与知识库中已有句子变得相同，则可在施加 θ 后断言该蕴含的结论。现在改一下条件——我们不知道 `Greedy(John)`，只知道**所有人都贪婪**（式 9.2）`∀ y Greedy(y)`。我们仍希望推出 `Evil(John)`，因为 John 是国王（给定）且 John 贪婪（因为人人贪婪）。这时需要对**蕴含句中的变量**和**知识库中的变量**同时找置换：`{x/John, y/John}` 作用到 `King(x)`、`Greedy(x)` 与 `King(John)`、`Greedy(y)` 上会让它们相同。

### 广义假言推理（Generalized Modus Ponens）

对原子句 `pi`、`pi′` 与 `q`，若存在置换 θ 使 `SUBST(θ, pi′) = SUBST(θ, pi)` 对所有 i 成立：

```
p1′, p2′, …, pn′,   (p1 ∧ p2 ∧ … ∧ pn ⇒ q)
—————————————————————————————————————————————
SUBST(θ, q)
```

共 **n + 1 个前提**：n 个原子句 `pi′` 加上那一条蕴含式。本例：`p1′=King(John)`、`p1=King(x)`、`p2′=Greedy(y)`、`p2=Greedy(x)`、`θ={x/John, y/John}`、`q=Evil(x)`，结论 `Evil(John)`。

**可靠性（soundness）推导**（p.283，完整三步）：

1. 对任意句子 p（变量默认全称量化）与任意置换 θ，由全称实例化有 `p ⊨ SUBST(θ, p)`；对满足本规则条件的那个 θ 当然也成立。
2. 于是由 `p1′,…,pn′` 可推断 `SUBST(θ, p1′) ∧ … ∧ SUBST(θ, pn′)`；由 `p1 ∧ … ∧ pn ⇒ q` 可推断 `SUBST(θ, p1) ∧ … ∧ SUBST(θ, pn) ⇒ SUBST(θ, q)`。
3. θ 的定义保证 `SUBST(θ, pi′) = SUBST(θ, pi)`，故前一句**恰好**匹配后一句的前提，于是由假言推理（Modus Ponens）得到 `SUBST(θ, q)`。∎

它是假言推理的**提升（lifted）**版本——把假言推理从基（无变量）命题逻辑提升到一阶逻辑。**提升推断规则相对命题化的关键优势：只做那些为了让特定推断进行下去而必需的置换。**

### 9.2.1 合一（Unification）

寻找让不同逻辑表达式看起来相同的置换，叫**合一（unification）**。`UNIFY(p, q) = θ`，其中 `SUBST(θ, p) = SUBST(θ, q)`。设查询 `AskVars(Knows(John, x))`（John 认识谁？）：

```
UNIFY(Knows(John, x), Knows(John, Jane))     = {x/Jane}
UNIFY(Knows(John, x), Knows(y, Bill))        = {x/Bill, y/John}
UNIFY(Knows(John, x), Knows(y, Mother(y)))   = {y/John, x/Mother(John)}
UNIFY(Knows(John, x), Knows(x, Elizabeth))   = failure
```

最后一次失败，因为 x 不可能同时取值 John 与 Elizabeth。但 `Knows(x, Elizabeth)` 意思是"人人都认识 Elizabeth"，我们本应能推出 John 认识 Elizabeth——问题**仅仅**来自两个句子碰巧用了同一个变量名 x。

**标准化分离（standardizing apart）**：把要合一的两个句子之一的变量改名。把 `Knows(x, Elizabeth)` 中的 x 改名为 `x17`（含义不变），合一就成功：

```
UNIFY(Knows(John, x), Knows(x17, Elizabeth)) = {x/Elizabeth, x17/John}
```

**最一般合一子（MGU）**：合一子可能不止一个。`UNIFY(Knows(John, x), Knows(y, z))` 可返回 `{y/John, x/z}`（得 `Knows(John, z)`），也可返回 `{y/John, x/John, z/John}`（得 `Knows(John, John)`）。后者可由前者再施加 `{z/John}` 得到，故前者**更一般**——对变量取值限制更少。

> ⚠️ **T3 性质要点**：每一对可合一的表达式都有**唯一的最一般合一子**，唯一性是**在变量改名与置换意义下**的（`{x/John}` 与 `{y/John}` 等价，`{x/John, y/John}` 与 `{x/John, y/x}` 等价）。**不要写成"绝对唯一"。**

**合一算法**（Figure 9.1，p.285，原样保留）：

```
function UNIFY(x, y, θ = empty) returns a substitution to make x and y identical, or failure
    if θ = failure then return failure
    else if x = y then return θ
    else if VARIABLE?(x) then return UNIFY-VAR(x, y, θ)
    else if VARIABLE?(y) then return UNIFY-VAR(y, x, θ)
    else if COMPOUND?(x) and COMPOUND?(y) then
        return UNIFY(ARGS(x), ARGS(y), UNIFY(OP(x), OP(y), θ))
    else if LIST?(x) and LIST?(y) then
        return UNIFY(REST(x), REST(y), UNIFY(FIRST(x), FIRST(y), θ))
    else return failure

function UNIFY-VAR(var, x, θ) returns a substitution
    if {var/val} ∈ θ for some val then return UNIFY(val, x, θ)
    else if {x/val} ∈ θ for some val then return UNIFY(var, val, θ)
    else if OCCUR-CHECK?(var, x) then return failure
    else return add {var/x} to θ
```

过程很简单：递归地"肩并肩"同时遍历两个表达式，沿途构造合一子；一旦结构中两个对应点不匹配就失败。

**出现检查（occur check）**是唯一昂贵的一步：把变量与复杂项匹配时，必须检查该变量是否出现在该项内部；若出现则匹配失败，因为构造不出一致的合一子。例如 `S(x)` 无法与 `S(S(x))` 合一。

> ⚠️ **T7 逐字抄**：出现检查使整个算法的复杂度**关于被合一表达式的大小是二次的**。许多逻辑编程系统干脆省略出现检查，把避免由此产生不可靠推断的责任推给用户；另一些系统采用更复杂的**线性时间**合一算法。（Prolog 也省略了出现检查，见 9.4.2。）

### 9.2.2 存储与检索（Storage and retrieval）

`TELL`、`ASK`、`ASKVARS` 之下是更原始的 `STORE(s)`（存句子）与 `FETCH(q)`（返回所有使 q 与知识库中某句子合一的合一子）。最简单实现是把所有事实放在长列表里逐个合一——低效但可行。改进：

1. **索引（indexing）**：只与"有可能合一"的句子尝试合一（不必拿 `Knows(John, x)` 去试 `Brother(Richard, John)`）。
2. **谓词索引（predicate indexing）**：把 `Knows` 事实放一个桶、`Brother` 事实放另一个桶，桶用哈希表存。适用于**谓词符号多、每符号子句少**的情形；若某谓词子句极多（如税务局的 `Employs(x, y)`，可能百万雇主、千万雇员），就得扫描整个桶。
3. **多重索引键**：同一事实可存在多个索引键下（谓词 + 第 1 参数、谓词 + 第 2 参数……）。

给定要存储的 `Employs(IBM, Richard)`，所有与它合一的查询构成一个**包容格（subsumption lattice）**（Figure 9.2(a)）：`Employs(IBM, Richard)`（IBM 雇 Richard 吗？）、`Employs(x, Richard)`（谁雇 Richard？）、`Employs(IBM, y)`（IBM 雇谁？）、`Employs(x, y)`（谁雇谁？）。该格的性质：

- 任一节点的子节点，都由其父节点经**单次置换**得到；
- 任意两节点的"最高"共同后代，就是施加它们最一般合一子的结果；
- 含重复常量的句子（如 `Employs(John, John)`）对应略有不同的格（Figure 9.2(b)）；函数符号虽未画出，也可纳入格结构。

> ⚠️ **T7 逐字抄**：对参数很少的谓词，为格上**每个点**建索引划算（存储时多花一点，检索时快很多）。但对有 n 个参数的谓词，**格包含 O(2ⁿ) 个节点**；若允许函数符号，节点数关于待存句子中项的大小也是**指数级**的。因此必须把索引限制在查询中可能频繁用到的那些上，否则建索引浪费的时间会超过它省下的时间——可定死策略（只维护"谓词 + 单个参数"的键），也可学习自适应策略。对事实数以十亿计的商业数据库，这一问题一直是密集研究的对象。

## 9.3 前向链接（Forward Chaining）

### 9.3.1 一阶确定子句（First-order definite clauses）

**确定子句**是**恰好有一个正文字**的文字析取式：要么是一个原子句，要么是一条蕴含式——前件为正文字的合取，后件为单个正文字。不允许存在量词，全称量词**隐含**（看到 x 就意味着有隐含的 `∀ x`）。典型样子 `King(x) ∧ Greedy(x) ⇒ Evil(x)`；`King(John)` 与 `Greedy(y)` 也算确定子句，所以 `Greedy(y)` 读作"人人都贪婪"。

**犯罪问题**（贯穿 9.3–9.5）：法律规定美国人向敌对国家出售武器是犯罪。Nono 是美国的敌人，拥有一些导弹，其所有导弹都由（美国籍的）West 上校卖给它的。

```
(9.3)  American(x) ∧ Weapon(y) ∧ Sells(x, y, z) ∧ Hostile(z) ⇒ Criminal(x)
(9.4)  Owns(Nono, M1)                    (9.8)  Enemy(x, America) ⇒ Hostile(x)
(9.5)  Missile(M1)                       (9.9)  American(West)
(9.6)  Missile(x) ∧ Owns(Nono, x) ⇒ Sells(West, x, Nono)      (9.10) Enemy(Nono, America)
(9.7)  Missile(x) ⇒ Weapon(x)
```

"Nono 有一些导弹"原为 `∃ x Owns(Nono, x) ∧ Missile(x)`，经**存在实例化**引入新常量 `M1` 变成 (9.4)(9.5)。

> 这正好是一个 **Datalog** 知识库：Datalog 由**不含函数符号**的一阶确定子句构成，得名于它能表示关系数据库中的常见陈述。没有函数符号使推断容易得多。

### 9.3.2 一个简单的前向链接算法

Figure 9.3（p.288，原样保留）：

```
function FOL-FC-ASK(KB, α) returns a substitution or false
    inputs: KB, the knowledge base, a set of first-order definite clauses
            α, the query, an atomic sentence

    while true do
        new ← {}                      // The set of new sentences inferred on each iteration
        for each rule in KB do
            (p1 ∧ … ∧ pn ⇒ q) ← STANDARDIZE-VARIABLES(rule)
            for each θ such that SUBST(θ, p1 ∧ … ∧ pn) = SUBST(θ, p′1 ∧ … ∧ p′n)
                    for some p′1, …, p′n in KB
                q′ ← SUBST(θ, q)
                if q′ does not unify with some sentence already in KB or new then
                    add q′ to new
                φ ← UNIFY(q′, α)
                if φ is not failure then return φ
        if new = {} then return false
        add new to KB
```

从已知事实出发，触发所有前提被满足的规则，把结论加入已知事实，重复直到查询被回答（假定只要求一个答案）或不再有新事实产生。

> **注意**：一个事实如果只是已知事实的**重命名（renaming）**，就不算"新"——两句子除变量名外完全相同即互为重命名，如 `Likes(x, IceCream)` 与 `Likes(y, IceCream)`，含义相同（"人人都喜欢冰淇淋"）。`STANDARDIZE-VARIABLES` 把参数中所有变量替换为此前未用过的新变量。

**犯罪问题的两轮迭代**（可用蕴含句为 (9.3)(9.6)(9.7)(9.8)）：

| 轮次 | 发生的事 |
|---|---|
| 第 1 轮 | (9.3) 前提未满足；(9.6) 以 `{x/M1}` 满足，加入 `Sells(West, M1, Nono)`；(9.7) 以 `{x/M1}` 满足，加入 `Weapon(M1)`；(9.8) 以 `{x/Nono}` 满足，加入 `Hostile(Nono)` |
| 第 2 轮 | (9.3) 以 `{x/West, y/M1, z/Nono}` 满足，加入 `Criminal(West)` |

Figure 9.4 的证明树：底层是初始事实，中间层第 1 轮推断，顶层第 2 轮推断。此时不再可能有新推断——凡前向链接能推出的句子都已显式包含在知识库里，这样的知识库称为推断过程的**不动点（fixed point）**。一阶不动点与命题的不动点（p.231）相似，主要差别是**一阶不动点可以包含全称量化的原子句子**。

**分析**：

- **可靠**：每次推断都只是广义假言推理的一次应用。
- **对确定子句知识库完备**。对不含函数符号的 Datalog 知识库，证明相当容易：令 k 为任一谓词的最大元数，p 为谓词个数，n 为常量符号个数，则**至多 `p·nᵏ` 个不同的基事实**，算法在这许多轮之后必达不动点。
- 对**含函数符号**的一般确定子句，`FOL-FC-ASK` 可能生成无穷多新事实。若查询 q 确有答案，须援引 Herbrand 定理（p.282）确立算法会找到证明；若查询无答案，算法**在某些情况下可能不终止**。例如知识库含 Peano 公理 `NatNum(0)`、`∀ n NatNum(n) ⇒ NatNum(S(n))`，前向链接就会不断加入 `NatNum(S(0))`、`NatNum(S(S(0)))`、`NatNum(S(S(S(0))))`……这一般无法避免：**用确定子句做蕴含推断同样是半可判定的**。

### 9.3.3 高效的前向链接

Figure 9.3 为易懂而设计，不是为效率。三处低效：① 内层循环把**每条规则**与**每个事实**尝试匹配；② 每轮**重查所有规则**；③ 生成大量与**目标无关**的事实。

#### 规则与已知事实的匹配

用规则 `Missile(x) ⇒ Weapon(x)` 需找出所有与 `Missile(x)` 合一的事实，索引得当时**每个事实只需常数时间**。再看 `Missile(x) ∧ Owns(Nono, x) ⇒ Sells(West, x, Nono)`：可每个对象花常数时间找出 Nono 拥有的全部对象再逐个检查是否导弹；但若 **Nono 拥有的对象很多而导弹很少**，更好的做法是先找齐导弹再检查是否为 Nono 所有。这就是**合取项排序（conjunct ordering）**问题——求最优排序是 **NP-hard** 的，但有好的启发式（第 6 章的 **MRV** 会建议先找较少的那一类）。

模式匹配与约束满足联系紧密：每个合取项可视为对其中变量的一个约束。由此可把**每个有限域 CSP 表达为单条确定子句加若干基事实**——Figure 9.5 把澳大利亚地图着色重写为：

```
Diff(wa,nt) ∧ Diff(wa,sa) ∧ Diff(nt,q) ∧ Diff(nt,sa) ∧ Diff(q,nsw)
∧ Diff(q,sa) ∧ Diff(nsw,v) ∧ Diff(nsw,sa) ∧ Diff(v,sa) ⇒ Colorable()
```

只有该 CSP 有解时才能推出 `Colorable()`。由于一般 CSP 把 3-SAT 包含为特例，**把确定子句与一组事实相匹配是 NP-hard 的**。三条宽心理由：

| 理由 | 内容 |
|---|---|
| 看数据复杂度 | 现实知识库的大多数规则小而简单（像犯罪例子），不是大而复杂（像 Figure 9.5）。数据库领域通常假定规则大小与谓词元数由常数界定，只关心**数据复杂度（data complexity）**——推断复杂度作为基事实个数的函数。**前向链接的数据复杂度是多项式而非指数的** |
| 找易解子类 | 几乎每条 Datalog 子句都可视为定义一个 CSP，匹配是否易解恰取决于对应 CSP 是否易解。约束图构成**树**时 CSP 可**线性时间**求解；同样结论对规则匹配成立。去掉 Figure 9.5 中的南澳大利亚州，子句变成 `Diff(wa,nt) ∧ Diff(nt,q) ∧ Diff(q,nsw) ∧ Diff(nsw,v) ⇒ Colorable()`（对应 p.201 Figure 6.12 的简化 CSP），树状 CSP 算法可直接套用 |
| 消除冗余匹配 | 见下 |

#### 增量式前向链接

演示犯罪例子时我们略去了部分规则匹配（如第 2 轮 `Missile(x) ⇒ Weapon(x)` 又与 `Missile(M1)` 匹配了一次）。关键观察：**第 t 轮推断出的每个新事实，都必须至少用到了第 t−1 轮推断出的一个新事实**（否则该推断本可在第 t−1 轮做完）。于是第 t 轮只检查那些前提含某合取项 `pi`、且 `pi` 与第 t−1 轮新事实 `p′i` 可合一的规则；每轮生成的事实与 Figure 9.3 **完全相同**，但效率高得多。

再进一步：给定事实通常只触发知识库中**很小一部分**规则，反复构造"部分匹配"（有前提未满足）会造成大量冗余。犯罪例子里第 1 轮就已构造出 (9.3) 与 `American(West)` 之间的部分匹配，第 2 轮成功时却被丢弃重建；更好的做法是**保留并逐步补全**。

- **Rete 算法**第一个解决此问题：预处理规则集，构造**数据流网络**，每个节点是某规则前提中的一个文字。变量绑定在网络中流动，匹配不上某文字时被过滤掉；若规则中两个文字共享变量（如 `Sells(x,y,z) ∧ Hostile(z)`），来自各文字的绑定要经过**相等节点**过滤。到达 n 元文字节点的绑定可能要等其他变量绑定确立后才能继续。任意时刻 Rete 网络的状态**捕获了规则的全部部分匹配**，避免大量重算。（Rete 是拉丁语"网"，与 treaty 押韵。）
- Rete 网络及其改进是**产生式系统（production system）**的关键组件，后者是最早被广泛使用的前向链接系统之一。**XCON**（原称 R1；McDermott, 1982）含数千条规则，为 DEC 客户配置计算机部件，是专家系统领域最早的明确商业成功之一；同类技术已用通用语言 **OPS-5** 实现。产生式系统在**认知架构（cognitive architecture）**（人类推理模型）中也很流行，如 ACT（Anderson, 1983）与 SOAR（Laird et al., 1987）："工作记忆"模拟人类短时记忆，产生式属长时记忆；每周期把产生式与事实工作记忆匹配，条件满足的产生式可增删事实。与数据库相反，产生式系统往往**规则很多而事实较少**；经适当优化，系统可**在千万条规则规模下实时运行**。

#### 无关事实

前向链接基于已知事实做出**所有**允许推断，哪怕与目标无关。三种对策：① 改用后向链接（9.4）；② 把前向链接限制在选定的规则子集上，如 `PL-FC-ENTAILS?`（p.231）；③ **演绎数据库（deductive database）**的做法：用来自目标的信息**重写规则集**，使前向推断只考虑属于**魔集（magic set）**的相关变量绑定。目标为 `Criminal(West)` 时，推出 `Criminal(x)` 的规则被改写为

```
Magic(x) ∧ American(x) ∧ Weapon(y) ∧ Sells(x, y, z) ∧ Hostile(z) ⇒ Criminal(x)
```

并加入事实 `Magic(West)`。这样即使知识库含数百万美国人的事实，前向推断也只考虑 West 上校。完整过程过繁，基本思想是做一次"泛型"后向推断以弄清哪些变量绑定需要约束。**魔集方法可视为前向推断与后向预处理的一种混合。**

## 9.4 后向链接（Backward Chaining）

### 9.4.1 一个后向链接算法

Figure 9.6（p.293，原样保留）：

```
function FOL-BC-ASK(KB, query) returns a generator of substitutions
    return FOL-BC-OR(KB, query, {})

function FOL-BC-OR(KB, goal, θ) returns a substitution
    for each rule in FETCH-RULES-FOR-GOAL(KB, goal) do
        (lhs ⇒ rhs) ← STANDARDIZE-VARIABLES(rule)
        for each θ′ in FOL-BC-AND(KB, lhs, UNIFY(rhs, goal, θ)) do
            yield θ′

function FOL-BC-AND(KB, goals, θ) returns a substitution
    if θ = failure then return
    else if LENGTH(goals) = 0 then yield θ
    else
        first,rest ← FIRST(goals), REST(goals)
        for each θ′ in FOL-BC-OR(KB, SUBST(θ, first), θ) do
            for each θ′′ in FOL-BC-AND(KB, rest, θ′) do
                yield θ′′
```

- 若 KB 含形如 `lhs ⇒ goal` 的规则（`lhs` 为合取项列表），则 `FOL-BC-ASK(KB, goal)` 得证；`American(West)` 这类原子事实被视为 `lhs` 为空表的子句。
- 含变量的查询可能有**多种**证法（`Person(x)` 可用 `{x/John}` 也可用 `{x/Richard}`），所以 `FOL-BC-ASK` 实现为**生成器（generator）**——返回多次的函数（见附录 B）。
- 后向链接是一种 **AND/OR 搜索**：OR 因为目标可由 KB 中任意一条规则证明，AND 因为子句 lhs 中所有合取项都必须被证明。

Figure 9.7 是从 (9.3)–(9.10) 推导 `Criminal(West)` 的证明树（深度优先、从左到右）。

> **注意**：一旦合取式中某个子目标成功，它的置换就要施加到后续子目标上。所以当 `FOL-BC-ASK` 走到最后一个合取项（原本是 `Hostile(z)`）时，z 已经被绑定为 `Nono` 了。

按我们写出的形式，后向链接显然是**深度优先**搜索：空间需求关于证明大小是**线性**的；但也因此遭受**重复状态**与**不完备性**的困扰（前向链接没有这两个问题）。

### 9.4.2 逻辑编程（Logic programming）

逻辑编程接近第 7 章的**声明式理想**，由 Robert Kowalski 的等式总结：`Algorithm = Logic + Control`。

**Prolog** 是使用最广泛的逻辑编程语言，主要用于快速原型与符号操作（编译器编写 Van Roy, 1990；自然语言句法分析 Pereira and Warren, 1980）。记号差异：**大写字母表变量、小写表常量**（与本书逻辑约定相反）；逗号分隔合取；子句"反着写"——`C :- A, B` 对应我们的 `A ∧ B ⇒ C`。

```prolog
criminal(X) :- american(X), weapon(Y), sells(X,Y,Z), hostile(Z).
```

Prolog 中 `[E|L]` 表示首元素为 E、其余为 L 的表。

```prolog
append([],Y,Y).
append([A|X],Y,[A|Z]) :- append(X,Y,Z).
```

读作：(1) 空表与 Y 拼接得到同一个 Y；(2) `[A|Z]` 是 `[A|X]` 与 Y 拼接的结果，前提是 Z 是 X 与 Y 拼接的结果。多数高级语言也能写类似的递归函数，但 Prolog 的定义**更强**：它描述三个参数之间成立的**关系**，而非由两个参数算出的函数。因此可以问 `append(X,Y,[1,2,3])`，Prolog 给出全部解：`X=[] Y=[1,2,3]`；`X=[1] Y=[2,3]`；`X=[1,2] Y=[3]`；`X=[1,2,3] Y=[]`。

Prolog 程序以**深度优先后向链接**执行，子句按其在知识库中书写的顺序依次尝试。以下几点落在标准逻辑推断之外：

1. 使用 **§8.2.8 的数据库语义**而非一阶语义（见 9.4.4）；
2. 有一组**算术内置函数**，含这些函数符号的文字靠**执行代码**而非继续推断来"证明"。`X is 4+3` 以 X=7 成功；`5 is X+Y` 失败，因为内置函数不做任意方程求解；
3. 有**带副作用的内置谓词**（I/O、`assert`/`retract`），逻辑中没有对应物，可能产生困惑的结果（如事实被断言在一条最终失败的分支上）；
4. **合一算法中省略了出现检查**，因此可能做出**不可靠**推断（实践中几乎从不成为问题）；
5. 深度优先搜索**不检查无限递归**——用得当时很快，但某些看起来是合法逻辑的程序不会终止。

### 9.4.3 冗余推断与无限循环（Redundant inference and infinite loops）

这是 Prolog 的阿喀琉斯之踵：深度优先搜索与含**重复状态**和**无限路径**的搜索树之间的错配。下面是一个判断有向图上两点间是否有通路的程序（Figure 9.8(a) 的三节点图由 `link(a,b)`、`link(b,c)` 描述）：

```prolog
path(X,Z) :- link(X,Z).
path(X,Z) :- path(X,Y), link(Y,Z).
```

| 子句顺序 | 查询 `path(a,c)` 的结果 |
|---|---|
| 上面这个顺序 | 生成 Figure 9.9(a) 的证明树，成功 |
| 两句**调换顺序** | Prolog 沿 Figure 9.9(b) 的**无限路径**走下去 |

因此 **Prolog 作为确定子句的定理证明器是不完备的**——即使对 Datalog 程序也不完备。

> **注意**：前向链接没有这个问题——一旦推出 `path(a,b)`、`path(b,c)`、`path(a,c)`，前向链接就停机了。

深度优先后向链接还有**冗余计算**问题。在 Figure 9.8(b) 的图中（每节点连到下一层两个随机后继）找从 A1 到 J4 的通路，Prolog 做了 **877 次推断**，大部分是在找通往那些**到不了目标的节点**的所有可能通路——类似第 3 章的重复状态问题。总的推断量**关于生成的基事实个数可以是指数的**。

改用前向链接：n 个节点之间至多生成 **n²** 个 `path(X,Y)` 事实；Figure 9.8(b) 的问题只需 **62 次推断**。

> 图搜索问题上用前向链接是**动态规划（dynamic programming）**的例子：子问题的解由更小的子问题增量构造并缓存以避免重算。在后向链接系统中也能得到类似效果，只是这里是**把大目标分解成小目标**。无论哪种方式，**存储中间结果以避免重复计算**是关键。

**制表逻辑编程（tabled logic programming）** 就采取这种做法，把后向链接的**目标导向性**与前向链接的**动态规划效率**结合起来。它对 Datalog 知识库是**完备的**，程序员因此不必那么担心无限循环（对 `father(X,Y)` 这类指向潜在无穷多对象的谓词仍可能死循环）。

### 9.4.4 Prolog 的数据库语义（Database semantics of Prolog）

- **唯一名称假设（unique names assumption）**：每个 Prolog 常量与每个基项都指称**不同的**对象。
- **封闭世界假设（closed world assumption）**：为真的句子**只有**那些被知识库蕴含的句子。Prolog 里没有办法断言一个句子为假。

这使 Prolog 表达力弱于一阶逻辑，却也正是它更高效简洁的部分原因。考虑（式 9.11）`Course(CS,101), Course(CS,102), Course(CS,106), Course(EE,101)`：在唯一名称假设下 `CS` 与 `EE` 不同（101、102、106 也互不相同），所以是 **4 门不同的课**；在封闭世界假设下没有别的课，所以**恰好 4 门课**。但若这些是一阶逻辑断言，我们只能说课程数在 **1 到无穷之间**——FOL 断言既不否认还有未提及的课程，也不说明已提及的课程彼此不同。

翻译成 FOL 需写（式 9.12）：

```
Course(d, n) ⇔ (d = CS ∧ n = 101) ∨ (d = CS ∧ n = 102)
             ∨ (d = CS ∧ n = 106) ∨ (d = EE ∧ n = 101)
```

这称为式 (9.11) 的**完备化（completion）**，表达"至多有 4 门课"。要表达"至少有 4 门课"，还需相等谓词的完备化：

```
x = y ⇔ (x = CS ∧ y = CS) ∨ (x = EE ∧ y = EE) ∨ (x = 101 ∧ y = 101)
      ∨ (x = 102 ∧ y = 102) ∨ (x = 106 ∧ y = 106)
```

完备化有助于理解数据库语义；但就实用而言，若问题能用数据库语义描述，直接用 Prolog 推理要比翻译成 FOL 再用完整 FOL 定理证明器推理更高效。

### 9.4.5 约束逻辑编程（Constraint logic programming）

标准 Prolog 求解 CSP 的方式与 Figure 6.5 的回溯算法完全一样。由于回溯靠枚举变量值域，它**只适用于有限域 CSP**——用 Prolog 的话说：任何含未绑定变量的目标必须有有限个解。**无限域 CSP**（整数或实数变量）需要完全不同的算法，如界传播或线性规划。例如：

```prolog
triangle(X,Y,Z) :- X>0, Y>0, Z>0, X+Y>Z, Y+Z>X, X+Z>Y.
```

`triangle(3,4,5)` 成功；`triangle(3,4,Z)` **找不到解**，因为子目标 `Z>0` 无法处理——不能把未绑定的值与 0 比较。

**约束逻辑编程（CLP）** 允许变量被**约束**而非被绑定。CLP 的解是能从知识库推出的、关于查询变量的**最具体约束集**——`triangle(3,4,Z)` 的解是约束 `7 > Z > 1`。标准逻辑程序只是 CLP 的特例：解约束必须是**相等约束**，即绑定。

CLP 系统为语言中允许的各种约束纳入相应的约束求解算法（允许实值线性不等式的系统可能含一个线性规划算法），对标准逻辑编程查询也不必用深度优先、从左到右回溯，而可用第 6 章的任意更高效算法（启发式合取项排序、回溯跳跃、割集条件化等）。因此 CLP 结合了约束满足算法、逻辑编程与演绎数据库三者的要素。

一些系统让程序员对搜索顺序有更多控制：**MRS** 语言（Genesereth and Smith, 1981; Russell, 1985）允许编写**元规则（metarule）**决定先试哪个合取项（如"变量最少的那个目标先试"）。

## 9.5 归结（Resolution）

唯一对**任意**知识库（不限于确定子句）都可用的家族。我们在 p.223 看到命题归结对命题逻辑完备；本节把它扩展到一阶逻辑。

### 9.5.1 一阶逻辑的合取范式（Conjunctive normal form for first-order logic）

第一步把句子转成**合取范式（CNF）**——子句的合取，每子句是文字的析取。CNF 中的文字可含变量，默认全称量化。例如

```
∀ x, y, z American(x) ∧ Weapon(y) ∧ Sells(x, y, z) ∧ Hostile(z) ⇒ Criminal(x)
```

变成 `¬American(x) ∨ ¬Weapon(y) ∨ ¬Sells(x, y, z) ∨ ¬Hostile(z) ∨ Criminal(x)`。

> **关键**：一阶逻辑的**每个**句子都能转换成一个**推断等价的** CNF 句子。

用"凡是爱一切动物的人都被某个人爱"演示完整流程：

```
∀ x [∀ y Animal(y) ⇒ Loves(x, y)] ⇒ [∃ y Loves(y, x)]
```

**1. 消去蕴含**（`P ⇒ Q` → `¬P ∨ Q`，本例两次）：

```
∀ x ¬[∀ y Animal(y) ⇒ Loves(x, y)] ∨ [∃ y Loves(y, x)]
∀ x ¬[∀ y ¬Animal(y) ∨ Loves(x, y)] ∨ [∃ y Loves(y, x)]
```

**2. 把 ¬ 内移**（除常规规则外还需 `¬∀ x p` → `∃ x ¬p`、`¬∃ x p` → `∀ x ¬p`）：

```
∀ x [∃ y ¬(¬Animal(y) ∨ Loves(x, y))] ∨ [∃ y Loves(y, x)]
∀ x [∃ y ¬¬Animal(y) ∧ ¬Loves(x, y)] ∨ [∃ y Loves(y, x)]
∀ x [∃ y Animal(y) ∧ ¬Loves(x, y)] ∨ [∃ y Loves(y, x)]
```

> **注意**：蕴含前提中的全称量词 `∀ y` 变成了**存在量词**。句子现在读作"要么有某个 x 不爱的动物，要么（若不是这样）有人爱 x"——原句含义显然被保留。

**3. 变量标准化**（重复变量名改名）：`∀ x [∃ y Animal(y) ∧ ¬Loves(x, y)] ∨ [∃ z Loves(z, x)]`

**4. Skolem 化（Skolemization）**：消去存在量词。简单情形就像存在实例化（`∃ x P(x)` → `P(A)`）。但**不能**直接对上面的句子用存在实例化——它不匹配 `∃ v α` 模式，只有句子**某些部分**匹配。盲目套用会得到 `∀ x [Animal(A) ∧ ¬Loves(x, A)] ∨ Loves(B, x)`，**含义完全错了**：它说"每个人要么不爱**某个特定的**动物 A，要么被**某个特定的**实体 B 爱"，而原句允许每个人不爱**不同的**动物、被**不同的**人爱。所以 Skolem 实体必须**依赖于 x**：

```
∀ x [Animal(F(x)) ∧ ¬Loves(x, F(x))] ∨ Loves(G(x), x)
```

F、G 是 **Skolem 函数（Skolem function）**。一般规则：**Skolem 函数的参数，是出现该存在量词的作用域内的所有全称量化变量**。与存在实例化一样，Skolem 化后的句子与原句**可满足性完全相同**。

**5. 丢掉全称量词**：`[Animal(F(x)) ∧ ¬Loves(x, F(x))] ∨ Loves(G(x), x)`

**6. 把 ∨ 分配到 ∧ 上**（可能还需展平嵌套）：

```
[Animal(F(x)) ∨ Loves(G(x), x)] ∧ [¬Loves(x, F(x)) ∨ Loves(G(x), x)]
```

已成 CNF，含两个子句，比原句难读得多（`F(x)` 指那个**可能不被 x 爱**的动物，`G(x)` 指**可能爱 x** 的某个人）。幸好人类很少需要看 CNF——翻译过程很容易自动化。

### 9.5.2 归结推断规则（The resolution inference rule）

一阶归结只是 p.226 命题归结规则的**提升**版本。两个子句（假定已标准化分离、不共享变量）若含**互补文字**就可归结：命题文字互补指一个是另一个的否定；**一阶文字互补指一个能与另一个的否定合一**。

```
ℓ1 ∨ … ∨ ℓk,     m1 ∨ … ∨ mn
—————————————————————————————————————————————————————————————————
SUBST(θ, ℓ1 ∨ … ∨ ℓi−1 ∨ ℓi+1 ∨ … ∨ ℓk ∨ m1 ∨ … ∨ mj−1 ∨ mj+1 ∨ … ∨ mn)

其中 UNIFY(ℓi, ¬mj) = θ
```

例如归结 `[Animal(F(x)) ∨ Loves(G(x), x)]` 与 `[¬Loves(u, v) ∨ ¬Kills(u, v)]`，消去互补文字 `Loves(G(x), x)` 与 `¬Loves(u, v)`，合一子 `θ = {u/G(x), v/x}`，得

```
[Animal(F(x)) ∨ ¬Kills(G(x), x)]
```

这叫**二元归结（binary resolution）**，因为它恰好消解两个文字。**二元归结规则本身并不构成完备的推断过程**。完备化有两条路：一是**全归结规则**（一次消解每子句中可合一的文字子集）；二是把**因子化（factoring）**推广到一阶——命题因子化在两个文字**完全相同**时化为一个，一阶因子化在两个文字**可合一**时化为一个（合一子须作用于整个子句）。**二元归结 + 因子化是完备的。**

### 9.5.3 示例证明（Example proofs）

归结通过证明 `KB ∧ ¬α` **不可满足**（即推出空子句）来证明 `KB ⊨ α`；算法做法与命题情形（Figure 7.13）完全相同。

#### 示例一：犯罪问题（Figure 9.10，p.301）

CNF 句子加否定目标 `¬Criminal(West)`，完整归结链：

```
¬Criminal(West)                                              （否定目标）
└ 对 (9.3) 归结，{x/West} → ¬American(West) ∨ ¬Weapon(y) ∨ ¬Sells(West, y, z) ∨ ¬Hostile(z)
  └ 对 American(West) 归结 → ¬Weapon(y) ∨ ¬Sells(West, y, z) ∨ ¬Hostile(z)
    └ 对 ¬Missile(x) ∨ Weapon(x) 归结，{x/y} → ¬Missile(y) ∨ ¬Sells(West, y, z) ∨ ¬Hostile(z)
      └ 对 Missile(M1) 归结，{y/M1} → ¬Sells(West, M1, z) ∨ ¬Hostile(z)
        └ 对 ¬Missile(x) ∨ ¬Owns(Nono, x) ∨ Sells(West, x, Nono) 归结，{x/M1, z/Nono}
          → ¬Missile(M1) ∨ ¬Owns(Nono, M1) ∨ ¬Hostile(Nono)
          └ 对 Missile(M1) 归结 → ¬Owns(Nono, M1) ∨ ¬Hostile(Nono)
            └ 对 Owns(Nono, M1) 归结 → ¬Hostile(Nono)
              └ 对 ¬Enemy(x, America) ∨ Hostile(x) 归结，{x/Nono} → ¬Enemy(Nono, America)
                └ 对 Enemy(Nono, America) 归结 → □（空子句）
```

> **注意证明的结构**：一条以目标子句开始的**单一"脊柱"**，不断与知识库子句归结直到生成空子句——这是在 Horn 子句知识库上做归结的典型特征。脊柱上的子句恰好对应 Figure 9.6 后向链接算法中 `goals` 变量的连续取值，因为我们总是选择与"当前"脊柱子句最左文字合一的正文字子句来归结，这正是后向链接所做的事。**因此后向链接只是归结的一个特例：一种决定下一步做哪次归结的控制策略。**

#### 示例二：谁杀了猫（Figure 9.11，p.303）

> 凡是爱一切动物的人都被某个人爱。任何杀动物的人都不被任何人爱。Jack 爱一切动物。Jack 或 Curiosity 杀了那只叫 Tuna 的猫。是 Curiosity 杀了猫吗？

```
A.  ∀ x [∀ y Animal(y) ⇒ Loves(x, y)] ⇒ [∃ y Loves(y, x)]
B.  ∀ x [∃ z Animal(z) ∧ Kills(x, z)] ⇒ [∀ y ¬Loves(y, x)]
C.  ∀ x Animal(x) ⇒ Loves(Jack, x)
D.  Kills(Jack, Tuna) ∨ Kills(Curiosity, Tuna)
E.  Cat(Tuna)                                F.  ∀ x Cat(x) ⇒ Animal(x)
¬G. ¬Kills(Curiosity, Tuna)
```

转成 CNF：

```
A1. Animal(F(x)) ∨ Loves(G(x), x)      E.  Cat(Tuna)
A2. ¬Loves(x, F(x)) ∨ Loves(G(x), x)   F.  ¬Cat(x) ∨ Animal(x)
B.  ¬Loves(y, x) ∨ ¬Animal(z) ∨ ¬Kills(x, z)
C.  ¬Animal(x) ∨ Loves(Jack, x)        ¬G. ¬Kills(Curiosity, Tuna)
D.  Kills(Jack, Tuna) ∨ Kills(Curiosity, Tuna)
```

完整归结链：

```
1. ¬G 与 D 归结                                  → Kills(Jack, Tuna)
2. E 与 F 归结，{x/Tuna}                         → Animal(Tuna)
3. B 与 Animal(Tuna) 归结，{z/Tuna}              → ¬Loves(y, x) ∨ ¬Kills(x, Tuna)
   再与 Kills(Jack, Tuna) 归结，{x/Jack}         → ¬Loves(y, Jack)
4. C 与 A2 归结（须先标准化分离！）：
   Loves(Jack, x) 与 ¬Loves(x′, F(x′))，MGU = {x′/Jack, x/F(Jack)}
                                                 → ¬Animal(F(Jack)) ∨ Loves(G(Jack), Jack)
   再与 A1 归结，{x/Jack}                        → Loves(G(Jack), Jack) ∨ Loves(G(Jack), Jack)
   因子化                                        → Loves(G(Jack), Jack)
5. 上句与 ¬Loves(y, Jack) 归结，{y/G(Jack)}      → □（空子句）
```

英文复述：假设 Curiosity 没杀 Tuna。我们知道 Jack 或 Curiosity 杀了它，所以是 Jack 杀的。Tuna 是猫、猫是动物，所以 Tuna 是动物。杀动物的人不被任何人爱，故没人爱 Jack；但 Jack 爱一切动物，故有人爱他。矛盾。因此 Curiosity 杀了猫。

> **注意 Figure 9.11 的两个细节**：(1) `Loves(G(Jack), Jack)` 的推导用了**因子化**；(2) 右上角 `Loves(x, F(x))` 与 `Loves(Jack, x)` 的合一，**只有在变量被标准化分离之后**才能成功。

**更一般的查询**：若问"谁杀了猫？"，目标是 `∃ w Kills(w, Tuna)`，取反后在 CNF 中是 `¬Kills(w, Tuna)`。用新否定目标重做证明，会得到类似的证明树，只是某一步带上置换 `{w/Curiosity}`——所以在这个例子里，"查出谁杀了猫"不过是**在证明中记录查询变量的绑定**。

> ⚠️ 可惜归结有时会对存在性目标产生**非构造性证明（nonconstructive proof）**：我们知道查询为真，但变量**没有唯一的绑定**。

### 9.5.4 归结的完备性（Completeness of resolution）

原书注明本节可安全跳过。我们证明归结是**反驳完备的（refutation-complete）**：若一个句子集不可满足，则归结总能够推出矛盾。归结无法用来生成一个句子集的**所有**逻辑后承，但可用来确立某个给定句子被该集合**蕴含**；因此它能通过证明 `KB ∧ ¬Q(x)` 不可满足，来找出问题 `Q(x)` 的**所有**答案。

**前提**：任何一阶逻辑（不含相等）的句子都能重写为 CNF 子句集（Davis and Putnam, 1960，对句子形式做归纳、以原子句为基始）。**要证**：若 S 不可满足，则对 S 施加**有限次**归结步骤会得到矛盾。

证明梗概（依 Robinson 原始证明，兼采 Genesereth and Nilsson, 1987 的简化；结构见 Figure 9.12）三步：

1. 若 S 不可满足，则存在 S 中子句的某个特定**基实例集合**也不可满足（Herbrand 定理）；
2. 援引第 7 章的**基归结定理**：命题归结对**基句子**完备；
3. 用**提升引理**说明：对任何使用这组基句子的命题归结证明，都存在对应的、使用相应一阶句子的一阶归结证明。

第 1 步需要三个新概念：

- **Herbrand 域（Herbrand universe）**：子句集 S 的 `H_S` 是由 (a) S 中的函数符号（若有）、(b) S 中的常量符号（若有；**若没有则取一个默认常量符号 S**）构造出的所有基项的集合。若 S 只含 `¬P(x, F(x, A)) ∨ ¬Q(x, A) ∨ R(x, B)`，则

```
H_S = {A, B, F(A, A), F(A, B), F(B, A), F(B, B), F(A, F(A, A)), …}
```

- **饱和（Saturation）**：`P(S)` 是把基项集 P 中的基项对 S 中变量做**所有可能的一致置换**后得到的全体基子句的集合。
- **Herbrand 基（Herbrand base）**：S 关于其 Herbrand 域的饱和，记为 `H_S(S)`。对上例：

```
H_S(S) = { ¬P(A, F(A, A)) ∨ ¬Q(A, A) ∨ R(A, B),
           ¬P(B, F(B, A)) ∨ ¬Q(B, A) ∨ R(B, B),
           ¬P(F(A, A), F(F(A, A), A)) ∨ ¬Q(F(A, A), A) ∨ R(F(A, A), B),
           ¬P(F(A, B), F(F(A, B), A)) ∨ ¬Q(F(A, B), A) ∨ R(F(A, B), B), … }
```

> **Herbrand 定理**：若子句集 S 不可满足，则存在 `H_S(S)` 的一个**有限子集**也不可满足。

令 `S′` 为该有限基句子子集。由基归结定理（p.228），归结闭包 `RC(S′)` 含有空子句。

**剩下的事**：证明也存在一个使用 **S 本身的子句**（未必是基子句）的归结证明。先看作**单次**归结。Robinson 的引理：

> 设 `C1`、`C2` 为两个不共享变量的子句，`C′1`、`C′2` 分别是它们的基实例。若 `C′` 是 `C′1` 与 `C′2` 的归结子句，则存在子句 C，使得 (1) C 是 `C1` 与 `C2` 的归结子句，(2) `C′` 是 C 的基实例。

这叫**提升引理（lifting lemma）**，因为它把一步证明从基子句提升到一般一阶子句（为证明它，Robinson 不得不发明合一并导出最一般合一子的全部性质）。原书不重复证明，只举例：

```
C1  = ¬P(x, F(x, A)) ∨ ¬Q(x, A) ∨ R(x, B)
C2  = ¬N(G(y), z) ∨ P(H(y), z)
C′1 = ¬P(H(B), F(H(B), A)) ∨ ¬Q(H(B), A) ∨ R(H(B), B)
C′2 = ¬N(G(B), F(H(B), A)) ∨ P(H(B), F(H(B), A))
C′  = ¬N(G(B), F(H(B), A)) ∨ ¬Q(H(B), A) ∨ R(H(B), B)
C   = ¬N(G(y), F(H(y), A)) ∨ ¬Q(H(y), A) ∨ R(H(y), B)
```

可见 `C′` 确实是 C 的基实例。一般地，要使 `C′1` 与 `C′2` 有任何归结子句，它们必须先由 `C1`、`C2` 中一对互补文字的**最一般合一子**作用于 `C1`、`C2` 而构造出来。

由提升引理容易推出关于任意**归结步骤序列**的类似陈述：对 `S′` 的归结闭包中任意子句 `C′`，在 S 的归结闭包中存在子句 C，使 `C′` 是 C 的基实例，且二者推导长度相同。于是若空子句出现在 `RC(S′)` 中，它必也出现在 S 的归结闭包中——**因为空子句不可能是任何别的子句的基实例**。

**回顾**：若 S 不可满足，则存在用归结规则推出空子句的有限推导。把定理证明从基子句提升到一阶子句带来能力的巨大增长，来源在于**一阶证明只需把变量实例化到证明所必需的程度**，而基子句方法被迫检查大量任意的实例化。

> 【原书侧栏，p.305】**哥德尔不完备定理**：把一阶逻辑稍作扩展以允许算术中的数学归纳模式，Gödel 证明了存在**为真但无法证明**的算术句子（完整证明至少 30 页）。提示：该理论有唯一常量 0 与唯一函数 S（后继），`S(0)` 指称 1、`S(S(0))` 指称 2……语言还有 `+`、`×`、`Expt`。第一步注意到可写出的句子集可枚举，故可给每个句子 α 编号（**哥德尔数** `#α`）——关键在于**数论含有它自己每个句子的名字**；证明也可编号 `G(P)`。设 A 是一组关于自然数为真语句的递归可枚举集，可写出 `α(j, A)`：∀ i，i 不是哥德尔数为 j 的句子的证明的哥德尔数（证明只用 A 中前提）。令 σ 为 `α(#σ, A)`，即陈述自身从 A 不可证的句子。若 σ 可从 A 证明，则 σ 为假（它说自己不可证），于是 A 含可证但为假的语句，与前提矛盾；故 σ 不可证——而这正是 σ 自身所断言的，故 σ 为真。相关争论原书放在第 27 章。

### 9.5.5 相等性（Equality）

本章前述所有推断方法，不额外做些工作都处理不了形如 `x = y` 的断言。三条路：

**路一：把相等公理化。** 在知识库里写下相等是**自反、对称、传递**的，并说在任何谓词或函数中**可以相等代相等**——三条基本公理，再为每个谓词和每个函数各加一条：

```
∀ x x = x
∀ x, y x = y ⇒ y = x
∀ x, y, z x = y ∧ y = z ⇒ x = z
∀ x, y x = y ⇒ (P1(x) ⇔ P1(y))
∀ x, y x = y ⇒ (P2(x) ⇔ P2(y))      …
∀ w, x, y, z w = y ∧ x = z ⇒ (F1(w, x) = F1(y, z))
∀ w, x, y, z w = y ∧ x = z ⇒ (F2(w, x) = F2(y, z))   …
```

有了这些，归结就能完成需要相等推理的任务（如解方程）。但这些公理会生成**大量结论**，多数对证明毫无帮助。

**路二：加推断规则而非公理。** 最简单的是**解调（demodulation）**：取单元子句 `x = y` 和某个含项 x 的子句 α，在 α 中把 y 代入 x。只要 α 中的项与 x **可合一**就行，不必恰好等于 x。

> ⚠️ **方向要点**：解调是**有方向的**——给定 `x = y`，**总是把 x 替换为 y，绝不反向**。因此可用 `z + 0 = z` 或 `z¹ = z` 这类解调器化简表达式。

例：给定 `Father(Father(x)) = PaternalGrandfather(x)` 与 `Birthdate(Father(Father(Bella)), 1926)`，可解调得 `Birthdate(PaternalGrandfather(Bella), 1926)`。

```
• 解调（Demodulation）：对任意项 x, y, z，其中 z 出现在文字 mi 中，且 UNIFY(x, z) = θ,
      x = y,    m1 ∨ … ∨ mn
      ——————————————————————————————————————————————
      SUB(SUBST(θ, x), SUBST(θ, y), m1 ∨ … ∨ mn)
```

其中 `SUBST` 是通常的绑定表置换，`SUB(x, y, m)` 表示在 m 中某处把 x 替换为 y。推广到含等号的非单元子句：

```
• 调解（Paramodulation）：对任意项 x, y, z，其中 z 出现在文字 mi 中，且 UNIFY(x, z) = θ,
      ℓ1 ∨ … ∨ ℓk ∨ x = y,    m1 ∨ … ∨ mn
      ——————————————————————————————————————————————————————————
      SUB(SUBST(θ, x), SUBST(θ, y), SUBST(θ, ℓ1 ∨ … ∨ ℓk ∨ m1 ∨ … ∨ mn))
```

例：由 `P(F(x, B), x) ∨ Q(x)` 与 `F(A, y) = y ∨ R(y)`，有 `θ = UNIFY(F(A, y), F(x, B)) = {x/A, y/B}`，可调解得 `P(B, A) ∨ Q(A) ∨ R(B)`。**调解对含相等的一阶逻辑给出完备的推断过程。**

**路三：把相等推理放进扩展的合一算法。** 两个项若在某种置换下**可证相等**就是可合一的。例如 `1 + 2` 与 `2 + 1` 通常不可合一，但知道 `x + y = y + x` 的合一算法可用**空置换**合一它们。这类**等式合一（equational unification）**可用针对特定公理（交换律、结合律等）设计的高效算法完成，不必显式地用这些公理做推断。使用该技术的定理证明器与 9.4 节的 CLP 系统关系密切。

### 9.5.6 归结策略（Resolution strategies）

| 策略 | 内容 | 完备性 |
|---|---|---|
| **单元优先（Unit preference）** | 优先做其中一个句子是**单文字（单元子句）**的归结——我们要产生空子句，所以优先产生**更短**子句的推断是好事：单元句（如 `P`）与任何别的句子（如 `¬P ∨ ¬Q ∨ R`）归结，总得到比后者更短的子句（此例 `¬Q ∨ R`）。1964 年首次在命题推断上试用时带来**戏剧性加速**，使原本处理不了的定理变得可证 | 单元**归结**（每步都须涉及单元子句）一般**不完备**，对 **Horn 子句完备**；Horn 上的单元归结证明与前向链接相似 |
| **支持集（Set of support）** | 要求**每一步**归结都至少涉及**支持集**中一个子句，归结子句随后加入支持集。支持集相对整个知识库很小时，搜索空间**急剧缩小**。为保证完备，可取使剩余句子**联合可满足**的支持集；例如取**否定查询**作为支持集（前提是原知识库一致——若不一致，"查询可从它推出"就是空洞的）。额外好处：生成**目标导向**、人类易懂的证明树 | 可保证完备 |
| **输入归结（Input resolution）** | 每次归结把一个**输入句子**（来自 KB 或查询）与某个别的句子结合。Figure 9.10 只用了输入归结，具有"单一脊柱 + 单句并入脊柱"的特征形状，这种形状的证明树空间显然小于所有证明图的空间。Horn 知识库上 Modus Ponens 就是一种输入归结策略 | 对 **Horn 形式**完备，**一般情形不完备** |
| **线性归结（Linear resolution）** | 输入归结的轻微推广：允许 P 与 Q 归结，只要 P 在原 KB 中，**或 P 是 Q 在证明树中的祖先** | **完备** |
| **包容（Subsumption）** | 删除所有**被**（即比……**更具体**）知识库中已有句子包容的句子。若 `P(x)` 在 KB 中，就没理由再加 `P(A)`，更没理由加 `P(A) ∨ Q(B)`。有助于保持 KB 小，从而保持搜索空间小 | — |
| **学习（Learning）** | 从经验改进定理证明器：给定一批先前证明过的定理，训练机器学习系统回答"给定一组前提和待证目标，哪些证明步骤与过去成功的步骤相似？" **DEEPHOL**（Bansal et al., 2019）用深度神经网络（见第 21 章）构造目标与前提的**嵌入**并据此选择；训练可同时用人类与计算机生成的证明，从 **10,000 个证明**的集合起步 | — |

**OTTER** 定理证明器（McCune, 1990）使用一种**最佳优先搜索**，启发式函数度量每个子句的"重量"，越轻越优先。启发式的具体选择由用户决定，但一般**重量应与子句的大小或困难程度相关**；单元子句被当作**轻**的，故该搜索可视为单元优先策略的推广。

**实际用途**：一阶逻辑能表示涉及买卖、武器、国籍的简单场景，但**复杂现实场景有太多不确定性与未知量**。逻辑已被证明在涉及**形式化、严格定义的概念**的场景中更成功，如硬件与软件的**综合（synthesis）与验证（verification）**——定理证明研究在硬件设计、编程语言、软件工程领域都在开展，不只在 AI。

- **硬件**：公理描述信号与电路元件的交互（见 §8.4.2, p.273）。专为验证设计的推理器已能验证**整个 CPU**，包括时序性质（Srivas and Bickford, 1990）；AURA 被用于设计比以往任何设计都更紧凑的电路（Wojciechowski and Wojcik, 1983）。
- **软件**：对程序推理与对动作推理（第 7 章）非常相似——公理描述每条语句的前提与效果。**算法的形式化综合**是定理证明器最早的用途之一（Cordell Green, 1969a，建立在 Herbert Simon, 1963 之上），想法是**构造性地**证明"存在一个满足某规格说明的程序 p"。完全自动的演绎综合对通用编程尚未可行，但**人工引导的演绎综合**已成功设计出若干新颖精巧的算法；专用程序（如科学计算代码）的综合也是活跃领域。类似技术现用于**软件验证**，如 SPIN 模型检查器（Holzmann, 1997）：**Remote Agent 航天器控制程序**在飞行前后都经过验证（Havelund et al., 2000）；**RSA 公钥加密算法**与 **Boyer–Moore 串匹配算法**也用这种方式验证过（Boyer and Moore, 1984）。

## 小结

1. 第一种路线用推断规则（**全称实例化**与**存在实例化**）把推断问题**命题化**。除非论域很小，这条路通常很慢。
2. 用**合一**识别变量的合适置换，消去了一阶证明中的实例化步骤，多数情况下使过程高效得多。
3. **广义假言推理**是假言推理的提升版本，用合一提供了自然且强大的推断规则；前向链接与后向链接把它应用于确定子句集合。
4. 广义假言推理对确定子句**完备**，尽管蕴含问题是**半可判定**的；对由**无函数确定子句**构成的 Datalog 知识库，蕴含是**可判定的**。
5. **前向链接**用于演绎数据库（可与关系数据库操作结合），也用于产生式系统（能用非常大的规则集做高效更新）。它对 Datalog **完备且在多项式时间内运行**。
6. **后向链接**用于逻辑编程系统，后者用精巧的编译技术提供极快的推断。后向链接受制于冗余推断与无限循环，可用**记忆化**（制表）缓解。
7. **Prolog** 不像一阶逻辑，它使用带**唯一名称假设**的封闭世界与**失败即否定**。这些使它成为更实用的编程语言，但也使它离纯逻辑更远。
8. **广义归结推断规则**为使用合取范式知识库的一阶逻辑提供了**完备**的证明系统。
9. 存在若干能在**不损害完备性**的前提下缩小归结搜索空间的策略。其中一个最重要的问题是处理**相等**——**解调**与**调解**可用于此。
10. 高效的基于归结的定理证明器已被用于证明有趣的数学定理，以及**验证与综合软件和硬件**。
