## 0. 本章要解决的问题

第 3–4 章假定环境里只有"我们"一个智能体在规划。本章处理**竞争性环境**：两个或多个智能体目标冲突，引出**对抗搜索**（adversarial search）问题。我们不研究现实冲突的混沌，而是集中研究博弈（国际象棋、围棋、扑克）——对 AI 研究者来说，博弈的简化性质是优点：状态容易表示，智能体可用的动作少而由精确规则定义。（槌球、冰球这类物理博弈描述复杂、动作范围大、规则含糊，除机器人足球外未引起 AI 界多少兴趣。）

## 5.1 博弈论（Game Theory）

面对多智能体环境，至少可以取三种立场：

| 立场 | 做法 | 局限 |
|---|---|---|
| **当作经济** | 智能体极多时，把它们**聚合**成一个经济体，于是能预测"需求上升导致价格上涨"，而不必预测任何个体的动作 | 只适用于海量智能体 |
| **把对手当环境** | 把对抗智能体看成环境的一部分，于是环境变成非确定性的 | **漏掉了关键一点**：对手在**主动**试图击败我们，而下雨并没有这种意图 |
| **显式建模对手** | 用对抗博弈树搜索技术显式建模对抗智能体 | 计算量大 |

本章取第三种立场，路线如下：① 从受限的一类博弈出发定义**最优走法**并给出求解算法——**minimax 搜索**（AND–OR 搜索的推广，见图 4.11）；② 用**剪枝**忽略对最优走法没有影响的树的部分；③ 非平凡博弈通常来不及保证找到最优走法，必须**截断搜索**，对每个停机状态判断"谁占优"——或用启发式**评估函数**按状态特征估计（§5.3），或从该状态**多次快速模拟**整局并取平均（§5.4）；④ §5.5 讨论含机会元素（掷骰子、洗牌）的博弈，§5.6 讨论不完全信息博弈（扑克、桥牌——并非所有牌对所有玩家可见）。

### 5.1.1 双人零和博弈

AI 中最常研究的博弈（国际象棋、围棋）正是博弈论家所说的**确定性、双人、轮流、完美信息、零和**博弈。

- **完美信息**（perfect information）：是"完全可观测"的同义词。
  > ⚠️ 原书脚注：有些作者做区分——用 *imperfect information game* 指扑克那样"玩家拿到关于自己手牌的私有信息"的博弈，用 *partially observable game* 指《星际争霸 II》那样"每个玩家看得见近处环境、看不见远处环境"的博弈。
- **零和**（zero-sum）：对一方有多好，对另一方就有多坏，不存在"双赢"结局。
  > 原书脚注：国际象棋结局取值 `1`、`0`、`1/2`，两值之和是 `+1` 而非 `0`。叫"常和"更准确，但"零和"是传统说法——想象每位玩家先被收取 `1/2` 的入场费，就自洽了。
- 博弈中常用 **move**（走法）作为 action（动作）的同义词、**position**（局面）作为 state（状态）的同义词；两位玩家分别记作 **MAX** 与 **MIN**，MAX 先走，然后轮流，直到终局给赢家加分、给输家罚分。

**博弈的形式定义**（六要素）：

| 元素 | 含义 |
|---|---|
| `S0` | 初始状态，规定开局如何摆设 |
| `TO-MOVE(s)` | 状态 `s` 下轮到谁走 |
| `ACTIONS(s)` | 状态 `s` 下的合法走法集合 |
| `RESULT(s, a)` | **转移模型**：在 `s` 中走 `a` 后到达的状态 |
| `IS-TERMINAL(s)` | **终止测试**：博弈结束时为真，否则为假；使博弈结束的状态称**终止状态** |
| `UTILITY(s, p)` | **效用函数**（也称目标函数 objective function 或收益函数 payoff function）：博弈在终止状态 `s` 结束时给玩家 `p` 的最终数值 |

- 国际象棋结局为赢/输/和，取值 `1`、`0`、`1/2`；有些博弈结局范围更宽，例如西洋双陆棋（backgammon）的收益从 `0` 到 `192`。

与第 3 章一样，初始状态、`ACTIONS`、`RESULT` 三者定义了**状态空间图**（顶点是状态、边是走法，一个状态可由多条路径到达）；我们也可以在图的一部分上叠加**搜索树**来决定走哪一步。**完整博弈树**（game tree）指沿每一种走法序列一路走到终止状态的搜索树——若状态空间本身无界，或规则允许无限重复的局面，博弈树可能是无穷的。

**例（Figure 5.1，井字棋）**：MAX 先手有 9 种走法；MAX 放 X 与 MIN 放 O 交替，直到某方三连或棋盘填满。每个叶节点标着该终止状态**从 MAX 视角**的效用值（高值对 MAX 好、对 MIN 坏——玩家的名字就是这么来的）。井字棋的博弈树相对小：终止节点少于 `9! = 362,880`（其中只有 `5,478` 个不同状态）。而国际象棋有超过 `10^40` 个节点，博弈树最好只当作一个我们无法在物理世界实现的**理论构造**。

## 5.2 博弈中的最优决策（Optimal Decisions in Games）

MAX 想找一条致胜的动作序列，但 MIN 对此有发言权。这意味着 MAX 的策略必须是一个**条件计划**——一条**应变策略**（contingent strategy），对 MIN 的每种可能走法都规定一个回应。结局为二值（赢/输）的博弈可以用 **AND–OR 搜索**（p.125）生成这个条件计划；事实上，对此类博弈，"博弈的致胜策略"的定义与"非确定性规划问题的解"的定义**完全相同**：两种情况下，无论"对方"做什么，都必须保证期望结果出现。结局有多个分值的博弈则需要一个稍更一般的算法：**minimax 搜索**。

**例（Figure 5.2，两层博弈树）**：根节点 MAX 的走法标为 `a1`、`a2`、`a3`；对 `a1` 的回应是 `b1`、`b2`、`b3`，以此类推。此博弈在 MAX 与 MIN 各走一步后结束，终止状态的效用从 `2` 到 `14`。

> **注意**：在某些博弈里 "move" 指**双方各走一步**；因此用 **ply** 一词明确表示"**一方**走一步"，使博弈树深一层。

### 5.2.1 minimax 搜索算法

给定博弈树，最优策略可由计算每个状态的 **minimax 值** `MINIMAX(s)` 得出：它是**假设双方从该状态起都最优地打到终局**时，MAX 在该状态得到的效用。

```
MINIMAX(s) =
    UTILITY(s, MAX)                            if IS-TERMINAL(s)
    max_{a∈Actions(s)} MINIMAX(RESULT(s, a))   if TO-MOVE(s) = MAX
    min_{a∈Actions(s)} MINIMAX(RESULT(s, a))   if TO-MOVE(s) = MIN
```

终止状态的 minimax 值就是它的效用；**非终止状态：轮到 MAX 时 MAX 偏好移动到取值最大的状态，轮到 MIN 时 MIN 偏好取值最小的状态**（即对 MAX 最小、从而对 MIN 最大）。

**应用到 Figure 5.2**：最底层的终止节点从 `UTILITY` 取值。第一个 MIN 节点 `B` 有三个后继，值 `3`、`12`、`8`，故 minimax 值为 `3`；另两个 MIN 节点的值都是 `2`。根节点是 MAX 节点，三个后继的 minimax 值为 `3`、`2`、`2`，故根的值为 `3`。**minimax 决策**：`a1` 是 MAX 的最优选择，因为它通向 minimax 值最高的状态。

> **重要保留**：这个"对 MAX 最优"的定义**假定 MIN 也走最优**。若 MIN 不走最优，MAX 至少会打得和面对最优对手一样好，可能更好。但这**并不**意味着面对次优对手时永远该走 minimax 最优走法——
> 考虑这样一个局面：双方最优都将导向和棋，但 MAX 有一个冒险走法，它通向一个 MIN 有 10 种看似合理的应对、其中 **9 种 MIN 输、1 种 MAX 输**的状态。若 MAX 认为 MIN 的算力不足以发现那个最优应对，MAX 可能愿意试这步险棋，理由是 **9/10 的取胜机会好过确定的和棋**。

**算法（Figure 5.3）**：把 `MINIMAX(s)` 变成搜索算法——试遍所有动作，选结果状态 `MINIMAX` 值最高的那个。它是递归的：一路下行到叶，然后在递归返回时把 minimax 值**回传**（backed-up value）到树上。

```
function MINIMAX-SEARCH(game, state) returns an action
    player ← game.TO-MOVE(state)
    value, move ← MAX-VALUE(game, state)
    return move

function MAX-VALUE(game, state) returns a (utility, move) pair
    if game.IS-TERMINAL(state) then return game.UTILITY(state, player), null
    v ← -∞
    for each a in game.ACTIONS(state) do
        v2, a2 ← MIN-VALUE(game, game.RESULT(state, a))
        if v2 > v then
            v, move ← v2, a
    return v, move

function MIN-VALUE(game, state) returns a (utility, move) pair
    if game.IS-TERMINAL(state) then return game.UTILITY(state, player), null
    v ← +∞
    for each a in game.ACTIONS(state) do
        v2, a2 ← MAX-VALUE(game, game.RESULT(state, a))
        if v2 < v then
            v, move ← v2, a
    return v, move
```

**演算（Figure 5.2）**：先递归到左下三个节点，用 `UTILITY` 得值 `3`、`12`、`8`；取最小值 `3` 作为 `B` 的回传值；同理 `C`、`D` 各得 `2`；最后取 `max(3, 2, 2)` 得根的回传值 `3`。

**复杂度（T7 逐字抄）**：minimax 做一次完整的深度优先遍历。若树的最大深度为 `m`、每处有 `b` 个合法走法，则**时间复杂度 `O(b^m)`**，**空间复杂度 `O(bm)`**（一次生成所有动作的算法）或 **`O(m)`**（一次生成一个动作的算法，见 p.80）。指数复杂度使 minimax 对复杂博弈不实用：国际象棋分支因子约 `35`、平均一局约 `80` ply，搜索 `35^80 ≈ 10^123` 个状态不可行。但 minimax 仍是博弈**数学分析**的基础；用各种方式近似 minimax 分析，可以导出更实用的算法。

### 5.2.2 多人博弈中的最优决策

把 minimax 推广到多人博弈在技术上很直接，但引出一些新概念。

1. **把单值换成值向量**：三玩家 `A`、`B`、`C` 的博弈中每个节点关联向量 `⟨vA, vB, vC⟩`，终止状态给出该状态从每位玩家视角的效用。（双人零和博弈中二元素向量可约化为单值，因为两值总是相反。）最简单实现是让 `UTILITY` 返回效用向量。
2. **非终止节点的回传规则**：看 Figure 5.4 中标 `X` 的节点，该处轮到 `C` 选，两个选择通向 `⟨vA=1, vB=2, vC=6⟩` 与 `⟨vA=4, vB=2, vC=3⟩`；因为 `6 > 3`，`C` 应选第一个，故 `X` 的回传值就是 `⟨1, 2, 6⟩`。
   > **一般规则**：节点 `n` 的回传值 = **在 `n` 处做选择的那位玩家取值最高的那个后继状态的效用向量**。

**联盟**：多人博弈（如《外交》《卡坦岛》）通常涉及玩家之间正式或非正式的**联盟**（alliance），而联盟会随博弈推进缔结又破裂。联盟是各玩家最优策略的自然结果吗？**答案是：可以是。** 若 `A`、`B` 处境弱而 `C` 处境强，则 `A` 和 `B` **都**最优地攻击 `C` 而不是互相攻击，否则 `C` 会逐个击破他们——**合作从纯粹的自私行为中涌现**。当然，`C` 一旦被削弱，联盟就失去价值，`A` 或 `B` 都可能违约；有时显性联盟只是把本来会发生的事具体化，有时违约带有社会污名，玩家要在**违约的短期收益**与**被视为不可信的长期损失**之间权衡（详见 §18.2）。

**非零和博弈中两人也会合作**：假设存在终止状态 `⟨vA=1000, vB=1000⟩` 且 `1000` 是每位玩家可能的最高效用，那么双方的最优策略就是尽一切可能到达该状态——玩家会**自动合作**去实现一个共同期望的目标。

### 5.2.3 Alpha–Beta 剪枝

博弈状态数对树深是指数的。**没有算法能完全消除这个指数，但我们有时能把它减半**：不必检查每一个状态，通过**剪枝**掉对结果没有影响的大片子树，就能算出正确的 minimax 决策。这个技术叫 **alpha–beta 剪枝**（alpha–beta pruning）。

**重看 Figure 5.2**：Figure 5.5 逐步给出了计算最优决策时我们在每个时刻知道什么——结果是**两个叶节点根本没被评估**，我们仍能确定 minimax 决策。

**另一种看法——把 `MINIMAX` 公式化简**：设 Figure 5.5 中 `C` 的两个未评估后继值为 `x`、`y`，则

```
MINIMAX(root) = max(min(3, 12, 8), min(2, x, y), min(14, 5, 2))
              = max(3, min(2, x, y), 2)
              = max(3, z, 2)   其中 z = min(2, x, y) ≤ 2
              = 3
```

也就是说，根的值与 minimax 决策**与 `x`、`y` 的值无关**，因此可以把它们剪掉。

**一般原则（Figure 5.6）**：α–β 可用于任意深度的树，而且常常能剪掉整棵子树而不仅是叶子。考虑树中某节点 `n`，Player 可以选择走到 `n`。若 Player 在**同一层**（图中 `m′`）或树上**更高处**（图中 `m`）有更好的选择，则 Player **永远不会**走到 `n`。所以，一旦我们通过检查 `n` 的部分后代获得了足够信息来得出这个结论，就可以剪掉它。

**α 与 β 的含义**：minimax 搜索是深度优先的，任意时刻只需考虑**单条路径**上的节点。α–β 剪枝得名于 `MAX-VALUE(state, α, β)`（Figure 5.7）多出的两个参数，它们描述**路径上任何地方出现的回传值的界**：

| 参数 | 含义 | 口诀 |
|---|---|---|
| **`α`** | 到目前为止，在路径上 **MAX** 的**任何**选择点找到的**最好**（即取值**最高**）选择的值 → **下界** | `α` = "至少" |
| **`β`** | 到目前为止，在路径上 **MIN** 的**任何**选择点找到的**最好**（即取值**最低**）选择的值 → **上界** | `β` = "至多" |

α–β 搜索边走边更新 `α` 与 `β`，并**在当前节点的值已知差于 MAX 或 MIN 各自的当前 `α` 或 `β` 值时，立即剪掉该节点余下的分支**（即终止递归调用）。完整算法见 Figure 5.7。

```
function ALPHA-BETA-SEARCH(game, state) returns an action
    player ← game.TO-MOVE(state)
    value, move ← MAX-VALUE(game, state, -∞, +∞)
    return move

function MAX-VALUE(game, state, α, β) returns a (utility, move) pair
    if game.IS-TERMINAL(state) then return game.UTILITY(state, player), null
    v ← -∞
    for each a in game.ACTIONS(state) do
        v2, a2 ← MIN-VALUE(game, game.RESULT(state, a), α, β)
        if v2 > v then
            v, move ← v2, a
        α ← MAX(α, v)
        if v ≥ β then return v, move
    return v, move

function MIN-VALUE(game, state, α, β) returns a (utility, move) pair
    if game.IS-TERMINAL(state) then return game.UTILITY(state, player), null
    v ← +∞
    for each a in game.ACTIONS(state) do
        v2, a2 ← MAX-VALUE(game, game.RESULT(state, a), α, β)
        if v2 < v then
            v, move ← v2, a
        β ← MIN(β, v)
        if v ≤ α then return v, move
    return v, move
```

> ⚠️ **T1 高危区，务必记清**：
> - `α` 在 **MAX-VALUE** 中更新（`α ← MAX(α, v)`），是**下界**；`β` 在 **MIN-VALUE** 中更新（`β ← MIN(β, v)`），是**上界**；两者都**原样传给子调用**。
> - **剪枝条件**：MAX 层 `if v ≥ β then return`（当前值已达/超过上界 → 剪，称 **β 剪枝**）；MIN 层 `if v ≤ α then return`（当前值已达/低于下界 → 剪，称 **α 剪枝**）。
> - 根调用传 `(-∞, +∞)`。

**逐步演算（Figure 5.5，对应 Figure 5.2 的树）**：

| 步骤 | 发生的事 | 得到的界 |
|---|---|---|
| (a) | `B` 下第一个叶值为 `3`；`B` 是 MIN 节点 | `B` 的值**至多 3** |
| (b) | `B` 下第二个叶值为 `12`；MIN 会避开这步 | `B` 仍至多 `3` |
| (c) | `B` 下第三个叶值为 `8`；`B` 的后继已看完 | `B` **恰好 = 3** → 可推出根的值**至少 3**（MAX 在根有一个值 3 的选择） |
| (d) | `C` 下第一个叶值为 `2`；`C` 是 MIN 节点，值至多 `2` | 已知 `B` 值 `3`，MAX 绝不会选 `C` → **不必再看 `C` 的其他后继**。这就是 α–β 剪枝 |
| (e) | `D` 下第一个叶值为 `14` | `D` 至多 `14`，仍高于 MAX 的最佳备选 `3`，需继续探索；此时根的所有后继都有了界，故根的值也**至多 14** |
| (f) | `D` 的第二个后继值 `5`（仍需探索）；第三个后继值 `2` | `D` **恰好 = 2**；MAX 在根的决策是走向 `B`，值 `3` |

### 5.2.4 走法排序

α–β 剪枝的效果**高度依赖状态的检查顺序**。例如在 Figure 5.5(e)(f) 中，`D` 的后继一个都没被剪掉，因为对 MIN 而言**最差**的后继先被生成了。若 `D` 的第三个后继（值 `2`）先生成，就能剪掉另外两个。**→ 值得先检查那些可能最好的后继。**

| 排序质量 | 需检查的节点数 | 有效分支因子 |
|---|---|---|
| minimax（无剪枝） | `O(b^m)` | `b` |
| **完美排序**的 α–β | `O(b^{m/2})` | **`√b`**（国际象棋约 **6** 而不是 **35**） |
| **随机排序**的 α–β（中等 `b`） | 约 `O(b^{3m/4})` | — |

完美排序意味着同样时间内 α–β 能解**深度约为 minimax 两倍**的树。但我们**做不到**完美排序——否则那个排序函数本身就能用来下出完美的棋！不过可以相当接近：国际象棋里一个相当简单的排序函数（先试吃子，再威胁，再向前走，再向后走）能达到最佳情形 `O(b^{m/2})` 结果的**约 2 倍以内**。

**动态排序**：再叠加"先试过去发现最好的走法"这类方案，就更接近理论极限。"过去"可以是**上一步**（同样的威胁常常还在），也可以来自对本步的**迭代加深**探索（见 p.80）：先搜一层深、按评估值给走法排名，再搜深一层、用上次排名指导排序，依此类推——迭代加深多花的时间能被更好的排序**赚回来**。这些最好的走法称为 **killer moves**，先试它们称为 **killer move 启发式**。

**变位表**：§3.3.3 说过，到重复状态的冗余路径会让搜索代价指数上升，保存已到达状态的表可以解决。博弈树搜索中重复状态来自**变位**（transposition）——走法序列的不同排列最终到达同一局面；可用**变位表**（transposition table）缓存状态的启发值。例：白方有走法 `w1`（黑应以 `b1`）与棋盘另一侧无关的 `w2`（黑应以 `b2`）；搜索 `[w1, b1, w2, b2]` 到达状态 `s`，探索其下方一大棵子树后把回传值存入变位表；后来搜索 `[w2, b2, w1, b1]` 又到达 `s`，直接查表即可。国际象棋中使用变位表非常有效，能在同样时间内把**可达搜索深度翻倍**。

**即便有 α–β 与巧妙排序，minimax 对国际象棋和围棋仍然不够**——在可用的时间里状态还是太多。计算机博弈的第一篇论文 *Programming a Computer for Playing Chess*（Shannon, 1950）中，Claude Shannon 就认清了这个问题并提出两种策略：

| 策略 | 做法 | 探索的树的形状 |
|---|---|---|
| **Type A 策略** | 考虑搜索树中到某一深度的**所有**可能走法，再用启发式评估函数估计该深度状态的效用 | **宽而浅** |
| **Type B 策略** | 忽略看起来差的走法，沿有希望的线路"尽可能深"地走 | **深而窄** |

历史上多数国际象棋程序是 Type A（下一节），而围棋程序更多是 Type B（§5.4），因为围棋的分支因子高得多。近来 Type B 程序已在包括国际象棋在内的多种博弈中展现出**世界冠军级**水平（Silver et al., 2018）。

## 5.3 启发式 Alpha–Beta 树搜索（Heuristic Alpha–Beta Tree Search）

为了用有限的计算时间博弈，我们可以**提前截断搜索**并对状态应用启发式**评估函数**，实质上是把非终止节点当作终止节点处理。也就是说：

- 把 `UTILITY` 换成 **`EVAL`**（估计状态的效用）；
- 把终止测试换成**截断测试**（cutoff test）：它对终止状态必须返回真，其余情况下可以按搜索深度、以及它选择考虑的状态的任何性质自由决定何时截断。

这就给出状态 `s` 在搜索深度 `d` 处的**启发式 minimax 值**：

```
H-MINIMAX(s, d) =
    EVAL(s, MAX)                                    if IS-CUTOFF(s, d)
    max_{a∈Actions(s)} H-MINIMAX(RESULT(s, a), d+1) if TO-MOVE(s) = MAX
    min_{a∈Actions(s)} H-MINIMAX(RESULT(s, a), d+1) if TO-MOVE(s) = MIN
```

### 5.3.1 评估函数

启发式评估函数 `EVAL(s, p)` 返回状态 `s` 对玩家 `p` 的**期望效用估计**——正如第 3 章的启发式函数返回到目标距离的估计。它必须满足：终止状态 `EVAL(s, p) = UTILITY(s, p)`；非终止状态 `UTILITY(loss, p) ≤ EVAL(s, p) ≤ UTILITY(win, p)`。

**除此之外，什么构成好的评估函数？** 两条：**计算不能太慢**（目的就是搜得更快）；应与**实际获胜机会强相关**。

> 有人会质疑"获胜机会"这个说法：国际象棋毕竟不是机会游戏——我们确定地知道当前状态，没有骰子；若双方都不出错，结局是预先确定的。**但若搜索必须在非终止状态处截断，算法就必然对这些状态的最终结果不确定**（尽管有无限算力可以消解这种不确定性）。

**特征与等价类**：多数评估函数通过计算状态的各种**特征**（features）来工作——例如国际象棋里有"白兵数""黑兵数""白后数""黑后数"等特征。这些特征合起来定义了状态的若干**类别/等价类**：同一类中的状态在所有特征上取值相同（例如"两兵对一兵残局"）。任意一个类中，有些状态（在完美走法下）致胜，有些致和，有些致负。评估函数**不知道**哪些是哪些，但它可以返回一个值，估计各结局所占的**比例**。

- 例：经验表明"两兵对一兵"类中 **82%** 的状态致胜（效用 `+1`）、**2%** 致负（`0`）、**16%** 致和（`1/2`）→ 该类状态的合理评估是期望值

```
(0.82 × +1) + (0.02 × 0) + (0.16 × 1/2) = 0.90
```

原则上可以对每一类状态定出这个期望值，从而得到一个对任何状态都适用的评估函数。但实践中这种分析需要**太多类别**、从而需要太多经验去估计全部概率。

**实践做法**：对每个特征分别算数值贡献，再合并成总值。几百年来棋手正是用这个想法判断局面价值的。入门棋书给出近似的**子力价值**（material value）：兵 `1`、马或象 `3`、车 `5`、后 `9`；其他特征如"好兵形""王的安全"可能值半个兵。把这些特征值**相加**即得局面评估。

数学上，这类评估函数叫**加权线性函数**（weighted linear function）：

```
EVAL(s) = w₁f₁(s) + w₂f₂(s) + ··· + wₙfₙ(s) = Σ_{i=1}^{n} wᵢ fᵢ(s)
```

其中 `fᵢ` 是局面的一个特征（如"白象的数目"），`wᵢ` 是权重（说明该特征有多重要）。权重应当归一化，使总和总落在败（`0`）到胜（`+1`）的区间内。稳当一个兵的优势就能带来相当可观的胜算，稳当三个兵的优势应当几乎必胜（Figure 5.8(a)）。

> **注意（T5）**：评估函数应与实际胜算**强相关**，但**不必线性相关**——若状态 `s` 的胜算是 `s′` 的两倍，我们**不要求** `EVAL(s)` 是 `EVAL(s′)` 的两倍，只要求 `EVAL(s) > EVAL(s′)`。

**相加的隐含假设**：把特征值加起来看似合理，其实包含了一个很强的假设——**每个特征的贡献与其他特征的取值无关**。因此当今的国际象棋等程序还使用特征的**非线性**组合，例如：一对象的价值可能高于单只象的两倍；象在残局比开局更值钱（当"走棋步数"特征高、或"剩余棋子数"特征低时）。

**特征与权重从哪来？** 它们不是国际象棋规则的一部分，而是**人类下棋经验的文化**的一部分。在缺乏这种经验的博弈中，可以用第 22 章的机器学习技术来估计权重。把这些技术用于国际象棋，**证实了象确实大约值三个兵**；看起来几百年的经验可以在几小时的机器学习中被复现。

### 5.3.2 截断搜索

改造 `ALPHA-BETA-SEARCH` 的方法是：把 Figure 5.7 中提到 `IS-TERMINAL` 的两行替换为

```
if game.IS-CUTOFF(state, depth) then return game.EVAL(state, player), null
```

并做一些簿记，使当前深度在每次递归调用时 `+1`。

**控制搜索量的两种做法**：

| 做法 | 说明 |
|---|---|
| **固定深度限制** | 最直接：设固定深度 `d`，`IS-CUTOFF(state, depth)` 对所有 `depth > d`（以及所有终止状态）返回真；选 `d` 使得能在分配到的时间内选出走法 |
| **迭代加深** | 更稳健：时间耗尽时，程序返回**最深一次已完成的搜索**选出的走法。附带好处：每轮迭代加深都保留变位表条目 → 后续轮次更快，且可用评估值改进走法排序 |

**评估函数的近似性会带来两类错误**：

**（1）非静态局面**：仍以基于子力优势的简单评估函数为例。假设程序搜到深度限制，到达 Figure 5.8(b) 的位置（黑方多一个马和两个兵），它会把这个值当作该状态的启发值，从而宣布黑方很可能赢。但白方下一步可以**无代价地吃掉黑后**——该位置实际上对白方有利，而这**只有往前看才看得出**。

> **静态性**（quiescence）：评估函数只应作用于**静态局面**——即不存在（比如吃掉后这样的）会让评估剧烈摇摆的**待决走法**的局面。对非静态局面 `IS-CUTOFF` 返回假，搜索继续直到到达静态局面。这种额外的**静态搜索**（quiescence search）有时只考虑某些类型的走法（如吃子走法），以便快速消解局面中的不确定性。

**（2）地平线效应**（horizon effect）更难消除：它出现在程序面对对手一步**会造成严重损失、最终不可避免、却可以用拖延战术暂时避开**的走法时。以 Figure 5.9 为例：黑象明显无处可逃——白车走 `h1`、再 `a1`、再 `a2` 吃掉它，那是 **6 ply** 处的一次吃子。但黑方有一串走法能把吃象"推到地平线之外"：假设黑搜 **8 ply**，多数走法会导致象最终被吃而被标为"坏"走法；但黑也会考虑先用兵将军、引诱王吃掉兵，再用第二个兵做同样的事——这耗掉足够多步，使得在黑剩余的搜索中**不会发现**吃象。于是黑以为这条线路用两个兵的代价救了象，实际上它只是浪费了兵、并把不可避免的吃象**推到了它看得见的地平线之外**。

**缓解策略——奇异延伸**（singular extension）：把"明显优于该局面中所有其他走法"的走法延伸出去，即使搜索本该在此截断。在上例中，搜索会揭示白车的三步（`h2→h1`、`h1→a1`、`a1` 吃掉 `a2` 上的象）每一步都明显更好；所以即使一串兵的走法把我们推到地平线，这些走法也有机会延伸搜索。这使树更深，但因为奇异延伸通常很少，不会给树增加很多总节点，实践中被证明有效。

### 5.3.3 前向剪枝

**关键区分（T5）**：

| 技术 | 剪掉什么 | 风险 |
|---|---|---|
| **α–β 剪枝** | 对最终评估**不可能有影响**的分支 | 无——结果与 minimax 相同 |
| **前向剪枝**（forward pruning） | **看起来差、但有可能好**的走法 | **省算力，但冒着出错的风险** |

用 Shannon 的术语，前向剪枝就是 **Type B 策略**。显然大多数人类棋手就是这么做的——在每个局面（至少有意识地）只考虑少数几个走法。

- **集束搜索**（beam search，见 p.115）：每一层只考虑"集束"内按评估函数排出的 `n` 个最佳走法，而不是考虑所有可能走法。这种方法**相当危险**，因为无法保证最佳走法不会被剪掉。
- **PROBCUT**（probabilistic cut，Buro, 1995）：α–β 的前向剪枝版本，用先前经验的统计量**降低最佳走法被剪掉的机会**。α–β 剪掉任何**可证明**落在当前 `(α, β)` 窗口之外的节点；PROBCUT 还剪掉**很可能**落在窗口外的节点——先做一次浅层搜索算出节点的回传值 `v`，再用过去经验估计"深度 `d` 处得分为 `v` 会落在 `(α, β)` 之外"的可能性。Buro 把它用于黑白棋程序 `LOGISTELLO`，带 PROBCUT 的版本在 **64%** 的对局中打败常规版本，**即使常规版本被给两倍的时间**。
- **后手走法缩减**（late move reduction）：假设排序做得好，于是排在候选走法表**后面**的走法不太可能是好走法；但不把它们完全剪掉，只是**减少**搜索深度以省时间。若缩减搜索返回的值高于当前 `α` 值，就用完整深度重跑。

**综合效果（原书算例，逐字核）**：假设已实现国际象棋评估函数、合理的截断测试与静态搜索；又假设经过数月枯燥的位操作优化，能在最新 PC 上**每秒生成并评估约一百万个节点**。国际象棋分支因子平均约 `35`，`35^5` 约 `5000 万`，所以：用 minimax，一分钟只能往前看 **5 ply**（比赛规则不给足够时间搜 6 ply），这样的程序会被普通人类棋手击败；加上 α–β 与大变位表可达约 **14 ply**，即**专家级**；换成带 8 个 GPU 的工作站可超过十亿节点/秒，但要达**特级大师**水平仍需大量调优的评估函数与大型残局数据库——`STOCKFISH` 这类顶级程序具备所有这些，常搜到深度 **30 或更深**。

### 5.3.4 搜索 vs 查表

一个国际象棋程序开局就考虑一棵含十亿个博弈状态的树，只为得出"兵走 e4"（最流行的第一步），似乎有点小题大做。讲述国际象棋开局与残局好棋的书籍已经存在一个多世纪（Tattersall, 1911）。因此，许多博弈程序对开局与残局用**查表**而非搜索。

| 阶段 | 谁有专长 | 做法 |
|---|---|---|
| **开局** | **人类** | 人类专家关于每个开局的最佳建议可从书中抄下来录入表格；此外计算机可从以往对局数据库收集统计，看哪些开局序列最常致胜。头几步可能性少，多数局面都在表里。**通常约 10 到 15 步之后**我们到达罕见局面，程序必须从查表切换到搜索 |
| **残局** | **计算机** | 近终局时可能局面再次变少，查表更容易，但这里计算机的分析远超人类能力 |

**残局的完全求解**：新手人类靠几条简单规则就能赢 **KRK**（王车对王）残局；其他残局如 **KBNK**（王象马对王）难以掌握，也没有简洁的策略描述。而计算机可以**完全求解**残局——生成一个**策略**（从每个可能状态到该状态下最佳走法的映射），然后只需查表就能完美下棋。这张表用**逆向 minimax 搜索**（retrograde minimax search）构造：① 先考虑把 KBNK 棋子摆到棋盘上的**所有**摆法，把白胜的局面标记为"胜"；② 然后把规则**反过来**做**逆着**（reverse moves）而非着——白方任何"无论黑方怎么应对、都走到标记为胜的局面"的走法本身也必是胜；③ 继续直到所有可能局面都被判定为**胜、负或和**，就得到**万无一失**的查找表。这不仅对 KBNK 做过，而且对**所有七子及以内**的残局都做过；这些表包含 **400 万亿**个局面，八子表需要 **40000 万亿**个。

## 5.4 蒙特卡洛树搜索（Monte Carlo Tree Search）

围棋暴露了启发式 α–β 树搜索的两个主要弱点：① 围棋的分支因子起手是 **361**，α–β 只能做到 **4 或 5 ply**；② 很难为围棋定义好的评估函数——**子力价值不是强指标**，而且多数局面直到终局都处在变动中。为应对这两个挑战，现代围棋程序放弃了 α–β 搜索，改用**蒙特卡洛树搜索**（Monte Carlo tree search, MCTS）。

> 原书脚注：「Monte Carlo」算法是随机化算法，以摩纳哥的蒙特卡洛赌场（Casino de Monte-Carlo）命名。

**基本思想**：基本 MCTS **不使用启发式评估函数**。状态的值被估计为从该状态出发**多次完整对局模拟的平均效用**。一次**模拟**（simulation，也称 **playout** 或 **rollout**）先为一方选走法、再为另一方选，重复直到到达终止局面；此时由**博弈规则**（不是会出错的启发式）决定谁赢谁输、赢多少。对只有胜/负两种结果的博弈，"平均效用"就等于"**胜率**"。

**模拟中怎么选走法？** 若只是随机选，多次模拟后回答的问题是"**双方都随机走**时的最佳走法是什么"——对多数博弈这不是我们要的答案。要从模拟中得到有用信息，需要一个把走法偏向好走法的**模拟策略**（playout policy）。对围棋等博弈，已成功用**神经网络从自我对弈中学到**模拟策略；有时也用博弈专用启发式（如国际象棋里"考虑吃子走法"、黑白棋里"占角"）。

**纯蒙特卡洛搜索**（pure Monte Carlo search）：有了模拟策略，还要决定从哪些局面开始模拟、给每个局面分配多少次模拟。最简单的答案是：从当前博弈状态出发做 `N` 次模拟，跟踪当前位置的各可能走法中哪个胜率最高。对某些随机博弈这随 `N` 增大收敛到最优走法，但对多数博弈不够——我们需要一个**选择策略**（selection policy），把计算资源**选择性地集中**到博弈树的重要部分，平衡两个因素：**探索**（模拟次数少的状态）与**利用**（过去模拟中表现好的状态）（见 §17.3）。

**MCTS 的四步（Figure 5.10）**：MCTS 维护一棵搜索树，并在每次迭代中按下面四步生长它：

1. **选择**（Selection）：从树根开始按选择策略选走法到达后继节点，重复此过程沿树下行到一个叶节点。Figure 5.10(a) 的根表示"白方刚走完"的局面，白在迄今 **100** 次模拟中赢了 **37** 次。粗箭头表示黑选了一个走法到达黑赢 **60/79** 的节点——这是三个走法中胜率最高的，是**利用**的例子；但出于**探索**，选 **2/11** 那个节点也合理——只做了 11 次模拟，估值仍很不确定。选择继续下行到标着 **27/35** 的叶节点。
2. **扩展**（Expansion）：生成被选节点的一个新子节点——Figure 5.10(b) 中标记为 **0/0** 的新节点。（有些版本在这一步生成多于一个子节点。）
3. **模拟**（Simulation）：从新生成的子节点出发做一次模拟，按模拟策略为双方选走法；这些走法**不记录**在搜索树中。图中这次模拟结果是**黑胜**。
4. **回传**（Back-propagation）：用模拟结果更新通往根的所有节点。因为黑赢了，**黑方**节点的**胜局数与模拟数都 +1**：`27/35 → 28/36`、`60/79 → 61/80`；因为白输了，**白方**节点只把**模拟数 +1**：`16/53 → 16/54`、根 `37/100 → 37/101`。

> ⚠️ 原书 p.162 正文把 `27/35` 写成变成 `28/26`，显系印刷笔误（应为 `28/36`：胜局数与模拟数各 +1）。

```
function MONTE-CARLO-TREE-SEARCH(state) returns an action
    tree ← NODE(state)
    while IS-TIME-REMAINING() do
        leaf ← SELECT(tree)
        child ← EXPAND(leaf)
        result ← SIMULATE(child)
        BACK-PROPAGATE(result, child)
    return the move in ACTIONS(state) whose node has highest number of playouts
```

重复这四步，直到达到设定的迭代次数或时间用尽，然后返回**模拟次数最多**的走法。

**UCT 选择策略**：一种非常有效的选择策略叫 **UCT**（upper confidence bounds applied to trees），它按 **UCB1** 上置信界公式为节点 `n` 的每个可能走法排名（细节见 §17.3.3）：

```
UCB1(n) = U(n)/N(n) + C × sqrt( log N(PARENT(n)) / N(n) )
```

| 符号 | 含义 |
|---|---|
| `U(n)` | 所有经过节点 `n` 的模拟的**总效用** |
| `N(n)` | 经过节点 `n` 的模拟**次数** |
| `PARENT(n)` | `n` 在树中的父节点 |

**`U(n)/N(n)` 是利用项**（`n` 的平均效用）；**带平方根的项是探索项**——分母是计数 `N(n)`，所以**只被探索过很少次的节点该项会很大**；分子是父节点被探索次数的 `log`。这意味着：只要我们以某个**非零比例**选择 `n`，探索项会随计数增加而**趋于零**，最终模拟次数集中给平均效用最高的节点。`C` 是平衡利用与探索的常数。**有理论论证 `C` 应为 `√2`**，但实践中博弈程序员会试多个 `C` 值并选表现最好的。（有些程序用略有不同的公式；例如 `ALPHAZERO` 加入一项**走法概率**，由从过去自我对弈训练的神经网络计算。）在 Figure 5.10 中，取 **`C = 1.4`** 时 60/79 节点的 UCB1 分数最高；取 **`C = 1.5`** 时则是 2/11 那个节点。

> **为什么返回"模拟次数最多"而不是"平均效用最高"？** 你也许觉得后者更好，但思路是：一个 `65/100` 胜的节点好过一个 `2/3` 胜的节点，因为后者不确定性太大。无论如何，UCB1 公式保证了**模拟次数最多的节点几乎总是胜率最高的节点**，因为随着模拟次数增加，选择过程越来越偏向胜率。

**为什么 MCTS 能做得这么深**：一次模拟的时间对博弈树深度是**线性**而非指数的，因为每个选择点只走一步。原书算例：分支因子 `32`、平均一局 `100` ply 的博弈，若算力足以在必须走棋前考虑**十亿**个博弈状态，则 minimax 能搜 **6 ply** 深、完美排序的 α–β 能搜 **12 ply**、蒙特卡洛搜索能做 **1000 万次模拟**。哪种更好？取决于启发式函数的准确度 vs. 选择策略与模拟策略的准确度。

**MCTS 相对 α–β 的优劣（原书立场）**：

| MCTS 的优势 | MCTS 的劣势 |
|---|---|
| 分支因子很高（α–β 搜不深）时，如围棋 | **单个走法可能改变全局走势**时——随机性意味着它**可能根本没考虑到**那个走法；即 MCTS 中的 Type B 剪枝意味着**一条关键线路可能完全没被探索** |
| 难以定义好的评估函数时 | 局面"明显"（按人类知识与评估函数）一方必胜、但一次模拟要走很多步才能验证胜者时 |
| 依赖**多次模拟的聚合**，不像 α–β 那样会被**单个节点的一次误算**击穿 | — |
| 可用于**全新**博弈：只要知道规则，不需要任何额外经验 | — |

α–β 做的是选一条通向"在对手会尽量压低分数的前提下可达到的**最高评估函数分数**"的节点的路径，因此**若评估函数不准确，α–β 就不准确**——单个节点上的一次误算就可能导致它错误地选择（或避开）通向该节点的路径。也可以把两者结合：做一定步数的模拟后**截断**模拟并应用评估函数；或在可能走很多步的博弈中使用**早期模拟终止**（early playout termination）——停掉一次走了太多步的模拟，用启发式评估函数评估它，或干脆判和。选择与模拟策略在有手工专家知识时能很好地利用它，但好的策略也可以只用**通过自我对弈训练的神经网络**学到。长期以来人们认为 α–β 更适合国际象棋这类低分支因子、有好的评估函数的博弈，但近来蒙特卡洛方法在国际象棋等其他博弈中也取得了成功。向未来模拟走法、观察结果、用结果判断哪些走法好——这个一般思想是一类**强化学习**，第 22 章覆盖。

## 5.5 随机博弈（Stochastic Games）

**随机博弈**加入随机元素（如掷骰子），让我们更接近真实生活的不可预测性。西洋双陆棋是典型的随机博弈，结合了运气与技巧。

**例（Figure 5.12，双陆）**：原书正文说 White 掷了 **6–5**，有四种可能走法（每种都是把一枚棋子向前（顺时针）移 5 格、另一枚向前移 6 格）。

> ⚠️ **待核**：原书 p.164 正文写 "White has rolled a 6–5"，而 Figure 5.12 的图注写 "Black has rolled 6–5"，并列出四种走法 `(5–11,5–10)`、`(5–11,19–24)`、`(5–10,10–16)`、`(5–11,11–16)`。二者不一致，疑为原书笔误。

**机会节点**：在这一步，Black 知道可以走哪些走法，但**不知道 White 会掷出什么**，因而不知道 White 的合法走法是什么。这意味着 Black 无法构造我们在国际象棋和井字棋中看到的那类标准博弈树——双陆的博弈树除了 MAX 与 MIN 节点，还必须包含**机会节点**（chance nodes，Figure 5.13 中画成圆形）。从每个机会节点出发的分支表示可能的骰子点数，每条分支标着该点数和它的概率：掷两个骰子有 **36** 种方式、每种等可能，但因为 6–5 与 5–6 相同，只有 **21** 种不同的点数；六个对子（1–1 到 6–6）各有概率 `1/36`，即 `P(1–1) = 1/36`；其余 **15** 种不同点数各有概率 `1/18`。

**期望 minimax（expectiminimax）**：局面不再有确定的 minimax 值，我们只能计算一个局面的**期望值**——对机会节点所有可能结果取平均。这就引出含机会节点博弈的 **expectiminimax 值**，它是确定性博弈 minimax 值的推广：

```
EXPECTIMINIMAX(s) =
    UTILITY(s, MAX)                          if IS-TERMINAL(s)
    max_a EXPECTIMINIMAX(RESULT(s, a))       if TO-MOVE(s) = MAX
    min_a EXPECTIMINIMAX(RESULT(s, a))       if TO-MOVE(s) = MIN
    Σ_r P(r) EXPECTIMINIMAX(RESULT(s, r))    if TO-MOVE(s) = CHANCE
```

- 终止节点以及 MAX、MIN 节点的工作方式与之前**完全一样**（一点保留：MAX 与 MIN 的合法走法将取决于前一个机会节点掷骰子的结果）。
- 对机会节点计算期望值：所有结果的值之和，按每个机会动作的概率加权。其中 `r` 表示一个可能的骰子点数（或其他机会事件），`RESULT(s, r)` 与 `s` 相同，只是附加了"骰子结果是 `r`"这一事实。

### 5.5.1 机会博弈的评估函数

与 minimax 一样，对 expectiminimax 最明显的近似是在某处截断搜索、并对每个叶应用评估函数。有人可能以为双陆这类博弈的评估函数就该和国际象棋的一样——只需给更好的局面更高的值。但事实上，**机会节点的存在意味着必须更小心地对待这些值的含义**。

**Figure 5.14 的反例**：

| 叶值 | 最佳走法 |
|---|---|
| `[1, 2, 3, 4]` | `a1` |
| `[1, 20, 30, 400]` | `a2` |

也就是说，即使**偏好顺序保持不变**，只要改动某些评估值，程序的行为就完全不同。

> **结论**：为避开这个问题，**评估函数必须返回获胜概率（或对有胜/负之外结局的博弈，期望效用）的正线性变换**。这种与概率的关系是"涉及不确定性的情形"的一个重要而普遍的性质，第 16 章会进一步讨论。

**代价（T7 逐字抄）**：若程序事先知道余下所有骰子点数，求解带骰子的博弈就和求解不带骰子的博弈一样，minimax 用 **`O(b^m)`** 时间完成（`b` 为分支因子、`m` 为最大深度）；因为 expectiminimax 还要考虑所有可能的掷骰序列，它将要 **`O(b^m n^m)`**（`n` 为不同点数的种数）。即使把搜索限制在小深度 `d`，相比 minimax 的额外代价也使"往前看很远"在多数机会博弈中不现实：双陆里 `n = 21`，`b` 通常约 `20`，但掷出对子时可高达 **4000**，我们大概只能做 **3 ply** 的搜索。

**换个角度理解**：α–β 的优势在于它忽略那些在最佳走法下**根本不会发生**的后续发展，从而集中在**很可能发生的事件**上。但在每步之前都要掷两个骰子的博弈中，**没有很可能的走法序列**——即使是最可能的走法也只有 **`2/36`** 的时间会发生，因为要让这个走法发生，骰子必须先掷出恰好使它合法的点数。这是不确定性进入画面时的一般问题：**可能性被极大地倍增，制定详细的行动计划变得毫无意义，因为世界大概不会配合**。

**机会节点也能剪枝**：事实证明可以——对 MIN 与 MAX 节点的分析不变，稍加巧思也可以剪机会节点。考虑 Figure 5.13 中的机会节点 `C`：在看完它**所有**子结点之前，能找到 `C` 的值的**上界**吗？初看似乎不可能，因为 `C` 的值是它子结点值的**平均**，而要算平均必须看完所有数。**但如果我们给效用函数的可能取值加上界，就能在不看每个数的情况下得到平均的界**——例如设所有效用值在 `−2` 与 `+2` 之间，那么叶值有界，进而可以不看全部子结点就给机会节点的值放一个上界。

在机会节点分支因子很高的博弈中——想想 **Yahtzee**，每回合掷 5 个骰子——你可能想考虑**前向剪枝**，只采样较少数量的可能机会分支；或者你可能想完全不用评估函数，改用**蒙特卡洛树搜索**，让每次模拟都包含随机掷骰。

## 5.6 部分可观测博弈（Partially Observable Games）

Bobby Fischer 宣称"国际象棋是战争"，但国际象棋缺少真实战争的至少一个主要特征：**部分可观测性**。在"战争迷雾"中，敌方单位的位置常常直到直接接触才被揭露；因此战争包括用侦察兵与间谍收集信息，以及用隐蔽与**诈唬**（bluff）迷惑敌人。部分可观测博弈具有这些特征，因而与前面几节的博弈**有质的不同**。《星际争霸》这类视频博弈特别有挑战性：**部分可观测、多智能体、非确定性、动态、且未知**。

在**确定性**部分可观测博弈中，对棋盘状态的不确定性**完全来自无法获知对手的选择**。这一类包括儿童游戏 Battleship（船的位置对对手隐藏）与 Stratego（棋子位置已知但类型隐藏）。我们将考察 **Kriegspiel**——一种部分可观测的国际象棋变体，棋子对对手**完全不可见**。其他博弈也有部分可观测版本：Phantom Go、Phantom tic-tac-toe、Screen Shogi。

### 5.6.1 Kriegspiel：部分可观测的国际象棋

**规则**：

- 白方与黑方各自看到一张**只含自己棋子**的棋盘。一位能看到所有棋子的**裁判**裁定比赛，并定期做出**双方都能听到**的宣告。
- 白方先向裁判提议一步"若没有黑子就会合法"的走法。若黑子阻止了这步，裁判宣告 **"illegal"（非法）**，白方继续提议直到找到合法的——并在过程中**逐步了解到黑子的位置**。
- 一旦提出合法走法，裁判宣告下列之一或多条：**"Capture on square X"**（若有吃子）；**"Check by D"**（若黑王被将军，`D` 是将军方向，可为 `Knight`（马）、`Rank`（横排）、`File`（竖线）、`Long diagonal`（长斜线）、`Short diagonal`（短斜线））；若黑被将死或逼和，裁判会说明；否则轮到黑走。

**信念状态**：Kriegspiel 看起来可怕得不可能下，但人类应付得相当好，计算机程序也正在赶上。回想 §4.4 的**信念状态**（belief state）——给定迄今完整感知历史，所有**逻辑上可能**的棋盘状态的集合——会有所帮助。初始时它是**单元素集**（黑子还没动）；白走一步、黑回应后包含 **20 个**局面（黑对任何开局走法都有 20 种应对）。随博弈推进跟踪信念状态正是**状态估计**问题，更新步骤由 p.132 的**式 (4.6)** 给出。若**把对手视为非确定性的来源**，就能把 Kriegspiel 的状态估计直接映射到 §4.4 的框架上：白方走法的 `RESULT` 由白方自己走法的（可预测的）结果与黑方回应给出的（不可预测的）结果**组合**而成。

> 原书脚注：有时信念状态会大到无法只表示成一张局面列表；第 7、8 章提出紧凑表示超大信念状态的方法。

**策略概念被改变**：对部分可观测博弈，策略不再是"为对手可能走的每个**走法**指定一个走法"，而是要为**每个可能收到的感知序列**指定一个走法。

**保证将死**（guaranteed checkmate）：一个致胜策略（或保证将死）指：对**每个可能的感知序列**，它都导致对当前信念状态中**每一个**可能棋盘状态的**实际将死**，无论对手怎么走。在这个定义下，**对手的信念状态无关紧要**——该策略即使对手能看到所有棋子也必须有效，这**大大简化了计算**。Figure 5.15 展示了 KRK（王车对王）残局中一个保证将死的一部分（黑只有一个王，故信念状态可在一张棋盘上标出）。通用 **AND–OR 搜索**可应用于信念状态空间来找保证将死，正如 §4.4；§4.4.2 的**增量信念状态算法**常能找到深度达 **9** 的中局将死——远超多数人类。

**概率将死**（probabilistic checkmate）：这是 Kriegspiel 引入的、在完全可观测博弈中**毫无意义**的全新概念。这类将死仍要求在信念状态的**每个**棋盘状态下都成立；"概率性"是相对于**获胜方自己走法的随机化**而言的。

- 基本概念：只用白王去找一个孤立的黑王，仅仅**随机移动**白王最终就会撞上黑王，即使后者试图躲避——因为黑不可能一直猜对躲避的走法。用概率论的术语说，**侦测以概率 1 发生**。
- **KBNK**（王象马对王）在这个意义上是赢的：白方向黑方呈现一个**无限长的随机选择序列**，其中某个选择黑会猜错并暴露位置，导致被将死。
- **KBBK** 以概率 **`1 − ε`** 获胜：白方只有把一只象**无保护**地留一步才能强制取胜；若黑恰好在正确位置吃掉那只象（这步在双象被保护时非法），棋局成和。白方可以在一段很长的序列中某个**随机选择的时刻**走这步险棋，把 `ε` 缩小到**任意小的常数**，但**不能降到零**。

**偶然将死**（accidental checkmate）：有时一个将死策略只对信念状态中的**某些**棋盘状态有效。尝试它可能成功，导致一次**偶然将死**——"偶然"是指白方**不可能知道**那会是将死——如果黑的棋子恰好在正确的位置。（人类对局中的多数将死都是这种偶然性质。）这自然引出两问：给定策略获胜的可能性有多大？信念状态中每个棋盘状态是**真实**棋盘状态的可能性有多大？

**各棋盘状态的概率该怎么算？** 第一个念头是"所有棋盘状态**等可能**"——但这不对：黑走了第一步之后，按定义（假设黑走最优）黑必定走了**最优**走法，所以所有由**次优**走法产生的状态应赋 **0 概率**。这个论证也不完全正确——每位玩家的目标不只是把棋子走到正确的格子，**还要最小化对手掌握的关于它们位置的信息**；走任何**可预测的**"最优"策略都会给对手提供信息。因此**部分可观测博弈中的最优玩法要求愿意以某种程度随机地走**（这就是餐馆卫生检查员做随机抽查的原因）：偶尔选择看起来"内在地"弱的走法，它们从**不可预测性**本身获得力量，因为对手不太可能针对它们准备过任何防御。

于是形成两难：各状态的概率只有在给定**最优随机化策略**时才能算出，而计算那个策略又需要知道各状态的概率。这个两难可用博弈论的**均衡解**（equilibrium solution）概念解决（原书指向第 17 章；§5.6 末尾又指向 §18.2）。一个**均衡**为每个玩家指定一个最优随机化策略。但对 Kriegspiel 计算均衡太昂贵，为一般 Kriegspiel 对局设计有效算法仍是**开放的研究课题**。目前多数系统在**自己的**信念状态空间中做有界深度前瞻、**忽略对手的信念状态**；评估函数与可观测博弈的相似，但多一个关于**信念状态大小**的分量——**越小越好**！

### 5.6.2 纸牌博弈

桥牌、惠斯特、红心大战、扑克等纸牌博弈具有**随机的部分可观测性**：缺失的信息由**随机发牌**产生。

**一个诱人但错误的类比**：初看，这些纸牌博弈似乎和掷骰子的博弈一样——牌随机发出、决定每个玩家可用的走法，只是**所有"骰子"在一开始就掷完了**！这个类比结果**是不正确的**，但它提示了一种算法：把博弈的**开始**当作一个机会节点，每种可能的牌局作为一个结果，用 **`EXPECTIMINIMAX`** 公式选最佳走法。注意这里**唯一的机会节点是根节点**，之后博弈变成完全可观测。这种方法有时称为**对超视者取平均**（averaging over clairvoyance），因为它假定一旦实际牌局发生，博弈就对双方都完全可观测。

**它为什么会把人引入歧途（原书的"三岔路"故事）**：

| | 情形 | "对超视者取平均"的结论 |
|---|---|---|
| 第 1 / 2 天 | 路 A 通向一罐金子；路 B 通向岔路口，你**能看见**哪条岔路通向两罐金子、哪条通向被公交车撞（两天左右相反） | B 是正确选择 |
| 第 3 天 | 路 A 通向一罐金子；路 B 通向岔路口，你被告知一条岔路通向两罐金子、另一条通向被公交车撞，**但不知道哪条是哪条** | 情形与第 1 天或第 2 天相同，所以 **B 一定仍是正确选择** |

**错在哪**：**它不考虑智能体行动后所处的信念状态。** 完全无知的信念状态是不可取的，尤其当其中一种可能是**必死**的时候。因为它假定每个未来状态都会自动成为完全知识的状态，超视者方法**永远不会**选择**收集信息**的动作（如 Figure 5.15 的第一步）；**不会**选择**对对手隐藏信息**或**给同伴提供信息**的动作（它假定他们**已经**知道这些信息）；在扑克中**永远不会诈唬**（它假定对手能看到它的牌）。

> 原书脚注：**诈唬**——即使手牌不好，也像手牌很好那样下注——是扑克策略的核心部分。

第 17 章会展示如何构造能完成所有这些事情的算法——求解真正的部分可观测决策问题，得到**最优均衡策略**（另见 §18.2）。

**尽管有这些缺点，加上一些技巧，"对超视者取平均"仍可以是有效策略**：

| 技巧 | 说明 |
|---|---|
| **抽象**（abstraction） | 桥牌里每位玩家只看到四手牌中的两手，两暗手各 13 张，牌局数 `C(26,13) = 10,400,600`；求解**一个**牌局已相当困难。于是把**相似的牌手看作相同**（一手牌里有哪些 A 和 K 很重要，但有 4 还是 5 不那么重要，可以抽象掉） |
| **前向剪枝** | 只取 `N` 个牌局的小随机样本再算 `EXPECTIMINIMAX`。即使 `N` 相当小——比如 **100 到 1000**——也给出不错的近似。也可用于 Kriegspiel 这类确定性博弈：只要能估计每个状态有多可能，就在**博弈的可能状态**上采样 |
| **深度截断** | 用带深度截断的启发式搜索，而不是搜索整棵博弈树 |

**叫牌带来的额外复杂性**：到目前为止我们假定每种牌局等可能——对惠斯特、红心大战这是合理的。但桥牌在打牌之前有一个**叫牌阶段**，每队表明自己期望赢多少墩；**由于玩家基于自己手上的牌叫牌，其他玩家能学到关于每种牌局概率 `P(s)` 的一些信息**。把这点考虑进去是棘手的，原因正是 Kriegspiel 那里提到的：**玩家可能以最小化传递给对手的信息的方式叫牌**。

**扑克上的超人表现**：扑克程序 **Libratus** 在一场为期 **20 天**的无限注德州扑克比赛中对阵**四位世界顶级**扑克玩家，决定性地击败了他们全部。由于扑克状态太多，它用**抽象**缩减状态空间：可能认为 `AAA72` 与 `AAA64` 等价（都是"三个 A 加一些小牌"），把 `200` 美元的注与 `201` 美元看作相同。但它也**监视**其他玩家：一旦发现他们在利用某个抽象，它会在**隔夜**做额外计算补上这个漏洞。总的来说它在一台超级计算机上用了 **2500 万 CPU 小时**才拿下这场胜利。

**计算代价的含义**：Libratus（以及 `ALPHAZERO` 等系统的类似开销）付出的代价说明，**世界冠军级的博弈水平可能不是预算有限的研究者能做到的**。就像不该指望用车库零件组装出冠军级 F1 赛车，能用上超级计算机或 TPU 这类专用硬件确有优势——这在**训练**时尤其明显。但训练也可以**众包**：开源系统 **LEELA ZERO** 是 `ALPHAZERO` 的重新实现，靠志愿者计算机上的自我对弈训练；而一旦训练完成，**实际比赛所需的计算量是适度的**——**ALPHASTAR** 在一台配单个 GPU 的普通台式机上就赢了《星际争霸 II》的对局，`ALPHAZERO` 本来也可以在这种模式下运行。

## 5.7 博弈搜索算法的局限（Limitations of Game Search Algorithms）

由于在复杂博弈中计算最优决策是**难解的**（intractable），所有算法都必须做某种假设与近似：α–β 用启发式评估函数作近似，蒙特卡洛搜索对随机选择的模拟计算近似平均。选哪个算法部分取决于每个博弈的特征——**分支因子高、或难以定义评估函数时，偏好蒙特卡洛搜索**。但两者都有**根本性**的局限。

**局限一：α–β 易受启发式函数误差影响。** Figure 5.16 展示了一棵两层博弈树，minimax 建议走**右**分支，因为 `100 > 99`。若所有评估值**完全准确**，那是对的走法。但假设每个节点的评估有与其他节点**独立**、标准差为 `σ` 的随机误差，那么：

| `σ` | 左分支实际上更好的比例 |
|---|---|
| `5` | **71%** |
| `2` | **58%** |

（因为在这些情形下，右分支**四个**叶节点之一很可能滑到 `99` 以下。）若评估函数的误差**不独立**，出错的机会上升。补偿这一点很困难，因为我们对**兄弟节点取值之间的依赖关系**没有一个好模型。

> ⚠️ **待核**：Figure 5.16 的树形只存在于图片中，PDF 文本层无数值；正文仅给出"右分支 minimax 值 `100`、左分支 `99`、右分支有四个叶"。

**局限二（α–β 与蒙特卡洛共有）：它们只会算走法的（界的）值。** 但有时有一步**明显最好**（例如只有一步合法走法），此时浪费计算时间去算这步的值毫无意义——不如直接走。更好的搜索算法会用**节点扩展的效用**（utility of a node expansion）这一思想：选择**高效用**的节点扩展，即那些**可能导致发现明显更好的走法**的扩展；若**没有**哪个扩展的效用高于它的时间代价，算法就应当停止搜索并走棋。这不仅适用于"明显最优"的情形，也适用于**对称走法**——那种情况下搜多久都不会显示某一步比另一步好。这种关于"该做哪些计算"的推理叫**元推理**（metareasoning，关于推理的推理），适用于任何种类的推理：所有计算都为达成**更好的决策**而做，都有**代价**，也都有**某种导致决策质量有一定改进的可能性**。蒙特卡洛搜索确实**试图**做元推理，把资源分配给树中最重要的部分，但**做得并不是最优**。

**局限三：两者都把全部推理放在单个走法的层面上。** 显然人类下棋的方式不同：他们能在**更抽象的层面**上推理，考虑一个更高层的目标——例如**困住对方的后**——并用该目标**选择性地生成有道理的计划**。第 11 章将研究这类规划，§11.4 会展示如何用从抽象到具体的层次结构来规划。

**局限四：把机器学习结合进博弈搜索过程的能力。** 早期博弈程序依赖**人类专长**手工打造评估函数、开局书、搜索策略与效率技巧。我们才刚开始看到像 `ALPHAZERO`（Silver et al., 2018）这样**依赖来自自我对弈的机器学习、而非博弈专用的人类生成专长**的程序。第 19 章起深入覆盖机器学习。

## 小结

1. **博弈**可由初始状态（棋盘如何摆设）、每状态下的合法动作、每个动作的结果、终止测试（说明博弈何时结束）、以及作用于终止状态以说明谁赢、最终比分是多少的效用函数来定义。
2. 在**双人、离散、确定性、轮流、零和、完美信息**的博弈中，**minimax 算法**可以通过对博弈树做深度优先枚举来选出最优走法。
3. **alpha–beta 搜索算法**算出与 minimax **相同**的最优走法，但通过消除**可证明无关**的子树获得了高得多的效率。
4. 通常我们不可能考虑整棵博弈树（即便用了 α–β），所以需要在某处截断搜索，并应用**启发式评估函数**来估计状态的效用。
5. 另一种选择是**蒙特卡洛树搜索（MCTS）**：它不用启发式函数评估状态，而是把博弈**一路走到底**、用博弈规则看谁赢；由于模拟中选的走法未必是最优走法，这个过程要重复多次，评估是各次结果的**平均**。
6. 许多博弈程序**预先计算**开局与残局的最佳走法表，以便**查表**而不是搜索。
7. **机会博弈**可用 **expectiminimax** 处理——它是 minimax 的扩展，对机会节点取其所有子结点效用的**加权平均**（权重为每个子结点的概率）。
8. 在**不完全信息**博弈（如 Kriegspiel、扑克）中，最优玩法需要对每位玩家**当前与未来的信念状态**做推理。一种简单的近似是：把动作的值对**缺失信息的每种可能配置**取平均。
9. 程序已大败人类冠军于国际象棋、跳棋、黑白棋、围棋、扑克及许多其他博弈。人类在少数**不完全信息**博弈（如桥牌与 Kriegspiel）中仍保有优势。在《星际争霸》《Dota 2》等视频博弈中，程序已能与人类专家竞争，但它们的部分成功可能来自**极快地执行大量动作**的能力。

**原书文献与历史注记（摘选）**

- 1846 年 Charles Babbage 讨论过计算机下国际象棋与跳棋的可行性，但不理解搜索树的指数复杂度；第一台博弈机器由西班牙工程师 Leonardo Torres y Quevedo 于约 1890 年造出，专攻 KRK 残局。
- **minimax** 追溯到 Ernst Zermelo（1912）；**expectiminimax** 由 Donald Michie（1966）提出；Bruce Ballard（1983）把 α–β 剪枝扩展到含机会节点的树。**alpha–beta** 由 John McCarthy 于 1956 年构想（Hart and Edwards, 1961 才付印）；Knuth and Moore（1975）证明其正确性并分析复杂度；Pearl（1982b）证明它在所有固定深度博弈树搜索算法中**渐近最优**。
- Claude Shannon 的 *Programming a Computer for Playing Chess*（1950）一举列出了几乎所有主要思想：局面表示、评估函数、静态搜索、选择性博弈树搜索。Slater（1950）提出把评估函数作为特征的线性组合。
- **MCTS** 由 Abramson（1987）引入；Brügmann（1993）用于围棋；Kocsis and Szepesvari（2006）以 UCT 选择机制改进。Monte Carlo 模拟本身由 Metropolis and Ulam（1949）开创。
- 里程碑：国际象棋 Fredkin 奖历届得主 `BELLE`（首个大师水平）、`DEEP THOUGHT`（首个国际大师水平）、**深蓝**（1997 年表演赛击败 Kasparov，以每秒 1 亿+局面跑 α–β，借助奇异延伸偶尔达 40 ply）；今日 `STOCKFISH` 等把**有效分支因子降到 3 以下**，单核百万节点/秒搜到约 20 ply，用零着启发式（null move）与无效剪枝（futility pruning）。
- 残局表：逆向分析来自 Bellman（1965）；Thompson 与 Stiller 解出所有五子及以内残局（Stiller 发现一个需 **262 步**的强制杀，曾引起不安，因为规则要求 50 步内须有吃子或兵的移动）。2012 年 Lomonosov 表解出所有七子及以内残局，7 子表占 **140 TB**。
- 跳棋：Samuel（1959, 1967）用强化学习从自我对弈中学评估函数；2007 年 Schaeffer 等人"解决"了跳棋——**完美走法下是和棋**（10 子残局表 39 万亿条目，另加 18 CPU-年 α–β）。
- 扑克：2017 年 `Libratus`（Brown and Sandholm）与 `DeepStack`（Moravčík et al.）首次在单挑无限注德州扑克中击败冠军选手；2019 年 `Pluribus` 在六人桌击败顶级职业选手。另：`MENACE`（Michie, 1963）用 304 个火柴盒学井字棋；`ALPHASTAR`（Vinyals et al., 2019）以 10:1 击败《星际争霸 II》专家人类玩家。
