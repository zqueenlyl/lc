抽象的两条标准：抽象必须有效（抽掉细节后仍能构造解）且有用（解能映射回原问题并执行）。 例子：从 Arad 开车去 Bucharest，抽象掉「沿路每个轮胎转动的角度、收音机里播了什么」，但如果把「加油站位置」也抽象掉，解就执行不了。
状态空间为什么必然是指数的：旅行商问题——从起点出发，第一个目的地有 n−1 种选法，第二个有 n−2 种…… 状态数 (n−1)!。搜索不是在「找一条路」，是在一棵大小对 n 指数增长的树里决定展开哪些分支。

颜色 = 被展开的顺序（浅 → 深 = 先 → 后）。 深灰格是障碍。青框 = 起点，金框 = 终点。
把 W 从 0 拉到 6 看三件事： ① W = 0：f = g，就是 UCS／Dijkstra，等值线是以起点为心的同心圆——它朝所有方向均匀扩张，完全不看目标在哪。 ② W = 1：A*，等值线被朝目标方向拉长成椭圆，横向几乎不扩张。 ③ W 越大：椭圆越窄，越贴着直线走——扩展的节点少了，但一旦被障碍挡住就要绕大弯，解不再最优。
为什么 A* 的等值线是椭圆：h 是到目标的直线距离，g 是已走路程。 g + h ≤ C 的轨迹，正是「以起点和目标为焦点、长轴为 C 的椭圆」。这个几何图像比任何公式都直观。

可采纳 ≠ 一致：一个可以自己改坏的实验室

拖滑块改 h 值，实时检查两条条件，看 A* 什么时候开始返回次优解。

h(A)3 h(B)2 h(C)1
两条条件的准确说法： 可采纳 h(n) ≤ h*(n)——不高估到目标的真实代价（只看单个节点）。 一致（= 单调） h(n) ≤ c(n,a,n′) + h(n′)——满足三角形不等式（看每条边）。 一致 ⇒ 可采纳，反之不成立。
动手找「可采纳但不一致」：把 h(B) 拖到 0，h(A) 拖到 4。 此时 h(A) = 4 = h*(A)，可采纳仍成立；但 h(A) = 4 > c(A,B) + h(B) = 1 + 0 = 1，不一致。 结论：A* 依然返回最优解 4。——因为最优性只需要可采纳。 一致性给的是另一件事：效率。不一致时，一个状态可能先以偏大的 g 被展开、之后才发现更便宜的路， 于是同一状态在边缘里留有多个副本、被多次展开。一致时这种情况不会发生，每个节点只展开一次。
动手找「次优」：把三个 h 都拖到 8（全部高估，不可采纳）。 A* 会返回 8 而不是最优 4 —— 它直接走了 A→G 那条 8 的路，因为 h 谎报「从 A 出发还要 8 步」， 把真正最优的 A→B→C→G 掩盖掉了。最优性保证的失效，只由「高估」引起，不由「不一致」引起。
h 太小会怎样：把三个 h 全拖到 0，A* 退化成 UCS——仍然最优，但扩展节点数暴涨。 占优（domination）：若 h₂ ≥ h₁ 且都可采纳，则 h₂ 占优 h₁，A*(h₂) 扩展的节点绝不会比 A*(h₁) 多。下一屏有实测数字。

b*（有效分支因子）怎么来的：若一棵深度为 d 的树有 N 个节点， 解 N = 1 + b* + (b*)² + … + (b*)^d 得到 b*。 b* 越接近 1，说明启发式把搜索压得越"细"。原书 Figure 3.26：d = 24 时 BFS 扩展 290082、A*(h₁) 53039、A*(h₂) 5733，对应 b* 分别约 1.62 / 1.50 / 1.36。
为什么 h₂ 占优 h₁：h₁ 只数"有几个格子放错了"，h₂ 数"每个放错的格子离正确位置有几步"。 每一步移动最多让 h₂ 减 1，也最多让 h₁ 减 1，所以两者都可采纳；而 h₂ ≥ h₁ 恒成立 → h₂ 占优。 另一个角度（松弛问题）：允许滑块直接穿过邻居 → 得到 h₂；再允许滑块直接跳到任意格 → 得到 h₁。 约束删得越多， admissible 的 h 越小、越弱。
为什么 BFS 也能跑完：八数码状态空间只有 9!/2 = 181 440 个可达状态， 所以暴力枚举是可行的——这正好让它成为一个能在浏览器里跑出真实数字的教科书例子。 把 k 拉到 24 以上再跑，你会看到三个数字拉开几个数量级。

内存不够怎么办：IDA* 用时间换空间

A* 的瓶颈从来不是时间，是内存——它要把整个边缘都留在内存里。 IDA* 每次只存一条 DFS 路径，代价是反复重算。

IDA* 在做什么：它是迭代加深和 A* 的合体—— 每轮做一次 f 值受限的 DFS，阈值取上一轮刚超过它的最小 f 值。 于是等值线一轮一轮往外推，直到碰到目标。每轮都从头重算，看起来很浪费， 但节点总数通常只比 A* 多一点点（因为绝大多数节点都在最后一轮）。
三兄弟的取舍： IDA* 内存 O(d)、不保存已访问表（同一状态会重复生成）、改 h 后重跑很贵。 RBFS 也是线性内存，会把被遗忘子树的最好 f 值回传给父节点，靠"f_limit"决定何时回头。 SMA* 则反过来：一直按 A* 跑，直到内存填满，然后丢掉最差的叶子并把它的值回传给父节点—— 内存给多少用多少，代价是可能颠簸（thrashing）：在两个子树间反复来回。

四个最易混的地方

「完备」≠「最优」完备 = 找得到解；最优 = 找到代价最小的解。BFS 只在单位代价下才最优——这不是因为它聪明，是因为它恰好按层数展开。
图搜索 vs 树状搜索 ≠ 状态空间是图还是树状态空间永远是图。区别只在于要不要查冗余路径（维护 reached 表）。不查就会把同一状态反复展开。
UCS 必须晚期目标测试生成即测会把一条还躺在边缘里的更贵路径当成答案。第 ② 屏有 310 vs 278 的现场复现。
迭代加深的时间并没有变差IDS 的时间仍是 O(bᵈ)，因为绝大多数节点都在最深一层。它换来的是空间从 O(bᵈ) 降到 O(bd)。
可采纳 ≠ 一致一致 ⇒ 可采纳，反之不成立。一致时节点第一次弹出即在最优路径上，无需重入队。第 ④ 屏可自己造反例。
启发式的分界线是"能否估计离目标多远"不是"是否用队列"。BFS 和 UCS 都用队列，但都不看目标在哪，所以都是无信息的。

为什么随机重启几乎必然成功（概率 1 完备）：每次随机重启成功概率 p ≈ 0.14， 失败概率 0.86，k 次全失败的概率 0.86ᵏ → 0。期望重启次数 1/0.14 ≈ 7 次。 加上侧向移动后 p ≈ 0.94，期望只要 1.06 次。 这是本章最实用的一条：一个不完备的算法，随机重启几下就几乎完备了，而代码只多了三行。

为什么"允许下坡"就能找到全局最优：爬山的问题不是它走错方向，是它太确定了—— 一旦走进局部极大值的吸引域就出不来。退火在高温时几乎随机游走（能跨过任意宽的山谷）， 随着 T 下降逐渐变得挑剔，最后在 T → 0 时退化成纯爬山。 如果降温足够慢，找到全局最优的概率趋于 1。
直觉图像：乒乓球掉进一个崎岖的表面。如果只让它滚，它会停在最近的凹坑。 如果一边摇动表面一边让它滚，它就能跳出浅坑、最终落进最深的那个。 T 就是"摇动的强度"——摇得太猛（T₀ 太大）等于纯随机，摇得太轻（降温太快）等于爬山。

局部极大值 / 山脊 / 高原：三种困境长什么样

在一维地形上看小球爬山。切换地形，看它卡在哪、能不能出来。

地形 步长 5
山脊是最反直觉的一种：在一维/二维里，山脊看起来是"一条窄窄的山顶线"， 你以为沿着它走就行。但真实问题有几百、几千维，每个维度上的可用步长都是离散的， 沿着山脊方向前进的那一步往往在网格上根本不存在。 所以"沿着山脊走"这个低维直觉在高维空间不成立——笔记明确把这一点列为易混点。
高原要分两种：平坦局部极大值是真正的死路（周围全是同高度，算法判定"没有更好的后继"而停止）； 山肩则是"当前这一步是平的，但再走一步就能继续上升"。 爬山算法如果不允许侧向移动，会在山肩上也停下来——这就是为什么允许侧向移动能把成功率从 14% 提到 94%。

目标函数 f(x) = x⁴/4 − x²/2，极小值在 x = ±1（f = −0.25）， x = 0 处是一个局部极大值。

起点 x₀ 1.50 学习率 α 0.30 迭代次数 12

牛顿–拉弗森x ← x − f′(x)/f″(x)　用二阶信息直接跳到二次近似的顶点。起点选得好时两步就到 ±1，但高维时求海塞矩阵的逆非常昂贵。
⚠️ 牛顿法找的是驻点，不是极小值：把 x₀ 拖到 0.3 —— 牛顿会收敛到 x = 0， 而 x = 0 是本函数的局部极大值！因为牛顿法求解的是 f′(x) = 0， 它分辨不出极大、极小和鞍点。判断要靠二阶导：f″(0) = −1 < 0 → 极大。 梯度下降反而会"沿着下坡方向"正确走到 ±1。 所以牛顿法快，但要求起点已经在正确的吸引域里。
为什么"减小 δ 不保证收敛到全局最优"：离散化连续空间后做最陡上升，等价于经验梯度法。 步长 δ 越小，越容易卡在局部极值（因为一次只能看到很小的邻域）。 离散化解决的是"怎么在连续空间里定义后继"，不是"怎么跳出局部最优"。

AND–OR 搜索：与节点是环境选，不是你选

打滑的吸尘器：Suck 在一个脏格子里，有时只清当前格，有时连另一格也清了； 在干净格子里有时还会掉灰。解不再是动作序列，而是条件规划。

求出的条件规划

与节点（AND）= 环境做选择。这是本节最容易搞混的一点： OR 节点由智能体挑一个动作（任选其一即可），AND 节点由环境挑结果—— 而 AND 节点的每一条出边都必须被处理成功，否则整个动作不成立。图上 AND 节点用一条弧把出边连起来。
环检测失败 ≠ 该状态无解。AND–OR 的环检测只保证无环解： 如果搜索在同一条路径上又遇到某个已出现的状态就返回失败，含义是"无环解一定可以从更早的那个状态得到"， 而不是"这里解不出来"。打滑吸尘器就有一个必须靠循环才能解决的版本： [Suck, L1: Right, if State = 5 then L1 else Suck]——无环解会失败，循环解成功。

先做这个对比：把叶子顺序设成「最好」→ 访问 5 个叶子，剪掉 4 个； 设成「最坏」→ 访问 9 个，一个都剪不掉。 算法、树、答案全都一样，只有顺序不同，工作量差了近一半。 这就是为什么真实引擎里 move ordering（先试吃子、先试杀手着法）比剪枝本身还重要。
剪枝条件的准确说法（最容易记反的地方）： 剪枝发生在 α ≥ β 时。 在 MIN 节点里，β 被更新为当前最小值，一旦发现 β ≤ α 就停止扩展这个 MIN 节点的剩余子节点（因为父 MAX 已经有更好的选择了）； 在 MAX 节点里对称处理。 剪掉的是"兄弟分支"，不是"整棵子树"。
α-β 不改变结果，只改变工作量：它返回的根值与完整 minimax 完全相同—— 书上明确说"α-β 得到的值与 MINIMAX 得到的值一样，只是效率更高"。 真正改变结果的是下一屏的截断搜索（深度不够 + 评估函数不准）。

什么是地平线效应：智能体在深度 d 处截断，一个必然发生但发生在第 d+1 步的损失， 在它的视野里不存在。于是它会选择一条"把损失推到地平线之外"的路线—— 每推一次就多活一步，但损失从未消失，只是永远看不见。 加大深度只能推迟地平线，不能消除它；真正的缓解手段是静止搜索（在非静止局面继续延伸）。
评估函数的三条要求（书上原话）： ① 顺序要与真实效用一致（否则会选出更差的走法）； ② 计算要快（否则省下的搜索深度全赔进去了）； ③ 对非终止状态要准。 实践上用加权线性函数：w₁f₁ + w₂f₂ + …（如国际象棋 子力×1 + 机动性×0.1）。 它隐含一个很强的假设——各特征相互独立，而棋子之间显然不独立。
前向剪枝 vs 后向剪枝：α-β 是后向的（先展开再证明无用，零风险）； beam search 这类前向剪枝是"只看前 k 个最有希望的分支"——可能剪掉最优解，且不保证结果不变。 是否损害完备性/最优性，是这两类剪枝的根本区别。

REVISE 之后要不要重新入队？看清楚了： 只有当 Dᵢ 真的被删掉了值，才把 (Xₖ, Xᵢ) 这样的弧加回队列。 如果域没变，就不入队 —— 观察队列长度的变化，这条规则让 AC-3 大多数时候很快收敛。
复杂度：二元 CSP 有至多 n² 条弧（实际是 2×约束数）； 检查一条弧是 d²，每条弧最多入队 d 次， 所以 AC-3 的总时间 O(n² d³)、空间 O(n²) —— 比从零开始回溯便宜得多。这就是为什么"先跑一遍 AC-3 再回溯"几乎总是划算的。

两色的三角形：弧一致但无解。每条边单独看都没问题（每条边两端总能选出不同的颜色）， 但三个变量两两不同、只有两种颜色 —— 鸽笼原理直接判死，而弧一致看不出来。 路径一致（检查所有长度为 2 的路径）能判定这种情形：它要求任意两个变量的每个相容赋值， 都能被第三个变量"支撑"。
更强的一致性要付代价：k-相容（k-consistency）要求"任意 k−1 个变量的相容赋值都能扩展到第 k 个"。 强 n-相容 = 可解，但代价是指数的，不实用。实用的是 2-相容（弧一致） 和 3-相容（路径一致）， 以及针对全局约束（AllDiff、atmost）的专用传播算法 —— 下一屏就是它。

题目 —
MRV（最少剩余值）为什么这么强：它挑"可选值最少的变量"先赋值， 也就是最容易失败的那个。一旦这个变量真的无值可选，MRV 会立刻发现—— 不用等其他 6 个变量都赋完才发现矛盾。"先挑最可能崩的地方"，这就是"失败优先"原则。 度启发式只在平局时才作为 MRV 的补充（选约束最多的那个），因为当所有变量的 MRV 都相同时， 约束最多的变量对后续影响最大。
LCV（最少约束值）在做什么：给变量赋值时，优先选那个给邻居剩下最多选择的值。 它的目标是"尽量别把路走窄"。注意 LCV 和 MRV 的方向是相反的： MRV 主动找最紧的地方下手（早点失败），LCV 则尽量保持宽松（避免失败）。两者配合才最强。
向前检查 vs MAC：向前检查只删直接邻居里冲突的值（浅一层）； MAC 是"每赋一个值就跑一遍完整的 AC-3"（深到底）。 MAC 每步更贵，但删得干净得多——在澳大利亚这种小问题上 MAC 通常完胜，在超稀疏问题上可能反而不划算。

五个最易混的地方

弧一致 ≠ 可满足2 色的三角形弧一致但无解。弧一致只是"每条边单独看还过得去"。
度启发式只是 MRV 的平局裁判不要在 MRV 不同时用它。它只在"剩余值数量相同"时才决定先给谁赋值。
LCV 和 MRV 方向相反MRV 主动找最紧的变量（早日失败）；LCV 尽量保持宽松（避免失败）。两者配合最强。
REVISE 后只有域变了才重新入队这是 AC-3 效率的关键。域没变就不必通知邻居。
把 AllDiff 拆成 ≠ 会丢推理能力两两约束看不出"k 个格子占 k 个值"。真正的 AllDiff 用二分图匹配传播。
"树宽"是问题固有的，不是算法的约束图是树 → 多项式；树宽小 → 仍可多项式。结构决定难度，换算法救不了高树宽。
