# 06. 贝叶斯博弈与不完全信息（Bayesian Games & Incomplete Information）

> 现实里你几乎从不知道对手的完整底牌：他的成本多少、底线多低、类型是强是弱。**不完全信息**博弈研究的就是「在不知道别人底牌的情况下怎么决策」。

---

## 一、不完全信息 ≠ 不完美信息

| 概念 | 问题 | 例子 |
|---|---|---|
| **不完全信息** | 不知道对手的**收益 / 类型** | 不知道对手成本高低、是不是骗子 |
| **不完美信息** | 不知道对手的**动作过程** | 不知道对方已经下了哪步棋 |

不完全信息博弈用 Harsanyi（1967-68）的**「类型」**框架处理，因此也叫**贝叶斯博弈**。

---

## 二、类型与信念

Harsanyi 的关键转化：把「不知道对手类型」改造成「对手的类型是**自然（Nature）**随机抽取的，我对其分布有一个**先验信念**」。

| 概念 | 含义 |
|---|---|
| **类型（Type）** | 参与者的私有信息，如「高成本 / 低成本」「强硬 / 软弱」「诚信 / 欺诈」 |
| **信念（Belief）** | 我对对手类型分布的概率判断，如「60% 概率他是强硬型」 |
| **自然（Nature）** | 虚构的「发牌者」，先随机决定每个人的类型 |

例子：进入者不知道在位者是「高成本」（容易打价格战）还是「低成本」（无力打价格战），只能根据先验概率判断，再决定进不进入。

---

## 三、贝叶斯纳什均衡（BNE）

在类型博弈里，策略变成「**每个类型都指定一个最优动作**」，且：

1. 每个参与者对自己的类型是清楚的；
2. 根据对别人类型的信念，最大化**期望收益**；
3. 别人的策略也是「类型→动作」的映射，且符合理性。

**贝叶斯纳什均衡**就是：给定信念和别人的类型策略，**每个类型的参与者都没有动机偏离**。

求解套路：先写「每种类型的最优反应」，再求这些反应彼此一致（固定点）。

---

## 四、信号博弈（Signaling Game）

信息不对称时，知情的一方可以通过**行动本身**传递信息——这就是「信号」。

经典结构：

```
自然 → 发送者（知道自己的类型）→ 发一个「信号」→ 接收者（看到信号）→ 行动
```

信号**可信的前提**是：不同类型的发送者，发同一个信号的成本**不同**。成本差异让信号无法被轻易模仿，于是信号可信。

例子：
- 学历作为能力信号：高能力者拿学位成本低、低能力者成本高，所以「高学历」才可信。
- 广告投入作为质量信号：真有实力的公司才烧得起大额广告。

### 两类均衡

| 均衡 | 含义 |
|---|---|
| **分离均衡（Separating）** | 不同类型发**不同**信号，接收者通过信号能完全区分类型 |
| **混同均衡（Pooling）** | 不同类型发**相同**信号，接收者无法区分，只能按先验行动 |

---

## 五、经典案例：柠檬市场（Akerlof）

二手车市场：卖家知道车是「好车」还是「柠檬（次品）」，买家不知道。

- 买家只能按**平均质量**出价；
- 好车卖家觉得亏，退出市场；
- 市场上好车比例下降，买家出价进一步降低；
- 恶性循环，最终**只剩次品**——「劣币驱逐良币」，市场可能崩溃。

**核心洞察：信息不对称会导致市场失灵。** 解决办法是「发信号」（质保、品牌、第三方检测）或「机制设计」（[07](./07-拍卖与机制设计.md)）。

---

## 六、应用

| 场景 | 谁发信号 / 隐藏类型 |
|---|---|
| 招聘 | 求职者用学历、作品集发能力信号 |
| 融资 | 创始团队用过往成功、自投资金发信心信号 |
| 谈判 | 双方隐藏各自底线，靠让步节奏互相试探 |
| 平台风控 | 商家隐藏真实质量，平台用保证金、评分机制反制 |
| 多智能体 / AI | 各 Agent 拥有私有信息，通过通信协议和承诺传递类型 |

---

## 七、小结

```
不完全信息 ──► 引入「类型」+「信念」──► 贝叶斯纳什均衡（按类型给策略）
                                                   │
                                    ┌──────────────┴──────────────┐
                                    ▼                             ▼
                              信号博弈（发信号揭示类型）    机制设计（用规则逼出真实类型，见 07）
```
