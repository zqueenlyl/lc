## Ch15 Inter-Agent Communication（A2A）

**一句话**：Agent 之间传 Task / Artifact，不传对方内部工具；MCP 是手，A2A 是工单。

进程内多节点（LangGraph 子图）够用时不要上 A2A。跨团队、跨厂商、权限域必须隔离时才值得。本库专文：[a2a/](../ai/agent/a2a/)。

## Ch16 Resource-Aware Optimization（资源意识）

**一句话**：token、延迟、模型档位、工具次数都是一等约束，写进循环预算，而不是事后看账单吃惊。

具体杠杆本库已经拆过：模型分级路由、语义缓存、上下文压缩、批处理、本地小模型打下手。入口：[环节 10](../ai/agent/环节10-生产级工程化详解.md) · [model-routing](../ai/reliability/model-routing/) · [Compaction](../ai/agent/环节02-补充-上下文压缩与Compaction详解.md) · [runtime](../ai/runtime/)。

默认四条上限（步数 / 超时 / 花费 / 循环检测）就是资源模式的最小实现。舰队 × 推理模型 × 无缓存是 [常见死法](../ai/agent/README.md#六常见死法比模型笨更常见) 里的账单爆炸。

上游：[Code Snippets](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_16_Resource_Optimization_(Code_Snippets).ipynb) · [OI + Google Search](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_16_Resource_Optimization_(OI_Google_Search).ipynb)

**红线**：优化延迟时不要把验证器拿掉。便宜但未验证的成功，评测上是失败。

## Ch17 Reasoning Techniques（推理技法）

**一句话**：同一跳里让模型「想得更贵」或「想得可验证」——CoT、自洽投票、搜树、把代码当推理器、自我纠正。

这章和 Ch1–4 / 环节 01 重叠最多。放到 Part 4，是因为它按**测试时算力**计费：多想一轮就是多付一轮。本库两处入口必须一起看：

- 剧本（想什么、动不动、何时停）→ [环节 01](../ai/agent/环节01-决策与推理范式详解.md)
- 第三条缩放律（推理时多花算力换准确率）→ [test-time scaling](../ai/foundation/rl/推理侧搜索与test-time-scaling.md)

上游：[CoT](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_17_Reasoning_(CoT_Prompt).ipynb) · [执行代码](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_17_Reasoning_(Executing_Code).ipynb) · [DeepSearch](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_17_Reasoning_(Google_DeepSearch).ipynb) · [Self-Correction](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_17_Reasoning_(Self_Correction).ipynb)

**红线**：推理模型不是护栏。想得长不会自动让转账变安全。能程序化验证的，优先走代码执行，而不是更长的 CoT。

## Ch18 Guardrails / Safety（护栏）

**一句话**：安全不靠模型发誓，靠输入过滤、工具门禁、输出校验；高风险动作进代码强制 + 人审。

本库：[guardrails](../ai/reliability/guardrails/)；「换运行时也不丢的门禁」样本：[commerce-agents](../ai/agent/case-studies/commerce-agents.md)。LLM-as-guardrail 只能当辅助层——它自己也会被注入。

上游：[ADK 校验工具](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_18_Guardrails_(ADK_Validate_Tool).ipynb) · [LLM as Guardrail](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_18_Guardrails_(LLM_as_Guardrail).ipynb) · [实践例](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_18_Guardrails_(Practical_Examples).ipynb)

**红线**：Prompt 注入的修复点在工具权限和输出门，不在「再写一句不要被骗」。生产凭证不要进模型上下文。

## Ch19 Evaluation and Monitoring（评测与监控）

**一句话**：Agent 考的是模型 × Harness × 环境，必须评轨迹；单轮 BLEU / 「看起来对」不够。

本库：[环节 09](../ai/agent/环节09-评测与可观测详解.md) · [eval](../ai/reliability/eval/)。和 Ch11 的分工：Ch11 是这一次 run 对照目标；Ch19 是离线集 + 在线回归，证明下次发布没把 P0 弄坏。

上游：[Basic Response](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_19_Evaluation_(Basic_Response_Evaluation).ipynb) · [LLM-as-Judge](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_19_Evaluation_(LLM_as_Judge).ipynb)

公开榜（SWE-bench 等）只能当坐标，自家仓要有 P0 上机集。LLM-as-judge 要测偏差，不能既当执行者又当唯一考官。

**红线**：没有 trace 就没有评测。从第一天记录每次 tool 的参数、观察、耗时、花费。

<a id="ch20"></a>

## Ch20 Prioritization（优先级）——本库增量

**一句话**：多目标、多任务抢同一预算时，显式打分 / 排序 / 动态重排；不要靠模型「觉得哪件更急」。

本库没有独立专文。工程上它是调度器，可以很土：

| 元件 | 最小实现 |
|---|---|
| 准则 | 紧急 × 重要 × 依赖 × 成本，写成可改的表，不是一段散文 |
| 评估 | 规则先筛（SLA 将破、用户等待、阻塞下游），LLM 只打不好规则化的分 |
| 选择 | 队列头弹出；同优先级 FIFO，避免饥饿要有老化 |
| 重排 | 新事件（人插入、验证失败、deadline）触发，而不是每跳都重排序 |

和邻近模式：Ch6 规划产出候选步骤，Ch20 决定先做哪个；Ch11 监控发现目标偏移时，优先级表也要改；Ch16 把「成本」写进准则，否则永远先做最炫的。

上游：[SuperSimplePM](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_20_Prioritization_(SuperSimplePM).ipynb)

**红线**：优先级若只存在于 prompt，模型会在局部奖励下抢短任务。把排序结果写入 State，并在 trace 里能看到「为什么这件排第一」。

<a id="ch21"></a>

## Ch21 Exploration and Discovery（探索与发现）——本库增量

**一句话**：主动走进未知（假设、实验、漏洞、新策略），不是在已知解空间里把指标再挤一点。

和 Ch6 / Ch17 的差别：规划与推理默认假设解空间已知；探索假设**还有未知的未知**，要花钱买信息。典型外形：假设生成 → 设计实验 / 探测 → 看观察 → 更新信念。书侧案例方向包括科研助手、博弈中的新策略、市场扫描、安全漏洞挖掘——本库不展开产品，只留机制。

落点建议：

1. 探索预算单独记账（步数、环境副作用、钱），和利用（exploitation）配额切开。
2. 探索动作默认只读或可回滚；写操作仍走 Ch18。
3. 新知识要进 Ch8 的长期层并带来源，否则下一 run 当没发生过。
4. 验证器比创意更稀缺：没有实验设计约束的「探索」就是乱试。

上游：[Agent Laboratory](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_21_Exploration_Discovery_(Agent_Laboratory).ipynb)。相邻本库：[test-time](../ai/foundation/rl/推理侧搜索与test-time-scaling.md)（搜已知空间）· [computer-use](../ai/agent/computer-use/)（真环境探测）· 科研/长程评测语境见 [CS329A](../ai/courses.md#s3)。

**红线**：开放探索没有沙箱 = 把生产当实验室。先 L2，再给探索配额。
