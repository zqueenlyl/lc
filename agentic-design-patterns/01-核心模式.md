# Part 1 · 核心模式（Ch1–7）

> 所属索引：[README.md](./README.md)。这七章是 Gulli 的「执行积木」：怎么拆、怎么分、怎么并、怎么改、怎么伸手、怎么排期、怎么组队。
> 本库对照：流水线在 [环节 01 / 04 / 07 / 08](../ai/agent/环节00-总揽与环节导航.md)；可跑样本在 [langgraph/demos](../ai/agent/case-studies/langgraph/demos/)。

七章可以看成一张控制流菜单。**前四个还不一定是 Agent**（链 / 路由 / 并行 / 反思都可以是无工具的 LLM 工作流）；从 Tool Use 开始才有环境反馈；Planning 决定「先想完再做还是走一步看一步」；Multi-Agent 是最后才加的宽度。

```
Chaining ──► Routing ──► Parallelization
                │
                ▼
           Reflection（旁路批评）
                │
                ▼
            Tool Use  ←── 这里才进入 Agent 区
                │
                ▼
            Planning  ←── 循环怎么拆步
                │
                ▼
          Multi-Agent ←── 最后加宽，不要一开始就拆人
```

## Ch1 Prompt Chaining（提示链）

**一句话**：大任务拆成有序小提示，上一步的输出是下一步的唯一输入。

单次巨型 prompt 容易漏指令、漂上下文、把早期错误放大。链把每一步的约束收窄，便于单步调试。它是**流水线**，不是循环：没有观察，失败不会自己改道。

| 该用 | 不该用 |
|---|---|
| 步骤固定、数据单向（抽取 → 校验 → 改写） | 中途要看工具结果再决定下一步 |
| 每步都能单独断言 | 你其实需要路由或并行 |

本库：[langgraph `01_basic_chain.py`](../ai/agent/case-studies/langgraph/demos/01_basic_chain.py)。升级信号见 [README §七](../ai/agent/README.md#七按栈升级从提示到图)——一次调用能稳住格式就停在提示，不要为了「像 Agent」把链包进 while。

上游 notebook：[`Chapter_01_Prompt_Chaining_(Code_Example).ipynb`](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_01_Prompt_Chaining_(Code_Example).ipynb) · [JSON 版](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_01_Prompt_Chaining_(JSON_Example).ipynb)

**红线**：链上每一步都要 schema / 断言；否则误差沿链累积，看起来像「模型不行」，其实是没有门。

## Ch2 Routing（路由）

**一句话**：先判断「这是哪类题」，再交给对应的链、模型或工具箱。

路由是条件边，不是第二个大脑。分类可以是规则、小模型、或一次 cheap LLM 调用。错分的代价是整条下游链都在做无关功。

| 该用 | 不该用 |
|---|---|
| 入口异构（退款 / 查单 / 闲聊）要不同工具集 | 所有请求同一条路径 |
| 贵模型只接难题 | 用路由代替权限系统 |

本库：[langgraph `02_branching_router.py`](../ai/agent/case-studies/langgraph/demos/02_branching_router.py)；按任务选模型 → [model-routing](../ai/reliability/model-routing/)。

上游：[`Chapter_02_Routing_(LangGraph).ipynb`](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_02_Routing_(LangGraph).ipynb) · [ADK](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_02_Routing_(Google_ADK).ipynb) · [OpenRouter](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_02_Routing_(Openrouter).ipynb)

**红线**：路由结果要可观测（哪条边、凭什么）。静默错分比慢更难查。

## Ch3 Parallelization（并行）

**一句话**：互相独立的子任务一起跑，再汇合；或同一题跑 N 次投票。

两种用法不要混：

| 形态 | 干什么 | 账单 |
|---|---|---|
| **扇出 / 汇合**（sectioning） | 文档切片、多源检索、多专家各写一段 | 延迟降、token 升 |
| **投票**（self-consistency） | 同一 prompt 采 N 次，多数决 | token × N，换稳定 |

本库：[langgraph `04_parallel_fanout.py`](../ai/agent/case-studies/langgraph/demos/04_parallel_fanout.py)；投票的原理在 [环节 01 Self-Consistency](../ai/agent/环节01-决策与推理范式详解.md)。

上游：[ADK](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_03_Parallelization_(Google_ADK).ipynb) · [LangChain](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_03_Parallelization_(LangChain).ipynb)

**红线**：有依赖就不要并行（B 需要 A 的输出）。汇合节点必须定义「缺一块怎么办」——丢弃、重试、还是降级。

## Ch4 Reflection（反思）

**一句话**：先产出，再由独立批评步对照标准挑错，再改；循环直到过门或预算尽。

批评者和作者**不要是同一次生成里的两段散文**。最好拆节点，标准尽量程序化（测试、schema、清单），模型只补程序查不到的。

和邻近模式：

| | Reflection | 环节 01 Reflexion | ReAct |
|---|---|---|---|
| 反馈从哪来 | 批评者（模型或规则） | 失败轨迹 + 书面反思 | 环境 / 工具 |
| 典型 | 作文改稿、代码 review | 任务失败后换策略再试 | 查库、跑测试 |

本库：[环节 01](../ai/agent/环节01-决策与推理范式详解.md)。编码场景把「批评者」换成 `pytest`，见 [loop-engineering](../ai/agent/loop-graph/loop-engineering.md) 的验证段。

上游：[迭代环](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_04_Reflection_(Iterative_Loop).ipynb) · [LangChain](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_04_Reflection_(LangChain).ipynb) · [ADK](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_04_Reflection_(ADK).ipynb)

**红线**：没有外部门的反思会自我表扬。步数上限必须有；否则「再改一版」是死循环的文雅说法。

<a id="ch5"></a>

## Ch5 Tool Use（工具调用）

**一句话**：模型只许按 schema 提出调用；真正执行在宿主；结果以 Observation 写回。

这是进入 Agent 区的门槛。一次 `get_weather` 仍是工具增强聊天；**转起来、能根据观察改计划**才是 Agent（[agent/README](../ai/agent/README.md)）。

要点（本库已经写细，这里只钉钉子）：

1. 名字和 schema 写清「何时不要用」。
2. 失败返回可行动的观察，不要只丢栈。
3. 写操作幂等或带确认；删除 / 转账进 Guardrails L2。

本库：[环节 04](../ai/agent/环节04-工具调用详解.md) → 插头 [环节 05 MCP](../ai/agent/环节05-工具接入协议MCP详解.md) → 沙箱 [sandbox](../ai/reliability/sandbox/)。

上游：[LangChain](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_05_Tool_Use_(LangChain).ipynb) · [执行代码](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_05_Tool_Use_(Executing_Code).ipynb) · [CrewAI](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_05_Tool_Use_(CrewAI).ipynb) · [Google Search](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_05_Tool_Use_(Google_Search).ipynb) · [Vertex AI Search](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_05_Tool_Use_(Vertex_AI_Search).ipynb)

**红线**：不要让模型「口头执行」。没进宿主的调用等于没发生；轨迹里只能写真实 Observation。

## Ch6 Planning（规划）

**一句话**：先给出可执行步骤，再按步做；世界变了就重规划，而不是死抱第一张清单。

和 ReAct 的分工：结构清楚、步骤可预估 → Plan-and-Execute；工具结果高度不确定 → 走一步看一步。两者可以嵌：计划是外环，每一步内部仍是 ReAct。

本库：[环节 01](../ai/agent/环节01-决策与推理范式详解.md) 的 Plan-and-Execute；「发现 → 规划 → 执行 → 验证 → 迭代」五段在 [loop-engineering](../ai/agent/loop-graph/loop-engineering.md)。

上游：[Code Example](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_06_Planning_(Code_Example).ipynb) · [Deep Research API](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_06_Planning_(Deep_Research_API).ipynb)

**红线**：计划是假设，不是合同。没有「观察后作废计划」的边，规划模式会在过时 To-Do 上空转。

<a id="ch7"></a>

## Ch7 Multi-Agent（多 Agent）

**一句话**：把过宽的工具箱 / 权限域拆成角色，由主管分发或沿流水线交接。

先问「是不是真的要第二个大脑」，再问协议。本库的判断表在 [agent/README §四](../ai/agent/README.md#四单-agent-vs-多-agent)：同一权限域、工具 < 15、验证能程序化 → 一个就够。

| 拓扑 | 适合 | 坑 |
|---|---|---|
| 主管–下属 | 角色边界清 | 主管 prompt 膨胀，变成单点 |
| 流水线 | 阶段产物可交接 | 上游错了下游放大 |
| 并行专家 | 可独立的子任务 | 汇合无标准 |
| 辩论 / 批评 | 作者与评审必须分离 | 没完没了 |

本库：[环节 08](../ai/agent/环节08-多Agent协作详解.md) · [langgraph 04](../ai/agent/case-studies/langgraph/04-多智能体与高级模式.md) · 跨厂商工单走 [a2a](../ai/agent/a2a/)（Ch15）。

上游 ADK 一套（Coordinator / Sequential / Parallel / Loop / AgentTool）+ [CrewAI](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_07_Multi_Agent_(CrewAI_Gemini).ipynb)——用来看「同一模式在不同框架里的接线」，不要当生产骨架。

**红线**：L4 舰队没有 L2 的沙箱和验证，只是把幻觉放大。先闭环，再开放。
