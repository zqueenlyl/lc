## Ch12 Exception Handling and Recovery（异常处理与恢复）

**一句话**：工具失败、超时、格式错误都是 Observation，不是未捕获异常；预先写好转、降、停。

Agent 里的异常和普通后端的差别：模型可以「看见」错误并换策略，前提是你把错误翻译成它能用的话。本库 [环节 04](../ai/agent/环节04-工具调用详解.md) 已强调「缺字段、权限拒绝」要可行动；[环节 10](../ai/agent/环节10-生产级工程化详解.md) 把重试 / 幂等 / 降级当成上线门槛。

一套最小策略：

| 失败类 | 默认动作 |
|---|---|
| 瞬时（超时、429） | 有限次退避重试；超限降级或失败 |
| 契约（JSON 坏、缺字段） | 回填错误，让模型改参数；2–3 次后停 |
| 未知工具 / 无权限 | 告诉模型「没有这手」，不要假装调用成功 |
| 业务拒绝（余额不足） | 停，交给规则或人，不要换个参数再转账 |
| 不可恢复 | 保状态、告警、给用户一个未完成的句柄 |

上游：[Chapter_12_Exception_Handling_(Fallback).ipynb](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_12_Exception_Handling_(Fallback).ipynb)

和 CMU 11-768 A1 的口径一致：malformed JSON 与未知工具转成可恢复 observation，而不是抛给框架（[courses.md §1](../ai/courses.md#s1)）。

**红线**：写操作必须幂等。重试「已成功但响应丢了」的退款，比不重试更危险。Checkpointer 是为了续跑，不是为了把半次转账重放。

## Ch13 Human-in-the-Loop（人机协同）

**一句话**：高风险、不可逆、或验证器覆盖不了的步骤，暂停等人；人的决定是状态的一部分，不是聊天旁白。

HITL 不是「做完给人口头汇报」。它是执行图上的一个节点：`interrupt` → 人审 → `Command` 写回 → 续跑。本库：[langgraph 03](../ai/agent/case-studies/langgraph/03-持久化-流式-人机协同.md) · [`07_human_in_the_loop.py`](../ai/agent/case-studies/langgraph/demos/07_human_in_the_loop.py)。生产里安全靠代码强制的样本：[commerce-agents](../ai/agent/case-studies/commerce-agents.md)。

| 该暂停 | 不该暂停 |
|---|---|
| 转账、删除、对客承诺、发外部邮件 | 只读查询、可逆草稿 |
| 验证器说「不确定」 | 模型说「我有点没把握」（太吵） |
| 合规要求预先审计的边 | 每一步都问人（那叫工作流，不要叫 Agent） |

自主程度停在 L2 是默认（[agent/README §一](../ai/agent/README.md#一先分清三件事)）。HITL 是 L2 的闸，不是 L4 的装饰。

上游：[Chapter_13_Human_in_the_Loop_(Customer_Support).ipynb](https://github.com/evoiz/Agentic-Design-Patterns/blob/main/chapter_notebooks/Chapter_13_Human_in_the_Loop_(Customer_Support).ipynb)

**红线**：人审超时要有策略（过期拒绝，不要过期默认同意）。人的批复要进审计日志，和模型轨迹同一条 trace。

## Ch14 Knowledge Retrieval（RAG）

**一句话**：训练时不在、上下文也装不下的事实，切块入库、检索、精排、带着来源拼进窗口。

本库主文在 [环节 06](../ai/agent/环节06-检索增强RAG详解.md) 和 [rag/](../ai/knowledge/rag/)，这里只钉和 Agent 的接口：

- **Naive RAG** 是链上的一步；**Agentic RAG** 是把检索当成工具，由循环决定「要不要搜、搜什么、够不够」。
- 检索质量的杠杆排序：Hybrid（BM25+向量）→ Rerank → 再考虑 GraphRAG。账单常在抽取。
- 引用是验收，不是装饰。答不在命中块里 = 失败，不是「模型总结得更好」。

上游 notebook 是 Google Search / LangChain / VertexAI 三条检索后端，对本库来说属于「换 Environment」。本地对照：[langgraph `05_rag_agent.py`](../ai/agent/case-studies/langgraph/demos/05_rag_agent.py)。

**红线**：无关检索会拉低质量（Self-RAG / Adaptive 要解决的就是这个）。知识库覆盖不足时先承认，再决定换源或交给人，不要用更长的生成掩盖空检索。
