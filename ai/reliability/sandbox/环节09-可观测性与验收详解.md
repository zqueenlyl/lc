## 0. 一句话定位

**沙箱的实际安全等级 = 边界强度 × 可证明程度。**

```
只有边界，没有观测   →  出事时无法回答"它到底做了什么"（等于没有边界）
只有观测，没有边界   →  看得见但挡不住（等于监控）
边界 + 观测，没有回归 →  今天安全，升级运行时/改配置后悄悄失效
```

所以验收这件事要能回答三个问题：

| 问题 | 靠什么回答 |
|---|---|
| **它刚才做了什么？** | 审计事件（命令 / 读写 / 网络出口 / 越界尝试） |
| **边界现在还生效吗？** | 主动越界测试用例集（不是"能不能跑"，是"能不能逃"） |
| **改动之后还生效吗？** | 把用例集变成**回归**，随配置变更与运行时升级自动跑 |

## 1. 审计事件模型：该记什么

沙箱审计与普通应用日志的最大区别：**它记录的是"被拒绝的动作"，而不只是"成功的动作"**——因为"尝试"是入侵的最强信号。

### 1.1 五类事件

| 类别 | 记录内容 | 为什么关键 |
|---|---|---|
| **命令执行** | 完整命令、工作目录、退出码、耗时 | 复盘"它想干什么"的主线 |
| **文件访问** | 读/写路径、是否命中保护路径 | 凭证外泄与提权路径的核心证据 |
| **网络出口** | 目标主机、端口、是否被白名单拒绝 | 数据外传的唯一可见面（TLS 未终止时只能看"连了谁"） |
| **越界尝试** | 被 seccomp / cap / 白名单 / 保护路径拦下的动作 | **最高价值**：正常业务不会触发 |
| **资源事件** | OOM kill、pids 触顶、CPU 限流、磁盘配额 | 区分"恶意"与"业务 bug"，也是容量依据 |

### 1.2 事件的必需字段（缺一个就复不了盘）

```
ts           时间戳（含时区）
tenant_id    租户 / 用户（多租户必需，用于审计与计费）
sandbox_id   沙箱实例 ID（串起一次任务的完整时间线）
phase        setup / exec / teardown（哪个阶段出的）
action       动作类型（exec / read / write / connect / syscall）
target       目标（命令 / 路径 / host:port / syscall 名）
result       allow / deny / error
policy       命中的策略条目（哪条规则做的决定）
latency_ms   耗时（性能与异常检测）
```

**`policy` 字段最容易被省、但最有用**：它把"被拦了"变成"被哪条规则拦了"，直接指出该放宽还是该收紧。

### 1.3 脱敏：审计要全，展示要红

日志本身是新的泄露源——不要把审计日志变成"凭证收集器"。

| 对象 | 存 | 展示 |
|---|---|---|
| 命令 | 全（含参数） | 参数里的密钥替换为 `***` |
| 文件内容 | **不存内容**（只存路径 + 哈希可选） | —— |
| 环境变量 | 只存**变量名**与是否被 mask | 值一律不展示 |
| 网络 | host:port 全存 | 全量展示（不含 query/body） |
| 请求体 | 默认不存；存则先过 DLP | 采样 + 脱敏 |

> **原则**：**"审计要全、展示要红"**——与 [guardrails](../guardrails/README.md) 的 L5 审计要求一致。

### 1.4 写入位置：审计不能落在沙箱里

```
❌ 沙箱内写日志文件 → 沙箱被攻破后攻击者可以删/改（甚至伪造"我很干净"）
✅ 沙箱外收集（宿主侧 / 独立日志通道）→ 且 append-only
✅ 更高要求：只追加存储 + 定期归档 + 校验（防篡改）
```

**同一个道理适用于审计通道本身**：如果审计走的是沙箱内的网络出口，那么"关掉网络"就等于"关掉审计"。审计通道要独立于业务通道。

## 2. seccomp 的"只记不拦"画像期：用数据生成白名单

[环节 01](./环节01-隔离原语详解.md) §4 讲了 seccomp 的**动作集合**里有 `SCMP_ACT_LOG`。它的正确用法不是"顺便记日志"，而是一个**方法**：

```
第 1 阶段（观察，1~2 周）：默认动作 = LOG（或"宽松允许 + 记录"）
     → 收集真实负载用到的 syscall 直方图
第 2 阶段（分析）：取直方图覆盖 99.9% 调用的集合 + 人工确认
     → 得到"白名单候选"
第 3 阶段（收紧）：默认动作 = ERRNO / KILL，只允许白名单
     → 上线后用 "拒绝" 事件的计数做回归信号
```

**为什么必须这么做**：手写 seccomp 白名单几乎一定会漏（漏了就是"上线后莫名的 EPERM"），而"观察期 + 数据驱动"把这件事从猜变成量。

**数据长什么样**（示意，量级）：

```
read 41.2%  write 22.7%  openat 9.8%  close 6.1%  fstat 5.3%  mmap 4.2%  ...
→ 前 20 个 syscall 覆盖 ≈ 99.5%；尾部是长尾（几百个各占比 <0.01%）
→ 白名单取头部 + 逐个确认长尾里"确实需要"的
```

> **`SCMP_ACT_NOTIFY`（5.0+）是更进一步的玩法**：把可疑 syscall 交给用户态 supervisor 实时裁决，可以做到"同一 syscall 按参数放行"（例如只允许 `connect` 到白名单地址）——这是"运行时动态授权"，比静态白名单灵活，但引入了 supervisor 的可用性依赖（supervisor 挂了要 fail-closed）。

## 3. 越界测试用例集（加固验收的核心资产）

**"沙箱启动了"不等于"隔离生效了"。** 验收的唯一方式是**主动尝试越界**，且要把它固化成可回归的用例集。

### 3.1 基础四件套（每个沙箱都该跑）

| # | 用例 | 期望结果 | 说明 |
|---|---|---|---|
| 1 | 读宿主敏感文件（`~/.ssh/id_rsa`、`/etc/shadow`） | **拒绝**或不可见 | 文件系统边界 |
| 2 | 连外网 + 连私网 + 连 `169.254.169.254` | **全部拒绝**（未白名单） | 网络边界 |
| 3 | fork 炸弹（或循环 fork） | **被 pids.max 拦住**，宿主不受影响 | 资源边界 |
| 4 | 写 `/proc/sys/*` / 挂载 / 改 cgroup | **拒绝**（无 CAP_SYS_ADMIN） | 提权边界 |

### 3.2 扩展用例（按威胁模型加）

| # | 用例 | 期望 |
|---|---|---|
| 5 | 访问 `docker.sock` / 其它高权限 socket | 拒绝 |
| 6 | 符号链接穿越（`ln -s /etc/passwd ./x` 后读 `./x`） | 拒绝（按解析后真实路径判定） |
| 7 | 通过 `/proc/<pid>/environ` 读别的进程 | 拒绝 |
| 8 | 内存炸弹（逐步吃内存） | OOM kill 且**只杀沙箱内进程** |
| 9 | 磁盘写满（往可写层灌数据） | `ENOSPC` 或配额拦住，宿主盘不受影响 |
| 10 | 输出洪泛（无限 echo） | 输出被截断，内存不涨 |
| 11 | 逃逸 CVE 复现脚本（若有） | 拒绝或至少被记录 |
| 12 | 越权读取工作目录外的**可读**路径 | 记录审计（许多实现默认放行读） |

### 3.3 用例写成断言，而不是"手动看一眼"

```python
# 形态示意（伪代码）
CASES = [
    Case("read_host_secret",   run="cat ~/.ssh/id_rsa",
         expect=["deny", "no_such_file"]),
    Case("connect_metadata",   run="curl -m 2 http://169.254.169.254/",
         expect=["deny", "timeout"]),
    Case("fork_bomb",          run=":(){ :|:& };:",
         expect=["pids_limit", "killed"], assert_host_healthy=True),
    Case("write_proc_sys",     run="echo 1 > /proc/sys/kernel/core_pattern",
         expect=["deny", "read_only_fs"]),
]
```

**关键断言不止"沙箱内报错"，还要断言"宿主/邻居无影响"**——很多逃逸的判据是"宿主出现了不该有的副作用"。

## 4. 与 Eval 的接口：把沙箱事件变成指标

沙箱不是"配好就不管"的基础设施，它需要**自己的指标与回归**。

### 4.1 四个指标（可直接进看板）

| 指标 | 计算 | 告警条件 |
|---|---|---|
| **越界拦截率** | 被拦下的越界尝试 / 全部越界尝试 | 越界尝试**总量**突变（说明有新攻击面被触发） |
| **误拦率** | 合法操作被误拒 / 全部操作 | 上升 = 白名单太紧，用户体验受损 |
| **逃逸用例通过率** | 用例集里"被正确拦住"的比例 | **不等于 100% 即事故** |
| **资源违规率** | OOM / pids 触顶 / 超时的任务占比 | 上升 = 配额不合理或负载变化 |

> **只盯"漏拦"会漂，只盯"误拦"会松**——两个方向都要有指标（与 [guardrails](../guardrails/README.md) §六 的"漏拦与误拦同时测"一致）。

### 4.2 触发回归的三个时点

```
① 沙箱配置变更（改白名单 / 加挂载 / 调配额）→ 必须跑用例集
② 运行时或内核升级（runc / gVisor / 内核版本）→ 必须跑用例集（逃逸面会变）
③ 依赖与环境基线更新（镜像、pip 包）→ 跑一遍（构建期攻击面）
```

**为什么必须自动化**：这三件事在真实团队里**每周都在发生**，靠人工"记得去测"必然漏。

### 4.3 与 `reliability/eval` 的关系

| | 本环节（沙箱验收） | [../eval/](../eval/README.md)（Agent 评测） |
|---|---|---|
| 测什么 | **边界**是否生效（安全属性） | **任务**做得好不好（能力属性） |
| 用例形态 | 越界脚本 + 断言宿主无副作用 | 数据集 + 评分器 |
| 失败含义 | 安全事故 | 能力退化 |
| 共同点 | **都要可复现环境 + 都要回归**（沙箱是 eval 的执行底座） |

> **一句话**：**沙箱验收是"安全回归"，eval 是"能力回归"**。两者共用同一套"一次性、可复现、有配额"的执行环境——所以沙箱的观测数据（谁跑了什么、花了多少）也是 eval 的成本归因来源。

## 5. 事件 → Trace：落地时的三个取舍

| 取舍 | 说明 |
|---|---|
| **采样 vs 全量** | 越界尝试**全量**（量小、价值高）；普通命令可采样（量大）。**别对最有价值的信号做采样** |
| **同步 vs 异步** | 审计写入异步（不阻塞执行）→ 但要接受"崩溃时丢尾部"；安全关键事件（拒绝）可同步落盘 |
| **关联 ID** | 必须有 `trace_id` / `sandbox_id` 串起"任务 → 沙箱实例 → 事件序列"，否则日志是一堆孤岛 |

**事件量级提醒**：一次"跑测试"的任务可能产生上万条文件访问事件。**不做聚合的事件流 = 昂贵的噪音**。实务做法：默认只记"拒绝 + 写 + 网络 + 命令"，读事件按需开启或聚合为"访问了哪些顶层目录"。

## 6. 面试高频追问

| 追问 | 回答要点 |
|---|---|
| 怎么证明沙箱真的隔离了？ | **主动越界测试用例集**（四件套 + 扩展）+ 断言宿主无副作用；不能靠"启动了没报错" |
| 审计日志最该记什么？ | **被拒绝的动作**（越界尝试）——正常业务不会触发，信噪比最高 |
| 审计为什么不能写在沙箱内？ | 被攻破后可被删改伪造；必须沙箱外、append-only |
| seccomp 白名单怎么定？ | **"只记不拦"画像期**（`SCMP_ACT_LOG`）收集 syscall 直方图 → 覆盖 99.9% + 人工确认 → 收紧 |
| 沙箱回归要覆盖哪几个触发点？ | 配置变更 / 运行时与内核升级 / 依赖基线更新 |
| 沙箱的指标和 Agent 评测指标有什么区别？ | 前者测**边界**（安全回归），后者测**能力**（能力回归）；共用执行底座 |
| 日志脱敏和"审计要全"矛盾吗？ | 不矛盾：**存储全、展示红**；内容不落盘，只落路径与元数据 |

## 7. 坑清单

1. **只记成功动作**：最该看的"被拦了什么"反而没记。
2. **审计落在沙箱内**：攻破即篡改，等于没有审计。
3. **审计无关联 ID**：几万个沙箱的事件混成一锅，无法归因到具体任务/租户。
4. **对越界事件做采样**：把最有价值的低频信号抽没了。
5. **不脱敏**：审计库变成凭证库（一次泄露双重损失）。
6. **白名单靠手写**：必然漏，表现为"上线后莫名的 EPERM"。
7. **"启动了"当"验收通过"**：没有越界测试的加固等于没有加固。
8. **升级运行时/内核后不回归**：逃逸面会变，旧结论不再成立。
9. **只测沙箱内报错、不测宿主无副作用**：逃逸的判据往往是宿主侧异常。
10. **审计阻塞主流程**：同步写日志导致执行变慢；应异步 + 缓冲（但接受丢尾部风险）。
