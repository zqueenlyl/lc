> 定位：**横切主题**，不占环节编号——它不属于某一个环节，而是把 [环节 01–08](./环节00-总揽与环节导航.md) 的内容收口成"**威胁怎么建模、选哪一档、成本怎么算、上线前过哪张清单、出问题按什么顺序查**"。
> 上游写法：Sandbox 在可靠性四道闸门里的位置见 [reliability](../README.md)；策略层配 [guardrails](../guardrails/README.md)。
> 相邻产物：Harness 的 runtime primitive → [harness](../../agent/harness/README.md)；评测执行底座 → [eval](../eval/README.md)。
> 适合人群：要判断"该上哪一档沙箱、成本多少、怎么验收"的工程决策者。
> **版本口径（2026-09-12）**：本篇产品信息（Claude Code / Codex / E2B / Modal / Daytona / Firecracker 等）是**带日期的快照**，**版本、价格、时长上限、SDK 都会变，引用前回官网核一遍**；机制类结论（共享/独立内核、配额语义、逃逸类别）相对稳定。

## 0. 一句话定位

**沙箱的全部工程问题可以压缩成三句**：

```
选型：  先问"代码多不可信 + 副作用多贵"，再问"选哪一档"——别反过来
成本：  贵不在隔离本身，而在【冷启动 + 每沙箱固定开销 + 自研运维人力】
验收：  能跑 ≠ 隔离生效；必须主动测"能不能逃"，并把配置评审当必选项
```

**演进骨架（"每一代都在补上一代的洞"）**：

| 代 | 机制 | 解决了什么 | 留下什么问题 | 详解 |
|---|---|---|---|---|
| 1979 | chroot | 换根目录 | 无进程/网络/资源隔离，可逃 | [环节 01](./环节01-隔离原语详解.md) §7 |
| 2002 | namespace | 视图隔离 | 限不了资源 | [环节 01](./环节01-隔离原语详解.md) §2 |
| 2007–08 | cgroup v1 | 资源维度 | 多层级混乱、`release_agent` 逃逸面 | [环节 01](./环节01-隔离原语详解.md) §3 |
| 2013 | Docker | 标准化 + 镜像分发 | 共享内核；默认配置不安全 | [环节 02](./环节02-隔离强度谱系与选型.md) |
| 2016+ | cgroup v2 | 统一层级、移除危险接口 | —— | [环节 01](./环节01-隔离原语详解.md) §3 |
| 2018 | gVisor | 不用 KVM 也收窄 syscall 面 | 兼容性代价 | [环节 02](./环节02-隔离强度谱系与选型.md) §2.1 |
| 2018 | Firecracker | 微 VM 百毫秒级启动 | 密度下降 | [环节 02](./环节02-隔离强度谱系与选型.md) §2.2 |
| 2023–26 | 云沙箱 + Agent 内置沙箱 | 免自运维、产品化 | 厂商锁定、配置项爆炸 | [环节 07](./环节07-Agent落地形态详解.md) |

## 1. 威胁建模三问（选型前必须先答）

```
Q1  要挡谁？
      误操作（自己的 Agent 手滑） ──► 轻隔离即可，重点在配额与审计
      恶意提交（用户代码 / 多租户）──► 必须有独立内核那一档
      供应链污染（依赖 / 模型权重）──► 构建与运行都要进沙箱

Q2  代码来源可信吗？
      完全可信（自己的 CI）  ──► 容器 + 配额，别自研
      半可信（模型生成的命令）──► 进程级/容器 + 严格 FS/网络边界
      完全不可信（外部提交）  ──► 微 VM / gVisor + 一次性 + 离线

Q3  失守的代价有多大？
      可重跑的计算   ──► 隔离强度可降，重点在配额
      能碰生产凭据   ──► 凭证策略（短 TTL + 出站代签）比隔离档更重要
      能碰用户数据   ──► 合规级要求，独立内核 + 强审计
```

> **反模式**：跳过三问直接问"选 Docker 还是 Firecracker"。**答案取决于 Q1–Q3，不取决于技术流行度。**

## 2. 场景 → 隔离档映射（可直接抄）

| 场景 | 推荐档 | 必须项 | 可选加强 |
|---|---|---|---|
| 本机编码 Agent（单租户） | 进程级沙箱 + 权限系统 | FS 边界 + 网络白名单 + 敏感路径保护 | 全量审计、凭证 mask |
| CI 跑自己的测试 | 容器 | 配额 + 超时 + 固定镜像 | 网络白名单 |
| 代码评测（可能恶意提交） | 微 VM / 强化容器 | **离线 + 答案隔离 + 一次性 + 配额** | 防作弊校验、独立内核 |
| 代码解释器（会话型） | 容器 ~ 微 VM | 会话配额 + 空闲回收 + 快照干净起跑 | 微 VM 提升隔离 |
| FaaS 多租户 | 微 VM / gVisor / V8 isolate | 冷启动优化 + 配额 + 逃逸加固 | 强审计 |
| Computer Use | 独立容器 / VM | **账号隔离 + 禁生产后台 + 页面内容当不可信输入** | 浏览器沙箱加固 |
| 企业内网 Agent | 容器 + 来源过滤 | **出口拒绝私网 + 拒元数据地址** | egress 网关统一管控 |

## 3. 技术/产品对比大表（快照：2026-09-12）

| 名称 | 档位 | 隔离原语 | 启动量级 | 特点 / 适合 |
|---|---|---|---|---|
| **runc / Docker / Podman** | 普通容器 | namespace + cgroup（共享内核） | 10²~10³ ms | 生态最好；**必须自己加固**（cap/socket/挂载/配额） |
| **bubblewrap** | 进程级 | user/mount/pid/net ns + 只读绑定 | ms | 无守护进程、非特权可用；Claude Code / Codex 的 Linux 底座 |
| **Seatbelt**（macOS） | 进程级 | OS 沙箱 profile（SBPL） | ms | macOS 系统自带；Claude Code / Codex 的 macOS 底座 |
| **Landlock** | 进程级 | 内核 LSM，非特权自我限制 | ms | 只覆盖文件系统；Codex Linux 的兼容回退 |
| **gVisor** | 强化容器 | **用户态内核**（Sentry + Gofer） | 10² ms | 高密度 + 收窄 syscall；**兼容性代价（`ENOSYS`）** |
| **Firecracker** | 微 VM | KVM 微 VM（独立内核） | 10² ms | 硬件级隔离；E2B / AWS Lambda 系 |
| **Kata Containers** | 微 VM | VM + OCI 接口 | 10²~10³ ms | "容器接口 + VM 内核"，运维更友好 |
| **Cloud Hypervisor** | 微 VM | KVM | 10² ms | 更完整设备模型，Rust 实现 |
| **Wasmtime / WASI** | Wasm | 内存沙箱 + 能力模型 | μs~ms | 最轻最快；**无 fork/exec、兼容性差** |
| **V8 isolate** | 进程内 | JS 堆隔离 | μs | 极高密度纯函数；Cloudflare Workers 系 |
| **E2B** | 云沙箱 | **Firecracker 微 VM** | 秒级（含调度） | Agent 代码执行、会话型 SDK、快照恢复 |
| **Modal** | 云沙箱 | **gVisor** | 秒级 | 数据/AI 工作负载平台，沙箱是其一能力 |
| **Daytona** | 云沙箱 | 容器 / VM 视配置 | 秒级 | 开发环境导向 |
| **Claude Code 内置沙箱** | 进程级 + 权限系统 | Seatbelt / bubblewrap（+ 可选 seccomp） | ms | **沙箱与权限两层正交**；网络走出站代理 |
| **Codex CLI 沙箱** | 进程级 | Seatbelt / bwrap + Landlock + seccomp | ms | 三档网络：`Isolated` / `ProxyOnly` / `FullAccess` |
| **Judge0 / isolate** | 评测 | namespace + cgroup | 10² ms | 专为评测：一次性、配额严、禁网 |
| **SWE-bench 执行环境** | 评测 | 每实例一个 Docker 容器 | 10²~10³ ms | 可复现镜像 + 补丁流程 |

> ⚠️ **两家"AI 沙箱"选了完全不同的哲学**：E2B = 微 VM（安全优先、独立内核），Modal = gVisor（密度优先、共享内核）。**这正好说明"AI 沙箱"不是一种技术，而是同一问题的两种答案**——选型时要先明确自己更怕什么。

## 4. 成本模型（三层，按对总成本影响排序）

| 层 | 内容 | 量级直觉 | 优化手段 |
|---|---|---|---|
| **冷启动** | 调度 + 镜像拉取 + 内核 boot + 应用初始化 | 一次性场景里常占体验时间大头 | 预热池 / 快照恢复 / 会话复用（[环节 05](./环节05-资源限制与生命周期详解.md) §4） |
| **每沙箱固定开销** | 内核 / 运行时进程 / page cache 是否共享 | 容器 ≪ 微 VM（VM 每份独立内核与缓存） | 共享只读层；密度规划按 P99 |
| **自研运维人力** | 自建隔离层、写代理、做审计、跟 CVE | **最容易低估的一项** | 优先托管云沙箱 / 成熟运行时，别自研（[环节 02](./环节02-隔离强度谱系与选型.md) §3） |

**决策提醒**：

- **"每任务一个新沙箱"不等于贵**——如果任务是秒级以上，冷启动可以摊薄；**真正贵的是"每请求一个新沙箱"**（此时看 Wasm/V8 isolate）。
- **"租户越不可信，成本越高"**：独立内核 + 一次性 + 离线 + 强审计，四项都会抬成本，但这是合规底线，不能用成本理由砍掉。
- **隐性成本**：厂商锁定的 SDK / 网络模型 / 镜像仓库 → 迁移成本要提前算进 TCO。

## 5. 上线前综合评审清单（合并 01–08 的必选项）

```
【隔离】
[ ] 不用 --privileged；cap-drop ALL + 按需加
[ ] 设置 no_new_privs
[ ] rootfs 只读；可写面是"枚举白名单"
[ ] 敏感路径单独保护（.git / shell rc / hooks / .env / ~/.ssh / ~/.aws）
[ ] 不挂宿主路径（尤其 /var/run、/proc/sys、/home）
[ ] /proc 在新 PID ns 重挂；/proc/sys 只读
[ ] cgroup 文件系统只读 + 用 v2
[ ] 不挂 docker.sock / containerd.sock；Unix socket 默认禁

【网络】
[ ] 默认断网（netns 只有 lo）
[ ] 要联网走沙箱外出站代理；域名白名单不带宽泛通配
[ ] 出口拒绝私网 / 链路本地（含 169.254.169.254）
[ ] 出口日志可用（能回答"连过哪些域名"）

【资源与生命周期】
[ ] cpu.max + memory.max + pids.max（+ io.max）
[ ] wall-clock 硬超时 + 无输出软超时
[ ] 输出截断上限
[ ] 一次性 / 干净起跑（overlay 换 upper 或快照）
[ ] 销毁彻底（挂载点 / 端口 / 孤儿进程 / 临时目录）

【凭证】
[ ] 凭证不进 prompt / 工具结果
[ ] 凭证不进 env / 沙箱内文件
[ ] 短 TTL + 最小 scope；优先出站代理代签
[ ] 快照与镜像里不含凭证

【审计与验收】
[ ] 命令 / 读写 / 网络出口 / 越界尝试全部留痕且脱敏
[ ] 越界尝试有实时告警
[ ] 加固验收包含主动越界测试（读宿主文件 / 连私网 / fork 炸弹 / 写 /proc/sys）
[ ] 依赖安装（pip/npm postinstall）也在沙箱内执行
```

## 6. 故障排查顺序（按"先能跑、再查边界、最后查安全"）

| 症状 | 先查 | 再看 |
|---|---|---|
| 命令报 `Operation not permitted` | 是不是沙箱拦的（seccomp / cap） | 该放开还是改造命令（[环节 01](./环节01-隔离原语详解.md) §4） |
| 进程"神秘消失" | `memory.max` 是否触发 **OOM kill** | 峰值内存 vs 配额（[环节 05](./环节05-资源限制与生命周期详解.md) §1） |
| `fork` 失败（`Resource temporarily unavailable`） | `pids.max` 触顶 | 是否有 fork 炸弹 / 线程泄漏 |
| 命令"越来越慢"但没报错 | `cpu.max` 限流 | 超配率与 P99 排队（[环节 05](./环节05-资源限制与生命周期详解.md) §5） |
| 网络时通时不通 | 白名单 / 代理环境变量是否传到子进程 | 是否有 DNS / IPv6 / 通配符匹配问题（[环节 04](./环节04-网络隔离与出口管控详解.md) §2） |
| 认证一直失败（用了 mask） | `tlsTerminate` 是否开 | `injectHosts` 与 `allowedDomains` 是否对齐（[环节 06](./环节06-凭证与密钥管理详解.md) §2） |
| bubblewrap 挂载失败 | 是否在容器里嵌套（`/proc` 挂载） | 是否需要预设权限或改用不嵌套架构 |
| 磁盘写满 / 内存莫名涨 | upper 层是否落在 tmpfs | 写入量放大（copy-up，[环节 03](./环节03-文件系统隔离与快照详解.md) §6） |
| 改不动文件 | 是否命中 Protected Paths / 只读挂载 | 是否需要显式 `allowWrite` |

## 7. 跨环节坑清单（Top 10）

1. **只做文件系统隔离或只做网络隔离**——两者乘性，缺一个等于没有（[环节 03](./环节03-文件系统隔离与快照详解.md) / [环节 04](./环节04-网络隔离与出口管控详解.md)）。
2. **默认"读整机"**——写入限制很严，读取却放行全盘（含 `~/.ssh`、`~/.aws`）。
3. **可写目录内的执行入口没保护**——`.bashrc` / hooks / `.git/config` 能让沙箱"下次运行时自我提权"。
4. **只设超时不设配额**——30 秒内可以吃完内存 / fork 炸弹。
5. **`cpu.max` 当超时用**——它只限流不终止。
6. **白名单带宽泛通配符或忘拒私网**——数据外传 / 打内网 / 拿云凭证。
7. **挂 `docker.sock` 或放开 Unix socket**——一条链直接逃逸。
8. **凭证进 env 或进快照**——前面所有边界作废；泄漏窗口被 TTL 与 scope 决定。
9. **预热池不复位状态**——跨任务数据泄露（多租户下是事故）。
10. **只测"能跑"不测"能逃"**——加固没有验收，等于没有加固。

## 8. 综合面试题（跨环节）

| 题目 | 答题骨架 |
|---|---|
| "给你一个多租户代码执行平台，怎么设计沙箱？" | 威胁建模三问 → 独立内核档（微 VM / gVisor）→ FS 只读 + 离线 + 一次性 + 配额 → 凭证出站代签 → 审计与越界测试 |
| "我们要跑 LLM 生成的代码，用 Docker 够吗？" | 先问代码来源与失守代价；Docker 够用于单租户"防误操作"；**必须补**配额、默认断网、cap drop、不挂 socket、敏感路径保护；多租户不可信 → 换档 |
| "沙箱拦住进程连网有几种做法？哪种最可靠？" | netns（默认无网）> 出站代理白名单 > 防火墙规则 > /etc/hosts（最弱，可被 IP 绕过）；最可靠是"netns + 出口强制代理" |
| "为什么说 '有 0day 所以沙箱没用' 是错的？" | 混淆"降低概率"与"降低后果"；沙箱同时做两件事，且**配置层能挡大多数真实攻击**；剩余风险靠短 TTL 凭证 + 审计兜底 |
| "gVisor 和 Firecracker 怎么选？" | 共享内核收窄 vs 独立内核；密度/兼容性 vs 安全等级；举 Modal(gVisor) 与 E2B(Firecracker) 的对比；gVisor 必须做真实负载验证 |
| "沙箱内要调 AWS，凭据怎么给？" | 不给原始凭证：出站代理持有 + 短 TTL STS + SigV4 重签；注意 aws-chunked/预签名 URL 无法重签需透传；mask 需 TLS 终止 |
| "怎么验收沙箱是真的隔离了？" | 主动越界测试四件套：读宿主敏感文件 / 连外网与私网 / fork 炸弹 / 写 `/proc/sys`；再加审计日志覆盖与告警验证 |
