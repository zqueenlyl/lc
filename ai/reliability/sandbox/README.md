# Sandbox · 沙箱隔离执行

> 让 Agent 生成的代码、命令和副作用被关进受控环境里跑：**碰不到宿主文件、上不了网、跑不超资源，越界就被拦。** 一句话：**Harness 给模型方向盘，Sandbox 是笼子 + 安全气囊。**
> 编码 Agent（Claude Code / Codex / Pi）、代码评测（Judge0 / SWE-bench）、Computer Use、FaaS 多租户，底层都在用某种沙箱。

配套 MVP：[mvp.py](./mvp.py)（虚拟 FS + 命令白名单 + 资源配额 + 审计日志，不碰真实系统）。
环节主线（01–11 关卡地图）：见 [环节00-总揽与环节导航.md](./环节00-总揽与环节导航.md)。**本页讲沙箱这门技术本身**（是什么 / 方法全景 / 怎么选），那边讲**一条主线 + 三大阶段怎么串**。
横切总表：[沙箱选型与落地总表.md](./沙箱选型与落地总表.md)（威胁建模 / 场景映射 / 产品对比 / 成本模型 / 评审清单 / 排查顺序）。

## 一、技术讲解

Agent 和普通程序最大的区别：**它按自然语言意图产生代码和命令，这些副作用不可信**。模型可能：

- 读走 `~/.ssh`、`.env`、云凭证；
- `rm -rf`、`git push --force`、改系统配置；
- 偷偷联网外传数据。

沙箱解决的是「执行层隔离」：不管模型多不可信，它的动作只能作用在一个受限的盒子里。隔离的五个维度：

| 维度 | 要挡什么 | 内核原语 |
|---|---|---|
| 文件系统 | 读宿主敏感文件 / 写坏宿主 | mount ns + overlayfs + `pivot_root` + 只读根 |
| 网络 | 外传数据 / 打内网 | network ns + veth + 出站代理 |
| 进程 | 提权、逃逸 | pid ns + seccomp + capabilities + `no_new_privs` |
| 用户 | 容器内 root ≈ 宿主 root | user ns + UID/GID 映射 |
| 资源 | 跑死循环 / 吃内存 | cgroup v2（cpu / memory / pids / io） |

**关键认知**：namespace 只能限"看得见什么"，**限不了"用多少"**（那是 cgroup 的职责）——这是最常见的概念混淆。五个维度的机制细节见 [环节 01](./环节01-隔离原语详解.md)。

**沙箱 ≠ 护栏（Guardrails）**，二者分层：

- [Guardrails](../guardrails/README.md) 是**策略层**：允许做什么、要谁审批、输出对不对。
- Sandbox 是**执行层**：动作真正落在哪个环境、能碰到什么。
- 护栏决定「能不能」，沙箱保证「就算放行也炸不出去」。生产上两者要绑死。

**一条硬要求**：**文件系统隔离与网络隔离必须同时做**——只做前者，被攻破的 Agent 能把密钥传出去；只做后者，它能给系统开后门换取网络访问。两者是**乘性**关系，缺一个等于都没有。

## 二、功能作用

- **兜底隔离**：Agent 执行不可信代码时，宿主机和网络不受伤。
- **可复现**：每次从干净快照起跑，避免「我本地能跑」。
- **可审计**：所有命令、读写、网络请求留痕。
- **资源治理**：单任务限 CPU/内存/进程数/时间，防拖垮整机。
- **多租户**：一个沙箱一份环境，互不串数据。
- **凭证边界**：让 Agent「能用权限」但「拿不到凭证」（[环节 06](./环节06-凭证与密钥管理详解.md)）。

## 三、沙箱类型怎么选

隔离强度、启动速度、运维成本不可兼得：

| 类型 | 隔离强度 | 启动 | 代表 | 适合 |
|---|---|---|---|---|
| 进程级 | 弱（同内核） | 毫秒 | bubblewrap、Seatbelt、Landlock | 单租户编码 Agent 兜底 |
| 容器 | 中 | 百毫秒~秒 | Docker、Podman | CI、编码 Agent 常规选择 |
| 强化容器 | 中高 | 百毫秒 | **gVisor**（用户态内核） | 多租户 + 需加固 |
| 微虚拟机 | 强（独立内核） | 百毫秒 | **Firecracker**、Kata、Cloud Hypervisor | 云函数 / 代码评测 / 代码执行 |
| WebAssembly | 中 | 微秒~毫秒 | Wasmtime、WASI | 插件、浏览器端、纯函数 |
| 云沙箱 | 强 | 按需 | E2B、Modal、Daytona、Codex 云 | 免自运维 |

记忆口诀：**进程快但弱，容器是默认，gVisor 是最兼容的加固，微 VM 最稳，Wasm 最轻，云沙箱最省心。**

**唯一硬分界是"有没有独立内核"**：它决定一次内核 0day 的影响范围。完整决策树（威胁建模三问 → 场景映射 → 产品对比）见 [环节 02](./环节02-隔离强度谱系与选型.md) 与 [沙箱选型与落地总表.md](./沙箱选型与落地总表.md)。

## 六、落地建议

1. 先做**威胁建模三问**：要挡谁、代码多不可信、失守代价多大（[总表 §1](./沙箱选型与落地总表.md)）。
2. 默认 **网络关闭**，要联网走域名白名单；**拒绝私网与云元数据地址**。
3. 资源配额（CPU/内存/进程数/超时）是必选项，不是加分项。
4. **凭证不进上下文、不进沙箱、TTL 要短**；能出站代签就别发原始 key。
5. 留**审计日志**（命令、读写路径、网络出口、**越界尝试**），出事了能复盘。
6. 从容器起步，多租户或高价值再上微 VM / 云沙箱，别一上来自研。
7. 上线前过一遍**配置评审清单**，并做**主动越界测试**（[环节 08](./环节08-逃逸攻击面与加固详解.md) §3）。
