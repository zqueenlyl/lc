# AI 生视频工具与生成范式调研

> **性质**：外部行业调研笔记，与 kb-gateway 知识库内容无关，仅作技术选型参考。
> **调研时间**：2026-10-10 ｜ **数据窗口**：2026-08 ~ 2026-09 公开横评与官网报价
> **注意**：视频模型迭代极快，参数（时长 / 分辨率 / 价格 / API 可用性）每月都在变，落地前必须复核官网。

---

## 0 一句话结论

当前范式是 **「短片段生成 + 工程编排兜底」**：模型只负责**单镜头内**的画面质量，**跨镜头一致性一律靠工程手段**（参考图注入、首尾帧、全局角色资产、人工筛选重生成）。

> 不存在一键生成完整短剧的模型。所有模型单次只能输出几秒到 30 秒片段，完整剧集必须**分段生成 + 后期剪辑缝合**。

---

## 1 范式的五个维度

工具之间的差异不在品牌，在这五个维度上的取值组合：

| 维度 | 可能取值 |
|---|---|
| **输入模态** | 文生 / 图生 / 多参考图 / 首尾帧 / 视频续写 |
| **输出模态** | 纯画面 / **原生音画同步** |
| **控制粒度** | 仅提示词 / 运镜 / 局部运动 / 角色锁定 |
| **时长策略** | 单片段 / 续写拼接 / 延长 |
| **部署形态** | 云端 API / 开源权重私有化 |

## 3 各生成范式详解

### 3.1 文生视频（T2V）

全部工具支持。**但对量产无实用价值** —— 纯提示词锁不住角色，是漂移的主要来源，只适合概念稿 / 氛围测试。

### 3.2 图生视频（I2V）

全部工具支持。**短剧生产的实际主力范式**，角色参考图在这一步注入。

### 3.3 多参考主体锁定

| 工具 | 支持情况 |
|---|---|
| **Vidu Q3** | 多人物参考图**同时传入**，多角色短剧漂移概率相对最低 |
| **Veo 3.1** | 最多 **4 张**参考图维持一致性 |
| 可灵 3.0 | 单人物写实稳定性优秀；**多人物同框易互相干扰** |
| Seedance 2.5 | 单镜头人物好，**镜头一切换极易变脸**，每段必须带参考图 |
| Wan 3.0 | **模型本身无身份记忆**，完全依赖外部图像模型锁定 |

### 3.4 首尾帧（锚帧续写）

工业界**最有效的一致性手段**：上镜头末帧 = 下镜头首帧，模型只在两帧之间插值。

- 优点：跨镜头外观稳定性显著高于纯 prompt
- 局限：**误差逐镜头累积**，长片会"滚雪球"，需定期重锚

### 3.5 续写 / 延长

| 工具 | 时长上限 | 备注 |
|---|---|---|
| 可灵 3.0 | 3 分钟 | **能力上限**；实测超过 15s 后画面一致性开始下降 |
| Seedance 2.5 | 30s 续写 | — |
| Veo 3.1 | 60s | 需付费订阅 |
| R1 | 5 分钟 + 无限延长 | 靠 Agent 编排而非单次生成 |

行业共识：**长短剧全部依赖分段生成 + 后期缝合，不存在一键输出几十分钟正片的模型。**

### 3.6 运镜与运动控制

| 工具 / 方向 | 能力 |
|---|---|
| **可灵 3.0** | 推拉摇移等复杂镜头语言；**MotionBrush 局部运动笔刷** |
| **Seedance 2.5** | 自动识别远景 / 特写 / 推拉摇移；中文提示词理解最强 |
| 学术方向 | 相机轨迹条件控制、姿态 / 深度 / 边缘 ControlNet 分支 |

### 3.7 原生音画同步

| 有原生音频 | 无原生音频 |
|---|---|
| 可灵、Seedance、Veo 3.1、~~Sora 2~~ | Vidu、Wan、PixVerse、Pika、Runway |

- 有原生音频：口型与台词自动匹配，**Seedance 中文口型表现最好**，大幅减少后期工作量
- 无原生音频：**必须自建 TTS + 视频合成 + 口型对齐管线**，这是短剧工程最大的隐藏工作量之一
- ⚠️ 即便有原生音频，**多镜头拼接后仍会出现音画错位**，最终项目仍需音频校准模块

### 3.8 特殊范式

| 范式 | 工具 | 说明 |
|---|---|---|
| **文档驱动生成** | Wan 3.0 | 读取文档直接生成视频 |
| **视频编辑 / 局部重绘** | Runway Gen-4.5 | 后期向，非生成向 |
| **空间音频** | Veo 3.1 | 声音随物体移动 |
| **风格化 / 艺术** | Pika 3.5、PixVerse V6 | 不适合真人写实叙事 |

## 4 关键结论：一致性是工程问题，不是模型问题

> **没有任何模型彻底解决跨镜头人物漂移问题，只是漂移概率高低的区别。**

生产环境**必须**用工程手段兜底：

1. 角色参考图
2. IP-Adapter
3. **固定角色资产库**
4. 锚帧续写
5. 人工筛选 + 重生成

**对架构的直接推论：**

| 层 | 职责 |
|---|---|
| 模型层 | 只保证「单镜头内像」 |
| **编排层** | **必须负责「跨镜头一致」** |

因此「全局角色资产 + 自动分发到每个镜头」的编排系统不是加分项，而是**必需品**。

## 5 场景选型建议

| 业务场景 | 首选 | 备选 |
|---|---|---|
| 写实精品竖屏短剧（少量高质量镜头） | 可灵 3.0 | Seedance 2.5 |
| **批量量产 / 多角色频繁切换 / 控成本** | **Vidu Q3** | Wan 3.0 |
| 创意短视频、广告片头、电影氛围感 | Seedance 2.5 | 可灵 |
| 私有化 / 技术原型 / 毕业设计 | **Wan 3.0**（开源权重本地跑） | — |
| 二次元、漫剧、艺术短片 | PixVerse V6 | Pika |
| 海外业务、后期剪辑重编辑 | Runway Gen-4.5 | PixVerse |

海外模型（Runway / Veo / Sora）在国内面临**网络访问、版权合规、审核**三重问题，**不适合国内业务量产**。

## 6 成本与工程约束

| 项目 | 参考值 |
|---|---|
| 国产闭源 API | 约 **0.3–1.3 元 / 秒**（1080P，受分辨率与队列优先级浮动） |
| 一分钟成片 | 约 **25–60 元 / 分钟**（全 AI 生成画面） |
| 开源 Wan 本地 | 零调用费，只消耗显卡算力 |
| 云端审核通过率 | 约 **60–80%**，需设计失败重试与任务降级 |
| API 工程能力 | 可灵 / Seedance / Vidu 均支持 REST + 异步任务 + 回调通知 |

**成本与质量不可兼得**：高清写实 = 贵 + 慢；快速批量 = 画质下降。

---

## 7 七个绕不开的坑

1. **不存在一键生成完整短剧** —— 所有模型单次几秒到 30 秒，续写累积误差
2. **角色一致性是工程问题，不是模型问题** —— 只靠提示词无法锁死人物
3. **画面内文字几乎全部乱码** —— 字幕、logo、标题必须后期叠加
4. **成本与质量不可三角** —— 没有两全方案
5. **版权商用坑** —— 网页免费生成多限非商用；不得传入真人明星肖像；AI 生成内容需保留人类编辑干预记录
6. **国内风控审核** —— 批量生产通过率 60–80%，必须有重试与降级
7. **原生音频不是万能** —— 拼接后仍错位，仍需音频校准模块

## 8 完整流水线（量产视角）

```
剧本 → 分镜脚本 → 角色参考资产生成 → 分段视频生成 → TTS 配音
                                        ↓
                          音画对齐合成 → 字幕叠加 → 批量调度 / 失败重试 / 成本统计
```

- 只调用模型 API 生成视频是**最浅的一层**
- 真正的工程价值在 **调度、一致性兜底、音频对齐、失败重试、成本核算**
- 选型要写清取舍：选 Vidu 就要说明如何补偿物理动作偏弱；选 Wan 就要讲如何通过参考图提升一致性
