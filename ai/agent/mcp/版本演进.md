# MCP 版本演进与变更特性

> 一句话：MCP 从 2024-11 首版到 2026-07，**一年半走了 5 个修订版**，主线是"从有状态、双向、重协商 → 无状态、请求-响应、可缓存"。
> 规范原文：`https://modelcontextprotocol.io/specification/<version>`；每版变更日志在 `.../<version>/changelog`。
> 相邻文档：[README.md](./README.md)（MCP 技术讲解 + MVP）、[环节 05 工具接入协议详解](../环节05-工具接入协议MCP详解.md)。

---

## 0. 速查总览

| 版本 | 主题 | 定性 | 最大变化 |
|---|---|---|---|
| **2024-11-05** | 初版 | 起点 | stdio + HTTP+SSE 双传输；`initialize` 握手；tools / resources / prompts |
| **2025-03-26** | 传输与授权重构 | 可用性大版本 | **Streamable HTTP 取代 HTTP+SSE**；OAuth 2.1 授权框架；tool annotations；JSON-RPC batching |
| **2025-06-18** | 生产化 | 安全与结构化 | **结构化工具输出**；elicitation；**强制 `MCP-Protocol-Version` 头**；**移除 batching** |
| **2025-11-25** | 生态与授权 | 一周年大版本 | **OIDC Discovery**；icons；增量授权同意；**实验性 tasks**；JSON Schema 2020-12 默认方言 |
| **2026-07-28** | **无状态化** | **破坏性重构** | **删 `initialize` 握手 + 删 `Mcp-Session-Id`**；`server/discover`；**MRTR**；`subscriptions/listen`；`ttlMs`/`cacheScope` |

> 破坏性变更集中在两版：**2025-06-18**（移除 batching、新增必带头）与 **2026-07-28**（整体无状态化）。
> 官方自 2026-07-28 起确立**特性生命周期政策**：Active / Deprecated / Removed 三态，**弃用到最早可移除间隔 ≥ 12 个月**。

---

## 1. 2024-11-05（初版）：定下协议骨架

首版就把角色（Host / Client / Server）、消息层（JSON-RPC 2.0）、能力原语定死了，后续版本基本是在这个骨架上加减。

| 维度 | 初版内容 |
|---|---|
| 传输 | **stdio**（本地子进程）+ **HTTP with SSE**（两个端点：POST 上行 + SSE 下行） |
| 生命周期 | `initialize` → `InitializeResult` → `notifications/initialized`；initialize 前不得发其他请求 |
| 服务端原语 | **prompts**、**resources**（URI 寻址）、**tools** |
| 客户端原语 | **sampling**（服务端反向请求模型）、**roots**（客户端告知工作目录边界） |
| 通用能力 | `logging`、`completion`（参数补全）、`progress`、`cancellation`、`ping` |
| 鉴权 | 无（未定义） |

## 2. 2025-03-26：传输层推倒重来 + 授权框架

### 2.1 主要变更

| 类型 | 变更 | PR |
|---|---|---|
| **替换** | 用 **Streamable HTTP** 替换 **HTTP+SSE** 传输——单一 endpoint，支持流式与非流式响应 | #206 |
| **新增** | 基于 **OAuth 2.1** 的完整授权框架（授权码流 + PKCE） | #133 |
| **新增** | **JSON-RPC batching**（后来又被移除） | #228 |
| **新增** | **tool annotations**：描述工具行为（是否只读 / 是否有破坏性） | #185 |

### 2.2 其他 schema 变更

- `ProgressNotification.message`：进度通知可带描述性状态文本；
- **音频数据**支持，与文本、图像内容类型并列；
- 新增 **`completions` 能力**，显式声明支持参数自动补全。

### 2.3 为什么重要

- **Streamable HTTP 是分水岭**：HTTP+SSE 需要两个端点、长连接难恢复；Streamable HTTP 一个 endpoint 同时支持请求-响应和流式，为后来的"可路由、可缓存、无状态"打底；
- 授权从"无"到"OAuth 2.1 全框架"，远程 MCP 才真正可上生产。

## 3. 2025-06-18：生产化（安全 + 结构化输出）

### 3.1 主要变更

| # | 类型 | 变更 | PR |
|---|---|---|---|
| 1 | **移除** | 移除 JSON-RPC **batching** 支持 | #416 |
| 2 | **新增** | **结构化工具输出**（tool output schema） | #371 |
| 3 | **修改** | MCP server 归类为 **OAuth Resource Server**，加受保护资源元数据以发现授权服务器 | #338 |
| 4 | **新增要求** | 客户端必须实现 **RFC 8707 Resource Indicators**，防恶意 server 骗取 access token | #734 |
| 5 | **新增** | **elicitation**：server 可在交互中向用户请求额外信息 | #382 |
| 6 | **新增** | tool call result 支持 **resource links** | #603 |
| 7 | **新增要求** | 走 HTTP 时，后续请求**必须**带 `MCP-Protocol-Version` 头 | #548 |
| 8 | **修改** | 生命周期操作中 **SHOULD → MUST**（收紧握手约束） | — |

### 3.2 其他 schema 变更

- 更多接口类型支持 `_meta` 字段；`CompletionRequest` 加 `context`（携带已解析变量）；新增 `title` 字段（人类可读名），让 `name` 专作程序化标识。

### 3.3 注意点

- 这版**移除了 batching**——如果你的代码依赖批量 JSON-RPC，这是第一个破坏性变更点；
- `MCP-Protocol-Version` 头是后来"无状态化"的前置伏笔：请求开始**自描述版本**。

## 4. 2025-11-25：一周年大版本（授权 + 生态 + 实验性 tasks）

### 4.1 主要变更（9 项）

| # | 变更 | 编号 |
|---|---|---|
| 1 | 授权服务器发现支持 **OpenID Connect Discovery 1.0** | PR #797 |
| 2 | tools / resources / resource templates / prompts 可暴露 **icons** 元数据 | SEP-973 |
| 3 | 通过 `WWW-Authenticate` 支持**增量式作用域授权同意**（incremental scope consent） | SEP-835 |
| 4 | 提供**工具命名指导** | SEP-986 |
| 5 | 更新 `ElicitResult` 与 `EnumSchema`，支持**有/无标题、单选/多选的枚举** | SEP-1330 |
| 6 | 新增 **URL 模式 elicitation** | SEP-1036 |
| 7 | sampling 支持**工具调用**（`tools` / `toolChoice` 参数） | SEP-1577 |
| 8 | 新增 **OAuth Client ID Metadata Documents**（推荐的客户端注册机制） | SEP-991 |
| 9 | 新增**实验性 tasks**（轮询 + 延迟结果，跟踪持久化请求） | SEP-1686 |

### 4.2 次要变更（10 项，挑要点）

- stdio 下可用 **stderr 记录所有类型日志**（不只错误）；
- `Implementation` 加可选 `description`；
- Streamable HTTP 对无效 `Origin` 头**必须返回 403**；
- **输入验证错误**应作为"工具执行错误"而非协议错误返回，**便于模型自我纠正**；
- **SSE 轮询**：允许服务器随时主动断开连接（SEP-1699）；恢复始终走 GET，事件 ID 应编码流身份；
- 受保护资源元数据发现对齐 **RFC 9728**，`WWW-Authenticate` 可回退 `.well-known`；
- elicitation schema 所有原始类型支持**默认值**；
- **确立 JSON Schema 2020-12 为 MCP schema 默认方言**。

### 4.3 治理更新

- 正式确立**治理结构**、**工作组/兴趣组**、社区沟通准则，以及 **SDK 分级体系**（Tier 1/2/3，明确功能支持与维护承诺）。

### 4.4 定性

**这版没有破坏性变更**，是"能力扩张 + 规范化"版：授权做得最深（OIDC、增量授权、CIMD），并把 JSON Schema 方言、SDK 分级、治理流程一次补齐。

## 5. 2026-07-28：无状态化（破坏性重构）

> 官方口径："自发布以来最大的一次协议修订"，核心动机是让远程 MCP server **摆脱粘性会话 + 共享会话存储 + 网关 DPI**，直接跑在普通轮询负载均衡之后。

### 5.1 重大破坏性变更

| # | 变更 | SEP |
|---|---|---|
| 1 | **移除协议级会话与 `Mcp-Session-Id`**；`tools/list`、`resources/list`、`prompts/list` 不再随连接变化 | SEP-2567 |
| 2 | **协议无状态化**：移除 `initialize` / `notifications/initialized`；版本与能力改由**每请求 `_meta`** 承载；版本不符返回 `UnsupportedProtocolVersionError` | SEP-2575 |
| 3 | **新增 `server/discover`**（Server **MUST** 实现），公布版本 / 能力 / 身份 | SEP-2575 |
| 4 | 用 **`subscriptions/listen`** 取代 HTTP GET 端点与 `resources/subscribe` / `unsubscribe` | SEP-2575 |
| 5 | 删除 `ping`、`logging/setLevel`、`notifications/roots/list_changed`；日志级别改为每请求 `logLevel` | SEP-2575 |
| 6 | **tasks 迁出核心** → 扩展 `io.modelcontextprotocol/tasks`：`tasks/result`（阻塞）→ `tasks/get`（轮询），新增 `tasks/update`，删除 `tasks/list` | SEP-2663 |
| 7 | **引入 MRTR**，取代服务端发起的 `roots/list`、`sampling/createMessage`、`elicitation/create` | SEP-2322 |
| 8 | 所有结果新增必填 **`resultType`**：`"complete"` 或 `"input_required"` | SEP-2322 |
| 9 | **移除 SSE 可续传与消息重投**（`Last-Event-ID`、SSE event ID）；断流后必须用**新请求 ID 重发** | SEP-2575 |

### 5.2 次要但需改代码的变更

| 变更 | SEP |
|---|---|
| 列表/资源读取结果新增必填 **`ttlMs`** 与 **`cacheScope`**（`CacheableResult`）——用带 TTL 的缓存/轮询部分取代订阅推送 | SEP-2549 |
| Streamable HTTP POST **强制要求 `Mcp-Method` / `Mcp-Name` 头**，且需与 body 一致；支持 `x-mcp-header` 从工具参数映射自定义头 | SEP-2243 |
| 资源未找到错误码由 `-32002` 改为 **`-32602`** | SEP-2164 |
| **错误码重分区**：`-32000~-32019` 给实现自定义；`-32020~-32099` 归规范（`HeaderMismatch` → `-32020`、`MissingRequiredClientCapability` → `-32021`、`UnsupportedProtocolVersion` → `-32022`） | — |
| 删除 `notifications/elicitation/complete` 与 elicitation 的 `elicitationId` | — |
| 工具 `inputSchema` / `outputSchema` 放宽到完整 **JSON Schema 2020-12**（允许 `oneOf`/`anyOf`/`allOf`/条件/`$ref`）；`structuredContent` 可为任意 JSON 值 | SEP-2106 |
| 授权：凭据按 issuer 键控持久化、不得跨授权服务器复用、变更时重注册；OIDC 响应需含 `iss` 且客户端 **MUST** 校验（RFC 9207） | SEP-2352 / SEP-2468 / SEP-837 |
| `_meta` 中约定 **W3C Trace Context** 传播键（`traceparent` / `tracestate` / `baggage`） | SEP-414 |
| `tools/list` **SHOULD** 返回确定性顺序（利于客户端缓存与 LLM 提示缓存命中） | — |

### 5.3 弃用（Deprecated，≥12 个月窗口）

| 弃用项 | 官方迁移建议 |
|---|---|
| **Roots** | 改用工具参数 / 资源 URI / 服务端配置 |
| **Sampling** | **直接对接 LLM 供应商 API**（绕过 MCP 协议层） |
| **Logging** | stdio 写 `stderr`；结构化可观测性用 **OpenTelemetry** |
| HTTP+SSE 传输（自 2025-03-26 起就被取代） | 迁移到 Streamable HTTP |
| `includeContext` 的 `"thisServer"` / `"allServers"` | 省略该字段或用 `"none"` |
| OAuth 2.0 动态客户端注册（RFC 7591） | 转向 **Client ID Metadata Documents** |

### 5.4 核心理念：无状态协议，有状态应用

删掉协议层会话 ≠ 应用无状态。官方推荐**显式句柄（explicit handle）**：

- 工具返回句柄（如 `basket_id`、`browser_id`）；
- 模型在后续调用中把它当**普通参数**回传。

官方认为这往往**更强**：模型能跨工具组合句柄、对其推理、在步骤间交接——这是藏在传输元数据里的会话状态做不到的。**把状态显式暴露给模型，而不是隐藏在传输层。**

### 5.5 两个官方扩展（Extensions 成为一等公民）

- **MCP Apps**（SEP-1865）：服务端下发交互式 HTML，Host 在沙箱 iframe 渲染，UI 回连走同一套 JSON-RPC 与审计/同意路径；
- **Tasks**（原实验性核心功能毕业为扩展）：服务端可用 task handle 响应 `tools/call`，客户端用 `tasks/get` / `update` / `cancel` 驱动；任务创建由**服务端主导**。

扩展以**反向 DNS ID** 标识，经 `extensions` map 协商，**独立于规范版本做版本控制**。

## 6. 纵向主线（按维度看演进）

### 6.1 传输

| 版本 | 变化 |
|---|---|
| 2024-11-05 | stdio + HTTP+SSE（双端点） |
| 2025-03-26 | **Streamable HTTP** 取代 HTTP+SSE（单 endpoint，流式/非流式通吃） |
| 2025-06-18 | HTTP 请求**必须**带 `MCP-Protocol-Version` 头 |
| 2025-11-25 | SSE 支持轮询、服务器可随时断开；无效 Origin → 403 |
| **2026-07-28** | **强制 `Mcp-Method` / `Mcp-Name` 头**（网关免解析 body）；**移除断流续传** |

### 6.2 会话与状态

| 版本 | 变化 |
|---|---|
| 2024-11-05 → 2025-11-25 | `initialize` 握手建立会话；Streamable HTTP 用 `Mcp-Session-Id` 关联请求（**会话可选**：不返回该头即无状态） |
| **2026-07-28** | **握手与会话 ID 双删** → 协议核心无状态；跨调用状态改由**服务器自铸句柄**承载 |

### 6.3 反向交互（Server → Client）

| 版本 | 变化 |
|---|---|
| 2024-11-05 | sampling / roots（**依赖长连接会话**） |
| 2025-06-18 | 新增 elicitation |
| 2025-11-25 | elicitation 扩展（URL 模式、枚举、默认值）；sampling 支持工具调用 |
| **2026-07-28** | 三者统一改 **MRTR**（`input_required` + `requestState` 重试），**不再需要长开 SSE**；且 Roots / Sampling / Logging 整体**弃用** |

### 6.4 授权

无（初版）→ **OAuth 2.1 框架**（2025-03）→ **Resource Server + RFC 8707**（2025-06）→ **OIDC Discovery + 增量授权 + CIMD + RFC 9728**（2025-11）→ **issuer 键控 + `iss` 强校验 + CIMD 取代 DCR**（2026-07）。

### 6.5 可发现 / 可缓存 / 可观测

- **可发现**：`tools/list` 运行时枚举（一直有）→ **icon 元数据**（2025-11）→ **`server/discover`**（2026-07，MUST）；
- **可缓存**：**`ttlMs` + `cacheScope`**（2026-07，`tools/list` 等结果自带 TTL 与共享边界）→ 取代长连接订阅推送；
- **可观测**：日志走 stderr / `logging` 能力 → **每请求 `logLevel`** + `_meta` 中 **W3C Trace Context**（2026-07 约定 `traceparent` 等键）。

### 6.6 能力原语

**tools / resources / prompts 三大原语从首版至今未变**——变的是它们的**元数据**（annotations、icons、output schema、ttlMs）和**变化通知机制**（`notifications/*/list_changed` → `subscriptions/listen`）。

## 7. 迁移与选型建议

| 你的现状 | 建议 |
|---|---|
| 还在 HTTP+SSE | 迁 **Streamable HTTP**（2025-03 起取代，2026-07 正式 Deprecated） |
| 依赖 `Mcp-Session-Id` 做会话 | 改**显式句柄**（句柄做工具参数回传），或把状态放外部存储 |
| 依赖 sampling | 规划改为**直连 LLM 供应商 API**（已弃用）；过渡期用 MRTR |
| 依赖 `ping` / `logging/setLevel` / `Last-Event-ID` | 2026-07 已删除，必须改 |
| 依赖 `resources/subscribe` | 改 `subscriptions/listen`，或靠 `ttlMs` **TTL 缓存 + 轮询** |
| 按 `-32002` 匹配资源缺失 | 改为 **`-32602`** |
| 用 2025-11-25 实验性 tasks | 迁到 **Tasks 扩展**（`tasks/list` 已删） |

**面试口径**：MCP 的演进主线是"**把状态从协议层赶到应用层**"——先统一传输（Streamable HTTP），再补授权与结构化输出，最后**整体无状态化**，使其能跑在商品化 HTTP 基础设施上（轮询 LB、serverless、边缘）。代价是服务端主动能力全部改为**请求内的 MRTR**，弃用了 Roots / Sampling / Logging。
