## 1. 条件边：让图「拐弯」

线性图只能一条道走到底。条件边根据**当前 State** 决定下一个节点。

```python
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    query: str
    kind: str
    answer: str

def classify(state: State):
    # 根据内容分类
    kind = "code" if any(w in state["query"] for w in ("代码", "bug", "python")) else "general"
    return {"kind": kind}

def answer_code(state): return {"answer": "走「代码」分支"}
def answer_general(state): return {"answer": "走「通用」分支"}

def route(state: State) -> str:
    # 返回下一个「节点名」字符串
    return "answer_code" if state["kind"] == "code" else "answer_general"

g = StateGraph(State)
g.add_node("classify", classify)
g.add_node("answer_code", answer_code)
g.add_node("answer_general", answer_general)
g.add_edge(START, "classify")
g.add_conditional_edges(
    "classify",          # 从哪个节点出发
    route,               # 路由函数：返回节点名
)
g.add_edge("answer_code", END)
g.add_edge("answer_general", END)
app = g.compile()
```

要点：

- 路由函数**入参是 State**，返回**目标节点名**（字符串）。
- 也可以返回一个「映射表」形式，见下方第 2 节。

### 1.1 用「映射表」做静态路由

当跳转规则固定时，可让路由函数返回一个键，再映射到节点：

```python
def route(state) -> str:
    return state["kind"]  # 返回 "code" / "general"

g.add_conditional_edges(
    "classify",
    route,
    {
        "code": "answer_code",
        "general": "answer_general",
    },
)
```

路由函数返回哪个 key，就跳转到对应 value 的节点。**推荐优先用这种方式**，可读性更好。

## 2. 典型路由模式

### 2.1 语义路由（Semantic Router）

用 LLM 判断 query 意图，分流到不同处理器（客服 / 技术 / 销售 / 兜底）：

```python
from langchain_openai import ChatOpenAI

def intent_route(state):
    prompt = f"判断问题属于：support / sales / technical / fallback。问题：{state['query']}"
    kind = llm.invoke(prompt).content.strip().lower()
    return kind

g.add_conditional_edges("route", intent_route, {
    "support": "support_node",
    "sales": "sales_node",
    "technical": "technical_node",
    "fallback": "fallback_node",
})
```

### 2.2 失败重试 / 质量门禁

```python
def quality_route(state):
    return "ok" if state["score"] >= 0.8 else "retry"

g.add_conditional_edges("check", quality_route, {
    "ok": "generate",
    "retry": "retrieve",   # 回指前面的节点 → 形成循环
})
```

## 3. 循环：让图「反复执行」

循环就是**某条边指向了前面的节点**，配合一个**终止条件**避免死循环。

### 3.1 手写循环（多跳检索）

```python
class State(TypedDict):
    query: str
    hops: int
    evidence: list
    answer: str

def hop(state):
    state["evidence"].append(f"检索第 {state['hops']+1} 跳")
    state["hops"] += 1
    return state

def should_continue(state) -> str:
    # 跳数够了就结束，否则继续
    return "generate" if state["hops"] >= 3 else "hop"

def generate(state):
    return {"answer": f"基于 {len(state['evidence'])} 条证据生成"}

g = StateGraph(State)
g.add_node("hop", hop)
g.add_node("generate", generate)
g.add_edge(START, "hop")
g.add_conditional_edges("hop", should_continue, {
    "generate": "generate",
    "hop": "hop",           # 回指自己 → 循环
})
g.add_edge("generate", END)
app = g.compile()
```

关键点：

- **终止条件必须由 State 驱动**（如 `hops` 计数、`finished` 标志、`max_iterations`），不能靠「硬编码死循环」。
- 循环步数受 `recursion_limit` 约束（默认 25），超限抛 `GraphRecursionError`。

### 3.2 用递归上限兜底

即使你忘了写终止条件，`recursion_limit` 也能防止失控：

```python
try:
    app.invoke({"query": "..."}, config={"recursion_limit": 50})
except GraphRecursionError:
    print("达到递归上限，循环被强制终止")
```

## 4. ReAct Agent：循环图的经典应用

ReAct（Reasoning + Acting）的流程本质是：

```
思考/调用 LLM → 是否要调工具？
   ├─ 要 → 执行工具 → 把结果回填 → 回到「调用 LLM」
   └─ 不要 → 输出最终答案 → 结束
```

这就是一个「LLM 节点 + 工具节点 + 条件循环」。

### 4.1 用 create_react_agent 一行构建

```python
from langgraph.prebuilt import create_react_agent
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool

@tool
def multiply(a: int, b: int) -> int:
    """两数相乘"""
    return a * b

llm = ChatOpenAI(model="gpt-4o-mini")
agent = create_react_agent(llm, tools=[multiply])

result = agent.invoke({"messages": [("user", "计算 12 * 34")]})
print(result["messages"][-1].content)
```

`create_react_agent` 会自动：

1. 构建 `agent`（调 LLM）与 `tools`（执行工具）两个节点。
2. 设置条件边：LLM 输出工具调用 → 走工具节点 → 回到 LLM；输出最终答案 → 结束。
3. 内置 `messages: Annotated[list, add_messages]` 状态。

### 4.2 手写 ReAct 图（理解内部原理）

```python
def call_model(state):
    # 实际中：让 LLM 决定「继续调工具」还是「给出答案」
    response = llm_with_tools.invoke(state["messages"])
    return {"messages": [response]}

def call_tools(state):
    from langgraph.prebuilt import ToolNode
    return ToolNode(tools).invoke(state)

def should_continue(state):
    last = state["messages"][-1]
    # 有工具调用就继续执行工具，否则结束
    return "tools" if last.tool_calls else END

g = StateGraph(State)
g.add_node("agent", call_model)
g.add_node("tools", call_tools)
g.add_edge(START, "agent")
g.add_conditional_edges("agent", should_continue, {"tools": "tools", END: END})
g.add_edge("tools", "agent")
app = g.compile()
```

## 5. 常见陷阱

1. **循环没有可变终止条件** → 靠 `recursion_limit` 兜底，但应在 State 里显式计数。
2. **条件边缺分支** → 路由函数返回值不在映射表里会抛错；确保所有可能返回值都有对应节点（可加 `fallback`）。
3. **路由函数改 State** → 路由函数应「只读 State 并返回目标」，不要在路由里改数据（改动不会生效）。
4. **`END` 作为条件值** → 想让条件边直接结束，映射值写 `END`（常量）即可。

## 6. 小结

| 需求 | 实现方式 |
|---|---|
| 按状态分流 | `add_conditional_edges(node, route, mapping)` |
| 失败重试 / 循环 | 边回指 + 终止条件 + `recursion_limit` |
| 语义路由 | 路由函数里调 LLM 分类 |
| Agent | `create_react_agent` 或手写 `agent↔tools` 循环 |
