## 一、这一层管什么

上下文工程把窗口当成编译器 / 操作系统：多源材料（系统、技能、记忆、RAG、对话、工具 I/O）要**选择、压缩、排序、去重**，再交给模型。提示是文案；上下文是系统。

```
源：系统、技能、长期记忆、检索、对话、工具 I/O、图/音
  ↓  选择 · 压缩 · 排序 · 去重
窗口（带预算与缓存前缀）
  ↓
模型
```

和两件常混的东西分开：

| | 本层（上下文工程） | 不是本层 |
|---|---|---|
| 问题 | 这一跳窗口装得下、装得对吗？ | |
| vs 提示工程 | 选什么、砍什么、排什么序 | [怎么措辞](./prompt-engineering.md) |
| vs 上下文图 | 召回之后如何裁进窗口 | [系统知道什么](./context-graph.md)（实体 / 关系 / 时效） |

图召回的是一小束关系；CE 决定这束关系占多少 token、放窗口哪一段。

---

## 二、何时停在这一层

- 单次或短会话，失败来自「现场材料」而不是「不会停」。
- 要管预算、前缀缓存、工具结果摘要，但还不需要验证闭环。
- 编码助手打开文件 + diff、客服近窗 + 画像，都是 CE，不必上循环。

## 三、升级信号

| 现象 | 下一层 |
|---|---|
| 要在真实环境行动（读文件、跑命令、调 API） | [Harness](./harness-engineering.md) |
| 窗口每次都对，但任务要测绿才算完 | [循环工程](./loop-engineering.md) |
| 多跳关系 / 「同一个客户」对不齐 | [上下文图](./context-graph.md)（经 [图工程](./graph-engineering.md)） |

长上下文（100k–1M）降低截断压力，不降低噪声和账单。「能塞下」≠「应该全塞」。
