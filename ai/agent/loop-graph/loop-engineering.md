## 一、人从循环里退出来

> Boris Cherny（Claude Code）：「我不再提示 Claude。我有循环在运行。我的工作是编写循环。」

| 旧方式（人是循环） | 新方式（系统是循环） |
|---|---|
| 你 → 提示 → 代理 → 输出 → 你审查 → 你修复 → 重复 | 你设定目标 → 循环运行 → 发现 → 规划 → 执行 → 验证 → 迭代 → 完成 |
| 提示给代理指令 | 循环给代理一份工作 |

[提示工程](../环节02-提示与上下文工程详解.md) 打磨**一次推理**；循环工程打磨**何时再转、凭什么停**。杠杆点从文案移到软件工程。

## 二、五段循环

```
发现(DISCOVER) → 规划(PLAN) → 执行(EXECUTE) → 验证(VERIFY) → 迭代(ITERATE)
```

- 验证通过 → 交付
- 验证失败 → 带着观察再进规划 / 执行，**禁止执行者给自己打分**

和 [ReAct](../环节01-决策与推理范式详解.md) 的关系：ReAct 是「想一步、做一步、看一步」的**微观骨架**；五段是整份工作的**宏观阶段**。每个 EXECUTE 步内部仍是 ReAct，VERIFY 必须是程序或独立评审者。

## 三、开环 vs 闭环

| 类型 | 特点 | 适用 |
|---|---|---|
| **开环** | 探索空间大、token 无上限，容易变成垃圾输出机 | 前沿研究、无限预算 |
| **闭环** | 有边界、每步有评估、预算可预期 | **默认**：90% 的实际工作 |

先闭环跑绿，再按失败案例放开。Agent 总图里的 L2 → L3 就是这条（见 [agent README](../README.md)）。

## 四、单代理 vs 舰队

**单代理**：一个 Agent 独自跑完五段。适合目标清楚、验证可程序化（测绿 / schema / 断言）。

**舰队（Fleet）**：编排者拆目标 → 专家 → 子 Agent，**每一层仍跑同一套五段循环**（递归，不是另一种循环）。

```
编排者（拥有目标 + 完成定义）
  ├─ 研究专家 ─ 网络研究员
  ├─ 工程专家 ─ 编写者 / 调试者
  └─ QA 专家 ─ 测试编写者 / 缺陷追踪
```

舰队只解决「同一套循环复制到多人」。并行怎么汇合、人审插在哪 → [执行图](./execution-graph.md)；是不是在改同一个客户 → [上下文图](./context-graph.md)。

## 五、成本（循环做不起来的真实原因）

多数团队做不出循环，不是五段不会画，是**转不起**：

| 循环类型 | Token 量级（经验） |
|---|---|
| 单代理、中等任务 | 5 万–20 万 / 次 |
| 舰队（编排者 + 3 专家） | 50 万–200 万 / 次 |
| 每日定时循环 | 每周数百万 |

Flash / 缓存前缀 / 路由把单价压下来之后，循环才进入默认形态。账单对策见 [Model Routing](../../reliability/model-routing/)、[环节 10](../环节10-生产级工程化详解.md)。

## 六、六个构建模块（映射本仓库）

| 模块 | 干什么 | 去哪写细的 |
|---|---|---|
| **自动化** | 循环的心跳：定时 / 事件触发发现阶段 | `/loop`、`/goal` |
| **工作树** | 多段执行并行且不互相改同一份工作区 | git worktree / 分支隔离 |
| **技能** | 成功标准、架构、禁区 | [Agent Skills](../agent-skills/) |
| **插件 / 连接器** | 在真实环境行动 | [MCP](../mcp/) |
| **子代理** | **验证者 ≠ 执行者** | [Harness](../harness/) · [环节 08](../环节08-多Agent协作详解.md) |
| **记忆** | 跨 run 记下试过什么、过了什么 | [Memory](../../knowledge/memory/) |

缺验证器的循环是开环；缺「执行者不当裁判」的循环会假装成功。这两条比多两个 Agent 更优先。

## 七、循环场景

| 循环 | 完成定义（例子） | 验证器 |
|---|---|---|
| 编码 | 指定测试绿、lint 过 | `pytest` / 类型检查，**不是**模型自评 |
| 研究 | 问题有引用、冲突已交叉验证 | 来源列表 + 矛盾检测 |
| 内容 | 清单项全覆盖、违禁词为零 | 规则检查 + 抽检 |
| 外展 / 运营 | 状态机走到「已跟进」且有记录 | CRM 字段 + 幂等 |

共同骨架：目标 → 行动 → 检查 → 修复 → 重复直到完成或预算耗尽。
