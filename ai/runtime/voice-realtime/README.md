# Voice / Realtime · 实时语音

> 双向音频流：人边说边听，模型边听边说，中间可插工具调用。延迟预算通常 **端到端 < 500ms** 才像通话，评测和护栏必须 **中途** 做，不能等整段结束。

代表：OpenAI Realtime、Gemini Live、各家电话 Agent / 坐席辅助。

配套 MVP：[mvp.py](./mvp.py)（分片流、部分转写、中途护栏、打断）。

---

## 一、技术讲解

聊天 API 是请求-响应。Realtime 是会话：

```
麦克风 → 分片 → (可选) 服务端 ASR
                → 模型（流式文本 / 原生音频）
                → 播放
用户打断 → 取消当前生成 → 新一轮
```

两条实现路径：

| 路径 | 组成 | 延迟 | 音质/情绪 |
|---|---|---|---|
| **管道** | ASR + LLM + TTS | 易叠到 1s+ | 转写丢语调 |
| **原生语音模型** | 音进音出 | 更低 | 更好，贵、难控词 |

工程难点不在「会说话」，而在 **打断、回声、静音检测、工具调用时的占线话术、中途安全**。

护栏要带 `check_interval`：每 N 个 token / 每 200ms 扫部分输出，命中就 `stop` 或插入免责声明。完整回复上的 DLP 来不及。

---

## 二、功能作用

- **电话 / 车机 / 眼镜**：手眼被占时的主界面。
- **坐席辅助**：实时提示话术，不代替挂断键。
- **会议**：边听边记待办，会后对齐 [Multimodal](../../foundation/multimodal/) 纪要。
- **无障碍**：语音进出。

---

## 三、应用场景

| 适合 | 不适合 |
|---|---|
| 预约、查订单、简单排障 | 需要长 thinking 的法律意见 |
| 语音验证后的低风险操作 | 无人值守大额支付（必须双因素 + 人审） |
| 导览、陪练口语 | 强噪声车间（需硬件降噪） |

---

## 四、延迟预算（经验拆分）

| 段 | 预算 |
|---|---|
| 端侧采集 + 回声消除 | 30–50ms |
| 上行网络 | 50–100ms |
| 模型首包 | 150–250ms |
| TTS 首包 / 原生音频 | 50–100ms |
| 余量 | 抖动与工具 |

工具一跑就破预算：先口语「我查一下」，异步回填。

## 六、落地建议

1. 先做 **半双工**（说完再答），再上全双工打断。
2. 关键槽位（金额、账号）用语音回读确认。
3. 录音与转写的留存期单独合规，默认短、可关。
4. 网络差时降级到「按键 + 短信」，不要死撑实时。
5. 评测用真实电话录音，不要只用干净朗读。

## 八、本目录 MVP

`mvp.py` 把用户话切成音频「帧」，边到边转写；若部分文本出现违禁则立刻 stop；用户发送 `barge_in` 取消当前回复。
