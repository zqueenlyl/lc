# Speculative Decoding · 投机解码

> 用 **小草稿模型** 连续猜多个 token，**大模型一次前向** 并行校验，接受前缀、拒绝后重来。正确性与大模型独自解码一致，平均少跑几次大模型。

2026 年它是推理加速标配，也和 [MoE](../../foundation/moe/) 专家缓存、端侧 [SLM](../../foundation/slm/) 草稿组合在一起。

配套 MVP：[mvp.py](./mvp.py)（草稿猜词、目标校验、统计接受长度）。

---

## 一、技术讲解

自回归解码的痛：每出一个 token，就要把巨大目标模型跑一遍（显存带宽往往比算力更痛）。

投机解码：

```
draft:  已有前缀 → 猜 t1 t2 t3 t4 t5
target: 一次算这 5 个位置的真实分布
        从左到右接受「草稿 = 目标会选的」
        在第一个分歧处停，用目标的采样补 1 个 token
```

若平均接受长度是 γ，大模型前向次数大约降为 1/γ 量级（还要算草稿成本）。EAGLE 等把草稿做到接近目标隐状态，γ 能到 3–5+。

保证：**最终分布与只跑目标模型相同**（在同样采样算法下）。不是「小模型近似生成」。

和 MoE 的摩擦：草稿走的专家与目标可能不同，预取策略要单独设计（2026 论文热点）。

---

## 二、功能作用

- **降延迟 / 提吞吐**：尤其目标模型很大时。
- **不降质量**：与朴素量化折质量不同。
- **端侧减访存**：少把大权重从内存搬来搬去。
- **草稿可用 LoRA 对齐** 目标域，提高接受率。

---

## 三、应用场景

| 场景 | 说明 |
|---|---|
| 云上大模型服务 | 默认开 |
| 端侧大模型 | SLM 草稿 + 量化目标 |
| 领域助手 | 域内 LoRA 草稿，接受率更高 |
| 推理模型 | 思考段也可投机，但草稿要对齐「思考风格」 |

收益小：目标已经很小；或草稿太弱导致 γ≈1 还多了开销。

---

## 四、接受率上不去时查什么

1. 草稿和目标不是同一 tokenizer / 不同系统提示。
2. 采样温度高，分歧来得早。
3. 领域漂移：闲聊草稿去解代码。
4. 草稿太慢，省下的目标前向被吃掉。

## 六、落地建议

1. 先量 **γ 和端到端 ms/token**，不要只看论文数字。
2. 草稿延迟应是目标的一小截（常见 <20–30%）。
3. 温度高时 γ 下降，产品默认温度要和加速一起调。
4. 流式输出仍可按「已接受前缀」先吐给用户。
5. 和路由叠加：小请求直接 SLM，大请求才「SLM 草稿 + 大模型校验」。

## 八、本目录 MVP

- `mvp.py`（标准版）：目标分布是一张固定词表概率表；草稿是「有偏差的近似」。逐步接受直到分歧，统计平均接受长度，对比纯目标逐步解码的前向次数。
- [`mvp-dspark.py`](./mvp-dspark.py)（DSpark 版）：**A 段**用 `no / of` × `problem / course` 演示并行草稿的「多模态碰撞」与低秩 Markov 转移偏置（期望单步接受率 0.550 → 0.931）；**B 段**用 `c_k → a_(r,j) → Θ = τ·SPS(B)` 演示置信度调度，并在一条锯齿 SPS 曲线上对比「早停（论文版）/ 去早停（生产版）/ 全验」。纯标准库零依赖。

## 九、重点论文笔记

- [DSpark · 置信度调度的半自回归投机解码](./DSpark-置信度调度半自回归投机解码.md) —— DeepSeek 上线 DeepSeek-V4 的框架（arXiv:2607.05147，2026-07）：**半自回归草稿**（并行骨干 + 轻量顺序头，解决并行草稿的后缀衰减）+ **置信度调度验证**（校准过的存活概率 × 引擎吞吐曲线，动态裁剪每请求验证长度）。含逐位置接受率分析、消融、生产 Pareto 数据与无损性（因果屏障）论证。

> 2026 年的实测口径提醒：**接受长度 τ 只是中间指标**，最终要看「同吞吐下每用户 tok/s」，且线上收益高度依赖并发档位（低并发拉长块、高并发缩回短块）。
