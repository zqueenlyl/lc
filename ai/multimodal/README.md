# Multimodal · 多模态

> 同一模型原生吃 **文本 / 图像 / 音频 / 视频**（部分还能出口语音），不再靠 OCR、ASR、TTS 一串胶水。2026 年这是前沿模型的默认能力，不是插件。

代表：GPT-5 系视频理解、Claude 图像、Gemini 全模态 + Live、开源 VL / Omni 模型。

配套 MVP：[mvp.py](./mvp.py)（统一消息里混排文本与「图像/音频」占位，做跨模态引用问答）。

---

## 一、技术讲解

早期「多模态」是管道：

```
图 --OCR--> 字 --LLM--> 字
音 --ASR--> 字 --LLM--> 字 --TTS--> 音
```

问题：版式、表情、图表结构、语调在转写时丢掉；延迟叠多层；每层各有错误。

原生多模态把不同模态编到 **共享 token 空间**（视觉 encoder / 音频 encoder 对齐到 LLM hidden）：

```
[图块 tokens] + [声帧 tokens] + [文字 tokens] → 同一 Transformer
```

能力分层：

| 层级 | 例子 |
|---|---|
| 理解 | 看图说话、视频里找事件、听会纪要 |
| 跨模态对齐 | 「第二张表里红色那列对应哪条政策」 |
| 生成 | 文生图/视频通常仍走 [Diffusion](../diffusion/)；部分模型一个 API 两套头 |
| 实时 | [Voice Realtime](../voice-realtime/) 是多模态的流式特化 |

2026 年产品差异在 **覆盖哪些模态、上下文里能放多少张图/几分钟视频、是否原生出声**，而不是「有没有识图开关」。

---

## 二、功能作用

- **少胶水**：减少 OCR/ASR 微服务和 prompt 拼接。
- **保真**：图表、UI 截图、白板照片比纯转写可靠。
- **统一记忆与工具**：同一 Agent 循环里既能看图又能 [Computer Use](../computer-use/)。
- **体验**：一个会话里丢合同 PDF 页 + 录音 + 问题。

代价：视觉 token 很贵（一张图 ≈ 几百到上千 token）；视频按帧采样策略决定成本和漏检。

## 三、应用场景

| 场景 | 模态 | 注意 |
|---|---|---|
| 文档审核 / 发票 | 图 + 文 | 关键字段仍建议结构化抽 + 校验 |
| 工业质检辅助 | 图 | 要域内评测，不能只靠通用 VQA |
| 会议纪要 | 音 + 文 | 说话人分离、实时 vs 会后 |
| UI Agent | 截图 | 见 Computer Use |
| 教辅 / 医疗影像 | 图 | 合规与专家复核 |
| 营销素材 | 文 → 扩散生图 | 理解用 VL，生成用 Diffusion |

---

## 四、工程要点

1. **分辨率与裁剪**：小字发票要高分辨率或切块，否则模型「看不清」。
2. **视频采样**：1 fps 可能漏掉 0.2s 的关键帧；按场景切镜头更好。
3. **引用**：让模型回答时指向「图 2 / 时间 01:13」，便于人审。
4. **缓存**：同一张产品图反复问，用前缀缓存压成本。
5. **降级**：VL 失败再走 OCR，而不是一上来双跑。

## 六、落地建议

1. 先定义 **模态清单和失败降级**，再选供应商。
2. Token 账本按「图张数 / 视频秒数」估，不要只按文字字数。
3. 评测集必须含你们自己的图（单据、后台截图），通用 MMBench 不够。
4. 隐私：图和音往往比纯文本更敏感，日志默认不落原片。
5. 和 [structured-output](../structured-output/) 结合：从图抽出 JSON，再用规则校验。

## 八、本目录 MVP

`mvp.py` 用统一 `Message` 装 `text` / `image` / `audio` 段。检索器按「提及的图 id + 文本」回答跨模态问题，模拟「看图2的红列」这类引用，不跑真实视觉模型。
