# DeepSeek 技术路线与架构演进

> 调研时间：2026-09-11 ｜ 范围：DeepSeek（深度求索）模型谱系、三代注意力架构演进、V4 架构与训练/推理基础设施

## 一、摘要（TL;DR）

DeepSeek 这条线有一条贯穿始终的主线：**在算力受限的前提下，用架构与工程效率换能力**。四次关键换代都指向同一个矛盾——**上下文长度与训练/推理成本随规模线性恶化**：

| 代际 | 时间 | 核心手段 | 解决的成本项 |
|------|------|----------|--------------|
| V2 | 2024-05 | **MLA**（多头潜在注意力）+ DeepSeekMoE | 推理侧 **KV cache 显存** |
| V3 | 2024-12 | **FP8 混合精度训练** + MTP + 无辅助损失负载均衡 | **训练**成本 |
| V3.2-Exp | 2025-09 | **DSA**（DeepSeek 稀疏注意力） | 长上下文**算力** |
| V4 | 2026-04 | **CSA + HCA 序列轴压缩注意力** + mHC + Muon | 把 **1M 上下文做成可负担** |

**核心判断**：V3/R1 把"MLA + MoE + 推理 RL"推到开源前列之后，V4 的目标已不再是榜单 SOTA，而是**"更长上下文更便宜"**——官方效率叙事以 V3.2 为基线，宣称 1M 场景下 FLOPs / KV cache 各降一个数量级（详见 §六）。

## 三、架构三代拆解

### 3.1 一代：MLA + DeepSeekMoE + MTP（V2 / V3）

**MLA（Multi-head Latent Attention）** —— 来自 DeepSeek-V2 技术报告（arXiv:2405.04434）：

| 项 | 说明 |
|----|------|
| 要解决的瓶颈 | 长上下文推理时，**KV cache 的显存占用与访存量**是解码速度的实际上限（算力早就过剩） |
| 机制 | 把每个 token 的 K/V **低秩压缩**成 latent 向量，推理时 KV cache **只存 latent**，需要时再上投影还原 |
| 关键设计 | **解耦 RoPE**：低秩压缩与位置相关的旋转变换不兼容，因此拆出一小部分维度（V4 中为 512 维里的 64 维）专门承载 RoPE，其余维度走压缩路径 |
| 收益（V2 报告口径） | KV cache 减少约 **93.3%**，吞吐提升约 **5.76×** |

**DeepSeekMoE**：两个设计——**细粒度专家**（专家切得更小更多，组合空间更大）+ **共享专家隔离**（公共知识放共享专家，减少路由专家的冗余学习）。V3 配置为 1 共享 + 256 路由、每 token 激活 8 个。

**MTP（Multi-Token Prediction）**：训练时让模型一次预测多个后续 token，**训练信号更密**；推理时该分支可拆卸，理论上可当 **speculative decoding** 的草稿头。

**V3 的另外两块工程**：
- **FP8 混合精度训练**：在 671B 规模上首次验证 FP8 GEMM + 细粒度量化 + 高精度累加，显存与通信开销显著下降
- **无辅助损失负载均衡**：用可学习 bias 调整路由倾向，替代会损害性能的 auxiliary loss

### 3.2 二代：DSA 稀疏注意力（V3.2-Exp，2025-09）

| 项 | 说明 |
|----|------|
| 要解决的瓶颈 | 上下文到 128K 以上后，**注意力 O(N²) 的算力项**成为主要成本 |
| 机制 | **Lightning Indexer** 对因果可见的历史 token 打分，只取 **Top-k** 参与注意力计算 → 复杂度从 O(N²) 降到 **O(N·k)** |
| 代价 | 引入 indexer 自身的计算与一个"选错 token"的召回风险；稀疏选择需要训练课程（dense 预热）才能稳定 |
| 标志意义 | 这是 DeepSeek 长上下文路线的**第一次换代**：从"每 token 表示维度压缩"扩展到"**检索范围压缩**" |

### 3.3 三代：CSA + HCA 序列轴压缩（V4，2026-04）

V4 的注意力**不再以 MLA 为主**，改为两种压缩注意力的**逐层交替**。以下细节来自第三方对 V4 技术报告（官方 PDF 见 `deepseek-ai/DeepSeek-V4-Pro` 仓库）的解读，**由两份独立来源交叉印证**，仍属转述口径：

| 机制 | 压缩比 | 是否有 selector | 说明 |
|------|--------|-----------------|------|
| **CSA**（Compressed Sparse Attention） | **4 : 1** 重叠压缩 | 有（沿用 V3.2 的 DSA selector） | 每 4 个 token 生成 1 个**重叠**摘要（读当前块 + 前一块），indexer 打分后取 **Top-k**（Flash 512 / Pro 1024）；再用 **shared-KV MQA** 读取选中摘要 |
| **HCA**（Heavily Compressed Attention） | **128 : 1** 非重叠 | 无 | 每 128 token 一个摘要，**全部已完成摘要进 dense 注意力**，不做选择 |

层分布（第三方口径）：Flash = 2 层滑窗 + 21 层 CSA + 20 层 HCA；Pro = 30 层 CSA + 31 层 HCA。**每层额外附一条 128-token 未压缩局部滑窗**，保证近程精度。

> **与 MLA 的关系**：MLA 压缩的是**每个 token 的通道维度**；CSA/HCA 进一步沿**序列轴**把历史 token 折叠成摘要。两者低秩 query 形式相近，但**官方报告未声明 CSA/HCA 源自 MLA**，属"平行演进"而非明确继承。
>
> **注意**：CSA **不是严格线性注意力**——indexer 仍需对约 N/m 个压缩条目打分，完整 prefill 仍含二次项（m=4 时约为 Θ(N²/4)）。所谓"线性化"只在 decode 侧成立。

V4 的另外三处改动：

| 组件 | 内容 |
|------|------|
| **mHC**（残差拓扑） | 把 1 条残差流扩为 **4 条**，用 A/B/C 三类映射混合；**B 投影到双随机矩阵集合（Birkhoff polytope）**并经 20 轮 Sinkhorn–Knopp 归一化，约束残差路径的谱范数 ≤ 1 以控稳。报告口径下系统开销约 **6.7%** |
| **优化器** | 大部分逻辑独立矩阵改用 **Muon**（Newton–Schulz 正交化，γ=0.18）；embedding / head / RMSNorm 等仍用 AdamW |
| **MoE 调整** | router affinity 由 Sigmoid 改为 **√Softplus**；**取消节点限制路由**；**前 3 层改为 hash routing**（静态 token→expert 映射）作为 bootstrap；新增权重 1e-4 的 sequence-wise balance loss |

**KV cache 预算**（第三方核算）：压缩条目 512 维 = 64 维 BF16（RoPE）+ 448 维 FP8 ≈ 576 B；CSA 约 144 B/token、HCA 约 4.5 B/token，两类各半 → 总体约为 BF16 GQA8 基线的 **2%** 量级。

## 四、V4 双规格与训练课程

| 配置 | V4-Flash | V4-Pro |
|------|----------|--------|
| 总参数 / 激活参数 | 284B / 13B | **1.6T / 49B** |
| 层数 / hidden | 43 / 4096 | 61 / 7168 |
| 共享 / 路由专家 | 1 / 256 | 1 / 384 |
| 每 token 激活专家 | 6 | 6 |
| 预训练 tokens | 32T | 33T |
| 上下文 | 1M | 1M |
| 路由 scale ρ | 1.5 | 2.5 |

（上表为第三方解读口径，非官方 API 文档披露。）

**训练课程**（第三方转述报告）：
- **序列长度课程**：4K → 16K → 64K → **1M**；**前 1T tokens 为 dense 注意力**，到 64K 阶段才引入稀疏并预热 indexer
- 最大 batch：Flash 75.5M tokens / Pro 94.4M tokens
- 学习率：Flash 2.7e-4 → 2.7e-5；Pro 2.0e-4 → 2.0e-5；warmup 2000 steps
- **FP4 QAT**：MoE 专家权重走 MXFP4，CSA indexer 的 QK 走 FP4 cache；KV cache 混合精度
- **稳定性技巧**：Anticipatory Routing（异常期用历史参数预计算 routing index 并短时 rollback，overhead 约 20%）、SwiGLU clamp

**后训练**：领域专家先 domain SFT → GRPO → **>10 个 teacher 的 on-policy 蒸馏**，用**全词表 reverse KL** 合并（不做 logits 全缓存，只存最后一层 hidden state）。

**推理三档**（与 API 侧 `reasoning_effort` 对应）：Non-think / Think High / Think Max。报告视角下这三档来自**不同的 RL 长度惩罚与上下文配置**，不是单一旋钮。

## 六、长上下文经济学（V4 的官方叙事核心）

| 对照基线 | 单 token 推理 FLOPs | KV cache |
|----------|---------------------|----------|
| V4-Pro（1M 场景） | 约 **27%**（≈ 3.7× 降幅） | 约 **10%**（≈ 9.5× 降幅） |
| V4-Flash（1M 场景） | 约 **10%**（≈ 9.8× 降幅） | 约 **7%**（≈ 13.7× 降幅） |

> 两份第三方来源给出的倍数（3.7×/9.8×、9.5×/13.7×）与比例（27%/10%、10%/7%）**互相吻合**，可信度较高。但需注意：这是**估算口径的 FLOPs/KV 比值，不是端到端延迟或吞吐倍数**。

**长上下文的"能用"边界（重要工程事实）**：报告承认，虽然原生训练到 1M，但 **MRCR 8-needle 在 256K 之后明显退化**——Pro-Max 从 128K 的 0.92 掉到 1M 的 0.59，Flash-Max 从 0.87 掉到 0.49。

> 这条比任何"1M 上下文"的宣传语都更有用：**标称 1M ≠ 无损 1M，实际有效区间大约在 128K–256K**。做 RAG / 长文档 Agent 时，不要用标称窗口做容量规划。

## 七、面试高频追问

1. **MLA 为什么要解耦 RoPE？**
   低秩压缩矩阵作用于 K 的表示，而 RoPE 是**位置相关**的旋转变换——若把 RoPE 也塞进低秩路径，压缩矩阵会变成位置相关且无法预计算，推理时无法复用 cache。解耦的做法是拆出一小部分维度**专供 RoPE**（不参与压缩），其余维度走 latent 压缩。

2. **MLA 压缩的是哪个维度？和 GQA / MQA 有什么本质区别？**
   GQA/MQA 压缩的是**注意力头数**（多个头共享 KV 头），MLA 压缩的是**每个 token 的特征维度**（投影到 latent），两者正交。MQA 是 MLA 的一种退化特例（共享全部 KV 通道）。

3. **DSA 和 V4 的 CSA 是什么关系？**
   DSA 的 selector 机制被 CSA **沿用**，但**候选单元变了**：DSA 在 per-token 的 latent KV 上选 Top-k，CSA 先在 4:1 压缩出的摘要条目上选 Top-k。粒度从"token 级"变成"块级"，这既是压缩比的提升，也是召回风险的来源。

4. **V4 为什么把优化器换成 Muon？**
   官方解读口径：Muon 通过 Newton–Schulz 正交化约束更新矩阵的谱，在 1.6T 量级的训练中提供更稳的更新尺度。代价是 **ZeRO 适配困难**——Muon 需要看到完整逻辑矩阵，不能任意切分到多个 rank，因此需要 hybrid ZeRO + 完整矩阵装箱。

5. **为什么 MoE 要取消节点限制路由 / 用 hash routing 打头？**
   取消节点限制是为了**解除路由的表达能力约束**（代价是通信 fan-out 上升）；前几层 hash routing 是**训练早期不稳定**的 bootstrap 手段——早期路由还没学好，静态映射比随机初始化更稳定。

## 八、未披露边界（不要在这些点上编造）

| 维度 | 缺口 |
|------|------|
| 训练资源 | GPU/NPU 型号、卡数、天数、GPU-hours、总 FLOPs、成本、MFU **全部未披露** |
| 数据 | 类别 / 语言比例、去重率、数据截止日期、污染分析 |
| Serving 栈 | 是否使用 vLLM / SGLang / Mooncake / 分离式 prefill-decode **均未确认**（开源仓库的启动示例不能反推内部栈） |
| 模块级消融 | 无 CSA-only / HCA-only / mHC-off / Muon-off 的同规模对照，单项贡献无法拆分 |
| 端到端指标 | FP4 的端到端吞吐 / 延迟 / 显存对照缺失；效率数字均为估算口径 |
