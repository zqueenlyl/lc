# 环节 10 · Flow 采样与推理（不是 KV 自回归）

> 全链路第十站。对照 Transformer [环节 10](../../../../foundation/transformer/环节10-推理解码与KV缓存详解.md)：LLM 推理是「序列变长 + KV 增量」。H3 推理是「序列长度冻结 + 扩散时间 \(t\) 变短」。把 LLM 的 decode 循环套过来会完全想错瓶颈。

## 1. 推理在循环什么

1. 抽视频噪声、音频噪声，形状等于目标 latent。
2. 编码条件：文本（第 50 层 + refiner）、可选首尾帧/参考（干净 VAE token）。
3. 对调度器每个 \(t\)（视频一套、音频一套）：
   - pack → 50 层 → 双头得到 \(u\)
   - Euler / 官方 flow step：\(x \leftarrow x + \Delta t\cdot u\)（符号随实现）
4. 积到 \(t\approx 0\)：VisualVAE decode + AudioVAE decode（左右合并）。

结束条件是 **步数用尽**，没有 EOS。时长在第 1 步就由 latent 形状定死——不能「再生成 1 秒」除非改格子或走续写任务（开源有 Retake 类工作流，见 DiffSynth；不是本环节默认）。

## 2. 和 KV Cache 的对照（务必记住）

| | LLM decode | H3 一步 |
|--|------------|---------|
| 序列 | +1 token | 仍是 6 万行 |
| 可缓存 | 过去 K/V | **条件 token 的 K/V 理论上可缓存**（实现看引擎）；噪声行每步都变，要重算 |
| AdaLN | 无 | 同一 \(t\) 的 \(\gamma\beta g\) 可缓存；卸 13B |
| 代价主导 | 带宽读 KV | **步数 × \(n^2\) 注意力**（全注意力开源） |

所以「H3 能不能像 vLLM 那样 decode 吞吐上万？」问法错了。问的是：步数能否少（蒸馏已经帮你去掉 CFG 第二遍）、\(n\) 能否短（VAE）、注意力能否稀疏（开源暂无）。

## 3. 你手上真正能拧的旋钮

| 旋钮 | 有没有 | 说明 |
|------|--------|------|
| seed | 有 | 噪声初值 |
| 步数 | 有（栈相关） | 少步快、细节损 |
| guidance / negative | **无** | 蒸馏掉了 |
| temperature / top-p | 无 | 不是分类头 |
| 时长 / 画幅 | 有 | 改 VAE 格子；要对齐 4× / 32× |
| IR | 产品有、本地常无 | 观感差的第一嫌疑 |

## 4. 训练一步 vs 推理一步

| | 训练 | 开源推理 |
|--|------|----------|
| \(x_t\) | 随机 \(t\) 插值真值 | 上一 scheduler 状态 |
| 前向次数 | 蒸馏后 1 | **1** |
| decode | 通常不做 | 只在最后做 |
| AdaLN | 要梯度，必须 load | 可预计算卸载 |

## 5. 工程要点

1. 参考媒体可预编码成 latent，多步复用。
2. `torch.compile` 在 SGLang 当前路径会改数值，官方推荐 eager lossless。
3. 不要拿 LLM 的 TTFT 口径套 H3：没有「首 token」。有的是排队 → 编码条件 → 第 1 步去噪。

## 6. 面试追问

- **H3 推理为什么不能 KV Cache 掉整网？** 噪声 token 每步都变，它们的 QKV 必须重算；只有干净条件段能跨步复用（若引擎实现了）。
- **为什么没有 vocoder 延迟？** 音频与视频同一环结束，decode 是 VAE 不是自回归波形。
