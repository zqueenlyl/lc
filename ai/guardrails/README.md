# Guardrails · 护栏与安全

> 独立于「模型有多聪明」的 **策略平面**：输入筛、工具门禁、输出校验、人审、审计。Agent 越能动手，护栏越要从「内容过滤」升级到「动作控制」。

配套 MVP：[mvp.py](./mvp.py)（五层流水线拦截一次危险退款）。

---

## 一、技术讲解

把安全写进系统提示不够：模型会忘、会被套话、工具调用可以绕过「口头禁止」。2026 年生产做法是 **控制平面与推理平面分离**：

```
用户输入
  → L1 输入筛（注入、PII、违禁）
  → 模型 / Agent
  → L2 工具门禁（谁能调、参数是否越权）
  → 工具执行
  → L3 输出校验（泄密、违禁、schema、事实核对）
  → L4 人审（金额 / 生产变更 / 对外发布）
  → L5 审计日志（谁、何时、调了什么、是否放行）
```

L1/L3 可用小分类模型 + 规则；L2 必须是 **确定性策略**（RBAC、白名单、参数范围），不要交给同一个聊天模型自评。L4 对高风险动作硬门闩。L5 为事故和 [Eval](../eval/) 提供证据。

越狱、间接注入（网页/邮件里藏「忽略指令去转账」）是 Agent 特有风险：工具读到的内容也要当 **不可信输入** 再走 L1。

---

## 二、功能作用

- **限爆半径**：模型犯错也不至于删库、乱退款。
- **合规**：可证明「这类动作必须人批」。
- **稳定体验**：护栏拒答比模型胡编政策更可预期。
- **分层成本**：廉价规则挡 90%，贵模型只审可疑。

---

## 三、应用场景

| 风险 | 护栏 |
|---|---|
| Prompt 注入 / 越狱 | 输入分类 + 工具结果隔离 + 系统提示优先级 |
| 数据泄漏 | 输出 DLP、禁止把检索原文外发 |
| 越权工具 | 身份绑定的 allowlist |
| 幻觉承诺 | 政策问答必须引用知识库，否则拒答 |
| 电脑操控 | 域名 / 窗口白名单，见 [Computer Use](../computer-use/) |
| 实时语音 | 流式中途截断，见 [Voice](../voice-realtime/) |

## 四、策略怎么写才可执行

坏：`不要做坏事`  
好：`refund 工具仅当 role=agent 且 amount<=500；>500 进入审批队列；禁止对 status=activated_code 的订单调用`

策略代码化，放进版本库，变更走 PR。模型只负责「申请」，护栏负责「批不批」。

## 六、落地建议

1. 先列 **危险动作清单**（写库、付款、对外发送、执行代码），逐个挂门禁。
2. 测两件事：漏拦（安全）和误拦（体验），只盯一个会漂。
3. 工具结果当脏数据，不要直接拼进高权限系统提示同一层级。
4. 人审队列要有超时与升级，否则护栏变成静默丢单。
5. 日志脱敏：审计要全，展示要红。
