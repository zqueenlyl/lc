## 1. 训练三阶段总览

| 阶段 | 学什么 | 数据/成本 | 产出 | 怎么学 |
|---|---|---|---|---|
| **预训练** | 世界知识 + 语言 | 万亿 token 网页/书/代码，千卡级 | 基座（只会续写） | [环节 08](./环节08-输出头与训练目标详解.md) 的 next-token CE，跑数十万步 |

## 2. 预训练（Pretraining）

### 2.1 目标与数据

- 目标：next-token prediction，本质是把世界知识"压缩"进参数。
- **数据工程是预训练的第一生产力**：
  - **清洗**：去重（低质量重复数据伤质量）、去毒/去隐私、质量过滤（启发式 + 模型打分）；
  - **配比**：网页 / 书籍 / 代码 / 多语的比例决定能力结构——**代码占比高，推理能力明显变强**（DeepSeek/Qwen 路线的公开经验）；
  - **Tokenizer**：中文要分词调优，词表大小影响压缩率与训练效率（[环节 01](./环节01-Tokenizer分词详解.md)）。
- 核心经验：**数据质量 > 数据量**；几 TB 垃圾不如几百 GB 精挑。

### 2.2 Scaling Law（缩放定律）

- 经验规律：模型 loss ≈ f(**参数规模、数据量、算力**)，三者呈幂律（power law）关系——都涨，loss 稳定下降。
- **Chinchilla 最优**（计算最优配比）：**约 20 tokens / 参数**。参数与数据要同步放大，只加参数不加数据 = 浪费算力。
- **涌现能力（emergent abilities）**：规模跨过某阈值后出现"小模型没有的能力"（如少样本推理）——学界对"平滑增长还是真涌现"仍有争议，面试提一嘴说明你读过。
- 工程含义：**算力是硬约束，配比是杠杆**——同样的钱，数据配比调得好，能力差一个档次。

### 2.3 成本与工程

- 千卡级集群、月级训练周期；必须**检查点（checkpoint）+ 断点续训（resume training）**（掉卡是常态）。
- 分布式策略见 §5（数据并行 + 张量并行 + 流水线并行组合）。
- **对 99% 的团队**：不要自己预训练。用开源基座（Qwen / Llama / DeepSeek），把预算花在数据、微调和 Agent 工程上。

## 3. SFT 之上再对齐（价值观/拒绝/推理风格这类"行为"用 RL 系而不是纯 SFT）

| 方法 | 怎么干 | 优点 | 缺点 | 代表 |
|---|---|---|---|---|
| **RLHF（Reinforcement Learning from Human Feedback，人类反馈强化学习）** | 训奖励模型（reward model），PPO 策略优化 | 质量上限高、可控 | 工程重：4 个模型、不稳 | InstructGPT、Claude |
| **DPO（Direct Preference Optimization，直接偏好优化）** | 直接用偏好对做"隐式奖励"监督，免去奖励模型 | 简单稳定、显存友好 | 上限略低于精心调的 RLHF | Llama-3、多数开源 |
| **GRPO（Group Relative Policy Optimization，组相对策略优化）** | PPO 去掉价值网络（value network），靠组内采样相对分做优势（advantage） | 省显存、适合可规则判分的任务 | 依赖规则/可判分场景才香 | DeepSeek-R1 推理风格 |

> 本节只给"选哪个"的结论。**为什么这么选**（RL 基础、PPO→DPO→GRPO→RLVR 的逐代删依赖、DAPO 补丁、PRM vs ORM、奖励黑客与稳定性旋钮、R1 四阶段案例）→ 横切主题 [强化学习与模型对齐详解](./强化学习与模型对齐详解.md)。

## 4. 微调（Fine-tuning）

### 4.1 核心决策：什么时候该微调？（先回答这个）

| 需求类型 | 首选手段 | 说明 |
|---|---|---|
| 事实知识（会更新/长尾） | **RAG（Retrieval-Augmented Generation，检索增强生成）** | 知识放库里检索；微调"记不住"且更新要重训 |
| 特定**输出格式**（JSON/固定结构/风格） | **微调** 或 Prompt + 结构化输出 | 格式要求硬且频繁 → 微调；低频 → Prompt |
| **风格/语气/领域术语**（客服口吻、法律文书） | **微调** | 行为层的改变微调最有效 |
| 私有**长尾知识**（几百上千条内部规范） | RAG 为主 | 微调强行灌知识 = 遗忘 + 幻觉（hallucination） |
| 推理链格式（思维链/工具调用习惯） | 微调 | 让模型"按你的套路思考" |

**一句话**：**知识 → RAG，行为/格式/风格 → 微调，临时指令 → Prompt**。三者组合：RAG 管"知道什么"，微调管"怎么干"。（RAG 详解见 [环节06-检索增强RAG详解.md](../../agent/环节06-检索增强RAG详解.md)。）

### 4.2 全参微调（full fine-tuning，FFT）vs PEFT（parameter-efficient fine-tuning，参数高效微调）

| 维度 | 全参微调（FFT） | LoRA | QLoRA |
|---|---|---|---|
| 更新范围 | 全部参数 | 注入的低秩矩阵 ΔW = B×A（r 通常 8~64） | 同 LoRA + 基座 4bit 量化（NF4） |
| 显存 | 高（≈ 训练版模型大小 × 优化器状态） | 低（只训增量，基座可冻结） | **最低**（单卡可训 7B~70B） |
| 效果 | 上限最高 | 接近全参（任务适配足够） | 接近 LoRA（量化损失可控） |
| 工程友好度 | 低（权重整个替换） | 高（**可插拔/可合并/可热切换**） | 高 |
| 适用 | 能力重构、最后冲刺 | **生产默认** | 个人/小团队训大模型 |

- **LoRA（Low-Rank Adaptation，低秩适配）原理**：权重增量 ΔW 低秩分解为两个小矩阵，训练时冻结原权重只训 ΔW，推理时可合并回 W 或按需插拔（一个基座挂多个 LoRA 按标签路由）。
- **QLoRA 关键**：4bit 量化基座 + 分页优化器 + 双重量化，把"优化器状态"这个显存大头也省掉。
- 其余 PEFT 手段：P-Tuning（软提示，soft prompt）、Adapter（层间小模块）——了解即可，LoRA 系是主流。

> 概览就绪后，下文 §4.3~§4.4 是 LoRA/QLoRA/PEFT 的**深水区**：显存账怎么算、低秩数学、7B 手算、工程与部署。应用层看 §4.3.5~4.4.3 即可。

### 4.3 LoRA 深水：凭什么"降维"就能微调

#### 4.3.1 先算清全参的显存账，才知道 LoRA 省在哪

FFT 要更新全部 7B 参数，混合精度下每参数 ≈ 14~16 字节（BF16 权重 2B + fp32 主权重副本 4B + AdamW 一阶矩 4B + 二阶矩 4B）——**7B 光"权重 + 优化器状态"就 ≈ 100GB+**，还没算梯度与激活，所以 FFT 是集群起步。同一模型切到 LoRA：

| 开销项 | FFT（7B） | LoRA（7B，r=16，q/k/v/o 全注入） |
|---|---|---|
| 可训练参数 | 7B | ≈ 1700 万（§4.3.3 手算） |
| 优化器状态 + 梯度 | ≈ 100GB+（按全参 14~16B/个算） | 几十 MB（只按可训练参数算） |
| 冻结基座 | 无 | 约 14GB（BF16 存放，只参与前向/反传，**不存梯度、不更新**） |
| 激活（activation） | 大 | **一样大——LoRA 不省激活**，靠激活重计算（activation checkpointing）/小 batch 压 |
| 落地门槛 | 8×80G 起步 | 单卡 24~48GB 可训 7B |

> 记忆点（面试高频误区）：**LoRA 省的是"可训练参数的梯度 + 优化器状态"**，不是显存全部。训练显存三大头——激活、参数/梯度/优化器态、临时 buffer——LoRA 只动第二块里属于增量的小部分，激活与前向算力照付。

#### 4.3.2 低秩数学：ΔW = B·A

冻结 W₀（d×k），增量 ΔW 强制写成两个小矩阵乘积：

```
h = W₀·x + ΔW·x = W₀·x + (B·A)·x
    ΔW ∈ R^{d×k}，B ∈ R^{d×r}，A ∈ R^{r×k}，r ≪ min(d,k)（如 r=16 vs 4096）
```

- **计算顺序**：先 `A·x`（压到 r 维）再 `B·(A·x)`，整张 ΔW（4096×4096）**从不物化**；
- **反传**：链式法则只产生 ∂L/∂A、∂L/∂B 两个小梯度，W₀ 全程冻结；
- **推理**：`W' = W₀ + (α/r)·BA` 一次性合并回普通矩阵，之后零额外开销。

**为什么低秩就够**：实证表明预训练权重高度过参数化，对下游任务的适配只需要**低秩扰动**（intrinsic dimensionality，Aghajanyan 2020；LoRA 原文 GPT-3 175B 上 r=4 即追平多数 FFT 任务）。LoRA 等价于把"允许模型改变的空间"显式限制在 r 维子空间——LLM 的适配本就是"轻量手术"，不需要动全身。

#### 4.3.3 数值走查：7B 到底训了多少参数

设 LLaMA-2-7B 形状：hidden 4096、32 层，target_modules 覆盖每个 attention 的 q/k/v/o（4 个 4096×4096 投影），r=16：

```
每个投影：B(4096×16) + A(16×4096) = 4096×16×2 = 131,072 参数
每层 4 投影：131,072 × 4 ≈ 52.4 万
32 层合计：≈ 1,678 万 ≈ 7B 的 0.24%
```

结论：只训**全参的约千分之 2.4**，就能完成绝大多数任务适配（LoRA 原文 r=8 时 7B 约 840 万、占比 ~0.12%）。

#### 4.3.4 三个设计细节（面试爱问）

1. **B 零初始化、A 随机**：ΔW 初始 = B·A = 0 → 训练起点就是原模型（不训=原样），避免开局就把预训练行为带偏，也让"开关 LoRA"无痕；
2. **α/r 缩放**：实现里 `scale = lora_alpha / r`。α 固定时缩放只随 r 变，论文观点是**不同秩之间超参可迁移**（把 α 当常数、lr 随 r 缩放）——配置里 alpha 与 r 别填反；
3. **LoRA 同样会过拟合**：参数量小 ≠ 不会崩。脏数据 + 大 epoch 照样把通用能力带偏，`dropout 0.05~0.1` 是标配。

#### 4.3.5 注入哪里 & 超参速查

- **注入位置**：attention 的 q/k/v/o 全上最稳（社区共识：即使只动 attention 已接近全参）；要更强表达再扩 FFN 的 gate/up/down（[环节 05](./环节05-FFN激活与MoE详解.md)）。
- **开局超参**：r=16~32（复杂任务可 64）、alpha=16~32、lr=1e-4~3e-4（**比 FFT 高一个数量级**——可训练参数少、低秩自带正则，可放心大 lr 快收敛）、epoch 1~3、cosine/linear 调度、LoRA dropout 0.05；
- **数据规模对应秩**：简单格式任务 r=8 足够；任务难、数据多再上调。

#### 4.3.6 上线形态：合并 or 热插拔

- **合并部署**：`W' = W₀ + scale·BA` 写回权重 → 与普通模型完全一致，推理零额外延迟（多数生产选这个）；
- **多 LoRA 热插拔（multi-LoRA）**：基座常驻，每个任务/客户只存几 MB~几十 MB 的 delta，按请求 tag 动态加载（vLLM/SGLang 支持多 LoRA，S-LoRA/Punica 思路）——"一个基座服务 N 个私有格式/风格"的标配；
- **红线**：同一请求别叠加多根 LoRA——不同任务 delta 落在同一基座上会**交叉污染**；隔离靠路由。（部署侧见 [环节 11 服务化](./环节11-服务化与推理引擎详解.md)。）

### 4.4 QLoRA 与 PEFT 全景

#### 4.4.1 QLoRA：把基座压到 4bit 再训

QLoRA 的核心是**省"冻结基座"的存储**，让单卡消费级显存能训 7B~13B（论文 48GB 单卡训 65B）：
- **NF4 量化**（4bit NormalFloat）：按正态分布分位点做信息最优的 4bit 映射，比均匀 4bit 更贴权重分布；
- **双重量化（double quantization）**：把"量化步长"本身再量化一次，额外省 ~0.37 bits/参数；
- **分页优化器（paged optimizers）**：优化器状态超出显存时换页到 CPU（类虚拟内存），防 OOM；
- **存储 4bit、计算 bf16**：前向/反传前反量化回高精度，只压缩"存储"不压缩"计算" → 精度损失可控。

#### 4.4.2 PEFT 家族全景对比

| 方案 | 改什么 | 可训练量 | 推理额外开销 | 一句话定位 |
|---|---|---|---|---|
| **LoRA** | W 的 r 维增量 B·A | 0.01~1% | 可合并 → 0 | 生产默认（§4.3） |
| **QLoRA** | 同 LoRA + 4bit 量化基座 | 同 LoRA | 同 LoRA | 个人/单卡训大模型 |
| **Adapter** | 层间插入小 MLP（串/并联 + 残差） | 0.1~3% | 串联结构有延迟 | 老派方案，LoRA 之前的主流 |
| **P-Tuning / Soft Prompt（软提示）** | 输入序列前加可学习 token | 极小 | 序列变长、KV 变大 | 不动权重，靠模型原能力，上限低 |
| **Prefix-Tuning** | 每层注意力前加前缀 KV | 小 | 同左 | 介于 soft prompt 与 Adapter |
| **DoRA** | ΔW 拆"方向 + 幅值"分别适配 | 同 LoRA | 同 LoRA | 风格分离更细，开源 SFT 常见 |
| **rsLoRA / AdaLoRA** | 缩放改 1/√r / 自动分配秩 | 同 LoRA | 同 LoRA | 研究向：更稳 / 更省 |

#### 4.4.3 什么时候 LoRA 不够（选型红线）

- **知识/新语言**：LoRA 只调"已有能力的使用方式"，模型**不知道的事实、词表外的语言它救不了** → RAG（知识类一律 RAG，见 §4.1）或继续预训练（continue-pretraining）；
- **浅层行为（格式/语气/工具调用）**：LoRA 甜点区，几千条高质量样本见效；
- **表达力/容量需求高**（深度技能重构、长链推理）：考虑大 r + 久训，或 FFT；
- **决策链速记**：知识 → RAG；任务/领域能力 → LoRA；语言级/大规模能力重构 → FFT / 继续预训练。

### 4.5 微调工程细节（通用流程；LoRA 专项参数见 §4.3.5~4.4）

- **数据**：指令格式（instruction / input / output）；**几百到几万条高质量样本足以改变行为**；质量 > 数量；做清洗、去重、配比。
- **超参**：
  - `epoch`：**1~3 轮**——轮次过多 = 灾难性遗忘（catastrophic forgetting）（把预训练学到的通用能力冲掉）；
  - `lr`：全参 ~1e-5，LoRA ~1e-4~2e-4；`warmup` 少量步数；`梯度累积（gradient accumulation）` 等效扩大 batch（批大小）；
  - 长上下文：截断/分组打包。
- **灾难性遗忘缓解**：微调数据里**混合一定比例通用数据**（10~20%），保住通用能力。
- **评估必做**：微调前后同一套 Eval 集回归——**任务分涨了、通用分跌了 = 微调失败**。

### 4.6 实操速查：微调工具链与上手路线（原理 → 代码的桥）

> 定位：§4.2~4.5 是原理与流程；本节把原理接到"今天真实世界按哪条命令跑"。**流程不变**（数据 → 超参 → Eval 回归，照 §4.5），变的只是封装工具。

**Unsloth 是什么**：微调领域的**加速库**（不是框架）——对 LoRA/QLoRA 训练做内核级优化，宣称同效果下 **~2x 速度、~70% 显存**：

| Unsloth 招牌 | 原理（对应库内哪节） |
|---|---|
| 训练 ~2x | Triton 手写 LoRA/QLoRA kernel，把反量化 + 投影**融合进一个算子**（少算子启动、省中间激活落盘）→ 与 [环节 04](./环节04-Attention注意力详解.md) §3 FlashAttention"融合 IO"同思路 |
| Q4 下 7B 只需 ~5 GB 显存 | 自研 4-bit 反量化内核，比 bitsandbytes 通用 kernel 更省 → §4.4.1 |
| Fast LoRA | 不冻结主权重：**训练中段把 LoRA 增量写回主权重** → 消除对冻结基座的等待，保住真实 LoRA 结构 → §4.3 |
| GRPO 支持 | 不止 SFT，还能跑 RL 系对齐 → §3 的"行为用 RL 而不是纯 SFT" |

配套形态：免费 **Colab 笔记本**（GPU 开箱即用）、GPU 商用版（Docker/API）、Desktop 版。注意：Unsloth 优化重心在 **NVIDIA/CUDA**，Mac 上主内核跑不了（呼应 [环节 11](./环节11-服务化与推理引擎详解.md) §2.1"引擎不分平台、分后端"）。

## 5. 分布式训练（预训练绕不开，面试常考）

| 方案 | 切什么 | 通信 | 适用 |
|---|---|---|---|
| **数据并行（data parallelism，DP/FSDP）** | 数据分片，每卡一份完整模型 + 梯度 all-reduce | 每步全量梯度 | 默认起点 |
| **张量并行（tensor parallelism，TP）** | 单层参数切到多卡（Megatron-LM） | 每层都通信 | 单机多卡大模型 |
| **流水线并行（pipeline parallelism，PP）** | 按层分组，卡间接力 | 层边界一次 | 多机超大模型（有气泡） |
| **ZeRO-1/2/3**（Zero Redundancy Optimizer；DeepSpeed） | 优化器状态 → +梯度 → +参数分片 | 逐步增多 | 显存不够时的救星 |
| **专家并行（expert parallelism，EP）** | MoE 专家分布多卡 | 路由通信 | MoE 模型（DeepSeek，[环节 05](./环节05-FFN激活与MoE详解.md)） |

**显存优化三板斧**：

1. **重计算（activation checkpointing）**：反向时重算激活而非全存 → 省显存换算力；
2. **混合精度（BF16/FP16）**：训练标配，BF16 数值稳定性更好；
3. **ZeRO / 量化**：优化器状态分片、4bit 基座。

> 面试速记：**TP 切模型、PP 切层、DP 切数据、ZeRO 切状态**。

## 6. 坑清单

1. **数据配比乱来**：代码/多语比例不当 → 能力结构偏移。
2. **用微调灌知识**：知识是"会变 + 长尾"的，微调固死且记不住 → 知识必须走 RAG。
3. **epoch 过多**：灾难性遗忘，通用能力崩，任务分虚高。
4. **微调后不回归通用 Eval**：只报任务分 = 自欺欺人（回归集怎么配，见横切主题 [模型评测与选型方法详解](./模型评测与选型方法详解.md)）。
5. **脏数据/幻觉数据进训练集**：模型把错误当真理学进去（数据是训练的唯一真相源）。
6. **显存不匹配硬跑**：忘了 ZeRO/QLoRA/重计算，直接 OOM。
7. **把"微调"当万能**：能 Prompt/结构化输出解决的，别微调（成本 + 维护负担）。
8. **混淆对齐手段**：纯 SFT 解决不了价值观/偏好这类"行为"问题，要用 RL 系（RLHF/DPO/GRPO）。

## 7. 面试高频追问

1. 预训练和微调的本质区别？→ 学世界知识 vs 学行为方式；数据规模差几个数量级。
2. Scaling Law 是什么？Chinchilla 最优？→ loss 随参数/数据/算力幂律下降；约 20 tokens/参数。
3. 什么时候该微调、什么时候用 RAG？→ 知识 → RAG，行为/格式/风格 → 微调，临时 → Prompt。
4. LoRA 为什么省显存？原理？→ 只训低秩增量 B·A（基座冻结、不存梯度与优化器状态），省的是可训练参数的梯度+优化器态；**注意激活照样算、照样占**，靠重计算/小 batch 压（§4.3.1）。推理可合并（零延迟）可热插拔。
5. QLoRA 怎么做到单卡训大模型？→ 4bit 量化基座 + 分页优化器 + 双重量化。
6. 灾难性遗忘怎么缓解？→ 控制 epoch、混合通用数据、评估回归。
7. 分布式训练几种并行？→ TP 切模型 / PP 切层 / DP 切数据 / ZeRO 切优化器状态。
8. 微调数据要多少？→ 几百到几万条高质量即可改变行为，质量 > 数量。
9. RLHF / DPO / GRPO 怎么选？→ 追求上限且能承担工程重 → RLHF；常规开源 → DPO；可规则判分/推理风格 → GRPO。
10. ΔW=B·A 为什么"低秩就够"？→ 预训练权重过参数化，下游适配只需低秩扰动（intrinsic dimension 论据）；LoRA 把可改空间显式限制在 r 维子空间，GPT-3 上 r=4 即追平多数 FFT 任务。
11. LoRA 具体训了多少参数？→ 每模块 2·d·r × 注入模块数。7B（hidden 4096、32 层）q/k/v/o 全注入、r=16 ≈ 1700 万 ≈ 全参 0.24%（§4.3.3 手算）。
12. 为什么 B 零初始化、A 随机？α/r 干嘛的？→ B=0 使 ΔW 起点为 0 → 训练起点 = 原模型；`scale=α/r`，α 当常数、r 可变 → 不同秩下超参可迁移。
13. LoRA 能注入新知识吗？→ 不能。它只调"已有能力的使用方式"；知识/新语言 → RAG / 继续预训练（§4.4.3）。
14. LoRA 训练完怎么上线？→ 合并 `W'=W₀+scale·BA`（零额外延迟，多数生产）；或 multi-LoRA 热插拔：基座常驻 + 每任务几 MB delta + 请求路由（vLLM/SGLang 支持）。
15. 多个 LoRA 能同时叠加吗？→ 会交叉污染（不同任务 delta 同基座相互干扰）；生产按请求路由单根。
16. QLoRA 为何能单卡训大模型？→ NF4 4bit 量化基座 + 双重量化 + 分页优化器；存储 4bit、计算反量化回 bf16 → 精度损失可控。
17. 何时 FFT / 继续预训练而不用 LoRA？→ 表达力/容量需求高、语言级能力重构时；知识类一律先 RAG。
18. 微调/上线前的评测怎么配？→ 微调 = 任务专属集 + 通用回归集（通用分掉 = 灾难性遗忘）；上线前 = 量化/格式回归 + 真实流量 A/B。评测方法论见 [模型评测与选型方法详解](./模型评测与选型方法详解.md)。
