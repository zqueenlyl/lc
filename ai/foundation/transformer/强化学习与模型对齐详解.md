## 0. 一句话定位

**SFT 教模型"像人一样说话"，RL 教模型"把事做对"。**

- SFT（监督微调）是**模仿**：交叉熵最大化"数据里那条回答"的似然 → **能力上限 = 训练数据的质量上界**；
- RL（强化学习）是**探索**：只给"好/坏"信号，让模型自己去找比数据里更优的解法 → **能力上限 = 奖励函数/验证器的质量上界**。

> 对齐（alignment）= 让模型的**行为**符合意图（有用、无害、诚实、按格式、会推理）。这一层**没法靠 SFT 完成**——原因见 §1。

```
SFT 的世界观：数据里怎么写，你就怎么学（有标准答案）
RL  的世界观：我只告诉你多少分，你自己想办法拿高分（无标准答案）
```

> 关键认知转变：对齐技术的演进史，本质是**"谁来定义好"不断换人的历史**——从「人类示范」→「人类偏好模型」→「机器验证器」。每换一次，成本和可扩展性都降一个量级。

## 1. 为什么 SFT 之后还要 RL（三个根本限制）

| 限制 | 机制 | 后果 |
|---|---|---|
| **只能模仿，不能超越** | 交叉熵只会把概率推向"数据里出现过的那条回答" | 数据里没写的更优解法学不到；"反思、换解法、验算"这类**策略性行为**无从模仿 |
| **只能优化可微目标** | 反向传播需要梯度 | "人类是否更喜欢""答案是否正确""代码是否通过测试"**全都不可微** → 没法直接写进损失函数 |
| **目标错配（token 级 ≠ 序列级）** | 逐 token 算似然，且训练用 teacher forcing（喂真值） | 每步概率高 ≠ 整段回答好；训练时看真值、推理时看自己 → **暴露偏差（exposure bias）**，一步错步步错 |

**最核心的一条**：next-token 预测与"这个回答好不好"之间**没有必然联系**。一个模型可以给错误答案分配极高概率（因为训练数据里就是这么写的）。

> 经典佐证（InstructGPT, arXiv 2203.02155）：**1.3B 的 PPO 模型，人类偏好度高于 175B 的纯 GPT-3**。说明"对齐"带来的收益，一个数量级以上于"堆参数"。

RL 的价值 = 把优化目标从"**像不像数据**"换成"**奖励高不高**"，于是：

- 能优化**不可微目标**（偏好、正确性、格式合规）；
- 能优化**整段回答**而非单 token；
- 能**探索**出训练数据里不存在的行为（R1-Zero 的长 CoT 就是这么长出来的）。

## 2. RL 基础速通（LLM 语境下的最小映射）

> 本节只保留"理解对齐算法必须懂"的部分。传统 RL（DQN / AlphaGo / Q-learning）不是必需背景。

### 2.1 要素映射：把 LLM 塞进 RL 框架

| RL 概念 | 符号 | 在 LLM 里是什么 |
|---|---|---|
| 策略 π(a\|s) | π_θ | 当前**待训模型**本身：π_θ(y\|x)，给定 prompt 生成回答 |
| 状态 s | — | prompt + **已生成的 token**（状态随生成而变） |
| 动作 a | — | **下一个 token**（动作空间 = 词表） |
| 轨迹 τ | — | 一次完整回答 y = (y₁…y_T) |
| 奖励 R | r | **奖励模型打分 / 验证器结果 / 人类偏好**（整段只给一个分数） |
| 价值 V(s) | V_φ | 从当前状态起、后续能拿多少分（**critic 网络**学它） |
| 优势 A(s,a) | A | 这个动作比"平均水平"好多少 → **决定该鼓励还是压制** |
| 折扣 γ | — | LLM 里通常取 1（不折扣，看整段） |

> 注意最后一行的坑：**整段回答只拿一个标量奖励，但要归因到每个 token**——这就是信用分配问题，是所有对齐算法差异的根源。

### 2.2 三条必须懂的机制

**① 信用分配（credit assignment）——最大的难点**

"这道题答对了"是整体结果，到底是哪一步功劳？哪一步错了？RL 算法全部设计都在解决它：

- PPO：训练一个 **critic 网络** 逐状态估计价值 → 用 `A = R - V(s)` 判断每步"超预期"程度；
- GRPO：**用同题其他回答的成绩当基线**（组内相对），免掉 critic；
- PRM（过程奖励）：**直接给每一步打分**，用标注成本换信用分配精度。

**② 基线（baseline）与方差削减**

最原始的策略梯度（REINFORCE, 1992）就是"奖励高的轨迹 → 提高其概率"：

```
∇J ≈ E[ R(τ) · ∇log π_θ(τ) ]
```

问题：**方差极大**（不同 prompt 难度天差地别，绝对分数噪声大）→ 学习极慢。

解法：减去一个**基线 b**（通常取价值函数 V(s)）→ 得到**优势 A = R - b**。语义从"这条轨迹拿了多少分"变成"比预期好多少"——只关心**相对好坏**，方差骤降。

> 这是 GRPO 的理论根基：**如果基线只要"比平均好多少"，那"平均"完全可以用同一 prompt 下其他采样回答的成绩来估计**——不必学一个网络。见 §3.3。

**③ KL 约束——对齐的"缰绳"**

```
目标 = E[r(x, y)] − β · KL( π_θ(·|x) ‖ π_ref(·|x) )
```

- **不加 KL 会怎样**：策略会坍缩到"奖励最高但不会说人话"的退化分布（重复、乱码、纯格式堆砌）——因为追求分数可以直接牺牲语言；
- `π_ref`：**冻结的参考模型**（通常就是 SFT 模型），代表"别偏离太远"；
- `β`：最重要的旋钮，控制"允许偏离多远"。RLHF 通常 0.01~0.1，DPO 0.1~0.5，GRPO（DeepSeek 风格）0.001~0.04。

> 类比：`r` 是 KPI，`KL` 是"不能为了 KPI 把业务做垮"。**β 太小 → 奖励黑客**，**β 太大 → 学不动**。

### 2.3 在线（on-policy）vs 离线（off-policy）——选型的第一分水岭

| | 在线 RL（PPO / GRPO / DAPO） | 离线偏好优化（DPO / SimPO / KTO / ORPO） |
|---|---|---|
| 数据 | **训练中自己采样**新回答，持续探索 | **静态偏好数据集**，跑完就完 |
| 能超越数据吗 | ✅ 能超出训练数据分布 | ❌ 被偏好对的质量上界框住 |
| 稳定性 | 差（多个旋钮，易悄悄劣化） | 好（本质是监督学习，"看曲线往下走"） |
| 成本 | 高（rollout 生成 + 多模型驻留） | 低（算力常为 PPO 的 1/2~1/4） |
| 角色 | 冲**能力上限**（数学/代码/推理） | 调**风格与价值观**（语气/格式/拒答） |

> 记忆点：**要"探索出新能力" → 在线 RL；要"改行为、控风格" → 离线偏好优化**。这一条基本能覆盖 90% 的选型问题。

## 3. 对齐方法谱系（主轴：逐代"删除依赖"）

### 3.0 演进直觉表

对齐史的骨架，就是一个不断**把昂贵部件删掉**的过程：

| 代际 | 方法 | 删掉了什么 | 关键节点 |
|---|---|---|---|
| — | TRPO → **PPO** | 二阶信赖域 → 一阶裁剪 | 2017，Schulman |
| 1 | **PPO + RLHF** | （基线：4 个模型同时在显存里） | 2022 InstructGPT → ChatGPT |
| 2 | **DPO** | **删掉奖励模型** | 2023, arXiv 2305.18290 |
| 3 | **GRPO** | **删掉 critic 网络** | 2024, arXiv 2402.03300，2025 被 R1 推上台前 |
| 4 | **RLVR** | **删掉"人类偏好"和步骤标注** | 2024–2026，R1 证明可行 |
| 5 | **Agentic RL** | 删掉"静态数据集"（改用环境） | 2025–2026，verl / Agent-Lightning |

```
PPO+RLHF:  Actor + Critic + RewardModel + Reference     （4 模型）
GRPO:      Actor + RewardModel/Verifier + Reference     （3 模型，无 critic）
DPO:       Actor + Reference                            （2 模型，无 RM）
SimPO:     Actor                                        （1 模型）
```

### 3.1 RLHF：SFT → 奖励模型 → PPO（一切的起点）

**三步流程**：

1. **SFT**：少量人类示范数据微调基座 → 会听话的初始策略；
2. **奖励模型（RM, reward model）**：给标注者看同一 prompt 的两个回答，问"哪个更好" → 训练 `r(x, y)` 预测人类偏好；
3. **PPO**：把 RM 当环境，策略采样回答 → RM 打分 → PPO 更新策略，同时用 KL 拴住参考模型。

**奖励模型的损失**（Bradley-Terry 偏好模型）：

```
L_RM = − E[ log σ( r(x, y_w) − r(x, y_l) ) ]      # y_w 人类偏好答案，y_l 被拒答案
```

**PPO 的裁剪目标**：

```
L_PPO = E[ min( ρ·A , clip(ρ, 1−ε, 1+ε)·A ) ] − β·KL(π_θ ‖ π_ref)
其中 ρ = π_θ(y|x) / π_old(y|x)      # 重要性采样比
```

- **clip 的作用**：新旧策略不能差太远（信任域），一步更新别把策略带崩；`ε` 通常 0.1~0.2；
- **A（优势）**：`A = R − V(s)`，`V` 由 **critic 网络**（第 4 个模型）估计，通常用 GAE 计算。

**为什么 RLHF 有效**：**问"哪个更好"远比"写出最好的答案"便宜**。写答案要专家、要时间、要想象力；做二选一只需判断力。这是 RLHF 相对 SFT 的数据经济学基础。

**代价**：4 个模型同时驻留显存（70B 策略 ≈ 要养出 280B 参数量的开销）；训练不稳定；RM 会随策略漂移而失效（loss 曲线看不出）。

### 3.2 DPO：用一个数学技巧删掉奖励模型

**核心洞见**：在 RLHF 的假设下（Bradley-Terry 偏好 + 带 KL 的正则目标），**最优策略 π\* 与奖励函数 r 之间存在闭式关系**：

```
r(x, y) = β · log( π*(y|x) / π_ref(y|x) ) + β · log Z(x)
```

既然奖励可以**由策略反解出来**，那就不必"先训 RM 再跑 PPO"——把 RM 代入 Bradley-Terry 损失，`Z(x)` 在配对相减时自动消掉，直接得到一个定义在偏好对上的**监督损失**：

```
L_DPO = − E[ log σ( β·log(π_θ(y_w|x)/π_ref(y_w|x))
                  − β·log(π_θ(y_l|x)/π_ref(y_l|x)) ) ]
```

**读法**：本质是**标准交叉熵作用在一个 logit 上**，而这个 logit 是"被选中回答的**对数概率比**"减"被拒回答的**对数概率比**"。

**最低配置只要三样东西**：

1. `π_ref`：SFT 模型的**冻结拷贝**（全程不动）；
2. `π_θ`：从同一 SFT 模型初始化的可训练策略；
3. 数据集：`(prompt, chosen, rejected)` 三元组。

**没有奖励模型、没有 rollout、没有 critic、没有 PPO 循环**——训练循环看起来和普通微调几乎一样。

| 优点 | 缺点 |
|---|---|
| 稳（本质是监督学习）、显存省、算力为 PPO 的 1/2~1/4 | **不探索**，被偏好数据质量上界框死 |
| 超参极少（基本只有 β 和 lr） | 上限通常略低于精心调过的在线 RL |
| 复现性好，中小团队可做 | 对**推理能力**提升有限（不能生成数据外的新解法） |

**实践要点**：

- `β` 太小学不动、太大策略漂走，**多数人落在 0.1~0.5**；
- **应该做迭代式 DPO**：用最新策略重新采样偏好对再训一轮，效果远好于一次性跑完；
- 甜点区是**风格塑造**：拒答行为、语气、格式遵循、闲聊有用性。

> 实证补充（ICML 2024, *Is DPO Superior to PPO for LLM Alignment?*）：**数据质量一致时，PPO 在数学任务上仍比 DPO 高约 2.5%、通用 benchmark 高约 1.2%**。结论：**PPO 没死，只是不再是简单场景的默认选项**。

### 3.3 GRPO：再删掉 critic（推理模型的主力算法）

**核心思想**：不需要学出来的价值网络（critic），**直接用"同一道题的一组回答"互为基线**。

**四步流程**：

1. 对单个 prompt `x`，从当前策略采样 **G 个**回答 `y₁…y_G`（典型 **G = 8~64**，公开实践多用 16~32）；
2. 用奖励函数给每个打分 `r_i = R(x, y_i)`——**通常来自验证器（规则/单测），而不是学出来的 RM**；
3. 计算**组内归一化优势**：

```
A_i = ( r_i − mean(r₁…r_G) ) / std(r₁…r_G)
```

4. 代入 PPO 风格的 clipped 目标 + 对参考策略的 KL 惩罚。

**为什么可以不要 critic**：PPO 需要 critic 是为了估计 `V(s)`（"平均水平"）。但组内其他兄弟回答的成绩，本身就是对"平均水平"的一个**免费且无偏的估计**——尤其当奖励是 0/1 时，组内天然形成"成功 vs 失败"的干净对比。

| 优点 | 固定坑（第一次跑必踩） |
|---|---|
| 省掉 critic → **显存约为 PPO 的一半**（7B：8×H100 可跑 vs PPO 要 16×H100） | **全对/全错组**：std=0 → 优势爆炸或直接消失 → 分母加 ε / 过滤退化 prompt |
| 组内归一化消解了 reward scale 问题（换任务不用重调奖励尺度） | **G 太小方差大、太大 rollout 成本线性涨** → 折中 16~32 |
| 天然契合可验证奖励（对/错天然可比） | **β 太小** → 语言连贯性崩（DeepSeek 风格多在 0.001~0.04） |
| 实现简单，去掉一整套 GAE + value loss 调参 | **奖励形态决定一切**：0/1 奖励与稠密奖励训出的模型差异巨大 |

> 理论支撑（arXiv 2603.01162）：GRPO 的策略梯度可写成 **U-statistic** 形式，渐近等价于"拥有理想价值函数的 oracle 算法"——即 **GRPO 不是碰巧能用的近似，而是在一大类策略梯度方法中可证最优**。

### 3.4 DAPO / Dr.GRPO / GSPO：GRPO 的工程补丁

GRPO 在**长思维链（long CoT）**训练中会失稳，于是有一批针对性修补。**核心思想不变：仍用一组 rollout 当基线。**

**DAPO**（字节跳动 + 清华，2025，arXiv 2503.14476）——四项技术：

| 技术 | 解决什么 |
|---|---|
| **Clip-Higher** | 抬高比率的上裁剪界 → **防熵坍缩**，保住探索性（长 CoT 需要持续探索） |
| **Dynamic Sampling** | 动态过滤批次，剔除全对/全错的无效样本 → 保证每步都有梯度信号 |
| **Token-level Policy Gradient Loss** | 长 CoT **必须按 token 算损失**；序列级损失在长回答上会梯度消失 |
| **Overlong Reward Shaping** | 对超长回答做奖励整形 → 降低截断/超长带来的奖励噪声 |

> 效果：AIME 2024 上把 Qwen2.5-32B 训到 **50 分**，且**训练步数比 R1-Zero 少约 50%**。系统已开源。

**其他变体**：

| 变体 | 一句话改动 |
|---|---|
| **Dr. GRPO**（arXiv 2503.20783） | 指出 GRPO 有两处偏差——**长度偏差**（除以长度）与**标准化偏差**（除以 std）→ 去掉它们，训练更稳 |
| **GSPO**（Qwen 团队，2025） | 把**重要性比从 token 级改成序列级** → 长序列训练更稳定（Qwen3 采用） |
| **DAPO / GRPO / RLOO** | 同属"组基线"家族，工程细节不同，别在选型上纠结太久 |

### 3.5 RLVR：把奖励换成"可验证"（2025–2026 的主线）

**RLVR = Reinforcement Learning with Verifiable Rewards**。奖励不再是"人类给 7/10 分"，而是：

- **单元测试通过了**；
- **`\boxed{}` 里的答案与标准答案一致**；
- **SQL 查询返回了正确的行**。

**为什么这是结构性转变**：对数学、代码、结构化推理这类任务，**质量判断根本不需要人类**——验证器给的二元信号更快、更便宜、更一致、可无限扩展。

> DeepSeek-R1 的关键证明：**纯 RLVR 可以"涌现"出推理能力**（自我反思、动态换策略、验算），**且不需要任何人类标注的推理轨迹**（R1-Zero 路线）。

**奖励信号演进四阶段**（看清"瓶颈在哪"）：

| 时代 | 奖励来源 | 捕捉什么 | 典型失败模式 | 瓶颈 |
|---|---|---|---|---|
| 2022–2023 | 人类成对偏好 → RM | 人类更喜欢哪个 | **谄媚**、对 RM 钻空子 | 人类标注者 |
| 2023–2024 | 直接吃偏好对（DPO） | 同上，去掉 RM | 不探索，被数据集边界框住 | 偏好数据质量 |
| **2024–2026** | **验证器**（单测/数学校验器/正则） | 这个答案是否**可被证明正确** | **对验证器钻空子**、能力隧道化 | **验证器的设计** |
| 2025– | 更强模型当 judge | 在更聪明的模型看来是否对 | judge 偏见、模式坍塌 | judge 的校准 |

**失效边界（重要）**：

- **对验证器钻空子（reward hacking）**：策略在边际上**总会比信号更聪明**——这是对齐的中心问题，不是可以一次性解决的 bug；
- **能力隧道化**：只训可验证任务 → 通用对话/风格能力退化（所以生产上常保留 RLHF/DPO 做一层兜底）；
- **验证器噪声**：数学检查器有边界情况、单测覆盖不全 → 需对观测奖励**去偏**（arXiv 2505.13445），防模型吃到假阳性漏洞。

> 趋势判断：**RLHF 不会死，但会退化成一层薄薄的专门化层**（管风格、语气、品牌口吻、拒答）；能力提升的主战场交给可验证 RL。业界一句话——**"验证器是新的数据集"**。

### 3.6 偏好优化家族（DPO 的衍生）

| 方法 | 改动 | 删掉了什么 | 备注 |
|---|---|---|---|
| **DPO** | — | 奖励模型 | 需 π_ref + 成对偏好数据 |
| **SimPO** | 用**回答的平均对数概率**当隐式奖励，去掉长度归一化外的长度偏好 | **reference model** | AlpacaEval 2 比 DPO **+6.4**、Arena-Hard **+7.5** |
| **KTO** | 用 **点赞/点踩式二元反馈**替代成对比较 | reference model + 成对数据 | 生产价值大：二元信号**廉价且海量**，成对偏好采集昂贵 |
| **ORPO** | 用 **odds ratio** 把 SFT 与偏好对齐**合并成单一目标** | 独立 SFT 阶段 + reference model | 减少训练时间，消除 SFT 与偏好调优间的分布漂移 |
| **IPO / cDPO** | 加正则 / 处理偏好噪声 | — | 研究向：更抗过拟合与标注噪声 |

> 记忆点：**KTO 的商业含义 > 技术含义**——真实产品里能拿到的是点赞/点踩/重新生成，不是精心标注的 A/B 对。

### 3.7 PRM vs ORM：过程奖励还是结果奖励

**两种奖励形态**：

| | ORM（Outcome RM，结果奖励） | PRM（Process RM，过程奖励） |
|---|---|---|
| 打分粒度 | 整段回答一个标量（通常 0/1） | **每个推理步骤**单独打分 |
| 成本 | 低（单测/答案匹配即可） | 高（需**步骤级人类标注**） |
| 代表 | R1 的规则奖励 + GRPO | PRM800K（*Let's Verify Step by Step*, 2023） |

**历史反转（面试很好用）**：

1. 2023 年 OpenAI 的 PRM 在 MATH best-of-N 上**大幅领先 ORM**，约一年内大家都认为"过程监督是方向"；
2. **DeepSeek-R1 反转了它**：用**规则结果奖励 + GRPO**，没有 PRM、没有步骤标注。论文明确说试过 PRM，但**难以规模化**（标注成本、奖励黑客、"一步"定义模糊）；
3. 2025 年进一步证实（*Is PRM Necessary?*）：**把现有 PRM 用到 R1/QwQ 这类前沿模型上，表现实际不如简单的多数投票**。

**为什么 ORM + GRPO 就够了**：G 足够大、题目足够难时，组内自然同时出现成功与失败轨迹；**组相对优势本身就在做一种隐式的步骤级信用分配**——成功与失败的轨迹共享早期决策，梯度会**偏向地落在它们开始分叉的那一步**。

> 一句话：**用结果奖励的 GRPO ≈ 不付标注费的过程监督。**

**PRM 仍然胜出的四种情形**：

1. **长程 Agent 任务**，最终答案本身模糊（40 步浏览-编码-重规划的流程里，"最终答案正确"太稀疏）；
2. **工具使用的安全性**：要惩罚特定中间行为（调错 API、泄露 PII、改错文件）——结果奖励来得太迟；
3. **多智能体训练（MARL）**：组内方差这招在多智能体下静默失效（见 §6）；
4. **推理时搜索**：即使训练用结果奖励，PRM 在推理时仍能指导 beam search / MCTS / best-of-N 的选择——**今天大多数生产推理系统正是这么用 PRM 的**。

**实操建议**：**从结果奖励开始**（更便宜、更好调试，数学/代码/SQL 上几乎总是够用）；**只有有证据时才加过程奖励**——看失败 rollout，若"结构对但卡在某类中间错误"，PRM 才有价值。

> 易混点：**"PRM vs ORM" 与 "稀疏 vs 稠密奖励" 不是同一根轴**。可以有稀疏 ORM（二值对/错），也可以有稠密 ORM（按部分分分级）。让 PRM 独特的是**逐步打分**，不是信号的稠密程度。

## 5. 工程落地

### 5.1 奖励设计决定一切

| 信号类型 | 怎么来 | 优点 | 风险 |
|---|---|---|---|
| **规则/验证器** | 单测、数学校验、正则、schema 校验 | 便宜、客观、可无限扩展 | 覆盖窄、可被钻空子 |
| **奖励模型（RM）** | 人类偏好对训练 | 覆盖广、能抓"软"质量 | 谄媚、长度偏置、随策略漂移失效 |
| **LLM-as-Judge** | 强模型按 rubric 打分 | 覆盖开放任务 | judge 偏见、校准难题 |
| **人类偏好** | 标注 | 最贴近真实 | 最贵、最慢、一致性差 |

**四类典型奖励病**：

1. **奖励黑客（reward hacking）**：策略找 RM 的每一处弱点（发现"长答案分高"就无限拉长、"出现 Markdown 标题分高"就狂加标题）；
2. **长度偏置**：RM 偏爱长回答 → 输出越来越长（**对策**：长度惩罚 / 长度归一化 / 成对长度匹配）；
3. **谄媚（sycophancy）**：偏好数据由人类标 → 人类喜欢被认同 → 模型学会迎合；
4. **分布漂移**：RM 是在**旧策略**的输出上训的，策略一前移 RM 就不准了——**而这在 loss 曲线上看不出来**（对策：定期用新策略数据重训 RM，或直接用验证器替代）。

### 5.2 稳定性旋钮（出问题先查这几个）

| 旋钮 | 典型值 | 调错的症状 |
|---|---|---|
| **KL 系数 β** | RLHF 0.01~0.1；GRPO 0.001~0.04；DPO 0.1~0.5 | 太小 → 语言崩坏/奖励黑客；太大 → 学不动 |
| **clip ε** | 0.1~0.2 | 太大 → 策略突变；太小 → 学不动 |
| **组大小 G** | 16~32（8~64） | 太小 → 优势噪声大；太大 → rollout 成本线性涨 |
| **温度 / top-p**（采样） | 略高以保探索 | 太低 → 无多样性、组内全同 → 优势恒为 0 |
| **rollout batch** | 越大越稳 | 太小 → 梯度噪声大 |
| **lr** | 比 SFT 小 1~2 个数量级 | 太大 → 策略崩溃 |

**三个高频故障**：

- **熵坍缩（entropy collapse）**：策略越来越确定 → 不再探索 → 提前收敛到平庸解（DAPO 的 Clip-Higher 就是治它）；
- **全对/全错组**：std=0 → 优势爆炸或消失（加 ε / 动态采样过滤）；
- **KL 崩塌/语言退化**：输出重复、格式堆砌、中英混杂。

### 5.3 显存与工具链

**为什么 RL 比 SFT 贵得多**：

```
RL 显存 =  策略（训练版：权重+梯度+优化器状态）
        + 参考模型（冻结，仅前向）
        + 奖励模型 / 验证器（前向 + 可能还要推理服务）
        + critic（仅 PPO）
        + rollout 的 KV Cache（G 条回答同时生成，长 CoT 下极占显存）
        + 训练侧激活
```

> 关键：**rollout 阶段是"推理负载"，训练阶段是"训练负载"，两套资源峰值都要扛**。这也是 GRPO"删 critic"价值巨大的原因——直接省一份完整模型副本。

**2026 年开源栈**：

| 工具 | 定位 |
|---|---|
| **verl**（火山引擎/字节） | 大规模 RL 训练骨干，主流工业选择 |
| **OpenRLHF** | 开源 RLHF/RL 全流程框架 |
| **TRL**（HuggingFace） | 中小规模 PPO / DPO / GRPO 主力，`PPOTrainer`/`DPOTrainer`/`GRPOTrainer` |
| **Unsloth** | 单卡 LoRA + GRPO 快速验证（呼应 [环节 09](./环节09-训练管线详解.md) §4.6） |
| **Agent-Lightning / Agent-R1** | Agent 轨迹上的多轮工具 RL |

### 5.4 完整案例：DeepSeek-R1 的四阶段（arXiv 2501.12948）

这是"现代对齐流水线"的标准范式，值得逐阶段记住：

| 阶段 | 做什么 | 关键点 |
|---|---|---|
| **① 冷启动 SFT** | 用**数千条**高质量长 CoT 数据微调基座 | 解决 R1-Zero 的"可读性差、语言混杂"问题；**这一步是 R1 与 R1-Zero 的核心差别** |
| **② 面向推理的 RL** | **GRPO + 规则奖励**（答案正确性 + 格式合规） | 只奖励"结果对 + 格式对"，不监督思考过程 → 推理能力**涌现**（自我反思、换解法、验算） |
| **③ 拒绝采样 + SFT** | 用阶段②模型采样，筛出高质量轨迹（**约 60 万条推理 + 约 20 万条通用**），重训基座 | 把 RL 学到的东西**"固化"进权重**，同时注入通用能力 |
| **④ 全场景 RL** | 推理任务继续用规则奖励 + 通用任务用奖励模型 | 兼顾推理与"有用/无害"，最终产品模型 |

> 三个可直接复用的结论：
> 1. **规则奖励足够训出推理能力**（不必上 PRM/RM）；
> 2. **RL 后要"蒸馏回 SFT"**（阶段③）——把策略探索的成果固化，避免 RL 后的输出风格不稳定；
> 3. **R1-Zero 证明了"纯 RL 涌现"可行，但 R1 的工程版加了冷启动和 SFT 收口**——**能跑通 ≠ 好用**，产品化要修补可读性。

## 6. 2026 年的前沿（值得知道，面试加分）

### 6.1 三阶段后训练流水线（顺序不可颠倒）

| 阶段 | 解决什么 | 数据形态 | 代表方法 |
|---|---|---|---|
| **SFT** | 格式：指令跟随、结构化输出、对话风格 | 百万~千万级精选样本 | — |
| **偏好优化** | 价值观与偏好对齐 | 偏好对 / 二元反馈 | DPO → SimPO / KTO / ORPO |
| **强化学习** | **突破训练数据上限**、产生推理能力 | 可验证奖励 / 环境反馈 | GRPO / DAPO |

> 核心判断：**预训练只提供"基础智力"，后训练（post-training）现在贡献了模型"可用能力"的大部分**。跳过 SFT 直接 RL 不成立（模型还没有基本格式能力，RL 无从探索）。

### 6.2 Agentic RL：环境取代数据集

训练多步工具使用，需要的是 **RL 环境**（可交互、可验证、能多轮 rollout），而不是静态数据集：

| 框架 | 关键能力 |
|---|---|
| **NeMo Gym**（NVIDIA） | 交互式 RL 环境、多轮 rollout、工具调用验证、agent/环境解耦；Nemotron 3 Super 跨 21 种环境跑了 120 万次 rollout |
| **RLFactory**（arXiv 2509.06980） | 即插即用多轮工具 RL；Qwen3-4B 训后在 Natural Questions 上超过更大模型，吞吐 6.8× |
| **MOSAIC**（arXiv 2603.03205, 2026-03） | 训练 Agent **知道何时拒绝**：把推理结构化为"计划 → 检查 → 行动或拒绝"；有害行为最多降 50% |
| **LightningRL**（Agent-Lightning） | 把 Agent 系统视为 POMDP，分解成单步转移，分层算优势（解决 MARL 信用分配） |

**MARL 为什么难**（信用分配失效）：单 Agent 下"组内其他回答"能当基线；多 Agent 共享一条团队轨迹、只拿一个团队级稀疏奖励时——"到底是谁的功劳"没法用组方差糊过去。三条杠杆：**过程奖励 / 价值分解（VDN、QMIX、COMA）/ 轨迹分解**。

### 6.3 合成自博弈（Self-Play）

思路反转：**模型生成自己的训练数据，再从中学**。

- **SPIN**：让模型区分"自己的输出"与"人类写作"，逐步逼近人类分布，无需额外标注；
- **SPICE**：把自博弈**锚定在外部文档**上（Challenger 出题、Reasoner 解题）→ 避免无锚自博弈的**幻觉放大与模型坍缩**；数学 +8.9%、通用推理 +9.8%。

> 红线：**自博弈必须锚定外部信息源**，否则模型会在自己的噪声里越走越偏（model collapse）。

### 6.4 三个未来方向（业界共识）

1. **统一流水线**：把 SFT / 偏好 / RL 三阶段合并为单一目标（ORPO 已走出第一步）；
2. **环境原生训练**：从"聊天模型"到"Agent 模型"的分化会拉大——**纯文本对训练的模型在 Agentic 任务上会日益落后**；
3. **自动课程生成**：模型按自身弱点生成训练任务 + 验证器闭环 → **识别弱点 → 生成数据 → 训练 → 重复**，全程无人类介入。

## 7. 坑清单

1. **跳过 SFT 直接 RL**：模型连格式都不会，RL 的探索空间里全是垃圾 → 必须先 SFT。
2. **把 DPO 当万能**：DPO 不探索，数学/代码这类需要"想出数据外解法"的任务，它提升有限。
3. **KL 系数设错**：太小 → 奖励黑客 + 语言崩坏；太大 → 白跑。GRPO 与 DPO 的 β 量级差 1~2 个数量级，别照抄。
4. **忽略全对/全错组**：std=0 时优势会爆炸或归零，训练悄悄不动 → 加 ε / 动态采样过滤。
5. **只有结果奖励却去做长程 Agent**：最终答案太稀疏、太晚，信用分配无解 → 需过程奖励或价值分解。
6. **奖励只看最终答案、不看过程安全**：模型会学出"答案对但中间乱调 API / 泄露 PII"。
7. **RM 不复训**：策略漂移后 RM 失效，而损失曲线正常 → 定期用新策略数据重训，或直接换验证器。
8. **用 RL 调风格而不做回归**：可验证 RL 会隧道化（能力集中在可验证任务），通用能力/风格需单独验收（见 [模型评测与选型方法详解](./模型评测与选型方法详解.md)）。
9. **忽视 rollout 的显存与延迟**：RL 的成本大头在"生成"，不在"反向传播"——长 CoT 下 KV Cache 会先爆。
10. **以为 RL 能灌知识**：RL 调的是**行为与策略**，知识依然要走 RAG / 继续预训练（呼应 [环节 09](./环节09-训练管线详解.md) §4.1）。

## 8. 面试高频追问

1. **SFT 已经很强了，为什么还要 RL？** → 三个限制：只能模仿不能超越（上限=数据质量）、只能优化可微目标（偏好/对错不可微）、token 级目标 ≠ 序列级质量（暴露偏差）。RL 换成"奖励高不高"的优化目标。
2. **RLHF 为什么必须加 KL 惩罚？** → 不约束会坍缩到"高分但不会说人话"的退化分布；β 控制允许偏离参考模型多远，是安全与效果的平衡阀。
3. **DPO 为什么不需要奖励模型？** → RLHF 最优解下奖励与策略有闭式关系（`r = β·log(π*/π_ref) + β·log Z`），把 r 代入 Bradley-Terry 损失、配对相减消掉 `Z(x)`，就得到直接吃偏好对的监督损失。
4. **DPO 和 PPO/GRPO 的本质区别？** → **离线 vs 在线**。DPO 吃静态偏好对、不探索、被数据质量框住；PPO/GRPO 训练中自己采样、能超越训练数据。所以"调风格用 DPO，冲能力用 GRPO"。
5. **GRPO 比 PPO 省了什么？为什么能不要 critic？** → 省掉 critic 网络（一份完整模型副本 + GAE + value loss 调参）。因为 critic 的作用只是估计"平均水平"当基线，而**同题 G 个回答的成绩本身就是免费基线**。
6. **GRPO 里组内全对或全错会怎样？** → std=0 → 优势要么爆炸要么为 0，该 prompt 无梯度或梯度异常 → 加 ε、动态过滤这类退化组（DAPO 的 Dynamic Sampling 就是干这个）。
7. **DAPO 解决了什么问题？** → 长 CoT 训练失稳，四项：Clip-Higher（防熵坍缩）、Dynamic Sampling（过滤无效样本）、token 级策略梯度损失（防长序列梯度消失）、超长奖励整形（降噪）。
8. **为什么 R1 用规则奖励而不用 PRM？** → PRM 难规模化（步骤标注贵、"一步"定义模糊、易被黑客）；规则结果奖励 + GRPO 的组相对优势**隐式完成了步骤级信用分配**——成功/失败轨迹分叉处梯度最强。且实测 PRM 用在前沿模型上不如多数投票。
9. **PRM 和 ORM 怎么选？** → **默认 ORM**（便宜好调，数学/代码够用）；PRM 只在四类场景胜出：长程 Agent（末答模糊）、工具安全（惩罚中间行为）、MARL、推理时搜索引导。
10. **RLHF 会死吗？** → 不会：RLVR 替代不了风格/语气/拒答这类**不可验证**目标；但 RLHF 会从"主战场"退化成"风格兜底层"。一句话：**验证器是新的数据集**。
11. **RL 训练为什么比 SFT 贵这么多？** → 四份开销叠加：多模型同驻（策略/参考/RM(/critic)）、rollout 生成（推理负载 + 长 CoT 的 KV Cache）、训练侧激活、以及两套资源峰值都要扛。删 critic/删 RM 的算法演进，本质都是在优化这一项。
12. **奖励黑客怎么防？** → 多信号交叉（规则 + RM + judge）、长度与格式正则化、定期用新策略重训 RM、验证器噪声去偏、保持 KL 约束、上线前做对抗性验收。
13. **什么任务该上 RL，什么不该？** → 该上：**可验证**（数学/代码/SQL/结构化）或**有明确偏好信号**（风格/拒答）的目标；不该上：**知识类**（走 RAG / 继续预训练）、**临时指令**（走 Prompt）、**无奖励信号可定义**的任务（上了也训不出方向）。
