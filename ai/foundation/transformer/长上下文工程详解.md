## 0. 一句话定位

**长上下文 = 四个互不相干的天花板 + 一本账单。** 它们各自独立，改一个不会顺带修好其余三个：

| 天花板 | 由什么决定 | 症状 | 正文位置 |
|---|---|---|---|
| **结构上限** | 位置编码能否对任意位置 m 定义 | 超窗直接报错 / 位置全乱 | [环节 03](./环节03-位置编码详解.md) §7.2（RoPE 结构上限≈无限） |
| **能力上限** | 权重只在 L_train 内学过"距离怎么分配" | 能跑，但质量崩、退化成只看近邻 | [环节 03](./环节03-位置编码详解.md) §7.2 |
| **结构可见上限** | 注意力机制看得见多远的 token | 远处的信息**根本没进注意力** | 本文 §2 |
| **显存 / 算力上限** | KV Cache ∝ 并发 × 上下文；注意力 O(n²) | OOM / 延迟与成本爆炸 | [环节 10](./环节10-推理解码与KV缓存详解.md) §2、[环节 11](./环节11-服务化与推理引擎详解.md) §4 |

> 记忆点：**位置决定"能不能"，注意力模式决定"看得见多少"，KV 决定"同时服务多少"，算力决定"要花多少钱"。** 四问要分开答——"窗口开到 1M 了为什么还不行"通常问的是第二个（能力上限），"为什么这么贵"问的是第四个。

## 1. 增长从哪来：为什么 Agent 先撞墙

单轮问答的上下文是常数；**Agent 的上下文是累积量**——每次调用都要把"固定前缀 + 全部历史"重发一遍（[agent 环节 10](../../agent/环节10-生产级工程化详解.md) §成本）。

线性增长的历史 × 每次调用重发一遍 = **累计成本二次（quadratic）**。一份课堂示例（5 次调用、每轮新增 5K）：

| 调用 | 本轮输入 | 累计输入 |
|---|---|---|
| 1 | 6K | 6K |
| 2 | 11K | 17K |
| 3 | 16K | 33K |
| 4 | 21K | 54K |
| 5 | 26K | **80K** |

一份真实分布的实测（课件引 1,500 个 OpenHands session）：单 session 平均 **77,922 tokens**——与上面 80K 同量级。其 prompt 组成大致为：system+tools 23%、user 9%、reasoning 9%、tool calls 2%、tool results 20%（余下约 37% 未分类）。

> 数据口径：以上两组数字引自 CMU 11-768 L03 课件（2026-09 快照），**本库未独立复现**，只作量级参考。
>
> **关键推论**：前缀缓存（[环节 11](./环节11-服务化与推理引擎详解.md) §5.1）只能把"重复前缀"的**单价**打折，**消不掉"每轮都要重发一遍"的 token 量**。真正能把量降下来的只有三条：**少放（截断/压缩）、外置（检索/记忆）、少问（减少轮数）**——前两条见 [agent 环节 02 补充篇](../../agent/环节02-补充-上下文压缩与Compaction详解.md)。

## 2. 结构可见上限：四种"少看点"的机制

dense attention 让每个 token 看全部历史，代价 O(n²)。要续长，只有把"谁能看谁"改小。四条路线：

| 机制 | 怎么少看 | 复杂度 | 代表 | 主要代价 |
|---|---|---|---|---|
| **局部窗口（sliding window）** | 每个 token 只看左右各 w 个 | O(n·w) | Longformer、Mistral 系、DeepSeek 局部窗口分支 | 单层看不远，须靠层数堆出感受野 |
| **线性 / 状态递推** | 不看历史，把历史压进固定大小的状态 | O(n·d_k·d_v) | Linear Transformer → DeltaNet → Gated DeltaNet → KDA、Mamba | 状态有损；精确检索能力弱 |
| **稀疏（sparse）** | 只 attend 被选中的 k 个位置 | O(n·k) | Longformer 固定模式、DeepSeek DSA、**MiniMax MSA**（M3） | 选择器本身要训；选错就丢 |
| **KV 压缩** | KV 本身降维再还原 | 省的是**显存**不是注意力项数 | MLA（[环节 04](./环节04-Attention注意力详解.md) §3） | 表达能力受压缩率限制 |

### 2.1 局部窗口：mask 是"带子"，不是三角

dense 因果 mask 是下三角；局部窗口把它削成**带宽 w 的带**（band mask）——第 i 行只有 [i−w, i] 这段为 1。于是单层成本从 O(n²) 降到 O(n·w)。

代价在"感受野"：**单层只看 w，但信息可以跨层传播**——第 L 层的 token 间接"看得到"约 L·w 远的原文。所以局部窗口模型必然要**堆得深**才够用，而且**远距离的精确聚合**（"把全文所有失败案例列出来"）天然吃亏。

### 2.2 线性 / 状态递推：把"看历史"换成"更新状态"

核心思想：不存历史，只维护一个固定大小的状态矩阵 S，每步更新。

| 环节 | 递推式 | 新加了什么 |
|---|---|---|
| **Linear Transformer**（2020） | `S_t = S_{t−1} + φ(k_t)·v_tᵀ`，输出 `o_t = φ(q_t)ᵀ S_t` | 把 softmax 去掉，注意力变成可结合的结合律 → 递推 |
| **DeltaNet**（2021） | `S_t = (I − β_t k_t k_tᵀ) S_{t−1} + β_t k_t v_tᵀ` | delta 规则：**只写入"预测误差"**（先读旧值、再补差） |
| **Gated DeltaNet**（2024） | `S_t = α_t (I − β_t k_t k_tᵀ) S_{t−1} + β_t k_t v_tᵀ` | 加**标量遗忘门** α_t（该忘的忘） |
| **KDA**（Kimi Delta Attention，2025） | `S_t = (I − β_t k_t k_tᵀ) D_t S_{t−1} + β_t k_t v_tᵀ`，`D_t = Diag(α_t)` | 门控从标量变**逐通道**（每个维度独立决定忘多快） |

递进规律很整齐：**每一步只加一个算子**——把 softmax 换成核（线性化）→ 加写入规则（delta）→ 加标量门 → 把门变成逐通道。注意这个链条的收益与代价同时存在：**显存与状态恒定（与 n 无关，这是它的杀手锏），但状态是"有损压缩"**——想精确取回第 3 页的某个数字，它不如 dense attention。

> 与 [RNN知识整理.md](./RNN知识整理.md) §8 的递推公式对照看：那边讲到 Linear Attention / RetNet 就停了，本表把 DeltaNet → Gated DeltaNet → KDA 这三环补上。

### 2.3 稀疏：两种"选择"，先验 vs 内容

| | 固定模式（Longformer） | 内容相关挑选（DeepSeek DSA） |
|---|---|---|
| 谁决定看哪里 | **先验**：滑动窗 + 少量全局 token（`S_i^fixed`） | **内容**：一个轻量打分器按当前 query 选 top-k |
| 复杂度 | O(n·w) | O(n·k)，且 k 与 n 无关（如 top-2048） |
| 额外代价 | 无 | **索引器（indexer）本身要训**：dense 预热 → 引入稀疏 → 蒸馏索引器 |
| 适合 | 长文档理解 | 长上下文 + 需要"按内容跳着看" |

判据一句话：**固定模式是"大家都一样地看"，top-K 是"各看各的"**。后者更强，但把复杂度从"结构问题"变成了"训练问题"。

> DeepSeek 的实例细节（Lightning Indexer 打分式、dense 预热节奏、与 CSA/HCA 层数配比）见 [DeepSeek 技术路线与架构演进.md](../../model-cases/deepseek/DeepSeek技术路线与架构演进.md) §3.2——那篇是厂商实例纵深，本文不复述。V4.1-Flash 在 CSA 之上再压 KV（CED / CSA2 / FP4 / SWA 有界重放）见 [DeepSeek-V4.1-Flash通俗解读.md](../../model-cases/deepseek/DeepSeek-V4.1-Flash通俗解读.md)。**MiniMax MSA**（M3）同属内容相关块稀疏，但是 **GQA 组独立 Top-k 块**（块 128、k=16）+ KV-outer 核，不是 DSA 的 indexer；见 [MiniMax-M3全景与架构.md](../../model-cases/minimax/MiniMax-M3全景与架构.md) §三。

### 2.4 KV 压缩与"混合架构"（工业主流）

- **KV 压缩**：MLA 把每层的 K/V 压成低维 latent 存入缓存，用时再投影还原（[环节 04](./环节04-Attention注意力详解.md) §3）——它**不减少注意力看的 token 数**，减的是每个 token 的显存占用，所以与上面三条机制**正交、可叠加**。
- **混合（hybrid）**：工业界的现实答案不是"选一种"，而是**按层配比**——大部分层用便宜的局部/状态机制，留少量 global 层做"远距离精确混合"。

| 模型（课件原文，未独立核实） | 便宜机制 | global 层 | 比例 |
|---|---|---|---|
| Qwen3.8-Flash-Next | Gated DeltaNet + 稀疏检索 | 12 | 36:12 ≈ 3:1 |
| GLM-5.3-Flash | Kimi Delta Attention | 11（+稀疏） | 34:11 ≈ 3:1 |
| Kimi K3 | KDA | 24（dense Gated MLA） | 69:24 ≈ 3:1 |
| Nemotron 3 Ultra | Mamba-2 | 12（dense GQA） | 48:12 = 4:1 |
| Inkling-Small | 512-token 窗口 | 7（dense GQA） | 35:7 = 5:1 |

> 读法：**global 层不是"冗余"，而是"精确检索与全局聚合的唯一出口"**。比例越激进（5:1）越便宜，但对"从长文里精确取出一项"越危险——这解释了为什么纯线性/纯窗口模型在 NIAH 类检索任务上普遍吃亏（§7）。

## 3. 位置侧：三条外推路线的选型判据

机制（PI / NTK-aware / YaRN / NoPE）与公式已在 [环节 03](./环节03-位置编码详解.md) §6、§7.2 讲全（含 YaRN 的注意力温度修正 `√(1/t) = 0.1·ln s + 1` 与 NoPE）。本文只补**工程选型判据**：

| 你的处境 | 该走哪条 | 为什么 |
|---|---|---|
| 只有权重、零训练预算，窗口要临时扩几倍 | PI / NTK-aware 微调频率表 | 改配置即可，代价是近邻分辨率下降 |
| 有继续训练预算，要长期稳定用 | **YaRN（改频率）→ 再短→长续训（§4）** | 只改频率是"事后补救"；续训才是把**能力上限**抬上去 |
| 从零训练新模型 | **把 base 调大 + 短→长课程**，或直接用 NoPE + 局部/状态分支 | 主动抬上限，比事后插值划算得多 |
| 已用 NoPE 架构 | 不要额外加位置编码 | NoPE 的外推优势正来自"不发位置卡" |

> 一句话：**插值是补救，课程是根治。** 只插值不续训，等于把没训练过的距离区间硬推给模型（[环节 03](./环节03-位置编码详解.md) §7.2 的"两个没见过的区间"）。

## 4. 训练侧：长上下文是"练"出来的

### 4.1 短→长课程（通用台阶）

```
阶段 1：4K–8K    （主训练，语料主体，最便宜）
阶段 2：32K–128K （长文续训，数据要换成"真的长"的）
阶段 3：128K+    （少量超长样本收尾 + 位置频率重映射）
```

为什么不能一步到位：注意力模式的训练经验与长度强绑定，短序列上学到的"距离分配"直接搬到超长会崩；分阶段是**让权重逐段适应新的距离尺度**。

### 4.2 长上下文数据从哪来（四类配方）

| 配方 | 做法 | 作用 |
|---|---|---|
| **长文档自然语料** | 书/代码库/法规等天然长文本 | 覆盖真实长程依赖 |
| **打包（packing）** | 多条短样本首尾拼接、跨样本注意力隔断 | 提高长度利用率、降成本（但要处理"样本边界"） |
| **Agent 轨迹** | 多轮工具调用的完整 trajectory | 上下文天然长且**结构重复**，最贴 Agent 场景 |
| **合成任务** | 植入关键事实 → 要求召回/聚合（NIAH 式） | 低成本定向训练"别丢远处的信息" |

> 实例：DeepSeek 的序列长度课程为 4K → 16K → 64K → 1M，且**前 1T tokens 用 dense 注意力、到 64K 阶段才引入稀疏并预热 indexer**（[DeepSeek 技术路线与架构演进.md](../../model-cases/deepseek/DeepSeek技术路线与架构演进.md)）——正好演示了"新机制必须用课程引入"这条规律。

### 4.3 切序列：长序列训练的必备并行（CP）

128K 以上，单卡放不下 O(L²) 的注意力激活；但**切序列不能像切层那样各管各**——每个 token 都要 attend 全局 K/V。解法是上下文并行（context parallelism）：K/V 块在卡间**环形传递**（Ring Attention），结果与单卡逐位一致（**精确计算**，不是稀疏近似），显存降到 O(L·d_k/P)，但**总计算量仍是 O(L²·d_k)**。

机制细节与"为什么它必须与 CP/TP/PP 正交叠加"见 [环节 09](./环节09-训练管线详解.md) §5。

## 5. 推理侧：五种机制各省什么（别搞混）

长上下文推理的账要拆成两个量：**token 数**（有多少历史进模型）与**每 token 成本**（读一遍 KV 要多少时间/显存）。

| 机制 | 省的是什么 | **不省**什么 | 位置 |
|---|---|---|---|
| GQA / MLA | 每个 token 的 KV 体积 | token 数、注意力项数 | [环节 10](./环节10-推理解码与KV缓存详解.md) §2 |
| PagedAttention | KV 的**碎片**（利用率） | KV 总量 | [环节 11](./环节11-服务化与推理引擎详解.md) §1.3 |
| 前缀缓存 / RadixAttention | 重复前缀的 **prefill**（TTFT） | decode 成本、可见历史量 | [环节 11](./环节11-服务化与推理引擎详解.md) §1.7 |
| Chunked Prefill | TTFT **抖动** | 总计算量 | [环节 11](./环节11-服务化与推理引擎详解.md) §1.5 |
| KV 量化 | 显存**带宽**占用 | 精度（有损，须回归） | [环节 11](./环节11-服务化与推理引擎详解.md) §1.8 |
| **截断 / 压缩 / 检索** | **token 数本身** | 需要重编码（有信息损耗） | [agent 环节 02 补充篇](../../agent/环节02-补充-上下文压缩与Compaction详解.md) |

> 最常被搞混的一条：**"我开了前缀缓存，所以长上下文不贵了"——错。** 前缀缓存只对"每轮都重复的那段前缀"打单价折扣；随着对话变长，每轮新增的 token 依然按全价算，而且 decode 每步都要读全部 KV。（定价快照见 [上下文缓存定价对比.md](../../model-cases/providers/上下文缓存定价对比.md)。）

## 6. 把长上下文换算成钱

三本账，按大小排序：

1. **轮数 × 上下文长度**（最大头）：Agent 场景的账单主项是"每轮重发一遍"，所以**减少轮数 / 压缩历史**的收益是复利式的；
2. **缓存命中率**：命中段的单价约为未命中的 1/10 量级（各家不同，见定价快照），但**只有前缀完全一致的部分才命中**——所以 prompt 的稳定性（[环节 11](./环节11-服务化与推理引擎详解.md) §5.1 三条铁律：不变的放最前、别塞时间戳、别重排历史）直接等于钱；
3. **显存容量**：并发 × 上下文决定需要几张卡（[环节 11](./环节11-服务化与推理引擎详解.md) §4）。

> 判据：**能"少放"就不要"多塞"**。把 20K 的日志用检索替代（只召回 2K 相关片段），比把 20K 塞进窗口再开缓存便宜得多——这也是 RAG（[agent 环节 06](../../agent/环节06-检索增强RAG详解.md)）在长任务里始终有效的原因。

## 7. 怎么验收"长且没丢"

**宣称窗口 ≠ 有效窗口**：模型能接收 1M token，不代表 1M 内都能用好。已有厂商侧证据：DeepSeek 的 MRCR 8-needle 在 256K 后明显退化，标称 1M 的**有效区间约 128K–256K**（[DeepSeek 技术路线与架构演进.md](../../model-cases/deepseek/DeepSeek技术路线与架构演进.md) §有效区间）。

三类探针（由易到难）：

| 探针 | 测什么 | 局限 |
|---|---|---|
| **NIAH（needle-in-a-haystack）** | 在长文本里找一句话 | 太容易：模型可能学到"位置捷径"，通过 ≠ 可用 |
| **RULER** | 合成任务族：多针、变量追踪、聚合、长文 QA 的组合 | 更接近"真需要长程推理" |
| **LongBench** | 真实长文档任务（摘要/问答/代码） | 最贴业务，但需自己配回归集 |

> 验收纪律（对齐 [模型评测与选型方法详解](./模型评测与选型方法详解.md) §3）：**别用单一 NIAH 分数给长上下文下结论**；要看"多针 + 聚合 + 变量追踪"三类一起过，再补一个**你自己的长任务回归集**（例如"从 200 页日志里找出全部违规记录"）。理由见 §2.4：局部分支做得越激进，全局精确聚合越容易垮。

## 8. 决策表：什么场景用什么

| 你的场景 | 首选 | 别做什么 |
|---|---|---|
| 长文档问答（单轮，偶发） | 直接塞 + 前缀缓存；超有效窗口则切块 + RAG | 别为偶发需求上 YaRN 续训 |
| 长任务多轮 Agent | **压缩 + 外置**（[补充篇](../../agent/环节02-补充-上下文压缩与Compaction详解.md)）+ prompt 前缀稳定 | 别指望"开缓存"能平掉线性增长 |
| 需要精确检索长文中的具体项 | dense/global attention 层必须留足；或 RAG 精排 | 别用纯线性/纯窗口模型硬扛 |
| 自训模型要 1M 窗口 | base 调大 + 短→长课程 +（必要时）YaRN + CP | 别只改配置插值就上线 |
| 成本敏感的长上下文服务 | GQA/MLA + PagedAttention + RadixAttention + KV 量化 | 别把"省显存"当成"省 token" |

## 9. 坑清单

1. **把"标称窗口"当"有效窗口"排容量**：按 128K–256K 这类经验区间规划，而不是按发布会数字。
2. **只做 YaRN 不续训**：插值是频率补救，能力上限仍卡在 L_train（[环节 03](./环节03-位置编码详解.md) §7.2）。
3. **用纯局部/状态模型做"精确聚合"**：它擅长的是连续语义，不是"把第 3 页第 7 行的数字取出来"。
4. **只用 NIAH 验收长上下文**：单针通过可以靠捷径，要上多针 + 聚合 + 变量追踪。
5. **长上下文 + 大 batch 同时上**：显存总 token 数是硬约束，二者此消彼长（[环节 11](./环节11-服务化与推理引擎详解.md) 坑 7）。
6. **以为前缀缓存能平掉长上下文成本**：它只省重复前缀的 prefill（§5）。
7. **稀疏/线性混合架构按 dense 的直觉调参**：新机制（indexer、状态分支）需要**课程引入**，直接替换会掉点。
8. **忘了 CP 只解决"装得下"**：切序列并行不减少 O(L²) 总计算量（[环节 09](./环节09-训练管线详解.md) §5）。

## 面试高频追问（横切主题速刷）

1. 为什么窗口开到 1M 还是"不够用"？→ 四个天花板分开答：结构上限（位置）、能力上限（L_train）、结构可见上限（注意力模式）、显存/算力上限；1M 只是把第一个和第四个放宽了。
2. 线性注意力为什么省显存却做不了精确检索？→ 把历史压进固定大小的状态 = 有损压缩，检索要的是无损取回；所以工业界用**混合**，留少量 global 层做精确出口。
3. 稀疏注意力"固定模式"和"内容相关"差在哪？→ 先验决定 vs 内容决定；后者更强但引入训练成本（索引器要 dense 预热 + 蒸馏）。
4. 前缀缓存能解决长上下文成本吗？→ 不能。它只省重复前缀的 prefill 单价；token 数增长与 decode 读全量 KV 的成本照旧。真正降量的是压缩/外置/少轮数。
5. PI、NTK-aware、YaRN 怎么选？→ 零训练预算选 PI/NTK 临时扩；有预算走 YaRN + 短→长续训；新训模型直接抬 base 或用 NoPE。插值是补救，课程是根治。
6. CP（Ring Attention）为什么"精确"？→ 每张卡与"传到手上的完整 K/V 块"算注意力，传满 P 轮即访问全部历史，结果与单卡逐位一致；代价是每层 P 次 P2P 通信。
7. 混合架构的 local:global 比例为什么多在 3:1~5:1？→ 便宜的局部/状态层负责大部分语义混合，global 层负责远距离精确混合与检索；比例越激进越省钱、越伤精确检索。
8. 长上下文怎么验收？→ 三条一起：NIAH（单针，易过）、RULER（多针/追踪/聚合）、LongBench 或自建长任务回归；单看 NIAH 会被"位置捷径"骗。
