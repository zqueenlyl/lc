## 1. 为什么必须补"顺序"：Attention 天生对顺序无感

每个 token 有了坐标，但坐标只描述了"这个字是谁"，**没说它排第几**。顺序重不重要？看一个句子：

```
"猫追狗"   和   "狗追猫"
```

字一模一样（猫、追、狗），顺序不同，含义相反。如果只把三个字的坐标发给模型，它看到的两次是完全一样的三张卡——分不清谁追谁。

原因：模型内部用**相关度打分**比较词与词（下一环节 Attention 细讲），打分只用坐标算，坐标没变分数就不变 → 模型对顺序"无感"。数学家称之为**排列等变（permutation equivariance）**。

类比：电影院进场，你知道每个人的长相（词义），但票根没印座位号 → 不知道谁先到、谁在谁前后。**必须额外补发座位号**——这个动作就是位置编码。

```
Embedding（环节02）= 告诉他："这个人是谁"（长相）
位置编码（本环节）= 告诉他："他坐在第几排第几号"（顺序）
```

## 2. 老办法：把"座位号"直接加进去（绝对位置）

最直觉的办法：位置也发一张"卡"，把词坐标 + 位置卡**相加**：

```
第1个字：猫坐标(1.0,0.5) + 位置1的卡(0.0,0.1) → (1.0,0.6)
第2个字：狗坐标(0.9,0.7) + 位置2的卡(0.0,0.2) → (0.9,0.9)
第3个字：鱼坐标(0.8,1.0) + 位置3的卡(0.0,0.3) → (0.8,1.3)
```

位置卡从哪来？两种：

- **可学习绝对位置（learned absolute position）**（GPT-2 时代）：让模型自己"学"每一号位置长什么样。
- **sin/cos 公式生成**（Transformer 原版）：用固定频率（frequency）的正弦/余弦（sinusoidal）公式算每号位置的卡。

这类办法的两个硬伤（也是后来被 RoPE 取代的原因）：

1. **两个信息搅在一起**：词义坐标和位置卡"相加"混成一锅粥，模型要费力把"我是谁"和"我在哪"再拆开；
2. **没见过的位置发不出卡**：训练时句子最长 2 千字，位置卡只学到 2000 号；输入 4000 字时第 2001 号之后全是"从没见过的卡"→ 乱猜（**外推（extrapolation）差**）。

而 RoPE 的思路完全不同：**不告诉每个字"你在第几排"，而是让它在跟别人比较时，自动体现出"我们隔了几个座位"**。

## 3. RoPE 直觉：给每个词向量"装一个转向"

RoPE = Rotary Position Embedding = 旋转位置编码。核心动作只有一个字：**转**。

### 3.1 时针类比

每个词的坐标可以看成一根"时针"（从一个方向伸出去）。RoPE 的做法：

```
位置 1 的词：把时针额外拨 1 格
位置 2 的词：把时针额外拨 2 格
位置 n 的词：把时针额外拨 n 格
```

（教学中一格 = 45°；真实模型一格极小，见 §5。）

于是，两个词的**时针夹角 = 它们隔着几个位置 × 每格角度**。模型判断"我们隔多远"，只要看两根针的夹角——这就是**相对位置（relative position）**：只看差值，不管绝对值。

### 3.2 为什么"转"而不是"加"

模型判断两个词多相关时，会算一个"像不像"的分数（点积，§4 算给你看）。旋转有个数学魔法：**两个向量都旋转之后，它们的点积恰好只跟"旋转角度差"有关**——即只跟位置差有关。"相加"没有这个性质："加"出来的位置要靠模型硬学，"转"出来的位置是自动的。

### 3.3 转谁，不转谁（关键！）

模型里每个词有三份"拷贝"，分工不同：

```
Q（像手电筒）：负责"我去照别人"   → 要转（比较时需要位置）
K（像名牌）：负责"别人来照我"     → 要转（被比较时需要位置）
V（像内容本身）：负责"说出内容"   → 不转！（内容不需要位置）
```

大白话：**"我隔着多远去照你"这种比较需要位置 → Q、K 转；"我本身讲了什么"不需要位置 → V 不转。** 每层 Transformer 都要重新做一次比较，所以**每层都要转一次**，不是转一次就完事。

## 4. 旋转这件小工具 + 平移不变性的数值验证

### 4.1 旋转只需要会查 sin/cos

把向量转 φ°，公式（记住即可，不用推导）：

```
(x, y) 旋转 φ° 后：
新x = x·cosφ − y·sinφ
新y = x·sinφ + y·cosφ
```

查表：

| 角度 φ | cosφ | sinφ | 通俗理解 |
|---|---|---|---|
| 0° | 1 | 0 | 不转 |
| 45° | 0.7071 | 0.7071 | 转半格 |
| 90° | 0 | 1 | 转四分之一圈 |
| 180° | −1 | 0 | 转到反面 |

（0.7071 就是 √2/2，不用背。）试转一个：k=(0.7, 0.5) 转到 45°：

```
新x = 0.7×0.7071 − 0.5×0.7071 = 0.1414
新y = 0.7×0.7071 + 0.5×0.7071 = 0.8485
→ k@45° = (0.1414, 0.8485)
```

这个数下面要用。

### 4.2 先认识"像不像分数"（点积，dot product）

两个向量算相关度，最简单是**点积**：对应位置的数相乘再全部相加。取 q=(1,0)（朝右），k=(0.7,0.5)（朝右上），还没加位置：

```
q·k = 1×0.7 + 0×0.5 = 0.7
```

现在开始旋转。设定：**第 m 个位置 → 转 m×45°**。

### 4.3 关键实验 A：绝对位置不同、相对位置相同 → 分数必须相同

```
q 在第 2 位：转 90° → (0, 1)
k 在第 1 位：转 45° → (0.1414, 0.8485)
分数 = 0×0.1414 + 1×0.8485 = 0.8485

q 在第 5 位：转 225° → (−0.7071, −0.7071)
k 在第 4 位：转 180° → (−0.7, −0.5)
分数 = (−0.7071)(−0.7) + (−0.7071)(−0.5) = 0.8485
```

q、k 的内容一模一样，一组在第 2/1 位、一组在第 5/4 位——**分数都是 0.8485**！因为两种情况里 k 都"紧挨在 q 前一位"。模型不在乎句子里的第几号位，只在乎**隔了几格、谁在前**——这就是"相对位置编码"名字的由来。

### 4.4 关键实验 B：相对位置不同 → 分数不同（能分辨远近）

| 情况 | 算出来 | 说明 |
|---|---|---|
| q 和 k 同位置（间隔 0） | 0.7000 | 自己看自己 |
| k 紧挨在 q 前 1 位 | 0.8485 | 紧邻上文 → 分高，很重要 |
| k 在 q 后 1 位（未来） | 0.1414 | 未来会被 Mask 挡掉 |
| k 在 q 后 2 位 | −0.5000 | 更远 |

同一对向量，只是"隔着几格"不同，分数从 0.85 一路变成 −0.5 —— 模型对距离有了清晰的感知。

> 进阶注记：完整数学只有一条性质——旋转矩阵（rotation matrix）是**正交的（orthogonal）**，所以 `(转 mθ 的 q)·(转 nθ 的 k) = q·(转(n−m)θ 的 k)`，右边只出现位置差 n−m。

## 5. 为什么要"多档转速"？（最容易被问倒的点）

如果所有维度用同一根时针（比如每格 45°），会撞车：

```
位置 0：0°   位置 8：360°=0°（转满一圈又回来了！）
→ 位置 0 和位置 8 的向量长得一模一样，永远分不清 "紧挨" 和 "隔 8 位"
```

每 8 步重复一次，这种编码只能区分 8 个以内的相对距离——太短。那把转速调慢？一步只转 0.01°，转几千步才一圈——长距离能分清了，可**紧挨着的两个字几乎没角度差**，谁先谁后都分不出。

一个指针解决不了两个矛盾（既要看清邻居、又要看清远方），所以 RoPE 的答案是——**准备很多根指针**：

```
把一个词向量拆成很多"小对"，每对一根指针：
  第 1 对指针：转得极慢 → 负责"远距离"的相对位置（句子结构、隔几百字的两处呼应）
  第 2 对：稍快一点 …
  最后一对：转得极快 → 负责"紧挨着"的细粒度顺序（谁在前谁在后、局部词法）
```

不同 Attention 头各取所需：语法类头用快指针，语义/主题类头用慢指针。真实模型里"一格角度"由公式 `θᵢ = 1/10000^(2i/d)` 决定，10000 这个数叫 **base**，它控制整体标尺——base 大则远距离更清晰，base 小则近距离更清晰。

## 6. 不同方法全景（含优缺点，重要横向表）

| 方法 | 怎么干 | 优点 | 缺点 | 外推（长文本） | 代表 |
|---|---|---|---|---|---|
| **可学习绝对位置** | 给每个位置 id 配一个可训练向量，加到 embedding 上 | 简单、模型自由发挥 | 位置信息是"加法噪声"；只能学到训练过的长度 | 差，超长需插值 | 早期 GPT、BERT |
| **Sinusoidal 正弦** | 用固定公式的 sin/cos（不同维度不同频率）编码位置 | 无需训练；理论上有相对性 | 固定频率不可学，现代模型用得少 | 一般 | Transformer 原论文 |
| **相对位置（relative positional encoding）** | 注意力打分时改用"i−j 的距离"而非绝对位置 | 更贴合注意力本质（关心距离而非序号） | 实现侵入注意力内部 | 较好 | T5 的相对 bias |
| **RoPE 旋转（主流）** | 把 Q/K 向量按位置旋转角度，让点积天然携带"相对旋转角差" | 与注意力融合最优雅、训练稳定、有理论外推性 | 长距离旋转角可能混淆；外推仍有限，需 YaRN/NTK 扩展 | 好（配合插值） | GPT 系、LLaMA、Qwen、DeepSeek |
| **ALiBi** | 注意力分数直接减去"距离×斜率"的线性偏置（linear bias） | 极简、几乎零成本、短训练长外推很好 | 偏置与内容无关，理论上限较低 | **优秀**（早期长上下文最爱） | BLOOM、MosaicML |

**一句话取舍**：要"主流 + 生态好"用 **RoPE**；要"短训练长外推、实现最简"看 **ALiBi**；可学习绝对位置基本淘汰。

## 7. 深入与延伸

### 7.1 一句话总结这一环

> **Embedding 把"符号"翻译成"语义坐标"（管：这个字是谁）；位置编码给坐标装上"转向"（管：它排第几、跟别人隔多远）。一个管是什么，一个管在哪，缺一个模型都没法正确接龙。**

### 7.2 长上下文外推的工程手法（面试常考）

**"RoPE 训练长度有限，但推理想续更长"**——这句要拆成两个上限看：

- **结构上限 ≈ 无限**：RoPE 的位置就是"把 Q/K 拨 m 格"，cos/sin 对任意 m 都有定义，位置卡永远发不完——这和 §2 可学习绝对位置"只训到 2000 号、2001 号之后没卡"是本质区别；
- **能力上限 = L_train**：位置编码只负责"让距离存在"，而"隔多远该给谁多大注意力"是**权重训出来的**。训练语料最长 L_train，模型只见过相对距离 ∈ [0, L_train) 的分配模式，超窗就是把没见过的输入推进来。

所以硬喂超长序列**不报错、能跑，但质量崩**，原因有两个：

1. **没见过的距离区间**：长距离注意力没有训练经验，逐渐退化成只看近邻、忽略远处上下文；
2. **没见过的相位区间**：低频档转速极慢（§5 的 θ_i，转一圈要上万步），2k 训练里从没转满过一圈，模型只见过它头一小段弧度；长位置把它推进从未露面的相位区——cos/sin 算得出值，但下游权重从没学过这类输入分布。

位置插值（positional interpolation）**PI** / **NTK-aware scaling** / **YaRN** 本质都是**把训练过的旋转频率（frequency）重新映射到更长序列**——不动模型结构、只改频率表，让新位置重新落回权重"舒适区"，即"推理期无痛续长"。三种手法的差别就是**这份长度预算怎么分**：

| 手法 | 频率处理 | 代价/取舍 |
|---|---|---|
| **PI** | 所有频率等比调慢（等价于位置 m→m/λ） | 慢档更慢 → 紧邻 token 区分度下降（§5：慢指针分不出挨着的字） |
| **NTK-aware** | 只压低高频，低频尽量保持 | 保住短程分辨率，兼顾长程 |
| **YaRN / NTK-by-parts** | 按波长与 L_train 把维度分三档：转熟的低频**不动**、临界中频**轻插**、从没转完的高频**大插**，另加注意力温度补偿 | 最精细，LongChat/LongLoRA 系主流 |

工程上：context 超长优先考虑这类扩展 + 配合 [环节 11 推理引擎](./环节11-服务化与推理引擎详解.md) 的前缀缓存（prefix caching）/滑窗（sliding window）。现代长上下文模型更是在预训练/续训时直接把 base 调大（LLaMA-3 用 500k、Qwen 系到百万级），主动抬高能力上限。反衬 §6 表里的 ALiBi 行：偏置线性、没有训练频率，天生"短训长推"，早期长上下文建模才常用它。

> 记忆点：RoPE 提供**位置的结构**（结构上限无限），训练提供**用位置的能力**（上限 L_train）。"续长" = 用频率重映射把能力上限追平结构上限，而不是让位置编码自己多长出卡来。

### 7.3 零基础自测（能答对 = 真懂了）

1. 为什么 Attention 天生不关心顺序？→ 它只按内容坐标算"像不像"，顺序对调分数不变。
2. RoPE 转什么、不转什么？→ 转 Q 和 K（比较用），不转 V（内容用）；每一层都转。
3. 为什么不能只用一根时针？→ 单一转速在"转一圈"处撞车，短距离和长距离不可兼得；要多档转速分工。
4. "相对位置"体现在哪？→ (转 mθ q)·(转 nθ k) = q·(转(n−m)θ k)，只剩位置差。
5. ALiBi 与 RoPE 的核心取舍？→ 极简可长外推 vs 与注意力融合的主流优雅解。
6. "RoPE 训练长度有限，但推理想续更长"是什么意思？→ 位置卡结构上对任意 m 都有定义（结构上限≈无限），但模型只在 L_train 内学过怎么分配注意力（能力上限=L_train）；超窗能跑但质量崩——没见过的距离区间 + 低频维没转满一圈的相位区间。续长 = PI/NTK/YaRN 把训练过的频率表重映射，让新位置落回权重舒适区。
7. PI / NTK-aware / YaRN 怎么分"长度预算"？→ PI 全频率等比调慢（近邻区分度降）；NTK-aware 只压高频保低频；YaRN 按波长 vs L_train 分三档（转熟的保 / 临界轻插 / 从没转完的大插）+ 注意力温度补偿。
