## 1. 干什么

Block 堆叠的最终输出 Z（每个位置一个向量）还不能直接当答案。出口要做两件事：

1. **输出头（LM Head）**：把向量映射到词表大小的分数（logits）；
2. **训练目标**：定义"哪个答案是对的、错的差多远"——训练的全部意义就是让"对的答案分数越来越高"。

---

## 2. 输出头（LM Head）

最后一层向量乘 `W_head`（词表大小矩阵）得到**未归一化分数 logits**，再 softmax 成"下一个 token 的概率分布"。窗口里每个位置都产出这样一行概率分布（probability distribution）：

```
logits = X·W_head + b_head                             # (n, |V|)，无 softmax
P_next = softmax(logits)                               # (n, |V|)，每行 = 该位置看前缀后的下一个词分布
```

> 细节：LM Head 常与输入 Embedding 权重共享（weight tying，省参数），见 [环节 02](./环节02-Embedding查表详解.md) §3。

---

## 3. 训练目标：怎么定义"对"

| 目标 | 做法 | 优点 | 缺点/代价 | 谁在用 |
|---|---|---|---|---|
| **Next-Token CE（事实标准）** | 标签（label）= 原序列右移一位；每个位置预测它后面的词，取平均交叉熵（cross-entropy，CE） | 无需标注（自我监督，self-supervised）、并行高效 | 每个位置只监督 1 个词，信息利用率低；训练/推理分布不一致（Exposure Bias） | GPT 全系 |
| **多 Token 预测（multi-token prediction，MTP）** | 主头（main head）外再叠 1~2 个"预测下一个、下下个…"的辅助头 | 加速收敛、提升推理与代码能力、训练完可卸掉 | 额外显存与实现复杂度 | DeepSeek-V3、Meta（2024 MTP 论文） |
| MLM（masked language modeling，掩码语言建模） | 随机盖住词，只预测被盖住的 | 双向理解强 | 属于 Encoder 系，与自回归生成不兼容 | BERT 系 |

### 3.1 关键澄清：训练是 Teacher Forcing

**训练永远拿"真实语料"当下一步输入，绝不拿模型上一步自己的输出喂自己**——这样整条序列才能并行（[环节 04](./环节04-Attention注意力详解.md) §2.3 的 Mask 保证不偷看），训练也稳定。代价：部署时模型只能吃自己的输出，分布有落差（**Exposure Bias**）→ 用 SFT/对齐部分补偿（[环节 09](./环节09-训练管线详解.md)）。

### 3.2 损失公式

输入 `[tok_0 … tok_{n-1}]`，第 i 行负责预测 `tok_{i+1}`，标签就是**右移一位**的同一个序列：

```
L = - (1/(n-1)) · Σ_{i=0}^{n-2} log P_next[i][ idx[i+1] ]     # 平均交叉熵
```

这就是为什么训练不需要"逐 token 喂"：整条序列一次性前向，位置 i 由于 Mask 只看得到 `tok_0..tok_i`，天然满足"预测 tok_{i+1} 时不能偷看未来"。

**交叉熵（CE）速览——上面这个公式到底在算什么**：每个位置都在做一次"词表上的分类"，正确答案是 one-hot（标签右移一位给的那个词），所以求和里其它项全是 0，单位置 loss 就退化成 **`−log p_c`**（负对数似然 NLL）——只罚一件事：**模型给"真实下一个词"的概率够不够高**。真词概率 1.0 → loss 0；0.5 → ≈0.69；0.1 → ≈2.3。"交叉熵"这名字来自信息论：`−log p` 叫惊讶度，交叉熵 ≈ 用模型分布 Q 去编码真实分布 P 的平均比特数；固定标签时（P 是 one-hot、熵为 0）它正好等于 KL 散度，所以"最小化 CE" 等价于"让模型分布贴近真实标签分布"。也正因目标是**分布对齐而非数值逼近**，分类不能用 MSE：MSE 会把概率往 0.5 的中间值扯，且真词概率接近 1 时梯度趋 0、学不动；而 softmax + CE 的梯度有漂亮闭合解 `p − y`（§4）——这就是它俩是黄金搭档的原因。训练完的 loss 可直接换算困惑度：`perplexity = e^loss`。

## 4. 数值走查·下半场：从注意力输出 Z 到损失与梯度

承接 [环节 04](./环节04-Attention注意力详解.md) §5 的走查：玩具模型（词表 {a,b,c,d}，标签 Y=[b,c,d] 即 [1,2,3]），已算出残差后的 Z（本例 FFN/LN 恒等、W_head=I，故 Z 即 logits）：

```
Z0 = a + O0 = [2.00000, 0, 0, 0]
Z1 = b + O1 = [0.37754, 1.62246, 0, 0]
Z2 = c + O2 = [0.27408, 0.27408, 1.45185, 0]
```

**Step 7 预测分布（softmax 每行）**：

```
行0：softmax(2,0,0,0)  = [0.71123, 0.09626, 0.09626, 0.09626]
行1：softmax(.38,1.62,0,0) = [0.17113, 0.59424, 0.11732, 0.11732]
行2：softmax(.27,.27,1.45,0) = [0.16646, 0.16646, 0.54053, 0.12656]
```

期望：行0 应预测 b、行1 应预测 c、行2 应预测 d。结果当然全错——因为权重是"手调的便于演示的值"，**不是训练出来的**。这正是我们要的起点：看损失多大、梯度往哪走。

**Step 8 训练损失（标签 [b,c,d]）**：

```
L = -(ln 0.09626 + ln 0.11732 + ln 0.12656) / 3
  = -(2.3416 + 2.1428 + 2.0670) / 3
  = 2.184
```

> 参考锚点：|V|=4 时**随机均匀输出**的损失 = ln 4 ≈ 1.386。本例手调权重与任务错配导致 > 1.386，训练的作用就是把 loss 一路压到 ~0。

**Step 9 梯度方向（为什么训练能学会）**

softmax + 交叉熵组合的梯度有闭合解，漂亮到值得背：

```
∂L / ∂z_i  =  P_i − y_i            # z：某位置未归一化 logits；y：标签 one-hot
```

以行 2 为例（标签 d）：

```
P2 − y2 = [0.16646, 0.16646, 0.54053, 0.12656] − [0,0,0,1]
        = [ 0.166,  0.166,  0.541, −0.873]
```

含义：让"正确 token(d)"的 logit 上升（负梯度方向 +0.873），其余被压下去——这就是一次参数更新的方向信号。反向传播（backpropagation）再把这个梯度按链式法则（chain rule）分摊到 W_Q/W_K/W_V/W_head/Embedding/位置向量（自动微分（automatic differentiation）代劳）。

> 完整数值验证（含 loss=2.1838）可用 [环节 04](./环节04-Attention注意力详解.md) §5.1 的 numpy 代码跑一遍。

## 5. 训练全过程（算法级）

```
① 数据打包：一句话 [tok_0,…,tok_L] → 训练对 (输入=窗口[0:L], 标签=[1:L+1])，即"右移一位"
② 前向：整条序列一次过 Embedding+pos → N 层 Block → LM Head      # 全位置并行
③ 损失：每个位置平均交叉熵（§3.2）
④ 反向：梯度沿 logits → Z → 各层 Block → QKV 投影/FFN/Embedding 回传
⑤ 更新：AdamW/lr schedule 更新全部参数
⑥ 重复 ②~⑤ 若干 epoch
```

要强调的两点：

- **并行不偷看 = Mask**。训练时位置 i 的注意力被 Mask 限制在 j≤i，因此"并行算所有位置"与"一个词一个词地预测"语义完全等价——这是 Decoder-only 能高效训练的根本（机制见 [环节 04](./环节04-Attention注意力详解.md) §2.3）。
- **Teacher Forcing**：训练时不拿"上一步模型的输出"喂下一步，而永远喂真实语料。优点：并行 + 稳定；代价：训练/推理分布不一致（Exposure Bias），用 SFT（supervised fine-tuning，监督微调）数据 + 少量策略梯度（policy gradient）缓解（RLHF/GRPO，[环节 09](./环节09-训练管线详解.md)）。

## 6. 训练 vs 推理机制对照（含 RNN 参照系）

| 维度 | RNN 训练 | Transformer 训练 | Transformer 推理 |
|---|---|---|---|
| 输入 | 序列 + 标签 | Teacher Forcing：整条序列进模型 | 只喂已生成的 token |
| 目标 | 每个位置的下一 token | 全部位置并行预测下一 token | 只预测最后一个位置 |
| 损失 | 各步交叉熵求和 | 全位置交叉熵平均 | 无（直接采样） |
| 并行度 | 低（串行依赖） | 全并行（Mask 保证因果） | Decode 串行（KV Cache 优化） |
| 因果性 | 天然（没看过未来） | 靠 Mask 屏蔽未来 | 天然（只有过去） |

### 6.1 同一前向的两个出口：读概率（生成）vs 读隐状态（向量）

先纠一个高频混淆。常听到"模型预训练完，除了生成还能拿来算 embedding"——这句话其实把三层叠在一起了：

- **① token embedding（词查表）**：地基。任何一条输入前向的第一步都要查表（[环节 02](./环节02-Embedding查表详解.md) §2.5：token id 就是 one-hot 的压缩存储），生成与向量计算**共用**，它不是"一个功能"；
- **② 生成出口**：前向到最末层后**接 LM Head**，把最后一个位置的向量映射成"下一个词的分布"（§2），采样递归出文本（[环节 10](./环节10-推理解码与KV缓存详解.md)）；
- **③ 向量出口**：同一套 backbone 前向到某层就**停**，**绕过 LM Head**，把整段隐状态"压"成一个 d 维向量返回。

真正能并列的是 ②③——同一个预训练底座，两种"职业"：

| 维度 | 生成出口（对话/续写） | 向量出口（文本向量化） |
|---|---|---|
| 读什么 | 接 LM Head → 全词表 logits → softmax（§2） | 不读 LM Head，直接池化隐状态 |
| 产物 | 一段文本 | 一个 d 维稠密向量 |
| 训练目标 | next-token CE（§3.2）：猜对下一个词 | 对比学习：同义句拉近、同批/难负例推开 |
| 前向次数 | 每 token 一次（自回归递归，环节 10） | 整段一次（无采样、无递归） |
| 用途 | 续写 / 问答 / Agent | 相似度度量 / 语义检索 / RAG 召回 |
| 部署特性 | 吃 KV Cache、看 TTFT/TPOT | 一次前向，天然低延迟 |

**"压成一个向量"是什么操作**：把每位置的 `(n, d)` 表示折成一个向量——mean pooling（全位置平均）、[CLS]（Encoder/BERT 风格），而 **Decoder 系主流用 last token**：因果注意力下最后一个位置恰好"看过全文"，直接取它的输出即整句语义（BGE-M3 / Qwen-Embedding / GTE 皆此风格）。

**为什么"拿对话模型直接算向量"不好用**：预训练只学过 next-token（§3.2），隐空间的几何按"谁的上下文像、谁离得近"生长，不是按"谁的句子同义"生长——同义改写句未必贴在一起，还会犯**各向异性**（少数方向主导，余弦值普遍偏高、区分度差）。所以好用的句向量 = **同基座 + 对比学习再微调**的专用模型：正样本 = 同义句、负样本 = batch 内其它句子、再加难负例（hard negatives）精修；这步微调同样可走 LoRA 等低秩路线（[环节 09](./环节09-训练管线详解.md)）。工业界因此几乎都是"专模专用"：对话 / 生成用一组模型，embedding（BGE / E5 / text-embedding-3 / Qwen-Embedding）是**另一组部署**，权重只在少数"多任务同训"实验里共享。

**"向量近似、token 精确"——为什么生成出口注定是一串 token，而不是一个向量**：模型内部每一步都在 d 维连续空间运算，隐状态本身也是"向量"，两个出口只是同一工作台的两种读法——**直接读出**是 embedding（保住近似语义），**离散化读出**（LM Head 映射词表取一个）是 token（还原精确符号）。生成绝不能"一次吐一个向量"交差，因为**最终产品是文本，而文本是离散序列**：从语义点反解回句子是病态问题——一句话的向量只概括"意思"，丢掉每个字的精确措辞，语义邻域里挤着无数"意思相近但用词不同"的句子，永远无法唯一还原原句。embedding 只能帮你"找出最像的另一句"（所以检索/召回好用），还原不出原文。于是生成必须走**逐步离散决策**：把 `词表^L`（如 100K^500）这种天文数字的联合选择，拆成 L 次"只看词表、挑 1 个"的小决策，且每步以已生成的 token 为条件（自回归，[环节 10](./环节10-推理解码与KV缓存详解.md)）——**精度来自每一步都咬合真实文本**。

> 记忆点：生成读**概率**、向量读**隐状态**；生成要递归、向量一次过；生成用 CE 训、向量用对比 loss 训。预训练给的是一具共用骨架，两个职业靠各自的微调目标上岗。在 RAG 里它们各司其职：向量管"找得准"（query/文档入库比对，召回见 [`../../agent/环节06-检索增强RAG详解.md`](../../agent/环节06-检索增强RAG详解.md) §2），生成管"写得好"（把命中的原文组织成答案）。

## 7. 可运行验证代码：PyTorch 训练版（从随机初始化学会 a→b→c→d）

```python
import torch, torch.nn as nn, math
V, d, N = 4, 16, 2                      # 词表4、d=16、2层
data = torch.tensor([0,1,2,3])          # 语料 a b c d
class Block(nn.Module):
    def __init__(s):
        super().__init__()
        s.q, s.k, s.v = (nn.Linear(d,d,False) for _ in range(3))
        s.n1 = nn.LayerNorm(d); s.f = nn.Sequential(nn.Linear(d,4*d), nn.GELU(), nn.Linear(4*d,d)); s.n2 = nn.LayerNorm(d)
    def forward(s, x):
        B,T,_ = x.shape
        Q,K,Vv = s.q(x), s.k(x), s.v(x)
        m = torch.triu(torch.full((T,T), float('-inf')), 1)
        P = (Q@K.transpose(-1,-2)/math.sqrt(d) + m).softmax(-1)
        return s.n2(x + s.f(s.n1(x + P@Vv)))
class GPT(nn.Module):
    def __init__(s):
        super().__init__()
        s.tok = nn.Embedding(V,d); s.pos = nn.Embedding(64,d)
        s.blocks = nn.ModuleList([Block() for _ in range(N)]); s.lm = nn.Linear(d,V)
    def forward(s, idx):
        T = idx.shape[-1]
        x = s.tok(idx) + s.pos(torch.arange(T, device=idx.device))
        for b in s.blocks: x = b(x)
        return s.lm(x)

m = GPT(); opt = torch.optim.AdamW(m.parameters(), 3e-3)
X, Y = data[:-1].unsqueeze(0), data[1:].unsqueeze(0)
for i in range(4000):
    opt.zero_grad()
    loss = nn.functional.cross_entropy(m(X).transpose(1,2), Y)
    loss.backward(); opt.step()
print("final loss:", loss.item())       # 过拟合单条语料，应降到 ~0
# 推理：从 [a] 自回归生成
def gen(seed, k=4):
    idx = seed.clone()
    for _ in range(k):
        logits = m(idx)[0,-1]; nxt = logits.argmax()
        if nxt == idx[-1] or len(idx) > 10: break   # 玩具防死循环
        idx = torch.cat([idx, nxt.view(1)])
    return idx.tolist()
print("generate:", gen(torch.tensor([0])))   # 期望近似 [0,1,2,3] = a b c d
```

> 玩具模型注意点：语料只有 4 个 token，学到的是"0→1→2→3"的单链转移；真实模型学的是词表级分布 + 长程条件概率。演示的是**机制**，不是规模。

## 8. 面试高频追问

1. LM Head 输出的是什么？→ 全位置、词表大小的 logits（未归一化分数），softmax 后才是概率。
2. 为什么训练要用 Teacher Forcing 而不是自回归喂自己？→ 并行 + 稳定；代价是 Exposure Bias，靠 SFT/对齐补偿。
3. Loss 下降到 ln|V| 以下意味着什么？→ 学到了超越"均匀猜词"的信息；下降到 ~0 则基本背住了训练分布（过拟合（overfitting）信号）。
4. MTP（多 token 预测）解决什么？→ 每个位置不止监督 1 个词，加速收敛与推理/代码能力，可训练后卸掉。
5. next-token CE 的缺点？→ 监督信号（supervision signal）稀疏（每位置只 1 个词）、训练/推理分布不一致。
6. 为什么"并行算所有位置"等于"逐词预测"？→ 因果 Mask 挡住未来，位置 i 的表示与只看前缀的逐词推理在语义上等价。
7. 同一个预训练模型能"既生成又当 embedding"用吗？→ 骨架可共享，但空间几何由训练目标决定：只学过猜词的对话模型，其隐状态当句向量"可用但不好用"（同义句未必近 + 各向异性，§6.1）；好用向量需同基座 + 对比学习微调的专用模型，生产通常两套部署——向量管召回、生成管作答。
