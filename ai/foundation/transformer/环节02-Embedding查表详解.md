## 0. 起步课：先明白模型到底在干嘛

你电脑里的 GPT 内部**没有任何文字**。它是一台只做数字运算的机器：

- 进去：一串数字；中间：成千上万次"乘、加、比较"；出来：另一串数字。

"文字接龙"是外面包装出来的感觉。它每次只干一件事：**看着前面已经出现的文字，猜下一个字（token）是谁**。所以文字进门之前必须被"翻译"成数字。翻译官有两位，各管一件事：

| 翻译官 | 回答的问题 | 在哪个环节 |
|---|---|---|
| Embedding | 这个字**是什么**（语义） | 本环节（环节 02） |
| 位置编码（positional encoding；实现用 RoPE） | 它在句子里**排第几**（顺序） | 下一站 [环节 03](./环节03-位置编码详解.md) |

全链路至此的旅行地图（本文只走前两站）：

```
"我爱猫"
  ① 切块、查编号本（[环节01](./环节01-Tokenizer分词详解.md)） →  [2] [7] [35]
  ② 翻译成词义坐标（Embedding，本环节）        →  每个字一串数字
  ③ 按位置旋转（RoPE，下一环节）              →  给坐标带上"排第几"
  ④ 送进 Transformer Block …（环节 04 起）
```

## 1. 干什么（为什么编号不能直接用）

上一站得到的是编号。编号是"离散（discrete）的、没有相似度"的：`猫=5`、`狗=6` 之间没有任何数学关系，网络吃不了，而且**编号本身有三个人为假象**：

| 坑 | 例子 | 为什么致命 |
|---|---|---|
| ① 编号是假的 | 7 + 35 = 42 | 模型爱做加法，可"爱+猫=42"毫无意义 |
| ② 大小是假的 | 35 > 7 | 不代表"猫"比"爱"高级 |
| ③ 远近是假的 | 猫=35、狗=36 挨着 | 可"爱"=7 离它们很远——编号顺序跟意思毫无关系 |

解决：给每个编号配**一维稠密向量（dense vector）**（几百~几千维），让"意思相近的词在向量空间里距离近"。这一串数字就叫**向量（vector）**；直观上把它想成地图上的点（坐标）：两个数字 = 平面上的点，几千个数字 = 几千维空间里的点，道理一样。

> **意思接近的词，在地图上住得近；意思无关的词，离得远。** —— 词的分布式表示（distributed representation）/ 语义向量（semantic vector）。这是本环节最重要的思想。

## 2. 怎么干：本质是一次查表（lookup）

`W_E` 是一个「词表大小（vocabulary size）× 隐藏维度（hidden dimension）」的矩阵，`向量 = W_E[token_id]`——按行号取一行，**查表瞬间完成，不涉及任何计算**。

### 2.1 词义坐标表长什么样

```
词义坐标表（示意，2 个数 = 2 维）

  编号   词     坐标（向量）
  2     我      ( 0.2,  0.9)
  7     爱      ( 0.1,  0.6)
  35    猫      ( 1.0,  0.5)
  36    狗      ( 0.9,  0.7)
  40    鱼      ( 0.8,  1.0)
  200   汽车    (-0.9,  0.1)
```

"我爱猫" → 查三行 → `(0.2,0.9) (0.1,0.6) (1.0,0.5)`。这张表就叫 **Embedding 矩阵（embedding matrix）/ 词嵌入（word embedding）**。

画到纸上：

```
  y↑
1.0│         ·鱼(0.8,1.0)
0.8│        ·狗(0.9,0.7)
0.6│   ·爱   ·猫(1.0,0.5)
0.4│  ·我
0.2│·汽车(-0.9,0.1)
0.0└──────────────────────→ x
  -1.0        0    0.5     1.0
```

算算距离（两点坐标相减取平方和再开根号）：

```
猫和狗：  差(0.1, 0.2) → 距离 ≈ 0.22   （很近）
猫和汽车：差(1.9, 0.4) → 距离 ≈ 1.94   （很远）
```

**猫狗为什么该近？不是谁规定的。** 训练时模型读海量文章，发现"猫"和"狗"总出现在相似的句子里（"小猫很可爱"、"小狗很可爱"），就一点点把它们的坐标挪近。这叫**分布式假设（distributional hypothesis）**：看一个词，从它身边的朋友来认识它。

### 2.2 训练在干嘛（大白话）

1. 一开始：整张表是**随机乱点**的地图（猫可能在左上、狗在右下）；
2. 每读一句话，模型预测错了 → 得到修正信号：把"该近的"挪近、"该远的"挪远一点；
3. 读上万亿句之后：地图越来越有规律 → 词坐标表"学习完成"。

### 2.3 训练更新机制：查表为什么也能反向传播

**问题**：前向 `W_E[token_id]` 只是"挑一行"，没做任何运算——没计算，梯度往哪传？答案：**不需要对"挑"求导**，因为"挑第 i 行"可以写成一次标准矩阵乘，整条链自然可导：

```
x_i = e_i · W_E        # e_i：第 i 位为 1、其余为 0 的 one-hot 行向量 → 乘出来恰是第 i 行
```

反向传播一路从 LM Head（猜词输出头）传回 `∂L/∂x`，到 W_E 这一层按链式法则得到：

```
∂L/∂W_E = Σ_i e_iᵀ ⊗ (∂L/∂x_i)      # 只对 batch 里出现过的 token 行非零
W_E ← W_E − η · ∂L/∂W_E              # 之后交给 Adam 等优化器加工
```

大白话翻译两句：
- **被取中的行**：收到下游原样送回的一笔梯度，往"模型认为该去的方向"挪一点；
- **没被取中的行**：本轮梯度为 0，原地不动。

实现上就是一个 `scatter_add`（把梯度累加回对应行）。所以随机初始化后，Embedding 与全网参数走**同一条反向传播**、一起更新——只是它每步只更新"命中"的那些行。

> 记忆点：Embedding 层**没有自己的损失函数**。它的梯度是下游 N 层 Block + 输出头一路反传回来的，每个词"往哪挪、挪多远"完全由 next-token 预测任务反向决定。语义地图（§2.1 猫狗近、汽车远）不是标的：是"猫狗总出现在相似上下文 → 反传回的梯度方向相近 → 被推向相近坐标"的涌现结果。

#### 2.3.1 推论一：梯度天然稀疏 → 低频词"学不动"

每步只更新 batch 内出现过的词行。高频词每步都被推、训得"熟"；低频词几乎收不到梯度，**长期停在初始小随机值附近**。这正是词表长尾"死 token"在训练侧的机理（[环节 01 §6.1](./环节01-Tokenizer分词详解.md) 词表大小专题的长尾表）：词表塞得再大，新增的多是低频行——占显存、几乎不吃梯度，等于白留名额。

#### 2.3.2 推论二：初始化尺度很讲究

现代 LLM（LLaMA/Qwen）用标准差约 `0.02` 的小随机，而不是 Word2Vec 时代的较大均匀分布：
- **太大** → 每个词的初始向量差异过大，刚进门就盖过位置编码与后续层信号，残差主干早期不稳；
- **太小** → 所有词都接近零向量，要先"从零长出来"，收敛慢。

`0.02` 这个量级 ≈ 不同词之间的随机区分度刚好够用，又不喧宾夺主。

#### 2.3.3 推论三：工程上是通信与显存大户

- 参数量是 `|V|×d`（130k×4096≈5.3 亿），见 §3 方案表与工程注记；
- 分布式训练要跨卡 allreduce **整张** `W_E` 梯度——梯度虽"稀疏"（只有命中行非零），通信却"稠密"（整张大矩阵都要同步），所以超大规模常做**词表并行**（embedding 按行分片到各卡）或 tie embedding 省参数；
- 训练阶段：预训练 / SFT 全程更新；LoRA 等冻结 base 参数的方案里它不更新。

### 2.4 与 Word2Vec 等"静态词向量"的本质区别

| | Word2Vec / GloVe | LLM 里的 Embedding |
|---|---|---|
| 训完 | **冻结（frozen）**：静态（static），一词一义，"bank"不分银行/河岸 | 只是入口层，跟随整个网络继续训练 |
| 语义 | 固定的一个向量 | **由上下文动态精修（contextualized）**——一词多义（polysemy）在后续几十层注意力里按语境决定 |
| 位置 | 独立工具 | 全链路第一站，语义靠后面 Block 逐步提炼 |

> 记忆点：**Embedding 只是"字典的起点"，不是终点**。真正的语义要等 [环节 04 Attention](./环节04-Attention注意力详解.md) 让词与词互相参照之后才成型。

### 2.5 one-hot 编码 vs Embedding：本质对比

**one-hot 编码（one-hot encoding）**：给词表里每个词配一个 `|V|` 维向量，只有它自己是 1、其余全是 0（"独热"）。这是"编号"最朴素、最诚实的向量化：编号 5 就是第 5 位点亮、其余全灭。

| 维度 | one-hot 编码 | Embedding 查表（本环节主角） |
|---|---|---|
| 表示 | 稀疏 0/1，长度 = 词表 `|V|` | 稠密实数，长度 = 隐藏维度 d（几百~几千） |
| 相似度 | **任意两词正交**（内积为 0、距离恒为 √2）——狗和汽车、猫和狗一样远，语义为零 | 语义近邻成立：猫狗近、猫车远（§2.1 距离演算） |
| 可学习 | 是编码方案不是参数：固定不变、学不动 | 可训练参数，随反向传播逐词更新（§2.3） |
| 输入含义 | 只在"说明自己是第几个词" | 承载整条训练史学出的语义坐标 |
| 规模代价 | `|V|`=130k 时一条向量 130k 维：存储、带宽、计算全爆炸 | 一条 4096 维：省约一个数量级，且维度可自由伸缩 |
| 现代用途 | 几乎不直接当词表示 | LLM 全系标配 |

**别被维度骗了：one-hot 其实没走远，只是"藏进了索引"。** 回到 §2.3 的改写 `x = e_i · W_E`：one-hot × 矩阵 = 取第 i 行，两者严格等价：

- **one-hot 视角**：输入是 `|V|` 维 0/1 向量，乘 W_E 得到 d 维；
- **查表视角**：输入是一个整数 id，直接取 W_E 第 i 行。

工程上**从不物化 one-hot**——130k 维向量、其中 129 999 个是 0，纯浪费带宽与显存；实际只传整数 id、按行取数。所以 [环节 01](./环节01-Tokenizer分词详解.md) 输出的 token id，本质就是 one-hot 的**压缩存储格式**。

> 记忆点：one-hot 是"教学正确"的表示，Embedding 是"工程正确"的实现，二者通过 `W_E[token_id]` 精确等价。one-hot 的死穴不是表达力（信息量足够），而是**没有相似度 + 维度爆炸**；词向量发展的本质，就是把 one-hot 的 `|V|` 维压缩成稠密 d 维、让相似性由语料训出来（§2.4 Word2Vec 那条线正是来填这个坑的）。

## 3. 方法与优缺点（工程视角）

| 方案 | 做法 | 优点 | 缺点 | 用在哪 |
|---|---|---|---|---|
| 随机初始化（random initialization）查表（主流） | Embedding 层随模型一起训练 | 端到端（end-to-end）、容量大、可学到任务相关词义 | 词表大 → 显存/参数占用（|V|×d） | GPT / LLaMA / Qwen 全系 |
| 静态预训练词向量（static word embeddings）初始化 | 拿 Word2Vec/GloVe 当起点 | 小模型或冷启动（cold start）略有帮助 | 静态词义与后续矛盾、收益被大模型淹没 | 基本淘汰 |
| 输出层权重共享（weight tying / tie embedding） | LM Head（language model head）复用输入查表矩阵 | 省一块大参数 | 输入与输出语义空间未必一致 | Llama 部分版本、小型模型 |

工程注记：表的大小 = 词表数 × 维度（130k × 4096 ≈ 5.3 亿参数）。它和输出层（output layer，即"猜词"的最后一步，见 [环节 08](./环节08-输出头与训练目标详解.md)）常共享同一张表，叫 weight tying（权重共享），能省约一半参数。

## 4. 零基础自测（能答对 = 真懂了）

1. 为什么不能把 token 的整数编号直接喂给模型？→ 编号的大小、加减、远近全是假的，不携带语义。
2. Embedding 表长什么样、谁教出来的？→ |V|×d 的一张表，编号查行；训练中靠"该近的近、该远的远"挪出来的，没人标答案。
3. 为什么"bank"不会只有一个意思？→ 入口向量 + 上下文注意力共同决定；一词多义靠语境精修。
4. Embedding 表真的是反向传播更新的吗？更新有什么特殊？→ 是，但靠"查表 = one-hot × W_E"保持可导；梯度只回传给被取中的行（scatter_add），没被取中的行本轮为 0。它没有自己的损失，方向由下游 next-token 任务反向决定；又因为单步只更新出现过的词，低频词几乎学不动。

## 5. 面试高频追问

1. Embedding 层参数量怎么算？→ |V| × d，130k×4096≈5.3 亿，是词表驱动的大头之一。
2. 为什么近年放弃 Word2Vec 初始化？→ 静态词义与端到端训练冲突，大规模下随机初始化收敛得更好。
3. weight tying 是什么、代价？→ 输出头共享输入矩阵省参数；代价是输入/输出向量被强制同一空间，未必最优。
4. 如果给模型加一个自定义 token，要动哪些参数？→ 词表 + Embedding 行（+ LM Head 若未共享），且需少量数据让模型"学会"它。
5. Embedding 向量要不要归一化（normalization）？→ 现代 LLM 一般不必（语义靠整条链路）；对比学习（contrastive learning）/检索模型（retrieval model）才常做归一化。
6. Embedding 层训练有什么特殊性？查表不可导为什么还能更新？→ ① 查表 = one-hot × W_E，`∂L/∂W_E` 只对被查行非零，本质是 scatter_add，仍随整体反向传播更新（见 §2.3）；② 无独立 loss，语义方向由下游 next-token 任务反向决定，与 Word2Vec"用上下文预测任务单独训出静态表"不同（§2.4）；③ 参数量大且多卡下梯度通信稠密 → 词表并行/分片、tie embedding 是常见工程手段（§2.3.3）；④ LoRA 等冻结 base 参数时不更新。
