# 环节 06 · DPO 家族与离线偏好优化（用一个数学技巧删掉奖励模型）

> RL 落到 LLM 的第二站：**DPO 把"先训奖励模型、再跑 PPO"三步压缩成一步监督学习**——本质是发现"奖励"可以由"策略"反解出来，于是不必再学 RM。这条路线在 2023 年之后成为**中小团队对齐的默认选项**，也是"调风格"的主力。

> 适合人群：需要"改行为、控风格"的工程实践者；被"DPO 和 PPO 到底差在哪"困扰过的人。

## 0. 一句话定位

**DPO = 用一个数学技巧，把"奖励模型 + PPO"这三步合并成"一次监督学习"。**

```
RLHF：  SFT → 训 RM → 用 RM 当环境跑 PPO      （3 步，4 个模型）
DPO ：  SFT → 直接吃偏好对做"分类"            （2 步，2 个模型）
SimPO： 直接吃偏好对（连 π_ref 都不要）        （2 步，1 个模型）
```

一句话记住它的数学核心：**在 RLHF 的假设下，奖励函数与最优策略之间存在闭式关系——所以奖励不用"学"，可以"算"。**

---

## 1. 推导：把奖励反解出来（DPO 的全部技术要点）

**第一步：写出 RLHF 目标的闭式最优解**（→ [环节 05](./环节05-偏好对齐与RLHF详解.md) §7）：

```
π*(y|x) = (1 / Z(x)) · π_ref(y|x) · exp( r(x,y) / β )        ,  Z(x) = Σ_y π_ref(y|x)·exp(r(x,y)/β)
```

**第二步：反解奖励**：

```
r(x, y) = β · log( π*(y|x) / π_ref(y|x) )  +  β · log Z(x)
```

**第三步：代入 Bradley-Terry**（偏好概率只依赖**奖励差**）：

```
P(y_w ≻ y_l) = σ( r(x,y_w) − r(x,y_l) )

r(x,y_w) − r(x,y_l)
  = β·log(π*(y_w)/π_ref(y_w)) + β·log Z(x)
  − β·log(π*(y_l)/π_ref(y_l)) − β·log Z(x)
                                          ↑_______________↑
                                          两项完全相同 → 相减抵消！
```

> **这就是 DPO 最漂亮的一步**：`Z(x)` 只依赖 prompt、不依赖回答，在**配对相减**时自动消失。于是"算不出来的配分函数"根本不是问题——**偏好概率从来不关心奖励的绝对值，只关心差**。

**第四步：把 `π*` 换成待训练的 `π_θ`，得到 DPO 损失**：

```
L_DPO(θ) = − E_{(x, y_w, y_l)} [ log σ( Δ_θ ) ]

Δ_θ = β · [ log(π_θ(y_w|x)/π_ref(y_w|x))  −  log(π_θ(y_l|x)/π_ref(y_l|x)) ]
        └──────── 被选中回答的"对数概率比" ────────┘  └──────── 被拒回答的"对数概率比" ────────┘
```

**读法**：本质是**标准交叉熵作用在了一个 logit 上**，而这个 logit 就是"chosen 的概率比"减"rejected 的概率比"。

**最低配置只要三样东西**：

1. `π_ref`：SFT 模型的**冻结拷贝**（全程不动）；
2. `π_θ`：从**同一个 SFT 模型**初始化的可训练策略；
3. 数据集：`(prompt, chosen, rejected)` 三元组。

**没有奖励模型、没有 rollout、没有 critic、没有 PPO 循环**——训练循环看起来和普通微调几乎一样。

---

## 2. 梯度：DPO 损失里藏着什么

对 `Δ_θ` 求梯度，得到两项：

```
∇_θ L_DPO = − β · σ(−Δ_θ) · [ ∇_θ log π_θ(y_w|x) − ∇_θ log π_θ(y_l|x) ]
              └────┬────┘     └────────── 提高 chosen ──────────┘ └── 压低 rejected ──┘
        自动权重：样本越"已分对"，这一项越小
```

**两个因子的分工，值得逐字记住**：

| 因子 | 作用 | 来源 |
|---|---|---|
| `σ(−Δ_θ)` | **自动降权"已经分得很开"的偏好对**——训练自动聚焦边界难例 | **直接继承自 Bradley-Terry 损失**（→ [环节 05](./环节05-偏好对齐与RLHF详解.md) §3.2），不是 DPO 额外设计的 |
| `∇log π_θ(y_w) − ∇log π_θ(y_l)` | 主体方向：**提高 chosen 的概率、压低 rejected 的概率** | 就是普通的策略梯度方向 |

**"隐式奖励"视角**（很多面试会问）：

```
DPO 训练中，`r̂(x,y) = β · log( π_θ(y|x) / π_ref(y|x) )` 扮演了奖励模型的角色
→ 它从不被显式训练，但训练结束时它已经是一个可用的奖励函数
→ 所以 DPO 又被称为"隐式奖励模型（implicit reward model）"
```

**一个著名反直觉现象（likelihood displacement）**：DPO 不保证 `log π_θ(y_w)` **上升**——只要能**让 `log π_θ(y_l)` 下降得更多**，损失就在下降。所以实践中会看到"chosen 的概率也一起下降"。这提醒我们：**DPO 优化的是相对差，不是绝对概率**；监控时要同时看 chosen 与 rejected 的 logprob。

---

## 3. β 的语义：它是"隐式奖励的放大倍数"

DPO 的 `β` 与 RLHF 的 `β`（KL 系数）**数学上是同一个东西**，都控制"允许偏离 `π_ref` 多远"，但作用方式不同：

```
Δ = β · (log 比值差)

β 大  → 同样的 log 比值差产生更大的 Δ → 更早进入饱和区 → 更新更保守（贴近 π_ref）
β 小  → 隐式奖励的尺度被压缩 → 需要"拉得很开"才有梯度 → 更新更激进
```

**实测（代码见 §8）**：

| β | log 比值差 `g` | `Δ = βg` | `loss` | `σ(−Δ)`（梯度权重） |
|---|---|---|---|---|
| 0.01 | 1.0 | 0.010 | 0.6882 | 0.498 |
| 0.01 | 3.0 | 0.030 | 0.6783 | 0.493 |
| **0.1** | 1.0 | 0.100 | 0.6444 | 0.475 |
| **0.1** | 3.0 | 0.300 | 0.5544 | 0.426 |
| 0.5 | 1.0 | 0.500 | 0.4741 | 0.378 |
| 0.5 | 3.0 | 1.500 | 0.2014 | 0.182 |

**读法**：`β = 0.01` 时，即使 log 比值差已经拉到 3.0，`Δ` 也只有 0.03 → 损失几乎不动、**梯度权重一直是 0.49**（永不饱和，一直猛推）；`β = 0.5` 时 `Δ=1.5` 就已经明显饱和（权重掉到 0.18）。

> **实践取值：多数人落在 `β ∈ [0.1, 0.5]`**。太小 → 学不动或策略漂走（隐式奖励尺度太小，等效于几乎没有正则）；太大 → 更新被过早饱和压住、贴合不动。

## 4. 优缺点：为什么它稳，以及它稳的代价

| 优点 | 缺点 |
|---|---|
| **稳**（本质是监督学习，"看 loss 往下走"就行） | **不探索**，被偏好数据质量上界框死 |
| 显存省（2 个模型）、**算力常为 PPO 的 1/2~1/4** | 上限通常略低于精心调过的在线 RL |
| 超参极少（基本只有 `β` 和 lr） | 对**推理能力**提升有限（不能生成数据外的新解法） |
| 复现性好，**中小团队可做** | 需要成对偏好数据（KTO/ORPO 才部分解决这点） |

**与 PPO 的实证对比**（ICML 2024, *Is DPO Superior to PPO for LLM Alignment?*）：

```
数据质量一致时：PPO 在数学任务上仍比 DPO 高约 2.5%，通用 benchmark 高约 1.2%
```

**结论：PPO 没死，只是不再是简单场景的默认选项。**
**判据很简单**：任务是"改行为/控风格"→ DPO；任务是"冲能力上限"→ 在线 RL（→ [环节 07](./环节07-GRPO与RLVR详解.md)）。

## 5. 在线 vs 离线：选型的第一分水岭

| | **在线 RL**（PPO / GRPO / DAPO） | **离线偏好优化**（DPO / SimPO / KTO / ORPO） |
|---|---|---|
| 数据 | **训练中自己采样**新回答，持续探索 | **静态偏好数据集**，跑完就完 |
| 能超越数据吗 | ✅ 能超出训练数据分布 | ❌ 被偏好对的质量上界框住 |
| 稳定性 | 差（多个旋钮，易悄悄劣化） | 好（本质是监督学习） |
| 成本 | 高（rollout 生成 + 多模型驻留） | 低（算力常为 PPO 的 1/2~1/4） |
| 角色 | 冲**能力上限**（数学/代码/推理） | 调**风格与价值观**（语气/格式/拒答） |

> 记忆点：**要"探索出新能力" → 在线 RL；要"改行为、控风格" → 离线偏好优化**。这一条能覆盖 90% 的选型问题。
> 中间地带：**迭代式 DPO**（§7）——它一边是离线算法，一边又通过"重新采样数据"把 on-policy 性拿回来了。

## 6. 家族：DPO 之后的五个改进（按"删掉了什么"排列）

| 方法 | 改动 | 删掉了什么 | 备注 |
|---|---|---|---|
| **DPO** | — | 奖励模型 | 需 `π_ref` + 成对偏好数据 |
| **SimPO** | 用**回答的平均对数概率**（长度归一化）当隐式奖励 | **`π_ref`** | AlpacaEval 2 比 DPO **+6.4**、Arena-Hard **+7.5** |
| **KTO** | 用**点赞/点踩式二元反馈**替代成对比较（借用前景理论的效用函数） | `π_ref` + **成对数据** | 生产价值大：二元信号**廉价且海量** |
| **ORPO** | 用 **odds ratio** 把 SFT 与偏好对齐**合并成单一目标** | **独立 SFT 阶段** + `π_ref` | 减少训练时间，消除 SFT 与偏好调优间的分布漂移 |
| **IPO / cDPO** | 加正则 / 处理偏好标注噪声（label smoothing） | — | 研究向：更抗过拟合与噪声 |

> **记忆点：KTO 的商业含义 > 技术含义**——真实产品里能拿到的是点赞/点踩/重新生成，**不是精心标注的 A/B 对**。数据形态决定算法，而不是反过来。
>
> **SimPO 的取舍要注意**：去掉 `π_ref` 省了显存，但也丢掉了"别偏离太远"的锚 → 需要更强的长度正则与更谨慎的训练步数控制。

## 7. 迭代式 DPO：把"离线"拉回"近在线"

**实现要点**（生产上比"选哪个损失函数"更重要）：

```
第 1 轮：用 SFT 模型采样 → 人工/模型标注偏好对 → DPO 训练 → 得到 π₁
第 2 轮：用 π₁ 重新采样偏好对 → 再训一轮 → 得到 π₂
第 3 轮：……
```

**为什么必须迭代**：一次性 DPO 的上限 = 那一份静态偏好对的质量上界；而**偏好对的分布是旧策略的输出**，策略前移后这批数据就"不对味"了（这是 off-policy 的通病，本质与 RM 的分布漂移同源 → [环节 05](./环节05-偏好对齐与RLHF详解.md) §3.3）。

> 效果上，**迭代式 DPO 远好于一次性跑完**。而且迭代次数一多，它和在线 RL 的边界就模糊了——**区别只剩"采样后是拿去做偏好标注，还是直接拿去打分"**。

**甜点区（生产定位）**：

| 用 DPO 家族调 | 不要用 DPO 家族调 |
|---|---|
| 拒答行为、安全边界 | 数学/代码/逻辑推理能力 |
| 语气、品牌口吻、格式遵循 | 需要"想出数据外新解法"的任务 |
| 闲聊有用性、结构化输出 | 长程 Agent 的多步决策 |

## 8. 数值走查：DPO 损失、梯度权重与 β（真实计算）

```python
import math
sig = lambda x: 1 / (1 + math.exp(-x))

# Δ = β·(log 比值差 g)；loss = −log σ(Δ)；梯度权重 = σ(−Δ)
for beta in (0.01, 0.1, 0.5):
    for g in (-1.0, 0.0, 1.0, 3.0):
        d = beta * g
        print(f"β={beta:<5} g={g:>5.1f}  Δ={d:>7.3f}  loss={-math.log(sig(d)):.4f}"
              f"  权重σ(−Δ)={sig(-d):.3f}  隐式奖励差β·g={beta * g:>6.3f}")
```

**输出（节选，完整表见 §3）**：

```
β=0.01  g= 3.0   Δ=  0.030  loss=0.6783  权重σ(−Δ)=0.493  隐式奖励差=0.030   ← 永不饱和，一直猛推
β=0.1   g= 3.0   Δ=  0.300  loss=0.5544  权重σ(−Δ)=0.426  隐式奖励差=0.300
β=0.5   g= 3.0   Δ=  1.500  loss=0.2014  权重σ(−Δ)=0.182  隐式奖励差=1.500   ← 已饱和，更新变慢
```

**再验证一次"`Z(x)` 真的消掉"**（这是 DPO 的全部要害）：

```python
import math
# 随便取两个不同的 Z(x)，算 Δ，看结果是否相同
beta, lw, ll = 0.3, 1.2, 0.4          # log(π_θ/π_ref) 分别为 1.2 与 0.4
for Z in (1.0, 7.5, 1e6):
    r_w = beta * lw + beta * math.log(Z)
    r_l = beta * ll + beta * math.log(Z)
    print(f"Z(x)={Z:>8}  r_w−r_l = {r_w - r_l:.6f}")
# Z(x)=1.0     → 0.240000
# Z(x)=7.5     → 0.240000
# Z(x)=1000000 → 0.240000      ← 奖励差与 Z(x) 完全无关：配分函数被消掉了
```

> **这两段代码合起来就是 DPO 的完整证明**：配分函数只在"绝对奖励"里出现，而偏好概率只看"奖励差"——**所以一个算不出来的量，在训练目标里根本不需要出现**。

## 9. 坑清单

1. **把 DPO 当万能**：它不探索。数学/代码这类需要"想出数据外解法"的任务，提升有限（实证差约 2.5%）→ 该上在线 RL。
2. **不做迭代**：一次性 DPO 被静态数据上界框死。**至少做一轮迭代式 DPO**。
3. **照抄 β**：DPO 的 0.1~0.5 与 GRPO 的 0.001~0.04 差 1~2 个数量级。
4. **只用"长度不同的 pairs"**：如果偏好对里 chosen 只是"更长"，DPO 会学出"输出越长越好"（长度偏置的 DPO 版本）。**成对长度匹配**是必要的数据清洗。
5. **只看 loss 不看 chosen/rejected 的 logprob**：损失下降不代表 chosen 概率上升（likelihood displacement）——**同时监控两条曲线**，否则可能训出"什么都不太想说"的模型。
6. **`π_ref` 与 `π_θ` 初始化不一致**：`π_ref` 必须是**同一个 SFT 模型的冻结拷贝**；用别的模型当 `π_ref` 会让 `Δ` 的基线直接偏掉。
7. **拿 DPO 去灌知识**：DPO 调的是**行为偏好**，知识要走 RAG / 继续预训练。
8. **忘了 SFT 阶段**：DPO 起点必须是"已经会听话"的 SFT 模型；从基座直接做 DPO，`π_ref` 本身就是个不会说话的模型，偏好对齐无从谈起（ORPO 是把这两步合并，不是省略 SFT）。

## 10. 面试高频追问

1. **DPO 为什么不需要奖励模型？** → RLHF 最优解下奖励与策略有闭式关系 `r = β·log(π*/π_ref) + β·log Z(x)`；把 `r` 代入 Bradley-Terry 损失后，**配对相减把 `Z(x)` 消掉**，直接得到只依赖偏好对与两个策略的监督损失。
2. **`Z(x)` 为什么能消掉？** → 它只依赖 prompt、是"所有回答的加权和"，在 `r(y_w) − r(y_l)` 里作为公共项被减掉。**偏好概率只关心奖励差**——这是 DPO 成立的关键。
3. **DPO 的损失函数长什么样？怎么读？** → `L = −log σ(β·[log(π_θ(y_w)/π_ref(y_w)) − log(π_θ(y_l)/π_ref(y_l))])`；本质是标准交叉熵作用在"两个对数概率比的差"上。
4. **DPO 的梯度有什么特点？** → 两项相乘：`σ(−Δ)`（自动降权已分对的样本，继承自 BT 的饱和性质）+ `∇log π(y_w) − ∇log π(y_l)`（提高 chosen、压低 rejected）。
5. **DPO 与 PPO/GRPO 的本质区别？** → **离线 vs 在线**。DPO 吃静态偏好对、不探索、被数据质量框住；PPO/GRPO 训练中自己采样、能超越训练数据。→ "调风格用 DPO，冲能力用 GRPO"。
6. **β 在 DPO 里是什么？** → 隐式奖励的放大倍数（与 RLHF 的 KL 系数是同一个 β）。大 → 更保守（贴近 `π_ref`）；小 → 更激进。实践 0.1~0.5。
7. **DPO 的失效场景？** → ①需要探索新能力的任务（数学/代码）；②偏好对只差长度（学出长度偏置）；③`π_ref` 与 `π_θ` 起点不一致；④一次性训练不迭代。
8. **SimPO / KTO / ORPO 各自删掉了什么？** → SimPO 删 `π_ref`（用长度归一化的平均对数概率当隐式奖励）；KTO 删成对数据（用点赞/点踩二元反馈）；ORPO 删独立 SFT 阶段（用 odds ratio 合并）。
9. **likelihood displacement 是什么？** → DPO 只优化"相对差"，可以靠"把 rejected 压得更低"降低损失，于是 chosen 的绝对概率也可能下降。所以必须同时监控两侧 logprob。
