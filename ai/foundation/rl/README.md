# RL · 强化学习与模型对齐

> **定位**：SFT（supervised fine-tuning，监督微调）之后「**为什么要 RL、怎么 RL**」的完整展开。
> **一句话**：**预训练给"基础智力"，SFT 给"格式"，RL 给"行为"与"超出训练数据上限的能力"。**
> **口诀**：「偏好 / 对错 / 打分不可微，要拿分数去调模型行为」→ 归这。
> 代表：InstructGPT（RLHF）、ChatGPT、DeepSeek-R1（GRPO + RLVR）、各家推理模型与工具型 Agent。

配套 MVP：[mvp.py](./mvp.py)（值迭代 → Q-learning → REINFORCE，纯标准库，无 numpy / torch）。
环节主线（01–08 关卡地图）：见 [环节00-总揽与环节导航.md](./环节00-总揽与环节导航.md)。本页讲**RL 这门技术本身**（是什么 / 方法全景 / 怎么选），那边讲**一条主线 + 两大阶段怎么串**。

> 版本口径（2026-09）：**当前主线是 GRPO + RLVR**，RLHF/PPO 从主战场退化为"风格 / 拒答"的薄层。快照型结论（工具链、开源栈）引用前请回官网核一遍。

## 一、技术讲解

### 1.1 RL 与监督学习的分水岭

监督学习有 `(x, y)` 成对答案，拟合即可；**RL 只有"分数"**——没有标准答案，只有一个标量（甚至延迟到整段结束才给）：

| | 监督学习（含 SFT） | 强化学习 |
|---|---|---|
| 数据 | 人工标注的 `(x, y)` | **自己采样出来的轨迹** |
| 反馈 | 正确答案（可逐 token 算 loss） | **一个分数**（不可微、常延迟） |
| 目标 | 拟合数据分布（**上限 = 数据质量**） | 最大化累计奖励（**可超出数据**） |
| 分布 | 固定 | 随策略变化（→ 不稳定） |

**为什么 SFT 之后还要 RL**（三个根本限制，[环节 05](./环节05-偏好对齐与RLHF详解.md) §1）：

1. **只能模仿，不能超越**：SFT 的上限就是标注数据的质量，学不出数据里没有的解法；
2. **只能优化可微目标**："哪种回答更受喜欢""答案对不对"这类信号天生不可微，没法写进交叉熵；
3. **token 级目标 ≠ 序列级质量**：逐 token 拟合会积累暴露偏差（exposure bias），整段质量没人管。

### 1.2 两大阶段：从 MDP 到 Agentic RL

- **通用原理（环节 01–04）**：把"试错"写成 MDP → 值方法（先估分再贪心）→ 策略梯度（直接调概率）→ 信赖域 / PPO（别改太猛）。
- **LLM 对齐工程（环节 05–08）**：奖励从人类偏好来（RLHF）→ 删掉奖励模型（DPO）→ 删掉 critic、奖励换验证器（GRPO + RLVR）→ 环境取代数据集（Agentic RL）。

两阶段完整串讲与演进因果链见 [环节00](./环节00-总揽与环节导航.md) §0。

### 1.3 奖励从哪来 —— 这才是路线分水岭

同一个 RL 框架，**奖励来源不同 → 方法与工具链完全不同**：

| 奖励来源 | 怎么来 | 对应方法 | 适合任务 |
|---|---|---|---|
| **人类偏好** | 标注偏好对 → 训奖励模型（RM） | RLHF / DPO / SimPO / KTO | 风格、语气、格式、拒答（**不可验证**的"软"质量） |
| **验证器** | 单测、数学校验、正则、schema | RLVR + GRPO / DAPO | 数学、代码、SQL、结构化输出（**可验证**） |
| **环境反馈** | 工具调用结果、任务完成度 | Agentic RL（verl / Agent-Lightning） | 多步工具型 Agent、多智能体 |
| **LLM-as-Judge** | 强模型按 rubric 打分 | 与前几种组合 | 开放任务（有 judge 偏见与校准风险） |

> 记忆点：**可验证 → RLVR；不可验证但可比较 → 偏好优化；多步 → Agentic RL。** 这一条覆盖 90% 的选型。

## 二、功能作用

- **突破数据上限**：SFT 学不到数据外的解法；RL 通过自己探索，能"想出"新解题路径（R1 的纯 RL 涌现是最强证据）。
- **对齐行为与价值观**：让基座模型变得礼貌、稳定遵循指令、学会拒答与安全边界。
- **把不可微目标变成可优化目标**：偏好、对错、通过率都能当奖励回传梯度。
- **推推理能力**：可验证奖励 + 长思维链，是目前推理模型能力的主要来源。
- **训工具型 / 多步 Agent**：把一整条工具调用轨迹的好坏变成训练信号。
- **代价可量化**：RL 是后训练里最贵的一环——贵在 **rollout 生成 + 多模型同驻**，不在反向传播（[总表 §5.4](./RL选型与工程落地总表.md)）。

## 三、应用场景

| 该上 RL | 不该上 RL |
|---|---|
| 数学 / 代码 / 逻辑：有验证器，奖励客观 | **知识注入**：走 [RAG](../../knowledge/rag/) / 继续预训练 |
| 风格 / 拒答 / 格式：有明确偏好信号 | **临时指令**：走 prompt engineering |
| 多步工具 Agent：环境能自动判任务成败 | **无奖励信号可定义**的任务（先把奖励想清楚再谈算法） |
| 推理模型训练（长 CoT） | 只是想让输出变短 / 改口吻（DPO 就够了，不用在线 RL） |

> **2026 的现实分工**：**GRPO + RLVR 主战"能力上限"（数学 / 代码 / 推理），DPO 家族主战"风格与安全"**；两者不是替代，是分工。

## 四、方法怎么选（心智模型）

**第一分水岭：在线 or 离线**

| | 在线 RL（PPO / GRPO / DAPO） | 离线偏好优化（DPO / SimPO / KTO / ORPO） |
|---|---|---|
| 数据 | 训练中**自己采样**新回答 | **静态偏好数据集**，跑完就完 |
| 能超出数据吗 | ✅ 能 | ❌ 被偏好对质量上界框住 |
| 稳定性 | 差（多旋钮，易悄悄劣化） | 好（本质是监督学习） |
| 成本 | 高（rollout + 多模型驻留） | 低（常为 PPO 的 1/2~1/4） |
| 角色 | 冲**能力上限** | 调**风格与价值观** |

**第二分水岭：需要什么部件**（依赖项少 = 便宜、稳）

| 方法 | critic | reward model | reference | 成对偏好 | 在线 | 本质 |
|---|---|---|---|---|---|---|
| **PPO + RLHF** | ✅ | ✅ | ✅ | ➖ | ✅ | 完整 RL 管线（4 模型） |
| **GRPO** | ❌ | 验证器 / RM | ✅ | ➖ | ✅ | 组基线 RL（3 模型） |
| **DAPO** | ❌ | 验证器 / RM | ✅ | ➖ | ✅ | GRPO + 长 CoT 补丁 |
| **DPO** | ❌ | ❌ | ✅ | ✅ | ❌ | 隐式奖励的监督学习（2 模型） |
| **SimPO / KTO / ORPO** | ❌ | ❌ | ❌（SimPO/KTO/ORPO） | 视方法 | ❌ | 更低成本的变体（1~2 模型） |

**选型速查**：

- 加拒答 / 安全行为 / 改风格 → **DPO**（偏好对是天然格式）。
- 推数学 / 代码 / 推理 → **GRPO + RLVR + 结果奖励**（长 CoT 加 [DAPO 补丁](./环节07-GRPO与RLVR详解.md)）。
- 只有点赞 / 点踩（二元反馈）→ **KTO**。
- 端到端训工具型 Agent → 在轨迹上跑 GRPO（verl / Agent-Lightning / Agent-R1）。
- 想一步到位少跑一个阶段 → **ORPO**（SFT + 对齐合并）。

> 完整版（含成本与显存、奖励病、稳定性旋钮、故障排查顺序）见 [RL选型与工程落地总表.md](./RL选型与工程落地总表.md)。

## 六、落地建议

1. **先问"奖励怎么来"，再问"用哪个算法"**：奖励定义不清楚，任何算法都白跑（奖励设计决定一切，[总表 §4](./RL选型与工程落地总表.md)）。
2. **顺序不可颠倒**：SFT →（偏好优化）→ RL。跳过 SFT 直接 RL，探索空间里全是垃圾。
3. **能离线就离线**：只调风格 / 拒答就用 DPO，别为了"先进"上在线 RL——稳定性和成本差一个数量级。
4. **β / clip ε / 温度三个旋钮别照抄**：GRPO、RLHF、DPO 的 β 量级差 1~2 个数量级；温度太低会导致组内全同、优势恒为 0（**整批 rollout 白采**）。
5. **盯熵、优势标准差、KL，而不是只盯回报**：策略梯度的故障在回报曲线上常常"是平的"（[总表 §5.3](./RL选型与工程落地总表.md) 排查顺序）。
6. **长 CoT 必须用 token 级损失、必开 DAPO 补丁**：序列级归一化会把长回答的梯度稀释（实测 30× 差距）。
7. **验收要独立**：验证器通过率涨 ≠ 真实能力涨（策略会钻验证器空子），必须配独立评测与对抗性验收。
