## 0. 一句话定位

**RL 的全部工程问题可以压缩成三句**：

```
选型：  要"探索出新能力" → 在线 RL（GRPO/PPO）；要"改行为、控风格" → 离线偏好优化（DPO）
成本：  贵不在反向传播，而在【rollout 生成 + 多模型同驻】
调试：  回报曲线是平的 → 先看熵、优势、KL 三个量，而不是先调 lr
```

> **演进史的骨架，就是不断把昂贵部件删掉的过程**（每一代都对应本专题的一篇环节）：

| 代际 | 方法 | 删掉了什么 | 关键节点 | 详解 |
|---|---|---|---|---|
| — | TRPO → **PPO** | 二阶信赖域 → 一阶裁剪 | 2017, Schulman | [环节 04](./环节04-信赖域与PPO详解.md) |
| 1 | **PPO + RLHF** | （基线：4 个模型同时在显存里） | 2022 InstructGPT → ChatGPT | [环节 05](./环节05-偏好对齐与RLHF详解.md) |
| 2 | **DPO** | **删掉奖励模型** | 2023, arXiv 2305.18290 | [环节 06](./环节06-DPO家族与离线偏好优化详解.md) |
| 3 | **GRPO** | **删掉 critic 网络** | 2024, arXiv 2402.03300；2025 被 R1 推上台前 | [环节 07](./环节07-GRPO与RLVR详解.md) |
| 4 | **RLVR** | **删掉"人类偏好"与步骤标注** | 2024–2026，R1 证明可行 | [环节 07](./环节07-GRPO与RLVR详解.md) §6 |
| 5 | **Agentic RL** | 删掉"静态数据集"（改用环境） | 2025–2026，verl / Agent-Lightning | [环节 08](./环节08-AgenticRL与信用分配详解.md) |

```
模型数演进（显存账的直观表达）：
PPO+RLHF:  Actor + Critic + RewardModel + Reference     （4 模型）
GRPO:      Actor + RewardModel/Verifier + Reference     （3 模型，无 critic）
DPO:       Actor + Reference                            （2 模型，无 RM）
SimPO:     Actor                                        （1 模型）
```

## 1. 三阶段后训练流水线（顺序不可颠倒）

| 阶段 | 解决什么 | 数据形态 | 代表方法 |
|---|---|---|---|
| **SFT** | 格式：指令跟随、结构化输出、对话风格 | 百万~千万级精选样本 | — |
| **偏好优化** | 价值观与偏好对齐 | 偏好对 / 二元反馈 | DPO → SimPO / KTO / ORPO |
| **强化学习** | **突破训练数据上限**、产生推理能力 | 可验证奖励 / 环境反馈 | GRPO / DAPO |

> **核心判断**：预训练只提供"基础智力"，**后训练（post-training）现在贡献了模型"可用能力"的大部分**。
> **为什么不能跳步**：跳过 SFT 直接 RL 不成立——模型还没有基本格式能力，RL 的探索空间里全是垃圾，无从探索。跳过偏好优化直接 RL，可以（R1 就这么干），但**风格/安全性要另找地方补**。

## 2. 依赖项拆解（选型第一张表）

| 方法 | 需 critic | 需 reward model | 需 reference | 需成对偏好数据 | 在线 RL | 本质 | 详细 |
|---|---|---|---|---|---|---|---|
| **PPO + RLHF** | ✅ | ✅ | 通常 ✅ | ➖ | ✅ | 完整 RL 管线 | [环节 04](./环节04-信赖域与PPO详解.md) / [05](./环节05-偏好对齐与RLHF详解.md) |
| **GRPO** | ❌ | 验证器或 RM | ✅（KL 约束） | ➖ | ✅ | 组基线 RL | [环节 07](./环节07-GRPO与RLVR详解.md) |
| **DAPO** | ❌ | 验证器或 RM | ✅ | ➖ | ✅ | GRPO + 长 CoT 补丁 | [环节 07](./环节07-GRPO与RLVR详解.md) §5 |
| **DPO** | ❌ | ❌ | ✅ | ✅ | ❌ | 隐式奖励的监督学习 | [环节 06](./环节06-DPO家族与离线偏好优化详解.md) |
| **SimPO** | ❌ | ❌ | ❌ | ✅ | ❌ | 长度归一化的 DPO | [环节 06](./环节06-DPO家族与离线偏好优化详解.md) §6 |
| **KTO** | ❌ | ❌ | ❌ | ❌（用二元反馈） | ❌ | 二元反馈版对齐 | [环节 06](./环节06-DPO家族与离线偏好优化详解.md) §6 |
| **ORPO** | ❌ | ❌ | ❌ | ✅ | ❌ | SFT + 对齐合并 | [环节 06](./环节06-DPO家族与离线偏好优化详解.md) §6 |

**在线 vs 离线——选型的第一分水岭**：

| | 在线 RL（PPO / GRPO / DAPO） | 离线偏好优化（DPO / SimPO / KTO / ORPO） |
|---|---|---|
| 数据 | **训练中自己采样**新回答，持续探索 | **静态偏好数据集**，跑完就完 |
| 能超越数据吗 | ✅ 能超出训练数据分布 | ❌ 被偏好对的质量上界框住 |
| 稳定性 | 差（多个旋钮，易悄悄劣化） | 好（本质是监督学习） |
| 成本 | 高（rollout 生成 + 多模型驻留） | 低（算力常为 PPO 的 1/2~1/4） |
| 角色 | 冲**能力上限**（数学/代码/推理） | 调**风格与价值观**（语气/格式/拒答） |

> 记忆点：**要"探索出新能力" → 在线 RL；要"改行为、控风格" → 离线偏好优化**。这一条基本能覆盖 90% 的选型问题。

## 3. 成本、稳定性与选型速查

### 3.1 成本与稳定性

| 算法 | 模型数 | 显存特征 | 稳定性 | 场景 |
|---|---|---|---|---|
| **PPO + RLHF** | **4** | 4 模型同驻；70B 策略 ≈ 要养出 280B 参数量的开销 | ⚠️ 脆弱（多旋钮，劣化不显形） | 有强 RM + 大 GPU 预算 |
| **GRPO** | **3** | 比 PPO **省约一半**（7B：8×H100 可跑 vs PPO 要 16×H100） | 中等（优势稳，但有组退化/KL 坑） | 数学/代码/推理，可验证奖励 |
| **DPO** | **2** | 算力常为 PPO 的 **1/2~1/4** | ✅ 高（就是监督学习） | 风格/拒答/格式，中小团队 |
| **SimPO / KTO / ORPO** | **1~2** | 更低 | ✅ 高 | 资源受限、二元反馈场景 |

### 3.2 选型速查

| 目标 | 推荐 |
|---|---|
| 让基座礼貌、稳定遵循指令 | SFT → **DPO** |
| 加拒答 / 安全行为 | **DPO**（偏好对是天然格式） |
| 推数学 / 代码 / 逻辑推理能力 | **GRPO + RLVR + 结果奖励**（长 CoT 加 DAPO 补丁） |
| 只有点赞/点踩信号 | **KTO** |
| 端到端训工具型 Agent | 在轨迹上跑 GRPO：**verl / Agent-Lightning / Agent-R1** |
| 用不起 critic 但想要 PPO 式探索 | **GRPO** |
| 真有高质量 RM + 充足 GPU | **PPO** |
| 想一步到位、少跑一个阶段 | **ORPO**（SFT + 对齐合并） |
| **知识类需求** | **都不上 RL**——走 RAG / 继续预训练 |
| **临时指令类需求** | **都不上 RL**——走 Prompt |

## 4. 奖励设计决定一切

### 4.1 四类信号来源

| 信号类型 | 怎么来 | 优点 | 风险 |
|---|---|---|---|
| **规则/验证器** | 单测、数学校验、正则、schema 校验 | 便宜、客观、可无限扩展 | 覆盖窄、可被钻空子 |
| **奖励模型（RM）** | 人类偏好对训练 | 覆盖广、能抓"软"质量 | 谄媚、长度偏置、随策略漂移失效 |
| **LLM-as-Judge** | 强模型按 rubric 打分 | 覆盖开放任务 | judge 偏见、校准难题 |
| **人类偏好** | 标注 | 最贴近真实 | 最贵、最慢、一致性差 |

### 4.2 四类典型奖励病（都会真实发生）

| 病 | 机制 | 对策 |
|---|---|---|
| **奖励黑客（reward hacking）** | 策略找信号的每一处弱点（"长答案分高"就无限拉长、"出现 Markdown 标题分高"就狂加标题） | 多信号交叉（规则 + RM + judge）、长度与格式正则化、对抗性验收 |
| **长度偏置** | RM 偏爱长回答 → 输出越来越长 | 长度惩罚 / 长度归一化 / 成对长度匹配 |
| **谄媚（sycophancy）** | 偏好数据由人类标 → 人类喜欢被认同 → 模型学会迎合 | 对抗性样本、多标注者交叉、独立 rubric |
| **分布漂移** | RM 在**旧策略**输出上训练，策略前移后 RM 失准——**而 loss 曲线上看不出来** | 定期用新策略数据重训 RM，或直接改用验证器 |

> **最阴险的是分布漂移**：RM 的 loss 平稳、PPO 的回报还在涨，但模型实际在钻 RM 的旧漏洞。这是"训练看起来正常但模型变差"的头号原因。

## 5. 上线要盯的旋钮与故障

### 5.1 稳定性旋钮

| 旋钮 | 典型值 | 调错的症状 |
|---|---|---|
| **KL 系数 β** | RLHF **0.01~0.1**；GRPO **0.001~0.04**；DPO **0.1~0.5** | 太小 → 语言崩坏 / 奖励黑客；太大 → 学不动 |
| **clip ε** | 0.1~0.2（DAPO 用非对称 `ε_low=0.2, ε_high=0.28`） | 太大 → 策略突变；太小 → 学不动 / 熵坍缩 |
| **组大小 G**（GRPO） | 16~32（范围 8~64） | 太小 → 优势噪声大；太大 → rollout 成本线性涨 |
| **温度 / top-p**（采样） | 略高以保探索 | 太低 → 组内全同 → **优势恒为 0（整批白采）** |
| **rollout batch** | 越大越稳 | 太小 → 梯度噪声大 |
| **lr** | 比 SFT 小 1~2 个数量级 | 太大 → 策略崩溃 |
| **γ / λ**（GAE） | γ = 1.0（LLM），λ = 0.95 | 见 [环节 03](./环节03-策略梯度与Actor-Critic详解.md) §7 |

> ⚠️ **三家的 β 量级差 1~2 个数量级，千万不要照抄**——这是最高频的事故来源。

### 5.2 三个高频故障

| 故障 | 现象 | 机制 | 对策 |
|---|---|---|---|
| **熵坍缩（entropy collapse）** | 熵持续下降、回报曲线变平 | 策略越来越确定 → 不再探索 → 收敛到平庸解 | DAPO 的 **Clip-Higher**（→ [环节 07](./环节07-GRPO与RLVR详解.md) §5.1） |
| **全对/全错组** | 该批梯度几乎为 0 | GRPO 组内 `std=0` → 优势爆炸或归零 | 分母加 `ε`、**Dynamic Sampling** 过滤 |
| **KL 崩塌 / 语言退化** | 输出重复、格式堆砌、中英混杂 | β 太小 / 跑得太久 | 提高 β、开 KL 早停、加熵奖励 |

### 5.3 出问题的排查顺序（照这个顺序走，别先调 lr）

```
① 熵 / 优势标准差 / KL        → 判断"是不是根本没在学"
② clipfrac（ρ 被截断的比例）   → 判断"是不是步子太大"（长期 >20% 就该降 ε 或 n_epochs）
③ 奖励分布与长度分布           → 判断"是不是奖励信号本身有问题"
④ critic 的 value loss        → 判断"优势估计是不是在漂"（仅 PPO）
⑤ 采样温度与组内多样性         → 判断"是不是优势恒为 0"
```

### 5.4 显存账与工具链

**RL 为什么比 SFT 贵得多**：

```
RL 显存 =  策略（训练版：权重 + 梯度 + 优化器状态）
        + 参考模型（冻结，仅前向）
        + 奖励模型 / 验证器（前向 + 可能还要独立推理服务）
        + critic（仅 PPO）
        + rollout 的 KV Cache（G 条回答同时生成，长 CoT 下极占显存）
        + 训练侧激活
```

> **关键**：rollout 阶段是"**推理负载**"、训练阶段是"**训练负载**"，**两套资源峰值都要扛**。成本大头在**生成**而不是反向传播——长 CoT 下 KV Cache 会先爆。这也是 GRPO"删 critic"价值巨大的原因：直接省一份完整模型副本。

**2026 年开源栈**：

| 工具 | 定位 |
|---|---|
| **verl**（火山引擎/字节） | 大规模 RL 训练骨干，主流工业选择 |
| **OpenRLHF** | 开源 RLHF/RL 全流程框架 |
| **TRL**（HuggingFace） | 中小规模 PPO / DPO / GRPO 主力：`PPOTrainer` / `DPOTrainer` / `GRPOTrainer` |
| **Unsloth** | 单卡 LoRA + GRPO 快速验证（呼应 [环节 09](../transformer/环节09-训练管线详解.md) §4.6） |
| **Agent-Lightning / Agent-R1** | Agent 轨迹上的多轮工具 RL（→ [环节 08](./环节08-AgenticRL与信用分配详解.md) §3） |

## 6. 坑清单（跨环节汇总）

1. **跳过 SFT 直接 RL**：模型连格式都不会，RL 的探索空间里全是垃圾 → 必须先 SFT。
2. **把 DPO 当万能**：DPO 不探索，数学/代码这类需要"想出数据外解法"的任务提升有限（实证差约 2.5%）。
3. **KL 系数设错**：GRPO 与 DPO 的 β 量级差 1~2 个数量级，别照抄。
4. **忽略全对/全错组**：`std=0` 时优势爆炸或归零，训练悄悄不动 → 加 `ε` / 动态采样过滤。
5. **采样温度太低**：组内全同 → 优势恒为 0 → 整批 rollout 白采。
6. **长 CoT 还用序列级损失**：长回答的 token 梯度被稀释（实测 30× 差距）→ 必须 token 级。
7. **只有结果奖励却去做长程 Agent**：末答奖励太稀疏、太晚 → 需过程奖励或价值分解。
8. **多 agent 直接套单 agent 的组基线**：优势只到"团队级"，失败的 agent 也被鼓励（实测错配率可达 33.3%）。
9. **奖励只看最终答案、不看过程安全**：模型会学出"答案对但中间乱调 API / 泄露 PII"。
10. **RM 不复训**：策略漂移后 RM 失效，而损失曲线正常 → 定期重训或改用验证器。
11. **用 RL 调风格却不做回归**：可验证 RL 会**隧道化**，通用能力/风格需单独验收（→ [模型评测与选型方法详解](../transformer/模型评测与选型方法详解.md)）。
12. **忽视 rollout 的显存与延迟**：RL 成本大头在"生成"不在"反向传播"，长 CoT 下 KV Cache 先爆。
13. **以为 RL 能灌知识**：RL 调的是**行为与策略**，知识依然要走 RAG / 继续预训练。
14. **拿验证器通过率当成功指标**：策略会钻验证器空子——**通过率涨、真实能力不涨**是常态。

## 7. 面试高频追问（跨环节综合版）

> 单环节的深度追问分别见各篇的「面试高频追问」；这里只留**跨环节综合题**。

1. **SFT 已经很强了，为什么还要 RL？** → 三个限制：只能模仿不能超越（上限=数据质量）、只能优化可微目标（偏好/对错不可微）、token 级目标 ≠ 序列级质量（暴露偏差）。RL 把优化目标换成"奖励高不高"。→ [环节 05](./环节05-偏好对齐与RLHF详解.md) §1
2. **RLHF 为什么必须加 KL 惩罚？** → 不约束会坍缩到"高分但不会说人话"的退化分布；β 控制允许偏离参考模型多远。→ [环节 05](./环节05-偏好对齐与RLHF详解.md) §4
3. **DPO 为什么不需要奖励模型？** → 最优策略与奖励有闭式关系 `r = β·log(π*/π_ref)+β·log Z(x)`，代入 Bradley-Terry 后配对相减把 `Z(x)` 消掉。→ [环节 06](./环节06-DPO家族与离线偏好优化详解.md) §1
4. **DPO 和 PPO/GRPO 的本质区别？** → **离线 vs 在线**：DPO 吃静态偏好对、不探索；PPO/GRPO 训练中自己采样、能超越训练数据。→ [环节 06](./环节06-DPO家族与离线偏好优化详解.md) §5
5. **GRPO 比 PPO 省了什么？为什么能不要 critic？** → 省掉 critic（一份完整模型副本）+ GAE + value loss；critic 的作用只是估"平均水平"当基线，而同题 G 个回答的成绩本身就是免费基线。→ [环节 07](./环节07-GRPO与RLVR详解.md) §1
6. **PPO 的 clip 到底在做什么？** → 用 `min(ρÂ, clip(ρ)Â)` 构造**悲观下界**，让"把策略改远"失去额外收益；`Â>0` 拦上界、`Â<0` 拦下界，**只取消激励不额外惩罚**。→ [环节 04](./环节04-信赖域与PPO详解.md) §4、§8
7. **DAPO 解决了什么问题？** → 长 CoT 训练失稳，四项：Clip-Higher（防熵坍缩）、Dynamic Sampling（过滤无效样本）、token 级策略梯度损失、超长奖励整形。→ [环节 07](./环节07-GRPO与RLVR详解.md) §5
8. **为什么 R1 用规则奖励而不用 PRM？** → PRM 难规模化；规则结果奖励 + GRPO 的组相对优势隐式完成步骤级信用分配；实测现有 PRM 用在前沿模型上不如多数投票。→ [环节 08](./环节08-AgenticRL与信用分配详解.md) §1
9. **PRM 和 ORM 怎么选？** → **默认 ORM**；PRM 在四类场景胜出：长程 Agent、工具安全、MARL、**推理时搜索引导**。→ [环节 08](./环节08-AgenticRL与信用分配详解.md) §1、§6
10. **RLHF 会死吗？** → 不会。RLVR 替代不了风格/语气/拒答这类**不可验证**目标；但 RLHF 会从主战场退化成风格兜底层。**验证器是新的数据集**。→ [环节 07](./环节07-GRPO与RLVR详解.md) §6
11. **RL 训练为什么比 SFT 贵这么多？** → 多模型同驻 + rollout 生成（推理负载 + KV Cache）+ 训练侧激活，两套资源峰值都要扛。删 critic/删 RM 的演进本质都在优化这一项。→ 本文 §5.4
12. **奖励黑客怎么防？** → 多信号交叉、长度与格式正则化、定期重训 RM、验证器噪声去偏、保持 KL 约束、上线前对抗性验收。→ 本文 §4.2
13. **什么任务该上 RL，什么不该？** → 该上：**可验证**（数学/代码/SQL/结构化）或**有明确偏好信号**（风格/拒答）；不该上：**知识类**（走 RAG / 继续预训练）、**临时指令**（走 Prompt）、**无奖励信号可定义**的任务。
14. **RL 训出的能力为什么容易"隧道化"？** → 可验证 RL 只奖励可验证的部分 → 通用对话/风格能力退化。生产上要保留 RLHF/DPO 兜底，并把通用能力单独纳入验收。
