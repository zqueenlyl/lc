## 0. 一句话定位

**GRPO = 拿掉 PPO 的 critic，用"同题一组回答"互为基线；RLVR = 把奖励从"人打分"换成"验证器判对错"。**

```
PPO+RLHF:  Actor + Critic + RewardModel + Reference     （4 模型）
GRPO:      Actor + RewardModel/Verifier + Reference     （3 模型，删掉 critic）
+ RLVR:    奖励不再来自人类偏好，而来自"单测/数学校验器"
```

**两句话记住它为什么成立**：

1. **critic 的唯一职责是估"平均水平"当基线**（→ [环节 03](./环节03-策略梯度与Actor-Critic详解.md) §5、[环节 04](./环节04-信赖域与PPO详解.md)）——而"平均水平"完全可以用**同一道题下其他回答的成绩**直接估出来，不必学一个网络；
2. **奖励只要能自动判对错，"谁来定义好"这件事就彻底不依赖人类了**——这是成本与可扩展性的结构性跃迁。

## 1. 从 PPO 到 GRPO：为什么能删掉 critic

**回顾 critic 的作用**（→ [环节 03](./环节03-策略梯度与Actor-Critic详解.md) §6）：它只负责估 `V(s)`，用来把"绝对回报"变成"优势"：

```
A = R − V(s)          ← V(s) 就是"平均水平"，critic 的唯一产出
```

**关键洞察**：如果你同时有**同一道题的 G 条回答**，那"平均水平"根本不用估：

```
"平均水平" ≈ (这 G 条回答的得分平均值)
```

**理论合法性来自 [环节 03](./环节03-策略梯度与Actor-Critic详解.md) §5 的基线无偏性**：任何**不依赖动作**的量都可以当基线减掉，不改变期望梯度。**同一道题下其他回答的平均分，恰好不依赖当前这条回答的动作** → 完全合法。

**收益（为什么工业界立刻换）**：

| 删掉的东西 | 省下的资源 |
|---|---|
| critic 网络（一份完整模型副本） | **显存约省一半**：7B 模型 8×H100 可跑（PPO 要 16×H100） |
| value loss 的调参 | 少一组超参（`c₁`、value clip 等） |
| GAE 的实现 | 少一套逐 token 自举逻辑 |
| `reward scale` 的敏感性 | 组内归一化天然消解（见 §3） |

> **代价**：必须为同一个 prompt 采样多条（**G 条**）——rollout 成本随 G 线性上涨，而且当"整组全对/全错"时这条 prompt 完全提供不了梯度（§4 的头号坑）。

## 2. GRPO 四步流程

```
① 采样：对单个 prompt x，从当前策略采样 G 个回答 y₁…y_G
        （G 典型 8~64，公开实践多用 16~32）

② 打分：r_i = R(x, y_i)
        通常来自验证器（规则 / 单测 / 数学校验），而不是学出来的 RM

③ 组内归一化优势：
        A_i = ( r_i − mean(r₁…r_G) ) / std(r₁…r_G)

④ 更新：代入 PPO 风格的 clipped 目标 + 对参考策略的 KL 惩罚
        J = E[ (1/G) Σ_i (1/|y_i|) Σ_t  min(ρ·A_i , clip(ρ,1−ε,1+ε)·A_i) ] − β·KL(π_θ‖π_ref)
```

**与 PPO 逐项对照**：

| | PPO | GRPO |
|---|---|---|
| 优势来源 | `A_t = GAE(δ_t)`，逐 token 自举 | `A_i = (r_i − mean)/std`，**整条回答共享一个值** |
| 需要 critic | ✅ | ❌ |
| 需要 GAE | ✅ | ❌ |
| 基线精度 | 依赖 critic 学得好不好 | 组内可见，**无偏且免费** |
| 适配奖励 | 连续/稠密都行 | **天然适配 0/1 离散奖励** |

> 注意第 ④ 步里的 `1/|y_i|`（按回答长度归一化）——**这一项是 Dr.GRPO 专门指出的偏差来源**，见 §5。

## 3. 组内优势的真实形状（G = 8，0/1 奖励）

这是理解 GRPO 全部行为的基础表。设一组 8 条回答里有 `k` 条正确（奖励 1），用总体标准差归一化：

| k 正确 | mean | std | **A(正确那条)** | A(错误那条) | \|A\| 量级 |
|---|---|---|---|---|---|
| 0 | 0.000 | 0.000 | — 分母为 0 — | — 分母为 0 — | **全同 → 无信号** |
| **1** | 0.125 | 0.331 | **+2.646** | −0.378 | 2.646 |
| 2 | 0.250 | 0.433 | +1.732 | −0.577 | 1.732 |
| 3 | 0.375 | 0.484 | +1.291 | −0.775 | 1.291 |
| **4** | 0.500 | 0.500 | **+1.000** | **−1.000** | 1.000 |
| 5 | 0.625 | 0.484 | +0.775 | −1.291 | 0.775 |
| 6 | 0.750 | 0.433 | +0.577 | −1.732 | 0.577 |
| 7 | 0.875 | 0.331 | +0.378 | **−2.646** | 0.378 |
| 8 | 1.000 | 0.000 | — 分母为 0 — | — 分母为 0 — | **全同 → 无信号** |

**三条必须记住的结论**：

1. **`k=0` 与 `k=8` 完全没信号**：`std=0`，分母为 0。实现上要么加 `ε`（`std+1e-4`）把优势压成 0，要么直接过滤掉这条 prompt（DAPO 的 Dynamic Sampling 就是干这个）。
2. **`k=1` 时正确那条的优势是 `k=4` 时的 2.6 倍**：**组内正确率越低，正确那条被"抬"得越狠**。这带来两个后果——
   - 好处：稀缺的正确样本得到强梯度（学习效率高）；
   - 坏处：**优势尺度随题目难度剧烈变化**（这就是 Dr.GRPO 说的"标准化偏差"）。
3. **除以 `std` 是"免费的任务自适应"**：无论奖励是 0/1 还是 0~100，归一化后优势都在 1 附近 → **换任务不用重调奖励尺度**（这是 GRPO 相对 PPO 最好用的一点）。

> **补充直觉**：`A_i` 是"这条回答比同题平均好多少"。当奖励是 0/1 时，组内天然形成"成功 vs 失败"的干净对比——**这正是"用结果奖励的 GRPO ≈ 不付标注费的过程监督"的来源**（→ [环节 08](./环节08-AgenticRL与信用分配详解.md) §1）。

## 4. 固定坑（第一次跑必踩）

| 坑 | 机制 | 后果 | 对策 |
|---|---|---|---|
| **全对 / 全错组** | `std=0` | 优势爆炸（除以 0）或直接归零 → **训练悄悄不动** | 分母加 `ε`；**Dynamic Sampling 过滤退化 prompt** |
| **G 太小** | 组内样本少 | 均值/标准差噪声大 → 优势抖动 | `G` 折中 **16~32**（8~64） |
| **G 太大** | rollout 线性涨价 | 成本失控（长 CoT 下 KV Cache 先爆） | 与 batch 大小一起权衡 |
| **β 太小** | KL 惩罚弱 | **语言连贯性崩坏**（重复、格式堆砌） | DeepSeek 风格多在 **0.001~0.04** |
| **采样温度太低** | 组内回答几乎相同 | 组内全同 → 优势恒为 0 → **白跑一整批** | 采样温度略高、保留探索 |
| **奖励形态没想清** | 0/1 与稠密奖励训出的模型差异巨大 | 训出来的行为完全不是你想要的 | 先在小规模上试不同奖励形态再看曲线 |

## 5. DAPO / Dr.GRPO / GSPO：GRPO 的工程补丁

GRPO 在**长思维链（long CoT）**训练中会失稳，于是有一批针对性修补。**核心思想不变：仍用一组 rollout 当基线。**

### 5.1 DAPO（字节跳动 + 清华，2025，arXiv 2503.14476）——四项技术

| 技术 | 解决什么 | 机制 |
|---|---|---|
| **Clip-Higher** | **防熵坍缩**，保住探索性 | 把比率的上裁剪界抬高（`ε_low=0.2`、`ε_high=0.28`，非对称） |
| **Dynamic Sampling** | 剔除全对/全错的无效样本 | 动态过滤批次，保证每步都有梯度信号 |
| **Token-level Policy Gradient Loss** | 长 CoT 必须按 token 算损失 | 序列级损失在长回答上会把梯度稀释到消失 |
| **Overlong Reward Shaping** | 降低截断/超长带来的奖励噪声 | 对超长回答做奖励整形（不是简单给 0 分） |

**Clip-Higher 的机制**（用数字说清楚）：设想把某个 token 的概率抬高 `Δπ`，则比率 `ρ = 1 + Δπ/π_old` —— **`π_old` 越小，`ρ` 越大**。所以**低概率 token 总是先撞上裁剪上界、拿到 0 梯度**：

| `π_old` | `ρ = 1 + 0.002/π_old` | 上界 0.20 | 上界 0.28 |
|---|---|---|---|
| 0.0010 | 3.000 | 已截断（梯度 0） | 已截断 |
| 0.0050 | 1.400 | 已截断（梯度 0） | 已截断 |
| **0.0080** | **1.250** | **已截断** | 未截断 |
| 0.0100 | 1.200 | 未截断 | 未截断 |
| 0.0500 | 1.040 | 未截断 | 未截断 |

等价说法：**clip 允许的"绝对概率提升额度"是 `ε·π_old`**（`π_old=0.001` 的 token 最多只能提到 0.0012）。**低概率 token 的额度天然极小 → 熵必然往下掉**。抬高上界把这个额度放大 40%，于是"冷门 token"仍有成长空间 → **熵不塌**。

**Token-level loss 的数量级（真实计算）**：4 条回答、同一题级优势 `A=1`：

| 长度分布 | 序列级下最短/最长回答的 token 梯度权重倍数 | token 级 |
|---|---|---|
| `[50, 200, 800, 1500]`（差异大） | **30.0×**（50 长的回答权重是 1500 长的 30 倍） | **1.0×（恒定）** |
| `[400, 420, 380, 440]`（接近） | 1.1× | 1.0× |

**读法**：序列级损失下，**短回答的每个 token 被赋予远大于长回答的梯度权重** → 长 CoT 里真正重要的长回答反而学不动。**长思维链训练必须用 token 级。**

> 效果：AIME 2024 上把 Qwen2.5-32B 训到 **50 分**，且**训练步数比 R1-Zero 少约 50%**。系统已开源。

### 5.2 其他变体

| 变体 | 一句话改动 |
|---|---|
| **Dr. GRPO**（arXiv 2503.20783） | 指出 GRPO 有两处偏差——**长度偏差**（除以长度 `1/\|y_i\|` 会让长回答的 token 梯度被稀释）与**标准化偏差**（除以 `std` 会把"简单题/难题"的优势强行拉平，扭曲难度权重）→ **去掉这两项**，训练更稳 |
| **GSPO**（Qwen 团队，2025） | 把**重要性比从 token 级改成序列级**（`ρ_seq = (π_θ(y)/π_old(y))^{1/\|y\|}`，做长度归一化）→ 长序列训练更稳定（**Qwen3 采用**） |
| **DAPO / GRPO / RLOO** | 同属"组基线"家族，工程细节不同，**别在选型上纠结太久** |

> **Dr.GRPO 与 DAPO 在"长度"上方向相反**（一个去掉长度归一化、一个要求 token 级损失），看似矛盾，其实说的是两件事：**DAPO 反对的是"序列级损失把长回答整体稀释"**（建议按 token 平均），**Dr.GRPO 反对的是"用长度当分母去缩放优势"**。关键是分清"损失归一化"与"优势缩放"这两个不同位置。

## 6. RLVR：把奖励换成"可验证"（结构性转变）

**RLVR = Reinforcement Learning with Verifiable Rewards**。奖励不再是"人类给 7/10 分"，而是：

- **单元测试通过了**；
- **`\boxed{}` 里的答案与标准答案一致**；
- **SQL 查询返回了正确的行**。

**为什么这是结构性转变**：对数学、代码、结构化推理这类任务，**质量判断根本不需要人类**——验证器给的二元信号**更快、更便宜、更一致、可无限扩展**。这是 [环节 05](./环节05-偏好对齐与RLHF详解.md) §5「验证比生成容易」被推到极致的结果。

> **DeepSeek-R1 的关键证明**：**纯 RLVR 可以"涌现"出推理能力**（自我反思、动态换策略、验算），**且不需要任何人类标注的推理轨迹**（R1-Zero 路线）。

### 6.1 奖励信号演进四阶段（看清"瓶颈在哪"）

| 时代 | 奖励来源 | 捕捉什么 | 典型失败模式 | 瓶颈 |
|---|---|---|---|---|
| 2022–2023 | 人类成对偏好 → RM | 人类更喜欢哪个 | **谄媚**、对 RM 钻空子 | 人类标注者 |
| 2023–2024 | 直接吃偏好对（DPO） | 同上，去掉 RM | 不探索、被数据集边界框住 | 偏好数据质量 |
| **2024–2026** | **验证器**（单测 / 数学校验器 / 正则） | 这个答案是否**可被证明正确** | **对验证器钻空子**、能力隧道化 | **验证器的设计** |
| 2025– | 更强模型当 judge | 在更聪明的模型看来是否对 | judge 偏见、模式坍塌 | judge 的校准 |

> 趋势判断：**"验证器是新的数据集"**。

### 6.2 三条失效边界（重要）

1. **对验证器钻空子（reward hacking）**：策略在边际上**总会比信号更聪明**——这是对齐的中心问题，**不是可以一次性解决的 bug**。防法：多信号交叉（规则 + RM + judge）、正则化、对抗性验收、验证器噪声去偏（arXiv 2505.13445）。
2. **能力隧道化**：只训可验证任务 → 通用对话/风格能力退化。**所以生产上常保留 RLHF/DPO 做一层兜底**（这就是"RLHF 不会死"的真正原因）。
3. **验证器噪声**：数学检查器有边界情况、单测覆盖不全 → 模型会吃到假阳性漏洞。

> **RLHF 的最终位置**：从"主战场"退化为**一层薄薄的专门化层**（管风格、语气、品牌口吻、拒答）。能力提升的主战场交给可验证 RL。

## 7. 理论：GRPO 为什么不是"碰巧能用"

> **arXiv 2603.01162**：GRPO 的策略梯度可写成 **U-statistic** 形式，渐近等价于"**拥有理想价值函数的 oracle 算法**"。

翻译成人话：**GRPO 不是"用组均值凑合替代 critic"的近似技巧，而是在一大类策略梯度方法中可证最优的**——组内其他样本恰好构成了对基线的无偏统计量，且这个估计量在统计意义上是"最优的"那一类。

这条结论的价值：它给"删掉 critic 却更好用"这个工程现象提供了理论解释，面试时是很好的加分点。

## 8. 案例：DeepSeek-R1 的四阶段（arXiv 2501.12948）

这是"现代对齐流水线"的标准范式，值得逐阶段记住：

| 阶段 | 做什么 | 关键点 |
|---|---|---|
| **① 冷启动 SFT** | 用**数千条**高质量长 CoT 数据微调基座 | 解决 R1-Zero 的"可读性差、语言混杂"问题；**这一步是 R1 与 R1-Zero 的核心差别** |
| **② 面向推理的 RL** | **GRPO + 规则奖励**（答案正确性 + 格式合规） | 只奖励"结果对 + 格式对"，**不监督思考过程** → 推理能力**涌现**（自我反思、换解法、验算） |
| **③ 拒绝采样 + SFT** | 用阶段②模型采样、筛出高质量轨迹（**约 60 万条推理 + 约 20 万条通用**），重训基座 | 把 RL 学到的东西**"固化"进权重**，同时注入通用能力 |
| **④ 全场景 RL** | 推理任务继续用规则奖励 + 通用任务用奖励模型 | 兼顾推理与"有用/无害"，得到最终产品模型 |

**三个可直接复用的结论**：

1. **规则奖励足够训出推理能力**（不必上 PRM / RM）；
2. **RL 之后要"蒸馏回 SFT"**（阶段③）——把策略探索的成果固化，避免 RL 后输出风格不稳定、语言退化；
3. **R1-Zero 证明"纯 RL 涌现"可行，但 R1 的工程版加了冷启动与 SFT 收口**——**能跑通 ≠ 好用**，产品化必须修补可读性。

## 9. 三阶段后训练流水线（顺序不可颠倒）

| 阶段 | 解决什么 | 数据形态 | 代表方法 |
|---|---|---|---|
| **SFT** | 格式：指令跟随、结构化输出、对话风格 | 百万~千万级精选样本 | — |
| **偏好优化** | 价值观与偏好对齐 | 偏好对 / 二元反馈 | DPO → SimPO / KTO / ORPO |
| **强化学习** | **突破训练数据上限**、产生推理能力 | 可验证奖励 / 环境反馈 | GRPO / DAPO |

> **核心判断**：预训练只提供"基础智力"，**后训练（post-training）现在贡献了模型"可用能力"的大部分**。
> **顺序不可颠倒**：跳过 SFT 直接 RL 不成立——模型还没有基本格式能力，RL 的探索空间里全是垃圾，无从探索（→ [RL选型与工程落地总表.md](./RL选型与工程落地总表.md) §1）。

## 10. 数值走查（纯标准库，全部真实输出）

### 10.1 组内优势与 std=0（§3 表格）

```python
import math
G = 8
for k in range(G + 1):
    mean = k / G
    std = math.sqrt(mean * (1 - mean))
    if std < 1e-12:
        print(f"k={k}  std=0  → 全同，无梯度信号（要么爆炸要么归零）")
    else:
        print(f"k={k}  mean={mean:.3f}  std={std:.3f}  A(对)={(1-mean)/std:+.3f}"
              f"  A(错)={(0-mean)/std:+.3f}")
# k=1 → A(对)=+2.646  ← 组内只有 1 条对，优势被放大
# k=4 → A(对)=+1.000  ← 一半对一半错，优势最"标准"
# k=0/8 → std=0      ← 无信号
```

### 10.2 序列级 vs token 级损失（§5.1）

```python
for lens in ([50, 200, 800, 1500], [400, 420, 380, 440]):
    tot = sum(lens)
    seq = [1 / len(lens) / L for L in lens]      # 序列级：先对序列平均，再除长度
    tok = [1 / tot] * len(lens)                  # token 级：所有 token 一起平均
    print(f"长度={lens}  序列级权重={[f'{s:.2e}' for s in seq]}  倍数={seq[0]/seq[-1]:.1f}×")
    print(f"{'':16}token 级权重={[f'{s:.2e}' for s in tok]}  倍数={tok[0]/tok[-1]:.1f}×")
# 长度差异大时：序列级最短/最长回答的 token 权重差 30.0×；token 级恒为 1.0×
```

### 10.3 Clip-Higher 的边界（§5.1）

```python
dpi = 0.002                                      # 想抬高的绝对概率
for p_old in (0.001, 0.005, 0.0080, 0.01, 0.05):
    rho = 1 + dpi / p_old
    print(f"π_old={p_old:<7} ρ={rho:.3f}  "
          f"ε=0.20: {'截断(梯度0)' if rho > 1.20 else '未截断':<12}"
          f"ε=0.28: {'截断(梯度0)' if rho > 1.28 else '未截断'}")
# π_old=0.0080 → ρ=1.250：ε=0.20 时被截断、ε=0.28 时有梯度 → 低概率 token 重新获得成长空间
```

**读法**：`ε` 决定的"绝对概率提升额度"是 `ε · π_old`。低概率 token 的额度天然极小 → 熵必然往下掉；**抬高上界就是在给冷门 token 留活路**。

## 11. 坑清单

1. **忽略全对/全错组**：`std=0` 时优势会爆炸或归零，训练**悄悄不动**（回报曲线平的）→ 加 `ε` / Dynamic Sampling 过滤。
2. **采样温度太低**：组内回答几乎相同 → 优势恒为 0 → 整批 rollout 白采。
3. **β 照抄 RLHF**：GRPO 的 β 比 RLHF 小 1~2 个数量级（0.001~0.04 vs 0.01~0.1），抄错就是语言崩坏。
4. **长 CoT 还用序列级损失**：长回答的 token 梯度被稀释（30× 差距），训不动 → 必须 token 级。
5. **以为"有了 RLVR 就不用 RLHF"**：可验证 RL 会**隧道化**，通用风格能力退化 → 生产上要保留 RLHF/DPO 兜底。
6. **把验证器的通过率当成功指标**：策略会钻验证器空子（奖励黑客），**验证器通过率涨、真实能力不涨**是常态 → 必须有多套独立评测 + 对抗性样本。
7. **只有结果奖励却去做长程 Agent**：末答奖励太稀疏、太晚 → 需过程奖励或价值分解（→ [环节 08](./环节08-AgenticRL与信用分配详解.md)）。
8. **以为 R1-Zero 能直接产品化**：纯 RL 涌现出的输出可读性差、语言混杂，**必须有冷启动 SFT + 蒸馏回 SFT 收口**。
9. **在 RL 里塞知识**：RL 调的是行为与策略，知识要走 RAG / 继续预训练。

## 12. 面试高频追问

1. **GRPO 比 PPO 省了什么？为什么能不要 critic？** → 省掉 critic 网络（一份完整模型副本）+ value loss + GAE。因为 critic 的作用只是估"平均水平"当基线，而**同题 G 个回答的成绩本身就是免费且无偏的基线**（合法性来自"不依赖动作的基线不减期望梯度"）。
2. **GRPO 的优势怎么算？** → `A_i = (r_i − mean(r₁…r_G)) / std(r₁…r_G)`：组内归一化。既提供了基线，又天然消解了 reward scale 的问题（换任务不用重调奖励尺度）。
3. **组内全对或全错会怎样？** → `std=0`，分母为 0 → 优势要么爆炸要么归零，**该 prompt 无梯度信号**。对策：分母加 `ε`、Dynamic Sampling 动态过滤退化 prompt。
4. **G 怎么选？** → 折中 16~32（范围 8~64）。太小 → 优势噪声大；太大 → rollout 成本线性上涨（长 CoT 下 KV Cache 先爆）。
5. **DAPO 解决了什么问题？** → 长 CoT 训练失稳，四项：**Clip-Higher**（防熵坍缩）、**Dynamic Sampling**（过滤无效样本）、**token 级策略梯度损失**（防长序列梯度稀释）、**超长奖励整形**（降噪）。
6. **Clip-Higher 为什么能防熵坍缩？** → `ρ = 1 + Δπ/π_old`，**低概率 token 天然 `ρ` 大、先撞上界、拿到 0 梯度**；而 clip 允许的绝对提升额度是 `ε·π_old`，低概率 token 额度极小 → 熵必然下降。抬高上界等于给冷门 token 留出成长空间。
7. **DR.GRPO 指出了什么偏差？** → 两处：**长度偏差**（`1/\|y_i\|` 缩放优势会让长回答的 token 梯度被稀释）与**标准化偏差**（除 `std` 把不同难度题目的优势强行拉平）；去掉它们训练更稳。注意它与 DAPO 的"token 级损失"说的是不同位置的事。
8. **GSPO 改了什么？** → 把重要性比从 **token 级**改成**序列级**（带长度归一化 `ρ_seq=(π_θ(y)/π_old(y))^{1/\|y\|}`），长序列训练更稳定，Qwen3 采用。
9. **RLVR 是什么？为什么是结构性转变？** → 用可验证奖励（单测/数学校验器）替代人类偏好。因为对数学、代码、结构化推理，"判断对错"根本不需要人类：更快、更便宜、更一致、可无限扩展。
10. **为什么 R1 用规则奖励而不用 PRM？** → PRM 难规模化（步骤标注贵、"一步"定义模糊、易被黑客）；规则结果奖励 + GRPO 的组相对优势**隐式完成了步骤级信用分配**——成功与失败的轨迹在分叉处梯度最强。且实测把现有 PRM 用在前沿模型上不如简单多数投票（→ [环节 08](./环节08-AgenticRL与信用分配详解.md) §1）。
11. **奖励黑客怎么防？** → 多信号交叉（规则 + RM + judge）、长度与格式正则化、定期用新策略重训 RM、验证器噪声去偏、保持 KL 约束、上线前做对抗性验收。
12. **"RLHF 会死吗"？** → 不会。RLVR 替代不了风格/语气/拒答这类**不可验证**目标；但 RLHF 会从主战场退化成"风格兜底层"。一句话：**验证器是新的数据集**。
