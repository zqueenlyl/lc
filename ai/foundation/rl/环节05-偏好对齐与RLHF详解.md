## 0. 一句话定位

**SFT 是"模仿"（有标准答案），RLHF 是"用人类的比较判断当信号"（没有标准答案）。**

```
SFT   ：数据里怎么写，你就怎么学          能力上限 = 训练数据质量上界
RLHF  ：我只告诉你"哪个更好"，你自己去拿分  能力上限 = 偏好信号质量上界
```

> 关键认知转变：**对齐技术的演进史，本质是"谁来定义好"不断换人的历史**——从「人类示范」→「人类偏好模型」→「机器验证器」。每换一次，成本和可扩展性都降一个量级。**本环节是"人类偏好模型"这一代的标准答案。**

## 1. 为什么 SFT 之后还要 RL（三个根本限制）

| 限制 | 机制 | 后果 |
|---|---|---|
| **只能模仿，不能超越** | 交叉熵只会把概率推向"数据里出现过的那条回答" | 数据里没写的更优解法学不到；"反思、换解法、验算"这类**策略性行为**无从模仿 |
| **只能优化可微目标** | 反向传播需要梯度 | "人类是否更喜欢""答案是否正确""代码是否通过测试"**全都不可微** → 没法直接写进损失函数 |
| **目标错配（token 级 ≠ 序列级）** | 逐 token 算似然，且训练用 teacher forcing（喂真值） | 每步概率高 ≠ 整段回答好；训练时看真值、推理时看自己 → **暴露偏差（exposure bias）**，一步错步步错 |

**最核心的一条**：next-token 预测与"这个回答好不好"之间**没有必然联系**。一个模型可以给错误答案分配极高概率（因为训练数据里就是这么写的）。

> **经典佐证（InstructGPT, arXiv 2203.02155）**：**1.3B 的 PPO 模型，人类偏好度高于 175B 的纯 GPT-3**。说明"对齐"带来的收益，一个数量级以上于"堆参数"。这是 RLHF 站住脚的根本论据。

**RL 带来三件 SFT 做不到的事**：

1. 优化**不可微目标**（人类偏好、正确性、格式合规）；
2. 优化**整段回答**而非单 token（序列级目标）；
3. **探索**出训练数据里不存在的行为（后来的 R1-Zero 长 CoT 就是这么长出来的）。

## 2. RLHF 三步流程

```
① SFT         少量人类示范（几万条）微调基座
              → 得到"会听话"的初始策略 π_SFT

② 奖励模型 RM   同一 prompt 给标注者两个回答，问"哪个更好"
              → 训练 r_θ(x, y) 预测人类偏好（标量）

③ PPO          把 RM 当"环境"：
                策略采样回答 → RM 打分 → PPO 更新策略
                同时用 KL 拴住 π_ref（= π_SFT 的冻结拷贝）
```

**注意 ③ 里三个模型的角色分工**（这是 RLHF 最容易讲糊的地方）：

| 模型 | 角色 | 梯度 |
|---|---|---|
| **π_θ（Actor / 策略）** | 被训练的模型 | ✅ 更新 |
| **π_ref（Reference）** | SFT 模型的**冻结拷贝**，当"别跑太远"的锚 | ❌ 冻结 |
| **r_θ（Reward Model）** | 给回答打分的"环境" | ❌ 冻结（PPO 阶段） |
| **V_φ（Critic）** | 估计"平均水平"当基线 | ✅ 更新（→ [环节 04](./环节04-信赖域与PPO详解.md)） |

> **4 个模型同时在显存里**——这是 RLHF 最贵的结构性原因，也是后面每种新算法"删掉一个部件"的动机来源（DPO 删 RM、GRPO 删 critic）。

## 3. 奖励模型：把"人更喜欢"变成一个标量

### 3.1 Bradley-Terry 偏好模型

**假设**：人类在 `y_w`（winner/chosen）与 `y_l`（loser/rejected）之间做选择时，选择概率只取决于两者奖励之差：

```
P( y_w ≻ y_l | x ) = σ( r(x, y_w) − r(x, y_l) )        ,   σ(z) = 1/(1+e^{−z})
```

**损失**（负对数似然 → 标准二分类交叉熵）：

```
L_RM = − E_{(x, y_w, y_l)} [ log σ( r(x, y_w) − r(x, y_l) ) ]
```

**工程实现**：把语言模型最后的 `lm_head`（输出词表 logits）换成一个**输出单个标量的线性头**（通常取**最后一个 token 的 hidden state**），用上面的损失训练——**就是在做二分类，只不过分类器是"哪个回答更好"**。

### 3.2 BT 损失的形状（决定训练行为的关键）

`Δ = r(x,y_w) − r(x,y_l)`：

| Δ | `P(偏好 chosen)` | `−log σ(Δ)`（损失） | `\|∂loss/∂Δ\|` |
|---|---|---|---|
| 0.0 | 0.5000 | 0.6931 | **0.5000** |
| 0.5 | 0.6225 | 0.4741 | 0.3775 |
| 1.0 | 0.7311 | 0.3133 | 0.2689 |
| 2.0 | 0.8808 | 0.1269 | 0.1192 |
| 4.0 | 0.9820 | 0.0181 | 0.0180 |
| 8.0 | 0.9997 | 0.0003 | **0.0003** |

**读表**：`Δ` 越大（模型已经把这组偏好分得越开）→ **梯度越接近 0**。

> 这是一个**饱和损失**：**已经从"分不开"变成"分得很开"的偏好对，几乎不再提供梯度**。训练自动把注意力转向"边界样本"（难例）。这个性质在 [环节 06](./环节06-DPO家族与离线偏好优化详解.md) 里会以 `σ(−Δ)` 的形式再次出现（DPO 的自动降权机制）。

### 3.3 奖励模型的四个工程病（都会真实发生）

| 病 | 机制 | 对策 |
|---|---|---|
| **长度偏置** | 人类标注者潜意识觉得长回答更"努力"→ RM 学会"长=好" | 长度惩罚 / 长度归一化 / 成对长度匹配 |
| **谄媚（sycophancy）** | 偏好数据由人类标 → 人类喜欢被认同 → 模型学会迎合 | 对抗性样本、多标注者交叉、独立 rubric |
| **分布漂移** | RM 是在**旧策略**输出上训的；PPO 一跑策略就前移，RM 判断失准 | 定期用新策略数据重训 RM；或改用验证器（→ [环节 07](./环节07-GRPO与RLVR详解.md)） |
| **只给一个标量** | `r(x,y)` 把整段回答压成一个数 → 过程信息全丢 | 需要过程信息就用 PRM（→ [环节 08](./环节08-AgenticRL与信用分配详解.md)） |

> **分布漂移最阴险**：它**在 loss 曲线上看不出来**——RM 的 loss 平稳、PPO 的回报还在涨，但模型实际在钻 RM 的旧漏洞。这是"训练看起来正常但模型变差"的头号原因。

## 4. RLHF 的目标函数与"缰绳"（KL 惩罚）

```
目标：max_π  E_{x~D, y~π(·|x)} [ r_θ(x, y) ]  −  β · KL( π_θ(·|x) ‖ π_ref(·|x) )
                    └── 拿高分 ──┘                    └──── 别偏离参考模型太远 ────┘
```

**为什么必须加 KL**（不加会怎样）：策略会坍缩到"**奖励最高但不会说人话**"的退化分布——重复、乱码、纯格式堆砌。因为**追求分数可以直接牺牲语言**：RM 只见过有限的回答分布，一旦策略跑到分布之外，RM 的打分就完全不可信（它成了可以被钻的空子）。

> 类比：`r` 是 KPI，`KL` 是"不能为了 KPI 把业务做垮"。**β 太小 → 奖励黑客（钻 RM 空子、语言崩坏）；β 太大 → 学不动（策略几乎不动）**。

| 算法 | β 典型量级 |
|---|---|
| **RLHF / PPO** | 0.01 ~ 0.1 |
| **DPO** | 0.1 ~ 0.5 |
| **GRPO**（DeepSeek 风格） | 0.001 ~ 0.04 |

> ⚠️ 三者的 β 量级差 **1~2 个数量级**，**千万不要照抄**（这也是 [RL选型与工程落地总表.md](./RL选型与工程落地总表.md) §4 里反复强调的一条）。

**实现上 KL 不是一个额外损失项，而是加在逐 token 奖励里**（L ^3 estimator）：

```
r_t = r_θ(x, y) · 1{t = T}  −  β · [ log π_θ(y_t|·) − log π_ref(y_t|·) ]
      └── 整段奖励只在最后一个 token 上给 ──┘   └──── 每个 token 都有一份 KL 惩罚 ────┘
```

**这一步很关键**：它把"序列级的标量奖励"变成了"逐 token 的稠密奖励"，**顺带解决了（一部分）信用分配问题**——每个 token 至少知道自己"离参考模型有多远"。

## 5. 数据经济学：RLHF 为什么成立

> **问"哪个更好"远比"写出最好的答案"便宜。**

| | SFT 数据 | 偏好数据 |
|---|---|---|
| 标注者要做什么 | **写出**一条好回答 | 在两条里**判断**哪个更好 |
| 要求 | 专家级能力 + 时间 + 想象力 | 只需判断力 |
| 单条成本 | 高 | 低得多 |
| 可否用非专家 | 难 | **可以**（相对判断比绝对生成容易得多） |

这是 RLHF 相对 SFT 的根本经济学基础，也是"**验证比生成容易**"这一整个思想的第一次登场——**RLVR 只是把这条思路推到极致**（用程序做验证器，连人类判断都省了，→ [环节 07](./环节07-GRPO与RLVR详解.md)）。

## 6. 代价：RLHF 贵在哪（四个模型 + 两套负载）

```
RLHF 显存 =  策略 π_θ（训练版：权重 + 梯度 + 优化器状态）
           + 参考 π_ref（冻结，仅前向）
           + 奖励模型 r_θ（前向，可能还要独立推理服务）
           + critic V_φ（PPO 独有）
           + rollout 的 KV Cache（G 条回答同时生成，长 CoT 下极占显存）
           + 训练侧激活
```

> **70B 的策略 ≈ 要养出 280B 参数量的开销**。而且 **rollout 阶段是"推理负载"、训练阶段是"训练负载"，两套资源峰值都要扛**（→ [RL选型与工程落地总表.md](./RL选型与工程落地总表.md) §5）。

三条历史结论由此而来：

1. **删掉 critic**（GRPO）→ 省一份完整模型副本 → [环节 07](./环节07-GRPO与RLVR详解.md)；
2. **删掉奖励模型**（DPO）→ 连 RM 都不要 → [环节 06](./环节06-DPO家族与离线偏好优化详解.md)；
3. **删掉人类偏好**（RLVR）→ 奖励从"人打分"换成"验证器 0/1" → [环节 07](./环节07-GRPO与RLVR详解.md)。

## 7. 埋伏笔：这个目标有闭式最优解

对 RLHF 的目标做变分优化（在"所有可能的策略分布"上求最优），可以得到一个**闭式解**：

```
π*(y|x) = (1 / Z(x)) · π_ref(y|x) · exp( r(x,y) / β )
```

其中 `Z(x) = Σ_y π_ref(y|x) exp(r(x,y)/β)` 是配分函数（**对所有可能的回答求和，实际算不出来**）。

**把它反解成 r**：

```
r(x, y) = β · log( π*(y|x) / π_ref(y|x) )  +  β · log Z(x)
```

这条式子就是 [环节 06](./环节06-DPO家族与离线偏好优化详解.md) 的全部起点：**"奖励"可以由"策略"反解出来**，于是"先训 RM 再跑 PPO"这三步可以合并成一步。

> 今天先记住两件事：①`KL 正则 + 线性奖励`的目标一定有这个形式的闭式解；②那个 `Z(x)` 看似不可计算，但在偏好对**相减**时会自动消掉——这是 DPO 推导里最漂亮的一步。

## 8. 数值走查：BT 损失与 KL 惩罚的真实数字

### 8.1 BT 概率与梯度饱和（§3.2 表格的代码）

```python
import math
sig = lambda x: 1 / (1 + math.exp(-x))
for d in (0.0, 0.5, 1.0, 2.0, 4.0, 8.0):
    print(f"Δ={d:>4.1f}  P(chosen 更好)={sig(d):.4f}  loss={-math.log(sig(d)):.4f}"
          f"  |grad|={abs(sig(d) - 1):.4f}")
# Δ=0.0 → P=0.5000 loss=0.6931 |grad|=0.5000
# Δ=1.0 → P=0.7311 loss=0.3133 |grad|=0.2689
# Δ=4.0 → P=0.9820 loss=0.0181 |grad|=0.0180   ← 已分得很开，几乎无梯度
```

**关键读法**：`|∂loss/∂Δ| = |σ(Δ) − 1| = σ(−Δ)`。这个式子后面在 DPO 的梯度里会原封不动再出现一次——**DPO 的"自动降权已经分对的样本"就是从 BT 损失继承来的，不是额外设计**。

### 8.2 闭式最优解的验证（KL 正则的作用）

取一个 3 选 1 的玩具分布（`π_ref = [0.5, 0.3, 0.2]`，奖励 `r = [0.0, 1.0, 2.0]`），直接套 `π* ∝ π_ref·exp(r/β)`：

```python
import math
pi_ref, r = [0.5, 0.3, 0.2], [0.0, 1.0, 2.0]
for beta in (0.1, 0.5, 2.0):
    w = [p * math.exp(ri / beta) for p, ri in zip(pi_ref, r)]
    Z = sum(w)
    pi = [x / Z for x in w]
    print(f"β={beta:>4}  π* = [{pi[0]:.4f} {pi[1]:.4f} {pi[2]:.4f}]")
# β=0.1  π* = [0.0000 0.0001 0.9999]   ← β 小：几乎只为最高奖励服务（语言崩坏风险）
# β=0.5  π* = [0.0367 0.1626 0.8008]
# β=2.0  π* = [0.3250 0.3215 0.3534]   ← β 大：明显向 π_ref 靠（学不动）
```

**读法（这是理解 β 最直观的一次）**：

- **β → 0**：`π*` 把全部概率压在奖励最高的那个回答上 → **完全无视 `π_ref`、无视语言质量**（这就是奖励黑客的模样）；
- **β → ∞**：`π* → π_ref` → **策略不动、学不到东西**；
- β 就是"**奖励最大化**"与"**不偏离参考模型**"之间的连续旋钮。

## 9. 坑清单

1. **跳过 SFT 直接 RL**：模型连格式都不会，RL 的探索空间里全是垃圾 → **必须先 SFT**（→ [RL选型与工程落地总表.md](./RL选型与工程落地总表.md) §1）。
2. **把 β 照抄**：RLHF 0.01~0.1、DPO 0.1~0.5、GRPO 0.001~0.04，量级差 1~2 个数量级。
3. **RM 不复训**：策略漂移后 RM 失效，而 loss 曲线完全正常（最阴险的一条）。
4. **把"RM 打分高"当成功**：RM 是**代理指标**。真正的验收是人类评测 / 下游任务 / 对抗性测试。
5. **以为 PPO 阶段的 KL 是"防过拟合"**：它是**防策略跑到 RM 不可信的区域**（分布外），语义是"待在参考模型的合理邻域"。
6. **用 RLHF 去灌知识**：RL 调的是**行为与策略**，知识依然要走 RAG / 继续预训练（→ [环节 09 · 训练管线](../transformer/环节09-训练管线详解.md) §4.1）。
7. **忽视长度膨胀**：RM 的长度偏置会让回答在训练中越变越长，而回报曲线一路向上——**必须把长度分布画出来一起看**。
8. **拿少量偏好对做 RLHF**：偏好数据少 + RM 容量大 → RM 过拟合到标注者个体口味，PPO 会把这种口味放大到极端。

## 10. 面试高频追问

1. **SFT 已经很强了，为什么还要 RL？** → 三个限制：只能模仿不能超越（上限 = 数据质量）、只能优化可微目标（偏好/对错不可微）、token 级目标 ≠ 序列级质量（暴露偏差）。RL 把优化目标换成"奖励高不高"。
2. **RLHF 为什么必须加 KL 惩罚？** → 不约束会坍缩到"高分但不会说人话"的退化分布；β 控制允许偏离 `π_ref` 多远，是安全与效果的平衡阀。
3. **奖励模型是怎么训的？** → Bradley-Terry：`P(y_w ≻ y_l) = σ(r(y_w) − r(y_l))`，损失 `−log σ(r_w − r_l)`；架构上就是把 `lm_head` 换成输出标量的线性头，取最后一个 token 的 hidden state 做二分类。
4. **BT 损失有什么性质？** → 饱和损失：`Δ` 越大梯度越接近 0（`|∂loss/∂Δ| = σ(−Δ)`），训练自动聚焦边界难例。DPO 的梯度权重就是这一项。
5. **RLHF 的目标函数最优解长什么样？** → `π*(y|x) ∝ π_ref(y|x)·exp(r(x,y)/β)`；反解可得 `r = β·log(π*/π_ref) + β·log Z(x)`——这就是 DPO 的出发点。
6. **为什么 RLHF 比 SFT 贵这么多？** → 4 个模型同驻（策略/参考/RM/critic）+ rollout 生成（推理负载 + KV Cache）+ 训练侧激活，**两套资源峰值都要扛**。后续算法演进本质都在删这几个部件。
7. **RLHF 的数据经济学基础是什么？** → 问"哪个更好"（判断）远比"写出最好的"（生成）便宜；这也是 RLVR 思想的第一次登场——**验证比生成容易**。
8. **RM 的分布漂移为什么危险？** → RM 是在旧策略输出上训的，策略前移后 RM 判断失准，但**loss 与回报曲线都正常**，模型实际在钻旧漏洞；对策是定期用新策略数据重训 RM 或改用验证器。
9. **RLHF 会死吗？** → 不会，但会退化：RLVR 替代不了风格/语气/拒答这类**不可验证**目标，所以 RLHF 从主战场变为"风格兜底层"。→ [环节 07](./环节07-GRPO与RLVR详解.md) §5。
