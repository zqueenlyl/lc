## 0. 一句话定位

**信用分配（credit assignment）是 RL 的核心难题；单轮问答里它被"组内方差"顺手解决了，多步/多智能体场景里它重新变成主要矛盾。**

```
单轮单 agent：  "这题答对了" → 组内其他回答当基线，天然逐条对比   ← 环节 07，已经解决
多步单 agent：  "40 步后任务成功了" → 哪一步的功劳？               ← 稀疏奖励，难
多 agent ：     "团队成功了" → 哪个 agent 的功劳？                 ← 团队奖励，最难
```

> 本环节的全部内容，都是围绕"**奖励的粒度该多细**"这一件事展开的。

## 1. PRM vs ORM：过程奖励还是结果奖励

**两种奖励形态**：

| | **ORM**（Outcome RM，结果奖励） | **PRM**（Process RM，过程奖励） |
|---|---|---|
| 打分粒度 | 整段回答一个标量（通常 0/1） | **每个推理步骤**单独打分 |
| 成本 | 低（单测 / 答案匹配即可） | 高（需**步骤级人类标注**） |
| 代表 | R1 的规则奖励 + GRPO | PRM800K（*Let's Verify Step by Step*, 2023） |

### 1.1 历史反转（面试很好用）

```
① 2023：OpenAI 的 PRM 在 MATH best-of-N 上大幅领先 ORM
        → 约一年内业界认为"过程监督是方向"
② 2024：DeepSeek-R1 反转了它 —— 用「规则结果奖励 + GRPO」
        没有 PRM、没有步骤标注。论文明确说试过 PRM，但难以规模化
        （步骤标注成本、"一步"定义模糊、易被奖励黑客）
③ 2025：进一步证实（*Is PRM Necessary?*）—— 把现有 PRM 用到 R1/QwQ
        这类前沿模型上，表现实际不如简单的多数投票
```

### 1.2 为什么 ORM + GRPO 就够了

关键在 [环节 07](./环节07-GRPO与RLVR详解.md) §3 的组内对比：

> **G 足够大、题目足够难时，组内自然同时出现成功与失败轨迹**；而组相对优势本身就在做一种**隐式的步骤级信用分配**——成功与失败的轨迹共享早期决策，**梯度会偏向地落在它们开始分叉的那一步**。

> 一句话：**用结果奖励的 GRPO ≈ 不付标注费的过程监督。**

### 1.3 PRM 仍然胜出的四种情形

| 情形 | 为什么结果奖励不够 |
|---|---|
| **长程 Agent 任务** | 最终答案本身模糊——40 步浏览-编码-重规划的流程里，"最终答案正确"太稀疏 |
| **工具使用的安全性** | 要惩罚**特定中间行为**（调错 API、泄露 PII、改错文件）——结果奖励来得太迟 |
| **多智能体训练（MARL）** | **组内方差这招在多智能体下静默失效**（见 §2、§4） |
| **推理时搜索** | 即使训练用结果奖励，PRM 在推理时仍能指导 beam search / MCTS / best-of-N 的选择——**今天大多数生产推理系统正是这么用 PRM 的**（§6） |

**实操建议**：

```
默认：从结果奖励开始（更便宜、更好调试，数学/代码/SQL 上几乎总是够用）
例外：只有【有证据】时才加过程奖励 —— 看失败 rollout，
      若"结构对但卡在某类中间错误"，PRM 才有价值。
```

> **易混点**：**"PRM vs ORM" 与 "稀疏 vs 稠密奖励" 不是同一根轴**。可以有稀疏 ORM（二值对/错），也可以有稠密 ORM（按部分分分级）。**让 PRM 独特的是"逐步打分"，不是信号的稠密程度。**

## 2. 为什么长程 Agent 让信用分配重新变难

### 2.1 "免费信用分配"的前提被打破

[环节 07](./环节07-GRPO与RLVR详解.md) 的组基线之所以好用，前提是：**奖励能定位到"这一条回答"**。到了多步/多 agent 场景，这个前提塌了：

```
① 多步单 agent：一条 40 步轨迹只拿一个末态奖励
   → 组相对优势能告诉我们"这条轨迹整体好坏"，
     但"是第 12 步查错了资料、还是第 30 步写错了代码"完全无法区分

② 多 agent：一条团队轨迹只拿一个团队级奖励
   → "到底是谁的功劳"没法用组方差糊过去（组方差只对比整条轨迹）
```

### 2.2 量化"团队级奖励的信用错配"

设两个 agent，各自有成功概率 `p₁`、`p₂`，**团队奖励 = 至少一个成功**（典型的"OR"型团队目标）。于是：

| p₁ | p₂ | P(团队成功) | **成功样本里 a₁ 其实失败的比例** |
|---|---|---|---|
| 0.9 | 0.9 | 0.990 | 9.1% |
| 0.7 | 0.7 | 0.910 | **23.1%** |
| 0.5 | 0.5 | 0.750 | **33.3%** |
| 0.9 | 0.3 | 0.930 | 3.2% |

**读法（这是本环节最值得记住的一张表）**：

- 两个能力相当的 agent（`p=0.5`）协作时，**每 3 次"团队成功"里就有 1 次其实是"a₁ 干错了、a₂ 兜住了"**；
- 但团队奖励给两条轨迹的是**同一个正优势** → **失败的 agent 也被鼓励了**（错误强化）；
- 换成**过程奖励**（各自只吃自己的成功信号），这个比例的**理论值直接是 0%**——奖励与动作一一对应。

> **结论**：**奖励粒度必须跟着任务结构走**。单轮任务里"结果奖励 + 组基线"免费拿到了过程信息；多 agent 任务里这个便宜捡不到了。

### 2.3 组基线在多 agent 下的失效（数值）

同一条 prompt 采样 8 条**团队**轨迹，每条只有一个团队级 0/1 奖励：

```
团队奖励 = [1, 1, 0, 1, 1, 1, 1, 1]   mean=0.875  std=0.331
  → 各轨迹优势 = [+0.38, +0.38, -2.65, +0.38, +0.38, +0.38, +0.38, +0.38]
```

**注意**：优势只告诉"整条团队轨迹的好坏"。那 7 条拿到 `+0.38` 的轨迹里，**每个 agent 各自的贡献完全没被区分**——梯度会把"整条轨迹里所有 agent 的所有动作"一起加强，包括其中某个 agent 的错误动作。

## 3. Agentic RL：环境取代数据集

训练多步工具使用，需要的是 **RL 环境**（可交互、可验证、能多轮 rollout），**而不是静态数据集**。这是"数据形态"层面的根本变化：

```
SFT / DPO：数据 = 静态样本（prompt, response / preference）
RLVR     ：数据 = 静态题库 + 验证器
Agentic RL：数据 = 【环境】—— 能接受动作、返回观测、给出奖励、可回滚、可并行
```

### 3.1 2026 年公开框架（能力速查）

| 框架 | 关键能力 |
|---|---|
| **NeMo Gym**（NVIDIA） | 交互式 RL 环境、多轮 rollout、工具调用验证、**agent / 环境解耦**；Nemotron 3 Super 跨 21 种环境跑了 120 万次 rollout |
| **RLFactory**（arXiv 2509.06980） | **即插即用**多轮工具 RL；Qwen3-4B 训后在 Natural Questions 上超过更大模型，**吞吐 6.8×** |
| **MOSAIC**（arXiv 2603.03205, 2026-03） | 训练 Agent **知道何时拒绝**：把推理结构化为"计划 → 检查 → 行动或拒绝"；有害行为最多降 **50%** |
| **LightningRL**（Agent-Lightning） | 把 Agent 系统视为 **POMDP**，分解成单步转移、**分层算优势**（正面解决 MARL 信用分配 → §4） |

### 3.2 一个 RL 环境的四个关键属性

| 属性 | 为什么重要 |
|---|---|
| **可验证** | 奖励必须自动产生（否则回到人类标注，成本无法扩展） |
| **可回滚 / 可重放** | 错误动作要能撤销（Agent 会犯错，环境不能因此毁掉） |
| **可并行** | rollout 是成本大头，并发度直接决定训练吞吐 |
| **确定性 / 可复现** | 否则实验之间不可比较，调参就是在噪声上瞎试 |

> **与 RLVR 的关系**：**验证器只是环境的一个特例**（无状态、单步）。环境多一点"状态转移"，但设计的关注点完全一致——**怎么把"做得好不好"变成自动、稳定、难以钻空子的信号**。

## 4. MARL 的信用分配：三条杠杆

| 杠杆 | 做法 | 代表 |
|---|---|---|
| **① 过程奖励** | 给中间步骤/中间 agent 单独打分 | PRM、工具调用正确性检查 |
| **② 价值分解** | 学一个"全局价值"，再拆到各个 agent 头上 | **VDN / QMIX / COMA** |
| **③ 轨迹分解** | 把长轨迹切成可独立评估的单步转移，分层算优势 | **LightningRL**（把 Agent 系统视为 POMDP） |

**价值分解的三个经典做法**（传统 MARL 遗产，理解思想即可）：

```
VDN ：Q_total = Σ_i Q_i            加法分解（最简单，但表达能力弱）
QMIX：Q_total = f(Q_1..Q_n, 状态)   单调混合网络（保证联合最优动作与个体贪心一致）
COMA：用反事实基线 A_i = Q_total − E_{a'_i}[Q_total]   "如果只有我换动作，会差多少"
```

- **COMA 的反事实思想最适合 LLM**：它问的正是"**这一步换掉，团队结果会怎样**"——这正是我们想要的信用分配语义；
- **但难点在 LLM 上**：`E_{a'_i}` 需要对每个 agent 的备选动作求期望，而 LLM 的动作空间是 **10⁵ 的词表**，且 agent 的"动作"往往是**几十到几百 token 的一段输出**（不是单个可枚举动作）。

> **实践上的折中**：**把"动作"的粒度从 token 提升到"步骤"**（一次工具调用、一次子任务完成），在步骤级做信用分配——这也是 LightningRL"分解成单步转移"的实质。**粒度选对了，问题就从"不可解"变成"可解"。**

## 5. 合成自博弈（Self-Play）

思路反转：**模型生成自己的训练数据，再从中学**。

| 方法 | 做法 |
|---|---|
| **SPIN** | 让模型区分"自己的输出"与"人类写作"，逐步逼近人类分布，**无需额外标注** |
| **SPICE** | 把自博弈**锚定在外部文档**上（Challenger 出题、Reasoner 解题）→ 避免无锚自博弈的幻觉放大与模型坍缩；数学 **+8.9%**、通用推理 **+9.8%** |

> **红线：自博弈必须锚定外部信息源**。否则模型会在自己的噪声里越走越偏（**model collapse**）——这是"模型给自己出题、自己判卷"这种体系的必然失败模式。

## 6. 推理时搜索：PRM 真正的战场

**重要认知**：**PRM 在"训练时"打不过 ORM+GRPO，但在"推理时"是主力**。

```
训练阶段：ORM + GRPO           （便宜、好调、够用）
推理阶段：PRM 引导搜索          beam search / MCTS / best-of-N 的步骤选择
                              ← 今天大多数生产推理系统就是这么用 PRM 的
```

**为什么推理时用得上 PRM**：推理时我们**已经有 k 条候选路径**，需要"选哪条 / 往哪扩"——这正是**过程打分**的天然用途（逐步打分 → 剪枝 → 加权投票）。而这一步**完全不需要梯度**，所以 PRM 的成本与噪声问题都变得可接受。

> 与 test-time scaling 的连接：这条路径属于"**推理侧算力换准确率**"的范畴，与 [reasoning（推理模型与 test-time scaling）](../reasoning/README.md) 直接相关——**训练侧 RL 与推理侧搜索是同一条战线上的两端**。

## 8. 数值走查（纯标准库，真实输出）

### 8.1 团队级奖励的信用错配（§2.2 表格）

```python
print(f"{'p1':>5} {'p2':>5} {'P(团队成功)':>11} {'成功里 a1 其实失败':>18}")
for p1, p2 in ((0.9, 0.9), (0.7, 0.7), (0.5, 0.5), (0.9, 0.3)):
    team = 1 - (1 - p1) * (1 - p2)      # 团队奖励 = 至少一个成功
    mask = (1 - p1) * p2                # a1 失败但 a2 兜住了
    print(f"{p1:>5.1f} {p2:>5.1f} {team:>11.3f} {mask / team * 100:>17.1f}%")
# p=0.5/0.5 → 团队成功里 33.3% 其实是 a1 失败但拿到正优势（错误强化）
# 换成过程奖励 → 这个比例恒为 0.0%
```

### 8.2 组基线在多 agent 下只给"团队级"信号（§2.3）

```python
import random, statistics
random.seed(0)
rew = [1, 1, 0, 1, 1, 1, 1, 1]                        # 8 条团队轨迹的团队级奖励
mean, sd = statistics.fmean(rew), statistics.pstdev(rew)
print([f"{(r - mean) / sd:+.2f}" for r in rew])
# ['+0.38','+0.38','-2.65','+0.38','+0.38','+0.38','+0.38','+0.38']
# 7 条成功轨迹共享同一个优势 → 谁贡献了多少完全没被区分
```

### 8.3 价值分解的最小可运行版（VDN）

```python
# 两个 agent 各自的 Q，团队 Q 就是加法分解：Q_total = Q_1 + Q_2
Q = {(1, 0): 0.2, (1, 1): 0.9, (2, 0): 0.1, (2, 1): 0.7}   # (agent, action) -> Q_i
def q_total(a1, a2):
    return Q[(1, a1)] + Q[(2, a2)]

best = max(((a1, a2) for a1 in (0, 1) for a2 in (0, 1)), key=lambda ab: q_total(*ab))
print("团队最优联合动作 =", best, " Q_total =", round(q_total(*best), 3))
print("各 agent 的贪心动作 =", [max((a for a in (0, 1)), key=lambda a: Q[(i, a)]) for i in (1, 2)])
# VDN 的可分解性保证了"个体贪心 = 联合最优"，这就是它作为信用分配工具的用处：
# 把团队价值拆成每人一份，梯度就能落到各自的动作上
```

## 9. 坑清单

1. **只有结果奖励却去做长程 Agent**：末答奖励太稀疏、太晚，信用分配无解 → 需过程奖励或价值分解。
2. **多 agent 直接套单 agent 的组基线**：优势只到"团队级"，失败的 agent 也被鼓励（§2.2 的 33.3%）。
3. **奖励只看最终答案、不看过程安全**：模型会学出"答案对但中间乱调 API / 泄露 PII / 改错文件"→ 中间行为必须单独约束。
4. **把 PRM 当训练必需品**：训练用结果奖励通常更好；PRM 的主场在**推理时搜索**（§6）。
5. **混淆"PRM vs ORM"与"稀疏 vs 稠密"**：两根轴不同，别在面试里答串。
6. **把 Agent 的动作粒度定在 token 级**：动作空间 10⁵、要枚举备选动作求期望 → 不可解。**把粒度提到"步骤"**（一次工具调用）才可解。
7. **自博弈不锚定外部信息源**：必然走向幻觉放大与模型坍缩（model collapse）。
8. **忽略环境的工程属性**：不可回滚/不可并行/不确定的环境会让"训练吞吐"和"实验可复现性"同时崩掉——**环境质量往往比算法选择更决定成败**。
9. **以为 Agentic RL 可以跳过 SFT**：Agent 的格式（工具调用语法、终止条件）必须先由 SFT 教会，否则 RL 的探索空间全是无效动作。

## 10. 面试高频追问

1. **什么是信用分配？为什么在多步/多 agent 下更难？** → "整段结果的好坏如何归因到具体动作"。单轮时组内对比天然完成；多步只有末态稀疏奖励、多 agent 只有团队级奖励时，优势只到"轨迹级/团队级"，无法定位到具体步骤或具体 agent。
2. **PRM 和 ORM 怎么选？** → **默认 ORM**（便宜好调，数学/代码/SQL 够用）；PRM 在四类场景胜出：长程 Agent（末答模糊）、工具安全（惩罚中间行为）、MARL、**推理时搜索引导**。
3. **为什么 R1 用规则奖励而不用 PRM？** → PRM 难规模化（步骤标注贵、"一步"定义模糊、易被黑客）；规则结果奖励 + GRPO 的组相对优势**隐式完成步骤级信用分配**——成功/失败轨迹分叉处梯度最强。实测把现有 PRM 用在前沿模型上不如多数投票。
4. **为什么说"用结果奖励的 GRPO ≈ 不付标注费的过程监督"？** → 组内同时存在成功与失败轨迹时，二者共享早期决策、在某个步骤分叉；组相对优势会把梯度偏向地落在分叉处，等价于免费拿到了步骤级信号。
5. **MARL 的信用分配有哪三条杠杆？** → 过程奖励、价值分解（VDN/QMIX/COMA）、轨迹分解（把长轨迹切成单步转移，如 LightningRL 把 Agent 系统视为 POMDP）。
6. **COMA 的反事实基线思想为什么适合 LLM？** → 它问"只有我换动作会差多少"，正是信用分配想要的语义；但 `E_{a'_i}` 需要枚举备选动作，而 LLM 动作空间是 10⁵ 词表、动作粒度是整段输出 → **必须把粒度提到"步骤级"才可解**。
7. **Agentic RL 为什么需要"环境"而不是数据集？** → 多步工具使用需要可交互、可验证、可回滚、可并行的多轮 rollout；静态数据集无法提供状态转移与自动奖励。**验证器只是环境的一个特例。**
8. **自博弈的风险是什么？** → 无锚自博弈会幻觉放大、模型坍缩（model collapse）；**必须锚定外部信息源**（如 SPICE 用外部文档让 Challenger 出题）。
9. **Agentic RL 最容易被忽视的一环是什么？** → **环境工程**。可验证、可回滚、可并行、确定性——这四项往往比算法选择更决定训练能否收敛与复现。
