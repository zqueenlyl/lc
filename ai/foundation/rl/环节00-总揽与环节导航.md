## 0. 宏观总揽

### 0.1 一句话认知

**强化学习 = 在"没有标准答案、只有一个分数"的世界里，靠试错找到拿分策略。**

和另外两种范式放一起看，差别一目了然：

| 范式 | 数据 | 反馈 | 目标 |
|---|---|---|---|
| 监督学习 | `(x, y)` 成对给定 | 告诉你**正确答案** | 拟合 `y` |
| 无监督学习 | 只有 `x` | 无 | 找结构 |
| **强化学习** | **自己采样出来的轨迹** | 只告诉你**多少分** | **最大化累计分数** |

RL 比监督学习难，只因为两件事（记死这两句，后面每个算法都是在处理它们）：

1. **反馈是延迟且稀疏的**——信用分配（credit assignment）问题：整段拿 1 分，哪一步的功劳？
2. **数据是自己产生的**——分布偏移（distribution shift）问题：策略一变，采样到的数据就变了。

本专题要回答两个层面：

- **通用层（环节 01–04）**：当"对错"只能用一个分数表达时，怎么把它变成**可优化**的目标？
- **LLM 层（环节 05–08）**：把这套框架套到大模型上——奖励从哪来、怎么删掉昂贵部件、长程 Agent 怎么办？

### 0.2 全链路 = 一条主线，两大阶段

```
┌── 阶段一：通用 RL 原理（环节 01–04）──────────────────────────────┐
│                                                                   │
│  [01] MDP          把"试错"写成 (S, A, P, R, γ)                    │
│        │            → 目标 = 最大化回报 G；工具 = V / Q / Bellman   │
│        ▼  怎么"解"这个 MDP？                                       │
│  [02] 值方法        先估"每个动作值多少分"，再贪心                   │
│        │            → 值迭代 / MC / TD / Q-learning / DQN           │
│        ▼  动作空间爆炸、要随机策略 → 不估分，直接调概率              │
│  [03] 策略梯度      REINFORCE → 基线 → Actor-Critic → GAE           │
│        │            → 直接用"分数"对策略参数求导                    │
│        ▼  步子太大会把策略走崩 → 给更新加约束                        │
│  [04] 信赖域 / PPO  clip 构造悲观下界："别改太猛"                    │
│                                                                   │
└───────────────────────────── 接缝：PPO ────────────────────────────┘
                                  │
┌── 阶段二：LLM 对齐工程（环节 05–08）───────────────────────────────┐
│                                  │                                 │
│  [05] RLHF          奖励从"人类偏好"来：训 RM → PPO；KL 当缰绳      │
│        │            → 埋下"闭式最优解"伏笔（通往 DPO）              │
│        ▼  嫌 4 个模型太贵 → 删掉奖励模型                            │
│  [06] DPO 家族      隐式奖励 + 离线偏好优化（SimPO / KTO / ORPO）   │
│        ▼  离线学不到数据外的东西 → 回到在线，但换掉两个昂贵部件      │
│  [07] GRPO + RLVR   删 critic（组基线）、奖励换验证器；R1 四阶段     │
│        ▼  单步生成不够用 → 多步、多工具、多智能体                    │
│  [08] Agentic RL    PRM vs ORM、信用分配、MARL、自博弈、推理时搜索  │
│                                                                   │
└───────────────────────────────────────────────────────────────────┘
```

一句话串起来：**环节 01–04 教"当只有分数时怎么优化"，环节 05–08 教"把分数换成人类偏好 / 验证器 / 环境反馈后，怎么在 LLM 上真的跑起来"。**

> **接缝为什么是 PPO**：它既是传统 RL 的工程巅峰（[环节 04](./环节04-信赖域与PPO详解.md)），也是 LLM RLHF 的默认算法（[环节 05](./环节05-偏好对齐与RLHF详解.md)）。所以环节 04 是唯一"两边都必读"的一站。

### 0.3 先把"为什么长这样"记住（演进因果链）

每一步演进都在**删掉一个昂贵部件**——这条线贯穿全专题，也是面试最爱问的"发展脉络"：

| 代际 | 方法 | 删掉了什么 | 关键节点 | 详解 |
|---|---|---|---|---|
| — | TRPO → **PPO** | 二阶信赖域 → 一阶裁剪 | 2017, Schulman | [环节 04](./环节04-信赖域与PPO详解.md) |
| 1 | **PPO + RLHF** | （基线：4 个模型同时在显存里） | 2022 InstructGPT → ChatGPT | [环节 05](./环节05-偏好对齐与RLHF详解.md) |
| 2 | **DPO** | **删掉奖励模型** | 2023, arXiv 2305.18290 | [环节 06](./环节06-DPO家族与离线偏好优化详解.md) |
| 3 | **GRPO** | **删掉 critic 网络** | 2024, arXiv 2402.03300；2025 被 R1 推上台前 | [环节 07](./环节07-GRPO与RLVR详解.md) |
| 4 | **RLVR** | **删掉"人类偏好"与步骤标注** | 2024–2026，R1 证明可行 | [环节 07](./环节07-GRPO与RLVR详解.md) §6 |
| 5 | **Agentic RL** | 删掉"静态数据集"（改用环境） | 2025–2026, verl / Agent-Lightning | [环节 08](./环节08-AgenticRL与信用分配详解.md) |

```
模型数演进（显存账的直观表达，选型时最常被引用）：
PPO+RLHF:  Actor + Critic + RewardModel + Reference     （4 模型）
GRPO:      Actor + RewardModel/Verifier + Reference     （3 模型，无 critic）
DPO:       Actor + Reference                            （2 模型，无 RM）
SimPO:     Actor                                        （1 模型）
```

## 2. 结构全景图（全局唯一一张"RL 方法地图"）

> 另外两张图已并入环节详解：**MDP 与 Bellman 递归图 → [环节 01](./环节01-RL基础与MDP详解.md) §4**；**GRPO 四步流程图 → [环节 07](./环节07-GRPO与RLVR详解.md) §2**。

```
                        目标：最大化累计奖励 G
                                 │
                ┌────────────────┴─────────────────┐
            有环境模型 P、R                     只有采样（LLM RL 全在这条线）
                │                                  │
        动态规划 DP                          ┌──────┴──────┐
        值迭代 / 策略迭代                  学值函数 Q      学策略 π
                │                          │              │
                │                  MC / TD / SARSA       REINFORCE
                │                  Q-learning / DQN    （似然比技巧）
                │                          │              │
                │                     表格 → 函数逼近   加基线降方差
                │                     （经验回放 +       │
                │                       目标网络）    Actor-Critic + GAE
                │                          │              │
                │                          │        给更新加约束
                │                          │              │
                │                          │      TRPO → PPO（clip）
                └──────────────┬───────────┴──────────────┘
                               │
                               ▼
           ┌────────── LLM 对齐：动作 = 下一个 token ──────────┐
           │        奖励来源决定路线（这是选型第一分水岭）       │
           │                                                    │
           │  人类偏好  → RLHF（训 RM + PPO） / DPO（隐式奖励）  │
           │  可验证    → RLVR + GRPO / DAPO（规则、单测、校验） │
           │  环境反馈  → Agentic RL / MARL（多步、多智能体）    │
           └────────────────────────────────────────────────────┘
```

看图要点（每行都对应一个环节详解文档）：

- **左右分叉 = 要不要环境模型**：DP 需要知道 `P(s'|s,a)`、可以"想"；MC/TD/策略梯度只能"试"。**LLM 里没有环境模型**——下一个 token 是自己的动作，不是环境给的转移（[环节 01](./环节01-RL基础与MDP详解.md) §5、[环节 02](./环节02-值方法与DQN详解.md) §7）。
- **值方法 vs 策略方法 = 要不要先估分**：值方法要能 `argmax_a Q(s,a)`，在 10⁵ 量级词表上不可行且给不出随机策略 → **LLM 只用策略方法**；但值方法提供了**优势、基线、信用分配**这些思想（[环节 03](./环节03-策略梯度与Actor-Critic详解.md)）。
- **底部三条路线 = 奖励来源**：这是 LLM 对齐真正的分水岭，决定了整套工具链与显存账单（[环节 05](./环节05-偏好对齐与RLHF详解.md) / [环节 07](./环节07-GRPO与RLVR详解.md) / [环节 08](./环节08-AgenticRL与信用分配详解.md)）。
- **状态就是上下文**：LLM 把"prompt + 已生成的全部 token"当状态 → 天然满足马尔可夫性，这是 LLM 能套进 MDP 的关键（[环节 01](./环节01-RL基础与MDP详解.md) §7）。
