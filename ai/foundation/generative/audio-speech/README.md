# Audio / Speech · 音频与语音

> 一句话：**语音这条线分三段——ASR（声波 → 文本）、TTS（文本 → 声波）、以及端到端的语音对话**；核心桥梁是「语音 tokenizer」，它把连续波形变成 LLM 能吃的离散 token。
>
> 原理详解（信号基础 / 三块任务地图 / TTS 三代演化 / 语音 token / 端到端对话 / 面试题）见 [音频与语音详解.md](./音频与语音详解.md)。

本目录是生成侧「音频维」专题；扩散 / 流匹配数学见 [../diffusion/](../diffusion/)；模态全景见 [../00-AIGC总揽与多模态地图.md](../00-AIGC总揽与多模态地图.md)；实时语音会话见 [../../../runtime/voice-realtime/](../../../runtime/voice-realtime/)。

## 一、技术讲解

三块任务的分工：

| 任务 | 方向 | 代表 | 关键指标 |
|---|---|---|---|
| **ASR** 语音识别 | 波形 → 文本 | Whisper 系 | WER |
| **TTS** 语音合成 | 文本 → 波形 | CosyVoice / Seed-TTS | MOS / RTF |
| **端到端语音对话** | 音频进、音频出 | Realtime / Live API | 首包延迟 |

TTS 的三代演化（看懂为什么越来越快）：**拼接 / 参数合成 → 自回归声学模型（Tacotron 系）→ 扩散 / 流匹配 / 非自回归（一次并行出帧）**。

语音 tokenizer 是音频接入 LLM 的桥：把波形编成离散 token，语音就能和文本同处一条自回归序列，这也是 Omni 系多模态模型的根基。

---

## 二、功能作用

- **转写**：会议记录、字幕、语音输入。
- **合成**：配音、有声内容、语音客服（含声音克隆，需治理）。
- **对话**：全双工、可打断的实时语音交互。
- **理解**：音频事件识别、情感与说话人分析。

---

## 三、应用场景

| 场景 | 用到的能力 |
|---|---|
| 会议转写 / 字幕 | ASR（长音频需分段 + 说话人分离） |
| 语音客服 / 外呼 | ASR + TTS（或端到端），要低延迟 |
| 有声书 / 配音 | TTS（音色一致性、韵律） |
| 实时语音助手 | 端到端语音模型 + 流式协议 |
| 多模态问答（带音频） | 语音 token 进多模态 LLM |

---

## 四、工程要点（后端直用）

1. **延迟是生死线**：实时对话看**首包延迟**而非总时长；RTF < 1 只是「能实时」的门槛。
2. **流式优先**：ASR / TTS 都走流式，配 VAD 断句与打断机制。
3. **音频按秒计费**：成本口径与文本按 token 完全不同，做好预算与降级。
4. **声音克隆要治理**：授权、水印、审核在服务端，见 [guardrails](../../../reliability/guardrails/)。
5. **评测分任务**：ASR 看 WER，TTS 看 MOS + RTF，对话看端到端延迟与打断正确率。

## 六、落地建议

1. **先 ASR 后 TTS**：转写链路是大多数业务的第一步，且评测最成熟。
2. **优先流式 + VAD**：不做流式，实时体验无从谈起。
3. **音色一致性用固定 speaker embedding / LoRA**，别靠随机采样。
4. **合规前置**：声音克隆、真人语音的授权与审计。
