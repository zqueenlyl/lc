# Generative · 生成与多模态

> 不只文本：**图像 / 视频 / 音频语音 / 3D 也都能生成**——把连续、高维、冗余的物理信号压成"机器好用的表示"，再让模型学会从表示预测表示。生成侧与 LLM 的工程思维完全同构（内容不可信、要审核、要算成本、慢 → 异步），可整体平移。

代表：Stable Diffusion / FLUX / Midjourney（文生图）、Sora / 可灵 / Veo / Vidu（文生视频）、Whisper（ASR）/ CosyVoice / Seed-TTS（语音）、GPT-4o / Gemini / Qwen-VL（多模态理解）。

> **先读**：[00-AIGC总揽与多模态地图.md](./00-AIGC总揽与多模态地图.md)（模态矩阵 + 两大范式 + 公共底座），把骨架搭好再进专题。
> **本目录没有 `mvp.py`**：生成模型无法用标准库最小实现，各专题以"原理 + 工程要点 + 成本账"为主。

## 一、技术讲解

生成有且只有两大范式，吃透这条线四篇全通：

| 范式 | 怎么生成 | 擅长 | 成本 |
|---|---|---|---|
| **自回归** | 逐单元预测下一个（token / patch / 帧） | 结构序列：语言、代码、逻辑 | 随序列长度线性涨 |
| **扩散** | 从纯噪声迭代去噪 N 步（加噪-去噪） | 连续分布：图像、波形 | ≈ 单次推理 × N 步 |

选范式本质是问：信号该"串行展开"还是"并行变换"？按"语言"建模还是按"分布"建模？图像/波形高度连续且强局部性，逐 token 自回归不划算（每像素决策、错误累积），扩散"整张并行去噪"更自然。

**公共底座**（各专题复用）：视觉编码器（ViT）、CLIP 类对比对齐、VAE / 自编码器、神经编解码器、文本编码器、模态 projector——一句话：**一切皆 token / patch**。细表见 [总揽 §1–§3](./00-AIGC总揽与多模态地图.md)。

## 二、功能作用

- **生成**：文字 → 图像 / 视频 / 语音 / 3D，按需生产素材。
- **理解**：原生吃多模态输入（图文音视频同模型），不再靠 OCR / ASR / TTS 一串胶水；理解侧细节见 [../multimodal/](../multimodal/)。
- **成本结构差异**：文本按 token，图像按**步数**，视频按**帧数 × 图像成本**，语音按 RTF——预算口径完全不同。

## 四、工程要点

后端接入生成模型，五条横切规则（四篇都遵守）：

1. **慢 → 异步**：图像秒级、视频分钟级。提交任务 → 队列 → 轮询 / SSE 进度 → 结果存储，**绝不同步阻塞 HTTP**。
2. **幂等可缓存**：同 prompt + seed 结果确定 → hash 命中直接返回。
3. **分级模型**：低质快 / 高质慢路由 + 配额看板 + 降级链。
4. **审核在服务端**：生成内容不可信（与幻觉同源）；审核放客户端 = 可绕过。
5. **锁版本 + 灰度**：模型升级必跑回归（风格 / 质量漂移）。

（展开与表格见 [总揽 §4–§5](./00-AIGC总揽与多模态地图.md)。）

## 六、落地建议

1. **先算成本账再选模型**：图像看步数（50 → 蒸馏 1–4 步差一个数量级），视频 ≈ 每秒 24–30 帧 × 图像成本。
2. **异步 + 队列 + 结果存储**从第一天就这么设计，别等超时再说。
3. **评测分模态**：文生图看图文一致性（CLIP 分）+ 美学主观；视频看时序一致性；语音看 WER / MOS / RTF。
4. **合规前置**：训练数据版权、真人肖像、深度伪造、声音克隆——商用前过法务。
5. **与 Agent 组合**：生成能力当 tool 暴露给 Agent，注意成本 / 延迟治理比文本模型更严苛。
