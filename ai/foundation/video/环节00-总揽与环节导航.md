## 0. 宏观总揽

### 0.1 一句话认知

**工业主核的生视频模型 = 一台只认 packed 数字的联合去噪（或运货）机器。**

把文 / 图 / 视频 / 音频压成一条带模态标签的向量序列，喂进多层 DiT（Diffusion Transformer），网络对每个要生成的时空 token 吐出「这一步该怎么改」——D 类预测噪声，E 类预测速度 \(u_\theta\)——再按调度器把噪声 latent 迭代成干净 latent，VAE 解码成画面（可选同期声）。

四句话把机制钉死（以 E 类 flow 为例，H3 走这条）：

- **机器在干什么**：运货。把一团高斯噪声沿速度场拉回「合理的视听信号」。
- **一次前向的产出**：不是画面本身，是每个音/视频 token 上「该往哪走、走多快」。
- **循环**：用 \(u_\theta\) 把扩散时间 \(t\) 往下走一小步，再整条序列前向一次；开源常见约 **20–50 步**。
- **「懂世界」压在哪**：DiT 权重里的「什么画面（+ 什么声音）同时出现才算合理」，加上前置视觉语言模型对指令和素材的理解。

训练做的是**压缩**：真实片子 → 调参；推理做的是**解压**：从纯噪声走到成片。两件事共用同一个网络、同一片速度场（或噪声场），换的只是 \(t\) 的走向。

> 这不是唯一类型。A GAN、B 时间膨胀 UNet、C 离散 token、F 世界模型见 [演化路线](./生视频模型演化路线与类型.md)。本系列按 **2024 之后的工业主核 D/E** 拆环节；H3-Base 是 E + 音画同环的开源标本。

### 0.2 全链路 = 一条主线，两个生命周期

```
多模态输入（文 / 图 / 片 / 声）
         → [环节1] 规格与任务族：时长 / 帧率 / 画幅 / 声道；T2V · I2V · 参考
         → [环节2] 条件接口：prompt / 关系描述 / 任务 IR（H3 叫 Context-IR）
         → [环节3] 视频（+音频）VAE：像素/波形 ↔ latent（序列长度在这里定死）
         → [环节4] 条件编码器 + patch 投影 + pack：三路信号 → 一条 hidden 维序列
         → [环节5] 三维位置（MM-RoPE）：给 (t,h,w) 注入时空顺序
         →  ┐
            │  DiT Block × N（每个 token 都过，模态常共享 Attn/FFN）：
         ↓  │  [环节6] AdaLN：按时间步 + 模态标签调制
         ↓  │  [环节7] 共享 Attention + FFN + 残差 RMSNorm
         ↓  └→ 堆叠 = 逐层提炼「画面该长什么样（声音该响什么）」
         ↓
         ↓ 训练生命周期（一次吃整条 packed 序列）     ↓ 推理生命周期（沿 t 积分）
         ↓                                          ↓
[环节8] 输出头 → 视频速度（+ 音频速度）         [环节8] 同一套头
         ↓                                          ↓
     对真值做 MSE（flow）或噪声回归              [环节10] Euler / 调度器走一步 t
         ↓                                          ↓
    反向传播更新权重                            再前向；积完再 VAE decode
         ↓
[环节9] VAE → caption → 混合预训练 → 分化权重 → CFG/步数蒸馏
         ↓
[环节11] 服务化：异步视频任务 + 推理栈；产品侧可再接 IR / 超分 / Regen
```

- **训练**：随机抽 \(t\)，整条序列一次前向，音画（若同环）两个回归项。
- **推理**：从 \(t\approx 1\)（纯噪声）走到 \(t=0\)（干净）。**贵在「步数 × 序列长度」**：长度全程不变，省钱主战场是 VAE 压缩比、稀疏注意力、AdaLN 卸载、序列并行。

### 0.3 先把「为什么长这样」记住（演进因果链）

零件对应的是生视频痛点，不是某家商标：

| 历史痛点 | 对应解法 | 落在哪一站 |
|---|---|---|
| 像素/波形太长，骨干吃不起 | 3D VAE（空间 8–16×、时间 4×）+ patch；音频另压到几十 Hz | 环节 03 |
| T2V / I2V / 参考 / 配音各养专家 | 语言写素材关系；预训练早融合（H3：Context-IR） | 环节 02、09 |
| 先出静音再配乐，口型对不齐 | 单流 packed，音画同一去噪环 | 环节 04、07 |
| 条件（文本、\(t\)、模态）怎么进 DiT | 输入/输出层分模态 + **AdaLN** | 环节 06 |
| 注意力分不清帧序和左右 | 三维 RoPE `(t,h,w)`，音频走同一条 \(t\) | 环节 05 |
| 深网不稳 / 只会汇总 | Pre-RMSNorm + 门控残差 + SwiGLU FFN | 环节 06、07 |
| 2K 另养超分丢小字 | 基模 in-context 重生成，或级联 SR | 环节 11 |
| CFG 每步两遍网络 | 蒸馏进权重，每步一次前向 | 环节 08、10 |
| 结构过巧不利泛化 | Attn/FFN 全模态通用，专家只留在调制 | 环节 07 |

类型换代（A→F）的完整时间轴不在本表展开，见 [演化路线](./生视频模型演化路线与类型.md)。Attention / SwiGLU / RMSNorm / RoPE 公式回 [transformer 环节](../transformer/环节00-总揽与环节导航.md)；本系列只讲 **它们在生视频上必须改什么**。

## 3. 训练一步 vs 推理一步（务必先分清）

同一个网络，两种用法。搞混了就会把参数调在错误的地方：

| | 训练 | 推理 |
|--|------|------|
| 扩散时间 \(t\) | 每条样本随机抽（音画可各一套 shift） | 调度器排好的几十个点，从 1 走到 0 |
| \(x_t\) 从哪来 | 真值 latent 与噪声的直线插值（flow） | 上一步的积分结果 |
| 序列构成 | 目标音画（加噪）+ 干净条件，一次吃完整条 | 同样一条，长度**全程不变** |
| 前向次数 | 一步一次，然后反传 | 每个 \(t\) 一次（CFG 若已蒸馏则不必两遍） |
| 注意力方向 | 双向：去噪必须看见未来帧 | 同 |
| 缓存什么 | 不缓存（要梯度） | 同一 \(t\) 的 AdaLN、参考素材的 VAE latent |
| 结束条件 | 数据跑完 | 调度器步数用尽 |
| 你能拧的旋钮 | 配比、分辨率桶、loss 加权 | 步数、seed、分辨率/时长、条件是否走官方管线 |

时长在推理第一步就由 latent 形状定死：想多要一秒，得改格子或走续写工作流。
