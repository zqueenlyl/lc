> 开源数字默认 MiniMax-H3 Base；机制对 2024 后潜空间 DiT / flow（类型 D/E）通用。总揽：[环节00](./环节00-总揽与环节导航.md)。类型见 [演化路线](./生视频模型演化路线与类型.md)。

## 1. 干什么

开源：三维 Multimodal RoPE，坐标 `(t, h, w)`。`head_dim=128`，`rope_inv_freq_len=16`。做法是把头维切成几段，不同段跟不同的轴旋转，而不是加一张可学习的 `pos_emb[t,h,w]` 表。

## 2. 最小直觉（旋转怎么编码位置）

二维向量转 \(\theta\)：

\[
(x,y)\mapsto (x\cos\theta-y\sin\theta,\; x\sin\theta+y\cos\theta)
\]

对 Q/K 做这种旋转，点积只依赖 **相对角** \(\theta_i-\theta_j\)。MM-RoPE 让一部分维度跟 \(t\) 转、一部分跟 \(h\)、一部分跟 \(w\)。

| 事件 | 哪个轴在转 |
|------|------------|
| 同一物体下一帧 | \(t\) 变，\(h,w\) 不变 |
| 同一帧里右边的 patch | \(w\) 变 |
| 第 3 秒的歌声 vs 第 3 秒画面 | 音频主要走 \(t\)；视频 \(t\) 相同则时间轴对齐 |
| 文本 token | 通常只转序列下标这一维 |

关键收获：**音画对齐不需要单独的对齐网络**。音频 token 和视频 token 的时间坐标本来就落在同一把尺子上，「第 3 秒的嘴」和「第 3 秒的声」在几何上天然近邻，剩下的交给注意力。

## 3. 为什么不用可学习的绝对时空表

| | 可学习 `E[t,h,w]` | MM-RoPE |
|--|-------------------|---------|
| 分辨率外推 | 没见过的格子要外插 | 相对旋转可外推（超长外推仍有衰减） |
| 参数 | 随格子数涨 | 几乎不涨 |
| 相对运动 | 要模型自己从绝对坐标减出来 | 点积天然相对 |

视频生成的分辨率、时长、宽高比每次请求都可能不同（环节 01 的合同是变量，不是常量），网格大小跟着变，相对编码因此更对口：模型学到的是「下一帧、右边一格」这种位移关系，换个画幅依然成立。

## 4. 这一站的两条 H3 特有约束

- **三维格子，双向可见**：去噪要看未来帧——物体从右边走进来，左边那些还是噪声的格子需要右边的信息。所以位置编码要支持任意方向的相对位移，不存在「只能往回看」这回事。
- **文本 Refiner 故意不用 RoPE**（[环节 04](./环节04-Encoder与Packed序列详解.md)）：那 2 层只在文本内部混合，此时文本还没和音画共享坐标系。进 packed 主栈之后，文本行才带上与音画一致的位置方案（实现细节以开源 `text_pos_info` 为准）。

## 5. 工程要点

1. pack 时必须带 `img_pos_info` / `audio_pos_info` / `text_pos_info`。位置错一格，口型会对到错误秒。
2. 稀疏注意力（训练末段有、开源推理暂无）仍要在同一套坐标上定义邻域；块大小 **未披露**。

## 6. 面试追问

- **没有 RoPE 会怎样？** 帧序可互换，运动解体；左右声道时间也对不齐画面。
- **为什么不学 3D 正弦表？** 可以，但旋转式相对编码在变分辨率、变时长上更省事，几何意义也更直接。
