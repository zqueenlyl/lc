## 1. 全景图（能还原的阶段）

```
真实自然数据（官方自称；配比未披露）
        │  清洗 / 切镜 / 音画对齐
        ▼
 A  Tokenizer     VisualVAE + ViT decoder；AudioVAE 左右独立
 B  Caption/IR    ~100K 理解 → ~4K 关系描述（专用模型，未开源）
 C  预训练        尽早混合 T2I / T2V+立体声+多镜头 / T2A / 广义参考编辑
                  理解与生成 workload 拆调度，自称吞吐 +~30%；末段稀疏 Attn
 D  分化          FL2VA vs Ref2VA 两份 DiT
 E  CFG 蒸馏      发布权重每步一次前向
 F  产品          IR 编排 + 审核 + Regenerator（部分未开源）
 G  社区后训练    DiffSynth SFT/LoRA；fal 人像 LoRA（非官方预训练）
```

优化器、全局 batch、token 总量、是否分辨率课程学习：**未披露**。官方也没有公开的 RLHF / 偏好对齐阶段；产品侧的「听话」主要由 B 的 caption 质量、C 的任务混合和线上审核承担。

## 2. 顺序为什么不能换

这条管线的依赖是硬的：

- **A 必须在 C 之前冻结形状**：DiT 的训练目标定义在 VAE latent 上（[环节 08](./环节08-双头与Flow训练目标详解.md)）。潜空间一改，所有已训权重作废。官方未写 VisualVAE encoder 在训 ViT decoder 时是否冻结。
- **B 必须在 C 之前**：没有关系式 caption，参考/编辑任务就退回「靠 task_id 分派」，早融合无从谈起。
- **D 在 C 之后**：两份权重共享同一段预训练，只在条件布局上分叉。
- **E 放最后**：蒸馏是把已经训好的 CFG 行为烤进学生，顺序反过来没有意义。

还有一条别套错的算账习惯：这里的「token」是 VAE 格子，一个格子的信息密度取决于压缩比和内容，同样的 token 总量在不同分辨率下根本不等价。谈数据量要落到「多少小时、什么分辨率」，不是笼统的 token 数。

## 3. 阶段 A：先把信封训好

视频生成的第一生产力经常是 VAE 可学性，不是 DiT 层数。H3 明确同时要重建质量和可学性；视觉还多一个 ViT decoder。音频独立，避免图像先验硬套频谱。

## 4. 阶段 B–C：语言当任务总线 + 早融合

样本不是 `(task_id=I2V, image)`，而是：「把图 A 的人放到视频 B 的运镜里，音色像音频 C」。官方原则：

- 数据与任务尽早融合，**配比是关键**（比例未给）；
- 广义参考/编辑完全来自真实自然数据，图可扩展；
- 人声/音效/音乐不拆 T2A。

基建：多模态上下文让序列长度方差约 ×3。把「读长 IR/参考」（理解）和「写 6 万视频 token」（生成）拆开占硬件，再做样本间负载均衡 → 自称端到端吞吐 +~30%。这不是推理 API 行为。

## 5. 阶段 D–E：你下载到的东西

两份 BF16 Omni Transformer +（布局上可共享的）VAE/Encoder。不要混加载。CFG 已蒸馏。

合理推断（**非官方**）：主训练分辨率在 768 桶，2K 更多是 regen 任务；未写死。

## 6. 阶段 G：你能做的后训练

| 做法 | 何时 |
|------|------|
| 只训双头（~百万参） | 冒烟，验证 pack/loss |
| LoRA 打 `to_qkv` / `out` / FFN | 单机实用；fal 人像只打融合 QKV，rank 32，高分桶比更长 step 更关键 |
| 全参 33B ZeRO-3 | 真有集群时 |

许可证：**禁止用 H3 或其输出蒸馏改进其它模型**。领土与营收门槛见全景篇，非法务意见。

静默毁权重的四条：

1. 视频/音频两套 \(t\) 不能共用；
2. pack 必须走官方函数；
3. AdaLN 相关投影保持 fp32；
4. 蒸馏权重不要再乘 CFG。

## 7. 面试追问

- **H3 预训练最不像视频专家的一点？** 参考/编辑用自然语言收成同一任务，而不是后加 ControlNet。
- **开源能否复现预训练？** 不能。只有权重和推理；数据与脚本未放。
