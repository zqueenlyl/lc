## 1. 干什么

官方把前代问题叫 **任务墙**：图侧 T2I/编辑/主体/风格分家，声侧人声/音效/音乐分家，视频侧再切文生、图生、首尾帧、参考。墙既限制创作者，也限制预训练泛化。

H3 的接口因此变成一句话：**用自然语言写「上下文 ↔ 目标、上下文内部」的关系。** 任务不再靠 `task_id` 或专家网络分派，而是靠这段话本身。Context-IR 负责读懂这句话和附件，输出 Contextual Omni Representation。

内部（官方叙述，结构**未开源**）：指令解析、跨模态关联、时序、复杂推理。在不偏离原意时可补未写清的语义。

官方数字：大部分素材需要约 **100K token 推理**，压到平均约 **4K**。这 100K 跑在哪套模型上：**未披露**。

## 2. 最小直觉

用户说：「参考视频 1 的希区柯克镜头，让图 2 的人唱歌，歌声参考音频 3。」

机器真正需要的不是三个文件名，而是类似：

```
目标视频 ← 运镜 来自 视频1（希区柯克：主体不动、镜头推近）
目标视频 ← 身份/外貌 来自 图2
目标视频 ← 人声旋律/音色 来自 音频3
目标视频 ← 口型 必须与人声时间对齐
（可选补全）镜头运动平滑、环境声压低、对白语言 = …
```

IR 把上面这张关系图序列化成 Base 的文本条件（再进 [环节 04](./环节04-Encoder与Packed序列详解.md) 的 Qwen3-VL）。

**分工要记死**：IR 只产出「谁和谁什么关系」的文字；像素和波形照样各自走 VAE 编码成 latent 一起 pack 进序列。IR **替代不了** 参考 token，它替代的是「任务 id」。

## 3. 三条路径，成片差一档

| 路径 | 进入 Base 的文本 | 观感 |
|------|------------------|------|
| 裸 prompt | 十几 token | 运镜/口型/Logo 容易糊 |
| 仓库 skill `h3-prompt-writing` | `base-en.txt` / `ref-en.txt` 模板 | 接近官方，仍缺自动补全 |
| 官方 IR API | ~4K 结构化 + 审核 | 对齐 App 的前提 |

安全：用户提交的文/图/视频以及增强 prompt 过自动审核。拦违法、色情、侵权；官方承认误拦/漏拦。不影响你本地合法微调义务。

## 4. IR 到底占了哪个位置

三件事容易混，分清楚：

| 它是什么 | 它不是什么 |
|----------|------------|
| Base 之前的**多阶段托管管线**，多个模型串起来 | 不是开源那 33B DiT 自己的一部分，也不是它的某一层 |
| 产出**文字**：关系、时序、补全的细节，平均约 4K | 不产出任何 latent，不编码像素和波形 |
| 取代了过去的任务分派（选 I2V 还是参考模式） | 取代不了参考素材本身进序列 |

直接结论：**本地只跑 Base ≠ 复现海螺。** 差的是这一站的条件质量（以及环节 11 的 2K Regen），不是你没开 CFG——CFG 已经蒸馏掉了。

## 5. 工程要点

1. 要对齐官方 2K 工作流：IR API → Base → Regen API（[环节 11](./环节11-系统与服务化详解.md)）。
2. 自建预处理时对白用 `<d>[English] …</d>`（本仓 tokenizer）。
3. IR 对成品质感「至关重要」是官方原话，不是营销闲笔。

## 6. 面试追问

- **IR 是 DiT 的一层吗？** 不是。是前置编排系统，可以整段换掉或自建。
- **为什么 caption 要写关系？** 预训练要把参考/编辑/首尾帧收成同一个任务，语言是唯一可泛化的任务接口。
