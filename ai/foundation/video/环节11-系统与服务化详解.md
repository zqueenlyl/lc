## 1. 完整系统仍是三块

```
用户请求
  → H3-Context-IR     托管     环节02
  → H3-Base 768p      开源     环节03–10
  → H3-Regenerate-2K  托管     本环节
```

Regenerator：**不是**独立超分网。让基模以 in-context 方式重画自己的 768p，并再次看见原始多模态上下文。官方理由：

1. 最大复用已经会的生成能力；
2. 小字/品牌细节传统 SR 只能猜，这里可以「再看见原图」。

这也是任务泛化的例子：超分不必另养专家。模块未开源。验证走 Regeneration API 或一键 create。

**选型坑**：开源 768p 对 App 2K，比的是系统。

## 2. 四套推理栈（不要混文件布局）

| 栈 | 适合 |
|----|------|
| ComfyUI ≥ 0.30 | 工作站、LoRA |
| SGLang Diffusion | 生产 HTTP、多卡菜谱 |
| vLLM-Omni | OpenAI 风格视频端点 |
| diffusers Modular | Python、offload、workflow=`fl2va`/`ref2va` |

官方数字：单 Transformer 分区 bf16 ≈ **61.7 GB**；Qwen 条件器 ≈ **62.1 GB**。两份 DiT 默认都 load 时显存再翻。`--task-type` / `--model-variant` 只留一份。

## 3. 生视频服务的四个特征

| 特征 | 后果 |
|------|------|
| **异步任务**：提交 → 轮询 → 取文件 | 分钟级响应很正常；没有中途可流式吐出的部分成片 |
| **端点是任务式**：`/v1/videos` 或 `video-generation-v2-*` | 需要任务表、重试、产物存储与过期策略 |
| **可缓存的是条件不是内容**：参考 latent、AdaLN 调制表 | 同一批素材反复出片时收益最大 |
| **请求长度方差大**：时长/画幅/参考数决定 \(n\)，成本按 \(n^2\) 走 | 必须按序列长度而不是请求数做排队和负载均衡（训练侧官方已强调方差 ×3） |

完整 2K 本地复现：SGLang Base + 官方 IR + Regen；768p 可纯本地。

## 4. LoRA 挂在哪

社区人像 LoRA 打共享 `attn.qkv_proj`，一份文件挂 T2V/I2V/R2V，**不替代** IR/Regen，也不合并 FL2VA/Ref2VA 两份基座。公式仍是 \(W+\gamma BA\)，见 [PEFT 环节04](../peft-lora/环节04-低秩适配公式详解.md)。

## 5. 工程要点

1. 审核在 IR 段也会做；本地 Base 的安全责任在你。
2. 许可证排除美/欧/英/韩领土、蒸馏禁令、营收门槛、UI 展示「MiniMax H3」——上线前读原文。
3. 路线图：H 系下一版计划吸收 M 系理解；**不是**现网已经合成一个模型。

## 6. 面试追问

- **2K 是超分吗？** 官方定义为基模 in-context 重生成。
- **开源缺什么导致不像 App？** 主要缺环节 02 和本站 Regen，其次缺官方 IR 补全的 caption 质量。

## 7. 系列收口

回到 [环节 00](./环节00-总揽与环节导航.md) 那句话：H3 是一台 packed 音视频联合去噪机。整条链只有一根主线——**规格定形状 → 条件写成文字 → VAE 压成 latent → pack 成一条序列 → 50 层带 AdaLN 的双向注意力 → 双头出速度 → 沿 \(t\) 积分 → decode 成片**。训练和推理共用这根主线，只是时间轴方向不同，调参时不要把两者的经验混着用。
