## 1. 推理在循环什么

1. 抽视频噪声、音频噪声，形状等于目标 latent。
2. 编码条件：文本（第 50 层 + refiner）、可选首尾帧/参考（干净 VAE token）。
3. 对调度器每个 \(t\)（视频一套、音频一套）：
   - pack → 50 层 → 双头得到 \(u\)
   - Euler / 官方 flow step：\(x \leftarrow x + \Delta t\cdot u\)（符号随实现）
4. 积到 \(t\approx 0\)：VisualVAE decode + AudioVAE decode（左右合并）。

结束条件是 **步数用尽**，由调度器决定，与内容无关。时长在第 1 步就由 latent 形状定死——不能「再生成 1 秒」，除非改格子或走续写任务（开源有 Retake 类工作流，见 DiffSynth；不是本环节默认）。

## 2. 一步的成本结构

每一步都是一次完整前向，代价 = **6 万行的 \(O(n^2)\) 全注意力 × 50 层**。总账就是 `步数 × 序列长度²` 这个乘积。

跨步能省的东西有限，但要知道有哪些：

| 成分 | 能否跨步复用 | 说明 |
|------|--------------|------|
| 噪声行（视频/音频）的 QKV | **不能** | 每步内容都变，必须重算——这是成本主体 |
| 条件行（文本/参考）的 K/V | 理论上可以 | 这些行全程干净不变；是否实现看引擎 |
| AdaLN 调制 \(\gamma\beta g\) | 可以 | 只依赖 \(t\) 和模态，几十个 \(t\) 预算好即可，还能顺带卸掉 13B（环节 06） |
| 参考素材的 VAE latent | 可以 | 请求开始时编一次 |
| VAE decode | 只做一次 | 积完再做 |

所以想让 H3 变快，只有三条路：**步数更少**（CFG 蒸馏已经砍掉了每步的第二遍前向）、**\(n\) 更短**（VAE 压缩比、分辨率、时长）、**注意力更稀疏**（训练末段有，开源推理暂无）。

## 3. 你手上真正能拧的旋钮

| 旋钮 | 有没有 | 说明 |
|------|--------|------|
| seed | 有 | 噪声初值 |
| 步数 | 有（栈相关） | 少步快、细节损 |
| guidance / negative | **无** | 蒸馏掉了 |
| 时长 / 画幅 | 有 | 改 VAE 格子；要对齐 4× / 32× |
| IR | 产品有、本地常无 | 观感差的第一嫌疑 |

## 4. 训练一步 vs 推理一步

| | 训练 | 开源推理 |
|--|------|----------|
| \(x_t\) | 随机 \(t\) 插值真值 | 上一 scheduler 状态 |
| 前向次数 | 蒸馏后 1 | **1** |
| decode | 通常不做 | 只在最后做 |
| AdaLN | 要梯度，必须 load | 可预计算卸载 |

## 5. 工程要点

1. 参考媒体可预编码成 latent，多步复用。
2. `torch.compile` 在 SGLang 当前路径会改数值，官方推荐 eager lossless。
3. 延迟只有一种结构：排队 → 编码条件 → N 步去噪 → 两个 VAE decode → 封装文件。中间没有任何可以提前吐给用户的部分产物，进度只能按步数报。

## 6. 面试追问

- **为什么不能把整网缓存起来？** 噪声 token 每步都变，它们的 QKV 必须重算；只有干净条件段能跨步复用（若引擎实现了）。
- **为什么没有 vocoder 延迟？** 音频与视频同一环结束，decode 是 VAE 不是逐样本生成波形。
