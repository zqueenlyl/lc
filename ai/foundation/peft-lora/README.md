# PEFT / LoRA · 参数高效微调

> 冻结原模型，只训练很小的附加参数（低秩矩阵、Adapter、前缀），用一份底座服务多个领域。一句话：**不复制 70B，只存几份几十 MB 的皮肤。**

代表：LoRA / QLoRA、DoRA、AdaLoRA、Prefix/Prompt Tuning、厂商「微调 API」。

配套 MVP：[mvp.py](./mvp.py)（低秩增量的矩阵算术 + 多适配器热插拔）。

---

## 一、技术讲解

全量微调：存一份完整权重，贵、易忘原能力、难同时服务 N 个客户。

LoRA 观察：微调对权重的改变 ΔW 往往是 **低秩** 的，于是：

```
W' = W + γ · B A
A: r×k,  B: d×r,  r ≪ min(d,k)
```

只训 A、B（以及可选的缩放 γ）。QLoRA 再把 W 做成 4-bit，在消费级显卡上也能微调大模型。

推理时：

- **合并**：把 BA 加回 W，零额外延迟，但每个领域一份合并权重；
- **热插拔**：底座一份，按请求加载不同 LoRA（多租户 SaaS 常用）。

PEFT 家族不止 LoRA：Adapter 插层、Prefix Tuning 改 KV、BitFit 只训 bias。2026 年 LoRA 仍是默认起点。

---

## 二、功能作用

- **省显存 / 省存储**：N 个领域 ≈ 1 底座 + N 个小文件。
- **快迭代**：小时级而不是天级出新领域版本。
- **少遗忘**：底座能力保留较好（仍要回归通用集）。
- **合规**：客户数据只进小适配器，底座可共用。
- **配合 RL**：策略/奖励模型也常 LoRA 化。

## 三、应用场景

| 场景 | 典型做法 |
|---|---|
| 企业话术 / 品牌语气 | 小语料 LoRA |
| 垂直抽取（病历、合同） | 指令数据 + 结构化输出 |
| 代码仓风格 | 仓内提交数据微调 |
| 多租户助手 | 底座共享，租户 LoRA 热加载 |
| 推理蒸馏 | 学生 SLM + LoRA 对齐教师 |

不优先微调：数据少于几百条且任务能靠提示 / RAG 解决——先别上训练链路。

---

## 四、数据与 rank 经验

- **r**：8–64 常见；过小学不动，过大接近全量、过拟合。
- **目标模块**：先 attn `q/v`，不够再加 FFN。
- **数据**：质量 ≫ 数量；指令格式要和推理一致。
- **学习率**：通常高于全量微调一个数量级，需 sweep。
- **评测**：领域集 + 通用集一起看，防「只会说客户黑话」。

## 六、落地建议

1. 基线：提示工程 → RAG → 才微调。每一步用 [Eval](../../reliability/eval/) 证明有增益。
2. 版本：`base_rev + lora_rev` 一起钉死，评测才可复现。
3. 热插拔注意 **首包延迟** 和 GPU 上 LoRA 缓存个数。
4. 安全：领域数据若含攻击样本，LoRA 可能学坏，上线前跑拒答集。
5. 许可：确认底座协议允许微调与分发适配器。

## 八、本目录 MVP

`mvp.py` 用 3×3 矩阵当 W，两个 rank-1 LoRA（「正式语气」「海盗语气」）热插拔，演示 W+BA 与合并结果，以及切换适配器不必复制 W。
