## 1. 干什么

给「微调」一个空间图像：每个可训练参数是一个独立方向，全参微调 = 在这个空间里找使损失更低的一点。方向一多，可走的路按指数涨，针在干草堆里。

LoRA 的第一步不是分解矩阵，而是承认：**选项太多是负担，限制路径反而更快接近。**

---

## 2. 怎么干（寻宝比喻）

森林里有宝藏（完美微调后的模型）。你能走的独立方向数 = 维数 = 自由度。

| 维数 | 图像 | 你能做的选择 |
|---|---|---|
| 0 | 一个点 | 无，钉死 |
| 1 | 直线，或弯了的小路 | 只剩前进 / 后退 |
| 2 | 平面，或弯了的曲面 | 左右 + 前后 |
| 3 | 立方体 / 球体内部 | 再加上下 |
| n | 想象不出，但合法 | n 个彼此独立的方向 |

二维森林里自由走动 = 两个坐标，选项很多，宝藏难撞上。若先铺一条铁轨，小车只能沿轨跑：

- 自由度从 2 降到 1；
- 宝藏未必恰好在轨上；
- 但只要轨道**穿过宝藏附近**，你用少得多的尝试就能贴近。

轨铺得蠢（贴着森林边缘走），贴近机会差；轨铺得巧（斜穿过密林），机会好。LoRA 后文的「选秩、选注入模块」，就是在选这条轨怎么铺、铺几条。

三维同理：在巨大立方体里搜，改成只在一块聪明的二维曲面上走——选项少了，覆盖仍可以很大。机器学习里 n 是千、百万、十亿、万亿，图景相同，只是立方体画不出来。

> 记忆钩子：**自由是好的，直到选项把你淹死。** LoRA 主动少给你几个旋钮。

## 3. 方法对比

| 搜索方式 | 自由度 | 优点 | 风险 |
|---|---|---|---|
| 全空间（全参微调） | 等于参数个数 | 理论上能走到任意宝藏 | 贵、慢、易忘原能力 |
| 一条轨道（秩 1） | 大约「行 + 列」量级 | 极省、正则强 | 轨铺歪就贴不近 |
| 几条轨道（秩 r） | 大约 r 倍于秩 1 | 覆盖更大，仍远小于全空间 | r 过大 ≈ 变回全参 |

这不是三种算法，是同一把尺子上的刻度。r 从 1 往上加，就是多铺几条轨。

---

## 4. 优缺点（这一站要记住的边界）

- **降维不是无损**：轨道以外的点你到不了。所以 LoRA 默认假设「好答案就在底座附近的低维切片里」。
- **降维也不是偷懒**：预训练已经把模型送到一片不错的区域；微调是在附近做手术，不是重新找大陆。
- **随机初始化上不要 LoRA**：起点本身是乱林，轨道再巧也是在错的高度搜针。必须先有一份可信底座——下一站用最小网络把这句话钉死。

---

## 5. 数值直觉（搜索体积）

二维边长 L 的正方形，自由搜索的「格子数」约 `L × L`；一条穿过它的轨大约只有 `L` 个格子。边长变 10 倍，平面选项 ×100，轨道只 ×10。维数到 20（下一站会落到 4×5 的一层权重），全空间 vs 秩 1 子空间的差距已经不是「省一点」，是省一个数量级以上。工程里一层是 4096×4096，差距变成千分之几——那笔账在 [环节09](../transformer/环节09-训练管线详解.md) §4.3.3。

本站只要求建立：

```
维数 = 独立方向数 = 你要调的旋钮个数
LoRA = 把旋钮数从 mn 降到大约 r(m+n)
```

## 6. 面试高频追问

1. **LoRA 在几何上到底限制了什么？** 把权重更新限制在低维子空间（「轨道」）里搜，而不是每个参数独立改。
2. **为什么限制路径还能微调好？** 宝藏（好模型）被假设就在预训练点附近；搜得少但搜得巧，比在亿维里穷举更快贴近。
3. **轨道铺歪了会怎样？** 到不了真正的最优点，表现为欠拟合——加大 r、或给更多模块铺轨（下一站 / [README](./README.md) 的 r 经验）。
4. **这和降维有何关系？** 就是降维：从 n 维空间走到 k 维子流形上优化，k ≪ n。
