# 多模态理解与统一模型详解（CLIP / VLM / 音频进 LLM）

> **定位**：生成（[图像扩散模型详解.md](../generative/diffusion/图像扩散模型详解.md) 等三篇）之外的另一半——**理解**：图/视频/音频怎么"看懂看懂听"进 LLM，以及"一个模型全模态进、全模态出"的统一路线。核心命题：**异构的像素/波形/文本，怎么在同一个模型里对齐与互操作。** 本文与生成篇互为镜像（CLIP 既做文生图条件也是理解基础）。

---

## 1. 任务地图

| 任务 | 输入→输出 | 代表 |
|---|---|---|
| 图文理解（VQA/描述） | 图 → 文本 | Qwen-VL、InternVL、GPT-4o |
| OCR / 图表 / 截图 | 图 → 精确文本/结构化 | 视觉文档模型 |
| 视频理解 | 视频 → 文本（摘要/问答/时间定位） | 视频 VLM（采样帧 + 时间建模） |
| 音频理解 | 语音 → 文本 / 事件 | Whisper 类 + LLM 编排 |
| 多模态对话 | 图/音 + 文本 → 文本（或语音） | Omni 系（[音频与语音详解.md](../generative/audio-speech/音频与语音详解.md) §6） |

**通用配方**：多模态 LLM = 模态编码器（把像素/波形变成模型能吃的向量）+ 投影/对齐 + 一个 LLM 主干。差异就在"编码器 → LLM 之间那层桥怎么建"。

## 2. CLIP：图文的"对齐锚点"

- 结构：图像塔（ViT/CNN）+ 文本塔，**对比学习**（不是生成学习）：一个 batch 里把"配对的图-文"拉近、把"错配的"推远
- 损失：对称交叉熵（InfoNCE 类）。数值直觉：batch=4 时构造 4×4 相似度矩阵，对角线（正样本）概率→1，非对角线→0；训练让对角线 logit 最大
- **为什么重要**：CLIP 让"图像语义"和"文本语义"落在同一向量空间——于是它成为：
  - 文生图的条件编码器（[图像扩散模型详解.md](../generative/diffusion/图像扩散模型详解.md) §7）
  - 零样本分类/图文检索（免训练，直接比相似度）
  - VLM 视觉侧的"语言化"前置
- 局限：对齐粒度粗（整体图-整句），细粒度 OCR/计数/空间关系弱 → 需要更强的视觉编码器与训练数据补

## 3. VLM 三代接入架构（核心对比表）

| 方案 | 桥怎么建 | 视觉 token | 代表 | 评价 |
|---|---|---|---|---|
| **Projector（MLP 投影）** | ViT 输出 patch 特征 → 一层 MLP 映射到 LLM embedding | 几十~上百 patch token | LLaVA 系 | 简单有效，基线 |
| **Q-Former（可学习 query）** | 用固定数量 query 从视觉特征"蒸馏"出少量 token | **固定少 token**（如 32） | BLIP-2 | 显存友好，丢细节 |
| **原生统一（视觉即 token）** | 视觉 patch 直接当序列 token 与文本同流（交替训练） | 多、可扩展 | Qwen-VL、InternVL、Gemini | 细节好，token 成本高 |

**分辨率/OCR 的现实痛点**：1024² 图按 14~16 patch ≈ 数千 token；喂给 LLM 又贵又容易丢小字 → 主流做法：
- **切 tiles**：把大图切成多块小图（每块 448²/1024²）分别编码再拼接
- **token 下采样/动态 token**：保细节同时控数量（如 640×640 后按内容压缩）
- 权衡轴永远是：**视觉细节（token 越多越好）vs 成本与上下文（token 越少越好）**——与 KV Cache 优化同思路（回链 [环节11](../transformer/环节11-服务化与推理引擎详解.md)）

## 4. 音频进 LLM

两条路（详见 [音频与语音详解.md](../generative/audio-speech/音频与语音详解.md) §5）：
- 特征路：mel 特征直接投影进 LLM（便宜、理解够用，不能高质量生成）
- **token 路**：神经编解码离散 token 当文本 token 训练 → 可进可出（Omni 系），语音输入+语音输出单模型

## 5. 统一模型的训练配方（2026 主流路径）

1. **预训练对齐**：图-文对、视频-文对、音-文对做对比或 next-prediction 对齐（CLIP/VLM 底座）
2. **交错数据**：把"图 + 对应文本 + 后续文本"当长序列训练，模型学会"图在中间也能接着写"（关键：不是"图在前文在后"，而是交错）
3. **指令微调**：SFT 视觉问答/对话数据（多模态版 RLHF 对齐同理，见 [环节09](../transformer/环节09-训练管线详解.md)）
4. 生成能力：文本出（LLM）由主干承担；**像素/波形级生成通常"外包"**给扩散/专用 decoder，而不是让 LLM 吐像素——统一"进"，生成按模态走最强引擎

## 6. 工程要点（后端直用）

1. **视觉 token 膨胀是成本大头**：一张 1024² 图 ≈ 上千 token；多图/长视频 = 上下文爆炸 → 控图数/tiles/下采样，缓存编码结果
2. 多模态 RAG：文档 → 版面解析（OCR + 图表结构）+ 图 embedding 检索（复用 [环节06-检索增强RAG详解.md](../../agent/环节06-检索增强RAG详解.md) 管线，检索对象从纯文本扩到图文块）
3. 评测：MMMU（大学多学科）/ MMBench / OCRBench / 视频 QA；**幻觉检测**（图里没有的东西别编）
4. 安全：图注毒/对抗样本、隐私（人脸/车牌打码）、审核链
5. 高并发：视觉编码器与 LLM 分开部署，编码结果缓存；图片走内部存储避免外链

## 7. 面试高频追问

1. **CLIP 是怎么做到"看图说话"的？** 它不"说"，它做对比对齐：图文双塔在 batch 内拉近正对推开负对，让图像与文本落在同一向量空间 → 相似度即语义匹配。
2. **LLaVA 的 projector 在干嘛？** 把 ViT 输出 patch 向量从"视觉空间"线性/MLP 映射进"文本 embedding 空间"，让 LLM 能接着处理；一层即可，关键是后续用数据微调对齐。
3. **Q-Former 相比 projector 的价值？** 用可学习 query 压缩视觉特征为固定少量 token——显存/上下文友好，但要丢视觉细节，细粒度任务吃亏。
4. **高分辨率图像怎么进 VLM？** 切 tiles + 动态 token：保留细节并控成本；本质是"分辨率/细节 vs token 预算"的工程权衡。
5. **多模态大模型怎么同时做理解又做生成？** 理解统一成"token 进出"（LLM 主干）；像素级生成外接扩散/专用 decoder。纯单模型全模态生成仍不成熟。
6. **为什么视觉 token 比文本贵？** 一张图数千 token vs 一句话几十 token；token 数决定 attention 成本与上下文占用 → 优化集中在压缩视觉表示。
